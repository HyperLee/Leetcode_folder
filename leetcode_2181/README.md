## 題目說明

給定一個以 `0` 分隔數字段落的單向串列。串列開頭與結尾一定是 `0`。對每一對相鄰的分隔零，將兩者之間所有節點的值加總成一個新結果節點；回傳的串列不得包含分隔用的 `0`。

例如：

```text
輸入：0 -> 3 -> 1 -> 0 -> 4 -> 5 -> 2 -> 0
輸出：4 -> 11
```

- 第一段為 `3 + 1 = 4`。
- 第二段為 `4 + 5 + 2 = 11`。

題目連結：[LeetCode 2181. Merge Nodes in Between Zeros](https://leetcode.com/problems/merge-nodes-in-between-zeros/description/)

### 限制條件

- 串列節點數介於 `3` 與 `2 × 10^5` 之間。
- `0 <= Node.val <= 1000`。
- 不會出現兩個值皆為 `0` 的相鄰節點。
- 串列第一個與最後一個節點的值都是 `0`。

## 解題概念與出發點

`0` 的用途不是參與加總，而是標示一段數字的開始與結束。因此兩種解法都只需要從左到右走訪一次，並維持「目前區段的總和」。差異在於總和最後存放的位置：

1. 原地解法把總和直接累加到原串列中每個區段的第一個非零節點，再改接 `next` 略過其餘節點。
2. 新串列解法使用獨立的 `sum`，遇到區段結尾的 `0` 時才建立結果節點。

測試入口會為每一種解法重新建立輸入串列。這點很重要，因為先執行的原地解法會改變節點值與節點連結，不能把同一份串列再交給第二種解法。

## 兩種解法比較

| 方法 | 核心設計 | 時間複雜度 | 額外空間 | 是否修改輸入 |
| --- | --- | --- | --- | --- |
| `MergeNodes` | 重用每段第一個節點，累加後改接 `next` | `O(n)` | `O(1)` | 是 |
| `MergeNodes2` | 使用累加器，每段建立一個新節點 | `O(n)` | `O(k)` | 否 |

其中 `n` 是輸入節點數，`k` 是合併後的結果節點數。第二種解法的 `O(k)` 是回傳結果本身所需的節點空間。

## 解法一：原地合併

### 設計說明

`MergeNodes` 不配置新的結果串列，而是把每段的第一個非零節點當成該段的結果節點：

1. 略過開頭的 `0`，令 `current` 指向第一個非零節點。
2. 若 `current.next` 不是 `0`，把下一個節點的值加到 `current.val`，再令 `current.next` 指向下下個節點。這會同時完成累加與移除已處理節點。
3. 若 `current.next` 是 `0`，代表目前區段完成；略過該分隔零，並將 `current` 移到下一段的第一個節點。
4. 回傳 `head.next`，排除原串列開頭的分隔零。

這個設計只使用固定數量的節點參照，因此額外空間為 `O(1)`；代價是呼叫後不能再假設輸入串列仍維持原貌。

### 範例演示流程

輸入：`[0,3,1,0,4,5,2,0]`

| 步驟 | `current` | `current.next` | 動作 | 目前保留的結果鏈結 |
| ---: | ---: | ---: | --- | --- |
| 初始 | 3 | 1 | 略過開頭的 `0` | `3 -> 1 -> 0 -> 4 -> 5 -> 2 -> 0` |
| 1 | 4 | 0 | 將 `1` 累加到 `3`，並移除值為 `1` 的節點 | `4 -> 0 -> 4 -> 5 -> 2 -> 0` |
| 2 | 4 | 5 | 略過第一個區段結尾的 `0`，移到下一段 | `4 -> 4 -> 5 -> 2 -> 0` |
| 3 | 9 | 2 | 將 `5` 累加到第二段結果節點 | `4 -> 9 -> 2 -> 0` |
| 4 | 11 | 0 | 將 `2` 累加到第二段結果節點 | `4 -> 11 -> 0` |
| 5 | — | — | 略過結尾的 `0`，走訪結束 | `4 -> 11` |

最終回傳：`[4,11]`。

## 解法二：累加器與新串列

### 設計說明

`MergeNodes2` 保留輸入串列不變，並使用 dummy head 簡化結果串列的建立：

1. 從開頭 `0` 的下一個節點開始走訪，令 `sum = 0`。
2. 遇到非零值時，將該值加入 `sum`。
3. 遇到 `0` 時，表示一個區段結束；建立值為 `sum` 的新節點，接到結果尾端，然後把 `sum` 歸零。
4. 走訪完成後回傳 `dummy.next`，排除輔助用的 dummy head。

這種作法不必修改任何輸入節點，資料流較直觀，也適合需要保留原始串列的呼叫端；代價是必須為每個結果配置新節點。

### 範例演示流程

輸入：`[0,3,1,0,4,5,2,0]`

| 讀到的值 | 處理前 `sum` | 動作 | 處理後 `sum` | 結果串列 |
| ---: | ---: | --- | ---: | --- |
| 3 | 0 | 累加 3 | 3 | `[]` |
| 1 | 3 | 累加 1 | 4 | `[]` |
| 0 | 4 | 建立值為 4 的節點並重設 | 0 | `[4]` |
| 4 | 0 | 累加 4 | 4 | `[4]` |
| 5 | 4 | 累加 5 | 9 | `[4]` |
| 2 | 9 | 累加 2 | 11 | `[4]` |
| 0 | 11 | 建立值為 11 的節點並重設 | 0 | `[4,11]` |

最終回傳：`[4,11]`，原輸入串列保持不變。
