## 題目說明

[LeetCode 143. Reorder List](https://leetcode.com/problems/reorder-list/)

給定單向鏈結串列：

```text
L0 → L1 → … → Ln-1 → Ln
```

請將它原地重新排列為：

```text
L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → …
```

例如：

```text
輸入：[1,2,3,4,5]
輸出：[1,5,2,4,3]
```

題目不允許只修改節點內部的值。實作必須保留原本的節點物件，透過改變節點之間的 `next` 參考完成重排，而且方法不需要回傳新的頭節點。

## 限制條件

- 鏈結串列的節點數量介於 `1` 到 `5 * 10^4`。
- `1 <= Node.val <= 1000`。
- 正式輸入是非空、無循環的單向鏈結串列。

> [!NOTE]
> 可執行範例額外加入空串列 `[]`，確認兩種公開方法面對 `null` 頭節點時都能安全返回。這是正式限制外的健全性檢查。

## 解題概念與出發點

重排後的節點取用順序是「最左、最右、次左、次右」，因此核心問題是如何有效取得尾端節點。

單向鏈結串列只能沿著 `next` 往後走，無法直接從尾端向前移動。可以採用兩種思路：

1. 先把所有節點參考存入可隨機存取的線性集合，之後用左右指標交替取節點。這種方式直觀易懂，但需要 `O(n)` 額外空間。
2. 將串列切成前後兩段，反轉後半段，使原本的尾端節點可以由前往後取得，再把兩段交錯合併。這種方式只調整節點參考，因此額外空間為 `O(1)`。

不論採用哪一種方法，都必須注意最後一個節點的 `next` 應為 `null`，否則可能留下舊串列的指向並形成循環。

## 解法比較

| 解法 | 主要方法 | 時間複雜度 | 額外空間 | 特點 |
| --- | --- | ---: | ---: | --- |
| 解法一 | 線性集合＋左右指標 | `O(n)` | `O(n)` | 流程直接，容易理解與檢查 |
| 解法二 | 快慢指標＋反轉＋合併 | `O(n)` | `O(1)` | 不建立與節點數量相關的集合 |

兩個方法都直接修改傳入串列的節點連結，回傳型別皆為 `void`。

## 解法一：線性集合與左右指標

### 設計說明

`ReorderList` 先走訪整條串列，將每個 `ListNode` 參考依序存入 `List<ListNode>`。集合支援以索引直接取得任意節點，因此可以使用：

- `left`：從索引 `0` 向右移動。
- `right`：從最後一個索引向左移動。

每一輪先令左側節點指向右側節點，再令右側節點指向下一個左側節點。當兩個指標相遇時，中央節點就是重排後的尾端，最後將它的 `next` 設為 `null`。

### 執行步驟

1. 若 `head` 為 `null`，直接返回。
2. 從 `head` 開始走訪，把所有節點參考加入 `nodes`。
3. 設定 `left = 0`、`right = nodes.Count - 1`。
4. 當 `left < right`：
   - 將 `nodes[left].next` 接到 `nodes[right]`。
   - 將 `left` 向右移動。
   - 若指標仍未相遇，將 `nodes[right].next` 接到新的 `nodes[left]`，再將 `right` 向左移動。
5. 將指標相遇位置的節點設為串列尾端。

### 正確性要點

- `nodes` 保留原串列的節點順序，因此 `nodes[left]` 永遠是尚未使用的最前方節點，`nodes[right]` 永遠是尚未使用的最後方節點。
- 每一輪正好依照題目要求加入一個前端節點與一個尾端節點。
- 左右指標只會向中央收斂，每個節點恰好被安排一次。
- 最後截斷尾端節點，可確保重排後串列正常結束且不產生循環。

### 複雜度

- 時間複雜度：`O(n)`。收集節點與重新接線都各自走訪線性數量的節點。
- 額外空間複雜度：`O(n)`。線性集合保存全部 `n` 個節點參考。

### 範例演示流程

輸入：

```text
1 → 2 → 3 → 4 → 5
```

收集節點後：

```text
nodes = [1,2,3,4,5]
left = 0
right = 4
```

| 步驟 | 接線操作 | 指標變化 | 已確定的排列 |
| ---: | --- | --- | --- |
| 1 | `1.next = 5` | `left: 0 → 1` | `1 → 5` |
| 2 | `5.next = 2` | `right: 4 → 3` | `1 → 5 → 2` |
| 3 | `2.next = 4` | `left: 1 → 2` | `1 → 5 → 2 → 4` |
| 4 | `4.next = 3` | `right: 3 → 2` | `1 → 5 → 2 → 4 → 3` |
| 5 | `3.next = null` | 指標在索引 `2` 相遇 | 完成 |

結果：

```text
1 → 5 → 2 → 4 → 3
```

## 解法二：尋找中點、反轉與交錯合併

### 設計說明

`ReorderList2` 將問題拆成三個經典的鏈結串列操作：

1. 使用快慢指標找出前半段的最後一個節點。
2. 切開串列並原地反轉後半段。
3. 將前半段與反轉後的後半段交錯合併。

快指標每次走兩步，慢指標每次走一步。快指標抵達尾端時，慢指標會停在前半段的最後一個節點。將 `slow.next` 保存為後半段起點並把 `slow.next` 設為 `null`，即可安全分割兩段。

反轉後半段後，原串列的最後一個節點會成為第二段的頭節點。此時只需要同步向後走訪兩段，依序連接一個前半段節點和一個後半段節點。

### 執行步驟

1. 若串列為空或只有一個節點，直接返回。
2. 使用 `slow` 與 `fast` 找出中點：
   - `slow` 每輪前進一個節點。
   - `fast` 每輪前進兩個節點。
3. 從 `slow.next` 切出後半段，並以 `slow.next = null` 結束前半段。
4. 使用 `previous`、`second` 與暫存的 `next` 原地反轉後半段。
5. 使用 `first` 與 `second` 走訪兩段：
   - 保存兩段各自的下一個節點。
   - 將 `first` 接到 `second`。
   - 將 `second` 接回原本的下一個前半段節點。
   - 移動到兩段尚未合併的下一個節點。
6. 後半段全部合併後結束。

### 正確性要點

- 快慢指標能把串列切成長度相同或前半段多一個節點的兩段，因此合併時前半段不會先耗盡。
- 反轉後半段會把節點順序由 `Ln-k → … → Ln` 轉成 `Ln → … → Ln-k`，正好提供題目要求的尾端取用順序。
- 每次合併都加入一個前半段節點與一個反轉後半段節點，因此形成 `L0 → Ln → L1 → Ln-1 → …`。
- 切割時已將前半段尾端設為 `null`，反轉與合併過程也只使用保存過的下一個節點，不會遺失節點或形成循環。

### 複雜度

- 時間複雜度：`O(n)`。尋找中點、反轉與合併各自最多走訪線性數量的節點。
- 額外空間複雜度：`O(1)`。只使用固定數量的節點參考。

### 範例演示流程

輸入：

```text
1 → 2 → 3 → 4 → 5
```

#### 階段一：尋找中點並切割

| 狀態 | `slow` | `fast` |
| --- | ---: | ---: |
| 初始 | 1 | 1 |
| 第 1 輪 | 2 | 3 |
| 第 2 輪 | 3 | 5 |

`slow` 停在節點 `3`，切割後得到：

```text
前半段：1 → 2 → 3
後半段：4 → 5
```

#### 階段二：反轉後半段

```text
4 → 5
```

反轉為：

```text
5 → 4
```

#### 階段三：交錯合併

| 輪次 | 前半段節點 | 後半段節點 | 合併後已確定部分 |
| ---: | ---: | ---: | --- |
| 1 | 1 | 5 | `1 → 5` |
| 2 | 2 | 4 | `1 → 5 → 2 → 4` |
| 結束 | 3 | 後半段已耗盡 | `1 → 5 → 2 → 4 → 3` |

結果：

```text
1 → 5 → 2 → 4 → 3
```
