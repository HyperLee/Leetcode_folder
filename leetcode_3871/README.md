## 題目說明

給定一個整數 `n`，請計算從 `1` 到 `n`（包含兩端）的所有整數，
以標準數字格式書寫時總共使用了多少個逗號。

標準數字格式的規則是：

- 從數字右側開始，每三位數字插入一個逗號。
- 少於四位數的數字不包含逗號。

### 官方範例 1

```text
n = 1002
輸出 = 3
```

`1,000`、`1,001` 與 `1,002` 各包含一個逗號，因此總數為 `3`。

### 官方範例 2

```text
n = 998
輸出 = 0
```

`1` 到 `998` 都少於四位數，因此不需要逗號。

## 限制條件

依照 [LeetCode 官方題目頁](https://leetcode.com/problems/count-commas-in-range-ii/description/)：

- `1 <= n <= 10^15`

輸入上限可以到一千兆，因此不能逐一走訪並格式化 `1` 到 `n` 的每個整數。
此外，結果也可能超過 32 位元整數的範圍，所以程式使用 `long` 儲存輸入與答案。

本專案遵循 LeetCode 的輸入契約，不另外處理 `n <= 0` 或超出限制的輸入。

## 解題概念與出發點

直接把每個數字轉成字串雖然容易理解，但最多要處理 `10^15` 個數字，時間複雜度為 `O(n)`，
實際上不可行。解題的關鍵是不要逐一計算數字，而是逐一計算「某一個逗號位置」對答案的貢獻。

從右側每三位插入一個逗號，會形成下列門檻：

| 逗號位置 | 最小數字 | 會被計入的整數 |
| --- | ---: | --- |
| 第 1 個逗號 | `1,000` | `1,000` 到 `n` |
| 第 2 個逗號 | `1,000,000` | `1,000,000` 到 `n` |
| 第 3 個逗號 | `1,000,000,000` | `1,000,000,000` 到 `n` |
| 第 4 個逗號 | `1,000,000,000,000` | `1,000,000,000,000` 到 `n` |
| 第 5 個逗號 | `1,000,000,000,000,000` | `1,000,000,000,000,000` 到 `n` |

一般化後，第 `k` 個逗號的門檻是 `1000^k`。只要 `threshold <= n`，
區間 `[threshold, n]` 中的每個數字都會在該位置貢獻一次逗號，貢獻數量就是：

```text
n - threshold + 1
```

因此，答案不需要知道每個數字的完整格式，只要從 `threshold = 1000` 開始，
每次乘以 `1000`，並累加仍在 `n` 範圍內的門檻貢獻即可。

## 解法：門檻貢獻法

對應程式方法：`CountCommas(long n)`。

### 演算法流程

```text
totalCommas = 0
threshold = 1000

while threshold <= n:
    totalCommas += n - threshold + 1
    threshold *= 1000

return totalCommas
```

`threshold` 依序代表 `1000^1`、`1000^2`、`1000^3`……，也就是每一個可能出現的逗號位置。
當門檻大於 `n` 時，代表 `[1, n]` 中沒有任何數字能出現該位置的逗號，迴圈便會停止。

### 為什麼不只計算 `n - 999`？

在較小的題目中，如果 `n` 不會達到 `1,000,000`，可以只計算 `[1000, n]` 的長度。
本題的上限是 `10^15`，數字可能包含多個逗號，因此必須把每一個門檻分開累加。

例如 `1,000,000` 含有兩個逗號：

1. 第 1 個逗號的門檻是 `1000`，`1000` 到 `1,000,000` 共 `999,001` 個數字。
2. 第 2 個逗號的門檻是 `1,000,000`，該數字本身再貢獻 `1` 個逗號。
3. 總數為 `999,001 + 1 = 999,002`。

### 範例演示：`n = 1002`

1. `threshold = 1000`，區間 `[1000, 1002]` 有 `1002 - 1000 + 1 = 3` 個數字。
2. 這三個數字分別是 `1,000`、`1,001`、`1,002`，各貢獻一個逗號，累計為 `3`。
3. `threshold` 乘以 `1000` 後變成 `1,000,000`，已經大於 `1002`，迴圈停止。
4. 回傳 `3`。

### 範例演示：`n = 1,000,000`

| `threshold` | 計算 | 本輪貢獻 | 累計答案 |
| ---: | --- | ---: | ---: |
| `1,000` | `1,000,000 - 1,000 + 1` | `999,001` | `999,001` |
| `1,000,000` | `1,000,000 - 1,000,000 + 1` | `1` | `999,002` |
| `1,000,000,000` | 大於 `n`，停止 | `0` | `999,002` |

這個例子顯示，達到下一個門檻的數字會同時被前面所有逗號位置計數，
所以不能只用「含逗號的數字個數」代替逗號總數。

### 最大輸入演示：`n = 10^15`

每個門檻的貢獻如下：

| `threshold` | `n - threshold + 1` |
| ---: | ---: |
| `1,000` | `999,999,999,999,001` |
| `1,000,000` | `999,999,999,000,001` |
| `1,000,000,000` | `999,999,000,000,001` |
| `1,000,000,000,000` | `999,000,000,000,001` |
| `1,000,000,000,000,000` | `1` |

加總後得到 `3,998,998,998,999,005`，整個過程只需要處理五個門檻。

## 解法二：純數學公式

對應程式方法：`CountCommas2(long n)`。

### 公式推導

門檻貢獻法會用迴圈逐一走訪 `1000`、`1,000,000` 等門檻；在目前題目限制下，
也可以把所有可能的門檻直接展開成固定公式。

若某一個逗號位置的門檻為 `p`，則：

- `p` 到 `n` 之間共有 `n - p + 1` 個整數。
- 當 `n < p` 時，這個逗號位置沒有任何貢獻，貢獻為 `0`。
- 合併兩種情況後，貢獻可寫成 `max(n - p + 1, 0)`。

因為 `p = 1000^k`，所以本題的總和可以改寫成：

```text
F(n) = max(n - 999, 0)
     + max(n - 999999, 0)
     + max(n - 999999999, 0)
     + max(n - 999999999999, 0)
     + max(n - 999999999999999, 0)
```

每一項分別代表一個逗號位置：

| 逗號位置 | 門檻 `p` | 固定公式項目 | 意義 |
| --- | ---: | ---: | --- |
| 第 1 個逗號 | `1,000` | `max(n - 999, 0)` | `1,000` 到 `n` 的數量 |
| 第 2 個逗號 | `1,000,000` | `max(n - 999999, 0)` | `1,000,000` 到 `n` 的數量 |
| 第 3 個逗號 | `1,000,000,000` | `max(n - 999999999, 0)` | `1,000,000,000` 到 `n` 的數量 |
| 第 4 個逗號 | `1,000,000,000,000` | `max(n - 999999999999, 0)` | `1,000,000,000,000` 到 `n` 的數量 |
| 第 5 個逗號 | `1,000,000,000,000,000` | `max(n - 999999999999999, 0)` | `1,000,000,000,000,000` 到 `n` 的數量 |

### C# 實作

```csharp
return Math.Max(n - 999L, 0L)
    + Math.Max(n - 999_999L, 0L)
    + Math.Max(n - 999_999_999L, 0L)
    + Math.Max(n - 999_999_999_999L, 0L)
    + Math.Max(n - 999_999_999_999_999L, 0L);
```

程式不需要迴圈，也不需要逐一格式化每個整數；每一項都直接計算一個逗號位置的總貢獻。
這個寫法依賴題目的上限 `n <= 10^15`，若未來上限提高到 `10^18` 或更大，
就必須再加入相應的 `1000` 次方項目。

### 範例演示：`n = 1,000,000`

| 公式項目 | 計算 | 貢獻 |
| --- | --- | ---: |
| 第 1 個逗號 | `max(1_000_000 - 999, 0)` | `999,001` |
| 第 2 個逗號 | `max(1_000_000 - 999999, 0)` | `1` |
| 第 3～5 個逗號 | 門檻大於 `n` | `0` |

因此：

```text
999,001 + 1 = 999,002
```

這與門檻貢獻法的結果一致，也說明 `1,000,000` 會同時在第一個與第二個逗號位置各貢獻一次。

## 正確性說明

令 `threshold = 1000^k`，其中 `k >= 1`。

1. 一個整數至少有第 `k` 個逗號，當且僅當它大於或等於 `1000^k`。因此在 `[1, n]` 中，
   會在第 `k` 個位置貢獻逗號的整數正好是 `[threshold, n]`。
2. 若 `threshold <= n`，該區間包含 `n - threshold + 1` 個整數；每個整數在這個位置貢獻一次，
   所以這正是第 `k` 個逗號的全部貢獻。
3. 程式會枚舉所有不超過 `n` 的 `1000^k`。一個含有 `q` 個逗號的整數會被前 `q` 個門檻各計入一次，
   不會漏算或重複計算任何逗號。

因此，所有門檻貢獻的總和，正好等於從 `1` 到 `n` 的逗號總數。

### 解法二的正確性

對於解法二的每一項，令 `p = 1000^k`：

1. 若 `n >= p`，`max(n - (p - 1), 0)` 會得到 `n - p + 1`，正好是 `[p, n]` 的整數數量。
2. 若 `n < p`，該項會得到 `0`，正好表示 `[1, n]` 中沒有數字包含第 `k` 個逗號。
3. 五個公式項目涵蓋題目上限 `10^15` 內的所有可能逗號位置，因此加總後與門檻貢獻法計算同一組逗號貢獻。

所以，解法二只是把解法一的門檻迴圈在固定限制下展開，兩者會得到相同答案。

## 複雜度分析

- 解法一時間複雜度：`O(log_1000 n)`，也可寫成 `O(log n)`；每次迴圈跳到下一個千進位門檻。
- 解法二時間複雜度：在本題固定上限下為 `O(1)`；直接計算五個公式項目，不需要迴圈。
- 兩種解法的額外空間複雜度都是 `O(1)`。
- 整數型別：`long`；符合 `n <= 10^15` 與答案上限的需求。
