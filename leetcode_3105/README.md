# LeetCode 3105. 最長的嚴格遞增或嚴格遞減連續子陣列

## 題目與限制

給定整數陣列 `nums`，回傳最長的嚴格遞增或嚴格遞減連續子陣列的長度。答案是元素個數。子陣列必須保留起點與終點之間的所有元素。

- 嚴格遞增表示每個元素都大於前一個，例如 `[1, 3, 5]`。
- 嚴格遞減表示每個元素都小於前一個，例如 `[5, 3, 1]`。
- 兩個相鄰元素相等時，兩種方向都無法跨過這一對。
- 單一元素沒有相鄰元素需要比較，所以兩種條件都成立，答案至少是 `1`。

題目保證 `1 ≤ nums.Length ≤ 50`，且每個元素都滿足 `1 ≤ nums[i] ≤ 50`。

| 官方範例輸入 | 輸出 | 原因 |
| --- | ---: | --- |
| `[1, 4, 3, 3, 2]` | 2 | `[1, 4]`、`[4, 3]` 和 `[3, 2]` 都合法。轉折與相等使它們無法繼續延伸。 |
| `[3, 3, 3, 3]` | 1 | 任意相鄰元素都相等，只有單元素區段合法。 |
| `[3, 2, 1]` | 3 | 整段嚴格遞減。 |

[LeetCode 官方題目](https://leetcode.com/problems/longest-strictly-increasing-or-strictly-decreasing-subarray/description/) · [題意與官方範例詳解](PROBLEM_EXPLANATION.md)

## 解題出發點

把陣列想成一串相鄰比較。以兩個方法共用的演示輸入 `[1, 4, 3, 3, 2, 1]` 為例，比較結果是 `1 < 4 > 3 = 3 > 2 > 1`。連續出現的 `<` 可以組成遞增段，連續出現的 `>` 可以組成遞減段。兩個連續的 `>` 連接三個元素，所以末尾 `[3, 2, 1]` 的長度是 `3`。

由於只要知道相鄰比較能否延續，就能決定目前區段的長度，可以掃描陣列並在區段結束時更新答案。第一種方法同時追蹤兩個方向，第二種方法每次追蹤一個方向直到該段結束。

## 方法一：雙計數器

`LongestMonotonicSubarray` 逐一比較 `nums[i - 1]` 和 `nums[i]`。`cnt1` 追蹤嚴格遞增的長度，`cnt2` 追蹤嚴格遞減的長度。兩者記錄的區段都必須結尾於目前掃描到的位置。`ans` 則記錄已結算區段中的最大長度，初始為 `1`。

迴圈從 `i = 1` 開始。在這一輪比較之前，只處理過索引 `0`，所以兩個計數器都是 `1`。一般來說，進入第 `i` 輪時，兩個計數器記的是以 `i - 1` 結尾的長度。這一輪依照各自方向更新後，它們才變成以 `i` 結尾的長度。

| 相鄰元素的關係 | 遞增計數器 `cnt1` | 遞減計數器 `cnt2` |
| --- | --- | --- |
| 目前值大於前一個 | 加 `1` | 先更新 `ans`，再重設為 `1` |
| 目前值小於前一個 | 先更新 `ans`，再重設為 `1` | 加 `1` |
| 目前值等於前一個 | 先更新 `ans`，再重設為 `1` | 先更新 `ans`，再重設為 `1` |

若相鄰比較符合某個方向，以 `i - 1` 結尾的最長區段就能直接接上 `nums[i]`，計數器加 `1`。若比較不符合該方向，任何跨過這一對的區段都會違反嚴格條件。先把舊計數器納入 `ans`，再重設為 `1`，代表以 `nums[i]` 單獨開一段。如果先重設，就會丟失剛結束的那段長度。

### 逐步演示

輸入 `[1, 4, 3, 3, 2, 1]`。圖中的比較符號位於兩個元素之間，狀態順序為 `(cnt1, cnt2, ans)`。

```text
index:   0   1   2   3   4   5
nums:    1 < 4 > 3 = 3 > 2 > 1

i = 2    (2, 1, 1) -> (1, 2, 2)
         [1, 4] ends; [4, 3] grows

i = 3    (1, 2, 2) -> (1, 1, 2)
         3 = 3 breaks both directions

end      (1, 3, 2) -> (1, 3, 3)
         ans = Math.Max(2, Math.Max(1, 3))
```

在索引 `2`，`4 > 3` 讓遞增段 `[1, 4]` 結束。此時舊的 `cnt1 = 2` 讓 `ans` 更新為 `2`，接著 `cnt1` 從目前的 `3` 重新計為 `1`。同一對元素也把遞減段延伸為 `[4, 3]`。到了索引 `3`，相等同時中斷兩個方向，兩個計數器都從第二個 `3` 重新計算。

最後一輪把遞減段延伸成 `[3, 2, 1]`，所以 `cnt2 = 3`。這一輪結算的是中斷的遞增段，其長度只有 `1`，因此 `ans` 仍是 `2`。迴圈後再比較 `ans` 和兩個計數器，末尾的遞減段才納入答案。

下表列出每輪完成後的狀態。

| `i` | 相鄰比較 | `cnt1` | `cnt2` | `ans` | 說明 |
| --- | --- | ---: | ---: | ---: | --- |
| 0 | 初始化 | 1 | 1 | 1 | 第一個元素可單獨成段。 |
| 1 | `1 < 4` | 2 | 1 | 1 | 遞增段延伸成 `[1, 4]`，遞減長度從 `4` 重新計算。 |
| 2 | `4 > 3` | 1 | 2 | 2 | 結算 `[1, 4]`，遞減段延伸成 `[4, 3]`。 |
| 3 | `3 = 3` | 1 | 1 | 2 | 兩個方向都中斷，從第二個 `3` 重新計算。 |
| 4 | `3 > 2` | 1 | 2 | 2 | 遞減段延伸成 `[3, 2]`。 |
| 5 | `2 > 1` | 1 | 3 | 2 | 遞減段延伸成 `[3, 2, 1]`，長度暫存在 `cnt2`。 |
| — | 末尾結算 | 1 | 3 | 3 | `Math.Max(2, Math.Max(1, 3))` 得到答案 `3`。 |

## 方法二：依方向分段

`LongestMonotonicSubarray2` 從左到右找出無法再延伸的嚴格遞增或遞減區段。`ans` 初始為 `1`，已涵蓋單元素與全部相等的情況。

1. 外層迴圈以 `i` 為候選段首，且只在右邊還有元素時檢查 `nums[i]` 和 `nums[i + 1]`。若兩者相等，就把 `i` 加 `1`，讓右側元素成為下一個候選段首。
2. 第一對不相等的元素決定這一段的方向。把段首存到 `j`，並以布林值 `inc` 記錄是否遞增。前兩個元素已經納入區段，因此 `i += 2` 後從第三個位置開始檢查。
3. 進入內層迴圈後，`i` 改為下一個待檢查的索引，`j` 繼續保存段首。三個條件用 `&&` 相連，由左到右檢查。先判斷 `i < n`，讓 `i == n` 時可以停止而不讀取 `nums[i]`。接著排除相等，因為相等和小於都會讓「目前值大於前一個值」得到 `false`。最後才把這個比較結果與 `inc` 核對。只要三個條件都成立，就納入目前元素並將 `i` 加 `1`。
4. 內層迴圈停止時，最後納入的是 `i - 1`，所以半開區間 `[j, i)` 包含 `i - j` 個元素。更新 `ans` 後執行 `i--`，讓上一段的最後一個元素也能作為下一段的起點。若相等導致上一段結束，下一輪會依步驟 1 跳過那個配對。

任何長度至少為 `2` 的合法子陣列，都在某一段可以沿同一方向延伸到底的區段內。因此只要比較這些區段的完整長度，就能找到最大值。轉折點可以同時是前一段的終點和下一段的起點。

### 逐步演示

沿用 `[1, 4, 3, 3, 2, 1]`。圖中的 `J` 是段首 `j`，`L` 是最後納入的索引 `i - 1`，`I` 是內層停止時的 `i`。相等配對發生在外層，該輪還沒有設定段首，因此用 `A` 和 `B` 標出正在比較的兩個位置。

```text
index   | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
nums    | 1 | 4 | 3 | 3 | 2 | 1 | - |
--------+---+---+---+---+---+---+---+
[0, 2)  | J | L | I |   |   |   |   | turn:   i-- -> 1
[1, 3)  |   | J | L | I |   |   |   | equal:  i-- -> 2
skip    |   |   | A | B |   |   |   | A == B: i++ -> 3
[3, 6)  |   |   |   | J |   | L | I | end:    i-- -> 5
```

第一輪從索引 `0` 的 `1` 起段。索引 `1` 的 `4` 確立遞增方向，這兩個元素已納入，所以 `i += 2` 後直接檢查索引 `2`。索引 `2` 的 `3` 無法接在 `4` 後面形成遞增段，`i` 就停在 `2`。已納入的是索引 `0` 到 `1`，因此 `[j, i) = [0, 2)` 的長度是 `2 - 0 = 2`。

第一段結算後，`i--` 回到索引 `1` 的 `4`，下一輪因此能比較 `4` 和第一個 `3`，組成 `[4, 3]`。這個遞減段遇到第二個 `3` 時中斷，結算後回到索引 `2`。外層發現索引 `2` 和 `3` 相等，就從索引 `2` 前進到 `3`，保留第二個 `3` 作為候選段首。它與後面的 `2` 建立遞減方向，再納入 `1`。此時 `i = 6` 到達陣列右端，段長是 `6 - 3 = 3`。

| 外層起點 `i` | `j` | 方向 | 停止原因與當下的 `i` | 區段與長度 | `ans` | 下一個 `i` |
| ---: | ---: | --- | --- | --- | ---: | ---: |
| 0 | 0 | 遞增 | 索引 `2` 的 `3` 小於前一個 `4`，故 `i = 2`。 | `[0, 2)` → `[1, 4]`，長度 `2` | 2 | 1 |
| 1 | 1 | 遞減 | 索引 `3` 的 `3` 等於前一個 `3`，故 `i = 3`。 | `[1, 3)` → `[4, 3]`，長度 `2` | 2 | 2 |
| 2 | — | — | 段首配對 `3 = 3`，直接跳過這一對。 | — | 2 | 3 |
| 3 | 3 | 遞減 | 索引 `5` 的 `1` 可接在 `2` 後面，之後 `i = 6` 到達陣列末端。 | `[3, 6)` → `[3, 2, 1]`，長度 `3` | 3 | 5 |

最後一段結算後，`i--` 讓 `i` 回到索引 `5`。此處右側已沒有元素，外層迴圈結束並回傳 `3`。

## 複雜度比較

設 `n = nums.Length`。以下複雜度只計算解法本身。

| 解法 | 維護的狀態 | 時間 | 額外空間 |
| --- | --- | --- | --- |
| 雙計數器 | 兩種方向在目前位置的長度，以及已結算的最大值。 | `O(n)` | `O(1)` |
| 依方向分段 | 目前區段的起點、方向、下一個待檢查的位置，以及最大值。 | `O(n)` | `O(1)` |

方法一對每對相鄰元素執行固定次數的比較。方法二雖然有兩層迴圈，但內層只向右延伸。每段至少納入兩個元素，即使 `i--`，下一輪段首也至少前進一格。段尾停止時的配對只會在下一輪再檢查一次，所以總時間仍是 `O(n)`。
