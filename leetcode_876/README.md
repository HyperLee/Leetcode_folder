## 題目說明

給定一個非空單向鏈結串列的頭節點 `head`，請回傳鏈結串列的中間節點。回傳值是一個節點參考，因此從該節點沿著 `next` 繼續走訪，就會得到中間節點到原串列尾端的完整尾段。

若串列長度為奇數，只有一個中間節點：

```text
輸入：1 -> 2 -> 3 -> 4 -> 5
中點：          3
輸出：3 -> 4 -> 5
```

若串列長度為偶數，會有兩個中間節點，題目要求回傳第二個：

```text
輸入：1 -> 2 -> 3 -> 4 -> 5 -> 6
中點：          3    4
回傳：               4 -> 5 -> 6
```

題目連結：

- [LeetCode 876. Middle of the Linked List](https://leetcode.com/problems/middle-of-the-linked-list/)
- [力扣 876. 链表的中间结点](https://leetcode.cn/problems/middle-of-the-linked-list/description/)

## 限制條件與輸入前提

- 鏈結串列的節點數量介於 `1` 與 `100` 之間。
- `1 <= Node.val <= 100`
- 輸入是至少含一個節點的無環單向鏈結串列。
- 偶數長度必須回傳兩個中間節點中的第二個。

> [!NOTE]
> `MiddleNode` 與 `MiddleNode2` 依照題目契約接受有效、非空輸入，不額外處理 `null` 頭節點或環狀串列。

## 解題概念與出發點

單向鏈結串列不能像陣列一樣直接以索引讀取 `head[n / 2]`。若要找到中點，至少需要透過 `next` 逐步走訪節點。

這個限制帶出兩種思考方式：

1. **先取得長度，再走到中間位置。**
   第一次走完整條串列得到長度 `n`，第二次從頭走 `n / 2` 步。
2. **讓兩個指標以不同速度前進。**
   快指標走過的距離是慢指標的兩倍；快指標到達尾端時，慢指標剛好走完整體的一半。

兩種解法都不建立新的答案串列，而是直接回傳原串列中的中間節點。主控台驗證器會將回傳節點到尾端的所有值轉成陣列，再和預期尾段逐項比較，避免只比較中點值而漏掉鏈結錯誤。

## 解法一：快慢指標

主要方法為 `MiddleNode(ListNode head)`。

### 核心設計

同時從 `head` 放置兩個指標：

- `slow`：每輪前進一個節點。
- `fast`：每輪前進兩個節點。

迴圈必須同時確認：

```csharp
fast is not null && fast.next is not null
```

這代表快指標目前存在，而且至少還能安全地走出第一步。每輪結束後：

- `slow` 累計前進 1 步。
- `fast` 累計前進 2 步。

因此，當快指標走到串列尾端時，慢指標正好位於中間位置。

### 為什麼偶數長度會選到第二個中點

假設節點數為 `n = 6`。迴圈會執行 `n / 2 = 3` 次，慢指標從索引 `0` 前進至索引 `3`，也就是第 4 個節點。

```text
索引：  0    1    2    3    4    5
節點：  1 -> 2 -> 3 -> 4 -> 5 -> 6
                         ^
                     第二個中點
```

不需要額外判斷奇偶數；停止條件本身就會產生題目要求的結果。

### 正確性理由

每完成一輪：

- 慢指標走過 `k` 條鏈結。
- 快指標走過 `2k` 條鏈結。

當快指標無法再前進兩步時，它已抵達尾端或最後一個節點。此時慢指標走過的距離是整體長度的一半：

- 奇數長度 `2k + 1`：慢指標位於唯一中點索引 `k`。
- 偶數長度 `2k`：慢指標位於索引 `k`，也就是第二個中點。

因此回傳 `slow` 符合兩種長度的題目要求。

### 範例演示：`[1, 2, 3, 4, 5, 6]`

| 階段 | `slow` | `fast` | 說明 |
| --- | ---: | ---: | --- |
| 初始 | 1 | 1 | 兩個指標都從頭節點開始 |
| 第 1 輪 | 2 | 3 | 慢指標走 1 步，快指標走 2 步 |
| 第 2 輪 | 3 | 5 | 兩者維持 1:2 的移動距離 |
| 第 3 輪 | 4 | `null` | 快指標越過尾端，迴圈結束 |

慢指標停在節點 `4`，因此回傳：

```text
4 -> 5 -> 6
```

### 複雜度

- 時間複雜度：`O(n)`，只需要一次走訪。
- 額外空間複雜度：`O(1)`，只保存 `slow` 與 `fast` 兩個節點參考。
- 回傳結果：`O(1)`，回傳原串列中的節點參考，不複製尾段。

## 解法二：兩次走訪

主要方法為 `MiddleNode2(ListNode head)`。

### 核心設計

這個解法把工作分成兩個明確階段。

第一次走訪：

1. 從 `head` 開始。
2. 每遇到一個節點就將 `length` 加一。
3. 走到 `null` 時，`length` 就是總節點數。

第二次走訪：

1. 將指標重新放回 `head`。
2. 前進 `length / 2` 步。
3. 回傳目前節點。

C# 的整數除法會捨去小數：

- `5 / 2 = 2`，從索引 0 前進 2 步，抵達索引 2 的唯一中點。
- `6 / 2 = 3`，從索引 0 前進 3 步，抵達索引 3 的第二個中點。

### 正確性理由

節點索引從 `0` 開始。長度為 `n` 時：

- 奇數長度 `n = 2k + 1` 的唯一中點索引為 `k`，而 `n / 2 = k`。
- 偶數長度 `n = 2k` 的兩個中點索引為 `k - 1` 與 `k`，而 `n / 2 = k`，正好選到第二個。

因此第二次走訪前進 `n / 2` 步後，必定停在題目要求的節點。

### 範例演示：`[1, 2, 3, 4, 5, 6]`

第一次走訪依序計數：

```text
1 -> 2 -> 3 -> 4 -> 5 -> 6 -> null
length = 6
```

計算目標步數：

```text
length / 2 = 6 / 2 = 3
```

第二次走訪：

| 已前進步數 | 目前節點 |
| ---: | ---: |
| 0 | 1 |
| 1 | 2 |
| 2 | 3 |
| 3 | 4 |

前進 3 步後停在節點 `4`，因此回傳：

```text
4 -> 5 -> 6
```

### 複雜度

- 時間複雜度：`O(n)`。第一次走 `n` 個節點，第二次走 `n / 2` 個節點，總計仍為線性時間。
- 額外空間複雜度：`O(1)`，只保存計數與節點參考。
- 回傳結果：`O(1)`，回傳原串列中的節點參考，不複製尾段。

## 解法比較

| 方法 | 走訪次數 | 時間複雜度 | 額外空間 | 特點 |
| --- | ---: | ---: | ---: | --- |
| `MiddleNode` | 一次 | `O(n)` | `O(1)` | 快慢指標直接利用速度比例定位中點 |
| `MiddleNode2` | 兩次 | `O(n)` | `O(1)` | 先知道長度，目標索引直觀清楚 |

快慢指標在漸進複雜度相同的情況下只需一次走訪，通常是這題更精簡的選擇。兩次走訪則清楚呈現「中點索引為 `n / 2`」的定義，適合作為對照解法。
