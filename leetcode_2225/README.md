## 題目說明

給定整數不規則陣列 `matches`，其中 `matches[i] = [winner_i, loser_i]` 表示玩家 `winner_i` 在第 `i` 場比賽擊敗玩家 `loser_i`。

請找出所有參加過比賽，而且符合下列條件的玩家：

1. 從未輸過任何比賽。
2. 恰好輸過一場比賽。

回傳兩個清單 `answer`：

- `answer[0]`：所有從未輸過的玩家編號，依遞增順序排列。
- `answer[1]`：所有恰好輸過一場的玩家編號，依遞增順序排列。

### 限制條件

- `1 <= matches.length <= 10^5`
- `matches[i].length == 2`
- `1 <= winner_i, loser_i <= 10^5`
- `winner_i != loser_i`
- 所有比賽記錄皆不重複。

### 主要範例

```text
matches = [[1,3],[2,3],[3,6],[5,6],[5,7],[4,5],[4,8],[4,9],[10,4],[10,9]]
answer  = [[1,2,10],[4,5,7,8]]
```

玩家 1、2、10 從未輸過；玩家 4、5、7、8 各輸一場；玩家 3、6、9 各輸兩場，因此不屬於第二組。

## 解題概念與出發點

題目只關心每位參賽玩家的敗場數是否為 0、1 或大於 1。因此不需要保存完整對戰圖，也不需要計算勝場總數。處理每場比賽時，只要確保勝方已被登記為參賽者，並更新敗方的敗場狀態即可。

本專案提供兩種觀察角度：

- `FindWinners` 直接維護三種敗場狀態，重點在玩家如何於集合之間轉移。
- `FindWinners2` 記錄精確敗場數，重點在統一計數後再篩選答案。

## 解法比較

| 解法 | 核心資料結構 | 掃描比賽 | 排序 | 空間 |
| --- | --- | --- | --- | --- |
| `FindWinners` | 三個 `HashSet<int>` | `O(m)` | `O(p log p)` | `O(p)` |
| `FindWinners2` | `Dictionary<int, int>` | `O(m)` | `O(p log p)` | `O(p)` |

其中 `m` 是比賽數量，`p` 是不同參賽玩家數量。兩種解法的整體時間複雜度皆為 `O(m + p log p)`，排序是最壞情況下的主要成本；額外空間皆為 `O(p)`。

## 解法一：HashSet 狀態分類

`FindWinners` 使用三個互斥集合表示玩家目前的敗場分類：

- `noLosers`：已參賽且目前零敗。
- `oneLosers`：目前恰好一敗。
- `manyLosers`：目前至少兩敗，之後無須再計算精確次數。

處理 `[winner, loser]` 時：

1. 若勝方不在 `oneLosers` 或 `manyLosers`，將其加入 `noLosers`。這能登記首次出現的勝方，也不會錯把曾輸過的玩家恢復為零敗。
2. 若敗方在 `noLosers`，將其從零敗移到一敗。
3. 若敗方在 `oneLosers`，將其從一敗移到多敗。
4. 若敗方尚未出現在任何集合，代表這是其首次出現且首次落敗，直接加入 `oneLosers`。
5. 已在 `manyLosers` 的玩家繼續留在多敗集合。

掃描完成後，只有 `noLosers` 與 `oneLosers` 需要排序並回傳。

### 正確性直覺

每位已出現的玩家始終只屬於一個敗場集合。勝方紀錄不會改變敗場狀態；敗方每次只會沿著「未登記／零敗 → 一敗 → 多敗」前進，不可能逆向移動。因此掃描完全部比賽後，前兩個集合恰好就是題目要求的兩組玩家。

### 範例演示流程

集合內容以下皆以遞增順序顯示，實際 `HashSet` 不保證列舉順序。

| 比賽 | `noLosers` | `oneLosers` | `manyLosers` | 關鍵轉移 |
| --- | --- | --- | --- | --- |
| `[1,3]` | `{1}` | `{3}` | `{}` | 1 首次獲勝；3 首次落敗 |
| `[2,3]` | `{1,2}` | `{}` | `{3}` | 3 由一敗轉為多敗 |
| `[3,6]` | `{1,2}` | `{6}` | `{3}` | 3 曾輸過，不能列為零敗；6 首次落敗 |
| `[5,6]` | `{1,2,5}` | `{}` | `{3,6}` | 5 加入零敗；6 轉為多敗 |
| `[5,7]` | `{1,2,5}` | `{7}` | `{3,6}` | 7 首次落敗 |
| `[4,5]` | `{1,2,4}` | `{5,7}` | `{3,6}` | 4 加入零敗；5 由零敗轉為一敗 |
| `[4,8]` | `{1,2,4}` | `{5,7,8}` | `{3,6}` | 8 首次落敗 |
| `[4,9]` | `{1,2,4}` | `{5,7,8,9}` | `{3,6}` | 9 首次落敗 |
| `[10,4]` | `{1,2,10}` | `{4,5,7,8,9}` | `{3,6}` | 10 加入零敗；4 轉為一敗 |
| `[10,9]` | `{1,2,10}` | `{4,5,7,8}` | `{3,6,9}` | 9 由一敗轉為多敗 |

最後回傳 `[[1,2,10],[4,5,7,8]]`。

## 解法二：Dictionary 敗場計數

`FindWinners2` 使用 `Dictionary<int, int>`，鍵是玩家編號，值是敗場數。

處理 `[winner, loser]` 時：

1. 若勝方尚未在字典中，將其敗場數初始化為 0。若勝方已存在，保留原有敗場數。
2. 以 `GetValueOrDefault(loser) + 1` 更新敗方；首次出現的敗方會由預設值 0 變成 1。
3. 掃描完成後，將值為 0 與 1 的鍵分別收集到兩個清單。
4. 分別排序兩個清單，以符合題目的輸出順序。

### 正確性直覺

每場比賽只替敗方增加一次敗場，勝方只在首次出現時以 0 登記。因此字典最後包含所有參賽玩家，而且每個值正好等於該玩家的總敗場數。篩選值為 0 與 1 的玩家，便會得到題目要求的兩組答案。

### 範例演示流程

| 比賽 | 處理後的敗場紀錄 | 本場重點 |
| --- | --- | --- |
| `[1,3]` | `1:0, 3:1` | 登記 1，3 敗場加一 |
| `[2,3]` | `1:0, 2:0, 3:2` | 登記 2，3 累積第二敗 |
| `[3,6]` | `1:0, 2:0, 3:2, 6:1` | 3 的既有敗場不變，6 首敗 |
| `[5,6]` | `1:0, 2:0, 3:2, 5:0, 6:2` | 登記 5，6 累積第二敗 |
| `[5,7]` | `1:0, 2:0, 3:2, 5:0, 6:2, 7:1` | 7 首敗 |
| `[4,5]` | `1:0, 2:0, 3:2, 4:0, 5:1, 6:2, 7:1` | 登記 4，5 首敗 |
| `[4,8]` | `... 4:0, 8:1` | 8 首敗 |
| `[4,9]` | `... 4:0, 9:1` | 9 首敗 |
| `[10,4]` | `... 10:0, 4:1` | 登記 10，4 首敗 |
| `[10,9]` | `... 10:0, 9:2` | 9 累積第二敗 |

最終敗場為 0 的玩家是 `1、2、10`；敗場為 1 的玩家是 `4、5、7、8`。排序後回傳 `[[1,2,10],[4,5,7,8]]`。
