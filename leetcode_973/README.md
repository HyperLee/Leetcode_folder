# LeetCode 973：最接近原點的 K 個點

[![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4?logo=dotnet)](https://dotnet.microsoft.com/)

這是一個以 .NET 10 撰寫的可執行教學範例。專案實作「先依平方距離完整排序，
再取出前 `k` 個點」的直觀解法，並以七組固定案例驗證答案。驗證時不要求回傳
順序一致，但會正確保留重複座標的出現次數。

- 題目：[K Closest Points to Origin](https://leetcode.com/problems/k-closest-points-to-origin/)
- 專案：`leetcode_973/leetcode_973.csproj`
- 目標框架：`.NET 10`

## 題目說明

給定二維平面上的座標陣列 `points`，其中 `points[i] = [xi, yi]`，以及整數
`k`，請回傳距離原點 `(0, 0)` 最近的 `k` 個點。

兩點 `(x1, y1)` 與 `(x2, y2)` 的歐幾里得距離為：

```text
√((x1 - x2)² + (y1 - y2)²)
```

本題只比較各點與原點的距離，因此公式可簡化為：

```text
√(x² + y²)
```

答案可以任意順序回傳；除了順序以外，題目保證答案唯一。

### 官方範例一

```text
輸入：points = [[1, 3], [-2, 2]], k = 1
輸出：[[-2, 2]]
```

`[1, 3]` 的距離為 `√10`，`[-2, 2]` 的距離為 `√8`，所以距離較近的
`[-2, 2]` 是唯一答案。

### 官方範例二

```text
輸入：points = [[3, 3], [5, -1], [-2, 4]], k = 2
輸出：[[3, 3], [-2, 4]]
```

`[[-2, 4], [3, 3]]` 也同樣是合法答案，因為題目不限制回傳順序。

### 限制條件

- `1 <= k <= points.Length <= 10^4`
- `points[i].Length == 2`
- `-10^4 <= xi, yi <= 10^4`

## 解題概念與出發點

### 為什麼比較平方距離即可

若兩個非負距離分別為 `d1` 與 `d2`，平方根函式在非負範圍內單調遞增，
所以：

```text
√d1 < √d2  等價於  d1 < d2
```

因此，不需要真的計算 `√(x² + y²)`；直接比較 `x² + y²` 就能得到相同的
遠近順序。這樣有三個好處：

1. 省略不必要的開根號運算。
2. 全程使用整數，不會引入浮點數比較誤差。
3. 排序比較式更容易閱讀與驗證。

在題目給定的座標界限內，最大平方距離為：

```text
10000² + 10000² = 200000000
```

此值小於 `int.MaxValue`，所以目前的 `int` 計算安全。

### 為什麼選擇完整排序

最直接的想法是先知道每個點離原點多遠，再依距離由小到大排列。排序完成後，
答案必然位於陣列前 `k` 個位置，因此只需複製這一段作為結果。

這個方法未必在所有情境下擁有最佳漸近複雜度，但步驟清楚、容易證明正確，
也能直接利用標準函式庫的 `Array.Sort`，很適合作為本題的第一個教學實作。

## 已實作解法：依平方距離完整排序

### 設計步驟

`KClosest` 依序完成以下工作：

1. 對每個座標 `[x, y]` 計算平方距離 `x² + y²`。
2. 使用 `Array.Sort` 依平方距離由小到大重新排列 `points`。
3. 建立長度為 `k` 的結果陣列。
4. 使用 `Array.Copy` 複製排序後的前 `k` 個座標。
5. 回傳結果；題目允許這些座標採任意順序。

比較器使用 `SquaredDistance(first).CompareTo(SquaredDistance(second))`，而不是
直接相減。這樣能直接表達「比較兩個距離」，也避免在未來放寬數值範圍時，
兩個距離相減可能溢位的風險。

### 正確性說明

令 `distance(point) = x² + y²`。

排序完成後，對任何索引 `i < j`，都有：

```text
distance(points[i]) <= distance(points[j])
```

因此，陣列前 `k` 個位置不可能有任一點比第 `k + 1` 個及其後方的點更遠。
換句話說，前 `k` 個位置恰好包含距離原點最近的 `k` 個點。複製並回傳這些
位置，便得到符合題意的答案。

### 輸入副作用

`Array.Sort` 會原地重新排列傳入的外層 `points` 陣列，因此 `KClosest` 具有
輸入排序副作用。方法回傳的新外層陣列只包含前 `k` 個參考；其中的內層座標
陣列仍與原輸入共用。

console 驗證器為每個案例建立深層副本後才呼叫 `KClosest`，避免原地排序污染
固定測資，也確保各案例彼此獨立。

### 複雜度

設 `n = points.Length`：

| 項目 | 複雜度 | 說明 |
| --- | --- | --- |
| 時間 | `O(n log n)` | 完整排序主導總時間；複製前 `k` 個點另需 `O(k)` |
| 排序額外空間 | `O(log n)` | `Array.Sort` 排序過程所需的堆疊空間 |
| 回傳空間 | `O(k)` | 新外層結果陣列保存 `k` 個座標參考 |

## 範例演示流程

以官方範例二 `points = [[3, 3], [5, -1], [-2, 4]]`、`k = 2` 為例：

### 1. 計算平方距離

| 座標 | 計算 | 平方距離 |
| --- | --- | ---: |
| `[3, 3]` | `3² + 3²` | `18` |
| `[5, -1]` | `5² + (-1)²` | `26` |
| `[-2, 4]` | `(-2)² + 4²` | `20` |

### 2. 依平方距離排序

```text
[[3, 3], [-2, 4], [5, -1]]
   18        20        26
```

### 3. 取出前 k 個點

`k = 2`，所以複製前兩個座標：

```text
[[3, 3], [-2, 4]]
```

這就是距離原點最近的兩個點。若回傳順序為 `[[-2, 4], [3, 3]]`，也同樣正確。

## 其他可行方法比較

本專案目前只實作「完整排序」。下表中的最大堆積與 Quickselect 用來說明
設計取捨，不代表程式已提供這兩種 API。

| 方法 | 時間複雜度 | 額外空間 | 適用情境與取捨 |
| --- | --- | --- | --- |
| 完整排序（已實作） | `O(n log n)` | 排序 `O(log n)`，結果 `O(k)` | 最直觀，排序後還可直接取得完整距離順序 |
| 大小為 `k` 的最大堆積 | `O(n log k)` | `O(k)` | 當 `k` 遠小於 `n` 時可避免排序全部資料，但實作與維護較複雜 |
| Quickselect | 平均 `O(n)`，最差 `O(n²)` | 依實作而定 | 只需切分出前 `k` 個點，不保證內部有序；樞紐選擇會影響最差情況 |

若需求只是一次取得答案，而且 `k` 很小，最大堆積通常更有吸引力；若追求
平均線性時間，可考慮 Quickselect。此教學範例優先選擇容易理解與驗證的完整
排序版本。
