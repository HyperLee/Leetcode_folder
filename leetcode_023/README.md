## 題目說明

給定一個包含 `k` 條鏈表的陣列 `lists`。每條鏈表都已依非遞減順序排列，請將所有節點合併成一條升序鏈表並回傳其首節點。

題目來源：[LeetCode 23. Merge k Sorted Lists](https://leetcode.com/problems/merge-k-sorted-lists/description/)

### 官方範例

```text
輸入：[[1,4,5],[1,3,4],[2,6]]
輸出：[1,1,2,3,4,4,5,6]
```

三條輸入鏈表為：

```text
1 -> 4 -> 5
1 -> 3 -> 4
2 -> 6
```

合併後：

```text
1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6
```

## 限制條件

以下限制依官方題目頁整理：

- `k == lists.length`
- `0 <= k <= 10^4`
- `0 <= lists[i].length <= 500`
- `-10^4 <= lists[i][j] <= 10^4`
- 每條 `lists[i]` 都已依非遞減順序排列。
- 所有鏈表的節點總數不超過 `10^4`。

程式介面額外容許 `lists` 本身為 `null`，並將它視為沒有可合併的節點。

## 解題概念與出發點

### 從「合併兩條鏈表」擴展到 K 條鏈表

合併兩條升序鏈表時，只需要比較兩邊目前的首節點：

1. 取出值較小的節點。
2. 將它接到結果尾端。
3. 讓被取出的那一側前進一格。
4. 某一側耗盡時，把另一側剩餘節點整段接上。

若直接依序合併 K 條鏈表，前面形成的累積鏈表會愈來愈長，後面的每次合併都要重新走過大量節點。當各鏈表長度接近時，最壞成本可能接近 `O(Nk)`。

本專案改採平衡的兩兩合併。每個節點在每一層至多被處理一次，而合併層數約為 `log k`，因此兩種解法都能達到 `O(N log k)`：

```text
第 1 層：K 條鏈表兩兩合併
第 2 層：約 K/2 條結果再兩兩合併
...
最後一層：合併成 1 條鏈表
```

其中：

- `k` 是輸入鏈表數量。
- `N` 是所有鏈表的節點總數。

### 節點重用與輸入隔離

兩種解法都直接重用原有 `ListNode`，只改寫節點的 `next` 指標，不為輸出結果複製節點。這能節省節點配置，但代表呼叫完成後，原輸入鏈表的串接關係可能已改變。

範例驗證因此不會把同一組節點依序交給兩種解法，而是從同一份 `int[][]` 規格各自重建獨立鏈表，確保解法一的副作用不會污染解法二。

## 解法一：Top-down 分治與遞迴合併

### 設計說明

`MergeKLists` 先檢查空輸入，再呼叫 `MergeSort` 處理完整索引區間。

`MergeSort(lists, left, right)` 的核心不變量是：回傳值必須是 `lists[left..right]` 之內所有節點組成的升序鏈表。

處理流程：

1. `left == right` 時，區間只剩一條鏈表，直接回傳。
2. 使用 `left + (right - left) / 2` 計算中點，避免直接相加的溢位風險。
3. 遞迴取得左半區間與右半區間的合併結果。
4. 呼叫 `MergeTwoListsRecursive` 合併兩個已排序結果。

`MergeTwoListsRecursive` 每次比較兩個首節點：

- 左側值較小時，左節點成為目前答案的首節點，再遞迴合併 `left.next` 與 `right`。
- 否則右節點成為目前答案的首節點，再遞迴合併 `left` 與 `right.next`。
- 任一側為空時，另一側可以直接接到結果。

### 官方範例演示

輸入索引：

```text
0: [1,4,5]
1: [1,3,4]
2: [2,6]
```

遞迴拆分：

```text
MergeSort(0, 2)
├── MergeSort(0, 1)
│   ├── MergeSort(0, 0) => [1,4,5]
│   └── MergeSort(1, 1) => [1,3,4]
│   合併 => [1,1,3,4,4,5]
└── MergeSort(2, 2) => [2,6]

最後合併：
[1,1,3,4,4,5] + [2,6]
=> [1,1,2,3,4,4,5,6]
```

在最後一次兩鏈表合併中，首節點比較順序的前幾步為：

1. `1` 與 `2` 比較，取左側 `1`。
2. 下一個 `1` 與 `2` 比較，再取左側 `1`。
3. `3` 與 `2` 比較，取右側 `2`。
4. 繼續處理 `[3,4,4,5]` 與 `[6]`，得到完整結果。

### 複雜度

- 時間：`O(N log k)`
- 分割鏈表陣列的遞迴深度：`O(log k)`
- 遞迴合併兩條鏈表的呼叫堆疊：最壞可達 `O(N)`
- 綜合輔助空間：最壞 `O(N)`，不計輸出鏈表本身

> [!NOTE]
> 僅考慮分割鏈表陣列時會得到 `O(log k)` 深度，但本實作的兩鏈表合併也是遞迴，因此完整空間分析必須包含最壞 `O(N)` 的節點遞迴堆疊。

## 解法二：Bottom-up 分治與迭代合併

### 設計說明

`MergeKLists2` 不遞迴切分索引，而是以 `interval` 表示本輪要合併的兩組結果相距多遠：

1. `interval = 1`：合併相鄰的第 0、1 條，第 2、3 條，以此類推。
2. `interval = 2`：合併上一輪形成的第 0、2 組，第 4、6 組。
3. 每輪讓 `interval` 加倍，直到完整陣列只剩一個合併結果。

方法先淺複製輸入陣列：

- 合併過程只替換工作陣列中的首節點參考，不改寫呼叫端保存的陣列元素。
- 鏈表節點仍會被重接，因此這不是節點的深層複製。

兩條鏈表由 `MergeTwoListsIterative` 負責合併：

- dummy head 讓第一個節點與後續節點使用相同接法。
- `tail` 永遠指向目前結果的最後一個節點。
- 每輪挑選較小首節點接到 `tail`，再移動被選取的一側。
- 一側耗盡後，另一側已經有序，可整段接上。

### 官方範例演示

初始工作陣列：

```text
index 0: [1,4,5]
index 1: [1,3,4]
index 2: [2,6]
```

第一輪 `interval = 1`：

```text
index 0 與 index 1 合併
[1,4,5] + [1,3,4]
=> [1,1,3,4,4,5]

index 2 沒有配對，保留 [2,6]
```

第二輪 `interval = 2`：

```text
index 0 與 index 2 合併
[1,1,3,4,4,5] + [2,6]
=> [1,1,2,3,4,4,5,6]
```

此時 `interval` 再加倍後已不小於鏈表數量，`mergedLists[0]` 就是答案。

### 複雜度

- 時間：`O(N log k)`
- 淺複製工作陣列：`O(k)`
- 迭代合併兩條鏈表：`O(1)` 額外空間
- 綜合輔助空間：`O(k)`，不計輸出鏈表本身

## 解法比較

| 比較項目 | 解法一：Top-down | 解法二：Bottom-up |
| --- | --- | --- |
| K 條鏈表的分治方式 | 遞迴切分索引區間 | `interval` 加倍、逐輪合併 |
| 兩鏈表合併方式 | 遞迴 | 迭代 |
| 時間複雜度 | `O(N log k)` | `O(N log k)` |
| 輔助空間 | 最壞 `O(N)` 呼叫堆疊 | `O(k)` 工作陣列 |
| 空鏈表處理 | 遞迴 base case 直接回傳另一側 | 迭代結束時直接接上非空側 |
| 優點 | 結構直接對應分治定義，容易理解 | 無節點層級遞迴，避免深鏈表造成大量呼叫堆疊 |
| 代價 | 長鏈表可能產生很深的遞迴 | 需要維護合併間距與工作陣列 |
