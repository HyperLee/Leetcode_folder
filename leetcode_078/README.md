# LeetCode 78：Subsets（子集）

## 題目說明

給定一個元素互不重複的整數陣列 `nums`，回傳所有可能的子集，也就是這個集合的冪集。

結果必須符合：

- 包含空集合 `[]`。
- 包含每一個單一元素形成的子集。
- 包含完整集合。
- 不可出現重複子集。
- 子集之間的排列順序不限定。

例如：

```text
輸入：nums = [1, 2, 3]
輸出：[[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]
```

題目連結：[LeetCode 78 - Subsets](https://leetcode.com/problems/subsets/description/)

## 限制條件

- `1 <= nums.length <= 10`
- `-10 <= nums[i] <= 10`
- `nums` 中的所有數字互不重複

若輸入有 `n` 個元素，每個元素都有「選」與「不選」兩種狀態，因此總共有：

```text
2 × 2 × ... × 2 = 2^n
```

個不同子集。

> [!NOTE]
> 主控台範例額外包含空陣列 `[]`。它不在官方的 `nums.length >= 1` 限制內，但可以驗證迭代起點是否正確保留唯一的空集合 `[[]]`。

## 解題概念與出發點

### 為什麼從空集合開始？

空集合是任何集合的子集，也是建立其他子集最自然的起點。尚未處理任何數字時，唯一可能的結果就是：

```text
[[]]
```

### 加入一個新元素時會發生什麼？

假設目前已經正確產生前面元素的所有子集。當新元素 `num` 出現時，每個舊子集都有兩種選擇：

1. 不加入 `num`：保留原本的子集。
2. 加入 `num`：複製原本的子集，再把 `num` 放進副本。

因此每處理一個元素，子集數量都會加倍。

### 核心不變量

處理完 `nums` 的前 `k` 個元素後，`result` 恰好包含由這 `k` 個元素組成的所有子集。

- 起點 `k = 0` 時，`result = [[]]`，包含零個元素能形成的唯一子集。
- 若處理前 `k` 個元素時命題成立，加入第 `k + 1` 個元素後：
  - 舊結果代表所有「不選新元素」的子集。
  - 舊結果的複本加上新元素，代表所有「選新元素」的子集。
- 兩組結果互不重複且完整，所以處理完全部元素後便得到完整冪集。

## 解法：迭代擴張

### 設計步驟

1. 建立結果集合，先加入空集合。
2. 依序讀取 `nums` 的每個數字 `num`。
3. 記錄本輪開始前的子集數量 `size`。
4. 只遍歷索引 `0` 到 `size - 1` 的舊子集。
5. 複製每個舊子集，在副本中加入 `num`，再把副本加入結果。
6. 全部元素處理完後回傳結果。

### 為什麼必須先保存 `size`？

迴圈執行期間會持續把新子集加入 `result`。如果用會跟著增加的 `result.Count` 當作迴圈上限，本輪剛新增的子集又會被同一個 `num` 再次擴張，可能產生 `[1, 1]` 之類的錯誤結果，迴圈也無法在正確位置停止。

先保存 `size`，便能明確區分：

- `0 .. size - 1`：本輪開始前的舊子集。
- `size .. result.Count - 1`：本輪使用 `num` 建立的新子集。

### 為什麼要複製子集？

舊子集代表「不選目前數字」的分支，必須保留。若直接修改舊子集，就會失去這個分支。因此程式使用：

```csharp
IList<int> expandedSubset = new List<int>(result[i])
{
    num
};
```

先建立獨立副本，再加入目前數字。

### 複雜度

| 項目 | 複雜度 | 說明 |
| --- | --- | --- |
| 時間 | `O(n × 2^n)` | 共有 `2^n` 個子集，每個子集的複製與輸出最多涉及 `n` 個元素。 |
| 空間 | `O(n × 2^n)` | 回傳結果需要保存所有子集及其中的元素。 |

### 優點與限制

優點：

- 不需要遞迴，也沒有呼叫堆疊深度問題。
- 產生順序穩定，容易配合範例逐輪觀察。
- 每輪都直接建立可保留於最終答案的子集，不需要額外搜尋狀態。

限制：

- 冪集本身就有 `2^n` 個結果，無法避免指數級輸出空間。
- 每次建立新子集都要複製舊內容，時間成本包含複製元素的 `n` 因子。
- 題目保證輸入元素不重複；本解法沒有額外處理重複輸入。

## 範例演示流程

以 `nums = [1, 2, 3]` 為例：

| 階段 | 本輪開始前的子集 | 加入目前元素後的新子集 | 本輪結束結果 |
| --- | --- | --- | --- |
| 初始 | 無 | `[]` | `[[]]` |
| 處理 `1` | `[[]]` | `[[1]]` | `[[], [1]]` |
| 處理 `2` | `[[], [1]]` | `[[2], [1, 2]]` | `[[], [1], [2], [1, 2]]` |
| 處理 `3` | `[[], [1], [2], [1, 2]]` | `[[3], [1, 3], [2, 3], [1, 2, 3]]` | `[[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]` |

每一輪都保留全部舊子集，再新增相同數量、包含目前元素的子集：

```text
1 → 2 → 4 → 8
```

最後共有 `2^3 = 8` 個子集。

## 可執行案例

`Main` 會依序執行四組固定案例：

| 案例 | 輸入 | 驗證目的 |
| --- | --- | --- |
| 兩個元素 | `[1, 2]` | 觀察兩輪擴張後的四個子集。 |
| 三個元素 | `[1, 2, 3]` | 驗證題目典型案例與完整八個子集。 |
| 空陣列 | `[]` | 額外確認超出官方限制時仍回傳唯一的空集合。 |
| 單一元素 | `[5]` | 驗證官方長度下限，結果應為空集合與完整集合。 |

案例判定會先排序每個子集內的元素，再排序所有子集的正規化表示。因此，只要預期與實際結果包含相同子集，就會判定為 `PASS`，不會把題目未限制的輸出順序誤當成錯誤。
