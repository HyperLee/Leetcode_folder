## 題目與限制

題目來源：[LeetCode 2747](https://leetcode.com/problems/count-zero-request-servers/description/)／[中文題目](https://leetcode.cn/problems/count-zero-request-servers/description/)。更細的題意入門可參閱 [題目說明.md](題目說明.md)。

給定 `n` 台伺服器，編號為 `1` 到 `n`。`logs[i] = [server_id, time]` 表示某台伺服器在指定時間收到一次請求。另給定視窗寬度 `x` 和查詢時間陣列 `queries`。

對每個查詢時間 `q`，計算在閉區間 `[q - x, q]` 內**完全沒有收到請求的伺服器數量**。答案必須按照輸入查詢的原始順序回傳。

左右端點都算在內；同一台伺服器收到多次請求，也只算一台活躍伺服器。某台即使曾經收到請求，只要該請求在本次區間外，本次仍可能是零請求。

| 輸入 | 限制 |
|---|---|
| `n` | `1 <= n <= 100000` |
| `logs.Length` | `1 <= logs.Length <= 100000` |
| `logs[i].Length` | 恰為 `2` |
| `logs[i][0]` | `1 <= server_id <= n` |
| `logs[i][1]` | `1 <= time <= 1000000` |
| `x` | `1 <= x <= 100000` |
| `queries.Length` | `1 <= queries.Length <= 100000` |
| `queries[i]` | `x < queries[i] <= 1000000` |

程式以合法題目輸入為前提，不另外驗證空陣列、空值或範圍外資料。

### 官方範例

```text
範例一
n = 3
logs = [[1,3],[2,6],[1,5]]
x = 5
queries = [10,11]
答案 = [1,2]

範例二
n = 3
logs = [[2,4],[2,1],[1,2],[3,1]]
x = 2
queries = [3,4]
答案 = [0,1]
```

範例二的 `[1,3]` 有伺服器 1、2、3 活躍，答案為 `0`；`[2,4]` 只剩 1、2 活躍，答案為 `1`。

## 解題出發點

直接逐台檢查是否沒有請求，需要反覆尋找紀錄。反過來，先找出收到請求的不同伺服器即可：

```text
零請求伺服器數 = n - 區間內至少收到一次請求的不同伺服器數
```

例如區間內的伺服器編號為 `1,1,2,1,2`，有五筆請求，但只有兩台活躍伺服器。若 `n = 3`，答案就是 `3 - 2 = 1`。

最直覺的做法是每個查詢重新掃描紀錄並去重，得到暴力解法。但紀錄數與查詢數都可達十萬，最多需要約 `10^10` 次紀錄判斷。因此主要解法改為按時間處理查詢，重用相鄰區間的資訊。

## 方法一：排序與滑動視窗

對應方法：`CountServers(int n, int[][] logs, int x, int[] queries)`。

### 1. 為什麼先排序？

先把 `logs` 依請求時間排序，再按查詢時間從小到大處理。因為 `x` 固定，查詢時間增加時，區間的左右端點都只會向右移動。

這是「離線查詢」：所有問題事先已知，所以可以調整處理順序，再把答案放回原位置。程式建立查詢索引陣列 `ids`，按照 `queries[ids[i]]` 排序，並不排序 `queries` 本身。

> [!NOTE]
> 此方法會原地排序 `logs` 的外層陣列，但不改寫每筆紀錄的兩個數值，也不修改 `queries`。若要保留原始紀錄順序，請先複製。範例測試為每次呼叫提供外層與內層都獨立的副本。

### 2. 需要維護什麼？

| 狀態 | 意義 |
|---|---|
| `left` | 第一筆尚未移除的紀錄索引 |
| `right` | 下一筆尚未加入的紀錄索引，不包含在當前紀錄區間內 |
| `cnt[id]` | 當前維護區間內，該伺服器的請求筆數 |
| `active` | `cnt[id] > 0` 的伺服器數量 |
| `ans[i]` | 原始第 `i` 個查詢的零請求答案 |

使用 `n + 1` 個計數位置，使伺服器編號能直接當索引，索引 `0` 不使用。

為什麼不能只用集合？移除一筆舊紀錄時，同一台伺服器可能仍有其他有效紀錄。需要計數，才能知道何時真的變成沒有請求。

### 3. 每個查詢的處理步驟

1. 加入所有時間 `<= q` 的尚未處理紀錄，推進 `right`。若某台的次數由 `0` 變成 `1`，才增加 `active`。
2. 移除所有時間 `< q - x` 的舊紀錄，推進 `left`。若某台的次數由 `1` 變成 `0`，才減少 `active`。
3. 計算 `ans[i] = n - active`，其中 `i` 是原始查詢索引。

邊界判斷特別重要：加入條件為 `<= q`，移除條件為 `< q - x`，所以左右端點都保留。

完成兩個迴圈後的不變量為：`logs[left..right)` 恰好包含時間落在 `[q-x,q]` 的紀錄；`cnt` 是這些紀錄的次數，`active` 是其中不同伺服器數量。這裡的 `[left,right)` 是陣列索引的半開區間，與題目的時間閉區間不同。

剛完成「加入」而還沒完成「移除」時，可能暫時包含過期紀錄，因此要等兩階段完成後才計算答案。若相鄰查詢相距很遠，新增的部分紀錄也可能立即過期；它們仍只會被加入、移除各一次。

### 4. 範例一完整演示

```text
n = 3, x = 5, queries = [10,11]
原始 logs = [[1,3],[2,6],[1,5]]
排序 logs = [[1,3],[1,5],[2,6]]
紀錄索引       0     1     2
初始 left = right = active = 0
```

以下計數寫作 `[cnt[1],cnt[2],cnt[3]]`：

| 查詢 | 動作 | left | right | 計數 | active | 答案 |
|---|---|---:|---:|---|---:|---|
| `10 → [5,10]` | 加入 `[1,3]` | 0 | 1 | `[1,0,0]` | 1 | 尚未計算 |
| 同上 | 加入 `[1,5]`，同台重複請求 | 0 | 2 | `[2,0,0]` | 1 | 尚未計算 |
| 同上 | 加入 `[2,6]` | 0 | 3 | `[2,1,0]` | 2 | 尚未計算 |
| 同上 | 移除 `[1,3]`，時間小於 5 | 1 | 3 | `[1,1,0]` | 2 | `3-2=1` |
| `11 → [6,11]` | 無新紀錄可加入 | 1 | 3 | `[1,1,0]` | 2 | 尚未計算 |
| 同上 | 移除 `[1,5]`，伺服器 1 次數歸零 | 2 | 3 | `[0,1,0]` | 1 | `3-1=2` |

第一個查詢移除 `[1,3]` 時，伺服器 1 還有時間 5 的請求，因此 `active` 不能減少。第二個查詢移除它最後一筆有效請求後，才減少 `active`。

最後回傳 `[1,2]`。兩個指標整段過程都沒有向左退。

### 5. 未排序查詢如何還原？

沿用相同 `n`、`logs`、`x`，改用 `queries = [11,6,10,6]`。

```text
原始索引：  0  1   2  3
查詢時間： 11  6  10  6
```

索引按照查詢時間排序後可以是 `[1,3,2,0]`；相同時間的索引先後順序不影響答案。

| 處理的原索引 | q / 區間 | 新增紀錄 | 移除紀錄 | 最終計數 | active | 寫回答案 |
|---:|---|---|---|---|---:|---|
| 1 | `6 / [1,6]` | `[1,3],[1,5],[2,6]` | 無 | `[2,1,0]` | 2 | `ans[1]=1` |
| 3 | `6 / [1,6]` | 無 | 無 | `[2,1,0]` | 2 | `ans[3]=1` |
| 2 | `10 / [5,10]` | 無 | `[1,3]` | `[1,1,0]` | 2 | `ans[2]=1` |
| 0 | `11 / [6,11]` | 無 | `[1,5]` | `[0,1,0]` | 1 | `ans[0]=2` |

回傳 `[2,1,1,1]`，對應原始查詢順序，而非處理順序。

## 方法二：暴力掃描與集合

對應方法：`CountServersBruteForce(int n, int[][] logs, int x, int[] queries)`。

### 設計與流程

每個查詢各自建立空的 `HashSet<int>`，從頭到尾掃描 `logs`。若 `q-x <= time && time <= q`，就將伺服器編號加入集合。最後以 `n - activeServers.Count` 得到答案。

集合會自動去重，所以同一台收到多次請求也只計一次。不同查詢使用不同集合，避免前一個區間的活躍伺服器殘留。直接按照輸入順序迭代查詢，答案自然保留原始順序，不需要排序。

此方法不修改 `logs` 或 `queries`，設計直覺，適合學習題意及作為小型測試的參考答案；大規模輸入應使用滑動視窗。

### 範例一完整演示

使用原始紀錄順序 `[[1,3],[2,6],[1,5]]`，不先排序。

| 查詢 / 區間 | 掃描紀錄 | 判斷 | 集合內容 | 不同活躍數 |
|---|---|---|---|---:|
| `10 / [5,10]` | `[1,3]` | 3 小於 5，跳過 | `{}` | 0 |
| 同上 | `[2,6]` | 6 在區間內，加入 2 | `{2}` | 1 |
| 同上 | `[1,5]` | 5 等於左端點，加入 1 | `{1,2}` | 2 |
| `11 / [6,11]` | `[1,3]` | 新集合；3 小於 6，跳過 | `{}` | 0 |
| 同上 | `[2,6]` | 6 等於左端點，加入 2 | `{2}` | 1 |
| 同上 | `[1,5]` | 5 小於 6，跳過 | `{2}` | 1 |

兩個查詢分別得到 `3-2=1`、`3-1=2`，回傳 `[1,2]`。表格中的集合只呈現成員，集合本身不保證列舉順序。

## 複雜度比較

令 `L = logs.Length`、`Q = queries.Length`。

| 面向 | 排序＋滑動視窗 | 暴力掃描＋集合 |
|---|---|---|
| 時間 | `O(L log L + Q log Q + n)` | 平均 `O(Q × L)` |
| 工作資料，不含答案與排序堆疊 | `O(n + Q)`：計數與查詢索引 | `O(min(n,L))`：單次查詢集合 |
| 排序呼叫堆疊 | `O(log L + log Q)` 的保守上界 | 無排序 |
| 回傳陣列 | `O(Q)` | `O(Q)` |
| 輸入副作用 | 原地排序 `logs` | 不修改輸入 |
| 使用情境 | 題目完整資料規模 | 小型驗證、理解題意 |

滑動視窗的兩個指標合計只做 `O(L)` 次移動；每個查詢額外 `O(1)`，因此掃描部分為 `O(L+Q)`。`cnt` 的配置與零初始化需要 `O(n)`，納入總時間。排序使用 .NET `Array.Sort`，兩次排序依序執行，上表堆疊上界已足夠涵蓋所需空間。

暴力解法平均時間以 `HashSet.Add` 平均 `O(1)` 為前提。每個查詢都掃描全部 `L` 筆，因此即使視窗很小也不能省掉掃描成本。

測試程式另外配置輸入副本，這些配置不屬於演算法方法本身的空間複雜度。
