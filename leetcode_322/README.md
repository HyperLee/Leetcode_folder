## 題目說明

給定一個整數陣列 `coins`，其中每個元素代表一種硬幣面額；另給一個整數
`amount`，代表要湊成的總金額。每種面額的硬幣都可以使用無限次。

請回傳湊成 `amount` 所需的最少硬幣數。如果無法以任何組合湊成目標金額，
則回傳 `-1`。

題目連結：

- [LeetCode 322 - Coin Change](https://leetcode.com/problems/coin-change/description/)
- [力扣 322 - 零錢兌換](https://leetcode.cn/problems/coin-change/description/)

### 官方範例

```text
輸入：coins = [1,2,5], amount = 11
輸出：3
說明：11 = 5 + 5 + 1

輸入：coins = [2], amount = 3
輸出：-1

輸入：coins = [1], amount = 0
輸出：0
```

## 限制條件

- `1 <= coins.Length <= 12`
- `1 <= coins[i] <= 2^31 - 1`
- `0 <= amount <= 10^4`
- 每種面額可以使用無限次。
- 實作依賴面額皆為正整數；因此若能組成金額 `amount`，最多只需使用
  `amount` 枚面額為 `1` 的硬幣。

## 解題概念與出發點

### 為什麼不是貪心

如果每次都選擇不超過剩餘金額的最大硬幣，某些面額組合會得到錯誤答案。例如：

```text
coins = [1, 3, 4], amount = 6

貪心：4 + 1 + 1，共 3 枚
最佳：3 + 3，共 2 枚
```

題目沒有保證硬幣面額具備讓貪心策略成立的特殊結構，因此需要完整比較不同面額
所形成的子問題。

### 動態規劃狀態

令：

```text
dp[i] = 湊成金額 i 所需的最少硬幣數
```

已知湊成 `0` 元不需要硬幣，因此：

```text
dp[0] = 0
```

對每個金額 `i`，逐一考慮每個不大於 `i` 的硬幣 `coin`。如果最後使用這枚硬幣，
在它之前就必須先湊成 `i - coin`，所以狀態轉移為：

```text
dp[i] = min(dp[i], dp[i - coin] + 1)
```

計算 `dp[i]` 時，所有 `dp[i - coin]` 都屬於較小金額，已經在前面的迴圈完成。
這就是「自底向上」的來源。

### 不可達狀態

陣列一開始除了 `dp[0]` 外都尚不可達。本實作以 `amount + 1` 當作哨兵值：

- 面額皆為正整數。
- 任何有效解最多只可能使用 `amount` 枚硬幣。
- 因此 `amount + 1` 不可能是一個有效的最少硬幣數。

如果所有狀態轉移完成後 `dp[amount]` 仍等於哨兵值，就代表不存在有效組合，
回傳 `-1`。

## 解法：一維自底向上動態規劃

### 設計說明

`CoinChange` 使用長度為 `amount + 1` 的整數陣列保存所有子問題答案：

1. 建立 `dp[0..amount]`，全部填入不可達哨兵值 `amount + 1`。
2. 設定 `dp[0] = 0`，作為所有可達狀態的起點。
3. 依序處理 `currentAmount = 1` 到 `amount`。
4. 對每個硬幣面額：
   - 面額大於目前金額時不能使用。
   - 否則比較既有的 `dp[currentAmount]` 與
     `dp[currentAmount - coin] + 1`。
5. 處理完成後，若 `dp[amount]` 仍為哨兵值則回傳 `-1`，否則回傳該最小值。

外層以金額遞增、內層遍歷硬幣的順序，會求出「最少硬幣數」，而不是統計不同
組合數。硬幣輸入是否排序不影響答案；重複面額只會重複一次相同轉移，也不會
改變最小值。

### 正確性說明

可用數學歸納法說明 `dp[i]` 的結果正確：

- **基礎情況**：`dp[0] = 0`。湊成零元確實不需要任何硬幣。
- **歸納假設**：假設所有小於 `i` 的可達金額都已保存其最少硬幣數。
- **歸納步驟**：任何能湊成 `i` 的組合都有一枚「最後使用的硬幣」`coin`。
  移除它後，剩餘組合湊成 `i - coin`。依歸納假設，
  `dp[i - coin]` 已是該剩餘金額的最少硬幣數，所以這種最後硬幣對應的最佳答案
  是 `dp[i - coin] + 1`。演算法枚舉所有可作為最後一枚的硬幣並取最小值，
  因此得到湊成 `i` 的全域最少硬幣數。
- 若沒有任何硬幣能從可達狀態轉移到 `i`，`dp[i]` 會維持哨兵值，正確表示
  該金額不可達。

因此完成至 `dp[amount]` 時，演算法會回傳最少硬幣數，或在不可達時回傳 `-1`。

### 複雜度

令 `n = coins.Length`：

- 時間複雜度：`O(amount × n)`。每個金額都會檢查全部硬幣面額。
- 額外空間複雜度：`O(amount)`。`dp` 保存從 `0` 到 `amount` 的最少硬幣數。
- 輸入陣列不會被排序或修改。

## 範例演示流程

以 `coins = [1,2,5]`、`amount = 11` 為例。初始時：

```text
dp[0] = 0
dp[1..11] = 12（不可達哨兵值）
```

依序計算每個金額：

| 金額 `i` | 可用轉移 | `dp[i]` | 一組最佳組合 |
| ---: | --- | ---: | --- |
| `0` | 基礎狀態 | `0` | 不使用硬幣 |
| `1` | `dp[0] + 1`（硬幣 `1`） | `1` | `1` |
| `2` | `dp[1] + 1`、`dp[0] + 1` | `1` | `2` |
| `3` | `dp[2] + 1`、`dp[1] + 1` | `2` | `2 + 1` |
| `4` | `dp[3] + 1`、`dp[2] + 1` | `2` | `2 + 2` |
| `5` | 加入 `dp[0] + 1`（硬幣 `5`） | `1` | `5` |
| `6` | `dp[5] + 1` 最小 | `2` | `5 + 1` |
| `7` | `dp[5] + 1` 或 `dp[2] + 1` | `2` | `5 + 2` |
| `8` | 三種最後硬幣皆得到 `3` | `3` | `5 + 2 + 1` |
| `9` | `dp[7] + 1` 或 `dp[4] + 1` | `3` | `5 + 2 + 2` |
| `10` | `dp[5] + 1`（硬幣 `5`） | `2` | `5 + 5` |
| `11` | `dp[10] + 1` 或 `dp[6] + 1` | `3` | `5 + 5 + 1` |

最後 `dp[11] = 3`，所以最少需要三枚硬幣。
