## 題目說明

給定只包含 `(`、`)`、`[`、`]`、`{`、`}` 的字串 `s`，判斷它是否為有效括號字串。有效字串必須同時符合：

1. 每個左括號都由相同種類的右括號閉合。
2. 左括號必須依正確的巢狀順序閉合。
3. 每個右括號都必須有對應且尚未配對的左括號。

例如：

| 輸入 | 輸出 | 原因 |
| --- | --- | --- |
| `"()"` | `true` | 一組同種類括號正確配對 |
| `"()[]{}"` | `true` | 三種括號依序各自完成配對 |
| `"{[()]}"` | `true` | 巢狀括號由內向外依序閉合 |
| `"(]"` | `false` | 左右括號種類不同 |
| `"([)]"` | `false` | `[` 尚未閉合時先出現 `)` |

題目連結：

- [LeetCode](https://leetcode.com/problems/valid-parentheses/)
- [力扣中國](https://leetcode.cn/problems/valid-parentheses/)

## 限制條件

目前 LeetCode 題目限制為：

- `1 <= s.Length <= 10^4`
- `s` 只由括號字元 `()[]{}` 組成。

> [!NOTE]
> 專案原始題目 XML 明確記載空字串也視為有效，因此教學案例額外保留 `IsValid("") == true` 與 `IsValid2("") == true`。兩個方法都以題目輸入契約為前提，不另外處理 `null` 或括號以外的字元。

## 解題概念與出發點

括號的關閉順序具有「後進先出」特性。最後出現且尚未配對的左括號，必須最先被對應的右括號關閉，正好符合 Stack 的 `Push`、`Peek` 與 `Pop` 行為。

兩種解法的差異不在時間或空間複雜度，而在 Stack 保存的資訊：

- 解法一看到左括號時，直接推導並保存未來期待的右括號。
- 解法二保存實際左括號，等右括號出現後再判斷兩者是否同類。

兩者都先檢查字串長度。每組括號固定包含兩個字元，因此奇數長度不可能全部配對，可立即回傳 `false`。

## 解法一：保存預期右括號

### 設計說明

`IsValid` 不把讀到的左括號本身放進 Stack，而是直接放入與它配對的右括號：

- 讀到 `(`，Push `)`。
- 讀到 `[`，Push `]`。
- 讀到 `{`，Push `}`。

之後讀到右括號時，它必須等於 Stack 頂端的「下一個預期右括號」。若 Stack 已空，表示這個右括號沒有先前的左括號；若字元與頂端不同，表示括號種類或巢狀順序錯誤。只有相同時才能 Pop 完成一組配對。

### Stack 不變條件

處理每個字元前，Stack 由底至頂依序保存所有尚未閉合左括號所期待的右括號。頂端永遠代表下一個必須出現的右括號。掃描結束時，Stack 必須為空，否則仍有左括號尚未閉合。

### 正確性說明

- 每個左括號都把同種類的右括號放入 Stack，因此預期種類正確。
- 只有目前字元等於 Stack 頂端時才 Pop，因此閉合順序符合後進先出。
- Stack 空時拒絕右括號，可避免沒有對應左括號的情況。
- 最後要求 Stack 為空，可排除只出現左括號或尚未完全閉合的字串。

因此，方法回傳 `true` 時三項有效條件必定成立；所有符合條件的字串也能逐一 Pop 至空 Stack。

### 範例演示：有效輸入 `"{[()]}"`

下表的 Stack 內容以「底 → 頂」顯示：

| 讀入字元 | 動作 | Stack |
| --- | --- | --- |
| `{` | Push 預期的 `}` | `}` |
| `[` | Push 預期的 `]` | `} ]` |
| `(` | Push 預期的 `)` | `} ] )` |
| `)` | 等於頂端，Pop | `} ]` |
| `]` | 等於頂端，Pop | `}` |
| `}` | 等於頂端，Pop | 空 |

所有字元處理完畢且 Stack 為空，因此回傳 `true`。

### 範例演示：失敗輸入 `"([)]"`

| 讀入字元 | 動作 | Stack |
| --- | --- | --- |
| `(` | Push 預期的 `)` | `)` |
| `[` | Push 預期的 `]` | `) ]` |
| `)` | 頂端是 `]`，種類與順序不符 | `) ]` |

第三個字元已證明字串不可能有效，因此立即回傳 `false`，不必繼續掃描。

### 複雜度分析

- 時間複雜度：`O(n)`；每個字元最多被讀取一次，並進行一次 Stack 操作。
- 輔助空間複雜度：`O(n)`；最壞情況下前半段全部是左括號。
- 結果空間複雜度：`O(1)`；方法只回傳一個布林值。

## 解法二：保存實際左括號

### 設計說明

`IsValid2` 採用較直觀的 Stack 表示方式：

1. 讀到 `(`、`[` 或 `{` 時，把左括號本身 Push。
2. 讀到右括號時，Stack 不可為空。
3. Pop 最近的左括號，交給 `IsMatchingPair` 判斷種類是否相同。
4. 任一配對不符便立即回傳 `false`。
5. 掃描結束後，Stack 必須為空。

`IsMatchingPair` 集中定義 `()`、`[]`、`{}` 三種合法組合，讓 Stack 流程只負責順序，配對 helper 負責種類。

### Stack 不變條件

處理每個字元前，Stack 由底至頂保存所有已出現、但尚未由右括號關閉的左括號。頂端是最近出現的左括號，也就是目前右括號唯一允許配對的對象。

### 正確性說明

- 左括號依出現順序 Push，Stack 頂端必定是最近尚未配對者。
- 每個右括號只與頂端左括號核對，確保巢狀順序正確。
- `IsMatchingPair` 只接受三種合法組合，確保括號種類相同。
- Stack 空時拒絕右括號，結束時也要求 Stack 為空，確保左右括號數量完整對應。

因此，此方法恰好接受所有種類、順序與數量都正確的括號字串。

### 範例演示：有效輸入 `"{[()]}"`

下表的 Stack 內容同樣以「底 → 頂」顯示：

| 讀入字元 | 動作 | Stack |
| --- | --- | --- |
| `{` | Push 左括號 | `{` |
| `[` | Push 左括號 | `{ [` |
| `(` | Push 左括號 | `{ [ (` |
| `)` | Pop `(`，確認 `()` 合法 | `{ [` |
| `]` | Pop `[`，確認 `[]` 合法 | `{` |
| `}` | Pop `{`，確認 `{}` 合法 | 空 |

所有字元都完成配對且 Stack 為空，因此回傳 `true`。

### 範例演示：失敗輸入 `"([)]"`

| 讀入字元 | 動作 | Stack |
| --- | --- | --- |
| `(` | Push 左括號 | `(` |
| `[` | Push 左括號 | `( [` |
| `)` | Pop `[`，但 `IsMatchingPair('[', ')')` 為 `false` | `(` |

最近的左括號 `[` 不能由 `)` 關閉，因此立即回傳 `false`。

### 複雜度分析

- 時間複雜度：`O(n)`；每個字元最多被讀取一次，配對判斷為固定次數比較。
- 輔助空間複雜度：`O(n)`；最壞情況下 Stack 保存所有左括號。
- 結果空間複雜度：`O(1)`；方法只回傳一個布林值。

## 兩種解法比較

| 比較項目 | 解法一：預期右括號 | 解法二：實際左括號 |
| --- | --- | --- |
| Stack 保存內容 | 未來期待出現的右括號 | 尚未配對的左括號 |
| 左括號處理 | 轉成對應右括號後 Push | 直接 Push 原字元 |
| 右括號處理 | 與 Stack 頂端直接比較 | Pop 左括號後呼叫配對 helper |
| 配對知識所在位置 | 三個左括號分支 | `IsMatchingPair` |
| 時間複雜度 | `O(n)` | `O(n)` |
| 輔助空間複雜度 | `O(n)` | `O(n)` |
| 結果空間複雜度 | `O(1)` | `O(1)` |

解法一把配對轉換提前到左括號出現時，右括號判斷較直接；解法二保留原始左括號，資料意義較直觀，也容易把種類判斷集中管理。兩者都是適合本題的線性解法。
