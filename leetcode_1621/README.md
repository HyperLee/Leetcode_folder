## 題目說明

一維平面上有 `n` 個點，第 `i` 個點位於座標 `x = i`。請計算恰好畫出 `k` 條
互不重疊線段的方式數量，條件如下：

- 每條線段必須涵蓋兩個或以上的點，因此左、右端點必須滿足 `left < right`。
- 端點座標必須是整數。
- 線段之間可以共用端點，但不能互相穿過或重疊內部區間。
- 不要求所有點都被線段涵蓋。
- 答案可能很大，回傳對 `10^9 + 7` 取模後的結果。

官方題目：

- [LeetCode](https://leetcode.com/problems/number-of-sets-of-k-non-overlapping-line-segments/description/)
- [力扣中文版](https://leetcode.cn/problems/number-of-sets-of-k-non-overlapping-line-segments/description/)

例如 `n = 4, k = 2` 時，答案是 `5`。

## 限制條件

- `2 <= n <= 1000`
- `1 <= k <= n - 1`
- 本專案的 `Main` 使用題目提供的三組合法輸入；方法本身也依上述限制設計。

## 解題概念與出發點

把線段依照從左到右的順序排列，設第 `i` 條線段端點為 `(left_i, right_i)`，則端點
必須滿足：

```text
left_1 < right_1 <= left_2 < right_2 <= ... <= left_k < right_k
```

其中：

- 同一條線段的兩個端點必須嚴格遞增，確保線段涵蓋至少兩個點。
- 相鄰線段之間允許 `right_i == left_{i+1}`，反映題目允許共用端點。

這個條件可以從兩個方向處理：

1. 逐步增加線段數量，使用動態規劃維護每個右界的方式數。
2. 將「同一線段內嚴格遞增、線段之間可相等」的端點序列轉換成嚴格遞增序列，直接套用組合數。

以 `n = 4, k = 2` 的合法配置 `(0,2)` 與 `(2,3)` 為例，兩條線段可以在端點 `2`
相接，但不能互相穿過：

```text
points:    0---1---2---3
segment 1: [===========]
           0           2
segment 2:         [===]
                   2   3

endpoint order: left_1 < right_1 <= left_2 < right_2
                 0    <    2   <=    2   <    3
```

## 解法一：一維動態規劃

### 狀態定義

令 `f_i(j)` 表示：只使用點 `0` 到 `j`，繪製恰好 `i` 條合法線段的方式數。

初始狀態是 `i = 0`：不繪製線段時，不論右界在哪裡都只有一種空集合，因此：

```text
f_0(j) = 1
```

### 狀態轉移

計算 `f_i(j)` 時，依照最後一個端點是否使用 `j` 分成兩種情況：

```text
f_i(j) = f_i(j - 1) + sum(f_{i - 1}(t)), 其中 0 <= t < j
```

- `f_i(j - 1)`：沒有使用點 `j` 作為端點，沿用前一個右界的結果。
- `f_{i - 1}(t)`：最後一條線段為 `(t, j)`，前面 `i - 1` 條線段的端點不超過 `t`。
  因為線段可以共用端點，所以 `t` 可以等於前一條線段的右端點。

若每次都重新計算總和，轉移會多出一層 `O(n)`。程式用 `prefixSums[j]` 維護上一輪
`f_{i - 1}(0)` 到 `f_{i - 1}(j - 1)` 的總和，因此每個狀態只需 `O(1)` 時間。

DP 的依賴方向可以用下面的單一步驟表示。計算 `f_2(3)` 時，先沿用目前列左側的
`f_2(2)`，再加上上一列中所有可能的最後線段起點：

#### ASCII 圖的資料來源與數值推導

這張圖使用官方範例一 `n = 4, k = 2`，因此原始點集合是 `{0, 1, 2, 3}`。圖中的
`previous row` 不是另一組輸入，而是已完成 `i = 1` 條線段時的 DP 結果；`current row`
則是正在計算 `i = 2` 條線段的結果。

先從基礎列開始。`f_0(j) = 1` 表示不繪製線段時，不論右界 `j` 在哪裡都只有一種空集合。
因此這個案例的三列完整狀態是：

```text
j       0  1  2  3
f_0(j)  1  1  1  1
f_1(j)  0  1  3  6
f_2(j)  0  0  1  5
```

第一列 `f_1` 由 `f_0` 逐格得到：

```text
f_1(0) = 0
f_1(1) = f_1(0) + f_0(0) = 0 + 1 = 1
f_1(2) = f_1(1) + f_0(0) + f_0(1) = 1 + 1 + 1 = 3
f_1(3) = f_1(2) + f_0(0) + f_0(1) + f_0(2)
       = 3 + 1 + 1 + 1 = 6
```

例如 `f_1(3) = 6` 是四個點中任選兩個點作為一條線段的六種方式，
也就是 `C(4, 2) = 6`。

計算圖中最終的 `f_2(3)` 時，若最後一條線段為 `(t, 3)`，其起點必須滿足 `t < 3`。所以：

```text
prefixSums[3]
= f_1(0) + f_1(1) + f_1(2)
= 0 + 1 + 3
= 4

f_2(3)
= f_2(2) + prefixSums[3]
= 1 + 4
= 5
```

其中 `f_2(2) = 1` 對應未使用點 `3` 的配置 `{(0,1),(1,2)}`；`prefixSums[3]`
的四種配置則來自：

- `t = 0`：`f_1(0) = 0`，沒有合法的前一條線段。
- `t = 1`：`f_1(1) = 1`，前一條為 `(0,1)`，再接上 `(1,3)`。
- `t = 2`：`f_1(2) = 3`，前一條可為 `(0,1)`、`(0,2)` 或 `(1,2)`，再接上 `(2,3)`。

因此五種配置合計為：

```text
{(0,1),(1,2)}
{(0,1),(1,3)}
{(0,1),(2,3)}
{(0,2),(2,3)}
{(1,2),(2,3)}
```

`f_1(3)` 不會放入 `prefixSums[3]`，因為那會讓 `t = 3`，形成不合法的零長度線段
`(3,3)`。這也就是 ASCII 圖中 `0 + 1 + 3 = 4` 而不是再加上 `6` 的原因。

```text
previous row: f_1(0)   f_1(1)   f_1(2)   f_1(3)
                  0        1        3        6
                              \___________/
                         prefixSums[3] = 0 + 1 + 3 = 4

current row:  f_2(0)   f_2(1)   f_2(2)   f_2(3)
                  0        0        1        5
                                      |
                                      +-- f_2(3) = f_2(2) + prefixSums[3]
                                                    = 1 + 4 = 5
```

程式中的兩個陣列對應如下：

```text
dp[j]          = 目前 i 條線段的 f_i(j)
prefixSums[j]  = 上一輪 f_{i - 1}(0) + ... + f_{i - 1}(j - 1)
```

每一輪完成 `dp` 後，再重新建立 `prefixSums`，供下一條線段使用；所有加法都即時
對 `10^9 + 7` 取模。

### 範例演示：`n = 4, k = 2`

四個點為 `0, 1, 2, 3`。逐輪計算得到：

| 線段數 `i` | `f_i(0)` | `f_i(1)` | `f_i(2)` | `f_i(3)` |
|---:|---:|---:|---:|---:|
| `0` | 1 | 1 | 1 | 1 |
| `1` | 0 | 1 | 3 | 6 |
| `2` | 0 | 0 | 1 | 5 |

例如：

```text
f_1(2) = f_1(1) + f_0(0) + f_0(1) = 1 + 1 + 1 = 3
f_2(3) = f_2(2) + f_1(0) + f_1(1) + f_1(2) = 1 + 0 + 1 + 3 = 5
```

所以最後回傳 `f_2(3) = 5`。

### 正確性說明

任何使用 `0..j` 的 `i` 條線段配置，必然屬於以下其中一類：

- 所有端點都小於 `j`，這正是 `f_i(j - 1)`。
- 最後一條線段的右端點是 `j`。若其左端點為 `t`，前面配置只能使用 `0..t`，
  對每個 `t < j` 恰有 `f_{i - 1}(t)` 種。

兩類互斥且涵蓋所有配置，因此轉移式不重複也不遺漏。前綴和只是把第二類的總和
從逐項計算改成常數時間查詢，不改變狀態定義或答案。

### 複雜度

- 時間複雜度：`O(nk)`。
- 空間複雜度：`O(n)`，只保留目前 DP 列與前綴和。

## 解法二：組合數學

### 將端點轉換成嚴格遞增序列

把所有端點依序寫成：

```text
x_1 = left_1, x_2 = right_1, x_3 = left_2, x_4 = right_2, ...
```

原本的條件是：

```text
x_1 < x_2 <= x_3 < x_4 <= ...
```

對第 `j` 個端點定義：

```text
y_j = x_j + floor((j - 1) / 2)
```

每兩個端點增加一次偏移量後，原本允許相等的線段交界也會變成嚴格遞增，因此：

```text
original x:  0       2       2       3
offset:      0       0       1       1
             +       +       +       +
new y:       0       2       3       4
             |       |       |       |
             +-------+-------+-------+
                 strictly increasing
```

```text
0 <= y_1 < y_2 < ... < y_{2k} <= n + k - 2
```

可選的位置總數是 `n + k - 1` 個，從中選出 `2k` 個位置：

```text
答案 = C(n + k - 1, 2k)
```

在上面的 `n = 4, k = 2` 例子中，轉換後共有 `5` 個可選位置，必須選出 `4` 個：

```text
available:  0   1   2   3   4
choose:     [x] [x] [x] [x] [ ]

number of choices = C(5, 4) = 5
```

### 模運算計算組合數

程式不建立完整階乘表，而是直接計算：

```text
C(n + k - 1, 2k)
= [product(i = 1..2k) (n + k - i)] / (2k)!
```

令 `MOD = 10^9 + 7`。因為 `MOD` 是質數，費馬小定理給出：

```text
(2k)!^(-1) mod MOD = ((2k)!)^(MOD - 2) mod MOD
```

`QuickPow` 使用二進位快速冪在 `O(log MOD)` 時間內計算這個次方，避免直接做模除法。
分子、分母與乘法結果使用 `long` 保存，並在每一步取模。

### 範例演示

#### 範例一：`n = 4, k = 2`

```text
C(4 + 2 - 1, 2 * 2) = C(5, 4) = 5
```

因此輸出 `5`。

#### 範例二：`n = 3, k = 1`

```text
C(3 + 1 - 1, 2 * 1) = C(3, 2) = 3
```

三種線段正好是 `(0,1)`、`(0,2)`、`(1,2)`。

#### 範例三：`n = 30, k = 7`

```text
C(30 + 7 - 1, 2 * 7) = C(36, 14) = 3796297200
3796297200 mod 1000000007 = 796297179
```

### 複雜度

- 組合數乘法：`O(k)`，因為只需計算 `2k` 個因子。
- 模反元素：`O(log MOD)`，由 `QuickPow` 完成。
- 總時間複雜度：`O(k + log MOD)`。
- 空間複雜度：`O(1)`。

## 兩種解法比較

| 解法 | 核心想法 | 時間 | 空間 | 特點 |
|---|---|---:|---:|---|
| 動態規劃 | 依線段數與右界累計配置，使用前綴和優化轉移 | `O(nk)` | `O(n)` | 推導直觀，適合從狀態轉移理解題目 |
| 組合數學 | 將端點轉成嚴格遞增序列，計算 `C(n+k-1,2k)` | `O(k + log MOD)` | `O(1)` | 執行快速，但需要理解端點轉換與模逆元 |

兩種方法都在 `Main` 中對相同輸入執行，方便確認不同推導得到一致結果。
