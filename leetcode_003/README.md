# LeetCode 3：無重複字元的最長子字串

## 題目說明

給定一個字串 `s`，找出其中不含重複字元的最長「子字串」，並回傳其長度。

子字串必須由原字串中連續的字元組成。例如，`"abcabcbb"` 的答案是 `3`，因為 `"abc"` 是不含重複字元的最長連續片段。`"acb"` 雖然字元不重複，但不是原字串中的連續片段，因此不能作為答案。

### 範例

| 輸入 | 輸出 | 說明 |
|---|---:|---|
| `s = "abcabcbb"` | `3` | 最長無重複子字串可為 `"abc"`。 |
| `s = "bbbbb"` | `1` | 所有字元相同，最長有效子字串只有 `"b"`。 |
| `s = "pwwkew"` | `3` | 最長有效子字串可為 `"wke"`；`"pwke"` 不是連續子字串。 |

## 限制條件

- `0 <= s.Length <= 5 * 10^4`
- `s` 由英文字母、數字、符號與空白組成。
- 本專案依題目字元範圍，將輸入視為 ASCII 字元；固定陣列解法使用索引 `0` 到 `127`。
- 公開方法預期接收非 `null` 字串；空字串是有效輸入，結果為 `0`。

## 解題概念與出發點

直接列舉每一個子字串，再逐一檢查是否包含重複字元，會產生大量重複工作。當右側新字元造成重複時，真正需要做的不是重新建立下一個子字串，而是移動左邊界，從現有視窗移除舊字元。

滑動視窗維護一段半開區間 `[left, right)` 或閉區間 `[left, right]`：

1. 右邊界向右擴張，嘗試把新字元放入視窗。
2. 若新字元與視窗內的字元重複，移動左邊界並同步移除狀態。
3. 當視窗重新滿足「每個字元最多出現一次」後，更新目前最大長度。
4. 左、右邊界都只向右移動，不會回頭，因此搭配常數時間的查詢結構時可達到 O(n)。

四種解法的核心不變量相同：

> 更新答案時，目前視窗內的所有字元必須互不重複。

差異在於如何表示視窗內的字元，以及如何判斷重複。

## 四種解法比較

令 `n` 為輸入長度，`k` 為目前視窗長度。ASCII 表示陣列的大小固定，因此視為 O(1) 額外空間。

| 解法 | 狀態結構 | 重複查詢／移除 | 時間複雜度 | 空間複雜度 | 特點 |
|---|---|---|---|---|---|
| 解法一 | `BitArray(256)` | 位元索引 O(1) | O(n) | O(1) | 節省每個存在狀態所需空間，但操作語意較不直觀。 |
| 解法二 | `List<char>` | `Contains`、`Remove` 皆可能為 O(k) | 最壞 O(n²) | O(min(n, 字元種類數)) | 最容易直接觀察視窗內容，適合入門理解。 |
| 解法三 | `int[128]` | 計數索引 O(1) | O(n) | O(1) | 能直接知道字元在視窗中的出現次數。 |
| 解法四 | `bool[128]` | 存在索引 O(1) | O(n) | O(1) | 只記錄存在與否，結構簡單且足以解本題。 |

## 解法一：`BitArray` 存在狀態

### 設計

`LengthOfLongestSubstring` 使用 `BitArray` 記錄每個 ASCII 字元是否存在於目前視窗：

- `map[c] == false`：字元 `c` 不在視窗中，可以直接加入並移動右邊界。
- `map[c] == true`：右邊界遇到重複字元。先用目前視窗長度更新答案，再移除左側字元，直到跨過相同字元上一次出現的位置。
- 相同字元的位元維持為 `true`，因為右側的新字元會留在縮短後的視窗內。
- 迴圈結束後再比較一次尾端視窗，避免漏掉沒有以重複字元結束的最長區段。

每個字元至多從右側進入一次、從左側離開一次，所以時間複雜度為 O(n)。

### `abcabcbb` 演示

此方法的 `right` 表示尚未處理位置，視窗為 `[left, right)`。

| 目前位置／字元 | 是否重複 | 主要動作 | 動作後有效視窗 | 最大長度 |
|---|---|---|---|---:|
| `0 / a` | 否 | 標記 `a`，`right` 右移 | `"a"` | `0` |
| `1 / b` | 否 | 標記 `b`，`right` 右移 | `"ab"` | `0` |
| `2 / c` | 否 | 標記 `c`，`right` 右移 | `"abc"` | `0` |
| `3 / a` | 是 | 先記錄長度 `3`，跨過索引 `0` 的 `a` | `"bca"` | `3` |
| `4 / b` | 是 | 跨過索引 `1` 的 `b` | `"cab"` | `3` |
| `5 / c` | 是 | 跨過索引 `2` 的 `c` | `"abc"` | `3` |
| `6 / b` | 是 | 移除 `a`，再跨過舊 `b` | `"cb"` | `3` |
| `7 / b` | 是 | 移除 `c`，再跨過舊 `b` | `"b"` | `3` |

最終答案為 `3`。

## 解法二：`List<char>` 保存視窗內容

### 設計

`LengthOfLongestSubstring2` 直接用 `List<char>` 保存目前視窗中的字元：

- 若 `letter.Contains(s[right])` 為 `false`，將字元加入串列並擴張右邊界。
- 若字元已存在，右邊界暫停；移除 `s[left]` 並移動左邊界。
- 重複上述縮窗動作，直到右側字元不再存在於串列，才把它加入。
- `count` 與串列中的有效字元數同步，並用來更新 `max`。

流程很直觀，但 `List<char>.Contains` 與依值移除都需要線性搜尋。當視窗很長時，每次查詢可能花費 O(k)，因此最壞時間複雜度是 O(n²)。

### `abcabcbb` 演示

| 右側字元 | 是否重複 | 主要動作 | `List<char>`／有效視窗 | 最大長度 |
|---|---|---|---|---:|
| `a` | 否 | 加入 `a` | `[a]`／`"a"` | `1` |
| `b` | 否 | 加入 `b` | `[a,b]`／`"ab"` | `2` |
| `c` | 否 | 加入 `c` | `[a,b,c]`／`"abc"` | `3` |
| `a` | 是 | 移除左側 `a`，再加入新 `a` | `[b,c,a]`／`"bca"` | `3` |
| `b` | 是 | 移除左側 `b`，再加入新 `b` | `[c,a,b]`／`"cab"` | `3` |
| `c` | 是 | 移除左側 `c`，再加入新 `c` | `[a,b,c]`／`"abc"` | `3` |
| `b` | 是 | 依序移除 `a`、舊 `b`，再加入新 `b` | `[c,b]`／`"cb"` | `3` |
| `b` | 是 | 依序移除 `c`、舊 `b`，再加入新 `b` | `[b]`／`"b"` | `3` |

最終答案為 `3`。

## 解法三：`int[]` 字元計數

### 設計

`LengthOfLongestSubstring3` 使用 `int[128]` 記錄每個 ASCII 字元在視窗內的出現次數：

- 右邊界每加入一個字元，就執行 `count[c]++`。
- 若 `count[c] > 1`，代表新加入的字元重複；持續將左界字元計數減一並移動 `left`。
- 當 `count[c]` 恢復為 `1` 時，視窗再次符合無重複條件。
- 此時以 `right - left + 1` 更新最大長度。

計數陣列除了能判斷是否重複，也能清楚表達「目前有幾個」相同字元。左右指標都只向右移動，因此時間複雜度為 O(n)。

### `abcabcbb` 演示

| `right`／字元 | 加入後是否重複 | 縮窗結果 | 有效視窗 | 最大長度 |
|---|---|---|---|---:|
| `0 / a` | 否 | 不縮窗 | `"a"` | `1` |
| `1 / b` | 否 | 不縮窗 | `"ab"` | `2` |
| `2 / c` | 否 | 不縮窗 | `"abc"` | `3` |
| `3 / a` | 是 | 移除索引 `0` 的 `a` | `"bca"` | `3` |
| `4 / b` | 是 | 移除索引 `1` 的 `b` | `"cab"` | `3` |
| `5 / c` | 是 | 移除索引 `2` 的 `c` | `"abc"` | `3` |
| `6 / b` | 是 | 依序移除 `a`、舊 `b` | `"cb"` | `3` |
| `7 / b` | 是 | 依序移除 `c`、舊 `b` | `"b"` | `3` |

最終答案為 `3`。

## 解法四：`bool[]` 模擬字元集合

### 設計

`LengthOfLongestSubstring4` 使用 `bool[128]` 表示字元是否存在：

- `exists[c] == false` 時，將它設為 `true`，表示右側字元加入視窗。
- `exists[c] == true` 時，不能直接加入；從左側開始把離開視窗的字元設為 `false`。
- 持續縮窗直到 `exists[c] == false`，再加入新字元。
- 每次完成加入後，視窗必定沒有重複字元，可以安全更新答案。

相較於計數陣列，此解法只保留「存在／不存在」兩種狀態。本題只需要判斷重複，因此布林狀態已經足夠。左右指標各自最多走過字串一次，時間複雜度為 O(n)。

### `abcabcbb` 演示

| `right`／字元 | 加入前是否存在 | 清除的左側字元 | 加入後有效視窗 | 最大長度 |
|---|---|---|---|---:|
| `0 / a` | 否 | 無 | `"a"` | `1` |
| `1 / b` | 否 | 無 | `"ab"` | `2` |
| `2 / c` | 否 | 無 | `"abc"` | `3` |
| `3 / a` | 是 | `a` | `"bca"` | `3` |
| `4 / b` | 是 | `b` | `"cab"` | `3` |
| `5 / c` | 是 | `c` | `"abc"` | `3` |
| `6 / b` | 是 | `a`、`b` | `"cb"` | `3` |
| `7 / b` | 是 | `c`、`b` | `"b"` | `3` |

最終答案為 `3`。
