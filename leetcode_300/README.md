## 題目說明

給定整數陣列 `nums`，回傳其中「最長嚴格遞增子序列」的長度。

子序列可以刪除原陣列中的部分元素，但保留下來的元素必須維持原本的相對順序；它不必在原陣列中連續。嚴格遞增則表示相鄰選取值必須滿足前者小於後者，因此相同數值不能延長序列。

例如：

```text
nums = [10, 9, 2, 5, 3, 7, 101, 18]
```

其中一條最長遞增子序列是 `[2, 3, 7, 18]`，長度為 `4`。

### 限制條件

- `1 <= nums.length <= 2500`
- `-10^4 <= nums[i] <= 10^4`
- 延伸要求：設計時間複雜度為 O(n log n) 的演算法。

> [!NOTE]
> 官方輸入至少包含一個元素；專案中的兩種方法仍防禦性支援空陣列，並回傳 `0`。

題目來源：[LeetCode 300. Longest Increasing Subsequence](https://leetcode.com/problems/longest-increasing-subsequence/description/)

## 解題概念與出發點

暴力列舉所有子序列會產生指數級組合。真正需要保留的資訊不是每一條完整子序列，而是「處理到目前位置時，哪些局部結果足以推導後續答案」。

- 動態規劃保留每個索引作為結尾時的最佳長度，資訊完整且容易理解。
- tails 解法只保留各種長度的最小尾值。尾值越小，越容易接上未來較大的數字，因此可以捨棄同長度但尾值較大的候選。

| 比較項目 | 動態規劃 | tails + 二分搜尋 |
| --- | --- | --- |
| 核心狀態 | `dp[i]`：以 `nums[i]` 結尾的 LIS 長度 | `tails[i]`：長度 `i + 1` 的候選序列最小尾值 |
| 每個元素的處理 | 檢查前方所有元素 | 二分搜尋追加或替換位置 |
| 時間複雜度 | O(n²) | O(n log n) |
| 額外空間 | O(n) | O(n) |
| 教學優點 | 狀態定義與轉移直接 | 展示如何用更精簡狀態優化搜尋 |

## 解法一：動態規劃

### 設計

定義 `dp[i]` 為「必須以 `nums[i]` 結尾」的最長嚴格遞增子序列長度。

1. 每個元素單獨都能形成長度為 1 的子序列，因此先將所有 `dp[i]` 初始化為 `1`。
2. 對每個位置 `i`，檢查所有 `j < i`。
3. 若 `nums[j] < nums[i]`，便能將 `nums[i]` 接在以 `nums[j]` 結尾的序列後方：

   `dp[i] = max(dp[i], dp[j] + 1)`

4. 所有 `dp[i]` 的最大值就是答案。

這個狀態不需要保存實際選了哪些元素，只保存每個結尾位置能達到的最佳長度。

### 範例演示

輸入：`[10, 9, 2, 5, 3, 7, 101, 18]`

| `i` | `nums[i]` | 可承接的代表前置值 | `dp[i]` | 目前最大值 |
| ---: | ---: | --- | ---: | ---: |
| 0 | 10 | 無 | 1 | 1 |
| 1 | 9 | 無 | 1 | 1 |
| 2 | 2 | 無 | 1 | 1 |
| 3 | 5 | 2 | 2 | 2 |
| 4 | 3 | 2 | 2 | 2 |
| 5 | 7 | 2、5、3 | 3 | 3 |
| 6 | 101 | 前方所有較小值 | 4 | 4 |
| 7 | 18 | 2、5、3、7 | 4 | 4 |

最後得到 `max(dp) = 4`。

### 複雜度

- 時間複雜度：O(n²)，每個位置都可能檢查所有更早的位置。
- 空間複雜度：O(n)，用來保存 `dp`。

## 解法二：tails + 二分搜尋

### 設計

`tails[i]` 表示「長度為 `i + 1` 的嚴格遞增子序列，目前能取得的最小尾值」。

逐一讀取 `num`：

1. 若 `tails` 為空，或 `num` 大於最後一個尾值，將 `num` 加到尾端，代表找到更長的遞增序列。
2. 否則，以 `LowerBound` 找出第一個大於或等於 `num` 的位置，並以 `num` 替換。
3. 替換不會增加目前長度，但能降低某個長度的尾值，讓未來元素更容易接續。

`LowerBound` 搜尋第一個 `tails[index] >= num` 的位置。使用「大於或等於」而不是「大於」，可確保重複值只會替換既有尾值，不會錯誤地延長嚴格遞增序列。

> [!IMPORTANT]
> `tails` 的內容不保證是一條可直接從原陣列取出的實際 LIS；它濃縮的是各長度的最佳尾值。`tails.Count` 才是本題需要的 LIS 長度。

### 範例演示

輸入：`[10, 9, 2, 5, 3, 7, 101, 18]`

| 讀入值 | 動作 | 更新後的 `tails` |
| ---: | --- | --- |
| 10 | 建立第一個尾值 | `[10]` |
| 9 | 替換第一個 `>= 9` 的值 | `[9]` |
| 2 | 替換第一個 `>= 2` 的值 | `[2]` |
| 5 | 大於最後尾值，追加 | `[2, 5]` |
| 3 | 替換第一個 `>= 3` 的值 | `[2, 3]` |
| 7 | 大於最後尾值，追加 | `[2, 3, 7]` |
| 101 | 大於最後尾值，追加 | `[2, 3, 7, 101]` |
| 18 | 替換第一個 `>= 18` 的值 | `[2, 3, 7, 18]` |

最後 `tails.Count = 4`，因此最長遞增子序列長度為 `4`。

### 複雜度

- 時間複雜度：O(n log n)，每個元素執行一次二分搜尋。
- 空間複雜度：O(n)，最壞情況下所有元素都會加入 `tails`。
