## 題目說明

給定一個非負整數 `c`，判斷是否存在兩個整數 `a` 與 `b`，使下式成立：

```text
a² + b² = c
```

只需要判斷是否存在符合條件的組合，不必回傳 `a` 與 `b`。兩個整數可以相同，也允許其中一個為 `0`。

例如：

- `c = 5` 時，`1² + 2² = 5`，因此回傳 `true`。
- `c = 3` 時，找不到符合條件的整數組合，因此回傳 `false`。

題目連結：[LeetCode 633. Sum of Square Numbers](https://leetcode.com/problems/sum-of-square-numbers/)

## 限制條件

- `0 <= c <= 2³¹ - 1`
- `c` 可達 `int.MaxValue`，平方與平方和若只使用 `int` 計算可能溢位。
- 本專案以 `int` 接收輸入，但在乘法、加法與搜尋邊界中使用 `long`。
- 題目只要求非負輸入；兩個公開解法皆依此輸入契約設計。

## 解題概念與出發點

最直接的想法是列舉所有可能的 `a` 與 `b`，檢查每一組是否滿足 `a² + b² = c`。由於 `a`、`b` 都不需要超過 `√c`，雙層列舉會各執行約 `√c` 次，整體時間複雜度是 `O(c)`。

這個暴力方法忽略了平方函數的單調性：

- 當整數變大時，其平方也會變大。
- 固定其中一個數後，另一個平方的目標值是確定的。
- 已知目前平方和太大或太小時，可以排除一整段不可能的組合。

本專案利用這些性質實作兩種改良方式：

1. **雙指針：** 同時維護最小候選值與最大候選值，依平方和大小移動其中一端。
2. **枚舉加二分搜尋：** 逐一固定第一個數，再以二分搜尋判斷剩餘值是否為完全平方數。

兩種方法都不需要建立集合或陣列，額外空間維持 `O(1)`。

## 解法一：雙指針

### 設計說明

平方函數在非負整數上單調遞增，因此可以令：

- `left = 0`
- `right = floor(√c)`

此時所有可能的非負平方根都位於 `[left, right]`。每一輪計算：

```text
sum = left² + right²
```

接著分成三種情況：

1. `sum == c`：已找到一組平方和，立即回傳 `true`。
2. `sum > c`：平方和太大。增加 `left` 只會讓總和更大，因此必須將 `right` 減一。
3. `sum < c`：平方和太小。減少 `right` 只會讓總和更小，因此必須將 `left` 加一。

每次移動都能安全排除目前不可能成為答案的一整列候選組合，直到找到答案或兩個指針交錯。

### 虛擬碼

```text
left = 0
right = floor(sqrt(c))

while left <= right:
    sum = left² + right²

    if sum == c:
        return true
    if sum > c:
        right--
    else:
        left++

return false
```

### 正確性說明

假設目前的候選組合為 `(left, right)`：

- 若平方和太大，任何 `(largerLeft, right)` 的平方和都不會更小，所以目前的 `right` 不可能再搭配尚未檢查的左側候選值形成答案，可以安全縮小 `right`。
- 若平方和太小，任何 `(left, smallerRight)` 的平方和都不會更大，所以目前的 `left` 不可能再搭配尚未檢查的右側候選值形成答案，可以安全增加 `left`。

因此，每次移動都不會略過可能的答案。若存在符合條件的組合，指針移動過程一定會抵達該組合；若指針交錯仍未找到，代表不存在答案。

### 範例演示：`c = 5`

初始狀態：

```text
left = 0
right = floor(√5) = 2
```

| 步驟 | `left` | `right` | 平方和 | 判斷 |
|---:|---:|---:|---:|---|
| 1 | 0 | 2 | `0² + 2² = 4` | `4 < 5`，增加 `left` |
| 2 | 1 | 2 | `1² + 2² = 5` | 等於目標，回傳 `true` |

### 複雜度分析

- **時間複雜度：** `O(√c)`。兩個指針合計最多移動約 `√c` 次。
- **額外空間複雜度：** `O(1)`。只使用固定數量的數值變數。

## 解法二：枚舉加二分搜尋

### 設計說明

第二種解法逐一枚舉第一個非負整數 `first`。只要 `first² <= c`，剩餘值就是：

```text
remaining = c - first²
```

問題接著轉換成：`remaining` 是否為某個整數的平方？

由於平方值會隨候選整數單調遞增，可以在 `[0, remaining]` 內二分搜尋：

1. 取中間值 `middle` 並計算 `middle²`。
2. 若 `middle² == remaining`，表示找到第二個整數，回傳 `true`。
3. 若平方太大，將搜尋區間縮到左半部。
4. 若平方太小，將搜尋區間縮到右半部。
5. 若所有 `first` 都找不到完全平方數，回傳 `false`。

雖然二分搜尋的初始右界可以進一步縮小到 `√remaining`，目前實作刻意使用 `remaining` 作為直接且容易驗證的完整搜尋界線；二分搜尋仍只需要 `O(log c)` 次比較。

### 虛擬碼

```text
for first from 0 while first² <= c:
    remaining = c - first²

    if remaining is a perfect square by binary search:
        return true

return false
```

完全平方數的二分搜尋：

```text
left = 0
right = target

while left <= right:
    middle = left + (right - left) / 2
    square = middle²

    if square == target:
        return true
    if square > target:
        right = middle - 1
    else:
        left = middle + 1

return false
```

### 正確性說明

外層迴圈會枚舉每個可能的第一個非負整數 `first`。若答案中存在某個 `a`，則迴圈一定會走訪到 `first = a`，並得到 `remaining = c - a² = b²`。

內層二分搜尋涵蓋從 `0` 到 `remaining` 的所有候選整數。平方函數在這個區間單調遞增，因此每次比較都能正確排除不可能包含平方根的半個區間。當 `remaining = b²` 時一定能找到 `b`；若搜尋區間耗盡，則該剩餘值不是完全平方數。

所以，只要存在 `a² + b² = c`，外層枚舉與內層搜尋就會回傳 `true`；所有候選值都失敗時才會回傳 `false`。

### 範例演示：`c = 5`

第一次外層枚舉：

```text
first = 0
remaining = 5 - 0² = 5
```

在 `[0, 5]` 搜尋平方根：

| 步驟 | 搜尋區間 | `middle` | `middle²` | 判斷 |
|---:|---|---:|---:|---|
| 1 | `[0, 5]` | 2 | 4 | 太小，搜尋右半部 |
| 2 | `[3, 5]` | 4 | 16 | 太大，搜尋左半部 |
| 3 | `[3, 3]` | 3 | 9 | 太大，區間耗盡 |

`5` 不是完全平方數，因此繼續枚舉：

```text
first = 1
remaining = 5 - 1² = 4
```

在 `[0, 4]` 中第一次取到 `middle = 2`，而 `2² = 4`，因此回傳 `true`。

### 複雜度分析

- **時間複雜度：** `O(√c log c)`。外層最多枚舉約 `√c` 個值，每次完全平方數判定最多進行 `O(log c)` 次比較。
- **額外空間複雜度：** `O(1)`。二分搜尋以迭代方式完成，沒有遞迴堆疊或額外集合。

## 兩種解法比較

| 比較項目 | 解法一：雙指針 | 解法二：枚舉加二分搜尋 |
|---|---|---|
| 核心策略 | 同時調整平方和的左右端點 | 固定第一個平方數，再搜尋第二個平方數 |
| 時間複雜度 | `O(√c)` | `O(√c log c)` |
| 額外空間 | `O(1)` | `O(1)` |
| 搜尋狀態 | 一個持續縮小的二維候選邊界 | 多次獨立的完全平方數搜尋 |
| 優點 | 執行次數較少，程式直接 | 將問題拆成枚舉與單調搜尋，概念易於重用 |
| 適合的教學重點 | 雙指針與搜尋不變量 | 問題轉換與二分搜尋 |

若只追求本題的時間效率，雙指針較佳；枚舉加二分搜尋則展示如何將「是否存在兩個值」拆解成「固定一個值後搜尋另一個值」。
