# LeetCode 2567：修改兩個元素後的最小分數

本專案使用 C# 實作 **Minimum Score by Changing Two Elements**，提供排序與單次遍歷兩種解法，以及可由 `Main` 直接執行的測試。

- 題目來源：[LeetCode 2567](https://leetcode.com/problems/minimum-score-by-changing-two-elements/)
- 更完整的題意入門與官方範例說明：[PROBLEM.md](PROBLEM.md)
- 程式碼：[Program.cs](leetcode_2567/Program.cs)

## 1. 題目說明

給定整數陣列 `nums`，從**不同位置**選取兩個元素進行比較，定義：

| 名稱 | 定義 |
| --- | --- |
| 低分（low score） | 所有元素配對中，最小的絕對差 |
| 高分（high score） | 所有元素配對中，最大的絕對差，即最大值減最小值 |
| 總分（score） | 低分 + 高分 |

修改陣列中兩個位置的數值後，回傳可以得到的**最小總分**。

修改是替換既有位置的數值，不會增減元素。新值不必出現在原陣列中，也可以讓不同位置存放相同數值。計算分數時仍須包含整個陣列；不只看修改過的位置，也不只比較相鄰位置。

### 輸入限制

- `3 <= nums.length <= 100000`。
- `1 <= nums[i] <= 1000000000`。
- 可以有重複值，輸入不保證已排序。
- 回傳最小總分，不需要回傳修改位置或修改後的陣列。

本專案兩個方法都以合法題目輸入為前提，不額外處理 `null` 或長度不足 3 的陣列。最終候選值介於 `0` 與 `999999999`，可使用 C# `int`。

### 官方範例

```text
範例一
輸入： [1,4,7,8,5]
修改： [6,6,7,8,5]
低分： |6-6| = 0
高分： 8-5 = 3
輸出： 0+3 = 3

範例二
輸入： [1,4,3]
修改： [1,1,1]
低分： 0
高分： 0
輸出： 0
```

## 2. 解題概念與出發點

### 2.1 先讓低分變成零

絕對差不會小於零。如果讓兩個不同位置的值相同，低分就能達到零。

因此可以考慮：保留 `n-2` 個元素，把另外兩個位置都改成某個保留元素的值。這樣既能製造重複值，又不會擴大保留元素原有的最大值與最小值範圍。

```text
原始排序： 1   4   5   7   8
修改位置： X   X   |-------|
保留元素：         5   7   8
改成 5 ： 5   5   5   7   8
                  ^       ^
                  min     max

low = 0, high = 8-5 = 3, score = 3
```

### 2.2 為什麼這樣一定能得到最小總分？

不能只說「低分能變成零」，還要確認高分的下界也能同時達成。

1. 不論修改哪兩個位置，其餘 `n-2` 個位置都保留原值。
2. 修改後的高分至少等於這些保留元素的最大值減最小值；低分至少為零。
3. 令所有保留方式中最小的範圍為 `R`，任何修改方式的總分都至少為 `R`。
4. 選擇範圍為 `R` 的保留方式，將另外兩個值都放到某個保留值上，就能同時做到低分為零、高分為 `R`。

下界可以達成，所以答案恰好是 `R`。當 `n=3` 時，只保留一個值，把其他兩個改成該值即可得到零。

### 2.3 為什麼只需要三種策略？

排序後記為 `a[0] <= a[1] <= ... <= a[n-1]`。要選 `n-2` 個元素並最小化範圍，只需考慮排序後連續的 `n-2` 個元素。

理由是：任何選取方式的最左與最右索引之間，至少容得下 `n-2` 個元素；在該區間內取一段連續的 `n-2` 個元素，範圍不會更大。修改中間值卻保留兩端，也無法縮小兩端決定的高分。

長度為 `n` 的排序陣列，長度為 `n-2` 的連續區間只有三個：

```text
                         保留的索引區間       候選分數
修改最小兩個： X X [................]         a[n-1] - a[2]
                       2 ... n-1

兩端各改一個： X [................] X         a[n-2] - a[1]
                     1 ... n-2

修改最大兩個： [................] X X         a[n-3] - a[0]
                    0 ... n-3

X 表示原值不再限制範圍，實際操作仍是替換，沒有刪除元素。
```

答案就是三個候選分數的最小值。

## 3. 解法一：排序 + 貪心（MinimizeSum）

### 設計說明

1. 記錄陣列長度 `n`，使用 `Array.Sort(nums)` 原地升冪排序。
2. 計算修改最小兩個、兩端各一個、最大兩個後的保留範圍。
3. 回傳三個範圍的最小值。

排序的目的，是把「哪些值限制了範圍」轉成固定索引。貪心的依據是只需要處理極端值，正確性來自前述下界與三個連續區間的推導。

```csharp
int changeTwoSmallest = nums[n - 1] - nums[2];
int changeBothEnds = nums[n - 2] - nums[1];
int changeTwoLargest = nums[n - 3] - nums[0];
return Math.Min(changeTwoSmallest, Math.Min(changeBothEnds, changeTwoLargest));
```

注意：修改最小兩個後，最小保留值是 `nums[2]`，不能使用 `nums[n-2]`。後者只計算排序後最大兩個值之間的差，沒有涵蓋所有保留元素。

### 範例一完整流程

```text
原始 nums： [1,4,7,8,5]
排序 nums： [1,4,5,7,8]
索引：       0 1 2 3 4

策略 A：修改最小兩個
             X X [5 7 8]  --> 8-5 = 3

策略 B：兩端各修改一個
             X [4 5 7] X  --> 7-4 = 3

策略 C：修改最大兩個
             [1 4 5] X X  --> 5-1 = 4

答案：min(3,3,4) = 3
```

採用策略 A，在原始位置把 `1` 與 `4` 改成 `5`，可得到 `[5,5,7,8,5]`。低分為零，高分為 `8-5=3`，與回傳值一致。這和官方改成 `6` 的方式都是最佳解。

### 範例二完整流程

```text
原始： [1,4,3]
排序： [1,3,4]，n=3

A：a[2]-a[2] = 4-4 = 0  --> 保留 4
B：a[1]-a[1] = 3-3 = 0  --> 保留 3
C：a[0]-a[0] = 1-1 = 0  --> 保留 1

min(0,0,0) = 0
```

### 複雜度與輸入影響

- 時間：`O(n log n)`，主要成本來自排序。
- 額外空間：候選值計算為 `O(1)`；計入 .NET 陣列排序的遞迴呼叫堆疊則為 `O(log n)`。
- 會改變輸入陣列的元素順序。方法只計算答案，不會實際套用那兩個替換操作。

## 4. 解法二：單次遍歷維護六個極值（MinimizeSum2）

### 從排序解法繼續觀察

三個公式只讀取最小三個與最大三個元素，其他中間值不會直接參與計算。因此不必把整個陣列排序，只要掃描時保留這六個名次。

| 變數 | 意義 | 排序後對應索引 |
| --- | --- | --- |
| `min1` | 最小值 | `a[0]` |
| `min2` | 第二小 | `a[1]` |
| `min3` | 第三小 | `a[2]` |
| `max1` | 最大值 | `a[n-1]` |
| `max2` | 第二大 | `a[n-2]` |
| `max3` | 第三大 | `a[n-3]` |

這些名次按**元素數量**計算，不是按不同數值計算。例如 `[1,1,1,9,9]` 的前三小是 `[1,1,1]`，前三大是 `[9,9,1]`。

### 如何維護最小三個值？

三個最小值初始為 `int.MaxValue`，表示尚未填入。讀到 `x` 時：

- 若 `x < min1`，原本第一小移到第二小、原本第二小移到第三小，`x` 成為第一小。
- 否則若 `x < min2`，原本第二小移到第三小，`x` 成為第二小。
- 否則若 `x < min3`，只更新第三小。
- 否則 `x` 不影響前三小。

```text
例如：目前前三小 [4,7,8]，讀到 x=1

舊值： min1=4   min2=7   min3=8
          |        |
          +----+   +----+
               v        v
新值： min1=1   min2=4   min3=7

賦值順序：min3=min2 --> min2=min1 --> min1=x
先搬後面的名次，才能保留仍需使用的舊值。
```

最大三個值則以 `int.MinValue` 初始化，使用 `>` 與對稱的搬移方式維護。

最小值與最大值必須使用兩個獨立的判斷鏈；不能合併成同一條 `else if`。掃描初期，一個元素可能同時屬於目前的最小三個與最大三個。

相等時雖然不會進入第一個嚴格比較，仍有機會進入後續名次。例如已有 `min1=1`、`min2` 尚未填入，下一個 `1` 仍會成為 `min2`。若三個名次都已是 `1`，則不需要更新。

### 範例一完整流程

依原始順序 `[1,4,7,8,5]` 掃描；表中的 `+INF` 與 `-INF` 分別代表兩個初始化哨兵，不是真正輸入值。

```text
讀入 x    min1  min2  min3       max1  max2  max3
------------------------------------------------
初始      +INF  +INF  +INF       -INF  -INF  -INF
1            1  +INF  +INF          1  -INF  -INF
4            1     4  +INF          4     1  -INF
7            1     4     7          7     4     1
8            1     4     7          8     7     4
5            1     4     5          8     7     5
------------------------------------------------

A：修改最小兩個 --> max1-min3 = 8-5 = 3
B：兩端各改一個 --> max2-min2 = 7-4 = 3
C：修改最大兩個 --> max3-min1 = 5-1 = 4

答案：min(3,3,4) = 3
```

最後讀到 `5` 時，它取代原本第三小的 `7`，也取代原本第三大的 `4`。這正好說明同一個元素可能同時更新兩側資訊。

### 範例二完整流程

```text
輸入順序： [1,4,3]

讀入 x    最小三個（升冪）      最大三個（降冪）
------------------------------------------------
1         [1,+INF,+INF]         [1,-INF,-INF]
4         [1,4,+INF]            [4,1,-INF]
3         [1,3,4]               [4,3,1]

A：4-4 = 0
B：3-3 = 0
C：1-1 = 0
答案：0
```

僅在全部元素掃描完畢後計算差值。因輸入至少有三個元素，此時六個名次均已填入有效值，不會拿初始化哨兵做差。

### 複雜度與輸入影響

- 時間：`O(n)`，每個元素只做固定次數的比較與賦值。
- 額外空間：`O(1)`，只保存六個極值。
- 不排序，也不修改輸入陣列。

## 5. 兩種解法比較

| 項目 | MinimizeSum | MinimizeSum2 |
| --- | --- | --- |
| 核心設計 | 排序後讀取固定索引 | 掃描時維護六個名次 |
| 時間 | `O(n log n)` | `O(n)` |
| 額外空間 | `O(log n)`，計入排序堆疊 | `O(1)` |
| 是否修改輸入 | 是，原地排序 | 否 |
| 理解重點 | 三種保留區間 | 極值搬移順序、重複值 |

初次理解可先閱讀排序解法，再把六個索引轉成六個變數，推導單次遍歷版本。兩者使用相同的數學結論。
