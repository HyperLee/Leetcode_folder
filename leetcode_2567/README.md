# LeetCode 2567：修改兩個元素後的最小分數

本專案使用 C# 實作 **Minimum Score by Changing Two Elements**，提供排序與單次遍歷兩種解法，以及可由 `Main` 直接執行的測試。

- 題目來源：[LeetCode 2567](https://leetcode.com/problems/minimum-score-by-changing-two-elements/)
- 更完整的題意入門與官方範例說明：[PROBLEM.md](PROBLEM.md)
- 程式碼：[Program.cs](leetcode_2567/Program.cs)

## 1. 題目說明

給定整數陣列 `nums`，從**不同位置**選取兩個元素進行比較，定義：

| 名稱 | 定義 |
| --- | --- |
| 低分（low score） | 所有元素配對中，最小的絕對差 |
| 高分（high score） | 所有元素配對中，最大的絕對差，即最大值減最小值 |
| 總分（score） | 低分 + 高分 |

修改陣列中兩個位置的數值後，回傳可以得到的**最小總分**。

修改是替換既有位置的數值，不會增減元素。新值不必出現在原陣列中，也可以讓不同位置存放相同數值。計算分數時仍須包含整個陣列；不只看修改過的位置，也不只比較相鄰位置。

### 輸入限制

- `3 <= nums.length <= 100000`。
- `1 <= nums[i] <= 1000000000`。
- 可以有重複值，輸入不保證已排序。
- 回傳最小總分，不需要回傳修改位置或修改後的陣列。

本專案兩個方法都以合法題目輸入為前提，不額外處理 `null` 或長度不足 3 的陣列。最終候選值介於 `0` 與 `999999999`，可使用 C# `int`。

### 官方範例

```text
範例一
輸入： [1,4,7,8,5]
修改： [6,6,7,8,5]
低分： |6-6| = 0
高分： 8-5 = 3
輸出： 0+3 = 3

範例二
輸入： [1,4,3]
修改： [1,1,1]
低分： 0
高分： 0
輸出： 0
```

## 2. 解題概念與出發點

### 2.1 先讓低分變成零

絕對差不會小於零。如果讓兩個不同位置的值相同，低分就能達到零。

因此可以考慮：保留 `n-2` 個元素，把另外兩個位置都改成某個保留元素的值。這樣既能製造重複值，又不會擴大保留元素原有的最大值與最小值範圍。

```text
原始排序： 1   4   5   7   8
修改位置： X   X   |-------|
保留元素：         5   7   8
改成 5 ： 5   5   5   7   8
                  ^       ^
                  min     max

low = 0, high = 8-5 = 3, score = 3
```

### 2.2 為什麼這樣一定能得到最小總分？

不能只說「低分能變成零」，還要確認高分的下界也能同時達成。

1. 不論修改哪兩個位置，其餘 `n-2` 個位置都保留原值。
2. 修改後的高分至少等於這些保留元素的最大值減最小值；低分至少為零。
3. 令所有保留方式中最小的範圍為 `R`，任何修改方式的總分都至少為 `R`。
4. 選擇範圍為 `R` 的保留方式，將另外兩個值都放到某個保留值上，就能同時做到低分為零、高分為 `R`。

下界可以達成，所以答案恰好是 `R`。當 `n=3` 時，只保留一個值，把其他兩個改成該值即可得到零。

### 2.3 為什麼只需要三種策略？

排序後記為 `a[0] <= a[1] <= ... <= a[n-1]`。要選 `n-2` 個元素並最小化範圍，只需考慮排序後連續的 `n-2` 個元素。

理由是：任何選取方式的最左與最右索引之間，至少容得下 `n-2` 個元素；在該區間內取一段連續的 `n-2` 個元素，範圍不會更大。修改中間值卻保留兩端，也無法縮小兩端決定的高分。

長度為 `n` 的排序陣列，長度為 `n-2` 的連續區間只有三個：

```text
                         保留的索引區間       候選分數
修改最小兩個： X X [................]         a[n-1] - a[2]
                       2 ... n-1

兩端各改一個： X [................] X         a[n-2] - a[1]
                     1 ... n-2

修改最大兩個： [................] X X         a[n-3] - a[0]
                    0 ... n-3

X 表示原值不再限制範圍，實際操作仍是替換，沒有刪除元素。
```

答案就是三個候選分數的最小值。

## 3. 解法一：排序 + 貪心（MinimizeSum）

### 設計說明

1. 記錄陣列長度 `n`，使用 `Array.Sort(nums)` 原地升冪排序。
2. 計算修改最小兩個、兩端各一個、最大兩個後的保留範圍。
3. 回傳三個範圍的最小值。

排序的目的，是把「哪些值限制了範圍」轉成固定索引。貪心的依據是只需要處理極端值，正確性來自前述下界與三個連續區間的推導。

```csharp
int changeTwoSmallest = nums[n - 1] - nums[2];
int changeBothEnds = nums[n - 2] - nums[1];
int changeTwoLargest = nums[n - 3] - nums[0];
return Math.Min(changeTwoSmallest, Math.Min(changeBothEnds, changeTwoLargest));
```

注意：修改最小兩個後，最小保留值是 `nums[2]`，不能使用 `nums[n-2]`。後者只計算排序後最大兩個值之間的差，沒有涵蓋所有保留元素。

### 範例一完整流程

```text
原始 nums： [1,4,7,8,5]
排序 nums： [1,4,5,7,8]
索引：       0 1 2 3 4

策略 A：修改最小兩個
             X X [5 7 8]  --> 8-5 = 3

策略 B：兩端各修改一個
             X [4 5 7] X  --> 7-4 = 3

策略 C：修改最大兩個
             [1 4 5] X X  --> 5-1 = 4

答案：min(3,3,4) = 3
```

採用策略 A，在原始位置把 `1` 與 `4` 改成 `5`，可得到 `[5,5,7,8,5]`。低分為零，高分為 `8-5=3`，與回傳值一致。這和官方改成 `6` 的方式都是最佳解。

### 範例二完整流程

輸入 `[1,4,3]` 排序後為 `[1,3,4]`，長度 `n=3`。可以修改兩個位置，因此只需要保留 `n-2=1` 個元素的原值。

先將 `n=3` 代入三種策略的公式：

```text
原始： [1,4,3]
排序： [1,3,4]，n=3

A：修改最小兩個
   a[n-1]-a[2] = a[2]-a[2] = 4-4 = 0  --> 保留 4

B：兩端各修改一個
   a[n-2]-a[1] = a[1]-a[1] = 3-3 = 0  --> 保留 3

C：修改最大兩個
   a[n-3]-a[0] = a[0]-a[0] = 1-1 = 0  --> 保留 1

min(0,0,0) = 0
```

#### 為什麼可以「自己減自己」？

這裡的減法是在計算**保留區間的最大值減最小值**。當區間只包含一個元素時，最大值與最小值就是同一個值，因此區間範圍為零。

以策略 A 為例，排序後修改最小兩個值 `1`、`3`，只保留 `4`：

```text
排序後：       [1, 3, 4]
索引：         0  1  2
修改位置：     X  X  |
保留區間：          [4]

保留區間最大值 = a[2] = 4
保留區間最小值 = a[2] = 4
保留區間範圍   = a[2]-a[2] = 4-4 = 0
```

**這不表示拿同一個位置的元素與自己配對。** 題目計算低分、高分時，仍要求選取不同位置；上述公式只是先求出保留區間的範圍。

接著，將另外兩個位置都改成保留值 `4`，就能讓整個陣列的範圍也等於零：

```text
修改前（排序後）： [1, 3, 4]
修改動作：         1->4、3->4，原本的 4 保留
修改後：           [4, 4, 4]
索引：             0  1  2

不同位置的所有配對：
索引 0 與 1：|4-4| = 0
索引 0 與 2：|4-4| = 0
索引 1 與 2：|4-4| = 0

低分 = 所有配對的最小絕對差 = 0
高分 = 所有配對的最大絕對差 = 0
總分 = 0+0 = 0
```

三種策略都可以用相同方式實現。下表以排序後的位置展示替換；實際修改原始陣列的對應位置也會得到相同結果：

| 策略 | 保留原值 | 替換動作 | 修改後陣列 | 低分 | 高分 | 總分 |
| --- | --- | --- | --- | ---: | ---: | ---: |
| A：修改最小兩個 | `4` | `1->4`、`3->4` | `[4,4,4]` | 0 | 0 | 0 |
| B：兩端各修改一個 | `3` | `1->3`、`4->3` | `[3,3,3]` | 0 | 0 | 0 |
| C：修改最大兩個 | `1` | `3->1`、`4->1` | `[1,1,1]` | 0 | 0 | 0 |

「只保留一個元素」指的是只保留一個位置的**原值**，另外兩個位置仍然存在，並沒有刪除元素。修改完成後始終有三個不同位置，因此可以合法地從不同位置選出相同數值來比較。

三種策略的總分都達到零，而絕對差不可能為負數，所以最小答案確定是 `0`。程式透過公式計算這個結果，不需要實際將陣列改成三個相同值。

### 複雜度與輸入影響

- 時間：`O(n log n)`，主要成本來自排序。
- 額外空間：候選值計算為 `O(1)`；計入 .NET 陣列排序的遞迴呼叫堆疊則為 `O(log n)`。
- 會改變輸入陣列的元素順序。方法只計算答案，不會實際套用那兩個替換操作。

## 4. 解法二：單次遍歷維護六個極值（MinimizeSum2）

### 從排序解法繼續觀察

三個公式只讀取最小三個與最大三個元素，其他中間值不會直接參與計算。因此不必把整個陣列排序，只要掃描時保留這六個名次。

| 變數 | 意義 | 排序後對應索引 |
| --- | --- | --- |
| `min1` | 最小值 | `a[0]` |
| `min2` | 第二小 | `a[1]` |
| `min3` | 第三小 | `a[2]` |
| `max1` | 最大值 | `a[n-1]` |
| `max2` | 第二大 | `a[n-2]` |
| `max3` | 第三大 | `a[n-3]` |

這些名次按**元素數量**計算，不是按不同數值計算。例如 `[1,1,1,9,9]` 的前三小是 `[1,1,1]`，前三大是 `[9,9,1]`。

### 如何維護最小三個值？

這些變數描述的是**目前已經讀過的元素**，並非還沒掃描完就知道整個陣列的答案。每讀入一個 `x`，就將它插入適當名次，只留下最小三個元素。

初始化為 `int.MaxValue`，表示該名次尚未填入。因為合法輸入都比它小，真實元素一定能逐步填入。以下以 `+INF` 表示這個哨兵。

```text
名次：        第一小      第二小      第三小
變數：        min1        min2        min3
初始：        +INF        +INF        +INF
維持關係：    min1   <=   min2   <=   min3
```

#### 情況 A：x 成為新的第一小

假設目前前三小是 `[4,7,8]`，讀到 `x=1`。把新值加入後，候選元素為 `[1,4,7,8]`，只需保留 `[1,4,7]`，原本第三小的 `8` 被擠出前三名。

```text
元素去向：
x=1       --> 新 min1
舊 min1=4 --> 新 min2
舊 min2=7 --> 新 min3
舊 min3=8 --> 不再保存在最小三個名次中

實際賦值順序                  min1   min2   min3
------------------------------------------------
原始狀態                         4      7      8
1. min3 = min2                   4      7      7
2. min2 = min1                   4      4      7
3. min1 = x                      1      4      7
```

為什麼要先更新 `min3`？因為 `min3` 需要的是**舊的 `min2`**，而 `min2` 需要的是**舊的 `min1`**。先保存後面的名次，再覆寫前面的來源，才不會遺失舊值。

中途出現 `[4,7,7]`、`[4,4,7]` 是搬移過程的暫時狀態，不表示真的讀入了重複的 `7` 或 `4`；這一輪更新完成後才是新的前三小。

如果反過來更新，就會出錯：

```text
錯誤順序                      min1   min2   min3
------------------------------------------------
原始狀態                         4      7      8
1. min1 = x                      1      7      8  <-- 舊的 4 遺失
2. min2 = min1                   1      1      8  <-- 複製到新的 1
3. min3 = min2                   1      1      1  <-- 再次複製新的 1

正確應為 [1,4,7]，錯誤結果卻是 [1,1,1]。
```

#### 情況 B：x 成為新的第二小

以下各情況都從同一組舊狀態 `[4,7,8]` 重新示範，並非接續上一個情況。

讀到 `x=5`，先判斷 `5 < min1`，也就是 `5 < 4`，不成立；接著 `5 < min2`，也就是 `5 < 7`，成立。第一小不用動，舊第二小移到第三小。

```text
插入概念： [4,7,8] + 5 --> [4,5,7,8] --> 保留 [4,5,7]

實際賦值順序                  min1   min2   min3
------------------------------------------------
原始狀態                         4      7      8
1. min3 = min2                   4      7      7
2. min2 = x                      4      5      7
```

仍然要先保存舊 `min2=7`，才能把 `min2` 改成 `5`；否則第三小會錯誤地變成新值 `5`。

#### 情況 C：x 成為新的第三小，或無須更新

```text
舊狀態： [4,7,8]

x=7   --> 7<4 不成立，7<7 不成立，7<8 成立。
          只做 min3=7，得到 [4,7,7]。
x=9   --> 9<4、9<7、9<8 都不成立，維持 [4,7,8]。
```

第三小分支只需 `min3 = x`，因為第一小與第二小都不受影響，也沒有第四小需要保存。`x=7` 的例子同時說明：不同位置的相同數值，可以分別占據第二小與第三小。

### 如何維護最大三個值？

最大值採用對稱的邏輯，但比較方向改為 `>`。三個名次初始為 `int.MinValue`，以下以 `-INF` 表示。

```text
名次：        第一大      第二大      第三大
變數：        max1        max2        max3
初始：        -INF        -INF        -INF
維持關係：    max1   >=   max2   >=   max3
```

#### 情況 A：x 成為新的第一大

假設目前前三大是 `[8,7,4]`，讀到 `x=10`。新順序是 `[10,8,7,4]`，因此保留 `[10,8,7]`。

```text
元素去向：
x=10      --> 新 max1
舊 max1=8 --> 新 max2
舊 max2=7 --> 新 max3
舊 max3=4 --> 不再保存在最大三個名次中

實際賦值順序                  max1   max2   max3
------------------------------------------------
原始狀態                         8      7      4
1. max3 = max2                   8      7      7
2. max2 = max1                   8      8      7
3. max1 = x                     10      8      7
```

同樣先保存舊第二名，再保存舊第一名，最後放入新值。若先做 `max1=x`，後面再複製 `max1`，就會複製到新的 `10`，遺失原本的 `8`。

#### 情況 B：x 成為新的第二大

這個情況使用舊狀態 `[8,6,4]`，讀到 `x=7`：`7 > 8` 不成立，接著 `7 > 6` 成立，因此進入第二大分支。

```text
插入概念： [8,6,4] + 7 --> [8,7,6,4] --> 保留 [8,7,6]

實際賦值順序                  max1   max2   max3
------------------------------------------------
原始狀態                         8      6      4
1. max3 = max2                   8      6      6
2. max2 = x                      8      7      6
```

第一大維持 `8`，先把舊第二大 `6` 保存到 `max3`，再將 `max2` 設為 `7`。

#### 情況 C：x 成為新的第三大，或無須更新

```text
舊狀態： [8,7,4]

x=5 --> 5>8 不成立，5>7 不成立，5>4 成立。
        只做 max3=5，得到 [8,7,5]。
x=3 --> 3>8、3>7、3>4 都不成立，維持 [8,7,4]。
```

### 判斷順序與賦值順序是兩件事

**判斷時從第一名開始**，找出 `x` 應該插入的最高名次；**搬移時從第三名開始**，保存即將被覆寫的舊值。

```text
判斷順序： 第一名 --> 第二名 --> 第三名
搬移順序： 第三名 <-- 第二名 <-- 第一名 <-- x
```

同一側使用 `if / else if / else if`，一輪只選一個插入位置。若改成三個獨立的 `if`，同一個 `x` 可能在更新第一名後，又被放進第二名、第三名，造成同一個元素被重複計入。

但最小值與最大值是**兩條獨立的判斷鏈**。每個 `x` 都要分別檢查兩側，不能把最大值鏈接在最小值鏈的 `else if` 後面。

以第一個讀入的 `x=1` 為例：

```text
最小值側： [+INF,+INF,+INF] --> [1,+INF,+INF]
最大值側： [-INF,-INF,-INF] --> [1,-INF,-INF]

目前只讀過一個元素，因此它同時是目前最小與最大的元素。
```

### 重複值如何占據不同名次？

嚴格比較 `<`、`>` 不代表排除重複值；相等時會繼續檢查下一個名次。以下逐一讀入不同位置的四個 `1`：

```text
讀入元素     最小三個          最大三個
------------------------------------------------
第一個 1     [1,+INF,+INF]     [1,-INF,-INF]
第二個 1     [1,1,+INF]        [1,1,-INF]
第三個 1     [1,1,1]           [1,1,1]
第四個 1     [1,1,1]           [1,1,1]（不需要更新）
```

第二個 `1` 無法取代第一名，但能填入尚未填滿的第二名；第三個則填入第三名。當前三名已全是 `1`，再來一個 `1` 也不會改變這三個名次的數值。

### 範例一完整流程

依原始順序 `[1,4,7,8,5]` 掃描；表中的 `+INF` 與 `-INF` 分別代表兩個初始化哨兵，不是真正輸入值。

```text
讀入 x    min1  min2  min3       max1  max2  max3
------------------------------------------------
初始      +INF  +INF  +INF       -INF  -INF  -INF
1            1  +INF  +INF          1  -INF  -INF
4            1     4  +INF          4     1  -INF
7            1     4     7          7     4     1
8            1     4     7          8     7     4
5            1     4     5          8     7     5
------------------------------------------------

A：修改最小兩個 --> max1-min3 = 8-5 = 3
B：兩端各改一個 --> max2-min2 = 7-4 = 3
C：修改最大兩個 --> max3-min1 = 5-1 = 4

答案：min(3,3,4) = 3
```

最後讀到 `5` 時，它取代原本第三小的 `7`，也取代原本第三大的 `4`。這正好說明同一個元素可能同時更新兩側資訊。

下面將每一輪的更新動作展開，與上表對照：

```text
第 1 輪，x=1
min：1<+INF，進入第一小分支。
     min3=min2(+INF) --> min2=min1(+INF) --> min1=1
max：1>-INF，進入第一大分支。
     max3=max2(-INF) --> max2=max1(-INF) --> max1=1
結果：min=[1,+INF,+INF]，max=[1,-INF,-INF]

第 2 輪，x=4
min：4<1 不成立，4<+INF 成立，進入第二小分支。
     min3=min2(+INF) --> min2=4
max：4>1 成立，進入第一大分支。
     max3=max2(-INF) --> max2=max1(1) --> max1=4
結果：min=[1,4,+INF]，max=[4,1,-INF]

第 3 輪，x=7
min：7<1、7<4 都不成立，7<+INF 成立，只更新 min3=7。
max：7>4 成立。
     max3=max2(1) --> max2=max1(4) --> max1=7
結果：min=[1,4,7]，max=[7,4,1]

第 4 輪，x=8
min：8<1、8<4、8<7 都不成立，不更新。
max：8>7 成立。
     max3=max2(4) --> max2=max1(7) --> max1=8
結果：min=[1,4,7]，max=[8,7,4]

第 5 輪，x=5
min：5<1、5<4 都不成立，5<7 成立，只更新 min3=5。
max：5>8、5>7 都不成立，5>4 成立，只更新 max3=5。
結果：min=[1,4,5]，max=[8,7,5]
```

每一輪只保存必要的六個名次，沒有把原陣列排序。掃描完成後再使用三個候選公式，便能得到與排序解法相同的答案。

### 範例二完整流程

```text
輸入順序： [1,4,3]

讀入 x    最小三個（升冪）      最大三個（降冪）
------------------------------------------------
1         [1,+INF,+INF]         [1,-INF,-INF]
4         [1,4,+INF]            [4,1,-INF]
3         [1,3,4]               [4,3,1]

A：4-4 = 0
B：3-3 = 0
C：1-1 = 0
答案：0
```

僅在全部元素掃描完畢後計算差值。因輸入至少有三個元素，此時六個名次均已填入有效值，不會拿初始化哨兵做差。

### 複雜度與輸入影響

- 時間：`O(n)`，每個元素只做固定次數的比較與賦值。
- 額外空間：`O(1)`，只保存六個極值。
- 不排序，也不修改輸入陣列。

## 5. 兩種解法比較

| 項目 | MinimizeSum | MinimizeSum2 |
| --- | --- | --- |
| 核心設計 | 排序後讀取固定索引 | 掃描時維護六個名次 |
| 時間 | `O(n log n)` | `O(n)` |
| 額外空間 | `O(log n)`，計入排序堆疊 | `O(1)` |
| 是否修改輸入 | 是，原地排序 | 否 |
| 理解重點 | 三種保留區間 | 極值搬移順序、重複值 |

初次理解可先閱讀排序解法，再把六個索引轉成六個變數，推導單次遍歷版本。兩者使用相同的數學結論。
