## 題目說明

給定兩個字串 `s` 與 `t`，請計算並回傳在 `s` 的所有子序列中，等於 `t` 的不同子序列數量。

子序列是從原字串刪除零個或多個字元後得到的結果，但保留剩餘字元的原本順序。
因此可以跳過字元，卻不能重新排列字元。

本題計算的是「選取索引的方法數」，而不只是最後看起來相同的文字數量。
例如 `s = "rabbbit"`、`t = "rabbit"` 時，可以從 `s` 中連續三個 `b` 選取其中兩個，
因此共有 3 種不同的索引選法。

### 官方範例 1

~~~text
s = "rabbbit"
t = "rabbit"
輸出 = 3
~~~

來源字串中的三個連續 `b` 有三種不同的索引選擇方式，其他字元的配對位置固定。

### 官方範例 2

~~~text
s = "babgbag"
t = "bag"
輸出 = 5
~~~

可以選取不同位置的 `b`、`a`、`g`，總共有 5 種符合順序的索引組合。

## 限制條件

依照 [LeetCode 官方題目頁](https://leetcode.com/problems/distinct-subsequences/description/)：

- `1 <= s.length, t.length <= 1000`
- `s` 與 `t` 只包含英文字母。
- 測試案例保證答案符合 32 位元有號整數範圍。

本專案另外使用 `t = ""` 驗證動態規劃的空目標邊界。空字串不在上述官方輸入限制內，
但它能直接驗證「空目標在任何來源字串中都有一種選法：什麼都不選」這個基底條件。

## 解題概念與出發點

如果直接列舉 `s` 的所有子序列，長度為 `m` 的字串最多有 `2^m` 種選法，
當 `m` 增加時會快速失去效率。這題的關鍵是，每次處理一個來源字元時，
只需要考慮兩種選擇：

1. 跳過目前的 `s[i]`，繼續使用後面的來源字元。
2. 當 `s[i] == t[j]` 時，使用目前的 `s[i]` 配對 `t[j]`，同時處理兩邊的下一個位置。

這兩種選擇會產生許多重疊子問題。例如，不同的前綴選法可能都會抵達相同的
`s[i:]` 與 `t[j:]` 狀態；動態規劃可以將該狀態的答案保存並重複使用。

本專案定義：

~~~text
dp[i, j] = 從 s[i..m-1] 中選取字元，組成 t[j..n-1] 的不同方法數
~~~

其中 `i` 是來源字串索引，`j` 是目標字串索引。`dp[0, 0]` 就是整題要求的答案。

## 解法設計：二維 DP

對應程式方法：`NumDistinct(string s, string t)`

### 1. 先處理不可能情況

令 `m = s.Length`、`n = t.Length`。如果 `m < n`，來源字串的字元數量少於目標字串，
不可能選出足夠的字元組成 `t`，因此直接回傳 `0`。

### 2. 建立 DP 陣列

程式配置大小為 `(m + 1) x (n + 1)` 的二維陣列：

~~~csharp
int[,] dp = new int[m + 1, n + 1];
~~~

多出的一列與一欄用來表示「來源後綴或目標後綴已經空了」的狀態。

### 3. 初始化邊界

當 `j == n` 時，目標後綴 `t[j:]` 是空字串。從任何 `s[i:]` 出發，
都可以透過不選取任何字元得到空字串，因此：

~~~text
dp[i, n] = 1
~~~

當 `i == m` 且 `j < n` 時，來源後綴已經是空字串，但目標仍有字元，
無法完成目標；二維陣列的預設值 `0` 正好代表這個邊界。

### 4. 狀態轉移

若 `s[i] == t[j]`，目前來源字元有兩種選擇：

~~~text
dp[i, j] = dp[i + 1, j] + dp[i + 1, j + 1]
             跳過 s[i]     使用 s[i] 配對 t[j]
~~~

若 `s[i] != t[j]`，目前字元不能配對，只能跳過：

~~~text
dp[i, j] = dp[i + 1, j]
~~~

### 5. 填表順序

每個狀態都依賴下一列的結果，所以外層索引 `i` 必須由 `m - 1` 遞減到 `0`；
同一列中，`j` 也由 `n - 1` 遞減到 `0`。所有狀態完成後回傳左上角的 `dp[0, 0]`。

### 正確性說明

對任一狀態 `dp[i, j]`：

- 若目前字元不同，任何有效選法都不能使用 `s[i]` 配對 `t[j]`，
  所以所有有效選法恰好來自 `dp[i + 1, j]`。
- 若目前字元相同，每一種有效選法都恰好屬於兩類之一：
  使用 `s[i]` 配對 `t[j]`，或跳過 `s[i]`。兩類不重疊，因此可以將
  `dp[i + 1, j + 1]` 與 `dp[i + 1, j]` 相加。
- 邊界條件正確描述了空目標與空來源的情況。

因此依照由後往前的填表順序，所有 DP 狀態都正確；最終 `dp[0, 0]`
就是從完整 `s` 組成完整 `t` 的不同索引選法數量。

### 複雜度

令 `m = s.Length`、`n = t.Length`：

- 時間複雜度：`O(m * n)`，每個 DP 格子只計算一次。
- 額外空間複雜度：`O(m * n)`，配置 `(m + 1) x (n + 1)` 的二維陣列。

## ASCII 陣列圖解

以下用 `s = "babgbag"`、`t = "bag"` 示範實際 DP 陣列。
列索引 `i` 對應 `s`，欄索引 `j` 對應 `t`；最右欄是空目標，
最下列是空來源。表格中的數字就是各個 `dp[i, j]` 的值。

~~~text
                         t[j] 欄索引 →
s[i] 列索引 ↓       j=0:b   j=1:a   j=2:g   j=3:空字串
---------------------------------------------------------
i=0, s[0]=b              5        3        2        1
i=1, s[1]=a              2        3        2        1
i=2, s[2]=b              2        1        2        1
i=3, s[3]=g              1        1        2        1
i=4, s[4]=b              1        1        1        1
i=5, s[5]=a              0        1        1        1
i=6, s[6]=g              0        0        1        1
i=7, 空來源               0        0        0        1
~~~

陣列的大小是 `(7 + 1) x (3 + 1)`，答案位於左上角 `dp[0, 0] = 5`。
最右欄全部是 `1`，因為每個來源後綴都能以唯一方式組成空目標；
最下列除了最右角以外都是 `0`，因為空來源無法組成非空目標。

### 單一格的依賴方向

當 `s[i]` 與 `t[j]` 相同時，會同時使用下一列的兩個狀態：

~~~text
                         dp[i + 1, j]  （跳過 s[i]）
                        /
dp[i, j]  （目前格子）
                        \
                         dp[i + 1, j + 1] （使用 s[i]）
~~~

因此填表時必須先完成較下面的列。程式的實際順序是：

~~~text
初始化最右欄 dp[i, n] = 1
    ↓
i = m - 1, m - 2, ..., 0
    每一列依序計算 j = n - 1, n - 2, ..., 0
    ↓
回傳 dp[0, 0]
~~~

## 範例演示流程

### 範例一：`rabbbit` 組成 `rabbit`

來源字串索引如下：

~~~text
索引 i：  0   1   2   3   4   5   6
s[i] ：   r   a   b   b   b   i   t

目標索引 j： 0   1   2   3   4   5
t[j]      ： r   a   b   b   i   t
~~~

`r`、`a`、`i`、`t` 的配對位置固定。目標只需要兩個 `b`，
而來源有三個連續的 `b`，可以分別跳過其中一個，因此得到 3 種不同索引選法。
DP 不必列出所有完整子序列，而是在每個 `b` 的狀態累積「使用」與「跳過」的數量。

### 範例二：`babgbag` 組成 `bag`

從右下角開始建立最右欄後，再倒序計算其他格子。例如：

1. `dp[6, 2]` 對應 `s[6] = g`、`t[2] = g`，可以使用這個 `g`，
   再加上空目標的基底，因此得到 `1`。
2. `dp[5, 1]` 對應 `s[5] = a`、`t[1] = a`，可以使用 `a` 後得到
   `dp[6, 2]`，也可以跳過 `a`；兩者合計為 `1`。
3. `dp[0, 0]` 會累積所有符合 `b -> a -> g` 順序的選擇，最後得到 `5`。

這個流程同時說明了為什麼 `i` 往下、`j` 往右的狀態不能在目前格子之後才計算；
它們必須先被填好，當前格子才能直接查表。

### 邊界案例：空目標與來源較短

- `s = "abc"`、`t = ""`：直接使用最右欄的基底，答案為 `1`。
- `s = "ab"`、`t = "abc"`：來源長度小於目標長度，提前回傳 `0`。

## Main 固定測試案例

`Main` 不讀取命令列或主控台輸入，而是使用六組固定資料。
每組案例呼叫 `NumDistinct`，比較預期與實際結果並輸出 `PASS` 或 `FAIL`；
最後以程序結束碼表示是否所有案例都通過。

| 案例 | `s` | `t` | 預期 | 覆蓋情境 |
| --- | --- | --- | ---: | --- |
| 官方範例 1 | `"rabbbit"` | `"rabbit"` | 3 | 重複字元的多種索引選擇 |
| 官方範例 2 | `"babgbag"` | `"bag"` | 5 | 多個位置的組合計數 |
| 完全相同 | `"abc"` | `"abc"` | 1 | 精確匹配 |
| 重複字元 | `"aaa"` | `"aa"` | 3 | 重複字元選擇 |
| 空目標（DP 邊界） | `"abc"` | `""` | 1 | 空目標基底，官方限制外 |
| `s` 短於 `t` | `"ab"` | `"abc"` | 0 | 提前回傳條件 |
