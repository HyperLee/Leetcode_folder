# LeetCode 921：使括號有效的最少添加

這個專案使用 C# / .NET 10 實作 LeetCode 921「Minimum Add to Make Parentheses Valid」。
程式提供兩種解法，兩者都計算最少需要插入多少個括號，才能讓整個字串成為有效括號字串：

- `MinAddToMakeValid`：貪心計數法，只追蹤尚未配對的左括號數量。
- `MinAddToMakeValid2`：堆疊模擬法，使用 `Stack<char>` 保存所有尚未配對的括號。

題目連結：[Minimum Add to Make Parentheses Valid](https://leetcode.com/problems/minimum-add-to-make-parentheses-valid/description/)

## 題目說明

括號字串在符合以下任一條件時是有效的：

1. 它是空字串。
2. 它可以寫成 `AB`，其中 `A` 與 `B` 都是有效括號字串。
3. 它可以寫成 `(A)`，其中 `A` 是有效括號字串。

給定只由 `(` 與 `)` 組成的字串 `s`，一次操作可以在任意位置插入一個括號。請計算讓 `s` 變成有效括號字串所需的最少操作次數。

例如，輸入 `s = "())"` 時，只要插入一個 `(`，就能得到有效字串 `"(())"`，因此答案是 `1`。

## 限制條件

- `1 <= s.length <= 1000`
- `s[i]` 只可能是 `(` 或 `)`

題目限制來自 [LeetCode 題目頁](https://leetcode.com/problems/minimum-add-to-make-parentheses-valid/description/)。
本專案的本機 runner 另外測試空字串 `""`，用來確認方法在最小邊界情況下也能正常處理；空字串是有效括號字串，但不在上述線上輸入長度限制內。

## 兩種解法總覽

兩種方法都從左至右掃描字串，遇到可以配對的 `()` 就消除這一組；差別在於「如何保存尚未配對的狀態」：

| 解法 | 對應方法 | 核心狀態 | 主要資料結構 | 時間複雜度 | 額外空間 |
| --- | --- | --- | --- | ---: | ---: |
| 解法一：貪心計數 | `MinAddToMakeValid` | `leftCount` 與 `res` | 整數變數 | `O(n)` | `O(1)` |
| 解法二：堆疊模擬 | `MinAddToMakeValid2` | Stack 中的所有未配對括號 | `Stack<char>` | `O(n)` | `O(n)` |

解法二保存的資訊比較完整，因此比較容易直接觀察哪些括號尚未配對；解法一只保存計算答案所需的數量，因此使用的記憶體較少。兩者的配對規則與最終答案相同，並不是兩個不同的問題解法。

## 共同原理：最少插入數的來源

從左至右掃描時，每個前綴都必須能夠被某些左括號配對。最少插入數可以拆成兩種無法避免的成本：

1. **掃描途中遇到沒有左括號可配對的 `)`**：這個右括號前面沒有可用的 `(`，至少要在它前面補一個 `(`。
2. **掃描結束後仍剩餘的 `(`**：每個未配對的左括號都至少需要一個 `)` 收尾。

因此可以用下列公式理解答案：

```text
最少插入數
= 掃描途中無法配對的 ')' 數量
  + 掃描結束時未配對的 '(' 數量
```

兩種解法都遵守同一個決策：只要目前有可配對的 `(`，就讓讀到的 `)` 與它配對；只有在確定無法配對時，才保留一個必須補救的狀態。

## 解法一：貪心計數——只追蹤未配對左括號

### 核心狀態

解法一不保存實際括號，只維護兩個整數：

| 狀態 | 意義 |
| --- | --- |
| `leftCount` | 掃描目前前綴後，尚未配對的 `(` 數量 |
| `res` | 到目前為止，已確定必須插入的括號數量；這裡只累計無法配對的 `)` |

遇到 `)` 且 `leftCount == 0` 時，演算法不真的修改字串，而是執行 `res++`，代表在這個右括號前補一個必要的 `(`。掃描結束後，再把剩餘的 `leftCount` 加到 `res`，代表補上相同數量的 `)`。

### 掃描流程

對字串中的每個字元依序處理：

1. 若字元是 `(`，執行 `leftCount++`。
2. 若字元是 `)` 且 `leftCount > 0`，使用一個未配對的左括號，執行 `leftCount--`。
3. 若字元是 `)` 且 `leftCount == 0`，目前沒有左括號可配對，執行 `res++`。
4. 掃描結束後執行 `res += leftCount`，為所有剩餘的左括號補上右括號。

最後回傳 `res`。

### 為什麼答案是最少插入次數

- 每次讀到無法配對的 `)`，至少需要補一個 `(`；這些成本彼此獨立，不能由同一個插入的左括號同時修正兩個右括號。
- 掃描結束後，每個剩餘的 `(` 都需要一個 `)`；一個右括號只能完成一個配對。
- 演算法只在上述兩種必要情況發生時增加計數，已能配對的括號不會產生額外插入。

所以 `res` 累計的兩類必要成本，正好就是最少插入次數。

### 程式狀態與實作對照

| 程式條件或動作 | 狀態轉移 | 解題意義 |
| --- | --- | --- |
| `c == '('` | `leftCount++` | 多了一個等待配對的左括號 |
| `leftCount > 0` | `leftCount--` | 當前右括號與一個左括號配對 |
| `leftCount == 0` | `res++` | 補一個必要的左括號 |
| 迴圈結束 | `res += leftCount` | 為所有剩餘左括號補右括號 |

### 複雜度

- 時間複雜度：`O(n)`，每個字元只掃描一次。
- 空間複雜度：`O(1)`，只使用 `leftCount`、`res` 與少量迴圈變數。

### 範例 trace：`s = "())"`

| 索引 | 字元 | 動作 | `leftCount` | `res` |
| ---: | :---: | --- | ---: | ---: |
| 0 | `(` | 累積一個未配對左括號 | 1 | 0 |
| 1 | `)` | 與左括號配對 | 0 | 0 |
| 2 | `)` | 沒有左括號可配對，計入一個必要的 `(` | 0 | 1 |

掃描結束時 `leftCount == 0`，因此答案是 `res == 1`。

## 解法二：堆疊模擬——保存所有未配對括號

### 核心狀態

解法二使用 `Stack<char>` 保存目前所有尚未配對的括號，Stack 內容由底部到頂端表示尚未處理完的配對需求：

- `(` 留在 Stack 中，表示之後需要補一個 `)`。
- `)` 留在 Stack 中，表示之前需要補一個 `(`。

因此掃描結束後，Stack 中每一個元素都對應一次必要插入，`stack.Count` 就是答案。

### 掃描流程

對字串中的每個字元依序處理：

1. 若字元是 `(`，執行 `stack.Push(c)`，保存這個等待配對的左括號。
2. 若字元是 `)`，且 Stack 不為空、頂端是 `(`，執行 `stack.Pop()` 完成一組配對。
3. 其他情況代表目前的 `)` 沒有可配對的左括號，執行 `stack.Push(c)` 保存這個未配對的右括號。
4. 掃描結束後回傳 `stack.Count`。

### 為什麼 `stack.Count` 是最少插入次數

當遇到 `)` 時，只要 Stack 頂端有未配對的 `(`，就立即 Pop 配對；這不需要新增括號，也是當下能減少未配對數量的唯一方式。若沒有可配對的 `(`，這個 `)` 必須由新插入的 `(` 配對，因此必須保留在 Stack 中。

掃描結束後，Stack 中的每個元素都仍然缺少一個相反方向的括號，而且一個插入的括號最多只能補足一個未配對括號。因此每個 Stack 元素各需要一次插入，`stack.Count` 正好是最少答案。

### 程式狀態與實作對照

| 程式條件或動作 | Stack 狀態變化 | 解題意義 |
| --- | --- | --- |
| `c == '('` | `stack.Push(c)` | 保存一個等待右括號的左括號 |
| 頂端是 `(` 且目前是 `)` | `stack.Pop()` | 取出一個左括號，完成配對 |
| 目前的 `)` 無法配對 | `stack.Push(c)` | 保存一個需要補左括號的右括號 |
| 迴圈結束 | `return stack.Count` | 每個剩餘括號各需要補一個相反括號 |

### 複雜度

- 時間複雜度：`O(n)`，每個字元只會被 Push 一次，或在配對時被 Pop 一次。
- 空間複雜度：`O(n)`，最壞情況下所有字元都會留在 Stack 中，例如 `"((("` 或 `")))"`。

### 範例 trace：`s = ")("`

Stack 內容以下表的「底 → 頂」表示：

| 索引 | 字元 | 動作 | Stack（底 → 頂） |
| ---: | :---: | --- | --- |
| 0 | `)` | 沒有 `(` 可配對，Push `)` | `[)]` |
| 1 | `(` | Push `(`，等待之後的 `)` | `[), (]` |

掃描結束後 Stack 有一個 `)` 與一個 `(`，分別需要補一個 `(` 與一個 `)`；答案是 `2`。若輸入是 `()`，第二個字元會與頂端的 `(` 配對並 Pop，最後 Stack 為空，答案就是 `0`。

## 兩種解法的整合比較

以 `s = "())(()"` 為例，兩種解法都會得到 `2`，但保存的狀態不同：

| 方法 | 掃描結束狀態 | 代表的必要插入 | 答案 |
| --- | --- | --- | ---: |
| 貪心計數 | `res = 1`、`leftCount = 1` | 為一個多餘 `)` 補 `(`，為一個剩餘 `(` 補 `)` | 2 |
| 堆疊模擬 | Stack 為 `[), (]`（底 → 頂） | 為 `)` 補 `(`，為 `(` 補 `)` | 2 |

兩種方法的取捨如下：

- 若只需要答案，貪心法的 `O(1)` 額外空間較精簡。
- 若希望保留每個未配對括號並直接觀察配對過程，Stack 法較直觀，但需要 `O(n)` 額外空間。
