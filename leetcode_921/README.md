# LeetCode 921：使括號有效的最少添加

這個專案使用 C# / .NET 10 實作 LeetCode 921「Minimum Add to Make Parentheses Valid」。
程式提供兩種解法：解法一使用貪心法從左至右掃描，解法二使用 Stack 保存未配對括號；兩者都計算最少需要插入多少個括號，才能讓整個字串成為有效括號字串。

題目連結：[Minimum Add to Make Parentheses Valid](https://leetcode.com/problems/minimum-add-to-make-parentheses-valid/description/)

## 題目說明

括號字串在符合以下任一條件時是有效的：

1. 它是空字串。
2. 它可以寫成 `AB`，其中 `A` 與 `B` 都是有效括號字串。
3. 它可以寫成 `(A)`，其中 `A` 是有效括號字串。

給定只由 `(` 與 `)` 組成的字串 `s`，一次操作可以在任意位置插入一個括號。請計算讓 `s` 變成有效括號字串所需的最少操作次數。

例如，輸入 `s = "())"` 時，只要插入一個 `(`，就能得到有效字串 `"(())"`，因此答案是 `1`。

## 限制條件

- `1 <= s.length <= 1000`
- `s[i]` 只可能是 `(` 或 `)`

題目限制來自 [LeetCode 題目頁](https://leetcode.com/problems/minimum-add-to-make-parentheses-valid/description/)。
本專案的本機 runner 另外測試空字串 `""`，用來確認方法在最小邊界情況下也能正常處理；空字串是有效括號字串，但不在上述線上輸入長度限制內。

## 解題概念與出發點

從左至右掃描時，可以用一個數字表示目前前綴的括號狀態：

- 讀到 `(`，未配對的左括號數量增加一個。
- 讀到 `)`，如果有未配對的 `(`，就讓其中一個左右括號配對。
- 讀到 `)` 時若沒有任何未配對的 `(`，這個右括號不可能被前面內容修正；無論把新 `(` 插在哪個允許位置，都至少需要增加一個括號。

因此只需要維護兩個狀態：

| 狀態 | 意義 |
| --- | --- |
| `leftCount` | 掃描目前前綴後，尚未配對的 `(` 數量 |
| `res` | 到目前為止已確定必須插入的括號數量 |

這種作法也可以理解為維護 prefix balance：`leftCount` 不會小於零；當原字串的 balance 想要變成負數時，就立刻把必要的左括號計入 `res`，讓後續狀態重新回到可繼續配對的範圍。

## 解法：貪心掃描

### 掃描流程

對字串中的每個字元依序處理：

1. 若字元是 `(`，執行 `leftCount++`。
2. 若字元是 `)` 且 `leftCount > 0`，使用一個未配對的左括號，執行 `leftCount--`。
3. 若字元是 `)` 且 `leftCount == 0`，目前沒有左括號可配對，執行 `res++`，代表必須插入一個 `(`。
4. 掃描結束後，`leftCount` 個左括號仍沒有右括號，因此把 `leftCount` 加到 `res`。

最後的答案是 `res`。

### 為什麼是最少次數

可以把必要的插入分成兩類：

1. **前綴出現多餘的 `)`**：當讀到 `)` 且 `leftCount == 0` 時，前面沒有任何左括號可以配對。要讓這個右括號出現在有效字串中，至少需要補一個 `(`，所以每次 `res++` 都是不可避免的成本。
2. **結尾剩餘的 `(`**：掃描結束後，每個未配對的 `(` 都需要一個 `)`。一個右括號只能完成一個配對，所以至少要補上 `leftCount` 個右括號。

演算法只在確定無法配對時才增加插入數量，且不會為已經可以配對的括號額外插入字元。因此兩類必要成本的總和就是最小答案。

### 程式狀態與實作對照

| 程式位置 | 狀態轉移 | 解題意義 |
| --- | --- | --- |
| `c == '('` | `leftCount++` | 多了一個等待配對的左括號 |
| `leftCount > 0` | `leftCount--` | 當前右括號與一個左括號配對 |
| `leftCount == 0` | `res++` | 補一個必要的左括號 |
| 迴圈結束 | `res += leftCount` | 為所有剩餘左括號補右括號 |

### 複雜度

- 時間複雜度：`O(n)`，每個字元只掃描一次。
- 空間複雜度：`O(1)`，只使用 `leftCount`、`res` 與少量迴圈變數。

## 解法二：Stack 保存未配對括號

### 核心想法

解法一只記錄「尚未配對的左括號數量」；解法二則直接使用 `Stack<char>` 保存目前尚未配對的括號，讓每個括號的配對過程更直觀：

- 讀到 `(`：推入 Stack，等待後面的 `)` 配對。
- 讀到 `)`：若 Stack 頂端是 `(`，就取出頂端完成一組配對。
- 讀到 `)` 且無法與 Stack 頂端的 `(` 配對：把這個 `)` 推入 Stack，表示之後必須插入一個 `(`。

掃描結束後，Stack 中每個尚未配對的括號都需要一個插入的括號：未配對的 `(` 需要補 `)`，未配對的 `)` 需要補 `(`。因此 Stack 的元素數量就是最少插入次數。

### 掃描流程

對字串中的每個字元依序處理：

1. 若字元是 `(`，執行 `stack.Push(c)`。
2. 若字元是 `)` 且 Stack 不為空、頂端是 `(`，執行 `stack.Pop()` 完成配對。
3. 其他情況代表目前的 `)` 沒有可配對的左括號，執行 `stack.Push(c)` 保留這個未配對的右括號。
4. 掃描結束後回傳 `stack.Count`。

### 為什麼是最少次數

當遇到 `)` 時，只要 Stack 頂端有未配對的 `(`，就立即配對；這不需要新增括號，也是當下能減少未配對數量的唯一方式。若沒有可配對的 `(`，這個 `)` 必須由某個新插入的 `(` 配對，因此保留在 Stack 中代表一個不可避免的插入成本。

掃描結束後，Stack 中的每個元素都仍然缺少一個相反方向的括號，而且一個插入的括號最多只能補足一個未配對括號。因此每個 Stack 元素各需要一次插入，`stack.Count` 正好是最少答案。

### 程式狀態與實作對照

| 程式條件或動作 | Stack 狀態變化 | 解題意義 |
| --- | --- | --- |
| `c == '('` | `stack.Push(c)` | 保存一個等待右括號的左括號 |
| 頂端是 `(` 且目前是 `)` | `stack.Pop()` | 取出一個左括號，完成配對 |
| 目前的 `)` 無法配對 | `stack.Push(c)` | 保存一個需要補左括號的右括號 |
| 迴圈結束 | `return stack.Count` | 每個剩餘括號各需要補一個相反括號 |

### 複雜度

- 時間複雜度：`O(n)`，每個字元只會被 Push 一次，或在配對時被 Pop 一次。
- 空間複雜度：`O(n)`，最壞情況下所有字元都會留在 Stack 中，例如 `"((("` 或 `")))"`。

### 範例演示流程

以 `s = "())(()"` 為例，Stack 內容由底部到頂端表示如下：

| 索引 | 字元 | 動作 | Stack（底 → 頂） |
| ---: | :---: | --- | --- |
| 0 | `(` | Push `(` | `[(]` |
| 1 | `)` | 與頂端 `(` 配對並 Pop | `[]` |
| 2 | `)` | 沒有 `(` 可配對，Push `)` | `[)]` |
| 3 | `(` | Push `(` | `[), (]` |
| 4 | `(` | Push `(` | `[), (, (]` |
| 5 | `)` | 與頂端 `(` 配對並 Pop | `[), (]` |

掃描結束後 Stack 還有一個 `)` 與一個 `(`，所以需要分別補一個 `(` 與一個 `)`；答案是 `2`。

## 範例演示流程

### 範例一：`s = "())"`

| 索引 | 字元 | 動作 | `leftCount` | `res` |
| ---: | :---: | --- | ---: | ---: |
| 0 | `(` | 累積一個未配對左括號 | 1 | 0 |
| 1 | `)` | 與左括號配對 | 0 | 0 |
| 2 | `)` | 沒有左括號可配對，補一個 `(` | 0 | 1 |

掃描結束時沒有剩餘左括號，因此答案是 `1`。

### 範例二：`s = "((("`

| 索引 | 字元 | 動作 | `leftCount` | `res` |
| ---: | :---: | --- | ---: | ---: |
| 0 | `(` | 累積一個未配對左括號 | 1 | 0 |
| 1 | `(` | 再累積一個未配對左括號 | 2 | 0 |
| 2 | `(` | 再累積一個未配對左括號 | 3 | 0 |

字串結束後有三個左括號沒有配對，因此需要補三個 `)`，答案是 `3`。

### 範例三：`s = "())(()"`

| 索引 | 字元 | 動作 | `leftCount` | `res` |
| ---: | :---: | --- | ---: | ---: |
| 0 | `(` | 累積左括號 | 1 | 0 |
| 1 | `)` | 配對 | 0 | 0 |
| 2 | `)` | 沒有左括號可配對，補一個 `(` | 0 | 1 |
| 3 | `(` | 累積左括號 | 1 | 1 |
| 4 | `(` | 再累積左括號 | 2 | 1 |
| 5 | `)` | 與一個左括號配對 | 1 | 1 |

最後還剩一個未配對的 `(`，所以再補一個 `)`；總答案為 `1 + 1 = 2`。

### 範例四：`s = "))"`

第一個 `)` 與第二個 `)` 都沒有可配對的左括號，每個都必須各補一個 `(`，因此答案是 `2`。這個案例示範了演算法如何處理前綴 balance 變成負數的情況。
