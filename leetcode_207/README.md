## 題目說明

共有 `numCourses` 門課程，編號從 `0` 到 `numCourses - 1`。每筆先修關係：

```text
[a, b]
```

表示修習課程 `a` 前，必須先完成課程 `b`。如果所有課程都能完成，回傳 `true`；如果依賴關係形成循環，回傳 `false`。

例如：

- `[[1,0]]` 表示先完成課程 `0`，再修課程 `1`，因此可以完成。
- `[[1,0],[0,1]]` 表示課程 `0` 與 `1` 互相等待，因此無法完成。

### 限制條件

- `1 <= numCourses <= 2000`
- `0 <= prerequisites.length <= 5000`
- `prerequisites[i].length == 2`
- `0 <= ai, bi < numCourses`
- 所有先修課程組合互不相同

限制條件與題意以 [LeetCode 207 — Course Schedule](https://leetcode.com/problems/course-schedule/description/) 為準。

## 解題概念與出發點

把每門課視為圖的節點。對於先修關係 `[a, b]`，建立一條從 `b` 指向 `a` 的邊：

```text
b -> a
```

問題就轉換成：

> 這張有向圖是否存在環？

- 沒有環：至少存在一種合法的拓樸順序，可以完成所有課程。
- 存在環：環內每門課都必須等待另一門課，無法完成所有課程。

本專案用兩個角度偵測環：

- DFS 觀察「目前遞迴路徑」是否再次遇到同一節點。
- Kahn BFS 反覆移除入度為零的節點，觀察能否移除全部節點。

## 解法一：DFS 三色標記

### 設計說明

`CanFinish` 先以鄰接表建立 `先修課程 -> 後續課程` 的圖，再由每個尚未處理的節點開始 DFS。`states` 陣列記錄三種狀態：

| 狀態 | 名稱 | 意義 |
|---:|---|---|
| `0` | 未搜尋 | 尚未進入此節點 |
| `1` | 搜尋中 | 節點仍位於目前的遞迴路徑 |
| `2` | 已完成 | 此節點及其後續路徑已確認無環 |

DFS 的關鍵不是一般的「是否拜訪過」，而是分辨節點是否仍在目前路徑中：

1. 進入節點時，把狀態從 `0` 改為 `1`。
2. 遞迴檢查所有後續課程。
3. 如果遇到狀態 `1`，表示沿著有向邊回到目前路徑上的節點，找到回邊，也就是環。
4. 所有後續路徑都安全後，把狀態改為 `2`。
5. 再次遇到狀態 `2` 時可直接回傳，避免重複計算。

### 為什麼正確

- 如果 DFS 遇到狀態 `1` 的節點，該節點已在目前遞迴路徑上；從它到目前節點已有一條路徑，再加上目前的回邊便形成有向環，所以必須回傳 `false`。
- 如果所有節點都能完成 DFS，代表每條路徑都沒有回到搜尋中的節點，因此圖中沒有有向環，可以完成全部課程。
- 狀態 `2` 只會在所有後續節點都確認無環後設定，所以重用此結果不會漏掉環。

### 範例演示：三門課形成環

輸入：

```text
numCourses = 3
prerequisites = [[1,0], [2,1], [0,2]]
```

建立的邊為 `0 -> 1`、`1 -> 2`、`2 -> 0`。

1. 從課程 `0` 開始，狀態變成 `[1,0,0]`。
2. 沿著 `0 -> 1` 進入課程 `1`，狀態變成 `[1,1,0]`。
3. 沿著 `1 -> 2` 進入課程 `2`，狀態變成 `[1,1,1]`。
4. 課程 `2` 的後續是課程 `0`，但課程 `0` 仍為搜尋中。
5. 找到回邊 `2 -> 0`，確認存在環，回傳 `false`。

### 複雜度

令 `V` 為課程數，`E` 為先修關係數：

- 時間複雜度：`O(V + E)`，每個節點與每條邊最多處理一次。
- 空間複雜度：`O(V + E)`，包含鄰接表、狀態陣列與最深 `O(V)` 的遞迴堆疊。

## 解法二：Kahn 入度 BFS

### 設計說明

`CanFinish2` 使用 Kahn 拓樸排序。除了鄰接表，也用 `indegrees` 記錄每門課還有多少先修條件尚未完成：

1. 對每筆 `[a, b]` 建立邊 `b -> a`，並把 `a` 的入度加一。
2. 將所有入度為零的課程加入佇列；這些課程目前沒有尚未完成的先修條件。
3. 從佇列取出一門課，視為完成，並將其後續課程的入度減一。
4. 某門後續課程的入度降到零時，將它加入佇列。
5. 最後比較完成的課程數與 `numCourses`。

如果圖中存在環，環內每個節點至少有一條來自環內的入邊，因此它們的入度永遠無法降為零。

### 為什麼正確

- 只有入度為零的課程才會進入佇列，所以每次完成課程時，它的所有先修條件都已處理。
- 移除一門課的出邊，相當於解除它對後續課程的限制；後續課程入度歸零時即可安全處理。
- 若最後處理了全部 `V` 個節點，取得了一個合法拓樸順序，因此圖無環。
- 若處理數小於 `V`，剩餘節點無法產生新的入度零節點，代表它們包含至少一個有向環。

### 範例演示：菱形依賴

輸入：

```text
numCourses = 4
prerequisites = [[1,0], [2,0], [3,1], [3,2]]
```

建立的邊是 `0 -> 1`、`0 -> 2`、`1 -> 3`、`2 -> 3`，初始入度為：

```text
課程：  0 1 2 3
入度：  0 1 1 2
```

1. 課程 `0` 入度為零，先加入佇列。
2. 完成 `0` 後，課程 `1`、`2` 的入度都降為零，兩者加入佇列。
3. 完成 `1` 後，課程 `3` 的入度由 `2` 降為 `1`，尚不可處理。
4. 完成 `2` 後，課程 `3` 的入度由 `1` 降為 `0`，加入佇列。
5. 完成 `3`，總共處理四門課，等於 `numCourses`，回傳 `true`。

### 複雜度

令 `V` 為課程數，`E` 為先修關係數：

- 時間複雜度：`O(V + E)`，建圖與移除每條邊各需要線性時間。
- 空間複雜度：`O(V + E)`，包含鄰接表、入度陣列與最多容納 `V` 個節點的佇列。

## 兩種解法比較

| 比較項目 | DFS 三色標記 | Kahn 入度 BFS |
|---|---|---|
| 核心觀察 | 搜尋路徑中出現回邊即有環 | 無法移除全部節點即有環 |
| 主要資料結構 | 鄰接表、狀態陣列、遞迴堆疊 | 鄰接表、入度陣列、佇列 |
| 時間複雜度 | `O(V + E)` | `O(V + E)` |
| 空間複雜度 | `O(V + E)` | `O(V + E)` |
| 優點 | 寫法直接，容易結合其他 DFS 圖論處理 | 無遞迴深度問題，也能自然產生拓樸順序 |
| 注意事項 | 深鏈圖會增加遞迴堆疊深度 | 必須正確維護每個節點的入度 |

兩種 API 都只讀取 `prerequisites`，不會改寫呼叫端的輸入內容。
