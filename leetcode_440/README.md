不需要真的列出或排序 `1` 到 `n` 的所有整數，也能找到字典序第 `k` 小的數字。

## 題目說明

給定兩個整數 `n` 和 `k`，將 `[1, n]` 內的所有整數依照字典序排列，回傳其中第 `k` 小的整數。

字典序比較的是十進位字串的先後順序，而不是數值大小。例如 `n = 13` 時，排列結果為：

```text
1, 10, 11, 12, 13, 2, 3, 4, 5, 6, 7, 8, 9
```

因此第 2 個數字是 `10`。

- 英文題目：[K-th Smallest in Lexicographical Order](https://leetcode.com/problems/k-th-smallest-in-lexicographical-order/description/?tab=Description)
- 中文題目：[字典序的第 K 小數字](https://leetcode.cn/problems/k-th-smallest-in-lexicographical-order/description/)

### 限制條件

```text
1 <= k <= n <= 10^9
```

`n` 最大可達十億，因此不能建立包含所有數字的字串集合再進行排序。

## 解題概念與出發點

### 直接排序為什麼不合適

最直觀的方式是將 `1` 到 `n` 全部轉成字串、排序，再取索引 `k - 1`。這個做法需要：

- 建立 `n` 個元素，至少使用 `O(n)` 空間。
- 對全部元素排序，排序成本至少為 `O(n log n)`，字串比較還會逐位檢查。
- 當 `n = 10^9` 時，時間與記憶體都不可接受。

真正需要的只有第 `k` 個位置，不需要產生前面所有數字。十進位字串共享前綴的特性，
可以把整個搜尋空間看成一棵不必實際建立的十叉字典樹，並一次跳過不含答案的整棵子樹。

### 隱式十叉字典樹

每個正整數同時是樹中的一個節點與一個十進位前綴：

```text
根
├─ 1
│  ├─ 10
│  │  ├─ 100
│  │  └─ ...
│  ├─ 11
│  └─ ...
├─ 2
│  ├─ 20
│  └─ ...
└─ ...
```

按照前序走訪這棵樹，得到的順序恰好就是字典序。對目前前綴 `curr`，演算法只需回答：

1. 以 `curr` 開頭且不超過 `n` 的數字共有多少個？
2. 這個數量是否足以包含目前要找的排名？

若子樹節點數小於或等於剩餘排名，可以一次跳過整棵子樹；否則答案就在子樹中，
應深入 `curr * 10`。

## 解法一：隱式字典樹與前綴計數

專案目前只有這一種正式解法，由 `FindKthNumber` 負責走訪、`GetSteps` 負責計算前綴子樹大小。

### 1. 將排名轉成剩餘步數

字典序第一個節點必定是 `1`，因此：

```csharp
int curr = 1;
k--;
```

此後的 `k` 代表「從 `curr` 還需要前進多少個位置」。當 `k == 0` 時，`curr` 就是答案。

### 2. 計算前綴子樹大小

對前綴 `curr`，使用半開區間 `[first, last)` 表示同一層所有以該前綴開頭的數字：

```text
第一層：[curr, curr + 1)
下一層：[curr * 10, (curr + 1) * 10)
再下一層：[curr * 100, (curr + 1) * 100)
```

每層可能部分超過 `n`，所以實際可用數量為：

```text
min(n + 1, last) - first
```

使用 `n + 1` 是因為區間右界不包含在內。例如 `n = 23`、前綴為 `2`：

| 層級 | 原始區間 | 截斷後有效值 | 數量 |
|---|---|---|---:|
| `2` | `[2, 3)` | `2` | 1 |
| `20...` | `[20, 30)` | `20, 21, 22, 23` | 4 |
| `200...` | 起點已大於 `23` | 無 | 0 |

所以以 `2` 為前綴的子樹共有 `1 + 4 = 5` 個節點。`first` 與 `last` 使用 `long`，
避免逐層乘以 10 時溢位。

### 3. 決定跳過或深入

設 `steps = GetSteps(curr, n)`：

- `steps <= k`：答案不在目前子樹。令 `curr++` 移到相鄰前綴，並以 `k -= steps`
  一次扣除整棵子樹。
- `steps > k`：答案仍在目前子樹。令 `curr *= 10` 深入最左側子節點，並以 `k--`
  扣除目前節點。

重複判斷直到 `k == 0`，即可回傳 `curr`。

### 核心實作

```csharp
public int FindKthNumber(int n, int k)
{
    int curr = 1;
    k--;

    while (k > 0)
    {
        int steps = GetSteps(curr, n);
        if (steps <= k)
        {
            curr++;
            k -= steps;
        }
        else
        {
            curr *= 10;
            k--;
        }
    }

    return curr;
}

public int GetSteps(int curr, int n)
{
    int steps = 0;
    long first = curr;
    long last = curr + 1;
    while (first <= n)
    {
        steps += (int)Math.Min(n + 1, last) - (int)first;
        first *= 10;
        last *= 10;
    }

    return steps;
}
```

### 複雜度分析

- 時間複雜度：`O(log² n)`。走訪路徑的層數與十進位位數成正比，而每次
  `GetSteps` 也會逐層計數；每層最多檢查固定數量的兄弟前綴。
- 額外空間複雜度：`O(1)`。只保存目前前綴、排名與區間邊界，沒有建立字典樹或排序清單。

## 範例演示流程

### 範例一：`n = 13, k = 2`

初始位置為 `curr = 1`，因為已經站在第一個節點，所以剩餘步數為 `k = 1`。

以 `1` 為前綴的有效節點為 `1, 10, 11, 12, 13`，因此 `steps = 5`。
因為 `steps > k`，答案仍在這棵子樹內：

```text
curr = 1  →  curr = 10
k = 1     →  k = 0
```

此時停止，答案為 `10`。

### 範例二：`n = 1000, k = 100`

先將排名轉為剩餘步數 `99`。下表中的 `k` 都表示目前尚需前進的距離：

| `curr` | `k` | `steps` | 決策 | 新 `curr` | 新 `k` |
|---:|---:|---:|---|---:|---:|
| 1 | 99 | 112 | 深入 | 10 | 98 |
| 10 | 98 | 12 | 跳過 | 11 | 86 |
| 11 | 86 | 11 | 跳過 | 12 | 75 |
| 12 | 75 | 11 | 跳過 | 13 | 64 |
| 13 | 64 | 11 | 跳過 | 14 | 53 |
| 14 | 53 | 11 | 跳過 | 15 | 42 |
| 15 | 42 | 11 | 跳過 | 16 | 31 |
| 16 | 31 | 11 | 跳過 | 17 | 20 |
| 17 | 20 | 11 | 跳過 | 18 | 9 |
| 18 | 9 | 11 | 深入 | 180 | 8 |
| 180～187 | 8～1 | 每棵皆為 1 | 逐棵跳過 | 188 | 0 |

`k` 歸零時停在 `188`，因此 `(n = 1000, k = 100)` 的正確答案是 `188`。
