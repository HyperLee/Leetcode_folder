## 題目說明

給定一個整數陣列 `nums` 與正整數 `k`，找出有多少個連續子陣列，使得 `nums` 的全域最大元素在該子陣列中至少出現 `k` 次。

這裡的「最大元素」是整個 `nums` 的最大值，而不是為每一個子陣列重新選擇最大值。答案可能超過 32 位元整數範圍，因此方法回傳 `long`。

題目連結：[Count Subarrays Where Max Element Appears at Least K Times](https://leetcode.com/problems/count-subarrays-where-max-element-appears-at-least-k-times/description/)

### 官方範例一

```text
Input: nums = [1, 3, 2, 3, 3], k = 2
Output: 6
```

全域最大值是 `3`。符合條件的子陣列為：

- `[1, 3, 2, 3]`
- `[1, 3, 2, 3, 3]`
- `[3, 2, 3]`
- `[3, 2, 3, 3]`
- `[2, 3, 3]`
- `[3, 3]`

### 官方範例二

```text
Input: nums = [1, 4, 2, 1], k = 3
Output: 0
```

全域最大值 `4` 只出現一次，所以沒有任何子陣列能讓它至少出現三次。

## 限制條件

- `1 <= nums.Length <= 100,000`
- `1 <= nums[i] <= 1,000,000`
- `1 <= k <= 100,000`

方法依照題目限制接收合法輸入，不另外處理空陣列、非正整數或非正的 `k`。

## 解題概念與出發點

### 從暴力列舉開始思考

最直接的方法是列舉每一個子陣列，再計算全域最大值在其中出現幾次。長度為 `n` 的陣列共有 `n(n + 1) / 2` 個子陣列；若每次又重新掃描子陣列，最差會到 `O(n³)`。即使在延伸右邊界時累積出現次數，仍需要 `O(n²)`，無法應付 `n = 100,000`。

真正需要追蹤的資訊只有一項：目前視窗內，全域最大值出現幾次。其他元素的值與次數都不會直接影響條件，因此適合使用滑動視窗。

### 核心視窗不變量

令滑動視窗為 `[start, end]`，`maxCount` 表示視窗內全域最大值的數量：

1. 右邊界 `end` 每次向右移動一格；若新元素是全域最大值，就增加 `maxCount`。
2. 當 `maxCount == k`，持續右移 `start`，直到移除一個最大值，使目前視窗重新只含 `k - 1` 個最大值。
3. 收縮完成後，所有起點 `0` 到 `start - 1` 都會讓以 `end` 結尾的子陣列含有至少 `k` 個最大值，所以本輪恰好新增 `start` 個答案。
4. 對每個右邊界累加 `start`，便得到所有有效子陣列的總數。

程式使用 `while (maxCount == k)` 而不是 `>= k`。原因是每輪開始前，保留的視窗最多只有 `k - 1` 個最大值；加入一個新元素後，計數最多只會增加到 `k`。兩種寫法在此不變量下都正確，但 `== k` 更直接表達「剛達到門檻就收縮」。

### 為何需要 `long`

若每個元素都是最大值且 `k = 1`，所有子陣列都符合條件。當 `n = 100,000` 時，答案可達：

```text
100,000 × 100,001 ÷ 2 = 5,000,050,000
```

此數值超過 `int` 上限，因此累計結果必須使用 `long`。

## 解法一：手動尋找最大值與 `while` 視窗

方法：`CountSubarrays(int[] nums, int k)`

### 設計步驟

1. 用 `foreach` 掃描 `nums`，手動維護 `maxNum`，取得全域最大值。
2. 以 `while` 迴圈控制右邊界 `end`。
3. 遇到 `maxNum` 時增加 `maxCount`。
4. 當最大值數量到達 `k`，移動 `start`，直到移除最左側的一個最大值。
5. 將 `start` 加入答案，代表本輪所有有效起點的數量。

這個版本完整展開「尋找最大值」與「推進右邊界」的細節，適合逐步觀察滑動視窗如何運作。

### 範例演示流程

輸入為 `nums = [1, 3, 2, 3, 3]`、`k = 2`、`maxNum = 3`。

| `end` | 新元素 | 加入後 `maxCount` | 收縮後 `start` | 本輪新增 | 累計答案 |
|---:|---:|---:|---:|---:|---:|
| 0 | 1 | 0 | 0 | 0 | 0 |
| 1 | 3 | 1 | 0 | 0 | 0 |
| 2 | 2 | 1 | 0 | 0 | 0 |
| 3 | 3 | 2 | 2 | 2 | 2 |
| 4 | 3 | 2 | 4 | 4 | 6 |

當 `end = 3` 時，視窗首次取得兩個 `3`。左邊界依序越過索引 `0` 與 `1`，收縮後 `start = 2`，因此起點 `0`、`1` 都有效，本輪新增 2。當 `end = 4` 時，同理可得到 4 個有效起點，最終答案為 6。

### 正確性說明

收縮完成後，視窗 `[start, end]` 只剩 `k - 1` 個最大值，因此任何不小於 `start` 的起點都不符合條件。相反地，每個小於 `start` 的起點都包含剛才被移除的第 `k` 個最大值，所以一定符合條件。故以 `end` 為右端點的有效子陣列恰有 `start` 個；對所有 `end` 加總即可完整且不重複地計數。

### 複雜度

- 時間複雜度：`O(n)`。尋找最大值需要 `O(n)`；左右邊界各自最多走訪陣列一次。
- 額外空間複雜度：`O(1)`。
- 輸入陣列：不會被修改。

## 解法二：LINQ `Max` 與 `for` 視窗

方法：`CountSubarrays2(int[] nums, int k)`

### 設計步驟

1. 使用 `nums.Max()` 取得全域最大值。
2. 用 `for` 迴圈宣告並推進右邊界 `end`。
3. 維護與解法一相同的 `maxCount`、收縮規則及 `start` 累計方式。
4. 回傳所有右邊界貢獻的總和。

此版本將最大值搜尋交給 LINQ，並把右邊界的生命週期限制在 `for` 迴圈內，程式結構較精簡。它與解法一採用相同演算法，不是不同複雜度的替代方案。

### 範例演示流程

同樣使用 `nums = [1, 3, 2, 3, 3]` 與 `k = 2`。`nums.Max()` 先得到 `3`，接著 `for` 迴圈產生以下狀態：

| `end` | `nums[end]` | 加入後最大值次數 | 左邊界移動範圍 | 收縮後 `start` | 累計答案 |
|---:|---:|---:|:---|---:|---:|
| 0 | 1 | 0 | 不移動 | 0 | 0 |
| 1 | 3 | 1 | 不移動 | 0 | 0 |
| 2 | 2 | 1 | 不移動 | 0 | 0 |
| 3 | 3 | 2 | `0 → 2` | 2 | 2 |
| 4 | 3 | 2 | `2 → 4` | 4 | 6 |

雖然最大值的取得方式與迴圈語法不同，`start` 在每一輪的值與解法一完全一致，因此答案同樣是 6。

### 正確性說明

`nums.Max()` 與手動掃描會得到相同的全域最大值。其後維護的視窗不變量也與解法一相同：收縮後，小於 `start` 的起點全部有效，而其餘起點全部無效。因此每輪加入 `start` 並對所有右端點加總，可以得到正確答案。

### 複雜度

- 時間複雜度：`O(n)`。LINQ `Max()` 走訪一次，滑動視窗再線性走訪一次。
- 額外空間複雜度：`O(1)`。
- 輸入陣列：不會被修改。

## 兩種解法比較

| 比較項目 | `CountSubarrays` | `CountSubarrays2` |
|:---|:---|:---|
| 最大值取得方式 | `foreach` 搭配 `Math.Max` | LINQ `Max()` |
| 右邊界控制 | 明確的 `while` 迴圈 | 精簡的 `for` 迴圈 |
| 核心演算法 | 滑動視窗 | 滑動視窗 |
| 時間複雜度 | `O(n)` | `O(n)` |
| 額外空間 | `O(1)` | `O(1)` |
| 是否修改輸入 | 否 | 否 |

兩個公開方法都保留，方便比較相同演算法在不同 C# 寫法下的可讀性。實務上可依團隊風格選擇其中之一，不需要同時呼叫兩者；本專案的 `Main` 同時執行它們，是為了教學與交叉驗證。
