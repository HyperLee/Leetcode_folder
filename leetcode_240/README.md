## 題目說明

給定一個 `m × n` 的整數矩陣 `matrix`：

- 每一列由左至右排序。
- 每一欄由上至下排序。

請判斷整數 `target` 是否存在於矩陣中。找到時回傳 `true`，否則回傳 `false`。

官方範例：

```text
matrix = [
  [ 1,  4,  7, 11, 15],
  [ 2,  5,  8, 12, 19],
  [ 3,  6,  9, 16, 22],
  [10, 13, 14, 17, 24],
  [18, 21, 23, 26, 30]
]
```

- `target = 5`：回傳 `true`
- `target = 20`：回傳 `false`

題目連結：[LeetCode](https://leetcode.com/problems/search-a-2d-matrix-ii/description/) ｜ [力扣中文站](https://leetcode.cn/problems/search-a-2d-matrix-ii/description/)

### 限制條件

- `m == matrix.length`
- `n == matrix[i].length`
- `1 <= m, n <= 300`
- `-10^9 <= matrix[i][j] <= 10^9`
- 每一列的整數由左至右排序。
- 每一欄的整數由上至下排序。
- `-10^9 <= target <= 10^9`

題目保證矩陣至少有一列與一欄，因此三種公開搜尋方法皆以非空、符合排序條件的矩陣為輸入前提。

## 解題概念與出發點

最直接的想法是檢查每一格，這不需要使用任何排序資訊，但最壞情況必須走訪 `m × n` 個元素。

注意到每一列本身已有序後，可以逐列套用二分搜尋，把單列的搜尋成本從 `O(n)` 降為 `O(log n)`。不過這種作法只利用橫向排序，仍沒有使用欄的上下排序關係。

若從右上角觀察，當前元素具有一個特別有用的性質：

- 左側元素不大於目前值。
- 下方元素不小於目前值。

因此，當目前值大於 `target` 時，可以排除整個目前欄並向左移；當目前值小於 `target` 時，可以排除整個目前列並向下移。每一步都永久排除一列或一欄，形成 `O(m + n)` 的階梯式搜尋。

## 三種解法比較

| 解法 | 使用的排序資訊 | 時間複雜度 | 額外空間 | 特點 |
| --- | --- | --- | --- | --- |
| 暴力法 | 不使用 | `O(m × n)` | `O(1)` | 最直觀，可作為正確性基準 |
| 逐列二分搜尋 | 每列由左至右排序 | `O(m × log n)` | `O(1)` | 比逐格掃描快，但未利用欄排序 |
| 右上角排除法 | 同時使用列與欄排序 | `O(m + n)` | `O(1)` | 每一步排除一列或一欄，本題首選 |

三種方法都不修改輸入矩陣。

## 解法一：暴力法

對應方法：`SearchMatrix`

### 設計說明

1. 由第一列開始逐列巡覽。
2. 對目前列的每一個元素逐一比較。
3. 一旦元素等於 `target`，立即回傳 `true`。
4. 所有元素都檢查完仍未命中，回傳 `false`。

這個方法不依賴排序條件，所以邏輯最簡單，也適合用來對照其他最佳化方法的結果。代價是無法提早排除大範圍資料；當目標不存在或位於最後一格時，必須檢查全部 `m × n` 個元素。

### 正確性說明

演算法逐一檢查矩陣中的每個元素。若 `target` 存在，巡覽到該位置時必定回傳 `true`；若完整巡覽後仍未命中，代表矩陣中沒有任何元素等於 `target`，因此回傳 `false`。

### 範例演示：`target = 5`

1. 第一列依序比較 `1、4、7、11、15`，都不等於 `5`。
2. 進入第二列，先比較 `2`，仍未命中。
3. 接著比較 `5`，找到目標並回傳 `true`。

本例共進行 7 次元素比較。

## 解法二：逐列二分搜尋

對應方法：`SearchMatrix_binary`，內部使用一維二分搜尋 helper `Search`

### 設計說明

1. 逐列處理矩陣。
2. 每一列皆由左至右排序，因此可用 `low`、`high` 表示目前可能包含目標值的區間。
3. 計算中點 `mid`：
   - `nums[mid] == target`：回傳該索引。
   - `nums[mid] < target`：中點與左半部都不可能命中，令 `low = mid + 1`。
   - `nums[mid] > target`：中點與右半部都不可能命中，令 `high = mid - 1`。
4. 任一列找到目標即回傳 `true`；所有列都找不到則回傳 `false`。

每列最多比較 `O(log n)` 次，總共有 `m` 列，因此時間複雜度為 `O(m × log n)`。二分搜尋使用迴圈而不是遞迴，額外空間維持 `O(1)`。

### 正確性說明

對每一列而言，`Search` 始終保留所有仍可能等於 `target` 的元素。中點較小時排除左半部，中點較大時排除右半部，因為被排除區間依排序性不可能包含目標。若某列包含 `target`，二分搜尋必定命中；逐列完成後仍未命中，表示所有列都不包含目標。

### 範例演示：`target = 5`

第一列 `[1, 4, 7, 11, 15]`：

1. `low = 0`、`high = 4`，`mid = 2`，值為 `7`；`7 > 5`，縮到左半部。
2. `low = 0`、`high = 1`，`mid = 0`，值為 `1`；`1 < 5`，縮到右半部。
3. `low = 1`、`high = 1`，值為 `4`；`4 < 5`，區間清空，此列未找到。

第二列 `[2, 5, 8, 12, 19]`：

1. 中點值為 `8`，向左縮小。
2. 中點值為 `2`，向右縮小。
3. 中點值為 `5`，找到目標並回傳 `true`。

## 解法三：右上角排除法

對應方法：`SearchMatrix_RightTop`

### 設計說明

1. 從右上角 `(row = 0, column = n - 1)` 開始。
2. 比較目前值與 `target`：
   - 目前值等於 `target`：立即回傳 `true`。
   - 目前值大於 `target`：目前欄下方只會更大，因此整欄不可能命中，向左移動。
   - 目前值小於 `target`：目前列左側只會更小，因此整列不可能命中，向下移動。
3. 若走出左邊界或下邊界，代表搜尋空間已全部排除，回傳 `false`。

搜尋路徑最多向左移動 `n` 次、向下移動 `m` 次，因此時間複雜度為 `O(m + n)`，額外空間為 `O(1)`。這也是三種方法中唯一同時利用列與欄排序資訊的解法。

### 正確性說明

每次移動前，目前位置都是尚未排除區域的右上角。當目前值較大時，下方同欄元素更不可能等於較小的 `target`，所以左移安全；當目前值較小時，左方同列元素更不可能等於較大的 `target`，所以下移安全。每次只排除不可能含有答案的區域，因此若目標存在必定會走到它；若越界，則所有候選位置都已被安全排除。

### 範例演示：`target = 5`

| 位置 | 目前值 | 判斷 | 下一步 |
| --- | ---: | --- | --- |
| `(0, 4)` | 15 | `15 > 5` | 左移 |
| `(0, 3)` | 11 | `11 > 5` | 左移 |
| `(0, 2)` | 7 | `7 > 5` | 左移 |
| `(0, 1)` | 4 | `4 < 5` | 下移 |
| `(1, 1)` | 5 | 命中 | 回傳 `true` |

本例只需 5 次比較。
