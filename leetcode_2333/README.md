## 題目與限制

題目：[Minimum Sum of Squared Difference](https://leetcode.com/problems/minimum-sum-of-squared-difference/description/)／[最小差值平方和](https://leetcode.cn/problems/minimum-sum-of-squared-difference/description/)。

給定兩個等長陣列 `nums1`、`nums2`，目標是讓以下平方和盡可能小：

```text
Σ (nums1[i] − nums2[i])²，0 ≤ i < n
```

可以對 `nums1` 的任意元素做 `+1` 或 `−1`，最多 `k1` 次；對 `nums2` 也可以做同樣修改，最多 `k2` 次。元素修改後允許變成負數。回傳最小平方和，而非操作步驟或修改後的陣列。

### 限制條件

| 參數 | 限制 |
|---|---|
| 長度 | `n == nums1.Length == nums2.Length` |
| `n` | `1 ≤ n ≤ 100000` |
| 陣列元素 | `0 ≤ nums1[i], nums2[i] ≤ 100000` |
| 操作預算 | `0 ≤ k1, k2 ≤ 1000000000` |

原始題目文字以「正整數」描述輸入，但實際限制包含 `0`；本專案依限制設計測試，保留 `Main` 的原始雙語題目 XML。

### 官方範例一：沒有操作預算

```text
nums1 = [1,2,3,4]
nums2 = [2,10,20,19]
k1 = 0, k2 = 0
差值 = [1,8,17,15]
答案 = 1² + 8² + 17² + 15² = 579
```

### 官方範例二：優先降低最大差值

```text
nums1 = [1,4,10,12]
nums2 = [5,8,6,9]
k1 = 1, k2 = 1
差值 = [4,4,4,3]
答案 = 43
```

例如讓 `nums1[0]` 增加 1、`nums2[2]` 增加 1，差值會變成 `[3,4,3,3]`，平方和為 `9 + 16 + 9 + 9 = 43`。最優操作不一定唯一。

## 共同解題出發點

### 1. 用絕對差值取代兩個陣列

令 `d[i] = |nums1[i] − nums2[i]|`。因為平方只取決於距離，差值正負不影響答案。

只要差值仍大於 0，修改任一陣列的對應元素，都能讓這個差值減少 1：較小者增加 1，或較大者減少 1。這兩種選擇分別消耗不同陣列的預算，因此可把預算合併成 `K = k1 + k2`。若需要 `t ≤ K` 次減少操作，將其中 `min(t, k1)` 次分配給第一個陣列，其餘分配給第二個，就不會超過任一預算。

於是原題轉成：最多進行 `K` 次「把某個正差值減少 1」，使 `Σ d[i]²` 最小。兩種方法只計算最小值，不實際重建上述修改過程。

### 2. 為什麼每次選最大差值？

把正差值 `d` 降為 `d − 1`，平方和減少：

```text
d² − (d − 1)² = 2d − 1
```

差值越大，一次操作的收益越高。如果 `a > b > 0`，降低 `a` 的收益就大於降低 `b`。任何優先降低較小值、卻讓更大值留在原高度的方案，都能交換操作而得到不更差的結果。

但 `K` 最多可達 20 億，不能逐次模擬。兩種解法都將最大值的下降批次處理：一種按排序層級移動，另一種直接搜尋目標門檻。

### 3. 預算足夠時可以停止

若 `Σ d[i] ≤ K`，所有差值都能變成 0，答案就是 0。題目要求「最多」操作，剩餘預算不用花完；不應讓差值越過 0 後再增加。

### 4. 整數型別與輸入副作用

- 單一平方可達 `100000² = 10000000000`；總平方和可達 `100000 × 100000² = 1000000000000000`。兩者都超過 `int`，必須使用 `long`。
- 貪心法用 `(long)nums1[i] * nums1[i]`，在乘法前轉型；先用 `int` 相乘、之後才轉型會太晚。
- 差值總和最多為 `10000000000`，成本累計同樣使用 `long`。
- 二分法的 `k1 + k2` 最多為 `2000000000`，仍可使用 `int`；這建立在題目範圍之內。
- 兩種方法都將 `nums1` 改寫為差值，並在需要時排序；`nums2` 不變。排序貪心若提早回傳 0，差值已寫入但尚未排序。
- 呼叫後的 `nums1` 並不是最優修改後的原始陣列，也不一定是最終下降後的差值。演算法只在區域變數中計算下降結果。
- `Main` 每次呼叫都複製兩個輸入陣列，讓兩種解法使用完全相同的原始測試資料。

兩個公開方法都假設輸入合法，不另做 `null`、長度或範圍檢查。

## 方法一：排序貪心

對應方法：`MinSumSquareDiff(int[] nums1, int[] nums2, int k1, int k2)`，回傳 `long`。

### 設計概念

將差值由小到大排序，從右端最大值開始處理。當最大值下降到次大值，兩者之後就應一起下降；再到第三大值時，群組繼續擴張。這好比把高低不同的柱子，從最高的一層開始一起削低。

程式不真的改寫每根柱子的高度。排序陣列保留原始差值，群組當前高度及操作成本用變數計算，最後一次把群組平方和加回。

### 變數與程式對照

| 變數 | 意義 |
|---|---|
| `n` | 差值數量 |
| `k` | 尚未使用的合併預算，型別為 `long` |
| `sum` | 原始差值總和，用來判斷是否可以全部消除 |
| `ans` | 初始為全部原始平方和；每次扣除一個新納入群組的原始平方 |
| `i` | 本輪新納入群組的排序位置，從右向左移動 |
| `m = n − i` | 本輪最大值群組包含的元素數量 |
| `v = nums1[i]` | 群組本輪開始時共同的概念高度 |
| `c` | 整組下降至下一層的成本：`m × (v − next)` |
| `remainder` | 整組平均下降後，還能額外下降 1 的元素數量 |

### 執行順序與不變量

1. 將 `nums1` 改寫成絕對差值，累計 `sum` 與初始 `ans`。
2. 若 `sum ≤ k`，直接回傳 0；否則排序。
3. 本輪納入位置 `i`，令 `m = n − i`。右側先前納入的元素已在概念上降到 `nums1[i]`，所以它們和本輪元素可視為共同高度 `v`。
4. 計算降至下一個較小值的成本 `c`，並從 `ans` 扣掉本輪元素原始的 `v²`。此時 `ans` 恰為索引 `0..i−1` 的原始平方和。
5. 若 `c < k`，花掉 `c`，往左納入下一個元素；若遇到相同高度，成本為 0，可直接擴張群組。
6. 若 `c ≥ k`，在本輪結算：整組每個值下降 `k / m`，餘數 `k % m` 個值再下降 1。

最後的公式是：

```text
v = 原高度 − k / m
remainder = k % m
答案 = ans + remainder × (v − 1)² + (m − remainder) × v²
```

`ans` 在迴圈中不是即時的總平方和。它是「尚未納入群組的原始平方和」；右側群組的最終平方和只在回傳時加入，避免每降一層都重算。

`c == k` 不需要進入下一輪，公式會把整組恰好降到下一層。由於已先排除 `sum ≤ k`，最後不會出現真正需要負差值的情況。

### 演示一：官方範例二與餘數分配

原差值 `[4,4,4,3]`，排序後 `[3,4,4,4]`，`k = 2`，初始 `ans = 57`。

| 輪次 | `i` | `m` | `v` | 下一層 | `c` | 扣除本輪平方後的 `ans` | 判斷 |
|---|---:|---:|---:|---:|---:|---:|---|
| 1 | 3 | 1 | 4 | 4 | 0 | 41 | `0 < 2`，擴張群組 |
| 2 | 2 | 2 | 4 | 4 | 0 | 25 | `0 < 2`，擴張群組 |
| 3 | 1 | 3 | 4 | 3 | 3 | 9 | `3 ≥ 2`，本輪結算 |

三個最大值無法全部從 4 降到 3。`k / m = 0`、`remainder = 2`，所以兩個值為 3，一個值為 4；未納入的最小值仍為 3。

```text
答案 = 9 + 2 × 3² + 1 × 4² = 43
```

### 演示二：跨越層級

原差值 `[9,5,1]`，排序後 `[1,5,9]`，`k = 6`，初始 `ans = 107`。

| 輪次 | `i` | `m` | 群組高度 `v` | 下一層 | 成本 `c` | 扣除後 `ans` | 預算與處理 |
|---|---:|---:|---:|---:|---:|---:|---|
| 1 | 2 | 1 | 9 | 5 | 4 | 26 | 花 4 次，`k = 2`，概念差值為 `[1,5,5]` |
| 2 | 1 | 2 | 5 | 1 | 8 | 1 | 不足以整組降到 1，改為平均分配 |

兩個最大值各下降 `2 / 2 = 1`，餘數為 0，概念差值變成 `[1,4,4]`：

```text
答案 = 1 + 2 × 4² = 33
```

### 正確性與邊界

最大正差值的單次收益最大，因此在群組尚高於下一層時，操作應全部用於該群組。群組下降到下一層後，納入該層元素，仍保持「最大值優先」的不變量。

當預算不足以再跨層，將群組平均下降最優：若兩個值相差至少 2，把一次下降操作從較小值轉移至較大值，能進一步減少平方和。因此最終群組的高度差最多為 1，恰由商數與餘數公式表達。

- 零預算：可直接在目前層結算，回傳原平方和。
- 重複最大值：零成本擴張群組，不需要逐次消耗預算。
- 單一元素：下一層視為 0，公式退化為直接降低該元素。
- 恰好等於層級成本：`c == k` 直接結算，答案包含未納入部分。
- 足夠或過剩預算：進入排序前回傳 0。

### 複雜度

一般情況排序為 `O(n log n)`，建差值與群組掃描各為 `O(n)`，總時間為 `O(n log n)`。若預算足夠而提早回傳，時間為 `O(n)`。

演算法本身只用固定數量變數，額外空間為 `O(1)`；計入原地排序的遞迴堆疊，為 `O(log n)`。測試端的陣列複本另外占 `O(n)`，不屬於方法內部配置。

## 方法二：二分答案

對應方法：`MinSumSquareDiff2(int[] nums1, int[] nums2, int k1, int k2)`，回傳 `long`。

### 設計概念

選一個門檻 `t`，把所有高於 `t` 的差值降到 `t`，所需操作數為：

```text
cost(t) = Σ max(d[i] − t, 0)
```

門檻越高，成本越低，所以 `cost(t) ≤ K` 是單調條件。`t = D`（最大差值）成本為 0，必定可行。二分搜尋找出最小可行門檻，再用剩餘預算微調最高的一群差值。

### 變數與程式對照

| 變數 | 意義 |
|---|---|
| `maxDiff` | 原始最大差值 `D`，搜尋上界 |
| `l`, `r` | 尚待搜尋的閉區間 |
| `mid` | 本輪候選門檻 |
| `sum` | 本輪 `cost(mid)`，以 `long` 累加；不是原始差值總和 |
| `res` | 已找到的可行門檻，搜尋結束後為最小可行門檻 |
| `k` | 搜尋階段是原預算；扣除 `cost(res)` 後是剩餘預算 |
| `diff` | 本元素截斷至 `res`、必要時再減 1 的最終差值，型別為 `long` |
| `ans` | 最終差值平方和 |

### 執行順序與不變量

1. 改寫 `nums1` 為差值，找出 `maxDiff`。
2. 在閉區間 `[0, maxDiff]` 搜尋，逐輪計算 `cost(mid)`。
3. 若成本不超過原預算，記錄 `res = mid`，令 `r = mid − 1`，尋找更低門檻；否則令 `l = mid + 1`。
4. 搜尋後從 `k` 扣除把所有差值壓至 `res` 的成本。
5. 將差值排序，由大到小處理。每個值先取 `min(d[i], res)`；若仍有預算且值大於 0，再下降 1，最後累加平方。

搜尋期間 `k` 不變，確保每個候選門檻都使用同一份原始預算判斷。`res` 初始為 0；首次找到可行門檻後，它記錄目前最小的已確認可行門檻。最大差值必定可行，因此搜尋結束一定找到門檻。

### 為什麼剩餘預算只需每個值再減一次？

若 `res > 0`，因為它是最小可行門檻：

```text
cost(res) ≤ K < cost(res − 1)
cost(res − 1) − cost(res) = 原始差值至少為 res 的元素數量
```

所以剩餘預算 `R = K − cost(res)`，小於截斷後高度為 `res` 的元素數量。只要從這群最大值選 `R` 個，各降低 1，就能用完剩餘預算；不會需要先降低較小值，也不會需要對同一個值下降兩次。

程式保留排序，是為了由大到小取得這群最大值。排序後取 `min(d[i], res)` 仍是由大到小，因此最後的單次下降分配符合貪心原則。

若 `res == 0`，所有差值已消除；`diff > 0` 的判斷防止多餘操作把它們變為負數。

### 演示一：官方範例二

差值 `[4,4,4,3]`，`K = 2`，`D = 4`。

| 輪次 | 判斷前 `l` | 判斷前 `r` | `mid` | `cost(mid)` | 可行？ | 更新 |
|---|---:|---:|---:|---:|---|---|
| 1 | 0 | 4 | 2 | `2+2+2+1 = 7` | 否 | `l = 3` |
| 2 | 3 | 4 | 3 | `1+1+1+0 = 3` | 否 | `l = 4` |
| 3 | 4 | 4 | 4 | 0 | 是 | `res = 4`，`r = 3` |

搜尋結束，門檻為 4，截斷成本為 0，剩餘預算為 2。排序後由右向左取值：

| 原始差值 | 截斷後 | 處理前剩餘預算 | 再下降？ | 最終差值 | 累計 `ans` |
|---:|---:|---:|---|---:|---:|
| 4 | 4 | 2 | 是 | 3 | 9 |
| 4 | 4 | 1 | 是 | 3 | 18 |
| 4 | 4 | 0 | 否 | 4 | 34 |
| 3 | 3 | 0 | 否 | 3 | 43 |

兩種方法可能把下降分配給不同索引，但最小平方和相同。

### 演示二：搜尋跨層門檻

差值 `[9,5,1]`，`K = 6`，`D = 9`。

| 輪次 | 判斷前區間 | `mid` | 成本 | 判斷與更新 |
|---|---|---:|---:|---|
| 1 | `[0,9]` | 4 | `5+1+0 = 6` | 可行，`res = 4`，`r = 3` |
| 2 | `[0,3]` | 1 | `8+4+0 = 12` | 不可行，`l = 2` |
| 3 | `[2,3]` | 2 | `7+3+0 = 10` | 不可行，`l = 3` |
| 4 | `[3,3]` | 3 | `6+2+0 = 8` | 不可行，`l = 4` |

最小可行門檻為 4，成本恰為 6，沒有剩餘預算。截斷後為 `[4,4,1]`，答案 `16 + 16 + 1 = 33`。

### 正確性與邊界

二分搜尋利用成本單調性，找到預算可達成的最低共同上限。把高於上限的差值壓低，相當於批次執行最大值優先的操作；剩餘操作再用於截斷後的最大群組，各減少 1。因此它和逐次選最大差值具有相同收益選擇，得到最小平方和。

- 零預算且有非零差值：最小可行門檻是原始最大值，平方和不變。
- 所有差值為 0：搜尋 `[0,0]` 一輪就得到門檻 0。
- 預算足夠或過剩：門檻 0 可行；最終全部累加 0，不必使用剩餘預算。
- 大差值或長陣列：成本用 `long` 累計，最終 `diff * diff` 也在 `long` 下運算。

### 複雜度

建差值為 `O(n)`；二分搜尋有 `O(log(D + 1))` 層，每層掃描 `n` 個元素；之後還有 `O(n log n)` 排序及線性掃描。因此總時間為 `O(n log(D + 1) + n log n)`，即常見的 `O(n log D + n log n)` 表示法；`D + 1` 寫法也涵蓋 `D = 0` 的邊界。

本方法仍保留排序，不能將目前實作的時間只寫成 `O(n log D)`。額外變數空間為 `O(1)`；計入排序堆疊為 `O(log n)`。本方法沒有貪心法的排序前提早回傳分支。

## 兩種方法比較

| 比較項目 | 排序貪心 | 二分答案 |
|---|---|---|
| 主軸 | 從最大差值逐層合併群組 | 搜尋最低可行門檻 |
| 批次操作 | 層級成本 `m × (v − next)` | 門檻成本 `Σ max(d − t, 0)` |
| 最後分配 | 商數平均下降，餘數再減 1 | 先截斷，再讓最高群組各減 1 |
| 一般時間 | `O(n log n)` | `O(n log(D + 1) + n log n)` |
| 計入排序堆疊的額外空間 | `O(log n)` | `O(log n)` |
| 預算足夠 | 建差值後直接回傳 | 搜尋門檻 0，仍排序與累加 |
| 輸入副作用 | 改寫 `nums1`，需要時排序 | 改寫並排序 `nums1` |
| 回傳型別 | `long` | `long` |

兩種解法都避免依照操作預算大小逐次模擬。本專案保留兩種方法供教學對照，沒有額外增加第三種解法。
