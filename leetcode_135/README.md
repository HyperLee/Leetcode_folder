# LeetCode 135：分發糖果

以 .NET 10 Console 專案示範兩種貪心解法：直觀的雙向遍歷，以及只使用常數額外空間的單次遍歷。專案入口包含可直接執行的固定案例，會同時驗證兩種解法並輸出 Expected、Actual 與 PASS/FAIL。

## 題目說明

有 `n` 個小孩站成一排，整數陣列 `ratings` 表示每個小孩的評分。分發糖果時必須遵守：

1. 每個小孩至少獲得一顆糖果。
2. 若某位小孩的評分高於相鄰小孩，他獲得的糖果也必須更多。

目標是計算滿足所有規則所需的最少糖果總數。

- [LeetCode 135. Candy](https://leetcode.com/problems/candy/description/)
- [力扣 135. 分發糖果](https://leetcode.cn/problems/candy/description/)

## 限制條件

- `n == ratings.Length`
- `1 <= n <= 2 * 10^4`
- `0 <= ratings[i] <= 2 * 10^4`

題目保證陣列至少有一個元素，因此 `Candy2` 直接以第一位小孩的一顆糖果作為初始狀態。

## 解題概念與出發點

這題的難點不是「每人至少一顆」，而是每一個位置可能同時受到左、右兩位鄰居的約束。只從左到右觀察，只能確定目前小孩是否應比左鄰居多；若後方接著出現下降序列，先前的分配可能仍不足以滿足右側關係。

貪心策略的核心是把局部規則拆開處理：

- 方法一分別處理左鄰居與右鄰居約束，再保留兩個方向都需要的較大糖果數。
- 方法二把評分走勢視為上升、持平與下降序列，邊走邊累加每段所需糖果，不保存完整分配陣列。

兩種方法都只做線性次數的比較，因此時間複雜度都是 `O(n)`。

## 方法一：兩次遍歷

### 設計說明

`Candy` 使用一個與 `ratings` 等長的 `candies` 陣列：

1. 將每個位置初始化為一顆糖果，先滿足最低數量規則。
2. 從左到右掃描。若 `ratings[i] > ratings[i - 1]`，令 `candies[i] = candies[i - 1] + 1`。
3. 從右到左掃描。若 `ratings[i] > ratings[i + 1]`，令 `candies[i] = Math.Max(candies[i], candies[i + 1] + 1)`。
4. 將 `candies` 全部加總。

第二次掃描不能直接覆蓋原值。第一次掃描已經建立了左側約束；若只寫入 `candies[i + 1] + 1`，可能破壞原本正確的左側關係。`Math.Max` 會保留兩個方向中較大的最低需求。

### 範例演示：`ratings = [1, 0, 2]`

| 階段 | 糖果分配 | 說明 |
| --- | --- | --- |
| 初始化 | `[1, 1, 1]` | 每位小孩先取得一顆 |
| 左至右 | `[1, 1, 2]` | 評分 `2 > 0`，第三位比第二位多一顆 |
| 右至左 | `[2, 1, 2]` | 評分 `1 > 0`，第一位比第二位多一顆 |
| 加總 | `5` | 最少需要五顆糖果 |

### `Math.Max` 的山峰效果

以 `[1, 2, 3, 2, 1]` 為例：

- 左至右後為 `[1, 2, 3, 1, 1]`。
- 右至左會先把第四位補成 `2`。
- 到達評分 `3` 的山峰時，左側約束已要求三顆，右側約束也要求三顆；取最大值後仍為 `3`。
- 最終分配為 `[1, 2, 3, 2, 1]`，總數為 `9`。

### 複雜度

- 時間複雜度：`O(n)`，初始化、雙向掃描與加總皆為線性。
- 額外空間複雜度：`O(n)`，需要保存每位小孩的糖果數。

## 方法二：單次遍歷

### 設計說明

`Candy2` 不保存完整糖果陣列，而是維護四個狀態：

- `inc`：最近上升序列峰值所取得的糖果數。
- `dec`：目前下降序列需要的糖果層級。
- `pre`：前一位小孩取得的糖果數。
- `res`：目前累計的糖果總數。

走勢分成兩類：

1. **上升或持平**
   - 上升時令 `pre + 1`，延續遞增糖果數。
   - 持平時兩者沒有大小約束，令 `pre = 1`。
   - 下降序列結束，因此將 `dec` 歸零，並以目前 `pre` 更新 `inc`。
2. **下降**
   - 每下降一步就增加 `dec`。
   - 若 `dec == inc`，代表下降側即將與峰值取得相同糖果數，必須再增加一次 `dec`，等同替峰頂補一顆。
   - 當前下降位置在後續比較中視為只拿一顆，因此將 `pre` 重設為 `1`。

### 範例演示：`ratings = [5, 4, 3, 2, 1]`

初始第一位取得一顆：`inc = 1`、`dec = 0`、`pre = 1`、`res = 1`。

| `i` | 評分比較 | `inc` | `dec` | `pre` | `res` | 說明 |
| ---: | --- | ---: | ---: | ---: | ---: | --- |
| 1 | `4 < 5` | 1 | 2 | 1 | 3 | `dec` 原本增至 1，與 `inc` 相同，因此補成 2 |
| 2 | `3 < 4` | 1 | 3 | 1 | 6 | 延長下降序列 |
| 3 | `2 < 3` | 1 | 4 | 1 | 10 | 延長下降序列 |
| 4 | `1 < 2` | 1 | 5 | 1 | 15 | 延長下降序列 |

雖然程式沒有建立分配陣列，上述累加等價於糖果分配 `[5, 4, 3, 2, 1]`，總數為 `15`。第一次下降時的峰值補糖，確保最左側評分最高的小孩仍比右鄰居獲得更多糖果。

### 複雜度

- 時間複雜度：`O(n)`，只需單次掃描。
- 額外空間複雜度：`O(1)`，僅使用固定數量的整數狀態。

## 方法比較

| 項目 | 方法一：兩次遍歷 | 方法二：單次遍歷 |
| --- | --- | --- |
| 主要方法 | `Candy` | `Candy2` |
| 時間複雜度 | `O(n)` | `O(n)` |
| 額外空間 | `O(n)` | `O(1)` |
| 優點 | 分配過程直觀，容易逐步驗證 | 不需額外陣列，空間使用固定 |
| 注意事項 | 第二趟必須使用 `Math.Max` | 必須正確維護下降長度與峰值補糖 |
| 適合情境 | 教學、重視可讀性 | 熟悉狀態轉換、希望節省空間 |

## 可執行案例

| 案例 | `ratings` | 預期結果 | 驗證重點 |
| --- | --- | ---: | --- |
| 官方範例一 | `[1, 0, 2]` | 5 | 中間為低點，左右都需增加 |
| 官方範例二 | `[1, 2, 2]` | 4 | 相同評分不要求相同或更多糖果 |
| 連續上升後下降 | `[1, 3, 4, 5, 2]` | 11 | 長上升序列後接下降 |

| 單一小孩 | `[1]` | 1 | 最小合法陣列長度 |
| 谷底 | `[2, 1, 2]` | 5 | 中間小孩同時低於左右鄰居 |
