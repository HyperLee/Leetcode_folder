## 題目說明

給定一棵二元樹的根節點 `root`。想像觀察者站在樹的右側，請依照由上到下的
順序，回傳每一層能看見的節點值。

例如：

```text
輸入：root = [1,2,3,null,5,null,4]
輸出：[1,3,4]
```

對應的樹：

```text
        1
       / \
      2   3
       \   \
        5   4
```

從右側觀察時，第 0、1、2 層分別看見 `1`、`3`、`4`。

### 限制條件

- 二元樹的節點數量介於 `0` 到 `100`。
- `-100 <= Node.val <= 100`。
- 空樹必須回傳空集合 `[]`。
- 結果必須按照由上到下的層級順序排列。

## 解題概念與出發點

右視圖不一定只包含沿著 `right` 指標形成的路徑。若某一層的右子樹沒有節點，
左子樹中位於該層最右側的節點仍然可見。因此真正要找的是：

> 每一個深度中，位置最右側的節點。

這個觀察可以轉換成兩種走訪策略：

1. **DFS 改變走訪順序**：先走右子樹，再走左子樹。每個深度第一次遇到的節點
   必然是該層最右側的節點。
2. **BFS 明確分層**：由左至右處理每一層，該層最後取出的節點就是最右側節點。

兩種解法都會走訪所有節點，差別在於如何辨識「每層最右側」以及需要保存的
中間狀態。

## 解法一：右子樹優先 DFS

### 設計說明

`RightSideView(TreeNode? root)` 建立空結果後，從根節點、深度 `0` 呼叫
`Dfs(node, depth, result)`。

一般前序 DFS 常使用「目前節點、左子樹、右子樹」的順序。本解法刻意改為：

1. 處理目前節點。
2. 遞迴走訪右子樹。
3. 遞迴走訪左子樹。

`result.Count` 同時代表已經記錄了多少個深度。當 `depth == result.Count` 時，
代表這是 DFS 第一次抵達該深度；由於走訪順序固定先右後左，目前節點就是這一層
最右側可見的節點。

若右子樹在更深處中斷，DFS 隨後仍會走訪左子樹。左子樹第一個抵達尚未記錄深度
的節點便會補上結果，因此不會漏掉「由左側分支延伸、但從右側仍可見」的節點。

### 演算法步驟

1. 建立空的右視圖結果。
2. 從根節點與深度 `0` 開始 DFS。
3. 若目前節點為 `null`，結束該分支。
4. 若 `depth == result.Count`，將目前節點值加入結果。
5. 以 `depth + 1` 先走右子樹，再走左子樹。
6. 所有分支完成後回傳結果。

### 正確性說明

對任意深度 `d`，右子樹優先 DFS 會先走訪所有較靠右、且位於深度 `d` 的候選
節點，之後才走訪同深度較靠左的節點。因此第一次抵達深度 `d` 的節點必定是
該層最右側節點。

此時 `result.Count == d`，演算法會將該節點加入結果。之後再抵達相同深度時，
`result.Count` 已大於 `d`，不會覆寫或重複加入。DFS 會走訪每個非空節點，
所以每個存在的深度都恰好記錄一次，最終結果就是由上到下的完整右視圖。

### 官方範例演示

輸入：

```text
[1,2,3,null,5,null,4]
```

右子樹優先 DFS 的走訪順序為 `1 → 3 → 4 → 2 → 5`：

| 順序 | 節點 | 深度 | `result.Count` | 動作 | 累積結果 |
| ---: | ---: | ---: | ---: | --- | --- |
| 1 | `1` | 0 | 0 | 首次抵達深度 0，加入 `1` | `[1]` |
| 2 | `3` | 1 | 1 | 首次抵達深度 1，加入 `3` | `[1, 3]` |
| 3 | `4` | 2 | 2 | 首次抵達深度 2，加入 `4` | `[1, 3, 4]` |
| 4 | `2` | 1 | 3 | 深度 1 已有結果，不加入 | `[1, 3, 4]` |
| 5 | `5` | 2 | 3 | 深度 2 已有結果，不加入 | `[1, 3, 4]` |

遞迴結束後回傳 `[1, 3, 4]`。

### 複雜度

- 時間複雜度：`O(n)`，每個節點恰好走訪一次。
- 額外空間複雜度：`O(h)`，`h` 是樹高，來自遞迴呼叫堆疊。
- 輸出空間：`O(h)`，每一層最多保存一個節點值。

## 解法二：逐層 BFS

### 設計說明

`RightSideView2(TreeNode? root)` 使用 `Queue<TreeNode>` 保存已發現但尚未處理的
節點。BFS 天然會依深度由淺到深走訪；只要在每輪開始時保存 `queue.Count`，
就能知道目前層共有多少個節點。

同一層固定由左至右出列，並將非空的左、右子節點依序加入佇列。當索引
`i == levelSize - 1` 時，目前節點是該層最後出列的節點，也就是位置最右側的
節點，因此將它加入結果。

在處理目前層時入列的子節點不會被本輪提前處理，因為迴圈只執行事先固定的
`levelSize` 次。這使各層的邊界保持清楚。

### 演算法步驟

1. 建立空結果；若根節點為 `null`，直接回傳。
2. 將根節點加入佇列。
3. 當佇列不為空時：
   - 保存目前的 `queue.Count` 為 `levelSize`。
   - 由左至右取出本層的 `levelSize` 個節點。
   - 若目前是本層最後一個節點，將節點值加入結果。
   - 將非空的左、右子節點加入佇列。
4. 佇列清空後回傳結果。

### 正確性說明

第一輪開始時，佇列只包含根節點，因此能正確記錄第 0 層。假設某輪開始時，
佇列前方的 `levelSize` 個節點恰好是同一層，且排列順序為由左至右；逐一處理
它們時，最後取出的節點就是該層最右側節點。

父節點依由左至右順序出列，子節點也固定先左後右入列，所以新加入的節點會按照
下一層的由左至右順序排列。由於本輪只處理原本的 `levelSize` 個節點，所有
子節點會留到下一輪。依此逐層推進，每一層都會加入正確的最右側節點。

### 官方範例演示

輸入：

```text
[1,2,3,null,5,null,4]
```

下表中的佇列由左至右表示「下一個出列到最後出列」：

| 層級 | 輪次開始時的佇列 | 本層出列順序 | 最後出列 | 加入結果 | 下一層佇列 |
| ---: | --- | --- | ---: | --- | --- |
| 0 | `[1]` | `1` | `1` | `[1]` | `[2, 3]` |
| 1 | `[2, 3]` | `2, 3` | `3` | `[1, 3]` | `[5, 4]` |
| 2 | `[5, 4]` | `5, 4` | `4` | `[1, 3, 4]` | `[]` |

佇列清空後回傳 `[1, 3, 4]`。

### 複雜度

- 時間複雜度：`O(n)`，每個節點各入列、出列一次。
- 額外空間複雜度：`O(w)`，`w` 是樹的最大寬度，來自佇列。
- 輸出空間：`O(h)`，每一層最多保存一個節點值。

## 兩種解法比較

| 比較項目 | DFS：`RightSideView` | BFS：`RightSideView2` |
| --- | --- | --- |
| 核心方式 | 先右後左，記錄新深度的第一個節點 | 逐層由左至右，記錄最後一個節點 |
| 主要資料結構 | 遞迴呼叫堆疊 | 佇列 |
| 時間複雜度 | `O(n)` | `O(n)` |
| 額外空間 | `O(h)` | `O(w)` |
| 優點 | 程式精簡，直接利用走訪順序 | 分層邏輯直觀，沒有深層遞迴 |
| 注意事項 | 偏斜樹會形成較深的遞迴堆疊 | 寬樹可能同時在佇列保存大量節點 |

若樹很深但不寬，BFS 可避免深層遞迴；若樹很寬但高度有限，DFS 通常只需保存
較短的遞迴路徑。本題最多只有 100 個節點，兩種方式都能在限制內穩定完成。
