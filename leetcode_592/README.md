## 題目說明

給定一個表示分數加法與減法的字串 `expression`，回傳字串格式的計算結果。結果必須是不可再約分的
最簡分數；若結果為整數，仍要使用分母為 `1` 的分數格式，例如整數 `2` 應回傳 `"2/1"`。

- 英文題目：[Fraction Addition and Subtraction](https://leetcode.com/problems/fraction-addition-and-subtraction/)
- 中文題目：[分數加減運算](https://leetcode.cn/problems/fraction-addition-and-subtraction/)

### 官方範例

```text
輸入：expression = "-1/2+1/2"
輸出："0/1"

輸入：expression = "-1/2+1/2+1/3"
輸出："1/3"

輸入：expression = "1/3-1/2"
輸出："-1/6"
```

## 限制條件

- 輸入與輸出只包含數字、`/`、`+` 與 `-`。
- 每個分數皆為 `±分子/分母`；第一個正分數與正數結果不帶前導 `+`。
- 輸入只包含合法的最簡分數。
- 每個輸入分數的分子與分母皆在 `[1, 10]` 內，分母不會是零。
- 運算式包含的分數數量在 `[1, 10]` 內。
- 最終結果的分子與分母保證在 32 位元整數範圍內。

因此本專案依題目契約處理合法且非空的輸入，不額外實作格式錯誤或空字串驗證。

## 解題概念與出發點

### 為什麼不用浮點數

若把 `1/3` 或 `1/10` 直接轉成浮點數，二進位浮點表示可能產生捨入誤差，也無法直接得知最後應回傳的
最簡分子與分母。本題應從頭到尾保存整數分子與分母，才能得到精確結果。

### 從 `0/1` 開始累加

令目前累積結果為 `a/b`，新讀入的分數為 `c/d`。兩者相加可寫成：

```text
a/b + c/d = (a × d + c × b) / (b × d)
```

初始值使用 `0/1`，因為它不會改變第一個讀入的分數，而且分母始終是合法的正數。減法不需要另一套
公式，只要把負號合併到新分數的分子 `c` 即可。

### 最後才統一約分

逐段累加時可以不斷保留尚未化簡的分子與分母。全部分數處理完畢後，計算：

```text
g = gcd(abs(累積分子), 累積分母)
```

再讓分子與分母同除以 `g`。若分子為零，直接回傳題目要求的標準形式 `"0/1"`。

## 解法：字串模擬、累加通分與 GCD 約分

專案目前只有一套完整的分數加減解法，由 `FractionAddition` 實作。`GCD` 與 `GCD2` 是可互相比較的
最大公約數輔助方法，不是兩套不同的分數解析演算法。

### 步驟一：解析正負號

每一輪從目前索引開始。若字元是 `+` 或 `-`，先記錄該分數的符號並把索引往後移；若第一個分數為正，
運算式會直接從數字開始，因此預設符號為正。

```text
"-10/7+3/7"
 ^
 第一段符號為負
```

### 步驟二：解析多位數分子

只要目前字元是數字，就使用十進位累積公式：

```text
value = value × 10 + 目前數字
```

例如讀取 `"10"` 時，數值會依序從 `0` 變成 `1`、再變成 `10`。讀到 `/` 後，將先前記錄的符號乘到
分子上。

### 步驟三：解析分母

跳過 `/` 後，以相同的十進位累積方式讀取分母。題目保證輸入格式合法且分母為正，因此不需要另外搜尋
分隔符或處理除以零。

### 步驟四：累加目前分數

假設累積值為 `numerator/denominator`，新分數為
`fractionNumerator/fractionDenominator`，更新方式如下：

```text
numerator =
    numerator × fractionDenominator
    + fractionNumerator × denominator

denominator =
    denominator × fractionDenominator
```

程式使用 `long` 保存中間值。即使題目保證最終答案落在 32 位元整數範圍，累加過程中的分母乘積仍可能
暫時超過 `int`。

### 步驟五：正規化並約分

- 分子為零：直接回傳 `"0/1"`。
- 分子不為零：以 `GCD(abs(numerator), denominator)` 找出最大公約數。
- 分子與分母同除以最大公約數，再組成 `分子/分母` 字串。

由於輸入分母都是正數，累積分母也保持正數，結果的負號自然只會出現在分子前方。

### 複雜度分析

令 `m` 為運算式字串長度，`M` 為最終約分前分子與分母的較小絕對值：

- 時間複雜度：`O(m + log M)`。字串只會由左至右掃描一次，最後的歐幾里得演算法需要
  `O(log M)` 次取餘數。
- 額外空間複雜度：`O(1)`。主解法只保存索引、符號、分子與分母等固定數量的變數。

## GCD 輔助方法比較

### `GCD`：迭代版

正式解法使用迭代版歐幾里得演算法。核心性質是：

```text
gcd(a, b) = gcd(b, a mod b)
```

每輪都把較大的問題縮小，直到第二個數為零，此時第一個數就是最大公約數。

```text
gcd(26, 24)
→ gcd(24, 2)
→ gcd(2, 0)
→ 2
```

- 時間複雜度：`O(log min(a, b))`
- 額外空間複雜度：`O(1)`
- 優點：沒有遞迴呼叫堆疊，適合作為正式約分 helper。

### `GCD2`：遞迴版

遞迴版套用相同數學性質，以 `GCD2(b, a % b)` 處理下一層，當 `b == 0` 時回傳 `a`。

- 時間複雜度：`O(log min(a, b))`
- 呼叫堆疊空間：`O(log min(a, b))`
- 優點：程式結構直接對應數學遞迴定義，適合教學比較。
- 取捨：相較於迭代版，多使用遞迴呼叫堆疊。

`GCD2` 在本專案中保留為教學 API；`FractionAddition` 實際呼叫的是 `GCD`。

## 範例演示流程

### 範例一：`1/3-1/2`

初始累積結果為 `0/1`。

1. 讀取 `1/3`：

   ```text
   0/1 + 1/3
   = (0 × 3 + 1 × 1) / (1 × 3)
   = 1/3
   ```

2. 讀取 `-1/2`，負號已合併到分子：

   ```text
   1/3 + (-1/2)
   = (1 × 2 + (-1) × 3) / (3 × 2)
   = -1/6
   ```

3. `gcd(abs(-1), 6) = 1`，結果已是最簡分數，因此回傳 `"-1/6"`。

### 範例二：`1/2+1/3+1/4`

此案例示範三個分母不同的分數如何依序累加，以及最後才統一約分：

| 步驟 | 新分數 | 通分計算 | 累積結果 |
|---:|---:|---|---:|
| 初始 | — | — | `0/1` |
| 1 | `1/2` | `(0 × 2 + 1 × 1) / (1 × 2)` | `1/2` |
| 2 | `1/3` | `(1 × 3 + 1 × 2) / (2 × 3)` | `5/6` |
| 3 | `1/4` | `(5 × 4 + 1 × 6) / (6 × 4)` | `26/24` |

最後計算 `gcd(26, 24) = 2`：

```text
26/24
= (26 ÷ 2) / (24 ÷ 2)
= 13/12
```

因此回傳 `"13/12"`。
