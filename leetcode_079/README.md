# LeetCode 79 — Word Search（單詞搜索）

[![.NET](https://img.shields.io/badge/.NET-10.0-512BD4)](https://dotnet.microsoft.com/)
[![Language](https://img.shields.io/badge/language-C%23-239120)](https://learn.microsoft.com/dotnet/csharp/)

這是一個使用 C# 與 .NET 10 實作的主控台專案。程式以深度優先搜尋（DFS）搭配回溯，在二維字元棋盤中尋找指定單字，並加入字元數量剪枝與搜尋方向優化。

## 題目說明

給定一個 `m x n` 的字元棋盤 `board` 和一個字串 `word`，判斷能否依序從棋盤中找到單字的每個字元。

- 下一個字元只能位於目前格子的上、下、左、右。
- 不可沿對角線移動。
- 同一格在一條搜尋路徑中不可重複使用。
- 找到完整路徑時回傳 `true`，否則回傳 `false`。

題目連結：[LeetCode 79. Word Search](https://leetcode.com/problems/word-search/)。

## 限制條件

- `m == board.Length`
- `n == board[i].Length`
- `1 <= m, n <= 6`
- `1 <= word.Length <= 15`
- `board` 與 `word` 僅包含大小寫英文字母

本專案依照上述題目條件實作，因此公開方法預期接收非空棋盤與非空單字。

## 解題概念與出發點

最直接的想法是從棋盤的每一格開始，嘗試走出所有可能路徑。若每一步都可任意走向四個方向，路徑數會快速成長；此外，同一格又不能在目前路徑中重複使用，因此需要同時解決：

1. 如何逐步探索相鄰格。
2. 如何記錄目前路徑已使用的格子。
3. 搜尋失敗或成功返回時，如何恢復棋盤供其他起點使用。
4. 如何在進入昂貴的 DFS 前排除明顯不可能的輸入。

本專案採用「字元統計剪枝 + 起點方向優化 + DFS + 原地標記回溯」。它只維護遞迴呼叫堆疊，不需要另外建立與棋盤等大的 `visited` 陣列。

## 解法設計：DFS 與回溯

專案目前只有一種解法，公開入口為：

```csharp
public bool Exist(char[][] board, string word)
```

### 1. 統計棋盤字元

先走訪整個棋盤，以固定大小的計數陣列記錄每個英文字元出現次數。

接著逐字統計 `word`。只要單字需要的某個字元數量超過棋盤供應量，就能立即回傳 `false`，完全不必啟動 DFS。

例如棋盤只有一個 `A`，搜尋 `B` 時：

```text
棋盤 B 的數量 = 0
單字 B 的需求 = 1
1 > 0，因此直接回傳 false
```

### 2. 選擇較少見的搜尋端點

若單字尾字元在棋盤中比首字元更少見，程式會反轉單字後再搜尋。

假設首字元有 10 個可能起點、尾字元只有 1 個可能起點，從尾端開始可將 DFS 第一層候選數由 10 降為 1。反轉不會改變答案，因為合法路徑可以正向走，也可以沿相同格子反向走。

### 3. 逐格啟動 DFS

`Exist` 將棋盤中的每一格視為候選起點，呼叫：

```csharp
Dfs(row, column, wordIndex, board, word)
```

若目前格子的字元不等於 `word[wordIndex]`，這條路徑立即失敗。若已匹配到單字最後一個字元，表示找到完整路徑。

### 4. 原地標記

目前格子匹配後，程式先保存原字元，再暫時改成 `'0'`。題目限定輸入只有英文字母，所以 `'0'` 不可能和下一個目標字元相同；DFS 因此不會在同一路徑中再次使用此格。

```text
保存原字元 → 標記為 '0' → 搜尋四個方向 → 恢復原字元
```

### 5. 四方向遞迴與恢復現場

每一層只探索仍在棋盤範圍內的上、下、左、右相鄰格。若其中一個方向找到完整單字，先記錄成功並停止探索其他方向。

無論搜尋成功或失敗，回傳前都會恢復目前格子的原字元。這項保證很重要：若成功時直接 `return true`，棋盤會殘留 `'0'`，後續案例或呼叫者便會取得被破壞的輸入。

## 正確性概述

- 字元數量剪枝只排除棋盤供應量不足的單字，不會排除任何可能存在的路徑。
- `Exist` 嘗試每一個可能起點，因此不會遺漏合法路徑的第一格。
- `Dfs` 只前往四個合法相鄰格，符合題目的移動規則。
- 原地標記確保目前路徑不會重複使用同一格。
- 只有在依序匹配到單字最後一個字元時才回傳成功。
- 每層回傳前皆恢復字元，所以不同分支與不同呼叫互不污染。

因此，方法回傳 `true` 若且唯若棋盤中存在一條符合題目規則的完整路徑。

## 複雜度分析

令棋盤尺寸為 `m x n`，單字長度為 `L`。

- 時間複雜度：`O(m x n x 3^L)`
  - 最初有 `m x n` 個候選起點。
  - 第一個字元之後，通常最多只剩三個未使用方向，因為剛走過的格子已被標記。
  - 字元統計需要額外的 `O(m x n + L)`，不影響最壞情況主項。
- 額外空間複雜度：`O(L)`
  - 主要來自最深為 `L` 的遞迴呼叫堆疊。
  - 兩個 ASCII 計數陣列大小固定，可視為 `O(1)`。

## 範例演示流程

### 範例一：成功找到 `ABCCED`

```text
A B C E
S F C S
A D E E
```

其中一條合法路徑為：

```text
(0,0) A
  → (0,1) B
  → (0,2) C
  → (1,2) C
  → (2,2) E
  → (2,1) D
```

每一步都水平或垂直相鄰，且沒有格子被重複使用，所以結果為 `true`。

### 範例二：`ABCB` 無法重複使用格子

在同一張棋盤中，從 `(0,0) A` 走到 `(0,1) B`、再走到 `(0,2) C` 後，下一個目標是 `B`。

此時唯一鄰近且曾經符合的 `B` 是 `(0,1)`，但它已在目前路徑中使用並被標記，不能再次走回去。其他起點與分支也無法完成單字，因此結果為 `false`。

### 範例三：字元數量不足而提前結束

```text
棋盤：A
單字：B
```

統計階段發現棋盤沒有任何 `B`，但單字需要一個 `B`。程式在 DFS 前直接回傳 `false`。

### 補充：`AABC` 的有效路徑

```text
C A A
A A A
B C D
```

一條合法路徑為：

```text
(1,1) A → (1,0) A → (2,0) B → (2,1) C
```

因此此案例的正確答案是 `true`。
