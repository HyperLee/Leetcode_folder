## 題目說明

給定整數陣列 `prices`，其中 `prices[i]` 表示第 `i` 天的股票價格。只能選擇某一天買入一股，並在未來另一個不同的日子賣出，求這一次交易可以取得的最大獲利。

交易必須符合以下規則：

1. 最多只能完成一次買入與一次賣出。
2. 賣出日必須晚於買入日，不能先賣後買。
3. 如果所有未來價格都不高於買入價格，可以不交易並回傳 `0`。

例如 `prices = [7, 1, 5, 3, 6, 4]`，最佳選擇是在價格為 `1` 時買入、價格為 `6` 時賣出，因此最大獲利是 `6 - 1 = 5`。

題目連結：

- [LeetCode 121 - Best Time to Buy and Sell Stock](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/)
- [力扣 121 - 買賣股票的最佳時機](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/)

## 限制條件

官方題目的輸入限制如下：

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`

三個方法都預期 `prices` 是非 `null`、依日期先後排列的整數陣列。範例執行器另外放入空陣列，確認目前實作會防禦性地回傳 `0`；空陣列不是 LeetCode 官方測試範圍。

## 解題概念與出發點

最大獲利可以寫成：

```text
賣出價格 - 買入價格
```

真正的限制不在減法，而是買入日必須早於賣出日。最直接的想法是列出每一組合法買賣日，再從中選最大值；但當資料量達到 `10^5` 時，兩層迴圈的組合數會變得非常大。

進一步觀察會發現：如果今天固定作為賣出日，最佳買入價格一定是今天以前出現過的最低價格。因此走訪到每一天時，只需保留兩個狀態：

- `minPrice`：截至目前為止最低的買入價格。
- `maxProfit`：截至目前為止找到的最大獲利。

每個價格只需處理一次，就能把時間複雜度從 `O(n²)` 降為 `O(n)`。

## 三種解法比較

| 方法 | 主要概念 | 時間複雜度 | 空間複雜度 | 特點 |
| --- | --- | ---: | ---: | --- |
| `MaxProfit` | 枚舉所有合法買入日與賣出日 | `O(n²)` | `O(1)` | 最直覺，適合用來理解題意，但大型輸入容易逾時 |
| `MaxProfit2` | 使用索引式 `for` 維護最低價格 | `O(n)` | `O(1)` | 可清楚看到索引與狀態更新條件 |
| `MaxProfit3` | 使用 `foreach` 搭配 `Math.Min`、`Math.Max` | `O(n)` | `O(1)` | 與解法二概念相同，寫法更精簡 |

## 解法一：枚舉所有買賣組合

### 設計說明

`MaxProfit` 讓外層迴圈選擇買入日，內層迴圈只能從買入日的下一天開始選擇賣出日。這個起點非常重要，它直接保證不會出現先賣後買或同一天買賣的組合。

每一組交易都計算：

```text
profit = prices[sellDay] - prices[buyDay]
```

再用 `maxProfit` 保留目前看過的最大值。`maxProfit` 從 `0` 開始，因此價格持續下跌時，不會回傳負數，而是代表選擇不交易。

### 範例演示

以 `prices = [2, 4, 1]` 為例：

| 買入日 | 買入價 | 賣出日 | 賣出價 | 本次獲利 | 目前最大獲利 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 第 1 天 | 2 | 第 2 天 | 4 | `4 - 2 = 2` | 2 |
| 第 1 天 | 2 | 第 3 天 | 1 | `1 - 2 = -1` | 2 |
| 第 2 天 | 4 | 第 3 天 | 1 | `1 - 4 = -3` | 2 |

所有合法組合都檢查完後，答案為 `2`。若陣列長度是 `n`，最多需要檢查約 `n(n-1)/2` 組交易，因此不適合題目允許的最大資料量。

## 解法二：以 `for` 維護最低價格

### 設計說明

`MaxProfit2` 從左到右走訪價格。遇到更低的價格時更新 `minPrice`，代表未來有更便宜的買入選擇；否則用當天價格減去 `minPrice`，檢查今天賣出是否能刷新 `maxProfit`。

這個流程始終維持兩個不變量：

1. `minPrice` 是目前索引以前（包含目前）的最低價格。
2. `maxProfit` 是目前已掃描範圍內所有合法交易的最大獲利。

因為不需要回頭尋找最低價格，每一天只處理一次。

### 範例演示

以 `prices = [7, 1, 5, 3, 6, 4]` 為例：

| 天數 | 當天價格 | 更新後最低價格 | 當天可得獲利 | 更新後最大獲利 |
| ---: | ---: | ---: | ---: | ---: |
| 第 1 天 | 7 | 7 | 0 | 0 |
| 第 2 天 | 1 | 1 | 0 | 0 |
| 第 3 天 | 5 | 1 | `5 - 1 = 4` | 4 |
| 第 4 天 | 3 | 1 | `3 - 1 = 2` | 4 |
| 第 5 天 | 6 | 1 | `6 - 1 = 5` | 5 |
| 第 6 天 | 4 | 1 | `4 - 1 = 3` | 5 |

最佳答案是在第 2 天以 `1` 買入，第 5 天以 `6` 賣出，回傳 `5`。

## 解法三：以 `foreach` 更新狀態

### 設計說明

`MaxProfit3` 使用 `foreach` 直接取得每天的 `price`，不需要操作索引。每輪先把當天價格納入最低價格，再計算「如果今天賣出」可得到的獲利。同一天作為最低價時，候選獲利只會是 `0`，不會改變答案：

```text
minPrice  = Min(minPrice, price)
maxProfit = Max(maxProfit, price - minPrice)
```

這與解法二採用相同的貪心觀察和相同的複雜度。差別主要在表達方式：解法二用條件分支清楚區分「更新低點」與「更新獲利」，解法三則用 `Math.Min`、`Math.Max` 集中表達狀態轉移。

### 範例演示

以 `prices = [3, 3, 5, 0, 0, 3, 1, 4]` 為例：

| 當天價格 | 掃描前最低價格 | 今天賣出的候選獲利 | 更新後最低價格 | 最大獲利 |
| ---: | ---: | ---: | ---: | ---: |
| 3 | 尚未建立 | 0 | 3 | 0 |
| 3 | 3 | 0 | 3 | 0 |
| 5 | 3 | 2 | 3 | 2 |
| 0 | 3 | -3 | 0 | 2 |
| 0 | 0 | 0 | 0 | 2 |
| 3 | 0 | 3 | 0 | 3 |
| 1 | 0 | 1 | 0 | 3 |
| 4 | 0 | 4 | 0 | 4 |

最低價格在中途從 `3` 更新為 `0`，之後以價格 `4` 賣出可以得到最大獲利 `4`。重複的價格不會破壞狀態，也不需要特別去重。
