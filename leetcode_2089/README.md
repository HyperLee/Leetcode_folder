# LeetCode 2089：排序後的目標索引

![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4?logo=dotnet&logoColor=white)

[LeetCode 英文題目](https://leetcode.com/problems/find-target-indices-after-sorting-array/) · [LeetCode 中文題目](https://leetcode.cn/problems/find-target-indices-after-sorting-array/)

## 題目說明

給定整數陣列 `nums` 和目標值 `target`。將陣列依非遞減順序排列後，找出所有值等於 `target` 的位置，並依遞增順序回傳這些索引。索引從 `0` 開始；若沒有符合的元素，回傳空清單。

### 限制條件

- `1 <= nums.Length <= 100`
- `1 <= nums[i], target <= 100`

題目有多個相同值的可能，因此答案可以包含多個連續索引。

### 題目範例

| `nums` | `target` | 排序後的陣列 | 回傳索引 |
| --- | ---: | --- | --- |
| `[1, 2, 5, 2, 3]` | `2` | `[1, 2, 2, 3, 5]` | `[1, 2]` |
| `[1, 2, 5, 2, 3]` | `3` | `[1, 2, 2, 3, 5]` | `[3]` |
| `[1, 2, 5, 2, 3]` | `5` | `[1, 2, 2, 3, 5]` | `[4]` |

## 解題概念與出發點

排序後，所有小於 `target` 的數值會在前面，等於 `target` 的數值會排在中間且彼此相鄰，大於 `target` 的數值則在後面。因此，目標索引在排序後一定形成一段連續區間。

這段區間的起點是「小於 `target` 的元素數量」，長度是「等於 `target` 的元素數量」。有了這個觀察，可以選擇真的排序後掃描，也可以只數兩種元素的數量，再直接生成答案。

## 解法一：排序後逐一掃描

### 設計步驟

1. 使用 `Array.Sort(nums)` 將陣列由小到大排序。
2. 從索引 `0` 掃描到最後一個索引。
3. 若 `nums[i] == target`，就把 `i` 加入結果清單。
4. 掃描方向由左至右，所以結果自然依遞增順序排列；若沒有相等值，結果保持空清單。

**輸入副作用：** `Array.Sort` 會原地排序傳入的 `nums` 陣列。若呼叫端需要保留原順序，應先複製陣列再呼叫。

### 範例演示

輸入 `nums = [1, 2, 5, 2, 3]`、`target = 2`。排序後為 `[1, 2, 2, 3, 5]`：

| 掃描索引 `i` | `nums[i]` | 判斷 | 結果清單 `res` |
| ---: | ---: | --- | --- |
| 0 | 1 | 小於 `target`，略過 | `[]` |
| 1 | 2 | 等於 `target`，加入索引 1 | `[1]` |
| 2 | 2 | 等於 `target`，加入索引 2 | `[1, 2]` |
| 3 | 3 | 大於 `target`，略過 | `[1, 2]` |
| 4 | 5 | 大於 `target`，略過 | `[1, 2]` |

掃描完成後回傳 `[1, 2]`。

### 複雜度

- 時間：`O(n log n)`，排序花費 `O(n log n)`，後續掃描花費 `O(n)`。
- 空間：結果清單需要 `O(k)`，其中 `k` 是目標值出現次數；排序的額外空間依 `Array.Sort` 實作而定，常見分析會將排序堆疊計為 `O(log n)`。

## 解法二：統計數量後直接建立索引

### 設計步驟

1. 不排序陣列，只掃描一次並統計：
   - `cnt1`：小於 `target` 的元素數量。
   - `cnt2`：等於 `target` 的元素數量。
2. 由於排序後 `target` 會接在所有較小值之後，第一個目標索引就是 `cnt1`。
   - `cnt1` 是元素數量，不是某個小於 `target` 的元素索引；它從 `0` 開始，每遇到一個小於 `target` 的元素就加 `1`。由於陣列索引從 `0` 開始，排序後這 `cnt1` 個較小元素占據索引 `0` 到 `cnt1 - 1`，所以下一個索引 `cnt1` 就是第一個 `target` 的位置。
   - 例如 `nums = [1, 2, 5, 2, 3]`、`target = 2` 時，`cnt1 = 1`；較小的 `1` 位於索引 `0`，所以第一個 `2` 位於索引 `1`。若從 `cnt1 + 1`（索引 `2`）開始，就會漏掉索引 `1`。
3. 目標值會連續出現 `cnt2` 次，因此依序產生左閉右開區間 `[cnt1, cnt1 + cnt2)` 中的索引。
4. 若 `cnt2` 為 `0`，區間是空的，結果也會是空清單。

### 範例演示

輸入 `nums = [1, 2, 5, 2, 3]`、`target = 2`。逐一統計時：

| 讀取值 `num` | 與 `target` 的關係 | `cnt1`（小於） | `cnt2`（相等） |
| ---: | --- | ---: | ---: |
| 1 | 小於 2 | 1 | 0 |
| 2 | 等於 2 | 1 | 1 |
| 5 | 大於 2 | 1 | 1 |
| 2 | 等於 2 | 1 | 2 |
| 3 | 大於 2 | 1 | 2 |

掃描結束後，`cnt1 = 1`、`cnt2 = 2`，所以答案索引是 `[1, 1 + 2)`，也就是 `[1, 2]`。

### 複雜度

- 時間：`O(n + k)`，掃描陣列花費 `O(n)`，建立結果清單花費 `O(k)`。
- 空間：計數器使用 `O(1)` 額外空間，結果清單需要 `O(k)`。

## 兩種方法比較

| 方法 | 是否排序 | 是否改動輸入陣列 | 時間複雜度 | 額外空間 |
| --- | --- | --- | --- | --- |
| `TargetIndices` | 是 | 是 | `O(n log n)` | `O(k)` 結果清單；排序空間依實作而定 |
| `TargetIndices2` | 否 | 否 | `O(n + k)` | `O(1)` 計數器，加上 `O(k)` 結果清單 |

`n` 是陣列長度，`k` 是 `target` 在陣列中出現的次數。若重視程式直觀，排序後掃描較容易理解；若只需要答案索引，直接計數可省去排序。
