# LeetCode 1352. 最後 K 個數的乘積

## 題目說明

設計一個接收整數的資料流。每次加入數字時，把它放到資料流尾端。每次查詢時，回傳目前最後 `k` 個連續元素的乘積。查詢可以和新增交錯進行，查詢後資料流仍保有原本的內容。

| 題目介面 | C# 對應 | 行為 |
| --- | --- | --- |
| `ProductOfNumbers()` | `ProductOfNumbers()` | 建立空資料流。 |
| `add(num)` | `Add(int num)` | 將 `num` 加入資料流尾端。 |
| `getProduct(k)` | `GetProduct(int k)` | 回傳最後 `k` 個數字的乘積。 |

[LeetCode 官方題目](https://leetcode.com/problems/product-of-the-last-k-numbers/description/) · [完整題目與範例](./Problem_Description.md)

### 限制條件

- `0 <= num <= 100`。
- `1 <= k <= 40,000`，每次查詢時已加入至少 `k` 個數字。
- `Add` 與 `GetProduct` 合計最多呼叫 40,000 次。
- 任意連續區間的乘積都可用 32 位元有號整數表示。

### 官方範例

| 操作 | 查詢涵蓋的尾段 | 回傳值 |
| --- | --- | ---: |
| 依序加入 `3, 0, 2, 5, 4` |  |  |
| `GetProduct(2)` | `[5, 4]` | 20 |
| `GetProduct(3)` | `[2, 5, 4]` | 40 |
| `GetProduct(4)` | `[0, 2, 5, 4]` | 0 |
| 加入 `8` |  |  |
| `GetProduct(2)` | `[4, 8]` | 32 |

## 解題出發點

直接從資料流尾端逐項相乘，每次查詢最壞需要處理 `k` 個元素。當同一段資料被反覆查詢時，很多乘法會重複執行。可以在加入數字時先更新資訊，讓查詢快速判斷尾段是否含零，並減少需要執行的乘除法。

只要尾段包含 `0`，答案就是 `0`。若尾段無零，可以用兩個前綴乘積的比值取得答案，也可以只乘上區間中大於 `1` 的因數，因為乘上 `1` 不會改變結果。

## 解法一：前綴乘積（`ProductOfNumbers`）

### 為什麼遇到零要重算前綴

如果從資料流開頭一路累乘，讀到第一個零後，所有後續前綴乘積都會變成零。例如對 `[3, 0, 2, 5, 4]` 從頭累乘，含空前綴的結果是 `[1, 3, 0, 0, 0, 0]`。查最後兩個數字時，原本要用完整前綴除以 `[3, 0, 2]` 的前綴，卻會算到 `0 / 0`，無法取得實際的 `5 × 4 = 20`。

由於查詢永遠從資料流尾端往左取，只要取到最近的零，就可以直接得出答案。只有查詢完全落在零右側時才需要計算乘積，所以把每個零當成分段點，從下一個非零數字重新累乘。

### 狀態與更新

`prefixProduct` 記錄最近一次加入零之後的非零區段。假設這段有 `m` 個數字，清單的第 `i` 格是前 `i` 個數字的乘積，清單長度為 `m + 1`。第 0 格固定是 `1`，代表空前綴。

- 建構子將清單初始化為 `[1]`，`Add(0)` 也會將它重設為 `[1]`。空前綴的 `1` 讓下一個非零數字可以從 `1 × num` 開始累乘，也讓查詢整個非零區段時可以直接除以 `1`。查詢若包含零，`GetProduct` 會在執行除法前回傳 `0`。
- 加入非零數字時，把目前最後一個前綴乘積乘上新數字，將結果加到清單尾端。`Add(1)` 走同一個分支。雖然乘積值相同，仍要新增一格，因為非零區段多了一個數字。

例如依序加入 `0, 5, 1`，清單依序變成 `[1]`、`[1, 5]`、`[1, 5, 5]`。

| 查詢 | 實際取出的尾段 | 結果 |
| --- | --- | --- |
| `GetProduct(1)` | `[1]` | `5 ÷ 5 = 1` |
| `GetProduct(2)` | `[5, 1]` | `5 ÷ 1 = 5` |
| `GetProduct(3)` | `[0, 5, 1]` | 含零，直接回傳 `0` |

例如非零區段為 `[2, 5, 4]` 時，清單的索引表示「已乘入幾個數字」。

| 前綴索引 `i` | 已乘入的數字 | `prefixProduct[i]` |
| ---: | --- | ---: |
| 0 | 空前綴 | 1 |
| 1 | `[2]` | 2 |
| 2 | `[2, 5]` | 10 |
| 3 | `[2, 5, 4]` | 40 |

### 查詢與公式

當 `k > m` 時，查詢比目前的非零區段長，必定包含最近一次加入的零。程式使用等價條件 `prefixProduct.Count <= k` 直接回傳 `0`。

當 `k <= m` 時，完整前綴分成兩段。前 `m - k` 個數字的乘積乘上目標尾段的乘積，正好等於 `prefixProduct[m]`。因此用 `prefixProduct[m] / prefixProduct[m - k]` 就能抵銷左段。兩個前綴都取自非零區間，除數大於零而且能整除。當 `k == m` 時，除數就是第 0 格的 `1`。

公式可對照到 `GetProduct` 裡的索引。這個方法的區域變數 `n` 是 `prefixProduct.Count`，所以 `m = n - 1`。完整前綴的索引是 `n - 1`，要消去的左段長度是 `m - k = n - 1 - k`。

下圖用 `P[i]` 表示 `prefixProduct[i]`。

```text
Nonzero suffix:   x[0] ... x[m-k-1] | x[m-k] ... x[m-1]
                  <--- m-k nums --> | <---- k nums ---->
                  <-------------- P[m] ---------------->
                  <--- P[m-k] ---->

P[m] = P[m-k] * product of the last k numbers
```

| 查詢長度 | 判斷與結果 |
| --- | --- |
| `k < m` | 尾段完全落在非零區段，除以長度 `m - k` 的前綴。 |
| `k == m` | 尾段就是整個非零區段，`P[m] / P[0] = P[m]`。 |
| `k > m` | 尾段包含最近的零，直接回傳 `0`。 |
| `m == 0` 且已有合法查詢 | 資料流末尾是零，所以每一個合法尾段都回傳 `0`。 |

加入每個非零值時，新乘積都對應原始資料流中的連續區段，因此可直接使用題目給的 32 位元整數保證。若接連加入兩個零，每次都重設為 `[1]`，而之後的查詢只需要考慮最新的零是否落在尾段內。

### ASCII 演示

```text
Operation         Nonzero suffix      prefixProduct
start             []                  [1]
Add(3)            [3]                 [1, 3]
Add(0)            []                  [1]
Add(2)            [2]                 [1, 2]
Add(5)            [2, 5]              [1, 2, 10]
Add(4)            [2, 5, 4]           [1, 2, 10, 40]

Stream                  3 | 0 | 2 | 5 | 4
GetProduct(2)                      [5 | 4]    P[3] / P[1] = 40 / 2 = 20
GetProduct(3)                  [2 | 5 | 4]    P[3] / P[0] = 40 / 1 = 40
GetProduct(4)              [0 | 2 | 5 | 4]    k > 3            -> 0

Add(8)            [2, 5, 4, 8]        [1, 2, 10, 40, 320]
GetProduct(2)     [4, 8]               P[4] / P[2] = 320 / 10 = 32
```

呼叫 `GetProduct(2)` 時，`prefixProduct` 是 `[1, 2, 10, 40]`，所以 `n = 4`。索引 `0` 的 `1` 代表空前綴，因此實際累乘了 `n - 1 = 3` 個數字。要留下最後 `k = 2` 個，左邊就有 `n - 1 - k = 1` 個數字要約掉。`prefixProduct[1]` 正好存著左邊這一個數字的乘積。

```text
prefixProduct[n - 1] / prefixProduct[n - 1 - k]
= prefixProduct[4 - 1] / prefixProduct[4 - 1 - 2]
= prefixProduct[3] / prefixProduct[1]
= (2 × 5 × 4) / 2
= 5 × 4
= 20
```

## 解法二：前綴零計數與索引跳躍（`ProductOfNumbers2`）

### 狀態與更新

三個清單都以資料流的零起始索引對齊。

| 清單 | 第 `i` 格的內容 |
| --- | --- |
| `nums` | 資料流第 `i` 個數字。 |
| `zeroCount` | 從索引 `0` 到 `i` 為止的累計零數，包含索引 `i`。 |
| `prevNonOne` | 索引 `i` 左側最近的大於 `1` 的位置，找不到時為 `-1`。 |

加入新數字時，以前一格的累計零數為基礎，新數字是零才加一。計算新位置的跳躍索引時，若前一格的值大於 `1`，就記住前一格的位置。若前一格是 `0` 或 `1`，前一格已記錄它左側最近的大於 `1` 的位置，沿用即可。第一格左側沒有任何元素，因此記為 `-1`。

程式加入後的資料流長度為 `n`，所以新索引是 `i = n - 1`，前一格是 `i - 1 = n - 2`。兩項狀態都只讀取左邊已經算好的資料。

| 新索引 `i` 的狀況 | `zeroCount[i]` | `prevNonOne[i]` |
| --- | --- | --- |
| `i == 0` | 新值是零時為 `1`，否則為 `0`。 | `-1` |
| `i > 0`，前一格大於 `1` | 前一格的累計零數，加上新值是否為零。 | `i - 1` |
| `i > 0`，前一格是 `0` 或 `1` | 前一格的累計零數，加上新值是否為零。 | `prevNonOne[i - 1]` |

例如依序加入 `3, 0, 2`。追加 `0` 時，新格的零計數增加為 `1`，而跳躍索引指向左邊的 `3`。追加 `2` 時，新格的零計數仍是 `1`，前一格的值是 `0`，因此新格沿用前一格所指向的索引 `0`。後續要不要真的乘到該位置，由查詢的零數檢查和左界共同決定。

### 查詢與正確性

資料流長度為 `n` 時，尾段範圍是 `[n - k, n - 1]`。

1. 用 `zeroCount[n - 1]` 扣掉尾段起點前一格的累計零數。若尾段從索引 `0` 開始，要扣掉的是空區間，零數為 `0`。
2. 若尾段內至少有一個零，直接回傳 `0`。這一步保證後續跳躍在查詢範圍內只會略過 `1`。
3. 從尾端索引 `i = n - 1` 開始。每輪先檢查 `i >= n - k`，成立才乘入 `nums[i]`，接著把 `i` 更新為 `prevNonOne[i]`。它指向左側最近的大於 `1` 的數字的索引，找不到時為 `-1`。更新後回到迴圈條件，索引等於左界時仍會乘入，小於左界時就停止。

令 `L = n - k`。圖中的 `Z` 代表 `zeroCount`，每格都包含該索引。

```text
index      0 ................ L-1 | L ................ n-1
           <------- Z[L-1] ------>|
           <------------------- Z[n-1] ------------------>
                                  |<------ last k ------->

zeros in suffix = Z[n-1] - Z[L-1]
```

當 `L = 0` 時，左側沒有元素，程式直接使用 `Z[n - 1]`，也就不會存取索引 `-1`。例如 `[7, 0, 0, 2]` 的累計零數為 `[0, 1, 2, 2]`。查最後一個數字時，零數是 `2 - 2 = 0`，答案為 `2`。查最後兩個數字時，零數是 `2 - 1 = 1`，馬上回傳 `0`。查整段時，左側為空，直接讀到兩個零。

確認尾段無零後，從末端向左更新 `ans`。每次迴圈結束時，`ans` 已包含剛走過區間中的所有大於 `1` 的因數。跳躍索引一定往左移，兩個造訪位置之間沒有其他大於 `1` 的數字，因此略過中間的 `1` 不影響結果。如果整段都是 `1`，先乘末端的 `1`，下一個跳躍目標會落在尾段左界之前，答案就是 `1`。

### ASCII 演示一：官方範例

```text
index          0   1   2   3   4
nums           3   0   2   5   4
zeroCount      0   1   1   1   1
prevNonOne    -1   0   0   2   3

k = 2: start = 3, zeros = Z[4] - Z[2] = 0
       indices 4 -> 3 -> 2 (stop), product = 4 * 5 = 20

k = 3: start = 2, zeros = Z[4] - Z[1] = 0
       indices 4 -> 3 -> 2 -> 0 (stop), product = 4 * 5 * 2 = 40

k = 4: start = 1, zeros = Z[4] - Z[0] = 1
       return 0

Add(8): new index = 5, Z[5] = 1, prevNonOne[5] = 4
k = 2: start = 4, zeros = Z[5] - Z[3] = 0
       indices 5 -> 4 -> 3 (stop), product = 8 * 4 = 32
```

例如 `k = 3` 時，索引 `2` 的跳躍目標是索引 `0`。索引 `0` 已經在尾段起點左邊，所以即刻停止，乘積只有 `4 * 5 * 2`。

### ASCII 演示二：略過中間的 1

```text
index          0   1   2   3   4
nums           2   1   1   3   1
zeroCount      0   0   0   0   0
prevNonOne    -1   0   0   0   3

k = 4, start = 1, zeros = Z[4] - Z[0] = 0

index    4 --------> 3 ----------------> 0 (stop)
value    1           3                   2
product  1 * 1 = 1   1 * 3 = 3
                     skips indices 2 and 1
```

呼叫 `GetProduct(4)` 時，`n = 5`，左界是 `n - k = 1`。確認尾段沒有零後，令 `ans = 1`，從 `i = n - 1 = 4` 開始。

| 目前的 `i` | 檢查 `i >= 1` | 本次動作 | 下一個 `i` |
| ---: | --- | --- | --- |
| `4` | `4 >= 1`，成立 | 乘入 `nums[4] = 1`，`ans = 1`。 | `prevNonOne[4] = 3` |
| `3` | `3 >= 1`，成立 | 乘入 `nums[3] = 3`，`ans = 3`。 | `prevNonOne[3] = 0` |
| `0` | `0 >= 1`，不成立 | 結束迴圈，回傳 `3`。 | — |

從索引 `3` 跳到 `0` 時，略過索引 `2` 和 `1` 的兩個 `1`。若改查 `GetProduct(5)`，左界變成 `0`。跳到索引 `0` 時，`0 >= 0` 成立，因此會再乘入 `nums[0] = 2`。接著 `i` 更新為 `prevNonOne[0] = -1`，下一次條件檢查失敗，回傳 `6`。

同一份跳躍索引在不同查詢長度下會停在不同位置。

| 查詢 | 左界 | 實際乘入的索引與值 | 停止位置 | 回傳值 |
| --- | ---: | --- | --- | ---: |
| `GetProduct(1)` | 4 | `4(1)` | 跳到 `3`，小於左界。 | 1 |
| `GetProduct(2)` | 3 | `4(1) → 3(3)` | 跳到 `0`，小於左界。 | 3 |
| `GetProduct(4)` | 1 | `4(1) → 3(3)` | 跳到 `0`，小於左界。 | 3 |
| `GetProduct(5)` | 0 | `4(1) → 3(3) → 0(2)` | 跳到 `-1`，小於左界。 | 6 |

## 複雜度比較

令 `n` 為目前已加入的數字總數，`r` 為歷來最長的連續非零區段長度，`t` 為無零尾段內大於 `1` 的因數個數。

| 解法 | 加入 | 查詢 | 額外空間 |
| --- | --- | --- | --- |
| 前綴乘積 | 攤銷 `O(1)` | `O(1)` | `O(r + 1)` |
| 前綴零計數與索引跳躍 | 攤銷 `O(1)` | 含零時 `O(1)`，無零時 `O(t + 1)` | `O(n)` |

- 兩種解法都使用 `List<int>`，單次追加可能要擴充容量。前綴乘積遇零清空時，清單可能保留原容量，因此空間估算使用歷來最長區段。
- 第二種解法最多會乘上 `t` 個大於 `1` 的因數，尾端為 `1` 時會多乘一次。題目保證正整數乘積小於 `2^31`，每個大於 `1` 的因數至少為 `2`，所以 `t <= 30`。在此限制下，無零尾段也最多造訪 31 個位置。

兩種解法把不同資訊留到查詢時使用。前綴乘積預先保存每個前綴的**乘積**，查詢最多做一次除法，所需容量取決於歷來最長的非零區段。第二種解法預先保存**零數與因數位置**，查詢時沿著索引重新乘上因數，因此能直接看出哪些原始位置參與計算，代價是三個清單會隨整條資料流一起成長。
