# LeetCode 1524｜總和為奇數的子陣列數目

## 題目說明

給定整數陣列 `arr`，求元素總和為奇數的子陣列個數，並回傳個數除以 `10^9 + 7` 的餘數。子陣列由一段連續且非空的索引區間決定。即使兩段區間的元素值相同，只要位置不同，就分開計數。

例如 `arr = [1, 3, 5]`，三個單元素子陣列與整段 `[1, 3, 5]` 的總和都是奇數，答案是 `4`。更多題意與範例見 [題目解說](PROBLEM_EXPLANATION.md)。

### 限制條件

- `1 ≤ arr.Length ≤ 100,000`
- `1 ≤ arr[i] ≤ 100`

## 解題出發點｜用前綴和表示區間

直接列舉每個起點和終點，即使每次能在常數時間求出區間總和，仍要檢查 `n × (n + 1) / 2` 個區間。當 `n = 100,000`，會有 5,000,050,000 個區間。可以把相同奇偶性的起點合併計數，讓每個終點只做一次查詢。

令 `P[k]` 為陣列前 `k` 個元素的總和，並定義空前綴 `P[0] = 0`。索引從 `0` 開始，且 `[l, r]` 包含兩個端點，因此它的總和是 `P[r + 1] - P[l]`。減掉前 `l` 個元素，剛好留下從索引 `l` 到 `r` 的元素。

```text
arr index           0       1       2
arr value           1       3       5
                |-------|-------|-------|
prefix index    0       1       2       3
P[k]            0       1       4       9
                        |<------------->|
                        P[3] - P[1] = 8
```

圖中 `P[3] - P[1]` 對應區間 `[1, 2]`，留下 `3 + 5 = 8`。兩個前綴都是奇數，因此相減是偶數。奇減偶或偶減奇都會得到奇數，所以只要知道目前前綴的奇偶性，以及先前有多少個相反奇偶性的前綴。

固定右端點 `r` 時，每個與 `P[r + 1]` 奇偶性相反的先前前綴 `P[l]`，都對應一個合法區間 `[l, r]`。由於前綴索引較早，`l ≤ r`，區間必定非空。每段區間都有唯一的起點和終點，所以整趟掃描恰好計入每個合法區間一次。

## 解法一｜掃描時維護奇偶前綴的個數

`NumOfSubarrays` 每讀到一個元素，就數出以目前位置結尾、總和為奇數的子陣列有幾個。

| 變數 | 記錄的內容 | 初始值 |
| --- | --- | ---: |
| `total` | 目前的前綴和 | `0` |
| `even` | 已登記的偶數前綴有幾個 | `1` |
| `odd` | 已登記的奇數前綴有幾個 | `0` |
| `subarrays` | 已找到的奇數和子陣列個數，保留取模後的餘數 | `0` |

`even` 從 `1` 開始，因為空前綴 `P[0] = 0` 已算作一個偶數前綴。減去這個 `0`，就能保留從索引 `0` 開始的整段區間。

每輪先執行 `total += x`。讀到索引 `r` 時，`total` 就是 `P[r + 1]`。接著用 `total` 的奇偶性選擇分支。

```csharp
if (total % 2 == 0)
{
    subarrays = (subarrays + odd) % MODULO;
    even++;
}
else
{
    subarrays = (subarrays + even) % MODULO;
    odd++;
}
```

- **`total` 是偶數時**，讀取 `odd` 來更新答案。每個先前的奇數前綴都提供一個起點，因為偶數減奇數會得到奇數。接著執行 `even++`，把目前前綴算進偶數前綴的個數。
- **`total` 是奇數時**，讀取 `even` 來更新答案。每個先前的偶數前綴都提供一個起點，因為奇數減偶數會得到奇數。接著執行 `odd++`，把目前前綴算進奇數前綴的個數。

每輪先用**相反奇偶性**的舊計數，算出這輪找到幾個總和為奇數的子陣列，再將**目前奇偶性**的計數器加 `1`。更新後的計數器會留給下一輪使用。

### 範例演示｜`[1, 3, 5]`

**每輪固定以目前讀到的元素為結尾，再往左選起點。** 每個起點和這個結尾形成一個連續子陣列。起點和結尾在同一個位置時，單一元素也算一個子陣列。

| 本輪結尾 | 所有以此結尾的子陣列與總和 | 本輪計入 |
| --- | --- | --- |
| `arr[0] = 1` | `[1]` → `1` | `[1]`，共 1 個 |
| `arr[1] = 3` | `[1, 3]` → `4`、`[3]` → `3` | `[3]`，共 1 個 |
| `arr[2] = 5` | `[1, 3, 5]` → `9`、`[3, 5]` → `8`、`[5]` → `5` | `[1, 3, 5]`、`[5]`，共 2 個 |

`[1]` 以索引 `0` 結尾，已在第一輪計入。第二輪以索引 `1` 為結尾，只有 `[3]` 的總和是奇數。程式透過 `even` 或 `odd` 直接得到表中的數量，下面逐輪對照。

#### 逐輪流程表

掃描開始前，空前綴 `P[0] = 0` 已登記，所以 `(even, odd) = (1, 0)`，`total` 和 `subarrays` 都是 `0`。每一列對應一次 `foreach` 迴圈。

| 本輪讀到 | 更新後的 `total` | 本輪採用的計數 | 本輪計入的子陣列 | 累計 `subarrays` | 登記後 `(even, odd)` |
| --- | --- | --- | --- | --- | --- |
| `arr[0] = 1` | `0 + 1 = 1`（奇） | `even = 1` | `1 - 0 = 1` → `[1]` | `0 + 1 = 1` | `(1, 1)` |
| `arr[1] = 3` | `1 + 3 = 4`（偶） | `odd = 1` | `4 - 1 = 3` → `[3]` | `1 + 1 = 2` | `(2, 1)` |
| `arr[2] = 5` | `4 + 5 = 9`（奇） | `even = 2` | `9 - 0 = 9` → `[1, 3, 5]`、`9 - 4 = 5` → `[5]` | `2 + 2 = 4` | `(2, 2)` |

#### 如何判讀這張表

1. **本輪讀到**決定右端點。第三輪讀到 `arr[2] = 5`，這一輪計入的子陣列都在索引 `2` 結尾。
2. **更新後的 `total`** 是執行 `total += x` 後的前綴和。第三輪把上一輪的 `4` 加上 `5` 得到 `9`。奇偶分支依 `total` 判斷，例如第二輪讀到的 `3` 是奇數，但當時 `total = 4`，因此走偶數分支。
3. **本輪採用的計數**表示這一輪要加幾個。第三輪的 `total = 9` 是奇數，所以讀取尚未登記目前前綴時的 `even = 2`。當時兩個偶數前綴是 `P[0] = 0` 和 `P[2] = 4`，各對應一個合法起點。
4. **本輪計入的子陣列**列出這一輪加進去的是哪幾段。第三輪扣掉 `P[0]`，也就是略過前 `0` 個元素，留下 `[1, 3, 5]`。扣掉 `P[2]`，也就是略過前 `2` 個元素，留下 `[5]`。兩段的總和分別為 `9` 和 `5`，所以程式可以直接用 `even = 2` 更新答案。
5. **累計 `subarrays`** 是上一輪的累計加上本輪個數後取模。第三輪開始前已找到 `2` 個，這輪又找到 `2` 個，所以累計為 `4`。
6. **登記後 `(even, odd)`** 是本輪結束時的兩個計數器。更新 `subarrays` 後，第三輪執行 `odd++` 來登記奇數前綴 `P[3] = 9`，使 `(2, 1)` 變成 `(2, 2)`。如果還有下一輪，這一列最右邊的數值就是下一輪開始時的計數。

#### 第 1 輪｜讀到 `1`，`total = 0 + 1 = 1`

1. **本輪找到 `1` 個總和為奇數的子陣列。** `total` 是奇數，走 `else`，讀取 `even = 1`。用 `1` 減去空前綴 `P[0] = 0`，得到 `[1]` 的總和 `1`。
2. **累計變成 `1`。** `subarrays` 從 `0` 加上本輪找到的 `1` 個子陣列，得到 `0 + 1 = 1`。
3. **登記後 `(even, odd) = (1, 1)`。** `P[1] = 1` 是奇數，執行 `odd++`，讓 `odd` 從 `0` 變成 `1`。

#### 第 2 輪｜讀到 `3`，`total = 1 + 3 = 4`

1. **本輪找到 `1` 個總和為奇數的子陣列。** `total` 是偶數，走 `if`，讀取 `odd = 1`。唯一的奇數前綴是 `P[1] = 1`。從 `[1, 3]` 的總和 `4` 扣掉開頭的 `1`，得到 `4 - 1 = 3`，對應子陣列 `[3]`。
2. **累計變成 `2`。** 上一輪找到 `[1]`，這一輪找到 `[3]`，所以 `subarrays = 1 + 1 = 2`。
3. **登記後 `(even, odd) = (2, 1)`。** `P[2] = 4` 是偶數，執行 `even++`。現在兩個偶數前綴是 `P[0] = 0` 和 `P[2] = 4`。

這一輪的 `subarrays = 2` 記錄累計找到的兩個奇數和子陣列，`even = 2` 記錄的是兩個偶數前綴。

#### 第 3 輪｜讀到 `5`，`total = 4 + 5 = 9`

1. **本輪找到 `2` 個總和為奇數的子陣列。** `total` 是奇數，走 `else`，讀取 `even = 2`。減去 `P[0] = 0`，得到 `9 - 0 = 9`，對應 `[1, 3, 5]`。減去 `P[2] = 4`，得到 `9 - 4 = 5`，對應 `[5]`。
2. **累計變成 `4`。** 前兩輪共找到 `2` 個，本輪再加 `2` 個，所以 `subarrays = 2 + 2 = 4`。
3. **登記後 `(even, odd) = (2, 2)`。** `P[3] = 9` 是奇數，執行 `odd++`，讓 `odd` 從 `1` 變成 `2`。

### 取模與複雜度

每次更新 `subarrays` 都對 `MODULO = 1_000_000_007` 取模。依照 `(a + b) % M = ((a % M) + b) % M`，每輪保留餘數和最後一次取模會得到相同的結果。前綴和 `total` 最大為 `10,000,000`，而 `subarrays` 每輪取模前最多是上一輪的餘數 `1,000,000,006` 加上 `100,000`，兩者都在 `int` 範圍內。迴圈結束時，`return subarrays % MODULO` 再取一次模會得到相同的餘數。

掃描一次，時間複雜度為 `O(n)`。只維護前綴和、兩個計數器與答案，額外空間複雜度為 `O(1)`。

## 解法二｜建立前綴奇偶陣列，再查表配對

`NumOfSubarrays2` 把同一個配對規則拆成兩趟。第一趟建立 `prefixParity`，第二趟只處理 `0` 和 `1`。

### 第一趟｜記錄每個前綴的奇偶性

建立長度為 `arr.Length + 1` 的陣列，用 `0` 表示偶數、`1` 表示奇數。`prefixParity[0]` 代表空前綴，初值為 `0`。每讀到一個元素，就用 `(prefixParity[i] + arr[i]) % 2` 得到下一個前綴的奇偶性。前一個前綴除以 `2` 的餘數已保留它的奇偶性，因此可以直接用這個餘數加上新元素。

```text
prefix index    0                  1                  2                  3
parity          0  -- +1, %2 -->   1  -- +3, %2 -->   0  -- +5, %2 -->   1

prefixParity = [0, 1, 0, 1]
```

### 第二趟｜數出奇偶性相反的先前前綴

`counts[0]` 與 `counts[1]` 分別記錄已掃過的偶數、奇數前綴數量。掃描從 `prefixParity[0]` 開始，所以兩格一開始都為 `0`。處理空前綴時會把它登記到 `counts[0]`，供後續前綴配對。

對於目前的 `parity`，`parity ^ 1` 會翻轉最低位元，使 `0` 變成 `1`、`1` 變成 `0`。先把 `counts[parity ^ 1]` 加到答案，然後增加 `counts[parity]`。

```text
k  parity  before(counts[0],counts[1])  lookup     added  after(counts[0],counts[1])  answer
0       0  (0,0)                       counts[1]      0  (1,0)                           0
1       1  (1,0)                       counts[0]      1  (1,1)                           1
2       0  (1,1)                       counts[1]      1  (2,1)                           2
3       1  (2,1)                       counts[0]      2  (2,2)                           4
```

在最後一列，`prefixParity[3] = 1`，查出的兩個偶數前綴來自索引 `0` 和 `2`。它們與目前前綴的索引 `3` 配對，形成 `[0, 2]` 和 `[2, 2]`。之前兩列已各計入一段，因此最後得到 `4`。

這個解法用 `long` 保存取模前的完整個數。例如 100,000 個 `1` 共有 50,001 個偶數前綴與 50,000 個奇數前綴，每組異奇偶前綴依索引先後對應一段區間。乘積是 `2,500,050,000`，超過 `int` 上限，取模後為 `500,049,986`。

建立陣列和查表各掃描一次，時間複雜度為 `O(n)`。由於保存了 `n + 1` 個前綴的奇偶性，額外空間複雜度為 `O(n)`。
