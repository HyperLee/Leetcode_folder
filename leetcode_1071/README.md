## 題目說明

對字串 `s` 與 `t`，若 `s` 可以由 `t` 重複拼接一次或多次而成，就稱 `t` 能整除
`s`。例如：

```text
"AB" 能整除 "ABABAB"，因為 "ABABAB" = "AB" + "AB" + "AB"
"ABA" 不能整除 "ABABAB"
```

給定兩個字串 `str1` 與 `str2`，找出最長字串 `x`，使 `x` 能同時整除這兩個
字串；若不存在共同因子字串，就回傳空字串。

### 官方範例一

```text
輸入：str1 = "ABCABC", str2 = "ABC"
輸出："ABC"
```

`"ABCABC"` 是兩個 `"ABC"`，而 `"ABC"` 本身是一個 `"ABC"`，所以最長
共同因子字串是 `"ABC"`。

### 官方範例二

```text
輸入：str1 = "ABABAB", str2 = "ABAB"
輸出："AB"
```

兩個輸入都能由 `"AB"` 重複組成，因此答案是 `"AB"`。

### 官方範例三

```text
輸入：str1 = "LEET", str2 = "CODE"
輸出：""
```

兩個字串沒有共同的重複週期，因此不存在共同因子字串。

## 限制條件

依 [LeetCode 1071 官方題面](https://leetcode.com/problems/greatest-common-divisor-of-strings/description/)：

- `1 <= str1.length, str2.length <= 1000`
- `str1` 與 `str2` 只包含大寫英文字母

三個公開解法均依循正式題目契約：輸入字串非 `null`、非空且符合上述限制。
字串在 C# 中不可變，因此所有解法都不會修改輸入。

## 解題概念與出發點

### 1. 共同因子一定是共同前綴

若 `x` 能整除 `str1`，`str1` 的開頭必然就是 `x`。同理，`x` 也必須是
`str2` 的前綴。因此不需要搜尋任意子字串，只需檢查前綴。

### 2. 候選長度必須同時整除兩個字串長度

假設 `str1` 由 `x` 重複 `p` 次、`str2` 由 `x` 重複 `q` 次：

```text
str1.Length = x.Length * p
str2.Length = x.Length * q
```

因此 `x.Length` 必須同時是兩個字串長度的因數。最長候選的長度不會超過：

```text
gcd(str1.Length, str2.Length)
```

### 3. 長度相容不代表內容相容

`"AAAAAB"` 與 `"AAA"` 的長度分別為 6 與 3，最大公因數是 3，但長度為 3 的
前綴 `"AAA"` 無法重複組成 `"AAAAAB"`。因此除了長度條件，仍須驗證字元週期。

## 解法一：長度 GCD 與重複拼接驗證

### 設計說明

`GcdOfStrings` 保留原有解題方向：

1. 使用歐幾里得算法計算兩個輸入長度的最大公因數 `gcdLength`。
2. 從 `str1` 擷取長度為 `gcdLength` 的前綴作為 `candidate`。
3. 將 `candidate` 重複適當次數，分別確認能否完整組成 `str1` 與 `str2`。
4. 兩次驗證都成功時回傳 `candidate`，否則回傳空字串。

`IsDivisor` 使用 `StringBuilder` 建立重複字串，讓「字串因子」的定義直接反映在
程式流程中，適合初次理解題意。

### 正確性說明

任何共同因子字串的長度都必須同時整除兩個輸入長度，因此最長共同因子的長度
若存在，必定是兩個長度的最大公因數。演算法取出該長度的共同前綴候選，再驗證
它是否真的能重複組成兩個輸入；驗證成功時它就是最長答案，失敗時也不可能存在
較短的共同週期，因為若兩字串共享較短週期，最大公因數長度的前綴也會由該週期
重複組成並通過驗證。

### 複雜度

- 時間複雜度：`O(m + n)`，其中 `m`、`n` 是兩個字串長度。
- 額外空間複雜度：`O(m + n)`，用於建立兩次驗證字串。
- 是否修改輸入：否。

### 範例演示流程

以 `str1 = "ABABAB"`、`str2 = "ABAB"` 為例：

```text
len1 = 6
len2 = 4
gcd(6, 4):
    6 % 4 = 2
    4 % 2 = 0
gcdLength = 2
candidate = str1[0..2] = "AB"
```

接著驗證候選：

```text
"AB" 重複 3 次 = "ABABAB" = str1  → 通過
"AB" 重複 2 次 = "ABAB"   = str2  → 通過
```

兩個輸入都能被 `"AB"` 整除，因此回傳 `"AB"`。

## 解法二：拼接交換律與長度 GCD

### 設計說明

`GcdOfStrings2` 利用一個更精簡的週期判斷：

```text
str1 + str2 == str2 + str1
```

若兩字串都由同一個基本週期重複組成，無論先拼接哪一個，結果都會是相同週期的
連續排列。反之，交換順序後內容不同，就代表兩者不可能共享共同因子字串。

流程如下：

1. 比較 `str1 + str2` 與 `str2 + str1`。
2. 若不相等，立即回傳空字串。
3. 若相等，計算兩個長度的最大公因數。
4. 回傳 `str1` 中對應該長度的前綴。

### 正確性說明

拼接結果相等表示兩字串的字元排列可對齊為同一個週期序列，因此存在共同的基本
週期。所有能同時整除兩字串的週期長度，必須是兩個長度的共同因數；選擇最大
公因數長度，就會得到最長共同因子字串。若拼接結果不同，兩字串連週期來源都不
相容，答案必為空字串。

### 複雜度

- 時間複雜度：`O(m + n)`，主要成本是建立與比較兩個拼接結果。
- 額外空間複雜度：`O(m + n)`，用於拼接字串。
- 是否修改輸入：否。

### 範例演示流程

同樣使用 `"ABABAB"` 與 `"ABAB"`：

```text
str1 + str2 = "ABABABABAB"
str2 + str1 = "ABABABABAB"
兩者相等，代表週期相容

gcd(6, 4) = 2
str1 的前 2 個字元 = "AB"
回傳 "AB"
```

若輸入改成 `"LEET"` 與 `"CODE"`：

```text
"LEETCODE" != "CODELEET"
```

週期不相容，因此直接回傳空字串。

## 解法三：由長到短枚舉候選前綴

### 設計說明

`GcdOfStrings3` 採用容易直觀驗證的枚舉策略：

1. 從 `min(str1.Length, str2.Length)` 開始，逐一縮短候選長度。
2. 若候選長度不能同時整除兩個輸入長度，直接略過。
3. 取 `str1` 的同長度前綴作為候選。
4. 使用 `IsDivisor` 驗證候選是否能重複組成兩個輸入。
5. 因為長度由大到小檢查，第一個通過的候選就是最長答案。

這種寫法不依賴拼接交換律的數學觀察，代價是最壞情況需要測試較多候選，適合用來
對照「直接枚舉」與「利用數學性質縮小搜尋範圍」的差異。

### 正確性說明

任何合法答案都必須是 `str1` 的前綴，且其長度必須同時整除兩個輸入長度。演算法
由最大可能長度開始，檢查所有符合必要長度條件的前綴，並用完整重複拼接確認充分
條件。因此不會漏掉合法答案；第一個通過驗證的候選也必然是最長答案。

### 複雜度

- 最壞時間複雜度：`O(min(m, n) * (m + n))`。
- 額外空間複雜度：`O(m + n)`，用於候選驗證時建立重複字串。
- 是否修改輸入：否。

### 範例演示流程

對 `str1 = "ABABAB"`、`str2 = "ABAB"`，最大候選長度為 4：

| 候選長度 | 能整除 6？ | 能整除 4？ | 處理結果 |
|---:|:---:|:---:|:---|
| 4 | 否 | 是 | 略過 |
| 3 | 是 | 否 | 略過 |
| 2 | 是 | 是 | 候選為 `"AB"`，繼續驗證 |

`"AB"` 可分別重複 3 次與 2 次組成兩個輸入，所以立即回傳 `"AB"`，不必再
檢查長度 1。

## 三種解法比較

| 項目 | 解法一：GCD + 重複驗證 | 解法二：拼接交換律 + GCD | 解法三：枚舉前綴 |
|:---|:---|:---|:---|
| 核心判斷 | 最大長度候選能否重複組成輸入 | 交換拼接順序是否相等 | 逐一驗證合法長度的前綴 |
| 時間複雜度 | `O(m + n)` | `O(m + n)` | 最壞 `O(min(m,n) * (m+n))` |
| 額外空間 | `O(m + n)` | `O(m + n)` | `O(m + n)` |
| 是否修改輸入 | 否 | 否 | 否 |
| 優點 | 直接對應題目對「整除」的定義 | 程式最精簡、數學性質明確 | 思路直觀，不需先推導交換律 |
| 取捨 | 需要實際建立重複字串 | 交換律的原因需要額外說明 | 最壞情況檢查次數較多 |

若以正式提交為目標，解法二最簡潔；解法一最貼近題目定義；解法三則適合展示尚未
發現數學捷徑時，如何運用必要條件安全地剪枝。
