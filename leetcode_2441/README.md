## 題目說明

給定一個不含 `0` 的整數陣列 `nums`，找出最大的正整數 `k`，使得 `k` 與 `-k` 都存在於陣列中。

- 若存在一組以上的有效配對，回傳其中最大的正整數 `k`。
- 若找不到任何有效配對，回傳 `-1`。

例如：

```text
nums = [-1, 10, 6, 7, -7, 1]
```

陣列中同時存在 `1` 與 `-1`，也同時存在 `7` 與 `-7`。因為 `7 > 1`，所以答案是 `7`。

題目連結：

- [LeetCode](https://leetcode.com/problems/largest-positive-integer-that-exists-with-its-negative/)
- [LeetCode 中文站](https://leetcode.cn/problems/largest-positive-integer-that-exists-with-its-negative/)

## 限制條件

- `1 <= nums.length <= 1000`
- `-1000 <= nums[i] <= 1000`
- `nums[i] != 0`

題目沒有規定元素必須互不相同，因此實作也必須能正確處理重複值。因為陣列不含 `0`，不會出現把 `0` 與自己視為正負配對的問題。

## 解題概念與出發點

每個候選答案都必須滿足兩個條件：

1. `k` 是正整數。
2. `k` 與 `-k` 同時存在。

問題的核心因此不是單純找最大值，而是有效率地回答「某個數的相反數是否存在」。本專案從兩種不同方向處理這個查找需求：

- `FindMaxK` 先排序，使數值具備順序，再從陣列兩端用雙指針排除不可能形成配對的值。
- `FindMaxK2` 用 `HashSet<int>` 記錄已掃描的數值，讓相反數查找在平均情況下可於常數時間完成。

兩種解法的輸出相同，但對輸入資料與額外空間的影響不同。排序法會原地改變陣列順序；雜湊集合法則保留原始輸入。

## 解法一：排序＋雙指針

### 設計說明

`FindMaxK` 先使用 `Array.Sort(nums)` 將陣列由小到大排列，接著建立：

- `left`：指向目前最小、較偏負數的一端。
- `right`：指向目前最大、較偏正數的一端。

對於目前兩端的值，計算：

```text
sum = nums[left] + nums[right]
```

依 `sum` 的正負決定下一步：

1. `sum == 0`
   - 兩個值互為相反數。
   - `right` 從全陣列最大值開始，只會向較小的方向移動，因此第一組找到的配對就是最大答案。
2. `sum > 0`
   - 右側正數相對太大。
   - 將 `right` 向左移，嘗試較小的正數。
3. `sum < 0`
   - 左側負數的絕對值相對太大。
   - 將 `left` 向右移，嘗試絕對值較小的負數。

當兩個指針相遇仍未找到配對，代表答案不存在，回傳 `-1`。

> [!IMPORTANT]
> `Array.Sort(nums)` 會直接修改傳入陣列。範例執行器在呼叫每種解法前都建立獨立複本，避免排序結果影響另一種解法或顯示內容。

### 正確性理由

排序後，左側數值只會隨 `left` 右移而變大，右側數值只會隨 `right` 左移而變小：

- 當總和大於零時，固定目前的右值並改用更大的左值，只會讓總和更大，不可能得到零；因此必須縮小右值。
- 當總和小於零時，固定目前的左值並改用更小的右值，只會讓總和更小，不可能得到零；因此必須增大左值。
- 每次移動都安全排除一個不可能與目前另一端形成答案的值，不會漏掉有效配對。
- `right` 由最大值開始遞減，所以第一次得到零和時，其正值一定是尚未排除候選中的最大者。

### 複雜度

- 時間複雜度：`O(n log n)`，排序為主要成本；雙指針掃描為 `O(n)`。
- 額外空間複雜度：一般以 `O(log n)` 表示排序所需的呼叫堆疊；雙指針本身只使用 `O(1)` 變數。
- 輸入副作用：會將 `nums` 原地排序。

### 範例演示流程

以 `nums = [-1, 10, 6, 7, -7, 1]` 為例。

排序後：

```text
[-7, -1, 1, 6, 7, 10]
  L                  R
```

| 步驟 | `nums[left]` | `nums[right]` | 總和 | 判斷與動作 |
| ---: | ---: | ---: | ---: | --- |
| 1 | -7 | 10 | 3 | 總和大於零，`right` 左移 |
| 2 | -7 | 7 | 0 | 找到相反數配對，回傳 `7` |

雖然陣列中也有 `-1` 與 `1`，但從右側最大值開始搜尋使演算法先找到較大的有效答案 `7`。

### 無解流程

以排序後的 `[-10, -3, -2, 6, 7, 8]` 為例：

1. `-10 + 8 < 0`，`left` 右移。
2. `-3 + 8 > 0`，`right` 左移。
3. 依相同規則持續縮小範圍。
4. 指針相遇前沒有任何總和為零的組合，因此回傳 `-1`。

## 解法二：雜湊集合

### 設計說明

`FindMaxK2` 使用 `HashSet<int> seen` 保存已掃描過的數值，並以 `ans = -1` 表示目前尚未找到有效配對。

對每個元素 `x` 執行：

1. 查詢 `seen` 是否包含 `-x`。
2. 若包含，代表 `x` 與先前元素形成相反數配對。
3. 使用 `Math.Abs(x)` 取得該配對的正整數。
4. 以 `Math.Max(ans, Math.Abs(x))` 保留目前最大答案。
5. 將 `x` 加入 `seen`，供後續元素查詢。

檢查相反數後才加入目前元素，可以清楚表達「目前值與先前看過的值形成配對」。正數或負數先出現都不影響正確性：較晚出現的一方一定能在集合中找到另一方。

### 正確性理由

掃描到任意元素 `x` 時，`seen` 恰好包含它之前的所有元素：

- 若 `seen.Contains(-x)` 為真，陣列中已確定同時存在 `x` 與 `-x`，所以 `Math.Abs(x)` 是有效候選答案。
- 若查詢為假，目前還不能形成配對；把 `x` 加入集合後，未來遇到 `-x` 時便能辨識這組配對。
- 每組實際存在的相反數至少會在較晚出現的一方被檢查到。
- `ans` 每次都取最大值，因此掃描結束後保存所有有效候選中的最大者。

### 複雜度

- 時間複雜度：平均為 `O(n)`，每個元素執行一次集合查詢與加入。
- 額外空間複雜度：`O(n)`，最壞情況集合保存所有不同元素。
- 輸入副作用：不修改 `nums` 的內容或順序。

### 範例演示流程

仍以 `nums = [-1, 10, 6, 7, -7, 1]` 為例：

| 讀取 `x` | 查詢 `-x` | 是否存在 | 更新後 `ans` | 加入集合後的重點內容 |
| ---: | ---: | --- | ---: | --- |
| -1 | 1 | 否 | -1 | `{-1}` |
| 10 | -10 | 否 | -1 | `{-1, 10}` |
| 6 | -6 | 否 | -1 | 加入 `6` |
| 7 | -7 | 否 | -1 | 加入 `7` |
| -7 | 7 | 是 | 7 | 找到 `7/-7` |
| 1 | -1 | 是 | 7 | 找到 `1/-1`，但不大於 7 |

掃描完成後回傳 `7`。

### 重複值流程

對 `[-1, 1, -1]`：

1. 第一個 `-1` 加入集合。
2. 遇到 `1` 時找到 `-1`，將答案更新為 `1`。
3. 最後一個 `-1` 再次找到 `1`，答案仍為 `1`。

`HashSet` 會忽略重複加入的相同值，而最大答案不受影響。

## 兩種解法比較

| 比較項目 | 排序＋雙指針 | 雜湊集合 |
| --- | --- | --- |
| 公開方法 | `FindMaxK` | `FindMaxK2` |
| 核心工具 | `Array.Sort`、左右指針 | `HashSet<int>` |
| 時間複雜度 | `O(n log n)` | 平均 `O(n)` |
| 額外空間 | 一般為 `O(log n)` | `O(n)` |
| 是否修改輸入 | 是，原地排序 | 否 |
| 最大值取得方式 | 從最大右端開始，首個配對即答案 | 掃描所有配對並持續更新最大值 |
| 優點 | 指針規則直觀，不需保存所有元素 | 平均執行時間較佳，保留輸入順序 |
| 取捨 | 排序成本且會改變輸入 | 需要額外集合空間 |

若允許修改輸入並希望練習排序後的區間排除，可使用 `FindMaxK`；若希望維持輸入內容並追求平均線性時間，`FindMaxK2` 較合適。
