# LeetCode 1002：查找共用字元

[![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4?logo=dotnet)](https://dotnet.microsoft.com/)

這是一個使用 C# 與 .NET 10 撰寫的可執行教學專案。程式以三種不同思路解答
「查找共用字元」，並用六組固定案例同時驗證三種方法，共執行 18 項檢查。

- 題目：[Find Common Characters](https://leetcode.com/problems/find-common-characters/)
- 專案：`leetcode_1002/leetcode_1002.csproj`
- 目標框架：`.NET 10`
- 驗證方式：console 固定案例與 PASS/FAIL 結果

## 題目說明

給定一個字串陣列 `words`，請找出在每一個字串中都出現的字元。若某個字元在
所有字串中都重複出現，答案也必須保留可共同使用的重複次數。

答案可以採任意順序回傳。

### 官方範例一

```text
輸入：words = ["bella", "label", "roller"]
輸出：["e", "l", "l"]
```

- `e` 在三個字串中都至少出現一次。
- `l` 在三個字串中都至少出現兩次，因此答案包含兩個 `"l"`。
- 其他字元至少缺席於一個字串，所以不能放進答案。

### 官方範例二

```text
輸入：words = ["cool", "lock", "cook"]
輸出：["c", "o"]
```

`c` 與 `o` 都在三個字串中出現；雖然部分字串有兩個 `o`，但 `"lock"` 只有
一個 `o`，所以答案只能保留一個。

### 限制條件

- `1 <= words.Length <= 100`
- `1 <= words[i].Length <= 100`
- `words[i]` 只包含小寫英文字母

本專案的三種解法都以題目保證的合法輸入為前提，不額外處理 `null`、空陣列、
空字串或其他字元。

## 解題概念與出發點

### 共同字元其實是「出現次數的交集」

只判斷「字元是否出現」並不足以解題，因為答案必須保留重複字元。對任一字元
`x`，它能出現在答案中的次數，等於 `x` 在所有字串中的最少出現次數：

```text
答案中 x 的次數 = min(x 在 word1 的次數, x 在 word2 的次數, ...)
```

例如：

```text
words = ["aaab", "aab", "aaa"]

"aaab" 中 a 出現 3 次
"aab"  中 a 出現 2 次
"aaa"  中 a 出現 3 次

共同次數 = min(3, 2, 3) = 2
答案 = ["a", "a"]
```

三種方法都在求同一個「多重集合交集」，差別只在於如何表示頻率或候選項目：

| 解法 | 核心資料結構 | 主要特色 |
| --- | --- | --- |
| 固定長度計數陣列 | 兩個長度 26 的 `int[]` | 最直接利用小寫英文字母限制，效率穩定 |
| Dictionary 頻率交集 | `Dictionary<char, int>` | 只保存實際出現的字元，較容易泛化 |
| 候選清單逐字移除 | `List<char>` | 不直接計算最小值，透過實際配對理解多重集合 |

## 解法一：固定長度計數陣列

對應方法：

```csharp
public static IList<string> CommonChars(string[] words)
```

### 設計出發點

題目保證字串只包含 `'a'` 到 `'z'`，因此可以使用長度固定為 26 的陣列，讓：

```text
索引 0 代表 a
索引 1 代表 b
...
索引 25 代表 z
```

`character - 'a'` 可以把字元直接轉成對應索引，不需要雜湊查找。

### 設計步驟

1. 建立 `minimumFrequencies[26]`。
2. 將每個位置初始化為 `int.MaxValue`，表示尚未遇到任何字串。
3. 對每一個 `word` 建立新的 `currentFrequencies[26]`。
4. 統計目前字串每個字母的出現次數。
5. 對 26 個位置分別計算：

   ```text
   minimumFrequencies[i] =
       min(minimumFrequencies[i], currentFrequencies[i])
   ```

6. 所有字串處理完後，依 `minimumFrequencies[i]` 的數量，把對應字母加入答案。

如果某個字元未出現在任一字串中，該字串的計數是 0，最小值也會成為 0，因此
該字元不會被加入答案。

### 範例演示

以 `["bella", "label", "roller"]` 為例，只列出可能成為答案的 `e` 與 `l`：

| 處理階段 | `e` 的目前次數 | `l` 的目前次數 | `e` 的最小值 | `l` 的最小值 |
| --- | ---: | ---: | ---: | ---: |
| `bella` | 1 | 2 | 1 | 2 |
| `label` | 1 | 2 | 1 | 2 |
| `roller` | 1 | 2 | 1 | 2 |

最後：

```text
e 的最小次數 = 1 → 加入一個 "e"
l 的最小次數 = 2 → 加入兩個 "l"

答案 = ["e", "l", "l"]
```

### 正確性說明

處理完前 `k` 個字串後，`minimumFrequencies[i]` 保存字母 `i` 在這 `k` 個字串
中的最少出現次數。加入下一個字串時，再與該字串的頻率取較小值，因此此性質
會繼續成立。

處理完所有字串後，每個位置就是對應字母能同時從所有字串取出的最大數量。
依該數量建立答案，既不會加入任何缺少的字元，也不會超過任一字串可提供的
重複次數。

### 複雜度

令：

- `T` 為所有字串的字元總數
- `n` 為字串數量
- `R` 為回傳答案長度

| 項目 | 複雜度 | 原因 |
| --- | --- | --- |
| 時間 | `O(T + 26n + R)` | 統計全部字元、每個字串更新 26 格、建立答案 |
| 輔助空間 | `O(26)` | 最小頻率與目前頻率陣列都是固定大小 |
| 回傳空間 | `O(R)` | 保存最後的共同字元 |

### 優缺點

優點：

- 充分利用題目只有 26 個小寫英文字母的限制。
- 不需要字典查找，時間與空間都容易估算。
- 結果自然按照 `a` 到 `z` 的順序建立。

缺點：

- 實作直接綁定 `'a'` 到 `'z'`。
- 若輸入字元集合擴充到 Unicode 或無法預知的符號，就需要更換資料結構。

## 解法二：Dictionary 頻率交集

對應方法：

```csharp
public static IList<string> CommonCharsWithDictionary(string[] words)
```

### 設計出發點

固定陣列為所有可能字母保留位置；Dictionary 則只保存實際出現的字元。先把
第一個字串的頻率當作候選答案，再逐一與後續字串的頻率取交集：

- 後續字串缺少某個候選字元：從候選 Dictionary 移除。
- 後續字串具有該字元：把候選次數更新為兩者的較小值。

### 設計步驟

1. 使用 `CountCharacters(words[0])` 統計第一個字串。
2. 對每個後續字串建立 `currentFrequencies`。
3. 複製候選 Dictionary 的鍵後逐一檢查：
   - `TryGetValue` 失敗時，移除候選字元。
   - 找到字元時，保存候選次數與目前次數的較小值。
4. 依最後 Dictionary 中保存的次數建立答案。

遍歷時使用 `minimumFrequencies.Keys.ToArray()`，是因為 Dictionary 不能在直接
列舉 `Keys` 的同時移除元素。先建立鍵的快照，就能安全縮小候選集合。

### 範例演示

以 `["cool", "lock", "cook"]` 為例：

第一個字串 `"cool"`：

```text
候選頻率 = { c: 1, o: 2, l: 1 }
```

與 `"lock"` 的 `{ l: 1, o: 1, c: 1, k: 1 }` 取交集：

```text
c → min(1, 1) = 1
o → min(2, 1) = 1
l → min(1, 1) = 1

候選頻率 = { c: 1, o: 1, l: 1 }
```

與 `"cook"` 的 `{ c: 1, o: 2, k: 1 }` 取交集：

```text
c → min(1, 1) = 1
o → min(1, 2) = 1
l → "cook" 中不存在，移除

候選頻率 = { c: 1, o: 1 }
答案 = ["c", "o"]
```

### 正確性說明

第一個字串的頻率表包含所有可能成為共同字元的候選。每處理一個新字串：

- 缺少的候選被移除，因為它不可能存在於所有字串。
- 仍存在的候選只保留較小次數，因此不會超過目前任何已處理字串的可用次數。

全部處理完成後，Dictionary 正好保存每個共同字元在所有字串中的最少頻率。

### 複雜度

令 `u` 為任一輸入字串中的最大不同字元數；本題最多為 26：

| 項目 | 平均複雜度 | 原因 |
| --- | --- | --- |
| 時間 | `O(T + un + R)` | 統計頻率、逐字串檢查候選鍵、建立答案 |
| 輔助空間 | `O(u)` | 候選表、目前頻率表與鍵快照 |
| 回傳空間 | `O(R)` | 保存最後的共同字元 |

Dictionary 操作的時間複雜度採一般情況下的平均 `O(1)` 估算。

### 優缺點

優點：

- 只保存實際出現的字元。
- 不需要依賴 `character - 'a'` 的索引換算。
- 若未來放寬字元種類，核心交集概念較容易沿用。

缺點：

- Dictionary 與鍵快照會帶來額外配置及雜湊成本。
- 本題字元集合固定且很小，因此通常不會比固定陣列更精簡。
- Dictionary 的列舉順序不應視為題目答案契約。

## 解法三：候選清單逐字移除

對應方法：

```csharp
public static IList<string> CommonCharsWithCandidateList(string[] words)
```

### 設計出發點

這個方法不另外保存「某字元出現幾次」，而是把第一個字串的每一個字元都當成
獨立候選。處理下一個字串時，每個候選都必須找到一個尚未使用的相同字元：

- 找到：移除該可用字元，防止它被重複配對。
- 找不到：從候選清單移除該候選。

候選清單最後剩下的內容，就是每個字串都能各自提供一次配對的共同字元。

### 設計步驟

1. 將第一個字串轉成 `candidates`。
2. 對每個後續字串建立獨立的 `availableCharacters`。
3. 從候選清單尾端往前遍歷：
   - 使用 `IndexOf` 尋找相同的可用字元。
   - 找到時從 `availableCharacters` 移除該位置。
   - 找不到時從 `candidates` 移除目前候選。
4. 將剩餘 `char` 逐一轉成 `string` 後回傳。

由尾端往前檢查候選，是為了在移除元素後不影響尚未處理的索引。

### 範例演示

以 `["aaab", "aab", "aaa"]` 為例：

初始候選來自 `"aaab"`：

```text
candidates = [a, a, a, b]
```

處理 `"aab"`，每次成功配對都消耗一個可用字元：

| 候選 | 是否找到可用字元 | 結果 |
| --- | --- | --- |
| `b` | 找到 | 保留 `b`，消耗 `"aab"` 中的 `b` |
| 第三個 `a` | 找到 | 保留，消耗一個 `a` |
| 第二個 `a` | 找到 | 保留，消耗一個 `a` |
| 第一個 `a` | 找不到 | 從候選移除 |

```text
candidates = [a, a, b]
```

處理 `"aaa"`：

| 候選 | 是否找到可用字元 | 結果 |
| --- | --- | --- |
| `b` | 找不到 | 移除 |
| `a` | 找到 | 保留並消耗一個 `a` |
| `a` | 找到 | 保留並消耗一個 `a` |

```text
candidates = [a, a]
答案 = ["a", "a"]
```

### 正確性說明

處理完任一字串後，每個仍存在的候選都已在每個處理過的字串中取得一對一配對。
成功配對後立即移除可用字元，所以同一個字元位置不可能支援兩個候選，重複次數
不會被高估。

若候選無法在目前字串配對，它就不可能是所有字串的共同字元，因此移除是安全
的。處理完所有字串後，剩餘候選恰好是完整的多重集合交集。

### 複雜度

令：

- `n` 為字串數量
- `L` 為單一字串最大長度
- `R` 為回傳答案長度

| 項目 | 複雜度 | 原因 |
| --- | --- | --- |
| 最差時間 | `O(nL² + R)` | `IndexOf` 與 `List.RemoveAt` 都可能線性掃描或搬移 |
| 輔助空間 | `O(L)` | 候選清單與目前字串的可用字元清單 |
| 回傳空間 | `O(R)` | 將剩餘 `char` 轉為字串 |

### 優缺點

優點：

- 「一個候選只能配對一個字元」的概念非常直觀。
- 不需要先理解頻率陣列或 Dictionary。
- 自然保留第一個字串中候選字元的相對順序。

缺點：

- `IndexOf` 與中間移除都是線性操作，效率低於兩種計數方法。
- 較長字串或較多字串時，重複搜尋與搬移成本更明顯。
- 適合教學與小型輸入，不是本題限制下最有效率的選擇。

## 三種解法比較

| 比較項目 | 固定陣列 | Dictionary | 候選清單 |
| --- | --- | --- | --- |
| 核心想法 | 每個字母保存最小頻率 | 逐步縮小候選頻率表 | 逐一建立一對一配對 |
| 最主要限制 | 綁定 26 個小寫字母 | 平均雜湊成本 | 最差平方級字串處理 |
| 輔助空間 | `O(26)` | `O(u)` | `O(L)` |
| 輸入副作用 | 無 | 無 | 無 |
| 教學重點 | 頻率與索引映射 | 多重集合的字典交集 | 重複字元的實際配對 |
| 建議用途 | 本題首選 | 字元集合可能擴充時 | 初學者理解或輸入很小時 |

本題只有 26 個小寫英文字母，因此固定長度計數陣列通常是最合適的實作。
另外兩種方法用來展示相同多重集合問題如何以不同資料結構表達。

## 可執行驗證

`Main` 會用下列六組合法案例執行三種方法：

| 案例 | 輸入 | 預期 | 驗證重點 |
| --- | --- | --- | --- |
| 官方範例一 | `["bella","label","roller"]` | `["e","l","l"]` | 多種共同字元與重複次數 |
| 官方範例二 | `["cool","lock","cook"]` | `["c","o"]` | 某字元只能保留最少次數 |
| 最小合法輸入 | `["a"]` | `["a"]` | 最少字串數與最短字串 |
| 單一字串保留重複字元 | `["aabb"]` | `["a","a","b","b"]` | 只有一個字串時保留全部項目 |
| 沒有共同字元 | `["abc","def"]` | `[]` | 空答案 |
| 以最少出現次數為準 | `["aaab","aab","aaa"]` | `["a","a"]` | 多個重複字元取最小頻率 |

答案驗證採多重集合比較：

- 忽略回傳順序。
- 字元種類必須相同。
- 每個字元的重複次數必須相同。

因此 `["e", "l", "l"]` 與 `["l", "e", "l"]` 視為相同答案，但
`["e", "l"]` 會因少一個 `"l"` 而失敗。
