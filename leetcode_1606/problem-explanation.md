# LeetCode 1606 題目說明：找出處理最多請求的伺服器

本文件只說明題目、輸入輸出、分派規則與範例，不涉及實際解法或程式實作。

這題要你按照指定的分派規則，判斷每個請求交給哪台伺服器，最後回傳「成功接下最多個請求的所有伺服器編號」。

## 1. 伺服器的設定

你有 `k` 台伺服器，編號從 `0` 到 `k - 1`。

例如：

```text
k = 3
伺服器編號：0、1、2
```

每台伺服器在同一時間只能處理一個請求：

- 空閒時，可以接新請求。
- 忙碌時，必須等目前的請求完成，才能接下一個。
- 不同伺服器可以同時處理各自的請求。

題目提到「無限的運算能力」，不代表一台能同時接很多請求；每台仍然一次只能處理一個，而且每個請求需要花費指定的時間。

## 2. 輸入資料代表什麼？

有三個輸入：

| 輸入 | 意義 |
|---|---|
| `k` | 伺服器數量 |
| `arrival` | 每個請求的到達時間 |
| `load` | 每個請求需要的處理時間 |

`arrival[i]` 和 `load[i]` 描述的是同一個請求 `i`，請求編號從 `0` 開始。兩個陣列的長度相同。

例如：

```text
arrival = [1, 2, 3]
load    = [5, 2, 3]
```

| 請求編號 `i` | 到達時間 `arrival[i]` | 所需時間 `load[i]` | 若當下接下，完成時間 |
|---|---:|---:|---:|
| 0 | 1 | 5 | 6 |
| 1 | 2 | 2 | 4 |
| 2 | 3 | 3 | 6 |

例如，請求 `0` 在時間 `1` 到達，需要處理 `5` 個時間單位，所以接下它的伺服器會在時間 `6` 完成。

**時間剛好到 `6` 時，這台伺服器就能接新請求。** 完成時間等於新請求的到達時間時，也算空閒。

另外，`arrival` 嚴格遞增，表示後面的請求一定比較晚到，不會有兩個請求同時到達。

## 3. 每個請求要交給哪台伺服器？

不能自由選擇伺服器，必須遵守題目指定的規則。

### 優先嘗試 `i % k`

對於第 `i` 個請求，先嘗試編號為 `i % k` 的伺服器。`%` 是取餘數。

例如有 `3` 台伺服器：

| 請求編號 `i` | 優先嘗試的伺服器 `i % 3` |
|---|---:|
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| 3 | 0 |
| 4 | 1 |
| 5 | 2 |

這只是優先嘗試的伺服器，不保證最後一定交給它。

### 空閒就接下，忙碌就往後找

如果優先嘗試的伺服器空閒，就直接交給它。

如果它忙碌，就依編號往後找，交給遇到的第一台空閒伺服器。超過最大編號後，要繞回 `0` 繼續找。

例如：

```text
k = 5
這次優先嘗試伺服器 3

嘗試順序：
3 → 4 → 0 → 1 → 2
```

假設：

```text
伺服器 3：忙碌
伺服器 4：忙碌
伺服器 0：空閒
伺服器 1：空閒
```

這個請求就必須交給伺服器 `0`，因為它是依指定順序遇到的第一台空閒伺服器。

### 全部忙碌就丟棄

如果所有伺服器都忙碌，就直接丟棄該請求。

沒有排隊，也不會等哪台伺服器完成後再補做。被丟棄的請求不計入任何伺服器的處理次數。

## 4. 完整範例

輸入：

```text
k       = 3
arrival = [1, 2, 3, 4, 5]
load    = [5, 2, 3, 3, 3]
```

一開始，三台伺服器全部空閒。

| 請求 `i` | 到達時間 | 處理時間 | 優先嘗試 | 實際結果 |
|---|---:|---:|---|---|
| 0 | 1 | 5 | 伺服器 0 | 0 空閒，接下，時間 6 完成 |
| 1 | 2 | 2 | 伺服器 1 | 1 空閒，接下，時間 4 完成 |
| 2 | 3 | 3 | 伺服器 2 | 2 空閒，接下，時間 6 完成 |
| 3 | 4 | 3 | 伺服器 0 | 0 忙碌；往後找到 1，交給 1，時間 7 完成 |
| 4 | 5 | 3 | 伺服器 1 | 三台都忙碌，丟棄 |

其中，請求 `3` 的分派過程是：

```text
到達時間：4
優先嘗試：3 % 3 = 0
```

在時間 `4`：

- 伺服器 `0` 要到時間 `6` 才完成，仍忙碌。
- 伺服器 `1` 剛好在時間 `4` 完成，已經可以接新請求。
- 因此，這個請求交給伺服器 `1`，並在時間 `4 + 3 = 7` 完成。

接著，請求 `4` 在時間 `5` 到達時，三台伺服器分別要到時間 `6`、`7`、`6` 才會空閒，所以這個請求被丟棄。

所有請求分派完後：

| 伺服器 | 成功處理的請求 | 總數 |
|---|---|---:|
| 0 | 請求 0 | 1 |
| 1 | 請求 1、3 | 2 |
| 2 | 請求 2 | 1 |

所以答案是：

```text
[1]
```

意思是：伺服器 `1` 處理的請求數量最多。

## 5. 最後要求回傳什麼？

要回傳的是伺服器編號清單，包含所有處理次數最多的伺服器。

例如：

```text
伺服器 0：處理 4 個
伺服器 1：處理 2 個
伺服器 2：處理 4 個
```

答案就是：

```text
[0, 2]
```

回傳 `[2, 0]` 也可以，因為答案順序不限。回傳的內容是伺服器編號，不是最大處理次數 `4`。

「最忙碌」在這題的定義是處理的請求個數最多，不是處理時間最長。

例如一台處理 `1` 個耗時 `100` 的請求，另一台處理 `3` 個各耗時 `1` 的請求，後者才是這題要找的最忙碌伺服器。

## 6. 容易誤會的地方

- `i` 是原始請求編號，不是到達時間；優先嘗試的是 `i % k`，不是 `arrival[i] % k`。
- 即使某個請求被丟棄，後續請求的編號仍照原本往下算，不會因為丟棄而重新編號。
- 往後找伺服器時，需要在最大編號之後繞回 `0`。
- 有多台空閒伺服器時，必須選指定循環順序中的第一台，不能任意選擇。
- 全部忙碌時，請求直接丟棄，不會等待。
- 完成時間剛好等於新請求到達時間時，伺服器可以立即接新請求。
- 多台伺服器並列最多時，必須全部回傳，順序不限。
