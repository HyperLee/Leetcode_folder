## 題目說明

給定一個包含 `n` 個元素的整數陣列 `nums`，使用下列數字表示三種顏色：

- `0`：紅色
- `1`：白色
- `2`：藍色

請直接在原陣列中排序，讓相同顏色彼此相鄰，並依照紅、白、藍，也就是 `0`、`1`、`2` 的順序排列。

題目不允許呼叫程式庫內建的排序函式。進階要求是使用常數額外空間，並嘗試以一次掃描完成排序。

- [LeetCode 英文題目](https://leetcode.com/problems/sort-colors/)
- [LeetCode 中文題目](https://leetcode.cn/problems/sort-colors/)

### 題目範例

```text
輸入：nums = [2, 0, 2, 1, 1, 0]
輸出：[0, 0, 1, 1, 2, 2]
```

```text
輸入：nums = [2, 0, 1]
輸出：[0, 1, 2]
```

## 限制條件

- `n == nums.Length`
- `1 <= n <= 300`
- `nums[i]` 只能是 `0`、`1` 或 `2`
- 必須修改原陣列，而不是建立並回傳另一個排序結果
- 不可使用 `Array.Sort`、LINQ `OrderBy` 或其他內建排序功能

## 解題概念與出發點

一般排序問題必須處理許多不同數值，但本題只有三種可能值。這項限制帶來三種不同的思考方向：

1. **沿用一般排序觀念**：比較相鄰元素，逐步消除逆序配對，形成氣泡排序。
2. **利用值域固定的特性**：只統計三種顏色各有幾個，再依數量覆寫陣列，形成計數排序。
3. **直接維護三個顏色區段**：掃描時把新遇到的 `0` 或 `1` 放進正確區段，讓 `2` 留在後方，形成一次掃描的指標法。

三種方法都會直接修改傳入的陣列，呼叫端不需要接收回傳值。差別主要在掃描次數、比較或交換成本，以及演算法是否充分利用「只有三種值」這項條件。

## 三種解法比較

| 方法 | 核心策略 | 時間複雜度 | 額外空間 | 掃描特性 |
| --- | --- | --- | --- | --- |
| `SortColors` | 相鄰比較與交換 | 最差 `O(n²)`；已排序時可提前結束 | `O(1)` | 最多執行多輪 |
| `SortColors2` | 計數後覆寫 | `O(n)` | `O(1)`，因為計數陣列固定為 3 格 | 一輪計數，再一輪覆寫 |
| `SortColors3` | 維護 0、1、2 區段 | `O(n)` | `O(1)` | 一次由左至右掃描 |

> [!NOTE]
> `SortColors2` 使用 `int[3]`，雖然確實配置了陣列，但其大小不會隨輸入長度增加，因此漸進空間複雜度仍是 `O(1)`。

## 解法一：氣泡排序

### 設計出發點

氣泡排序不需要利用本題只有三種值的特殊條件。它反覆比較相鄰元素；若左邊大於右邊，就交換兩者。每完成一輪，尚未排序區間中的最大值便會移到該區間最右側。

程式使用 `swap` 記錄本輪是否發生交換：

- 有交換：陣列可能仍存在逆序配對，需要下一輪。
- 沒有交換：所有相鄰元素都已符合遞增順序，可以提前停止。

### 流程

1. 外層迴圈控制排序輪數。
2. 內層迴圈只掃描尚未確定的區間。
3. 發現 `nums[j] > nums[j + 1]` 時交換。
4. 若整輪沒有交換，立即結束。

### 範例演示

輸入為 `[2, 0, 2, 1, 1, 0]`：

| 輪次 | 該輪結束後的陣列 | 已確定的尾端 |
| ---: | --- | --- |
| 初始 | `[2, 0, 2, 1, 1, 0]` | 尚無 |
| 1 | `[0, 2, 1, 1, 0, 2]` | 最後一個 `2` |
| 2 | `[0, 1, 1, 0, 2, 2]` | 最後兩個 `2` |
| 3 | `[0, 1, 0, 1, 2, 2]` | 尾端維持排序 |
| 4 | `[0, 0, 1, 1, 2, 2]` | 排序完成 |
| 5 | 沒有交換，提前結束 | 全部確定 |

### 優缺點與適用情境

- 優點：概念直接、容易從一般排序知識理解、只需要常數額外空間。
- 缺點：最差需要平方級比較，沒有利用值域只有三種的條件。
- 適合：教學、輸入很小，或需要先用熟悉方法建立正確版本的情境。

## 解法二：計數排序

### 設計出發點

因為陣列只可能包含 `0`、`1`、`2`，不必比較元素大小。可以使用固定三格的 `count`：

- `count[0]`：`0` 的數量
- `count[1]`：`1` 的數量
- `count[2]`：`2` 的數量

第一階段用數值本身作為索引完成計數；第二階段依 `0`、`1`、`2` 的順序，把每個數值寫回原陣列。

### 流程

1. 建立 `count = [0, 0, 0]`。
2. 掃描 `nums`，執行 `count[nums[i]]++`。
3. 從 `count[0]` 開始，依數量寫入 `0`。
4. 接著寫入對應數量的 `1` 與 `2`。

### 範例演示

輸入為 `[2, 0, 2, 1, 1, 0]`。

完成計數後：

```text
count[0] = 2
count[1] = 2
count[2] = 2
```

覆寫過程：

| 寫入數值 | 寫入數量 | 已建立的排序前綴 |
| ---: | ---: | --- |
| `0` | 2 | `[0, 0]` |
| `1` | 2 | `[0, 0, 1, 1]` |
| `2` | 2 | `[0, 0, 1, 1, 2, 2]` |

### 優缺點與適用情境

- 優點：流程清楚、時間複雜度穩定為 `O(n)`、不需要元素交換。
- 缺點：需要先完整計數才能覆寫，不符合進階題要求的一次掃描。
- 適合：值域很小且固定，並希望兼顧效率與可讀性的情境。

## 解法三：p0／p1 指標法

### 設計出發點

這個方法在掃描過程中維護已處理區間的排列。進入每一輪時，區間具有以下不變量：

```text
[0, p0)  全部是 0
[p0, p1) 全部是 1
[p1, i)  全部是 2
```

- `p0` 指向下一個 `0` 應放置的位置。
- `p1` 指向下一個 `1` 應放置的位置。
- `i` 是目前正在讀取的索引。

### 三種判斷

#### 遇到 2

`2` 已屬於已處理區間的最後一段，不需要交換，繼續掃描即可。

#### 遇到 1

把目前的 `1` 與 `p1` 交換，讓 `1` 加入中間區段，再將 `p1` 向右移動。

#### 遇到 0

先把目前的 `0` 與 `p0` 交換。若 `p0 < p1`，表示 `p0` 原本位於 `1` 的區段，第一次交換會把一個 `1` 移到索引 `i`；因此還要把該 `1` 與 `p1` 交換，才能恢復三段的不變量。最後同時遞增 `p0` 與 `p1`。

### 範例演示

輸入為 `[2, 0, 2, 1, 1, 0]`。表格中的 `p0`、`p1` 顯示該輪處理前與處理後的位置：

| `i` | 目前值 | `p0` | `p1` | 動作 | 處理後陣列 |
| ---: | ---: | --- | --- | --- | --- |
| 0 | 2 | `0 → 0` | `0 → 0` | `2` 留在後段 | `[2, 0, 2, 1, 1, 0]` |
| 1 | 0 | `0 → 1` | `0 → 1` | 與索引 0 交換 | `[0, 2, 2, 1, 1, 0]` |
| 2 | 2 | `1 → 1` | `1 → 1` | `2` 留在後段 | `[0, 2, 2, 1, 1, 0]` |
| 3 | 1 | `1 → 1` | `1 → 2` | 與索引 1 交換 | `[0, 1, 2, 2, 1, 0]` |
| 4 | 1 | `1 → 1` | `2 → 3` | 與索引 2 交換 | `[0, 1, 1, 2, 2, 0]` |
| 5 | 0 | `1 → 2` | `3 → 4` | 先與索引 1 交換，再把移出的 `1` 與索引 3 交換 | `[0, 0, 1, 1, 2, 2]` |

### 為什麼是一次掃描

索引 `i` 只會由左向右前進，不會返回重新檢查先前元素。每輪最多執行兩次常數時間交換，因此總時間複雜度為 `O(n)`；演算法只使用索引與暫存變數，額外空間為 `O(1)`。

### 優缺點與適用情境

- 優點：符合一次掃描與常數額外空間的進階要求。
- 缺點：遇到 `0` 時的第二次交換較不直觀，必須理解區段不變量。
- 適合：需要最佳漸進時間、希望避免額外資料結構，或練習區間不變量的情境。
