## 題目說明與限制

給定只包含括號和字母的字串 `s`，移除最少數量的無效括號，使字串有效。回傳所有透過最少次數刪除得到的唯一結果，結果順序不限。字母不刪除，也不影響括號配對。

官方限制如下：

- `1 <= s.Length <= 25`
- `s` 只包含小寫英文字母、`'('` 和 `')'`
- `s` 中最多有 20 個括號

題目原文與範例可參考 [LeetCode 301](https://leetcode.com/problems/remove-invalid-parentheses/description/)。

## 有效括號的判準

從左至右掃描時，以 `balance` 記錄尚未配對的左括號數：遇到 `(` 加一，遇到 `)` 減一，遇到字母則不變。字串有效必須同時符合：

1. 每個前綴的 `balance` 都不小於零；否則該前綴有多出的右括號。
2. 掃描結束時 `balance` 等於零；否則仍有未配對的左括號。

這兩個條件也是 `IsValid` 掃描候選字串時採用的判準。

## 解法 1：回溯與剪枝

`RemoveInvalidParentheses` 先算出必須移除的左右括號數，再以 `Helper` 列舉刪除位置，最後由 `IsValid` 驗證候選。這是本專案保留的基準解法。

### 1. 先算出最少要刪除幾個括號

`RemoveInvalidParentheses` 第一次掃描字串，維護 `lremove` 與 `rremove`：

- 遇到 `(`，增加 `lremove`，代表目前多出一個尚未配對的左括號。
- 遇到 `)`，若有未配對的 `(` 就配對並減少 `lremove`；否則增加 `rremove`，代表這個右括號無法配對。
- 掃描結束時，`rremove` 是多出的右括號數，剩餘的 `lremove` 是多出的左括號數。

這兩個數字固定了左右括號各自的最少刪除量，但不指定必須刪除哪些索引。回溯會枚舉符合數量的刪除位置，再由有效性檢查篩選結果；因此能保留不同的最少刪除答案，也不會多刪括號。

以 `s = "()())()"` 為例：

| 索引 | 字元 | `lremove` | `rremove` | 說明 |
| ---: | :---: | ---: | ---: | --- |
| 0 | `(` | 1 | 0 | 一個待配對左括號 |
| 1 | `)` | 0 | 0 | 與左括號配對 |
| 2 | `(` | 1 | 0 | 一個待配對左括號 |
| 3 | `)` | 0 | 0 | 與左括號配對 |
| 4 | `)` | 0 | 1 | 沒有可配對的左括號 |
| 5 | `(` | 1 | 1 | 一個待配對左括號 |
| 6 | `)` | 0 | 1 | 與左括號配對 |

因此只需移除一個右括號：`lremove = 0`、`rremove = 1`。

### 2. 回溯列舉刪除位置

先用 `()())()` 看這三個判斷如何配合：字串多出一個 `)`，因此只需刪除一個右括號。

- **略過重複位置：** 第 4、5 個字元都是相鄰的 `)`，刪除任一個都會得到 `()()()`；同一層只列舉第一個位置，就不會重複搜尋相同結果。
- **剩餘字元足夠：** 若目前還需要刪除 2 個字元，但搜尋位置之後只剩 1 個字元，就不可能完成這個分支，可以直接剪枝。
- **建立刪除分支：** 本例只需刪除 `)`，所以遇到 `)` 且尚有待刪數量時才遞迴；遇到 `(` 時不建立刪除分支。


`Helper(str, start, lremove, rremove)` 以深度優先方式，列舉恰好再刪除 `lremove` 個 `(` 和 `rremove` 個 `)` 的候選字串。`str` 是這一層正在檢查的字串，`start` 是這一層允許開始選擇刪除位置的索引。

每次進入 `Helper`，會先檢查是否已完成指定刪除數量：如果 `lremove` 和 `rremove` 都是 `0`，就呼叫 `IsValid(str)`；有效時加入結果，無效時捨棄，然後直接返回。這時不能再繼續刪除，因為題目要求的是最少刪除數量。

尚有括號要刪除時，才執行 `for (int i = start; i < str.Length; i++)`。每一輪把目前的 `str[i]` 當成「下一個可能刪除的位置」，依照下列順序處理：

1. **略過同層的重複位置：** 若 `i != start` 且 `str[i] == str[i - 1]`，執行 `continue`，跳到下一個索引。這項條件比較任意相鄰字元；若是可刪除的相同括號，刪除連續區段中任一個都會得到相同候選，因此本層只展開從 `start` 起可選的第一個位置。相鄰重複字母也會被條件略過，但字母本來就不會建立刪除分支。這項判斷不會略過不同字元或中間隔著其他字元的位置。
2. **檢查剩餘字元是否足夠：** `str.Length - i` 是從 `i` 到字串結尾、包含目前字元的數量。若 `lremove + rremove` 大於這個數量，即使刪掉剩餘的每個字元也不夠，便以 `return` 結束這一層的迴圈。之後的索引只會更靠右、可用字元更少，所以不必再檢查。
3. **符合條件才建立刪除分支：** 若 `str[i]` 是 `(` 且 `lremove > 0`，就建立移除索引 `i` 的新字串，遞迴時將 `lremove` 減一；若 `str[i]` 是 `)` 且 `rremove > 0`，則建立相同方式的新字串並將 `rremove` 減一。其他情況（例如字母，或該括號種類已不需刪除）不建立分支，這一輪結束後迴圈就會查看下一個索引，等於保留目前字元。

刪除 `str[i]` 時，程式用前綴和後綴組成新字串，原本位於 `i + 1` 的字元會移到新字串的索引 `i`。因此遞迴仍傳入 `start = i`，才能檢查剛移到這裡的字元；若傳入 `i + 1` 就會跳過它。子呼叫返回後，父層的 `str` 並未改動，原本的 `for` 迴圈會繼續遞增 `i`，嘗試其他刪除位置。同一條搜尋路徑會按原字串由左至右的順序選擇後續刪除位置；因為字元會左移，同一個數值索引也可能在下一層遞迴中再次檢查。這可避免以不同順序刪除同一組字元而重複搜尋。

以 `str = "()())()"`、`start = 0`、`lremove = 0`、`rremove = 1` 為例，這一層只會建立刪除右括號的分支：

| `i` | `str[i]` | 這一輪的行為 |
| ---: | :---: | --- |
| 0 | `(` | `lremove` 已是 `0`，不建立刪除分支，迴圈前進。 |
| 1 | `)` | 遞迴刪除索引 1，得到 `(())()`；子呼叫驗證有效並加入結果，返回後父層繼續。 |
| 2 | `(` | `lremove` 已是 `0`，不建立刪除分支，迴圈前進。 |
| 3 | `)` | 遞迴刪除索引 3，得到 `()()()`；子呼叫驗證有效並加入結果，返回後父層繼續。 |
| 4 | `)` | 與前一字元相同，觸發 `continue`；刪除索引 4 和索引 3 的結果相同，因此略過。 |
| 5 | `(` | `lremove` 已是 `0`，不建立刪除分支，迴圈前進。 |
| 6 | `)` | 遞迴刪除索引 6，得到 `()())(`；`IsValid` 發現前綴餘額變成負數，因此捨棄。 |

所以這一層完成後，結果清單新增 `"(())()"` 和 `"()()()"`；索引 4 不會再產生重複結果。

### 3. 檢查候選結果

`IsValid` 逐字掃描候選字串。左括號讓餘額加一，右括號讓餘額減一；若餘額變成負數，立即判定無效。掃描結束時只有餘額等於零才有效。字母不改變餘額。

每次呼叫 `RemoveInvalidParentheses` 都會建立新的結果清單，因此同一個 `Program` 物件可以連續處理多筆輸入，且先前呼叫回傳的清單不會被後續呼叫改動。

## 解法 2：餘額剪枝 DFS

`RemoveInvalidParentheses2` 先算出必須移除的左右括號數，再從左到右決定每個括號要保留或刪除。它不為每條分支建立新候選字串，而是用一個共用的 `StringBuilder path` 暫存目前保留的字元；遞迴返回時再復原路徑。

### 1. 遞迴狀態與最少刪除配額

第一輪掃描維護 `leftRemove` 和 `rightRemove`：每遇到 `(` 就先記一個未配對左括號；遇到 `)` 時，若有未配對的 `(` 就配對，否則記下一個必須刪除的右括號。掃描結束後，兩個數字分別是無法配對的左、右括號數，也就是要達到最少刪除所需的配額。

接著呼叫 `Search(index, leftRemaining, rightRemaining, balance)`。其中 `path` 是 `Search` 外層建立、由遞迴共用並回溯復原的狀態：

| 狀態 | 意義 |
| --- | --- |
| `index` | 下一個要處理的輸入索引；索引以前的字元已決定保留或刪除。 |
| `leftRemaining` | 後續還必須刪除幾個 `(`。 |
| `rightRemaining` | 後續還必須刪除幾個 `)`。 |
| `balance` | `path` 中尚未配對的左括號數；任何已保留前綴都維持非負。 |
| `path` | 到目前為止保留下來的字元，包含不會刪除的字母。 |

`remainingLeft[i]` 和 `remainingRight[i]` 是從索引 `i` 到字串結尾（包含 `i`）還有幾個左右括號，讓搜尋能在展開分支前判斷配額是否仍有可能完成。

### 2. 剪枝與每個字元的選擇

每次進入 `Search`，依序執行兩個可行性檢查：

1. 若 `leftRemaining > remainingLeft[index]` 或 `rightRemaining > remainingRight[index]`，代表後綴中對應種類的括號不夠刪除，直接返回。
2. 若 `balance > remainingRight[index] - rightRemaining`，代表後綴右括號扣掉必須刪除的數量後，剩下可保留的 `)` 仍不足以關閉目前所有未配對的 `(`。未來保留 `(` 只會令餘額更大，因此這條分支也不可能成功。

通過剪枝後才處理 `s[index]`。刪除分支先遞迴到 `index + 1`，只減少對應刪除配額，不改動 `path`；保留分支則把字元附加到 `path`，遞迴返回後用 `path.Length--` 還原：

- `(` 可以在 `leftRemaining > 0` 時選擇刪除；若保留，遞迴的 `balance` 加一。
- `)` 可以在 `rightRemaining > 0` 時選擇刪除；保留前必須確認 `balance > 0`，再將餘額減一。這使不可能修復的「前綴右括號過多」狀態不會進入搜尋。
- 字母沒有刪除分支，必須保留，且不改變 `balance`。

刪除分支還會檢查 `path` 尾端：若 `path[^1]` 已是目前的相同括號，就略過這個等價選擇，避免以相同字元的不同位置形成重複結果。最後的 `HashSet<string>` 再保證回傳內容唯一。

當 `index == s.Length` 時，只有 `leftRemaining == 0`、`rightRemaining == 0` 且 `balance == 0` 才會將 `path.ToString()` 加入結果。配額歸零確保只刪除預先算出的最少數量；餘額歸零確保所有保留的左括號都已配對。

### 3. 以 `"()())()"` 追蹤兩條成功路徑

初始掃描得到 `leftRemove = 0`、`rightRemove = 1`，所以只需刪除一個右括號。下表只列兩條成功路徑；其他分支會被配額／餘額剪枝或重複分支檢查排除。

| 選擇 | `path` 與 `balance` 的主要變化 | 葉節點結果 |
| --- | --- | --- |
| 刪除索引 1 的 `)` | 保留索引 0 的 `(` 後餘額為 1；刪除索引 1；保留索引 2、3、4 後餘額依序為 2、1、0；再保留索引 5、6 後回到 0。 | `(())()` |
| 刪除索引 3 的 `)` | 保留索引 0、1 後餘額回到 0；保留索引 2 後為 1；刪除索引 3；保留索引 4、5、6 後餘額依序為 0、1、0。 | `()()()` |

索引 3 和 4 是相鄰的 `)`。在保留索引 3 的分支中，`path` 尾端已是 `)`，因此刪除索引 4 的等價分支會被略過；若刪除索引 3，則會保留索引 4，仍能得到 `()()()`。這說明略過的是重複的刪除選擇，不會漏掉唯一結果。

**正確性與複雜度：** 初始配額是使括號序列有效所需移除的未配對括號數；搜尋會探索所有符合配額且未被可行性檢查排除的保留／刪除選擇。保留右括號前要求餘額為正，葉節點再要求餘額歸零，因此加入的結果必定有效；每個有效的最少刪除結果都由對應選擇路徑產生。令 `n` 為字串長度、`p` 為括號數、`r` 為結果數，最壞時間為 `O(n × 2ᵖ + r × n)`；不計結果集合，後綴計數、遞迴堆疊與 `StringBuilder` 共需 `O(n)` 空間，結果集合另需 `O(r × n)`。

## 解法 3：BFS 逐層搜尋

`RemoveInvalidParentheses3` 將「刪除一個括號」視為一條搜尋邊，使用廣度優先搜尋（BFS）從原字串開始。與 DFS 沿一條路徑深入到底不同，BFS 先檢查所有零次刪除候選，再檢查所有一次刪除候選，依此類推。

### 1. `currentLevel` 和 `nextLevel` 的用途

- `currentLevel` 是目前刪除次數的所有唯一候選。初始化為 `{ s }`，代表第 0 層。
- 先對 `currentLevel` 的每個字串呼叫 `IsValid`。若 `validResults` 非空，就回傳整份清單；此時不可只回傳第一個有效字串，因為同一層可能還有其他同樣最少刪除的答案。
- 若本層沒有有效字串，建立空的 `nextLevel`。對每個候選逐一嘗試刪除一個括號，把產生的字串加入 `nextLevel`；一層全部處理完後，才令 `currentLevel = nextLevel`。

產生下一層時，只刪除 `(` 或 `)`，字母一律略過。若目前括號與前一字元相同，就不再刪除這個位置：刪除相鄰相同括號中的任一個會得到相同子字串。不同候選也可能產生同一結果，因此 `nextLevel` 使用 `HashSet` 去重。

### 2. 以 `"()())()"` 追蹤層級

第 0 層只有原字串 `()())()`，`IsValid` 發現其中有一個多出的 `)`，所以不回傳並開始產生第 1 層。刪除一個括號可得到例如：

| 刪除位置 | 候選結果 | 第 1 層檢查 |
| --- | --- | --- |
| 索引 1 的 `)` | `(())()` | 有效 |
| 索引 3 的 `)` | `()()()` | 有效 |
| 索引 4 的 `)` | 與索引 3 相鄰且相同，略過這個重複位置 | 不另建候選 |

程式先檢查完第 1 層的所有候選，再回傳這兩個結果，順序不限：`["(())()", "()()()"]`。雖然其餘候選無效，這些有效結果仍會一併保留；也不會再產生第 2 層，因為那會多刪括號。

**正確性與複雜度：** 第 `k` 層的每個候選都由原字串刪除恰好 `k` 個括號得到。BFS 只在找到有效層級時停止，所以該層的 `k` 是最小刪除數；檢查並收集整層有效候選，則能回傳全部最少刪除答案。集合去重只合併相同字串，不會丟失不同結果。令 `n` 為字串長度、`p` 為括號數，最壞時間為 `O(n² × 2ᵖ)`：候選數最多呈指數成長，而每個候選最多嘗試刪除 `O(n)` 個位置、每次建立新字串最多花 `O(n)`。目前層與下一層都可能保存指數個長度 `O(n)` 的字串，因此額外空間為 `O(n × 2ᵖ)`。

## 三種解法比較

令 `n` 為字串長度、`p` 為括號數、`r` 為唯一結果數。下表列出最壞時間與空間上界；解法 1、2 的空間欄將搜尋所需空間和回傳結果分開，解法 3 的候選層級空間包含找到的有效結果層。

| 方法 | 搜尋方式 | 時間複雜度 | 空間複雜度 | 優點與取捨 |
| --- | --- | --- | --- | --- |
| 解法 1：回溯與剪枝 | 先固定左右刪除數，再列舉刪除位置，最後驗證候選 | `O(n² × 2ᵖ)` | 搜尋路徑 `O(n × p)`；結果另需 `O(r × n)` | 狀態簡單、容易看出刪除位置的枚舉；使用 `Substring` 建立中間字串，候選完成後才檢查有效性。 |
| 解法 2：餘額剪枝 DFS | 逐字決定保留或刪除，沿途維護餘額 | `O(n × 2ᵖ + r × n)` | 搜尋輔助空間 `O(n)`；結果另需 `O(r × n)` | `StringBuilder` 共用路徑，剩餘括號數與餘額能提早剪枝；搜尋最壞仍可能呈指數級。 |
| 解法 3：BFS 逐層搜尋 | 依刪除次數逐層產生候選 | `O(n² × 2ᵖ)` | 候選層級 `O(n × 2ᵖ)` | 第一個有效層直接保證刪除次數最少，思路直觀；需保留目前層與下一層候選，記憶體用量可能很高。 |

**推薦解法 2：餘額剪枝 DFS。** 它同時利用最少刪除配額、剩餘括號數與括號餘額排除不可能的分支，並以 `StringBuilder` 共用搜尋路徑；對照解法 1，可避免在每個刪除分支建立候選字串，對照解法 3，也不必保存大量 BFS 層級候選。若教學重點是直接呈現「先少刪、再逐層增加刪除數」的最少性證明，解法 3 也很適合；實作時需留意其較高的空間成本。

## 範例演示

### 多個最少刪除結果：`"()())()"`

初始計算得到 `lremove = 0`、`rremove = 1`，所以每條搜尋路徑都只刪除一個右括號：

```text
刪除索引 1 的 ')'  -> (())()  -> 有效，保留
刪除索引 3 的 ')'  -> ()()()  -> 有效，保留
刪除索引 4 的 ')'  -> 與索引 3 相鄰且相同，略過重複分支
刪除索引 6 的 ')'  -> ()())(  -> 前綴出現負餘額，捨棄
```

結果為 `["(())()", "()()()"]`。兩種結果各刪除一個括號，且都符合有效括號判準。

### 輸入 `")("`，移除左右括號後得到空字串

輸入 `")("` 開頭有一個無法配對的右括號，結尾有一個未配對的左括號，因此 `rremove = 1`、`lremove = 1`。移除兩者後得到空字串；空字串沒有不平衡括號，所以是有效結果，回傳值是 `[""]`（包含一個空字串的清單）。

### 其他邊界案例

| 輸入 | 預期結果 | 說明 |
| --- | --- | --- |
| `"(a)())()"` | `["(a())()", "(a)()()"]` | 保留字母並回傳所有最少刪除結果 |
| `"(a(b)c)"` | `["(a(b)c)"]` | 原字串已有效，不需刪除 |
| `"((("` | `[""]` | 重複的未配對左括號都必須移除 |
| `"())"` | `["()"]` | 移除一個多出的右括號 |
| `"abc"` | `["abc"]` | 沒有括號時，原字串就是唯一結果 |
| `""` | `[""]` | 專案額外健壯性案例；長度 0 不在官方限制內 |

## 正確性與複雜度

- **最少刪除：** 解法 1、2 先計算左右括號的必要刪除數，只接受恰好刪除該數量且括號有效的結果。解法 3 依刪除層級搜尋，第一個有有效結果的層級就是最少刪除數。
- **完整且有效：** 解法 1 列舉符合配額的刪除位置並於葉節點驗證；解法 2 保留右括號前先確認餘額為正，並在葉節點確認餘額歸零；解法 3 檢查每一層候選的有效性。
- **唯一結果：** 解法 1、2 略過等價刪除分支並使用結果集合去重；解法 3 使用集合去重每層候選。
- **解法 1 時間：** 最壞情況為 `O(n² × 2ᵖ)`，涵蓋分支中的字串建立與候選驗證。
- **解法 2 時間：** 最壞情況為 `O(n × 2ᵖ + r × n)`；分支逐字前進，建立輸出字串則需 `O(n)`。
- **解法 3 時間與額外空間：** 最壞時間為 `O(n² × 2ᵖ)`，額外空間為 `O(n × 2ᵖ)`，因為每層集合可能保存指數數量的候選字串。
- **解法 1 額外空間：** 不計結果清單，遞迴路徑上保留的候選字串最多為 `O(n × p)`；若有 `r` 個結果，另需 `O(r × n)`。
- **解法 2 額外空間：** 不計結果集合，後綴計數、遞迴堆疊與 `StringBuilder` 共需 `O(n)`；結果集合另需 `O(r × n)`。
