## 題目說明

給定一個可能包含重複正整數的陣列 `candidates`，以及正整數 `target`，找出所有數字總和等於 `target` 的不同組合。

- `candidates` 中的每個陣列位置，在同一個組合中最多只能使用一次。
- 即使陣列中有多個相同數值，答案仍不能包含重複組合。
- 組合內數字的排列順序不影響組合是否相同。例如 `[1, 2, 5]` 與 `[5, 2, 1]` 應視為同一組答案。
- 答案可以任意順序回傳。

題目連結：

- [LeetCode 40. Combination Sum II](https://leetcode.com/problems/combination-sum-ii/)
- [力扣 40. 组合总和 II](https://leetcode.cn/problems/combination-sum-ii/)

## 限制條件

LeetCode 原題限制如下：

- `1 <= candidates.length <= 100`
- `1 <= candidates[i] <= 50`
- `1 <= target <= 30`

> [!IMPORTANT]
> `CombinationSum2` 與 `CombinationSum2ByFrequency` 都會先複製輸入，再排序內部副本。兩個方法執行完成後，呼叫端傳入的 `candidates` 內容與順序都不會改變。

## 解題概念與出發點

這題不能只把每個數值視為「可用」或「不可用」，因為輸入可能有多個相同值。例如：

```text
candidates = [1, 1, 2, 5]
```

數值 `1` 最多可以選兩次，但每個實際陣列位置仍只能使用一次。搜尋同時要滿足：

1. 不可重複使用同一個陣列位置。
2. 可以使用輸入中不同位置的相同數值。
3. 相同數值形成的同一組答案只能保留一次。
4. 當目前總和已不可能達到 `target` 時，應停止建立無效分支。

兩種解法都先排序。排序有三個作用：

- 組合內的數字自然維持遞增，較容易理解與比較。
- 當候選值大於剩餘目標時，後續值只會更大，可以直接剪枝。
- 相同數值會排列在一起，方便跳過同層重複值或壓縮成頻率群組。

兩種公開方法都不使用共享欄位。每次呼叫都建立自己的結果集合、目前路徑與排序副本，因此可以安全地連續呼叫，不會累積上一次搜尋的答案。

## 解法一：排序、回溯與同層去重

### 核心想法

`CombinationSum2` 對排序後的陣列逐項做「選擇、探索、撤銷」：

1. 把目前候選值加入 `combination`。
2. 將剩餘目標扣掉候選值。
3. 下一層從 `index + 1` 開始，因此同一個陣列位置不會再次使用。
4. 遞迴回來後移除最後一個值，繼續探索其他候選。

回溯狀態可以寫成：

```text
Backtrack(candidates, remainingTarget, start, combination, result)
```

- `remainingTarget`：目前還需要湊出的數值。
- `start`：本層可以選擇的最小陣列索引。
- `combination`：目前搜尋路徑已選擇的數字。
- `result`：已完成且不重複的組合。

### 為什麼要從 `index + 1` 繼續

LeetCode 39 允許同一個候選位置重複使用，遞迴時可以保留目前索引；本題規定每個位置最多使用一次，所以選擇 `candidates[index]` 後，下一層必須從 `index + 1` 開始。

這不代表同一個「數值」只能使用一次。若輸入有兩個 `1`，排序後它們位於不同索引，搜尋仍可依序選取兩個位置並形成 `[1, 1]`。

### 同層去重

核心判斷為：

```csharp
if (index > start && candidates[index] == candidates[index - 1])
{
    continue;
}
```

`index > start` 表示目前不是這一層的第一個候選。若它與前一個值相同，從這個位置出發會建立內容完全相同的搜尋分支，因此跳過。

「同層跳過」與「跨層選取」必須分清楚：

- 在根節點先選第一個 `1` 後，下一層仍可選第二個 `1`，所以 `[1, 1]` 合法。
- 回到根節點後，不再用第二個 `1` 重新建立另一棵相同搜尋樹，因此不會重複產生相同答案。

### 剪枝

當 `candidates[index] > remainingTarget` 時，這個值已無法加入目前組合。由於陣列已排序，後面的候選值只會更大，因此使用 `break` 結束本層迴圈，不必再探索必定失敗的分支。

### 範例演示流程

以 `candidates = [10, 1, 2, 7, 6, 1, 5]`、`target = 8` 為例，排序副本為：

```text
[1, 1, 2, 5, 6, 7, 10]
```

| 步驟 | 本層 start | 目前組合 | 剩餘目標 | 動作 |
| --- | ---: | --- | ---: | --- |
| 1 | 0 | `[]` | 8 | 選索引 0 的第一個 `1` |
| 2 | 1 | `[1]` | 7 | 可選索引 1 的第二個 `1` |
| 3 | 2 | `[1, 1]` | 6 | 選 `6`，得到 `[1, 1, 6]` |
| 4 | 1 | `[1]` | 7 | 回溯後改選 `2`，再選 `5`，得到 `[1, 2, 5]` |
| 5 | 1 | `[1]` | 7 | 改選 `7`，得到 `[1, 7]` |
| 6 | 0 | `[]` | 8 | 根節點遇到第二個 `1`，因同層重複而跳過 |
| 7 | 0 | `[]` | 8 | 選 `2` 後再選 `6`，得到 `[2, 6]` |
| 8 | 0 | `[]` | 8 | 遇到 `10 > 8`，結束根節點搜尋 |

最後得到：

```text
[[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]]
```

### 複雜度分析

令 `n` 為候選數量：

- 複製與排序需要 `O(n)` 空間及 `O(n log n)` 時間。
- 每個位置有選或不選兩種可能，回溯搜尋最壞會檢查 `O(2^n)` 個分支；若把複製答案路徑的成本納入，寬鬆時間上界為 `O(n × 2^n)`。
- 不計回傳結果，排序副本、目前組合與遞迴堆疊共需要 `O(n)` 額外空間。
- 若共有 `k` 組答案，每組最長為 `n`，回傳結果最多需要 `O(k × n)` 空間。

## 解法二：頻率壓縮回溯

### 核心想法

`CombinationSum2ByFrequency` 不直接對每個重複位置建立分支，而是先把排序後的資料壓縮為 `(Value, Count)`：

```text
[1, 1, 2, 2, 2, 5]
          ↓
[(1, 2), (2, 3), (5, 1)]
```

回溯走到一個群組時，不再問「要不要使用這個位置」，而是決定：

```text
這個數值要取 0、1、2、... 次？
```

取用上限同時受兩個條件限制：

```text
maximumUses = min(輸入中的出現次數, remainingTarget / value)
```

這讓演算法從資料模型上保證：

- 不會使用超過輸入實際數量的候選值。
- 每個不同數值只會在一個群組中決定一次，不需要額外排除相同值建立的重複分支。
- 遞迴每次前進到下一個群組，因此組合自然維持固定數值順序。

### 設計步驟

1. 複製並排序 `candidates`。
2. 掃描排序副本，建立遞增排列的頻率群組。
3. 從第一個群組開始，先探索取用 0 次的分支。
4. 再逐次加入目前數值，探索取用 1 到 `maximumUses` 次的分支。
5. 每次遞迴都移到下一個群組。
6. 本層所有選擇完成後，一次移除本層加入的數字，恢復上一層路徑。

### 範例演示流程

以 `candidates = [2, 5, 2, 1, 2]`、`target = 5` 為例，排序與壓縮結果為：

```text
排序：[1, 2, 2, 2, 5]
群組：[(1, 1), (2, 3), (5, 1)]
```

| 群組 | 剩餘目標 | 可取次數 | 選擇 | 後續結果 |
| --- | ---: | ---: | --- | --- |
| `(1, 1)` | 5 | 0～1 | 取 0 次 | 後續 `(5, 1)` 可取 1 次，得到 `[5]` |
| `(1, 1)` | 5 | 0～1 | 取 1 次 | 組合為 `[1]`，剩餘目標為 4 |
| `(2, 3)` | 4 | 0～2 | 取 2 次 | 組合為 `[1, 2, 2]`，剩餘目標為 0 |
| `(2, 3)` | 5 | 0～2 | 其他取法 | 剩餘群組無法補足目標，不加入答案 |

雖然輸入有三個 `2`，剩餘目標為 4 時最多只需取兩個；`maximumUses` 會把第三個不可能成功的選擇直接排除。最後得到：

```text
[[1, 2, 2], [5]]
```

### 複雜度分析

令 `u` 為不同數值的數量，第 `i` 個數值出現 `cᵢ` 次：

- 複製、排序及建立頻率群組需要 `O(n log n)` 時間。
- 搜尋樹最多枚舉 `∏(cᵢ + 1)` 種取用次數配置；此值不超過逐位置選或不選的 `2^n` 上界。若納入答案路徑複製成本，可表示為 `O(n × ∏(cᵢ + 1))`。
- 不計回傳結果，排序副本、頻率群組、目前組合與遞迴堆疊需要 `O(n + u)` 額外空間，因 `u <= n`，可簡化為 `O(n)`。
- 回傳結果空間同樣取決於答案數量與各組合長度，最多為 `O(k × n)`。

## 兩種解法比較

| 比較項目 | 解法一：同層去重 | 解法二：頻率壓縮 |
| --- | --- | --- |
| 搜尋單位 | 每個排序後的陣列位置 | 每個不同數值及其出現次數 |
| 去重方式 | 同一層跳過相鄰重複值 | 每個數值只建立一個頻率群組 |
| 使用量限制 | 下一層從 `index + 1` 開始 | 取用次數不超過群組 `Count` |
| 剪枝方式 | 候選值大於剩餘目標時停止迴圈 | 群組值過大時停止，並限制最大取用次數 |
| 教學重點 | 理解「同層去重、跨層可選」 | 將重複位置轉換為有限次數決策 |
| 重複值很多時 | 仍掃描各陣列位置，但跳過重複起點 | 群組數減少，搜尋結構通常更精簡 |
| 輸入副作用 | 無 | 無 |

解法一是 Combination Sum II 最常見的寫法，程式較短；解法二把重複數量直接放入模型，較容易說明「每個值最多能取幾次」，也能清楚對照兩種去重策略。

## 結果驗證方式

題目允許任意答案順序，因此 console harness 不直接比較巢狀集合的列舉順序。`FormatCombinations` 會：

1. 將每個組合依數值排序。
2. 把每個組合轉成固定文字。
3. 將所有組合依字典順序排列。

兩個內容相同但回傳順序不同的答案會得到相同文字，再據此判斷 `PASS` 或 `FAIL`。

每個案例對兩種解法各檢查：

- 正規化後的答案是否符合預期。
- 呼叫後的輸入陣列是否與呼叫前完全相同。

8 個案例 × 2 種解法 × 2 項檢查，共 32 項檢查。
