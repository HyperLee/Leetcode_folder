# LeetCode 3483：不同三位偶數的數目

使用 C# / .NET 10 實作 LeetCode 3483，計算由數字陣列組成的不同三位偶數數量。

- [LeetCode 英文題目](https://leetcode.com/problems/unique-3-digit-even-numbers/description/)
- [力扣中文題目](https://leetcode.cn/problems/unique-3-digit-even-numbers/description/)

## 題目說明

給定一個名為 `digits` 的數字陣列，從中選出三個數字，組成一個三位數偶數，並回傳所有不同結果的數量。

每個陣列元素代表一份數字副本。在同一個三位數中，每個陣列索引只能使用一次；如果陣列中有多份相同數字，則可以依照實際副本數量重複使用該數字。

一個合法結果必須同時符合：

1. 必須是三位數，因此百位不能是 `0`。
2. 個位必須是偶數，也就是 `0`、`2`、`4`、`6` 或 `8`。
3. 三個位置使用的陣列索引不可重複。
4. 不同的選取順序只要產生相同數字，就只能計算一次。

### 限制條件

依照[官方題目限制](https://leetcode.com/problems/unique-3-digit-even-numbers/description/)：

- `3 <= digits.Length <= 10`
- `0 <= digits[i] <= 9`
- `digits` 可能包含重複數字。

## 官方範例

### 範例一

```text
輸入：digits = [1, 2, 3, 4]
輸出：12
```

可以形成的數字包括 `124`、`132`、`134`、`142`、`214`、`234`、`312`、`314`、`324`、`342`、`412` 與 `432`。

### 範例二

```text
輸入：digits = [0, 2, 2]
輸出：2
```

數字 `2` 有兩份副本，因此可以形成 `202` 與 `220`。以 `0` 作為百位的排列不是三位數，不能計算。

### 範例三

```text
輸入：digits = [6, 6, 6]
輸出：1
```

三份 `6` 只能形成一個不同結果：`666`。

### 範例四

```text
輸入：digits = [1, 3, 5]
輸出：0
```

沒有偶數可以放在個位，因此無法形成三位偶數。

## 解題概念與出發點

這題的關鍵不是計算所有索引排列後直接累加，而是同時處理三個條件：

- 百位要排除 `0`。
- 個位要限制為偶數。
- 陣列中的重複數字可能因不同索引排列產生相同的三位數，結果必須去重。

本專案保留三種不同思路：

1. 直接枚舉三個索引，使用布林陣列去重。
2. 先統計每個數字出現次數，再以個位數分類並用組合數學計算。
3. 排序後使用 DFS 與回溯列舉不重複的數字排列。

三種方法都由 `TotalNumbers`、`TotalNumbers2`、`TotalNumbers3` 實作，`Main` 會用相同測試資料同時驗證三者的結果。

## 解法一：三重枚舉 + 布林陣列去重

### 設計方式

`TotalNumbers` 依序枚舉：

- `i`：百位使用的索引。
- `j`：十位使用的索引。
- `k`：個位使用的索引。

枚舉過程中立即排除：

- `digits[i] == 0`，因為百位不能是 `0`。
- `j == i`、`k == i` 或 `k == j`，因為同一份陣列元素不能重複使用。
- `digits[k]` 是奇數，因為個位必須是偶數。

找到合法組合後，將三個數字組成：

```text
number = digits[i] * 100 + digits[j] * 10 + digits[k]
```

由於陣列可能包含重複數字，不同索引組合可能得到同一個 `number`。因此使用長度為 `1000` 的 `seen` 陣列記錄數字是否已經計算過，只有第一次出現時才增加答案。

### 演示：`digits = [0, 2, 2]`

1. 百位選 `0` 的路徑全部排除，避免產生前導零。
2. 使用一份 `2` 作為百位、另一份 `2` 作為十位、`0` 作為個位，可以得到 `220`。
3. 使用 `2` 作為百位、`0` 作為十位、另一份 `2` 作為個位，可以得到 `202`。
4. 交換兩份內容相同的 `2` 時，可能再次得到 `202` 或 `220`，但 `seen` 會阻止重複計數。

最後答案為 `2`。

### 正確性

三重迴圈會檢查所有三個互異索引的排列。每個通過百位、個位與索引條件的組合都會形成一個合法候選數；`seen` 將相同數值映射到同一個位置，因此每個不同三位偶數恰好計數一次。

### 複雜度

- 時間：`O(n³)`，其中 `n = digits.Length`。
- 空間：`O(1000)`；因為三位數範圍固定為 `100` 到 `999`，相對於 `n` 可視為固定空間。

## 解法二：頻率統計 + 組合數學

### 設計方式

`TotalNumbers2` 不逐一產生三位數，而是先建立 `count[10]`，統計每個數字的出現次數。

接著枚舉個位數 `d = 0, 2, 4, 6, 8`。假設消耗一份 `d` 後，剩餘數字的統計如下：

- `kinds`：仍然存在的不同數字種類數，可作為十位。
- `nonZeros`：仍然存在的非零數字種類數，可作為百位。
- `singles`：目前恰好只剩一份的非零數字種類數。

如果忽略百位與十位不能使用同一份副本，候選配對數是：

```text
tensKinds * hundredsKinds
```

但如果某個非零數字只剩一份，將它同時放到百位與十位會被錯誤計算一次，因此要扣除 `remainingSingles`：

```text
本次貢獻 = tensKinds * hundredsKinds - remainingSingles
```

消耗個位數後的調整規則：

- 若 `d` 原本只有一份，十位不能再使用 `d`。
- 若 `d` 是非零且原本只有一份，百位也不能再使用 `d`。
- 若 `d` 是非零且原本有兩份，消耗一份後，`d` 會成為恰好剩一份的數字，因此 `remainingSingles` 增加一。
- 若 `d` 是非零且原本只有一份，該數字被消耗完，因此 `remainingSingles` 減少一。

### 演示：`digits = [0, 2, 2]`

初始統計為：

```text
count[0] = 1
count[2] = 2
kinds = 2
nonZeros = 1
singles = 0
```

#### 個位使用 `0`

- `0` 原本只有一份，使用後不能再作為十位，因此 `tensKinds = 1`。
- 非零數字 `2` 仍可作為百位，因此 `hundredsKinds = 1`。
- `remainingSingles = 0`。
- 貢獻：`1 * 1 - 0 = 1`，對應 `220`。

#### 個位使用 `2`

- `2` 原本有兩份，使用一份後仍可作為十位，因此 `tensKinds = 2`。
- `2` 仍可作為百位，因此 `hundredsKinds = 1`。
- `2` 使用後恰好剩一份，`remainingSingles = 1`。
- 貢獻：`2 * 1 - 1 = 1`，對應 `202`。

總答案為 `1 + 1 = 2`。

### 正確性

每一個合法數字都具有唯一的偶數個位 `d`，因此可以被歸入且只歸入一個個位分類。固定 `d` 後，`tensKinds * hundredsKinds` 列出所有百位與十位的種類配對，再扣除只有一份副本卻被同時使用的非法配對，正好保留所有可使用的百位與十位組合。因此各分類加總後，就是所有不同三位偶數的數量。

### 複雜度

- 時間：`O(n + 10)`，可寫成 `O(n)`。
- 空間：`O(10)`，可視為固定空間。

## 解法三：排序 + DFS + 回溯

### 設計方式

`TotalNumbers3` 先複製並排序輸入陣列，避免改變呼叫端的原始資料。DFS 每次選擇一個尚未使用的索引，將數字接到目前的部分數字後面，直到選出三位數。

DFS 使用 `used` 陣列防止同一個索引重複使用。因為排序後相同數字會相鄰，所以在同一層遞迴中，如果前一個相同數字的索引尚未被使用，就跳過目前索引：

```csharp
if (i > 0 && digits[i] == digits[i - 1] && !used[i - 1])
{
    continue;
}
```

這個判斷只跳過同一層的重複選擇，不會錯誤阻止不同層使用相同數字；只要輸入中有足夠副本，像 `202` 或 `220` 仍然可以建立。

### 演示：`digits = [0, 2, 2]`

1. 排序後仍為 `[0, 2, 2]`。
2. DFS 選 `0` 作為第一位的分支，最後形成的數字小於 `100`，在葉節點被排除。
3. 選第一份 `2` 作為百位後，可以選 `0`、另一份 `2`，形成 `202` 或 `220`。
4. 同一層遇到第二份 `2` 時，若第一份 `2` 尚未被使用，會跳過第二份，避免產生相同排列。
5. 葉節點只接受 `100..999` 且個位為偶數的數字。

最後只保留 `202` 與 `220`，答案為 `2`。

### 正確性

DFS 會逐層選擇三個不同索引，因此不會超過輸入副本數量。排序搭配同層重複跳過，確保相同數值排列只被保留一次；回溯會在返回上一層時恢復 `used` 狀態，讓其他合法分支仍能被探索。所有三位排列都在葉節點檢查百位與個位條件，因此得到的計數正好符合題目要求。

### 複雜度

- 排序：`O(n log n)`。
- DFS：固定選三位，最壞為 `O(n³)`。
- 總時間：`O(n log n + n³)`，可簡化為 `O(n³)`。
- 空間：排序複本、`used` 陣列與最多三層遞迴，為 `O(n)`。

## 三種解法比較

| 解法 | 核心思路 | 時間複雜度 | 空間複雜度 | 優點 |
|---|---|---:|---:|---|
| `TotalNumbers` | 枚舉三個索引，使用 `seen` 去重 | `O(n³)` | `O(1000)` | 直觀，容易確認每個條件 |
| `TotalNumbers2` | 頻率統計，固定個位後計算百位/十位組合 | `O(n)` | `O(10)` | 不需產生每個候選數，效率最佳 |
| `TotalNumbers3` | 排序後 DFS、回溯與同層去重 | `O(n³)` | `O(n)` | 展示通用排列與去重技巧 |
