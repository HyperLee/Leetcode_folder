## 題目說明

給定一個長度為 `n`、索引從 `0` 開始的整數陣列 `nums`，建立一個同樣長度的陣列 `diff`。

對每個索引 `i`：

- 前綴為 `nums[0..i]`，包含 `nums[i]`。
- 後綴為 `nums[i+1..n-1]`，不包含 `nums[i]`。
- `diff[i]` 等於「前綴中的相異元素數量」減去「後綴中的相異元素數量」。

公式如下：

```text
diff[i]
= distinct(nums[0..i])
- distinct(nums[i+1..n-1])
```

當 `i = n - 1` 時，右側後綴是空陣列，因此其相異元素數量為 `0`。

### 輸入與輸出

- 輸入：整數陣列 `nums`。
- 輸出：整數陣列 `diff`，長度與 `nums` 相同。

例如：

```text
輸入：nums = [1, 2, 3, 4, 5]
輸出：diff = [-3, -1, 1, 3, 5]
```

索引 `0` 的前綴 `[1]` 有 `1` 種相異元素，後綴 `[2, 3, 4, 5]` 有 `4` 種，
所以 `diff[0] = 1 - 4 = -3`。

## 限制條件

- `1 <= nums.length <= 50`
- `1 <= nums[i] <= 50`

雖然限制不大，可以對每個索引重新掃描前綴與後綴，但本專案採用可擴展到較大輸入的線性解法。

## 解題概念與出發點

### 直接計算會重複做什麼？

最直觀的做法，是對每個索引 `i`：

1. 建立一個集合，掃描 `nums[0..i]`。
2. 再建立一個集合，掃描 `nums[i+1..n-1]`。
3. 將兩個集合的大小相減。

這個做法容易理解，但相鄰索引的前綴與後綴高度重疊。例如從 `i = 1` 移到 `i = 2` 時，
大部分元素已經掃描過，若全部重算便會產生重複工作。總時間複雜度會是 O(n²)。

### 如何移除重複掃描？

答案只需要兩項資訊：

1. 目前前綴 `nums[0..i]` 有多少種相異元素。
2. 下一個位置開始的後綴 `nums[i+1..n-1]` 有多少種相異元素。

前綴可以在正向走訪時持續把 `nums[i]` 加入集合；集合大小就是當前前綴的相異元素數量。
後綴則可以先由右向左預處理，將每個起點的相異元素數量記錄在 `sufCnt`。

因此：

```text
res[i] = prefixSet.Count - sufCnt[i + 1]
```

## 解法一：HashSet 與後綴預處理

### 使用的資料結構

- `HashSet<int> set`
  - 集合只保留不重複的值。
  - `set.Count` 可以直接表示目前區段的相異元素數量。
- `int[] sufCnt`
  - 長度為 `n + 1`。
  - `sufCnt[k]` 表示 `nums[k..n-1]` 的相異元素數量。
  - `sufCnt[n] = 0` 表示陣列尾端之後的空後綴。
- `int[] res`
  - 儲存每個索引最後的相異元素數量差。

### 第一階段：由右向左預處理後綴

從 `n - 1` 走到 `1`，把每個元素加入 `HashSet`，並將集合大小寫入 `sufCnt[i]`。

程式不需要計算 `sufCnt[0]`，因為計算 `res[i]` 時只會查詢 `sufCnt[i + 1]`；
當 `i` 的範圍是 `0..n-1`，實際使用的後綴索引就是 `1..n`。

### 第二階段：由左向右累積前綴

清空集合後，從索引 `0` 開始：

1. 將 `nums[i]` 加入集合。
2. `set.Count` 是 `nums[0..i]` 的相異元素數量。
3. `sufCnt[i + 1]` 是 `nums[i+1..n-1]` 的相異元素數量。
4. 兩者相減並寫入 `res[i]`。

### 為什麼這個解法正確？

對任意索引 `i`：

- 正向迴圈處理完 `nums[i]` 後，集合恰好包含 `nums[0..i]` 出現過的所有不同值，
  所以 `set.Count` 等於前綴的相異元素數量。
- 反向預處理已保證 `sufCnt[i + 1]` 等於 `nums[i+1..n-1]` 的相異元素數量。
- 程式將這兩個定義完全相符的數量相減，因此得到的 `res[i]` 正是題目要求的 `diff[i]`。

以上敘述對所有 `0 <= i < n` 都成立，所以回傳陣列的每個位置皆正確。

### 複雜度分析

- 時間複雜度：O(n)
  - 反向預處理走訪一次。
  - 正向建立答案再走訪一次。
  - `HashSet` 的新增操作平均為 O(1)。
- 空間複雜度：O(n)
  - `sufCnt` 與答案陣列各需要 O(n)。
  - `HashSet` 最多保存 O(n) 個不同值。

## 解法一範例演示流程

以官方範例二為例：

```text
nums = [3, 2, 3, 4, 2]
```

### 1. 建立後綴相異數量

`sufCnt[k]` 記錄從索引 `k` 到陣列尾端的相異元素數量：

| `k` | 後綴 `nums[k..n-1]` | 相異元素集合 | `sufCnt[k]` |
|---:|---|---|---:|
| 5 | `[]` | `{}` | 0 |
| 4 | `[2]` | `{2}` | 1 |
| 3 | `[4, 2]` | `{4, 2}` | 2 |
| 2 | `[3, 4, 2]` | `{3, 4, 2}` | 3 |
| 1 | `[2, 3, 4, 2]` | `{2, 3, 4}` | 3 |

`sufCnt[0]` 不會被答案公式使用，因此程式不必計算它。

### 2. 正向建立答案

| `i` | 加入的值 | 前綴相異集合 | 前綴數量 | 使用的後綴數量 | 計算 | `res[i]` |
|---:|---:|---|---:|---:|---|---:|
| 0 | 3 | `{3}` | 1 | `sufCnt[1] = 3` | `1 - 3` | -2 |
| 1 | 2 | `{3, 2}` | 2 | `sufCnt[2] = 3` | `2 - 3` | -1 |
| 2 | 3 | `{3, 2}` | 2 | `sufCnt[3] = 2` | `2 - 2` | 0 |
| 3 | 4 | `{3, 2, 4}` | 3 | `sufCnt[4] = 1` | `3 - 1` | 2 |
| 4 | 2 | `{3, 2, 4}` | 3 | `sufCnt[5] = 0` | `3 - 0` | 3 |

最後得到：

```text
res = [-2, -1, 0, 2, 3]
```

這個例子也呈現了 `HashSet` 的重要特性：索引 `2` 再次遇到 `3`、索引 `4` 再次遇到 `2` 時，
集合大小不會增加，因為相同值只計算一次。

## 解法二：固定大小頻率陣列

### 改進出發點

解法一已經是 O(n) 時間，無法在漸進複雜度上再降低，因為至少必須讀取每個輸入元素。
不過題目保證 `1 <= nums[i] <= 50`，代表可能出現的值只有 50 種，可以直接把數值當成陣列索引：

- `suffixFrequency[value]`：這個值目前在後綴還剩幾次。
- `prefixSeen[value]`：這個值是否已經進入前綴。
- `suffixDistinct`：目前後綴有幾種不同值。
- `prefixDistinct`：目前前綴有幾種不同值。

這樣可以省去雜湊計算，也不必保存每個索引的 `sufCnt`。使用的兩個輔助陣列長度固定為 `51`，
不會隨 `nums.Length` 增長。

### 第一階段：建立完整後綴頻率

先掃描一次 `nums`，將每個值的出現次數加入 `suffixFrequency`。
如果某個值加入前的頻率為 `0`，表示第一次遇到這個值，因此將 `suffixDistinct` 加一。

以 `nums = [3, 2, 3, 4, 2]` 為例，初始化完成後：

```text
suffixFrequency[2] = 2
suffixFrequency[3] = 2
suffixFrequency[4] = 1
suffixDistinct = 3
prefixDistinct = 0
```

此時尚未處理任何索引，所以所有元素都屬於後綴。

### 第二階段：把元素從後綴移到前綴

由左向右處理索引 `i`。在計算答案前，必須讓 `nums[i]` 從後綴
`nums[i..n-1]` 移到前綴 `nums[0..i]`：

1. 將 `suffixFrequency[nums[i]]` 減一。
2. 如果頻率變成 `0`，表示這個值已完全離開後綴，`suffixDistinct` 減一。
3. 如果 `prefixSeen[nums[i]]` 尚未設為 `true`，表示這個值第一次進入前綴，
   將它標記為已出現，並讓 `prefixDistinct` 加一。
4. 寫入 `result[i] = prefixDistinct - suffixDistinct`。

### 解法二範例演示流程

同樣使用 `nums = [3, 2, 3, 4, 2]`：

| `i` | 移動的值 | 移動後的後綴頻率變化 | `suffixDistinct` | 前綴是否首次出現 | `prefixDistinct` | 計算 | `result[i]` |
|---:|---:|---|---:|---|---:|---|---:|
| 0 | 3 | `2 -> 1` | 3 | 是 | 1 | `1 - 3` | -2 |
| 1 | 2 | `2 -> 1` | 3 | 是 | 2 | `2 - 3` | -1 |
| 2 | 3 | `1 -> 0` | 2 | 否 | 2 | `2 - 2` | 0 |
| 3 | 4 | `1 -> 0` | 1 | 是 | 3 | `3 - 1` | 2 |
| 4 | 2 | `1 -> 0` | 0 | 否 | 3 | `3 - 0` | 3 |

觀察索引 `2`：

- 值 `3` 的後綴頻率由 `1` 變成 `0`，代表右側後綴已經沒有 `3`，所以 `suffixDistinct` 從 `3` 降為 `2`。
- 值 `3` 先前已在索引 `0` 進入前綴，因此 `prefixDistinct` 保持 `2`。
- 答案是 `2 - 2 = 0`。

最後同樣得到：

```text
result = [-2, -1, 0, 2, 3]
```

### 為什麼解法二正確？

在處理索引 `i` 前，頻率陣列描述尚未移入前綴的 `nums[i..n-1]`。
將 `nums[i]` 的後綴頻率減一後，頻率陣列便精確描述題目要求的右側後綴
`nums[i+1..n-1]`；只有頻率歸零時，後綴才真正少掉一種相異值。

同一時間，`prefixSeen` 在加入 `nums[i]` 後，精確記錄 `nums[0..i]` 出現過的值；
只有第一次出現時，前綴相異數量才增加。因此每一步的
`prefixDistinct - suffixDistinct` 都等於題目定義的 `diff[i]`。

### 複雜度分析

- 時間複雜度：O(n)
  - 第一次掃描建立後綴頻率。
  - 第二次掃描將元素由後綴移至前綴並建立答案。
- 輔助空間複雜度：O(1)
  - `suffixFrequency` 與 `prefixSeen` 的長度固定為 `51`。
  - 回傳用的結果陣列不計入輔助空間。

> [!NOTE]
> O(1) 空間成立的前提是題目把值域固定在 `1..50`。若值域不受限制，便需要改用雜湊集合或字典，
> 此時輔助空間會回到 O(n)。

## 兩種解法比較

| 比較項目 | 解法一：HashSet＋後綴陣列 | 解法二：固定頻率陣列 |
|---|---|---|
| 公開方法 | `DistinctDifferenceArray` | `DistinctDifferenceArray2` |
| 時間複雜度 | O(n) | O(n) |
| 輔助空間 | O(n) | O(1)，固定 51 格 |
| 相異值追蹤 | `HashSet<int>` | 直接以數值索引陣列 |
| 後綴資訊 | 保存每個起點的 `sufCnt` | 只維護當前頻率與相異數量 |
| 優點 | 適用於一般整數值域、觀念直觀 | 無雜湊成本、配置固定、狀態集中 |
| 限制 | 需要集合與 O(n) 後綴陣列 | 依賴 `nums[i] <= 50` 的題目限制 |

若只針對本題，解法二更充分利用限制條件，輔助空間與資料存取常數都更小。
若希望方法能直接延伸到未知或很大的整數值域，解法一會更通用。

LeetCode 顯示的單次 Runtime 與 Beats 百分比會受到測試機器、執行批次、JIT 暖機及同批提交影響；
解法二可以合理減少雜湊與配置成本，但不保證每次提交的毫秒數或排名都一定更高。
