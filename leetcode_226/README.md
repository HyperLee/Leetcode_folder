## 題目說明

給定一棵二元樹的根節點 `root`，反轉整棵樹並回傳根節點。

「反轉」是指對每個節點交換左子樹與右子樹。這不是只交換根節點的兩個直接子節點，而是樹中每一個非空節點都必須進行相同操作。

例如：

```text
輸入：[4,2,7,1,3,6,9]

        4
      /   \
     2     7
    / \   / \
   1   3 6   9

輸出：[4,7,2,9,6,3,1]

        4
      /   \
     7     2
    / \   / \
   9   6 3   1
```

本專案以 LeetCode 慣用的層序陣列顯示樹；`null` 表示該位置沒有節點。

## 限制條件

- 樹中的節點數量介於 `0` 到 `100`。
- `-100 <= Node.val <= 100`。
- `root == null` 代表空樹，應回傳 `null`。

題意與限制以 [LeetCode 226 — Invert Binary Tree](https://leetcode.com/problems/invert-binary-tree/) 為準。

## 解題概念與出發點

二元樹是遞迴結構：一棵樹由根節點、左子樹與右子樹組成。反轉整棵樹可以拆成重複的小問題：

1. 找到一個非空節點。
2. 交換該節點的 `left` 與 `right`。
3. 對交換後的兩棵子樹執行相同操作。
4. 所有節點都處理完成後，原本的根節點仍然是反轉後的根節點。

三種解法的差別只在於「如何找到下一個尚未處理的節點」：

- 遞迴 DFS 使用系統呼叫堆疊。
- 迭代 DFS 明確使用 `Stack<TreeNode>`。
- 迭代 BFS 明確使用 `Queue<TreeNode>`。

三種方法都會直接修改傳入的樹，不建立一棵包含所有新節點的副本。因此，驗證器會為每一種解法重新建立獨立輸入樹，避免先執行的解法改變後續解法看到的資料。

## 解法一：遞迴 DFS

### 設計說明

`InvertTree` 利用二元樹的遞迴定義：

1. `root == null` 時，空樹不需要處理，直接回傳 `null`。
2. 暫存原本的左子樹。
3. 遞迴反轉原本的右子樹，並將結果指定給 `root.left`。
4. 遞迴反轉原本的左子樹，並將結果指定給 `root.right`。
5. 回傳原本的 `root`。

關鍵在於左右子樹都要「反轉完成後再放到相反方向」。暫存原本的左子樹，可避免第一次指定 `root.left` 後遺失其參考。

### 正確性

- 基底情況：空樹沒有任何節點，回傳 `null` 已是正確反轉結果。
- 遞迴假設：假設 `InvertTree` 能正確反轉目前節點的左右子樹。
- 遞迴步驟：把已反轉的原右子樹放到左邊，把已反轉的原左子樹放到右邊，因此目前節點及其所有後代都完成鏡像交換。
- 從葉節點一路回到根節點後，整棵樹均已反轉。

### 範例演示

輸入 `[4,2,7,1,3,6,9]`：

1. 從根節點 `4` 開始，先保留左子樹 `2`。
2. 遞迴進入右子樹 `7`；節點 `9`、`6` 都是葉節點，其空子樹互換後仍為空。
3. 節點 `7` 得到左節點 `9`、右節點 `6`，形成反轉後的左子樹。
4. 遞迴進入原左子樹 `2`；同理得到左節點 `3`、右節點 `1`。
5. 根節點 `4` 的左邊接上反轉後的 `7` 子樹，右邊接上反轉後的 `2` 子樹。
6. 層序結果為 `[4,7,2,9,6,3,1]`。

### 複雜度

- 時間複雜度：`O(n)`，每個節點恰好處理一次。
- 輔助空間複雜度：`O(h)`，`h` 為樹高，來自遞迴呼叫堆疊。
- 平衡樹的 `h = O(log n)`；完全偏斜的樹最壞為 `O(n)`。

## 解法二：堆疊迭代 DFS

### 設計說明

`InvertTree2` 將遞迴呼叫堆疊改成明確的 `Stack<TreeNode>`：

1. 空樹直接回傳 `null`。
2. 將根節點推入堆疊。
3. 當堆疊不為空時，彈出一個節點。
4. 原地交換彈出節點的左右子樹。
5. 將交換後的非空右子節點推入堆疊，再推入非空左子節點。
6. 重複直到堆疊清空。

堆疊是後進先出，因此先推右、再推左，下一輪會優先處理左子樹，形成常見的「根、左、右」前序 DFS 順序。反轉結果其實不依賴左右子樹的處理先後，只要每個節點恰好交換一次即可。

### 正確性

- 根節點一開始一定在堆疊中。
- 每次彈出節點時會交換其左右子樹，完成該節點所需的反轉操作。
- 每個非空子節點都會被推入一次，之後也會被彈出並交換一次。
- 堆疊清空時，所有可由根節點到達的節點都已處理，因此整棵樹完成反轉。

### 範例演示

輸入 `[4,2,7,1,3,6,9]`：

1. 堆疊為 `[4]`。
2. 彈出 `4` 並交換子樹，根節點暫時變成左 `7`、右 `2`；依序推入 `2`、`7`。
3. 彈出 `7`，交換後變成左 `9`、右 `6`；推入 `6`、`9`。
4. 依序彈出 `9`、`6`；兩者為葉節點，交換空子樹不改變結構。
5. 彈出 `2`，交換後變成左 `3`、右 `1`；再處理兩個葉節點。
6. 堆疊清空，層序結果為 `[4,7,2,9,6,3,1]`。

### 複雜度

- 時間複雜度：`O(n)`，每個節點各進出堆疊一次。
- 輔助空間複雜度：最壞 `O(n)`，取決於堆疊同時保存的待處理節點數。
- 不使用遞迴，因此不受系統呼叫堆疊深度限制。

## 解法三：佇列迭代 BFS

### 設計說明

`InvertTree3` 使用 `Queue<TreeNode>` 逐層處理：

1. 空樹直接回傳 `null`。
2. 將根節點加入佇列。
3. 當佇列不為空時，取出最前面的節點。
4. 原地交換該節點的左右子樹。
5. 將交換後的非空左右子節點加入佇列。
6. 重複直到佇列清空。

佇列是先進先出，所以同一層節點會先處理完，再前往下一層。交換後才把子節點加入佇列，可讓佇列中的順序直觀對應反轉後的由左到右層序；即使入列順序相反，最終樹形仍然相同。

### 正確性

- 根節點先入列，因此第一層一定會處理。
- 每個出列節點都會完成一次左右交換。
- 該節點的所有非空子節點都會入列，使下一層不會遺漏。
- 二元樹沒有環，所以每個節點只會由其父節點加入一次。
- 佇列清空代表所有層、所有節點均已交換，整棵樹完成反轉。

### 範例演示

輸入 `[4,2,7,1,3,6,9]`：

1. 初始佇列為 `[4]`。
2. 取出 `4`，交換成左 `7`、右 `2`，並將 `7`、`2` 入列。
3. 取出 `7`，交換成左 `9`、右 `6`，將 `9`、`6` 入列。
4. 取出 `2`，交換成左 `3`、右 `1`，將 `3`、`1` 入列。
5. 依序取出第三層的 `9`、`6`、`3`、`1`；它們都是葉節點。
6. 佇列清空，層序結果為 `[4,7,2,9,6,3,1]`。

### 複雜度

- 時間複雜度：`O(n)`，每個節點各進出佇列一次。
- 輔助空間複雜度：`O(w)`，`w` 是二元樹的最大寬度。
- 最壞情況下某一層可包含 `O(n)` 個節點。

## 三種解法比較

| 比較項目 | 遞迴 DFS | 堆疊迭代 DFS | 佇列迭代 BFS |
|---|---|---|---|
| 主要 API | `InvertTree` | `InvertTree2` | `InvertTree3` |
| 節點處理順序 | 深度優先，由遞迴返回 | 深度優先，後進先出 | 廣度優先，逐層處理 |
| 主要資料結構 | 系統呼叫堆疊 | `Stack<TreeNode>` | `Queue<TreeNode>` |
| 時間複雜度 | `O(n)` | `O(n)` | `O(n)` |
| 輔助空間 | `O(h)` | 最壞 `O(n)` | `O(w)` |
| 是否原地修改 | 是 | 是 | 是 |
| 優點 | 程式精簡，直接對應樹的遞迴結構 | 避免遞迴深度限制 | 逐層流程容易觀察 |
| 注意事項 | 偏斜樹可能造成很深的呼叫堆疊 | 必須自行維護待處理堆疊 | 寬樹可能讓佇列同時保存大量節點 |

`h` 表示樹高，`w` 表示最大層寬。三種解法都回傳原本的根節點參考；差異只在走訪策略與輔助空間。
