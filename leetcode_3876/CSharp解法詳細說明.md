# 3876. 建構奇偶一致的陣列 II：C# 解法詳細說明

## 題目核心

給定一個由互不相同正整數組成的陣列 `nums1`，需要建構另一個同長度陣列 `nums2`，使 `nums2` 的元素全部都是奇數，或全部都是偶數。

對每個索引 `i`，可以選擇以下其中一種操作：

1. 保留原值：`nums2[i] = nums1[i]`。
2. 選擇另一個索引 `j`，令 `nums2[i] = nums1[i] - nums1[j]`，但必須滿足：

   ```text
   nums1[i] - nums1[j] >= 1
   ```

   也就是：

   ```text
   nums1[i] > nums1[j]
   ```

目標是判斷能否讓 `nums2` 中所有元素的奇偶性一致。

## 解法程式碼

最精簡的 LINQ 寫法如下：

```csharp
public bool UniformArray(int[] nums1)
{
    int min = nums1.Min();
    bool hasOdd = nums1.Any(x => x % 2 != 0);

    return min % 2 != 0 || !hasOdd;
}
```

這個解法只需要掌握兩項資訊：

- 陣列中的最小值 `min`。
- 陣列中是否存在奇數 `hasOdd`。

## 為什麼只需要關注奇偶性？

減法是否會改變一個數的奇偶性，取決於被減掉的數是奇數還是偶數：

| 運算 | 結果的奇偶性 | 是否改變原數奇偶性 |
|---|---|---|
| 偶數 - 偶數 | 偶數 | 否 |
| 奇數 - 偶數 | 奇數 | 否 |
| 偶數 - 奇數 | 奇數 | 是 |
| 奇數 - 奇數 | 偶數 | 是 |

因此，只有「減去奇數」才會改變原本的奇偶性；減去偶數不會改變奇偶性。

## 為什麼最小值最重要？

程式首先取得最小值：

```csharp
int min = nums1.Min();
```

第二種操作要求被減數必須嚴格大於減數。由於 `min` 已經是整個陣列的最小值，因此找不到另一個比它更小的元素讓它相減。

換句話說：

> 最小值只能保留原值，它的奇偶性無法透過第二種操作改變。

例如：

```text
nums1 = [2, 3, 5]
min = 2
```

如果想把 `2` 變成奇數，就必須讓它減去某個奇數，因為：

```text
偶數 - 奇數 = 奇數
```

但是陣列中沒有比 `2` 更小的奇數，所以 `2` 無法執行符合限制的減法，只能維持偶數。

因此，最小值的奇偶性會限制最後能夠建構出的目標奇偶性。

## `hasOdd` 代表什麼？

```csharp
bool hasOdd = nums1.Any(x => x % 2 != 0);
```

這行用來判斷陣列中是否至少存在一個奇數。

例如：

```csharp
nums1 = [2, 4, 6];
// hasOdd = false
```

```csharp
nums1 = [2, 4, 7];
// hasOdd = true
```

如果 `hasOdd` 是 `false`，就表示陣列中的元素全部都是偶數，不需要進行任何減法，直接保留所有元素便已符合要求。

## 分類討論

### 情況一：全部都是偶數

例如：

```text
nums1 = [2, 4, 6, 10]
```

所有元素原本就具有相同的偶數奇偶性，因此每個位置都選擇保留原值：

```text
nums2 = [2, 4, 6, 10]
```

此時：

```text
min 是偶數
hasOdd = false
```

所以回傳 `true`。

### 情況二：全部都是奇數

例如：

```text
nums1 = [1, 3, 5]
```

所有元素原本就都是奇數，直接保留即可：

```text
nums2 = [1, 3, 5]
```

最小值一定是奇數，因此回傳 `true`。

### 情況三：奇偶混合，而且最小值是奇數

例如：

```text
nums1 = [3, 4, 8, 11]
min = 3
```

可以將目標設定為「全部變成奇數」：

- 原本的奇數 `3`、`11` 直接保留。
- 偶數 `4`、`8` 分別減去最小奇數 `3`。

```text
4 - 3 = 1
8 - 3 = 5
```

因此可以建構出：

```text
nums2 = [3, 1, 5, 11]
```

所有元素都是奇數。

由於 `3` 是陣列最小值，其他與它不同的元素一定都比 `3` 大，所以這些減法結果必定至少為 `1`，符合題目限制。

因此，只要最小值是奇數，就一定可以回傳 `true`。

### 情況四：奇偶混合，而且最小值是偶數

例如：

```text
nums1 = [2, 3, 6]
min = 2
```

這是唯一失敗的情況。

#### 嘗試全部變成奇數

最小值 `2` 是偶數，若要把它變成奇數，必須減去一個更小的奇數。但 `2` 已經是陣列最小值，沒有任何更小的元素可供選擇，因此無法把 `2` 變成奇數。

#### 嘗試全部變成偶數

奇數 `3` 若要變成偶數，必須減去另一個比它小的奇數。但比 `3` 小的陣列元素只有偶數 `2`：

```text
3 - 2 = 1
```

結果仍然是奇數，奇偶性沒有改變。因為陣列中不存在比 `3` 更小的奇數，所以也無法把所有元素變成偶數。

兩種目標都無法達成，因此回傳 `false`。

## 核心回傳條件

```csharp
return min % 2 != 0 || !hasOdd;
```

可以拆成以下兩個成功條件：

1. `min % 2 != 0`：最小值是奇數，可以利用它把所有較大的偶數轉成奇數。
2. `!hasOdd`：陣列完全沒有奇數，代表所有元素原本就都是偶數。

只要其中一項成立，就能建構出奇偶性一致的 `nums2`。

將它翻成較直觀的分支寫法如下：

```csharp
public bool UniformArray(int[] nums1)
{
    int min = nums1.Min();
    bool hasOdd = nums1.Any(x => x % 2 != 0);

    if (min % 2 != 0)
    {
        return true;
    }

    if (!hasOdd)
    {
        return true;
    }

    return false;
}
```

兩種寫法的判斷結果完全相同。

## 所有情況整理

| 陣列情況 | 最小值 | `hasOdd` | 結果 |
|---|---:|---:|---:|
| 全部為偶數 | 偶數 | `false` | `true` |
| 全部為奇數 | 奇數 | `true` | `true` |
| 奇偶混合，最小值為奇數 | 奇數 | `true` | `true` |
| 奇偶混合，最小值為偶數 | 偶數 | `true` | `false` |

整題可以濃縮成一句話：

> 只有「最小值為偶數，而且陣列中存在奇數」時無法成功。

## 從失敗條件理解德摩根定律

唯一的失敗條件是：

```csharp
min % 2 == 0 && hasOdd
```

所以成功條件也可以寫成：

```csharp
return !(min % 2 == 0 && hasOdd);
```

根據德摩根定律：

```text
!(A && B) 等價於 !A || !B
```

套用到本題：

```text
!(min 是偶數 && 存在奇數)
```

等價於：

```text
min 是奇數 || 不存在奇數
```

因此：

```csharp
!(min % 2 == 0 && hasOdd)
```

與以下寫法完全等價：

```csharp
min % 2 != 0 || !hasOdd
```

## 單次迴圈版本

`Min()` 會走訪陣列一次，`Any()` 最壞情況也會再走訪一次。雖然整體時間複雜度仍然是 `O(n)`，但也可以在一次迴圈內同步取得最小值並記錄是否存在奇數：

```csharp
public bool UniformArray3(int[] nums1)
{
    int min = int.MaxValue;
    bool hasOdd = false;

    foreach (int num in nums1)
    {
        min = Math.Min(min, num);

        if (num % 2 != 0)
        {
            hasOdd = true;
        }
    }

    return min % 2 != 0 || !hasOdd;
}
```

這個版本與 LINQ 版本使用相同的判斷原理，只是將兩次資料收集合併成一次走訪。

## 複雜度分析

令 `n` 為 `nums1` 的長度：

- 時間複雜度：`O(n)`。需要走訪陣列以取得最小值並判斷是否存在奇數。
- 空間複雜度：`O(1)`。只使用 `min` 與 `hasOdd` 等固定數量的變數。

## 推導流程總結

```text
最小值無法透過第二種操作改變
        ↓
最小值的奇偶性限制了目標奇偶性
        ↓
最小值是奇數時，可用它把所有較大的偶數轉成奇數
        ↓
陣列全為偶數時，直接保留所有元素即可
        ↓
最小值是偶數且陣列中仍有奇數時，兩種統一方向都不可行
```

所以最終答案是：

```csharp
return min % 2 != 0 || !hasOdd;
```

真正重要的是理解「最小值無法改變奇偶性」，最後的布林判斷只是這項觀察的程式化結果。
