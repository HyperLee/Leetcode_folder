# LeetCode 856 — 括號的分數

本專案為 [LeetCode 856: Score of Parentheses](https://leetcode.com/problems/score-of-parentheses/description/) 的 C# 解題集，示範三種不同的演算法思路，並以 ASCII 圖逐步說明實際的資料與狀態變化。

---

## 題目說明

給定一個**平衡括號字串** `s`，依照以下規則計算並回傳其分數：

| 規則 | 分數 |
|------|------|
| `()` | `1` |
| `AB` | `score(A) + score(B)` |
| `(A)` | `2 × score(A)` |

其中 `A`、`B` 都是平衡括號字串。題目保證：

- `2 <= s.length <= 50`
- `s` 只包含 `(` 與 `)`。
- `s` 一定是平衡括號字串。

### 範例

```text
Input: "()"         -> Output: 1
Input: "(())"       -> Output: 2
Input: "()()"       -> Output: 2
Input: "(()(()))"   -> Output: 6
```

---

## 共通基礎：從括號規則到深度貢獻

題目規則可以先轉換成一個重要觀察：**每個最內層 `()` 的分數，會依照外面包了幾層括號而乘上對應次數的 2。**

例如：

```text
()          位於深度 0：1
(())        內層 () 位於深度 1：1 × 2 = 2
((()))      內層 () 位於深度 2：1 × 2 × 2 = 4
```

因此，位於深度 `k` 的最內層 `()`，對答案的貢獻就是：

```text
2^k
```

以 `"(()(()))"` 為例，將它依照最外層括號拆開：

```text
字串：(()(()))

        最外層包住整個內容，最後會乘以 2
             +-----------------+
             |  (  ()  (())  ) |
             +-----------------+
                |       |
                |       +-- (()) 的分數是 2
                +---------- () 的分數是 1

內部：1 + 2 = 3
整體：2 × 3 = 6
```

三種方法的差別，在於它們記錄這些「深度」與「中間分數」的方式不同：

- 方法一只記錄目前深度，不儲存中間分數。
- 方法二用堆疊保存每一層尚未完成的分數。
- 方法三直接依照 `(A)` 與 `A + B` 的規則遞迴拆解。

## 解題方法

### 方法一 — 位元位移深度計數

#### 核心想法

維護兩個整數：

- `cnt`：目前所在的括號深度。
- `score`：已經找到的所有最內層 `()` 貢獻總和。

掃描每個字元時：

1. 遇到 `(`，代表進入一層，`cnt++`。
2. 遇到 `)`，代表離開一層，`cnt--`。
3. 如果這個 `)` 前一個字元是 `(`，就代表剛好完成一個最內層 `()`。
4. 這時的 `cnt` 已經是該 `()` 外面包住的括號層數，所以加入 `1 << cnt`，也就是 `2^cnt`。

關鍵在於：**要先 `cnt--` 再計算貢獻。** 例如 `"(())"` 的內層 `()` 關閉後，`cnt` 從 2 降為 1；這個 1 才是它真正的外層包覆深度。

#### ASCII 狀態追蹤

以 `"(()(()))"` 為例。下方的 `深度` 表示「處理完該索引字元後」的深度：

下面的索引列只表示原始字串的**資料排列**；真正的演算法事件要看 `事件` 列，並不是依照圖上的字元順序重新排列資料。

```text
索引：  0   1   2   3   4   5   6   7
字元：  (   (   )   (   (   )   )   )

處理後
深度：  1   2   1   2   3   2   1   0
事件：  -   -  +2   -   -  +4   -   -
累計：  0   0   2   2   2   6   6   6
```

兩個加分事件分別是：

```text
i = 2：s[1] == '('，完成索引 [1..2] 的 "()"
      cnt = 1，貢獻 1 << 1 = 2

i = 5：s[4] == '('，完成索引 [4..5] 的 "()"
      cnt = 2，貢獻 1 << 2 = 4

總分 = 2 + 4 = 6
```

注意，索引 6 與 7 雖然也是 `)`，但它們前面是 `)`，不是新的最內層 `()`，所以不會重複加分。它們只代表把先前算好的結果向外層返回。

#### 與程式碼對應

```csharp
public int ScoreOfParentheses(string s)
{
    int score = 0, cnt = 0;

    for (int i = 0; i < s.Length; i++)
    {
        if (s[i] == '(')
        {
            cnt++;
        }
        else
        {
            cnt--;

            // 前一個字元是 '('，代表剛完成最內層 "()"
            if (s[i - 1] == '(')
            {
                score += 1 << cnt;
            }
        }
    }

    return score;
}
```

#### 為什麼正確？

每一個最內層 `()` 都只會在它的右括號被掃描時被辨識一次。此時 `cnt` 等於它外面包覆的括號數量，而題目規則表示每包一層就乘 2，因此該區塊的貢獻正好是 `2^cnt`。所有最內層 `()` 的貢獻相加，就是完整字串的分數。

#### 複雜度

| 項目 | 複雜度 | 原因 |
|------|--------|------|
| 時間 | `O(n)` | 字串只被從左到右掃描一次 |
| 空間 | `O(1)` | 只使用 `score`、`cnt`、`i` 等固定數量變數 |

### 方法二 — 堆疊模擬

#### 核心想法

把堆疊中的每個整數看成一個「括號層級的計分框架」：

- 初始的 `[0]` 是整個字串外面的累計分數。
- 遇到 `(`，開啟新的括號層，推入 `0` 等待計算內部內容。
- 遇到 `)`，關閉目前層級並合併回外層。

遇到右括號時：

```text
v = 目前括號內已累積的分數
w = 外層在這個括號之前已累積的分數
```

接著依規則計算目前這一對括號的貢獻：

```text
v == 0：代表內容是空的 "()"，貢獻 1
v > 0 ：代表內容是 A，貢獻 2 × v

新的外層分數 = w + max(2 × v, 1)
```

#### `v`、`w` 與兩次 `Pop()`

可以把一次右括號的處理，先簡化成下列堆疊狀態。堆疊方向仍是「左邊為底部，右邊為頂部」：

```text
[..., w, v]
```

每個字元的處理流程如下：

- 遇到 `(`：`Push(0)`，建立一個新的括號層級，等待累積內部內容。
- 遇到 `)`：依序 `Pop()` 出 `v` 與 `w`，計算後再 `Push()` 回堆疊。

程式中的兩次 `Pop()`：

```csharp
v = stack.Pop();   // 第一次 Pop：目前括號內的分數
w = stack.Pop();   // 第二次 Pop：外層同一層已累積的分數
```

因為堆疊採用後進先出（LIFO），所以頂端的 `v` 會先被取出，接著才取出下一層的 `w`。`Pop()` 本身只會取出並移除數值；真正的計算與累加發生在後續公式：

```text
目前括號的分數：
    v == 0 -> 1          // 內部是空串 "()"
    v > 0  -> 2 × v      // 內部是 A，套用 (A) = 2 × A

回填外層：
    w + max(2 × v, 1)
```

計算後，使用 `Push()` 將兩個框架合併成一個：

```text
[..., w, v]
    -> [..., w + max(2 × v, 1)]
```

因此，`w` 不是整個字串最後的答案，而是目前括號之前、同一外層的暫時小計；`v` 則是目前括號內已完成內容的小計。

以 `"()"` 為例：

```text
初始       [0]
遇到 '('   [0, 0]
遇到 ')'   v=0, w=0
           0 + max(2×0, 1) = 1
結果       [1]
```

以 `"()()"` 為例，第一個 `()` 完成後堆疊為 `[1]`。處理第二個 `)` 時：

```text
v=0, w=1
1 + max(2×0, 1) = 2
```

這個 `w=1` 就是第一個 `()` 留下的累計分數，因此最後得到 `1 + 1 = 2`。

#### ASCII 堆疊追蹤

以下以 `"(()(()))"` 示範。圖中堆疊方向固定為「左邊是底部，右邊是頂部」：

```text
處理前       stack（底 -> 頂）

初始         [0]

i=0 '('      [0, 0]
              ^       +-- 新開啟的括號框架
              +---------- 原本的外層框架

i=1 '('      [0, 0, 0]

i=2 ')'      v=0, w=0
              0 + max(2*0, 1) = 1
              [0, 1]

i=3 '('      [0, 1, 0]

i=4 '('      [0, 1, 0, 0]

i=5 ')'      v=0, w=0
              0 + max(2*0, 1) = 1
              [0, 1, 1]

i=6 ')'      v=1, w=1
              1 + max(2*1, 1) = 3
              [0, 3]

i=7 ')'      v=3, w=0
              0 + max(2*3, 1) = 6
              [6]

最後 stack.Peek() = 6
```

相鄰區塊 `"()()"` 則會呈現「先算第一段，再累加第二段」：

```text
[0]
 '(' -> [0, 0]
 ')' -> [1]
 '(' -> [1, 0]
 ')' -> [2]
```

這正好對應 `score("()") + score("()") = 1 + 1 = 2`。

#### 與程式碼對應

```csharp
public int ScoreOfParentheses2(string s)
{
    var stack = new Stack<int>();
    stack.Push(0);              // 整個字串外部的累計分數

    foreach (char c in s)
    {
        if (c == '(')
        {
            stack.Push(0);      // 開啟新的括號框架
        }
        else
        {
            int v = stack.Pop(); // 目前括號內的分數
            int w = stack.Pop(); // 外層已累積的分數

            stack.Push(w + Math.Max(2 * v, 1));
        }
    }

    return stack.Peek();
}
```

#### 堆疊不變量與正確性

掃描到任一位置時，堆疊中的每個元素都代表對應括號層級目前已完成的子字串分數。右括號會先完成最內層框架：空框架依規則得到 1，非空框架依規則乘 2，再加回外層。因此每次合併都符合題目三條規則，最後堆疊頂端就是整個字串的分數。

#### 複雜度

| 項目 | 複雜度 | 原因 |
|------|--------|------|
| 時間 | `O(n)` | 每個字元只推入或彈出固定次數 |
| 空間 | `O(n)` | 最深時堆疊會保存每一層括號框架 |

### 方法三 — 分治法

#### 核心想法

任何非空的平衡括號字串，都可以拆成以下兩種形式之一：

1. **`(A)`**：整個字串被同一對最外層括號包住。
2. **`A + B`**：字串由兩個或更多獨立的平衡括號字串相連。

用 `bal` 從左到右掃描：

- 遇到 `(`，`bal++`。
- 遇到 `)`，`bal--`。
- `bal` 第一次回到 0 的位置，就是第一個完整平衡前綴的結尾。

判斷方式如下：

```text
第一個 bal == 0 的位置剛好是字串結尾
    -> 整體是 (A)，答案 = 2 * score(A)

第一個 bal == 0 的位置早於字串結尾
    -> 整體是 A + B，答案 = score(A) + score(B)
```

#### ASCII 平衡值追蹤

先看完整字串 `"(()(()))"`：

```text
索引：  0   1   2   3   4   5   6   7
字元：  (   (   )   (   (   )   )   )
bal ：  1   2   1   2   3   2   1   0
                                      ^
                         第一次回到 0，len = 8 = n
```

因為 `len == n`，所以它是 `(A)`：去除最外層後，遞迴處理 `"()(())"`。

接著處理 `"()(())"`：

```text
字串：  (   )   (   (   )   )
索引：  0   1   2   3   4   5
bal ：  1   0   1   2   1   0
              ^
       len=2 < n，於是切成 A="()"、B="(())"
```

#### 遞迴樹

```text
Score("(()(()))")
+-- 2 * Score("()(())")                 // 外層是 (A)
|   +-- Score("()") = 1                  // A
|   +-- Score("(())")
|       +-- 2 * Score("()") = 2           // (A)

Score("()(())") = 1 + 2 = 3
Score("(()(()))") = 2 * 3 = 6
```

#### 與程式碼對應

```csharp
public int ScoreOfParentheses3(string s)
{
    if (s.Length == 2)
    {
        return 1;                       // 只可能是 "()"
    }

    int bal = 0, n = s.Length, len = 0;

    for (int i = 0; i < n; i++)
    {
        bal += (s[i] == '(' ? 1 : -1);

        if (bal == 0)
        {
            len = i + 1;                // 第一個完整平衡前綴
            break;
        }
    }

    if (len == n)
    {
        // s 是 (A)，移除最外層後乘 2
        return 2 * ScoreOfParentheses3(s.Substring(1, n - 2));
    }

    // s 是 A+B，分別計算後相加
    return ScoreOfParentheses3(s.Substring(0, len))
         + ScoreOfParentheses3(s.Substring(len));
}
```

`len` 是長度而不是最後索引，因此：

- `s.Substring(0, len)` 取得前綴 `A`。
- `s.Substring(len)` 取得剩餘部分 `B`。
- `(A)` 情況使用 `s.Substring(1, n - 2)`，移除索引 0 與索引 `n - 1` 的外層括號。

#### 為什麼正確？

第一個 `bal == 0` 代表前綴已經完整閉合；在它之前不可能再分割出另一個完整的平衡字串。因此，如果這個位置是結尾，整體只能是 `(A)`；如果不是結尾，前綴與剩餘部分必定是 `A + B`。遞迴依照題目對應規則計算，長度為 2 時則直接套用 `score("()") = 1`。

#### 複雜度

| 項目 | 複雜度 | 說明 |
|------|--------|------|
| 時間 | `O(n²)` 最壞 | 每層遞迴都可能重新掃描剩餘字串 |
| 遞迴深度 | `O(n)` | 最深可能是一層包一層 |
| 實際字串配置 | 最壞 `O(n²)` | 目前實作使用 `Substring`，每層會建立新的字串內容 |

若只討論抽象的遞迴框架，常會把空間寫成遞迴深度 `O(n)`；但本專案的 C# 實作確實呼叫 `Substring`，因此 README 同時標示實際字串配置成本。

## 正確性與邊界案例

三種方法都依賴題目保證輸入是平衡括號字串，因此不需要額外處理無效輸入。下列案例涵蓋主要結構：

| 輸入 | 結構 | 用來驗證 |
|------|------|----------|
| `"()"` | 基本單元 | 方法三的遞迴基底、方法一的深度 0 |
| `"(())"` | 單層巢狀 | `(A)` 會乘以 2 |
| `"()()"` | 相鄰串接 | `A + B` 會相加 |
| `"(()(()))"` | 巢狀與串接混合 | 深度、堆疊、分治都要正確配合 |

常見的理解錯誤：

- 方法一的 `cnt` 是**處理完右括號後**的外層深度，不是右括號處理前的深度。
- 方法一只有在 `s[i - 1] == '('` 時加分，外層右括號不能再次把同一個結果加進去。
- 方法二的 `v == 0` 表示空內容 `()`，不是分數為 0 的一般括號內容。
- 方法三要找的是**第一個** `bal == 0`，不是最後一個；第一個完整前綴才能判斷 `A + B` 的切點。

## 方法比較

| 方法 | 時間 | 空間 | 核心資料結構 | 適用情境 |
|------|------|------|--------------|----------|
| 一 — 位元位移 | `O(n)` | `O(1)` | 深度與累計變數 | 追求最少記憶體 |
| 二 — 堆疊 | `O(n)` | `O(n)` | `Stack<int>` | 直觀模擬括號層級 |
| 三 — 分治 | `O(n²)` | 遞迴深度 `O(n)`；目前 `Substring` 配置最壞 `O(n²)` | 遞迴與子字串 | 對應題目遞迴定義、理解結構 |

選擇建議：

- 若只在意效率與空間，選擇方法一。
- 若希望清楚表示每個括號層級的中間分數，方法二最直觀。
- 若想從題目的三條定義直接推導演算法，方法三最容易理解，但效率較低。
