# LeetCode 150：逆波蘭表示法求值

![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4)

以 C# 與 `Stack<int>` 實作 LeetCode 150
[Evaluate Reverse Polish Notation](https://leetcode.com/problems/evaluate-reverse-polish-notation/)。
專案提供六組可直接執行的案例，逐筆比較預期值與實際值，適合作為理解 Stack
與後綴運算式求值流程的教學範例。

## 題目說明

給定一個字串陣列 `tokens`，內容是一個有效的逆波蘭表示法
（Reverse Polish Notation，RPN）運算式。請依序計算運算式，回傳整數結果。

可使用的運算子如下：

- `+`：加法
- `-`：減法
- `*`：乘法
- `/`：整數除法，結果向零截斷

逆波蘭表示法將運算子放在運算元之後，因此不需要括號或額外的優先序規則。
例如：

```text
["2", "1", "+", "3", "*"]
```

等價於一般中序表示法的 `(2 + 1) * 3`，結果為 `9`。

## 限制條件

依照題目限制：

- `1 <= tokens.Length <= 10^4`
- 每個 token 是 `+`、`-`、`*`、`/`，或介於 `-200` 到 `200` 的整數
- 輸入一定是有效的逆波蘭表示法運算式
- 不會發生除以零
- 答案與所有中間計算結果都可用 32 位元整數表示

## 解題概念與出發點

### 為什麼使用 Stack？

從左到右掃描 RPN 時，數字可能要等到後面的運算子出現才會被使用。
Stack 的後進先出特性正好符合需求：

1. 遇到數字時，先推入 Stack。
2. 遇到運算子時，最近加入的兩個數字就是這次運算所需的運算元。
3. 將計算結果推回 Stack，讓它成為後續運算的一部分。
4. 所有 token 處理完成後，Stack 中唯一的數字就是答案。

在掃描過程中，Stack 保存的是「已完成解析，但尚未被後續運算子消耗」的子運算式結果。
這個不變量使巢狀運算式也能用相同規則逐步化簡。

## 解法一：Stack 逐步求值

### 設計說明

`EvalRPN(string[] tokens)` 建立一個 `Stack<int>`，並依序處理每個 token：

- `IsNumber(token)` 透過最後一個字元是否為數字來辨識運算元。
  題目保證 token 只會是有效整數或四種運算子，因此 `"12"`、`"0"` 與
  `"-11"` 都會被正確判定為數字，運算子的最後一個字元則不會是數字。
- 數字使用 `int.Parse` 轉型後推入 Stack。
- 遇到運算子時，第一次 `Pop()` 取得右運算元 `num2`，第二次 `Pop()`
  取得左運算元 `num1`，再計算 `num1 operator num2`。
- 計算結果重新推入 Stack，供下一個運算子使用。
- 掃描結束後，彈出 Stack 中唯一的值並回傳。

> [!IMPORTANT]
> 減法與除法不符合交換律，兩次 `Pop()` 的順序不能顛倒。例如
> `["7", "-3", "/"]` 必須計算 `7 / -3`，而不是 `-3 / 7`。

### 正確性說明

每處理完一個 token，Stack 由下到上保存目前所有尚未被消耗的運算元或已完成的
子運算式結果：

- 若 token 是數字，將它推入 Stack 後，不變量仍成立。
- 若 token 是運算子，有效 RPN 保證 Stack 至少有兩個值。彈出右、左運算元並
  推回計算結果，相當於將一個完整子運算式縮減成它的值，因此不變量仍成立。
- 當所有 token 都處理完成，有效運算式只會留下整體運算結果。

所以 `EvalRPN` 回傳的值就是輸入運算式的正確結果。

### 複雜度

- 時間複雜度：`O(n)`，每個 token 只處理一次。
- 空間複雜度：`O(n)`，最壞情況下 Stack 會暫存線性數量的運算元。

## 範例演示流程

### 範例一：加法結果再參與乘法

輸入：

```text
["2", "1", "+", "3", "*"]
```

下表的 Stack 由左至右表示「底部到頂部」：

| Token | 動作 | Stack |
| --- | --- | --- |
| `"2"` | 推入 `2` | `[2]` |
| `"1"` | 推入 `1` | `[2, 1]` |
| `"+"` | 取出右值 `1`、左值 `2`，推入 `2 + 1 = 3` | `[3]` |
| `"3"` | 推入 `3` | `[3, 3]` |
| `"*"` | 取出右值 `3`、左值 `3`，推入 `3 * 3 = 9` | `[9]` |

最後只剩 `9`，因此答案為 `9`。

### 範例二：負數與向零截斷

輸入：

```text
["7", "-3", "/"]
```

| Token | 動作 | Stack |
| --- | --- | --- |
| `"7"` | 推入 `7` | `[7]` |
| `"-3"` | 最後一個字元是數字，因此推入負整數 `-3` | `[7, -3]` |
| `"/"` | 計算 `7 / -3`，C# 整數除法向零截斷為 `-2` | `[-2]` |

## 可執行案例

| 案例 | Tokens | 預期結果 | 驗證重點 |
| --- | --- | ---: | --- |
| 1 | `["2", "1", "+", "3", "*"]` | `9` | 加法結果接續乘法 |
| 2 | `["4", "13", "5", "/", "+"]` | `6` | 整數除法與加法 |
| 3 | `["10", "6", "9", "3", "+", "-11", "*", "/", "*", "17", "+", "5", "+"]` | `22` | 巢狀運算與負數 |
| 4 | `["5"]` | `5` | 最小合法輸入 |
| 5 | `["3", "-4", "+"]` | `-1` | 負數運算元 |
| 6 | `["7", "-3", "/"]` | `-2` | 負數除法向零截斷 |
