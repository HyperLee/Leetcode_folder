## 題目說明

給定一個 `m x n` 二元矩陣 `matrix`。一次操作可以選擇任意一欄，並翻轉該欄
的每個值，也就是將 `0` 變成 `1`、將 `1` 變成 `0`。可以選擇任意數量的欄，
也可以完全不翻轉。

目標是找出一組欄翻轉方式，使盡可能多的列在操作後成為「列內所有值都相等」：
該列可以全部是 `0`，也可以全部是 `1`。回傳能同時符合條件的最大列數。

### 官方範例一

```text
輸入：matrix = [[0,1],[1,1]]
輸出：1
```

不翻轉任何欄時，第二列 `[1,1]` 已經符合條件；不存在能讓兩列同時符合條件的
翻轉方式，因此答案為 `1`。

### 官方範例二

```text
輸入：matrix = [[0,1],[1,0]]
輸出：2
```

兩列互為補數。翻轉第一欄後，矩陣變成 `[[1,1],[0,0]]`，兩列雖然值不同，
但各自的列內元素都相等，因此答案為 `2`。

### 官方範例三

```text
輸入：matrix = [[0,0,0],[0,0,1],[1,1,0]]
輸出：2
```

第二列 `[0,0,1]` 與第三列 `[1,1,0]` 互為補數。翻轉前兩欄後，兩列會分別
成為 `[1,1,1]` 與 `[0,0,0]`，所以最多能讓兩列符合條件。

## 限制條件

依 [LeetCode 1072 官方題面](https://leetcode.com/problems/flip-columns-for-maximum-number-of-equal-rows/description/)：

- `m == matrix.length`
- `n == matrix[i].length`
- `1 <= m, n <= 300`
- `matrix[i][j]` 只會是 `0` 或 `1`

三個公開解法均依循正式題目契約：矩陣非 `null`、至少包含一列與一欄、每列等長，
且所有元素皆為二元值。三種解法只讀取矩陣，不會改動任何列或元素。

## 解題概念與出發點

### 1. 同一組欄翻轉會作用於所有列

不能替每一列選擇不同的翻轉方式。若翻轉集合是 `F`，每一列都會在相同欄位被
翻轉。因此真正要找的不是「每列能否獨立變成全相等」，而是「哪些列能共用同一組
翻轉欄位」。

### 2. 能共用翻轉方式的兩列必須完全相同或完全互補

假設某列在操作後成為全 `0`，那麼翻轉欄位就由該列原本為 `1` 的位置決定。
另一列若要使用同一組翻轉：

- 想變成全 `0`，原始內容必須與第一列完全相同。
- 想變成全 `1`，原始內容必須與第一列逐位互補。

例如 `001` 與 `110` 互為補數，可以共用同一組欄翻轉；`001` 與 `100` 則既不
相同也不互補，不能同時達成列內全相等。

這個關係把所有列劃分成數個等價類。答案就是最大等價類的大小。

### 3. 使用首元素將相同列與互補列正規化

對一列 `row` 的每個位置計算：

```text
normalized[j] = row[j] XOR row[0]
```

正規化後的第一位一定是 `0`。若原列以 `0` 開頭，模式保持不變；若以 `1`
開頭，整列會被取反。於是原列與其互補列會得到完全相同的正規化模式：

```text
row = 001  →  001 XOR 0 = 001
row = 110  →  110 XOR 1 = 001
```

解法一與解法三利用這個模式直接分組；解法二則不建立模式，而是在比較兩列時確認
每一欄的 XOR 關係是否一致。

## 解法一：XOR 正規化與字串雜湊

### 設計說明

`MaxEqualRowsAfterFlips` 保留原有解題方向，將每列正規化後轉成字串，使用
`Dictionary<string, int>` 統計模式：

1. 建立與目前列同長的 `char[]`。
2. 對每一欄計算 `row[column] ^ row[0]`，再轉成字元 `'0'` 或 `'1'`。
3. 將字元陣列轉成不可變字串，作為字典 key。
4. 增加該模式的出現次數，持續更新最大值。

字串提供內建的內容雜湊與相等比較，程式短而直接，適合作為正式提交版本。

### 正確性說明

相同列逐位與各自首元素 XOR 後，必然得到相同模式。互補列的每一位與首元素都
同時取反，兩者 XOR 結果不變，因此也得到相同模式。反之，若兩列正規化模式相同，
它們每一欄相對於首元素的關係完全一致；兩列首元素相同時原列完全相同，不同時則
原列完全互補。因此每個字典 key 恰好代表一個可共用翻轉方式的等價類，最大的計數
就是答案。

### 複雜度

- 時間複雜度：`O(m * n)`。
- 額外空間複雜度：最壞 `O(m * n)`，用於保存不同模式的字串。
- 是否修改輸入：否。

### 範例演示流程

以 `matrix = [[0,1],[1,0]]` 為例：

```text
第 1 列 [0,1]：
    首元素 = 0
    [0 XOR 0, 1 XOR 0] = [0,1]
    key = "01"，count = 1

第 2 列 [1,0]：
    首元素 = 1
    [1 XOR 1, 0 XOR 1] = [0,1]
    key = "01"，count = 2
```

兩列落在同一個 key，最大計數為 `2`。

## 解法二：逐列等同或互補比較

### 設計說明

`MaxEqualRowsAfterFlips2` 不建立字典或其他索引，而是直接檢查每個可能的等價類：

1. 依序選擇一列作為 `baseRow`。
2. 對每個 `candidateRow`，先計算兩列第一欄的 XOR，得到預期關係：
   - `0` 表示兩列應在每一欄都相同。
   - `1` 表示兩列應在每一欄都互補。
3. 掃描剩餘欄位；只要某欄的 XOR 不等於預期關係，立即停止比較。
4. 統計與基準列等同的列數，取所有基準列中的最大值。

這個版本的效能較低，但不需要先理解雜湊或 Trie，最直接展示「完全相同或完全互補」
是合法分組的充要條件。

### 正確性說明

若兩列每一欄的 XOR 都是 `0`，它們完全相同；若每一欄的 XOR 都是 `1`，它們
完全互補，兩種情況都能共用翻轉方式。只要 XOR 關係在某欄改變，兩列就不是完整
相同或完整互補，不能屬於同一等價類。演算法會把每個實際存在的列都當一次基準，
因此一定會計算到最大等價類，並回傳其大小。

### 複雜度

- 時間複雜度：最壞 `O(m² * n)`。
- 額外空間複雜度：`O(1)`。
- 是否修改輸入：否。

### 範例演示流程

同樣使用 `matrix = [[0,1],[1,0]]`，以第一列為基準：

```text
比較 [0,1] 與 [0,1]：
    第一欄 XOR = 0，第二欄 XOR = 0
    關係一致 → 完全相同，計數 +1

比較 [0,1] 與 [1,0]：
    第一欄 XOR = 1，第二欄 XOR = 1
    關係一致 → 完全互補，計數 +1
```

第一列的等價類共有 `2` 列，因此答案為 `2`。

## 解法三：XOR 正規化與二元 Trie

### 設計說明

`MaxEqualRowsAfterFlips3` 使用與解法一相同的 XOR 正規化，但不配置字串 key，
而是把每個正規化位元當作 Trie 的一層：

1. 從 Trie 根節點開始。
2. 對目前列的每一欄計算正規化位元。
3. 位元為 `0` 時走 `Zero` 子節點，為 `1` 時走 `One` 子節點；分支不存在就建立。
4. 走完整列後才增加終端節點的 `Count`。
5. 所有終端節點的最大計數就是答案。

Trie 讓共同前綴共用節點，並明確呈現二元模式的路徑結構，適合對照「完整字串作為
key」與「逐位建立索引」兩種資料結構設計。

### 正確性說明

由正規化性質可知，同一等價類的列會產生相同位元序列，因此必然沿相同 Trie 路徑
抵達同一終端節點。不同等價類至少有一個正規化位元不同，會在該層走向不同分支，
不會共享完整路徑。終端節點 `Count` 因而恰好等於一個等價類的列數，最大終端計數
就是正確答案。

### 複雜度

- 時間複雜度：`O(m * n)`。
- 額外空間複雜度：最壞 `O(m * n)` 個 Trie 節點。
- 是否修改輸入：否。

### 範例演示流程

對 `matrix = [[0,1],[1,0]]`：

```text
[0,1] 正規化為 01：
    root → Zero → One
    終端 Count = 1

[1,0] 正規化為 01：
    root → 已存在的 Zero → 已存在的 One
    終端 Count = 2
```

相同模式會重走既有路徑，終端最大計數為 `2`。

## 三種解法比較

| 項目 | 解法一：字串雜湊 | 解法二：逐列比較 | 解法三：二元 Trie |
|:---|:---|:---|:---|
| 核心方法 | 正規化模式作為字典 key | 直接確認每欄 XOR 關係 | 正規化模式作為 Trie 路徑 |
| 時間複雜度 | `O(m * n)` | `O(m² * n)` | `O(m * n)` |
| 額外空間 | `O(m * n)` | `O(1)` | `O(m * n)` |
| 是否修改輸入 | 否 | 否 | 否 |
| 優點 | 精簡、使用標準集合、適合提交 | 思路最直觀、無額外集合 | 展示逐位索引與前綴共用 |
| 取捨 | 每列建立字元陣列與字串 | 列數增大時比較成本高 | 節點物件與實作複雜度較高 |

若以正式提交為目標，解法一通常最平衡；解法二適合先建立正確性直覺；解法三則適合
學習如何把固定長度二元模式映射到 Trie。
