# 3882. 網格圖中的最小 XOR 路徑

[![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4?logo=dotnet&logoColor=white)](https://dotnet.microsoft.com/)
[![C#](https://img.shields.io/badge/C%23-C%23-239120?logo=csharp&logoColor=white)](https://learn.microsoft.com/dotnet/csharp/)

[LeetCode 3882. Minimum XOR Path in a Grid](https://leetcode.com/problems/minimum-xor-path-in-a-grid/description/) 的 C# 解題實作，包含動態規劃與記憶化 DFS 兩種方法。程式入口會執行題目範例、單格案例與 10 位元上界案例，方便直接確認結果。

## 題目說明

給定一個 `m × n` 的整數網格，從左上角 `(0, 0)` 出發，每一步只能向右或向下，最後抵達右下角 `(m - 1, n - 1)`。一條路徑的成本是路徑上所有格子值的位元 XOR，起點和終點都要計入。請找出所有合法路徑中最小的 XOR 值。

| 限制 | 條件 |
| --- | --- |
| 列數 | `1 <= m <= 1000` |
| 欄數 | `1 <= n <= 1000` |
| 總格數 | `m * n <= 1000` |
| 格子值 | `0 <= grid[i][j] <= 1023` |

每個格子值最多使用 10 個位元，因此路徑 XOR 的可能值介於 `0` 到 `1023`。

### 題目範例

| 範例 | `grid` | 最小 XOR |
| --- | --- | ---: |
| 1 | `[[1, 2], [3, 4]]` | `6` |
| 2 | `[[6, 7], [5, 8]]` | `9` |
| 3 | `[[2, 7, 5]]` | `0` |

## 解題概念與出發點

XOR 不像一般加法，保留到目前為止最小的前綴值，未必能得到終點的最小值。例如後續 XOR 某個數字時，較大的前綴 XOR 可能反而消掉更多位元。因此每個格子都需要保留「所有可到達的 XOR 值」，而不是只保留其中最小的一個。

格子值最多 1023，整條路徑的 XOR 也只會是 `0..1023` 之一。這個有限狀態範圍讓每個格子至多管理 1024 個 XOR 狀態：動態規劃逐格傳遞可行狀態；DFS 則用「目前格子與路徑 XOR」作為狀態避免重複搜尋。

## 解法一：壓縮狀態動態規劃

### 狀態與轉移

- `dp[j][x]` 表示目前掃描位置的第 `j` 欄，是否存在一條到達該格且 XOR 為 `x` 的路徑。
- 由左到右掃描每一列時，`dp[j]` 尚未更新前保存上方格子的狀態；`dp[j - 1]` 已保存本列左方格子的狀態。
- 對每個可從上方或左方到達的 XOR 值 `x`，將目前格子的值 `v` 加入路徑，新的狀態為 `x ^ v`。
- 使用暫存陣列 `next` 收集新狀態，避免在轉移時覆寫仍要讀取的來源狀態，再複製回 `dp[j]`。
- 起點先初始化為 `dp[0][grid[0][0]] = true`；處理完終點後，第一個可達的 XOR 值就是答案。

### 範例演示：`grid = [[1, 2], [3, 4]]`

依照由上到下、每列由左到右的順序處理：

1. 起點 `(0, 0)` 的值是 `1`，可達 XOR 集合為 `{1}`。
2. `(0, 1)` 從左方到達：`1 ^ 2 = 3`，集合為 `{3}`。
3. `(1, 0)` 從上方到達：`1 ^ 3 = 2`，集合為 `{2}`。
4. 終點 `(1, 1)` 可以從上方或左方到達：`3 ^ 4 = 7`、`2 ^ 4 = 6`，集合為 `{6, 7}`。
5. 取最小值，答案為 `6`。

### 複雜度

- 時間：`O(m * n * 1024)`。每個格子都檢查最多 1024 個 XOR 狀態。
- 空間：`O(n * 1024)`。每欄保存 1024 個布林狀態，另有一個長度為 1024 的暫存陣列。

## 解法二：反向 DFS 與狀態去重

### 狀態與搜尋方式

原本的路徑只能向右或向下，因此從終點反向搜尋時，只需向上或向左移動。DFS 狀態 `(i, j, xor)` 中的 `xor` 是終點到目前格子的後綴 XOR，但尚未包含目前格子的值。

每次進入一格時，先記錄 `(i, j, xor)` 已拜訪，再計算 `xor ^ grid[i][j]` 並遞迴至上方和左方。相同格子若帶著相同的後綴 XOR 再次出現，往起點延伸後會得到相同結果，因此可以略過重複狀態。

`visited` 第三維使用 `orAll + 1`：`orAll` 是整張網格所有值的位元 OR，任何路徑 XOR 只會包含這些位元，因此其數值不會大於 `orAll`，第三維最多 1024。當找到答案 `0` 時可停止搜尋，因為不可能有比 0 更小的 XOR 值。

### 範例演示：`grid = [[1, 2], [3, 4]]`

從終點 `(1, 1)` 開始，初始後綴 XOR 為 `0`：

1. 加入終點值 `4`，目前 XOR 為 `0 ^ 4 = 4`。
2. 向上至 `(0, 1)`，加入 `2` 後為 `4 ^ 2 = 6`；再到起點加入 `1`，得到路徑 XOR `6 ^ 1 = 7`。
3. 回到終點的另一個分支，向左至 `(1, 0)`，加入 `3` 後為 `4 ^ 3 = 7`；再到起點加入 `1`，得到路徑 XOR `7 ^ 1 = 6`。
4. 兩條路徑 XOR 分別為 `7` 和 `6`，最小值為 `6`。

### 複雜度

令 `S = orAll + 1`，且 `S <= 1024`：

- 時間：`O(m * n * S)`。每個格子與後綴 XOR 的組合至多探索一次，每個狀態最多走向上方和左方。
- 空間：`O(m * n * S)` 儲存拜訪狀態，另有最多 `O(m + n)` 的遞迴呼叫堆疊。
