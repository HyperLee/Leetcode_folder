## 題目說明

有 `n` 位士兵依序站成一列，第 `i` 位士兵的評分為 `rating[i]`，而且每個評分都不相同。需要選擇三個索引 `i`、`j`、`k`，並同時滿足：

```text
0 <= i < j < k < n
```

評分還必須呈現同一個嚴格單調方向：

```text
rating[i] < rating[j] < rating[k]
```

或：

```text
rating[i] > rating[j] > rating[k]
```

同一位士兵可以出現在不同隊伍中。程式要回傳所有有效三人隊伍的數量。

題目來源：[LeetCode 1395. Count Number of Teams](https://leetcode.com/problems/count-number-of-teams/description/)

## 限制條件

- `n == rating.Length`
- `3 <= n <= 1000`
- `1 <= rating[i] <= 100000`
- `rating` 中的所有整數皆互不相同

因此正式輸入不包含空陣列、少於三人的陣列或重複評分；兩個解法都依照這項題目契約運作，不額外處理非法輸入。

## 解題概念與出發點

一支隊伍由三個保持原始站位順序的索引組成。最直接的想法是列出所有 `(i, j, k)` 再檢查評分；進一步觀察則會發現，每支有效隊伍都只有一個中間索引 `j`，所以也能固定 `j`，分別計算左右兩側可與它配對的人數。

| 方法 | 核心問題 | 時間複雜度 | 額外空間 |
| --- | --- | --- | --- |
| `NumTeams` | 每個三人組合是否嚴格遞增或遞減？ | O(n³) | O(1) |
| `NumTeams2` | 固定中間點後，左右各有多少合法選擇？ | O(n²) | O(1) |

兩種方法都只讀取 `rating`，不會排序或修改輸入陣列。

## 解法一：三層枚舉

### 設計說明

`NumTeams` 使用三層迴圈直接建立所有索引三元組：

1. 第一層選擇左側索引 `i`。
2. 第二層從 `i + 1` 開始選擇中間索引 `j`。
3. 第三層從 `j + 1` 開始選擇右側索引 `k`。
4. 迴圈範圍本身已保證 `i < j < k`，因此判斷式只需要確認三個評分是否嚴格遞增或嚴格遞減。
5. 每找到一個有效組合，就把結果加一。

這個方法幾乎是題目定義的直接翻譯，容易理解與驗證，適合作為基準解法。缺點是組合數量會隨輸入長度以三次方成長。

### 正確性直覺

每一組合法索引 `(i, j, k)` 都會被三層迴圈恰好走訪一次。判斷式接受且只接受嚴格遞增或嚴格遞減的評分，因此不會漏掉有效隊伍，也不會重複或錯誤計入其他組合。

### 範例演示

輸入 `rating = [2, 5, 3, 4, 1]` 時，共有 `C(5, 3) = 10` 種索引組合：

| 索引 `(i,j,k)` | 評分 | 判斷 |
| --- | --- | --- |
| `(0,1,2)` | `(2,5,3)` | 無效 |
| `(0,1,3)` | `(2,5,4)` | 無效 |
| `(0,1,4)` | `(2,5,1)` | 無效 |
| `(0,2,3)` | `(2,3,4)` | 遞增，有效 |
| `(0,2,4)` | `(2,3,1)` | 無效 |
| `(0,3,4)` | `(2,4,1)` | 無效 |
| `(1,2,3)` | `(5,3,4)` | 無效 |
| `(1,2,4)` | `(5,3,1)` | 遞減，有效 |
| `(1,3,4)` | `(5,4,1)` | 遞減，有效 |
| `(2,3,4)` | `(3,4,1)` | 無效 |

最後得到 `3` 支有效隊伍。

## 解法二：枚舉中間點

### 設計說明

`NumTeams2` 固定中間索引 `j`。對每個 `j`，分別統計：

- `leftLowerCount`：左側比 `rating[j]` 低的人數。
- `leftHigherCount`：左側比 `rating[j]` 高的人數。
- `rightLowerCount`：右側比 `rating[j]` 低的人數。
- `rightHigherCount`：右側比 `rating[j]` 高的人數。

接著利用乘法原理：

```text
遞增隊伍數 = leftLowerCount * rightHigherCount
遞減隊伍數 = leftHigherCount * rightLowerCount
```

兩者相加就是以目前 `j` 為中間成員的有效隊伍數。`j` 只需從索引 `1` 走到 `n - 2`，因為中間點左右都必須至少保留一位士兵。

### 正確性直覺

任何有效隊伍都有唯一的中間索引 `j`。遞增隊伍必定由一個左側較低評分與一個右側較高評分組成；遞減隊伍則相反。左右選擇彼此獨立，所以兩側數量相乘會恰好列出所有以該 `j` 為中心的隊伍。逐一處理所有 `j` 後，每支隊伍只會被計算一次。

### 範例演示

同樣使用 `rating = [2, 5, 3, 4, 1]`：

| `j` | `rating[j]` | 左低 | 左高 | 右低 | 右高 | 本輪貢獻 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `1` | `5` | `1` | `0` | `3` | `0` | `1×0 + 0×3 = 0` |
| `2` | `3` | `1` | `1` | `1` | `1` | `1×1 + 1×1 = 2` |
| `3` | `4` | `2` | `1` | `1` | `0` | `2×0 + 1×1 = 1` |

將每輪貢獻相加：`0 + 2 + 1 = 3`。
