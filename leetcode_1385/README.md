## 題目與限制

題目：[1385. Find the Distance Value Between Two Arrays](https://leetcode.com/problems/find-the-distance-value-between-two-arrays/description/)／[中文題目](https://leetcode.cn/problems/find-the-distance-value-between-two-arrays/description/)。

給定整數陣列 `arr1`、`arr2` 與整數 `d`，計算 `arr1` 中有多少個元素，與 `arr2` **每一個**元素的絕對差都嚴格大於 `d`。

```text
x 可以計數 <=> 對所有 y in arr2，|x - y| > d
x 必須排除 <=> 存在某個 y in arr2，|x - y| <= d
```

距離值是符合條件的「元素個數」，不是兩陣列的最小差值或差值總和。相同數值在 `arr1` 出現多次時，每次出現都獨立計數；絕對差恰等於 `d` 時必須排除。

官方輸入限制：

| 項目 | 範圍 |
| --- | --- |
| `arr1.Length`、`arr2.Length` | `1` 至 `500` |
| `arr1[i]`、`arr2[j]` | `-1000` 至 `1000` |
| `d` | `0` 至 `100` |

方法假設輸入符合上述限制，不另做 `null` 或其他無效輸入驗證。差值介於 `-2000` 至 `2000`，本題使用 `int` 與 `Math.Abs` 可安全計算；不能直接將此安全性推廣到任意 `int` 輸入。

### 官方範例

| 範例 | arr1 | arr2 | d | 輸出 | 符合元素 |
| --- | --- | --- | --- | --- | --- |
| 一 | `[4,5,8]` | `[10,9,1,8]` | 2 | 2 | `4、5` |
| 二 | `[1,4,2,3]` | `[-4,-3,6,10,20,30]` | 3 | 2 | `1、2` |
| 三 | `[2,1,100,3]` | `[-5,-2,10,-3,7]` | 6 | 1 | `100` |

以範例一為例：

```text
               對 arr2 = [10, 9, 1, 8] 的絕對差
x = 4                  [ 6, 5, 3, 4]  全部 > 2 -> 計數
x = 5                  [ 5, 4, 4, 3]  全部 > 2 -> 計數
x = 8                  [ 2, 1, 7, 0]  存在 <=2 -> 排除
                                                  答案 = 2
```

## 解題出發點

對固定的 `x`，題目要求的是一連串條件的 AND：

```text
(|x - arr2[0]| > d) AND ... AND (|x - arr2[m-1]| > d)
```

因此有四個自然的實作方向：

1. 直接尋找不符合條件的反例，找到就停止：解法一。
2. 完整走訪所有比較，把條件累積成一個布林值：解法二。
3. 排序後只找距離最近的候選元素，省略其他比較：解法三。
4. 將排除條件改寫為封閉區間，搜尋左界後檢查是否有元素落在區間內：解法四。

四種方法皆使用 `int[] arr1, int[] arr2, int d` 作為參數並回傳 `int`。方法名稱分別為 `FindTheDistanceValue`、`FindTheDistanceValue2`、`FindTheDistanceValue3`、`FindTheDistanceValue4`，均為 `Program` 的實例方法。

## 解法一：雙迴圈與提前停止

### 設計與正確性

對每個 `x` 將 `isValid` 設為 `true`，依序檢查 `arr2`。一旦發現 `Math.Abs(x - y) <= d`，就將旗標設為 `false` 並 `break`。題目要求所有比較都合格，一個反例就足以決定排除，剩下的比較不可能挽回結果。

若走完內層迴圈後旗標仍為 `true`，代表沒有任何反例，將 `cnt` 加一。每次外層迴圈只決定目前元素是否計數，因此結束時 `cnt` 就是距離值。兩個輸入陣列都不會被修改。

### ASCII 流程

```text
取出下一個 x，isValid = true
          |
          v
    還有下一個 y？ ----- no ----> isValid 為 true？
          | yes                         | yes -> cnt++
          v                             | no  -> 不計數
     |x - y| <= d？                     v
      | no      | yes              下一個 x
      |         v
      |    isValid = false
      |    break -> 不計數 -> 下一個 x
      v
   比較下一個 y
```

### 範例一逐步演示

| x | 比較過程（依原始 arr2 順序） | 結果 | 累計 cnt |
| --- | --- | --- | --- |
| 4 | `6>2 → 5>2 → 3>2 → 4>2` | 無反例 | 1 |
| 5 | `5>2 → 4>2 → 4>2 → 3>2` | 無反例 | 2 |
| 8 | `abs(8-10)=2 <= 2`，立即停止 | 排除 | 2 |

對 `x=8`，本解法不會繼續計算與 `9、1、8` 的距離。最差情況仍需完成每一對元素的比較，但遇到反例較早時可以節省工作。

## 解法二：雙迴圈與布林累積

### 設計與正確性

保留完整雙迴圈，將「所有距離都必須大於 `d`」直接翻譯成布林 AND：

```csharp
bool isValid = true;
foreach (int y in arr2)
{
    isValid &= Math.Abs(x - y) > d;
}
cnt += isValid ? 1 : 0;
```

`true` 是 AND 的初始值：第一個條件可直接決定目前旗標；每處理一個 `y`，旗標表示「目前處理過的所有比較是否都成立」。迴圈結束時，這個意義就涵蓋整個 `arr2`。

### `&=`、`&&` 與 `?:` 的差異

對這裡的布林區域變數而言：

```text
isValid &= condition
等同於
isValid = isValid & condition
```

`&` 在兩邊都是 `bool` 時表示邏輯 AND，不是對整數做位元 AND。真值表如下：

| 原本 isValid | 本次條件 | 更新後 isValid |
| --- | --- | --- |
| true | true | true |
| true | false | false |
| false | true | false |
| false | false | false |

`false` 一旦出現就會保留，這正好符合「有任一反例就排除」的需求。

- `&`、`&=` **不短路**：即使旗標已經是 `false`，本次右側距離運算仍會執行。
- `&&` **短路**：左側為 `false` 時，右側不求值；但這不會自行結束外層或內層迴圈。
- `isValid ? 1 : 0` 是條件運算子：為 `true` 時選 `1`，否則選 `0`。它將有效旗標轉換成計數增量。

所以解法二與解法一答案相同，但不具有解法一的提前 `break`。寫法更直接呈現邏輯公式，不代表比較次數更少。

### ASCII 與範例一逐步演示

```text
每個 x：true -> AND 條件 1 -> AND 條件 2 -> ... -> 最終旗標
                                                      |
                                             true +1 / false +0

arr2 順序：         10       9        1        8
x=4，距離：          6       5        3        4
條件 >2：          true    true     true     true
旗標：      true -> true -> true  -> true  -> true  -> cnt = 1

x=5，距離：          5       4        4        3
條件 >2：          true    true     true     true
旗標：      true -> true -> true  -> true  -> true  -> cnt = 2

x=8，距離：          2       1        7        0
條件 >2：          false   false    true     false
旗標：      true -> false -> false -> false -> false -> cnt = 2
```

`x=8` 在第三次比較雖然得到 `7>2`，但 `false & true` 仍然是 `false`，不會讓已被排除的元素重新有效。兩個輸入陣列都不會被修改。

## 解法三：排序與二分搜尋

### 為什麼只看左右鄰居？

將 `arr2` 升冪排序。對沒有出現在陣列中的 `x`，找到其插入位置 `p`，就能將陣列分成兩半：

```text
索引：    0 ... p-2   p-1    |    p   p+1 ... m-1
數值：    更小的值   左鄰居   |  右鄰居    更大的值
                          插入 x

左側：y <= arr2[p-1] < x  -> x-y >= x-arr2[p-1]
右側：x < arr2[p] <= y    -> y-x >= arr2[p]-x
```

左鄰居已是左半部最接近 `x` 的元素；右鄰居同理。因此：

- 任一存在的鄰居與 `x` 的差小於等於 `d`，就有反例，必須排除。
- 所有存在的鄰居距離都大於 `d`，更遠的元素也一定合格，可以計數。

若搜尋直接命中 `x`，差值為 `0`，在題目 `d>=0` 的條件下必定排除。此時 `p` 是命中位置，不必也不能假設它是第一個相同元素的位置；本程式會在檢查 `arr2[p]` 時將旗標設成 `false`，之後的左鄰居比較不會改變結論。

### `Array.BinarySearch` 與 `~p`

依 [Microsoft Array.BinarySearch 文件](https://learn.microsoft.com/en-us/dotnet/api/system.array.binarysearch?view=net-10.0)，輸入陣列必須已排序，回傳值分成兩種：

| 搜尋情況 | 回傳值 r | 後續使用的 p |
| --- | --- | --- |
| 命中 | 非負索引 | `p=r`，表示某個相同元素的位置 |
| 未命中 | 插入位置的位元補數 | `p=~r`，表示第一個大於 x 的位置，或陣列長度 |

對 C# `int`，位元補數滿足 `~r = -r - 1`。例如插入索引是 `1`，搜尋回傳 `~1 = -2`，程式再以 `~(-2) = 1` 還原。因此不能只取絕對值：`abs(-2)=2` 會得到錯誤位置。

```text
32 位元 int（二補數）示意：
插入索引  1：00000000 00000000 00000000 00000001
搜尋回傳 -2：11111111 11111111 11111111 11111110  <- 每位反轉
再次取 ~ ：00000000 00000000 00000000 00000001  -> 還原為 1
```

`~` 是整數的**位元補數**；`!` 是布林的**邏輯否定**，例如 `!true` 得到 `false`。`!` 不能用來還原整數索引，程式只對負的搜尋回傳值使用 `~`，不對命中索引反轉。

未命中的插入位置範圍是 `0` 到 `m`，包含兩端：

```text
排序後 arr2 = [0, 5, 10]

x=-5：p=0     x | 0  5  10     無左鄰居，只檢查 0
x= 7：p=2     0  5 | x | 10    檢查 5 與 10
x=15：p=3     0  5  10 | x     無右鄰居，只檢查 10
```

### 條件與邏輯運算如何配合

```csharp
bool isValid = true;
if (p < arr2.Length)
{
    isValid &= Math.Abs(arr2[p] - x) > d;
}
if (p - 1 >= 0 && p - 1 < arr2.Length)
{
    isValid &= Math.Abs(arr2[p - 1] - x) > d;
}
cnt += isValid ? 1 : 0;
```

第一個 `if` 排除 `p=m`，避免存取不存在的右鄰居。第二個 `if` 用 `&&` 組合左鄰居的上下界條件：左側為 `false` 時不計算右側；真正的陣列存取在 `if` 內，只有完整條件為真才執行。雖然在這裡 `p` 的範圍已能推導出上界，仍保留現有程式的完整索引檢查。

兩次 `&=` 將存在的候選檢查做 AND。若右側已使旗標為 `false`，存在左鄰居時仍會計算其距離；這是原本寫法的非短路行為。不存在的鄰居由 `if` 略過，不需額外條件；初始 `true` 讓單邊鄰居也能正常判斷。最後同樣用 `?:` 決定是否加一。

### ASCII 流程

```text
原地排序 arr2
      |
      v
取下一個 x -> BinarySearch(arr2, x)
                   |
             回傳 p < 0？
              | yes -> p = ~p（還原插入位置）
              | no  -> 保留命中索引
                   v
             isValid = true
                   |
           p < m？--yes--> AND 右候選距離 > d
                   |
           左索引合法？--yes--> AND 左候選距離 > d
                   |
             true 加 1，false 加 0
                   |
                下一個 x
```

### 範例一逐步演示

```text
原始 arr2：[10, 9, 1, 8]
排序 arr2：[ 1, 8, 9, 10]
索引：       0  1  2   3

x=4：   1 | 4 | 8  9  10
        ^       ^
      左差=3  右差=4  -> 都 > 2 -> +1

x=5：   1 | 5 | 8  9  10
        ^       ^
      左差=4  右差=3  -> 都 > 2 -> +1

x=8：   1   8   9  10
            ^
         直接命中，差=0 -> 排除
```

| x | 搜尋回傳值 | p 的意義 | 實際比較順序 | 累計 cnt |
| --- | --- | --- | --- | --- |
| 4 | `-2` | `~(-2)=1`，插入索引 | 右差 `4>2`，左差 `3>2` | 1 |
| 5 | `-2` | `~(-2)=1`，插入索引 | 右差 `3>2`，左差 `4>2` | 2 |
| 8 | `1` | 命中索引 | 命中差 `0>2` 為 false；左差 `7>2` 為 true，旗標仍 false | 2 |

> [!NOTE]
> 解法三呼叫 `Array.Sort(arr2)`，會改動呼叫端傳入的陣列順序。需要保留順序時，先傳入 `(int[])arr2.Clone()`。本專案的測試會為每次方法呼叫複製兩個輸入陣列。

## 解法四：區間左界二分搜尋

### 從距離條件改寫為區間

解法三尋找靠近 `x` 的左右鄰居；解法四則直接問：「排序後的 `arr2`，有沒有元素落在排除區間內？」

```text
|x-y| <= d
<=> -d <= y-x <= d
<=> x-d <= y <= x+d

                         封閉排除區間
較小元素             [ x-d ........ x+d ]             較大元素
不會使 x 被排除          有元素就排除 x                不會使 x 被排除
```

兩端都包含在排除區間內，因此候選值必須嚴格大於 `x+d` 才能讓 `x` 合格，不能使用 `>=`。

### 設計與 C# 核心程式

此方法是前述 Java 寫法的 C# 對應版本，以 `Array.Sort` 與 `Array.BinarySearch` 實作：

```csharp
Array.Sort(arr2);
int cnt = 0;
foreach (int x in arr1)
{
    int i = Array.BinarySearch(arr2, x - d);
    if (i < 0)
    {
        i = ~i;
    }
    if (i == arr2.Length || arr2[i] > x + d)
    {
        cnt++;
    }
}
return cnt;
```

搜尋目標改成左界 `x-d`，接著分三種情況：

1. **命中左界**：`arr2[i] == x-d`，已經有元素在排除區間內。由於 `d>=0`，這個值不會大於 `x+d`，所以不計數。即使命中的是多個重複左界中的任一筆，結論也相同。
2. **未命中且 `i<m`**：以 `~i` 還原插入位置後，`arr2[i]` 是第一個大於左界的元素。若它仍小於等於右界，就有反例；若它已超過右界，後面只會更大，區間內不可能有元素。
3. **未命中且 `i=m`**：所有元素都小於左界，區間內沒有元素，直接計數。

`Array.BinarySearch` 命中時不保證回傳第一個重複值的位置，因此這個寫法不能泛稱為「一定找到第一個大於等於左界的索引」。只有未命中後還原的插入位置具有上述第一個較大元素的意義；命中任意左界元素就足以判定排除。[搜尋回傳規則參考](https://learn.microsoft.com/en-us/dotnet/api/system.array.binarysearch?view=net-10.0)。

### 正確性與 `||` 短路

若存在區間內元素，搜尋命中左界就會直接找到反例；未命中時，第一個跨過左界的元素不可能比該區間內元素更大，因此候選一定也位於區間內。反過來說，若候選不存在或已超過右界，排序性保證前面全部低於左界、後面全部超過右界，整個區間就是空的。

```csharp
i == arr2.Length || arr2[i] > x + d
```

`||` 是短路 OR：左側為 `true` 時，右側不會求值。當 `i` 等於陣列長度時，這可避免讀取越界的 `arr2[i]`；不能直接換成不短路的 `|`。當左側為 `false` 才讀取唯一候選並比較右界。

題目限制下 `x-d` 與 `x+d` 都落在 `-1100` 至 `1100`，使用 `int` 安全。和解法三一樣，此方法會原地排序 `arr2`，需要保留順序時應傳入副本。

### ASCII 流程

```text
原地排序 arr2
      |
      v
取下一個 x -> 搜尋左界 x-d
                    |
              回傳 i < 0？
               | yes -> i = ~i（插入位置）
               | no  -> 保留命中左界的索引
                    v
               i == m？
               | yes -> cnt++（不存取 arr2[i]）
               | no
               v
           arr2[i] > x+d？
               | yes -> cnt++（區間內沒有元素）
               | no  -> 不計數（候選在封閉區間內）
                    |
                 下一個 x
```

### 官方範例一逐步演示

```text
arr1 = [4,5,8]，d = 2
排序 arr2 = [1,8,9,10]
索引：       0 1 2  3

x=4：區間 [2,6]    1 | [2 ... 6] | 8 9 10
                                  ^ 候選 8 > 6 -> +1
x=5：區間 [3,7]    1 | [3 ... 7] | 8 9 10
                                  ^ 候選 8 > 7 -> +1
x=8：區間 [6,10]   1 | [6 ... 8 9 10]
                             ^ 候選 8 <= 10 -> 排除
```

| x | 左界／右界 | 搜尋回傳值 | 還原後 i | 候選與判斷 | 累計 cnt |
| --- | --- | --- | --- | --- | --- |
| 4 | `2 / 6` | `-2` | 1 | `8>6`，區間為空 | 1 |
| 5 | `3 / 7` | `-2` | 1 | `8>7`，區間為空 | 2 |
| 8 | `6 / 10` | `-2` | 1 | `8<=10`，區間內有元素 | 2 |

注意最後一列搜尋的是 `6`，不是 `8`，因此即使 `arr2` 包含 `x=8`，搜尋仍然是「未命中左界」後檢查候選。

### 邊界與重複值演示

以下均取 `x=5、d=2`，排除區間為 `[3,7]`：

| arr2（排序後） | 搜尋 3 的結果 | 最後判斷 |
| --- | --- | --- |
| `[3]` | 命中左界 | `3>7` 為 false，排除 |
| `[3,3,10]` | 命中某個 3，不保證第一筆 | 任一個 3 都在區間內，排除 |
| `[1,6,10]` | 未命中，還原 `i=1` | `6<=7`，排除 |
| `[1,7,10]` | 未命中，還原 `i=1` | 候選等於右界，排除 |
| `[1,8,10]` | 未命中，還原 `i=1` | `8>7`，計數 |
| `[2]` | 未命中，還原 `i=1=m` | 不讀取候選，直接計數 |

## 複雜度與取捨

令 `n=arr1.Length`、`m=arr2.Length`。

| 解法 | 時間複雜度 | 額外空間（解法本身） | 特性 |
| --- | --- | --- | --- |
| 一：提前停止 | 最差 `O(nm)` | `O(1)` | 有反例即可停止；輸入不變 |
| 二：布林累積 | `O(nm)` | `O(1)` | 固定完成全部配對比較；輸入不變 |
| 三：排序與二分搜尋 | `O(m log m + n log m)` | 排序使用 `O(log m)` 堆疊；搜尋及旗標 `O(1)` | 原地排序 arr2，每個 x 最多比較兩個候選 |
| 四：區間左界二分搜尋 | `O(m log m + n log m)` | 排序使用 `O(log m)` 堆疊；搜尋及計數 `O(1)` | 原地排序 arr2，每個 x 最多比較一個候選 |

解法三、四的空間估計包含 .NET 陣列排序所使用的堆疊；若呼叫端為保留輸入額外複製 `arr2`，則再增加 `O(m)` 空間。測試工具複製兩個陣列所需的 `O(n+m)` 不計入各解法本身。

本題陣列最多各 500 個元素，雙迴圈最多 250,000 次配對比較，適合先用解法一理解題意。解法二適合理解全稱條件與 AND；解法三則示範如何利用排序消除不必要的比較，也需要付出排序成本與處理輸入順序變動。解法四沿用相同排序成本，以區間觀點將搜尋後的判斷縮減為一個候選。

## 四種解法比較表

令 `n=arr1.Length`、`m=arr2.Length`。候選檢查數指每個 `x` 在二分搜尋完成後的檢查，不包含搜尋本身的比較。

| 比較項目 | 解法一：提前停止 | 解法二：布林累積 | 解法三：左右鄰居 | 解法四：區間左界 |
| --- | --- | --- | --- | --- |
| 核心概念 | 尋找一個距離不合格的反例 | AND 累積所有距離條件 | 檢查左右最近元素 | 檢查封閉排除區間是否為空 |
| 搜尋目標 | 逐一走訪 y | 逐一走訪 y | 二分搜尋 x | 二分搜尋 x-d |
| 時間複雜度 | 最差 `O(nm)` | `O(nm)` | `O(m log m + n log m)` | `O(m log m + n log m)` |
| 額外空間 | `O(1)` | `O(1)` | 含排序堆疊 `O(log m)` | 含排序堆疊 `O(log m)` |
| 每個 x 的檢查量 | 最多 m 次距離比較 | 固定 m 次距離比較 | 搜尋後最多 2 個候選 | 搜尋後最多 1 個候選 |
| 提前停止／略過 | 找到反例就 break | 不短路，完整遍歷 | 依索引略過不存在的鄰居；不在候選失敗後停止 | `i==m` 時以短路略過候選存取 |
| 修改輸入 | 不修改 | 不修改 | 原地排序 arr2 | 原地排序 arr2 |
| 主要運算 | 絕對差、條件判斷 | 絕對差、`&=`、`?:` | `~`、`&&`、`&=`、`?:` | `~`、`\|\|`、區間右界比較 |
| 適用情境 | 入門、直接理解題意 | 練習全稱條件與布林累積 | 學習排序後最近鄰居的性質 | 直接解決區間存在性判斷 |

以本題實作的精簡程度而言，解法四只需檢查一個候選，直接對應排除區間，較容易維持簡潔的判斷。解法三保留最近鄰居的教學價值；兩者的漸進時間複雜度相同，沒有基準測試就不能保證解法四實際執行較快。兩種排序解法若另行複製輸入以保留順序，仍須加計副本的空間成本。
