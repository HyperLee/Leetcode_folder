# 3904. Smallest Stable Index II

[![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4)](https://dotnet.microsoft.com/)

這是一個使用 C# 與 .NET 10 撰寫的 LeetCode 3904 解題範例。專案保留兩種可獨立呼叫的 O(n) 解法，並在 `Main` 中提供不需要輸入資料的固定案例，方便直接建置、執行與比較兩種解法的結果。

- 題目：[Smallest Stable Index II](https://leetcode.com/problems/smallest-stable-index-ii/description/)
- 中文題目：[最小穩定下標 II](https://leetcode.cn/problems/smallest-stable-index-ii/description/)
- 解法：完整前綴／後綴預處理、後綴陣列搭配滾動前綴最大值
- 執行方式：.NET 10 console application

## 題目說明

給定一個長度為 `n` 的整數陣列 `nums` 與整數 `k`。陣列索引從 `0` 開始，對每個索引 `i` 定義不穩定分數（instability score）為：

```text
max(nums[0..i]) - min(nums[i..n - 1])
```

其中：

- `max(nums[0..i])` 是從索引 `0` 到 `i` 的前綴區間最大值。
- `min(nums[i..n - 1])` 是從索引 `i` 到 `n - 1` 的後綴區間最小值。
- 如果不穩定分數小於或等於 `k`，索引 `i` 就是穩定索引。

請回傳最小的穩定索引。如果不存在穩定索引，回傳 `-1`。

### 官方範例 1

```text
nums = [5, 0, 1, 4], k = 3
答案 = 3
```

逐一計算如下：

| 索引 `i` | `max(nums[0..i])` | `min(nums[i..n-1])` | 不穩定分數 | 是否穩定 |
| ---: | ---: | ---: | ---: | :---: |
| 0 | 5 | 0 | 5 | 否 |
| 1 | 5 | 0 | 5 | 否 |
| 2 | 5 | 1 | 4 | 否 |
| 3 | 5 | 4 | 1 | 是 |

索引 `3` 是第一個滿足 `score <= k` 的位置，因此回傳 `3`。

### 官方範例 2

```text
nums = [3, 2, 1], k = 1
答案 = -1
```

三個索引的不穩定分數都為 `3 - 1 = 2`，全部大於 `k = 1`，所以沒有穩定索引。

### 官方範例 3

```text
nums = [0], k = 0
答案 = 0
```

唯一索引的分數為 `0 - 0 = 0`，符合條件，因此回傳 `0`。

## 限制條件

依照 [LeetCode 3904 官方題目頁](https://leetcode.cn/problems/smallest-stable-index-ii/)：

- `1 <= nums.length <= 10^5`
- `0 <= nums[i] <= 10^9`
- `0 <= k <= 10^9`

因此輸入陣列一定非空，可以安全地使用 `nums[0]` 與 `nums[n - 1]` 初始化前綴或後綴資訊。`nums[i]` 與 `k` 的最大值使得差值不超過 `10^9`，使用 C# `int` 即可表示。

相較於 LeetCode 3903 的 `n <= 100`，本題的陣列長度最多可達 `100000`。如果對每個索引重新掃描後綴，最壞情況會產生 O(n^2) 的約 `10^10` 次級別操作，無法符合本題的效率要求，因此本題採用 3903 的解法 2 與解法 3，將時間複雜度維持為 O(n)。

## 解題概念與出發點

題目要求的是「最小」穩定索引，所以兩種解法都遵循同一個外層策略：

1. 按照 `i = 0, 1, 2, ...` 的順序檢查索引。
2. 取得目前前綴的最大值與後綴的最小值。
3. 計算 `max - min`。
4. 第一次得到小於或等於 `k` 的結果時立即回傳。

真正需要加速的是兩個區間查詢：

- 前綴最大值可以由左到右累積：

  ```text
  preMax[0] = nums[0]
  preMax[i] = max(preMax[i - 1], nums[i])
  ```

- 後綴最小值可以由右到左累積：

  ```text
  sufMin[n - 1] = nums[n - 1]
  sufMin[i] = min(sufMin[i + 1], nums[i])
  ```

這樣每個索引的前綴最大值與後綴最小值都能在 O(1) 時間取得，整體就能在 O(n) 時間內完成。

## 解法設計

### 解法一：完整前綴／後綴預處理 `FirstStableIndex`

#### 設計想法

這個方法完整保存兩種區間資訊，分成三個階段：

1. 從右到左建立 `sufMin`，讓 `sufMin[i]` 保存 `nums[i..n - 1]` 的最小值。
2. 從左到右建立 `preMax`，讓 `preMax[i]` 保存 `nums[0..i]` 的最大值。
3. 從左到右比較 `preMax[i] - sufMin[i]` 與 `k`。

後綴陣列先設定最後一格，再往左推導：

```text
sufMin[n - 1] = nums[n - 1]
for i = n - 2, n - 3, ..., 0:
    sufMin[i] = min(sufMin[i + 1], nums[i])
```

前綴陣列先設定第一格，再往右推導：

```text
preMax[0] = nums[0]
for i = 1, 2, ..., n - 1:
    preMax[i] = max(preMax[i - 1], nums[i])
```

這裡後綴迴圈從 `n - 2` 開始，是因為 `sufMin[n - 1]` 已經先初始化；前綴迴圈從 `1` 開始，是因為 `preMax[0]` 已經先初始化。當 `n = 1` 時，兩個迴圈都不會執行，邊界值本身就是完整答案。

#### 流程演示

以 `nums = [5, 0, 1, 4]`、`k = 3` 為例。

先建立兩個陣列：

```text
preMax = [5, 5, 5, 5]
sufMin = [0, 0, 1, 4]
```

接著由左到右計算分數：

| 索引 `i` | `preMax[i]` | `sufMin[i]` | 不穩定分數 | 判斷 |
| ---: | ---: | ---: | ---: | :--- |
| 0 | 5 | 0 | 5 | `5 > 3`，繼續 |
| 1 | 5 | 0 | 5 | `5 > 3`，繼續 |
| 2 | 5 | 1 | 4 | `4 > 3`，繼續 |
| 3 | 5 | 4 | 1 | `1 <= 3`，回傳 `3` |

#### 正確性

`preMax[i]` 的遞推式會保留 `nums[0..i]` 中的最大值；`sufMin[i]` 的遞推式會保留 `nums[i..n - 1]` 中的最小值。因此 `preMax[i] - sufMin[i]` 正好是索引 `i` 的不穩定分數。

最後的掃描按照索引遞增順序進行，第一個滿足分數不超過 `k` 的位置必定是最小穩定索引；如果整個掃描都沒有通過，就回傳 `-1`。

#### 複雜度

- 時間複雜度：O(n)。建立兩個陣列與最後的判斷各需要一次線性遍歷。
- 額外空間複雜度：O(n)。配置一個 `preMax` 與一個 `sufMin` 陣列。

### 解法二：後綴陣列搭配滾動前綴最大值 `FirstStableIndex2`

#### 設計想法

解法一雖然已經是 O(n)，但最後只需要按照索引由左到右判斷，並不需要完整保存所有 `preMax` 值。因此可以省略 `preMax` 陣列，改用單一變數保存目前前綴最大值：

1. 先由右到左建立 `sufMin`。
2. 再由左到右走訪 `nums`。
3. 到達索引 `i` 時，以 `max(preMax, nums[i])` 更新目前前綴最大值。
4. 立刻用 `preMax - sufMin[i]` 判斷是否穩定。

程式將 `preMax` 初始化為 `0`，是因為題目保證所有 `nums[i]` 都不小於 `0`；因此初始值不會大於合法元素，也不會破壞第一個位置的最大值計算。

#### 流程演示

仍以 `nums = [5, 0, 1, 4]`、`k = 3` 為例。後綴陣列先建立為 `[0, 0, 1, 4]`，左到右判斷時只保留一個 `preMax`：

| 索引 `i` | 目前元素 | 更新後 `preMax` | `sufMin[i]` | 不穩定分數 | 判斷 |
| ---: | ---: | ---: | ---: | ---: | :--- |
| 0 | 5 | 5 | 0 | 5 | 不穩定 |
| 1 | 0 | 5 | 0 | 5 | 不穩定 |
| 2 | 1 | 5 | 1 | 4 | 不穩定 |
| 3 | 4 | 5 | 4 | 1 | 穩定，回傳 `3` |

#### 正確性

在處理索引 `i` 時，`preMax` 會先更新成 `nums[0..i]` 的最大值；`sufMin[i]` 已經在前一趟由右到左的掃描中正確建立，代表 `nums[i..n - 1]` 的最小值。因此每次比較都使用題目要求的兩個區間資訊。

同樣由小索引往大索引檢查，第一次通過的索引就是最小穩定索引；如果沒有任何位置通過，就回傳 `-1`。

#### 複雜度

- 時間複雜度：O(n)。建立 `sufMin` 與判斷索引各需要一次線性遍歷。
- 額外空間複雜度：O(n)。只配置 `sufMin`，另使用一個 `preMax` 變數；相較解法一少配置一個長度為 `n` 的前綴陣列。

## 兩種解法比較

本題的兩種解法分別對應 LeetCode 3903 解題說明中的解法 2 與解法 3；3904 不保留 3903 的 O(n²) 逐一枚舉解法，因為本題的最大輸入長度已提升至 `10^5`。

| 解法 | 對應 3903 | 核心做法 | 時間複雜度 | 額外空間複雜度 | 特點 |
| --- | ---: | --- | ---: | ---: | --- |
| `FirstStableIndex` | 解法 2 | 完整保存前綴最大值與後綴最小值 | O(n) | O(n) | 每個索引的兩種資訊都可直接查詢 |
| `FirstStableIndex2` | 解法 3 | 保存後綴最小值，前綴最大值滾動計算 | O(n) | O(n) | 少一個前綴陣列，額外記憶體較少 |

兩者都符合本題的時間要求。若需要清楚觀察每個索引的前綴狀態，解法一較直觀；若只需要找到答案，解法二可以用較少的輔助資料完成相同工作。

`Main` 不讀取命令列或主控台輸入，而是建立六組固定資料。每組資料都會呼叫兩個方法，因此總共會執行 `6 x 2 = 12` 次解法判斷。只有兩種方法都等於預期值時，該案例才會顯示 `PASS`。

| 案例 | `nums` | `k` | 預期結果 | 覆蓋情境 |
| --- | --- | ---: | ---: | --- |
| 官方範例 1 | `[5, 0, 1, 4]` | 3 | 3 | 第一個穩定索引在最後方 |
| 官方範例 2 | `[3, 2, 1]` | 1 | -1 | 不存在穩定索引 |
