## 題目說明

有一排花圃，其中：

- `0` 代表空地。
- `1` 代表該位置已經種花。
- 任意兩朵花都不能位於相鄰位置。

給定整數陣列 `flowerbed` 與希望新增的花朵數量 `n`，判斷能否在不違反相鄰限制的情況下，再種下至少 `n` 朵花。可以則回傳 `true`，否則回傳 `false`。

題目連結：

- [LeetCode 605. Can Place Flowers](https://leetcode.com/problems/can-place-flowers/)
- [力扣 605. 种花问题](https://leetcode.cn/problems/can-place-flowers/)

### 官方範例

範例一：

```text
輸入：flowerbed = [1, 0, 0, 0, 1], n = 1
輸出：true
```

中間三格空地的中央位置可以種一朵花。

範例二：

```text
輸入：flowerbed = [1, 0, 0, 0, 1], n = 2
輸出：false
```

同一段空地最多只能再容納一朵花，無法種下兩朵。

### 限制條件

- `1 <= flowerbed.Length <= 2 * 10^4`
- `flowerbed[i]` 只能是 `0` 或 `1`
- 原始 `flowerbed` 中不存在兩朵相鄰的花
- `0 <= n <= flowerbed.Length`

> [!NOTE]
> 程式中的兩種解法都只讀取 `flowerbed`，不會真的把新花寫入陣列。範例執行器會為兩種解法建立獨立副本，並驗證副本內容在呼叫後沒有改變。

## 解題概念與出發點

問題的核心不是找出實際種花配置，而是計算是否存在足夠的合法位置。因為原始花圃已保證沒有相鄰花朵，可以利用兩個觀察：

1. 從「連續空地」角度計算每個區段最多能放幾朵花。
2. 從左到右模擬時，一旦某個位置種花或遇到既有花朵，就能直接跳過下一個必定不能種花的位置。

兩種解法都只掃描一次陣列，也都可以在已找到足夠位置時提前回傳。

| 解法 | 主要概念 | 是否修改輸入 | 時間複雜度 | 額外空間 |
| --- | --- | --- | --- | --- |
| `CanPlaceFlowers` | 計算開頭、中間、結尾空白區段的容量 | 否 | `O(m)` | `O(1)` |
| `CanPlaceFlowers2` | 依 `00`、`01`、`10` 狀態調整索引 | 否 | `O(m)` | `O(1)` |

其中 `m` 是 `flowerbed.Length`。

## 解法一：空白區段計數

### 設計概念

`CanPlaceFlowers` 記住上一朵既有花的位置 `prev`，每次遇到下一朵花時，就能計算兩者之間的連續空地最多可容納幾朵新花。陣列邊界與既有花朵的限制不同，因此分成三類。

#### 1. 第一朵既有花之前

若第一朵花位於索引 `i`，前方共有 `i` 格空地。右側必須與既有花隔一格，但左側沒有鄰居，因此容量為：

```text
i / 2
```

例如 `[0, 0, 1]` 的第一朵花位於索引 `2`，前方可以在索引 `0` 種一朵。

#### 2. 兩朵既有花之間

上一朵花位於 `prev`，目前花位於 `i`。兩端各有一格不能使用，所以容量為：

```text
(i - prev - 2) / 2
```

整數除法會自然捨去不足以再放一朵花的餘數。

#### 3. 最後一朵既有花之後

最後一朵花位於 `prev`，尾端共有 `m - prev - 1` 格空地。左側需要保留間隔，右側沒有鄰居，因此容量為：

```text
(m - prev - 1) / 2
```

若整個花圃都沒有既有花，則可從第一格開始交錯種植，容量為：

```text
(m + 1) / 2
```

每計算完一個區段，就比較累積容量是否已達到 `n`，足夠時立即回傳 `true`。

### 範例演示

輸入：

```text
flowerbed = [1, 0, 0, 0, 1], n = 1
```

1. 在索引 `0` 遇到第一朵花，前方容量為 `0 / 2 = 0`。
2. 在索引 `4` 遇到第二朵花，中間容量為 `(4 - 0 - 2) / 2 = 1`。
3. 累積容量成為 `1`，已達到 `n = 1`，因此提早回傳 `true`。

若 `n = 2`，中間仍只能放一朵，尾端也沒有空地，最後會回傳 `false`。

### 複雜度

- 時間複雜度：`O(m)`，最差情況掃描完整個花圃。
- 額外空間：`O(1)`，只使用計數器與索引。

## 解法二：索引跳躍模擬

### 設計概念

`CanPlaceFlowers2` 從左到右處理花圃。由於游標左側的狀態已經合法處理完畢，目前位置只需要搭配右側位置判斷。

| 目前狀態 | 處理方式 | 下一個索引 |
| --- | --- | --- |
| `00` | 在目前位置種花，下一格必須保持空白 | `i += 2` |
| `01` | 下一格已有花，目前位置及既有花右側都不能種花 | `i += 3` |
| `10` | 目前位置已有花，下一格不能種花 | `i += 2` |
| 最後一格為 `0` | 左側已由跳躍規則保證合法，可直接種花 | 結束掃描 |

此方法用遞減 `n` 表示還需要找到多少個位置。每次成功找到位置就執行 `n--`；當 `n <= 0` 時立即回傳 `true`。

演算法不會將 `flowerbed[i]` 改成 `1`。索引跳躍本身已經記錄「剛才選擇的位置會讓下一格不能再種花」這項狀態，因此不需要額外陣列。

### 範例演示

輸入：

```text
flowerbed = [0, 0, 1, 0, 0], n = 2
```

1. `i = 0` 時看到 `00`，可在索引 `0` 種花；`n` 變為 `1`，跳到 `i = 2`。
2. `i = 2` 是既有花朵，索引 `3` 不能種花，因此跳到 `i = 4`。
3. `i = 4` 是最後一格且為空，左側狀態已合法，可再種一朵；`n` 變為 `0`。
4. 已找到兩個合法位置，回傳 `true`。

### 複雜度

- 時間複雜度：`O(m)`；索引只向右移動，且每次至少前進兩格或結束。
- 額外空間：`O(1)`；只使用長度、索引與剩餘數量。
