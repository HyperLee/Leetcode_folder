## 題目說明

[LeetCode 241 - Different Ways to Add Parentheses](https://leetcode.com/problems/different-ways-to-add-parentheses/description/) 給定一個由非負整數及 `+`、`-`、`*` 組成的算術表達式。題目不採用原本的運算子優先順序，而是要求列舉所有不同的加括號方式，計算每一種運算順序的結果。

例如 `2-1-1` 有兩種括號方式：

- `(2-1)-1 = 0`
- `2-(1-1) = 2`

因此答案為 `[0, 2]`。題目允許以任意順序回傳答案；若不同括號方式得到相同數值，該數值仍須重複保留。例如 `2*3-4*5` 的答案含有兩個 `-10`。

### 限制條件

- `1 <= expression.length <= 20`
- `expression` 只包含數字與 `+`、`-`、`*`
- 表達式中的整數值介於 `0` 與 `99`
- 輸入保證是合法表達式，不包含空白、負數或一元運算子
- 所有中間結果及答案都在 32-bit 整數範圍內

## 解題概念與出發點

一般算式會先乘除、後加減；本題則要主動忽略既定優先順序。核心觀察是：

> 任選一個運算子作為「最後執行的運算」，它左邊與右邊就形成兩個獨立子問題。

假設目前選到的運算子為 `op`：

1. 求出左側子表達式的所有結果 `leftResults`。
2. 求出右側子表達式的所有結果 `rightResults`。
3. 將兩邊做笛卡兒積；每個左結果都必須搭配每個右結果。
4. 對每一組 `(left, right)` 套用 `op`，加入目前區間的答案。

這個結構自然形成二元運算樹。每一棵不同形狀的樹代表一種括號方式，因此輸出數量會隨運算子數量快速增加。四種解法的差異不在數學定義，而在於如何表示子問題、是否快取，以及採用遞迴或迭代。

程式在比較結果前會先排序，確保「任意回傳順序」不影響驗證；排序只改變比較用的複本，且不會移除重複值。

## 四種解法

### 解法一：記憶化搜尋 `DiffWaysToCompute_memo`

這個版本先把字串解析成整數序列。非負值代表運算數，負值常數代表運算子：

| 原始內容 | 內部值 |
| --- | ---: |
| `+` | `-1` |
| `-` | `-2` |
| `*` | `-3` |

`dp[l][r]` 儲存編碼序列從 `l` 到 `r` 的所有結果。遞迴進入某個區間時：

1. 若快取已有結果，直接回傳，避免重算。
2. 若 `l == r`，區間只有一個數字，直接把該數字當作唯一結果。
3. 掃描區間內的每個運算子位置。
4. 遞迴取得左右區間結果，再做笛卡兒積。
5. 將合併結果存入 `dp[l][r]`。

優點是相同索引區間只會完整求解一次；代價是必須保存所有區間的中間結果。

#### 範例演示：`2-1-1`

1. 編碼為 `[2, -2, 1, -2, 1]`。
2. 求 `dp[0][4]` 時，可在索引 `1` 或 `3` 的減號切分。
3. 索引 `1`：左側 `[2]`，右側 `1-1` 得到 `[0]`，組合為 `2-0 = 2`。
4. 索引 `3`：左側 `2-1` 得到 `[1]`，右側 `[1]`，組合為 `1-1 = 0`。
5. `dp[0][4]` 保存 `[2, 0]`；驗證時排序為 `[0, 2]`。

### 解法二：動態規劃 `DiffWaysToCompute_DP`

動態規劃沿用相同的數字／運算子編碼，但不使用遞迴。`dp[left][right]` 仍表示一段合法子表達式的所有結果。

填表順序是關鍵：

1. 先建立所有單一數字區間，例如 `dp[0][0]`。
2. 合法編碼區間的長度必為奇數，因此依序處理長度 `3、5、7...`。
3. 每個區間只嘗試位於數字之間的運算子位置。
4. 所需的左右短區間已先完成，可以直接合併。
5. 最後回傳覆蓋整個編碼序列的區間。

優點是沒有遞迴堆疊；代價是需要預先建立二維表，而且即使某些區間最後未被需要，也會按照填表順序計算。

#### 範例演示：`2-1-1`

1. 編碼為 `[2, -2, 1, -2, 1]`。
2. 基底：`dp[0][0] = [2]`、`dp[2][2] = [1]`、`dp[4][4] = [1]`。
3. 長度 `3`：`dp[0][2] = [1]`，`dp[2][4] = [0]`。
4. 長度 `5`、在第一個減號切分：`2-0 = 2`。
5. 長度 `5`、在第二個減號切分：`1-1 = 0`。
6. 完整區間得到 `[2, 0]`，排序後為 `[0, 2]`。

### 解法三：分治法 `DiffWaysToCompute`

這是最直接對應題意的版本，不先建立額外編碼：

1. 若目前字串只有數字，直接解析成整數。
2. 逐字掃描每個運算子。
3. 以該運算子切出左右子字串。
4. 對左右子字串遞迴呼叫同一方法。
5. 合併兩側的所有結果。

優點是概念直觀、程式結構接近數學遞迴定義；缺點是相同子字串可能被多次計算，而且 `Substring` 會建立新的字串。

#### 範例演示：`2-1-1`

1. 以第一個 `-` 作為最後運算：左側 `2 → [2]`，右側 `1-1 → [0]`，得到 `2`。
2. 以第二個 `-` 作為最後運算：左側 `2-1 → [1]`，右側 `1 → [1]`，得到 `0`。
3. 合併為 `[2, 0]`，排序後為 `[0, 2]`。

### 解法四：字元區間 DFS `DiffWaysToCompute_DFS`

這個版本與分治法使用相同遞迴概念，但先把表達式轉為 `char[]`，再以閉區間 `[l, r]` 表示子問題：

1. 掃描目前字元區間。
2. 遇到運算子時，遞迴處理 `[l, i-1]` 與 `[i+1, r]`。
3. 將左右結果依目前運算子組合。
4. 若整個區間找不到運算子，逐字累積成多位整數。

優點是不需要反覆建立左右子字串；缺點是仍未快取區間，相同子問題會重複求解。

#### 範例演示：`2-1-1`

1. 字元陣列索引為 `0..4`，完整問題是 `DFS(cs, 0, 4)`。
2. 在索引 `1` 切分：`DFS(0, 0) = [2]`，`DFS(2, 4) = [0]`，得到 `2`。
3. 在索引 `3` 切分：`DFS(0, 2) = [1]`，`DFS(4, 4) = [1]`，得到 `0`。
4. 回傳 `[2, 0]`，排序後為 `[0, 2]`。

## 複雜度與取捨

令 `m` 為運算子數量，`R` 為必須回傳的結果數量。對二元運算式而言，`R` 對應第 `m` 個卡塔蘭數；即使多個括號方式得到相同數值，仍各自佔一個輸出位置。因此所有解法至少需要 `Ω(R)` 時間與 `Θ(R)` 結果空間，不能只用一般多項式複雜度描述。

| 解法 | 子問題處理 | 時間特性 | 結果以外的空間重點 |
| --- | --- | --- | --- |
| 記憶化搜尋 | 每個索引區間求解一次 | 區間掃描外，主要成本是合併並保存所有中間結果；屬輸出敏感的指數成長 | `O(m²)` 個快取位置、遞迴堆疊，以及所有區間結果 |
| 動態規劃 | 依長度計算每個合法區間 | 與記憶化版本相同，結果合併量主導成本 | `O(m²)` 個表格位置，以及所有區間結果；無遞迴堆疊 |
| 分治法 | 相同子字串可能重算 | 至少 `Ω(R)`，重複子問題與字串切割帶來額外指數工作 | 最深 `O(m)` 的遞迴堆疊、子字串及中間結果 |
| 字元區間 DFS | 相同索引區間可能重算 | 至少 `Ω(R)`，仍有重複子問題，但省去子字串配置 | 最深 `O(m)` 的遞迴堆疊及中間結果 |

若重視易懂程度，分治法最貼近題意；若希望避免重複計算，可選記憶化搜尋；若希望避免遞迴，可選動態規劃；字元區間 DFS 則用索引降低字串切割成本，適合拿來與直接分治版本比較。
