# LeetCode 3041：修改陣列後最大化連續元素數量

使用 C# / .NET 11 實作「排序＋Dictionary DP」與「排序＋兩個 DP 狀態」，由 `Main` 執行範例及正確性驗證。

- [英文題目](https://leetcode.com/problems/maximize-consecutive-elements-in-an-array-after-modification/description/)
- [中文題目](https://leetcode.cn/problems/maximize-consecutive-elements-in-an-array-after-modification/description/)

## 題目說明與限制

給定正整數陣列 `nums`，每個元素都可以獨立選擇保持原值或增加 `1`，最多一次。修改完成後選取一些元素，使它們排序後成為連續且不重複的整數，回傳最多可選幾個元素。

選取的元素不必在原陣列中相鄰，也不必使用全部元素。例如 `[3,4,5]` 合法，`[3,4,6]` 有缺口，`[1,1,2,3]` 有重複值。

- `1 <= nums.length <= 100000`
- `1 <= nums[i] <= 1000000`
- 修改後最大值為 `1000001`，數值與答案皆可使用 C# `int`。
- 兩種解法均以符合題目限制的非空陣列為前提，不額外定義 `null` 或空陣列行為。

範例一：`[2,1,5,1,1]` 的答案為 `3`。

```text
Original:      [2, 1, 5, 1, 1]
Modification:  +1  0  0 +1  0
Final:         [3, 1, 5, 2, 1]
Selected:       3  1     2
Sorted:        [1] -> [2] -> [3]       length = 3
```

範例二：`[1,4,7,10]` 的答案為 `1`。相鄰原值差 `3`，較小者即使加一，仍無法接到下一個值。

## 解題概念與出發點

暴力列舉每個元素是否加一，共有 `2^n` 種選擇，無法處理十萬筆輸入。我們需要將「哪些連續序列可以形成」壓縮成最佳長度。

首先排序：原位置不影響選取結果；從小到大處理時，較小值形成的序列可以用來延伸目前值。排序不會漏掉必須交換處理順序的答案，因為原值 `u < v` 時，`u+1 <= v`，修改後不會逆序；相同原值則可交換元素身分。

重複值仍然有用：兩個 `1` 可以分別提供 `1`、`2`。但三個 `1` 也只能提供這兩種不同值，不能形成長度 `3` 的連續序列。

## 解法一：排序＋Dictionary 動態規劃

方法：`public int MaxSelectedElements(int[] nums)`。

### 先看懂 dp：key 是結尾值，value 是長度

本方法先排序，再從小到大處理每個元素。核心問題是：「目前元素保持原值或加一後，可以接在哪一條連續序列後面？」

```csharp
Array.Sort(nums);
Dictionary<int, int> dp = new Dictionary<int, int>();
```

`dp[v]` 表示：**只使用目前已處理的元素，各自選擇保持原值或加一，再選取其中一些元素後，能形成「以數值 v 結尾」的最長連續序列長度。**

因此，dp 記錄的是**修改、選取後可形成的連續序列長度**。`dp` 本身是 Dictionary，不是修改後的陣列，也沒有儲存完整序列；程式透過轉移公式計算可能結果，不會真的列出所有修改後的陣列。

例如 `dp[3] = 2`，意思是可以形成 `[2,3]`，結尾值為 `3`，長度為 `2`。

這裡的 `[2,3]` **確實表示選取後的元素數值為 2 和 3**，不是「長度、結尾」的表示法。因為 dp 只記錄連續且不重複的整數序列，長度為 `2`、結尾為 `3` 時，前一個值必須是 `2`。

| 選取後的元素數值 | 長度 | 結尾值 | 是否符合連續條件 |
|---|---:|---:|---|
| `[2,3]` | 2 | 3 | 符合，兩個值相差 1 |
| `[1,3]` | 2 | 3 | 不符合，中間缺少 2 |
| `[0,3]` | 2 | 3 | 不符合，中間缺少 1、2；且 0 不在本題合法值域內 |

要區分「原始輸入」和「修改、選取後的結果」：原始輸入若為 `[1,3]`，可以把 `1` 加一、`3` 保持原值，形成合法的 `[2,3]`，因此處理完這兩個元素後會有 `dp[3] = 2`。這筆紀錄描述的是結果 `[2,3]` 的長度。

對連續整數而言，知道結尾值與長度，就能推算整段數值：

```text
起點 = 結尾值 - 長度 + 1

dp[3] = 2 → 起點 = 3 - 2 + 1 = 2 → [2,3]
dp[5] = 3 → 起點 = 5 - 3 + 1 = 3 → [3,4,5]
```

這只能推算結果序列的數值，無法得知每個值來自原始陣列的哪個位置，或哪個元素曾經加一。

| 部分 | 範例 | 意義 |
|---|---|---|
| key | `3` | 連續序列最後一個元素的數值 |
| value | `2` | 以這個值結尾的最長連續序列長度 |

**key 不是陣列索引，value 也不是該數值出現的次數。** Dictionary 只儲存最佳長度，沒有儲存完整序列；本文列出的序列是幫助理解的示意。

### 為什麼同一個結尾只保留最長長度？

可以先這樣理解：**題目要找最大長度，而結尾相同的序列，未來延伸的機會也相同，所以只需要保留較長的。**

例如，使用目前已處理的元素，可以形成 `[3,4]` 和 `[1,2,3,4]`。兩條序列都以 `4` 結尾，要延伸都必須接上 `5`：

| 後續可提供的數值 | 較短的序列 | 較長的序列 |
|---|---|---|
| 尚未接上新元素 | `[3,4]`，長度 2 | `[1,2,3,4]`，長度 4 |
| 提供 `5` | `[3,4,5]`，長度 3 | `[1,2,3,4,5]`，長度 5 |
| 再提供 `6` | `[3,4,5,6]`，長度 4 | `[1,2,3,4,5,6]`，長度 6 |
| 無法提供 `5` | 無法延伸，也不能跳過 `5` 接上 `6` | 同樣無法延伸 |

能延伸時，兩條序列都增加相同長度，較長的仍然較長；不能延伸時，較短的也沒有額外優勢。因此只需要記錄 `dp[4] = 4`，不用再保存同樣以 `4` 結尾、長度為 `2` 的結果。

較長的序列雖然使用了更多元素，但那些都是已處理的元素；後續延伸使用的是尚未處理的新元素，所以不會因為保留較長的結果，就占用未來需要的元素。

**這個比較只適用於結尾相同的序列。** 結尾不同時，即使目前較短，未來也可能延伸得更長，所以 Dictionary 仍要依不同結尾值分別記錄最佳長度；不能只保留目前全域最長的那一條。

### Dictionary 簡寫怎麼讀？

後面的範例會使用 `{key:value, ...}` 列出 Dictionary 的內容。例如：

```text
dp = {1:1, 2:2}
```

等同於以下兩筆紀錄：

```csharp
dp[1] = 1;
dp[2] = 2;
```

| 簡寫紀錄 | key：結尾值 | value：最佳長度 | 可以形成的序列 |
|---|---:|---:|---|
| `1:1` | 1 | 1 | `[1]` |
| `2:2` | 2 | 2 | `[1,2]` |

因此 `{1:1, 2:2}` 不是陣列，而是「以 1 結尾最長有 1 個、以 2 結尾最長有 2 個」的兩筆紀錄。

### 每輪先保存三個舊長度

處理目前元素 `x` 前，先讀取三個更新前的狀態：

```csharp
dp.TryGetValue(x - 1, out int prev);
dp.TryGetValue(x, out int curr);
dp.TryGetValue(x + 1, out int next);
```

| 變數 | 儲存的舊狀態 | 用途 |
|---|---|---|
| `prev` | 舊 `dp[x - 1]` | 目前元素保持 `x` 時，可接在這條序列後面 |
| `curr` | 舊 `dp[x]` | 目前元素變成 `x + 1` 時，可接在這條序列後面；也可保留既有結果 |
| `next` | 舊 `dp[x + 1]` | 保留既有的、以 `x + 1` 結尾的最佳結果 |

三個變數儲存的都是**長度**。key 不存在時，`TryGetValue` 回傳 `false`，這裡的 `out int` 得到預設值 `0`。此時 `0 + 1 = 1`，自然表示從目前元素開始一條新序列。

### 選擇一：將目前元素 x 加一

```csharp
dp[x + 1] = Math.Max(next, curr + 1);
```

目前元素變成 `x + 1` 後，可以接在舊的、以 `x` 結尾的序列後面：

```text
舊序列：[..., x-1, x]       長度 curr
接上目前元素 x+1
新序列：[..., x-1, x, x+1]  長度 curr+1
```

也可以略過目前元素，保留原本以 `x + 1` 結尾的最佳長度 `next`。因此：

```text
新的 dp[x + 1]
= max(原本的最佳長度, 使用目前元素得到的長度)
= max(next, curr + 1)
```

**Math.Max 比較的是兩個候選長度。** 不是直接比較結尾數值 `x` 和 `x + 1`，也不是直接比較舊的 `dp[x]` 與 `dp[x + 1]`，而是比較 `next` 和延伸後的 `curr + 1`。

同一行的兩種 `+ 1` 意義不同：

| 寫法 | 增加的是什麼？ |
|---|---|
| `dp[x + 1]` 中的 `x + 1` | 元素數值增加一，決定新序列的結尾值 |
| `curr + 1` | 序列長度增加一，因為多選取目前這一個元素 |

### 選擇二：讓目前元素 x 保持原值

```csharp
dp[x] = Math.Max(curr, prev + 1);
```

保持 `x` 時，可以接在舊的、以 `x - 1` 結尾的序列後面，得到長度 `prev + 1`。也可以略過目前元素，保留舊長度 `curr`。

```text
舊序列：[..., x-2, x-1]  長度 prev
接上目前元素 x
新序列：[..., x-2, x-1, x]  長度 prev+1

新的 dp[x] = max(curr, prev + 1)
```

兩條轉移同時涵蓋「加一、保持原值、略過目前元素」的可能性，但只記錄各結尾能達到的最佳長度。

### 更新全域答案 res

```csharp
res = Math.Max(res, Math.Max(dp[x], dp[x + 1]));
```

每輪只有 `dp[x]` 和 `dp[x + 1]` 可能改變，所以用它們更新全域最大長度即可。最後處理的元素未必屬於最佳序列，`res` 負責保留先前找到的答案。

### 為什麼必須保存舊狀態？

同一元素只能使用一次。若先改寫 `dp[x]`，再讀取它更新 `dp[x + 1]`，可能將同一元素同時當成原值及加一後的值。

```text
輸入：[1]
錯誤更新：
  dp[1] = 1
  dp[2] = dp[1] + 1 = 2  ← 唯一的元素被使用兩次，錯誤組出 [1,2]

正確更新：先保存舊 curr = dp[1] = 0（key 不存在，視為 0）
  dp[2] = 0 + 1 = 1     ← 這個元素加一，形成 [2]
  dp[1] = 0 + 1 = 1     ← 這個元素保持原值，形成 [1]
```

更新後的 `{1:1, 2:1}` 代表兩個不同選擇的最佳結果，不表示同一個元素能同時提供 `1` 和 `2`。**各個狀態不需要在同一次修改中同時成立。**

本實作已先保存 `prev`、`curr`、`next`，兩條轉移都只讀舊值，所以這兩行更新可以交換順序；關鍵是不能讀取本輪剛寫入的狀態來再次使用目前元素。

### 入門範例：完整追蹤 [1,1,2]

此輸入已排序。將兩個不同位置的 `1` 暫時標記為 `1a`、`1b`，方便追蹤；它們的數值仍都是 `1`，程式不需要這些標記。

#### 第一步：處理第一個 1a

更新前 `dp = {}`，目前 `x = 1`：

```text
prev = 舊 dp[0] = 0
curr = 舊 dp[1] = 0
next = 舊 dp[2] = 0

dp[2] = max(0, 0+1) = 1  → 1a 加一，形成 [2]
dp[1] = max(0, 0+1) = 1  → 1a 不變，形成 [1]
res = 1
```

更新後 `dp = {1:1, 2:1}`：以 `1` 結尾最長有 `1` 個，以 `2` 結尾也最長有 `1` 個。這是兩種選擇，還不能形成 `[1,2]`。

#### 第二步：處理第二個 1b

更新前 `dp = {1:1, 2:1}`，目前仍是 `x = 1`：

```text
prev = 舊 dp[0] = 0
curr = 舊 dp[1] = 1
next = 舊 dp[2] = 1

dp[2] = max(1, 1+1) = 2  → 保留舊 [2]，或用 1b 加一延伸成 [1,2]
dp[1] = max(1, 0+1) = 1  → 以 1 結尾的最佳長度仍是 1
res = 2
```

此時可以讓 `1a` 保持原值、`1b` 加一，形成 `[1,2]`。兩個 `1` 不能直接接成 `[1,1]`，因為選取結果不能有重複值。

更新後 `dp = {1:1, 2:2}`：以 `1` 結尾最長有 `1` 個，以 `2` 結尾最長有 `2` 個。

#### 第三步：處理原始元素 2

更新前 `dp = {1:1, 2:2}`，這次 `x = 2`，因此讀取的 key 也改變：

```text
prev = 舊 dp[1] = 1
curr = 舊 dp[2] = 2
next = 舊 dp[3] = 0

dp[3] = max(0, 2+1) = 3  → 目前的 2 加一，將 [1,2] 延伸成 [1,2,3]
dp[2] = max(2, 1+1) = 2  → 保留舊結果，或保持目前的 2，最佳長度都是 2
res = 3
```

更新後 `dp = {1:1, 2:2, 3:3}`。答案 `3` 對應的元素使用方式為：

```text
原始元素： 1a    1b     2
修改方式： 不變   +1    +1
選取結果：  1     2     3
```

將 Dictionary 展開為表格，就比較容易看出每筆紀錄的意思：

| 已處理元素 | 以 1 結尾的最長長度 | 以 2 結尾的最長長度 | 以 3 結尾的最長長度 | res |
|---|---:|---:|---:|---:|
| `[1a]` | 1 | 1 | 尚無 | 1 |
| `[1a,1b]` | 1 | 2 | 尚無 | 2 |
| `[1a,1b,2]` | 1 | 2 | 3 | 3 |

**欄位回答「結尾是誰」，格子裡的數字回答「最長有幾個」。**「尚無」表示 key 不存在，讀取舊狀態時視為長度 `0`。

### 原題範例：追蹤 [2,1,5,1,1]

排序後為 `[1,1,1,2,5]`。下表的「更新後 dp」列出完整 Dictionary，`v:L` 表示「以數值 v 結尾，最佳長度為 L」；`prev / curr / next` 也全部都是長度。

| 步驟 | 目前數值 x | 舊 prev / curr / next | 更新後 dp（結尾值:最佳長度） | 全域答案 res |
|---|---:|---|---|---:|
| 1 | 1 | 0 / 0 / 0 | `{1:1, 2:1}` | 1 |
| 2 | 1 | 0 / 1 / 1 | `{1:1, 2:2}` | 2 |
| 3 | 1 | 0 / 1 / 2 | `{1:1, 2:2}` | 2 |
| 4 | 2 | 1 / 2 / 0 | `{1:1, 2:2, 3:3}` | 3 |
| 5 | 5 | 0 / 0 / 0 | `{1:1, 2:2, 3:3, 5:1, 6:1}` | 3 |

前兩步與入門範例相同。第三個 `1` 只能提供 `1` 或 `2`，無法產生 `3`；更新 `dp[2] = max(2, 1+1) = 2`，因此最佳長度沒有增加。處理原值 `2` 時，才可將它加一，形成 `[1,2,3]`。

最後處理 `5` 時，沒有以 `4` 或 `5` 結尾的舊序列，因此只能新建 `[5]` 或 `[6]`，長度都是 `1`。Dictionary 仍保留先前的紀錄，`res` 也仍是 `3`。

```text
排序後元素：1a    1b    1c     2     5
選取結果：   1     2   略過    3   略過
連續序列： [1] → [2] → [3]，長度 3
```

### 正確性理由

初始沒有元素，所有結尾的長度為零。假設舊狀態正確，加入 `x` 後，任何使用目前元素的新序列結尾只能是 `x` 或 `x+1`，分別由舊 `dp[x-1]`、`dp[x]` 延伸得到。

轉移完整列出兩種選擇，也保留不使用目前元素的舊答案，因此更新後狀態仍正確。所有步驟的最大長度就是答案。

### 複雜度與輸入副作用

- 排序 `O(n log n)`，DP 為 `O(n)` 次預期常數時間的 Dictionary 操作，總時間為預期 `O(n log n)`。
- 每個輸入最多產生兩種 key，Dictionary 額外空間為 `O(n)`。
- `Array.Sort(nums)` 會原地排序輸入；要保留原順序，請先複製陣列。

## 解法二：排序＋兩個 DP 狀態

方法：`public int MaxSelectedElementsConstantSpace(int[] nums)`。

### 壓縮狀態的出發點

Dictionary 保留所有結尾，但下一個元素不會小於目前原值 `p`。要建立下一個結尾，只需追蹤以 `p`、`p+1` 結尾的最佳長度；更早的較小結尾若可連接，已由這兩種狀態代表，否則會因距離太大而失去延伸機會。

無法延伸的歷史最佳序列仍由全域答案保存，不會因狀態重設而遺失。

- `unchanged`，以下記為 `a`：以最近原值 `p` 結尾的最佳長度。
- `incremented`，記為 `b`：以 `p+1` 結尾的最佳長度。
- `best`：目前曾經出現的最大長度。

狀態名稱描述的是結尾值，不保證序列一定使用最近那一筆元素。第一個元素可形成 `[p]` 或 `[p+1]`，所以 `a = b = best = 1`。

### 四種差值的轉移推導

令下一個值為 `x`、`gap = x-p`。下表右側一律使用更新前的 `a`、`b`。

| gap | 新 a：結尾 x | 新 b：結尾 x+1 | 原因 |
|---|---|---|---|
| 0 | `a` | `max(b,a+1)` | 相同值不能接在自己後面；加一可延伸舊 a |
| 1 | `max(a+1,b)` | `b+1` | 舊 a 可接上 x，舊 b 本來就以 x 結尾，也要保留 |
| 2 | `b+1` | `1` | 舊 b 的結尾是 x-1；目前值若加一則仍有缺口 |
| >2 | `1` | `1` | 兩種新結尾皆無法接上，重新開始 |

```text
gap=0:   old a ends at x     -- append x+1 --> new b
         old a stays                         new a
         old b competes with new b

gap=1:   old a ends at x-1   -- append x   --> new a
         old b ends at x    -- keep chain --> new a
         old b ends at x    -- append x+1 --> new b

gap=2:   old b ends at x-1   -- append x   --> new a
         no old endpoint at x                new b = 1

gap>2:   [old chain] ... missing values ... [x] or [x+1]
                                             1       1
```

程式以 `oldUnchanged`、`oldIncremented` 保存舊值，避免賦值順序影響轉移；完成後更新 `best`，並將 `p` 移到 `x`。

### 範例演示

同樣使用 `[2,1,5,1,1]`，排序後為 `[1,1,1,2,5]`。

| 已處理的 x | gap | a：結尾 x | b：結尾 x+1 | best |
|---|---|---:|---:|---:|
| 第一個 1 | 初始化 | 1 | 1 | 1 |
| 第二個 1 | 0 | 1 | 2 | 2 |
| 第三個 1 | 0 | 1 | 2 | 2 |
| 2 | 1 | 2 | 3 | 3 |
| 5 | 3 | 1 | 1 | 3 |

```text
Read 1a:   a: [1]          b: [2]              best=1
Read 1b:   a: [1]          b: [1 -> 2]         best=2
Read 1c:   a: [1]          b: [1 -> 2]         best=2
Read 2:    a: [1 -> 2]     b: [1 -> 2 -> 3]    best=3
Read 5:    a: [5]          b: [6]              best=3
```

最後狀態都變為 `1`，但 `best` 仍保存先前的 `3`。

差值為 `2` 的 `[1,3]`：

```text
Original:    [1]       [3]
Choices:    1 or 2    3 or 4
Select:        [2] -> [3]       length=2

old b ends at 2; keep 3 => new a=old b+1=2
current 3 becomes 4    => new b=1
```

差值為 `3` 的 `[1,4]` 無法橋接：`{1,2}` 與 `{4,5}` 間至少缺一個整數，答案為 `1`。

### 正確性理由

第一個元素的兩種結尾正確。假設目前 `a`、`b` 是以 `p`、`p+1` 結尾的最佳長度，下一個值與 `p` 的差只可能落在表中四種情況。

`gap=0` 時，更早元素不可能已提供 `x+2`；`gap=1` 時也不可能已提供 `x+1`，故表中無須另保留這些結尾。`gap>=2` 時，更早元素的最大可能值為 `p+1`，只剩表中列出的橋接或重新開始。

表格已列出保持、加一、保留舊序列的所有可行連接，因此新狀態仍正確；無法延伸的歷史答案由 `best` 保存，最終回傳全域最佳長度。

### 複雜度與輸入副作用

- 排序 `O(n log n)`、DP 掃描 `O(n)`，總時間 `O(n log n)`。
- **DP 狀態**額外空間為 `O(1)`；計入 .NET 陣列排序的呼叫堆疊，整體輔助空間為 `O(log n)`。
- 同樣會原地排序輸入。名稱 ConstantSpace 指排序後的 DP 狀態，不表示排序完全不用堆疊。

## 兩種解法比較

| 面向 | Dictionary DP | 兩狀態 DP |
|---|---|---|
| 狀態 | 每個已知結尾的最佳長度 | 最近原值與原值加一的最佳長度 |
| 時間 | 預期 O(n log n) | O(n log n) |
| DP 額外空間 | O(n) | O(1) |
| 含排序的輔助空間 | O(n) | O(log n) |
| 學習重點 | 依結尾值推導轉移 | 利用排序與最大增量壓縮狀態 |
| 注意事項 | 更新只依賴舊狀態 | 四種差值與全域 best |

建議先理解 Dictionary 版本，再理解壓縮版本。本專案沒有量測兩者的效能差異。

## 可執行測試設計

`Main` 呼叫 `RunTests()`，不需要參數或外部測試套件。

1. **11 組固定案例**：兩個題目範例、單一元素、兩個與三個重複值、已連續數列、可橋接與不可橋接缺口、重複值延伸、最大值、反向輸入。

3. **2 組長度上限案例**：100000 個 `1`，預期 `2`；`1..100000` 連續數列，預期 `100000`。

暴力法列舉 `2^m` 種加一選擇，以 `SortedSet` 去重排序，直接掃描最長連續段，不使用正式解法的 DP 轉移。去重不會損失答案，因相同最終值最多只能選一個。

每次呼叫解法都傳入獨立副本，避免原地排序污染原始資料。固定案例顯示兩種結果，窮舉與大案例僅顯示摘要。若結果不符，例外會列出輸入、預期值及兩種解法的實際值，程序以非零狀態結束。
