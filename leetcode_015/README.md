# LeetCode 15 - 3Sum

![C#](https://img.shields.io/badge/C%23-Console-512BD4?logo=csharp)
![.NET](https://img.shields.io/badge/.NET-10.0-512BD4?logo=dotnet)

這個專案是 LeetCode 15「3Sum／三數之和」的 C# Console 教學範例。程式保留排序加雙指針解法，並加入三層迴圈暴力枚舉與 HashSet Two Sum 解法，讓三種思路可以直接比較。

`Main` 會執行六組固定測資，逐一檢查：

- 解法回傳的三元組集合是否正確。
- 解法執行後是否保留原始輸入陣列。

三種方法都會回傳不重複、組內遞增且依字典序排列的結果。

## 題目說明

給定一個整數陣列 `nums`，找出所有符合下列條件的三元組：

```text
nums[i] + nums[j] + nums[k] == 0
```

三個索引必須互不相同：

```text
i != j
i != k
j != k
```

答案中不能包含重複的三元組。題目不要求三元組之間或三元組內部的特定輸出順序，本專案額外將結果正規化，使主控台輸出保持穩定。

官方範例：

```text
輸入：[-1,0,1,2,-1,-4]
輸出：[[-1,-1,2],[-1,0,1]]
```

因為：

```text
-1 + -1 + 2 = 0
-1 +  0 + 1 = 0
```

雖然不同索引組合可能產生相同的三個值，答案仍只能保留一份。

題目連結：

- [LeetCode 15 - 3Sum](https://leetcode.com/problems/3sum/)
- [力扣 15 - 三數之和](https://leetcode.cn/problems/3sum/)

## 限制條件

- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

在這個範圍內，任意三個元素相加仍不會超出 C# `int` 的有效範圍。

## 解題概念與出發點

最直接的想法是枚舉所有三個不同索引，檢查總和是否為零。這會得到正確答案，但總共有約 `n³` 種組合，資料量增加時會非常慢。

若先固定第一個數 `x`，問題就會變成：

```text
在剩下的元素中尋找 y + z = -x
```

也就是熟悉的 Two Sum。接下來有兩種方式加速：

1. 使用 HashSet 記錄已看過的值，以平均 `O(1)` 的時間尋找補數。
2. 先排序陣列，再使用左右雙指針依總和大小移動。

三種解法都可能從不同索引得到值相同的答案，因此共用下列正規化策略：

1. 將命中的三個值排序為 `first <= second <= third`。
2. 以 `(first, second, third)` tuple 放入 `HashSet` 去重。
3. 回傳前依第一、第二、第三個值排序，產生固定的字典序輸出。

## 解法一：排序 + 雙指針

### 設計說明

`ThreeSum` 先複製 `nums`，因此排序不會修改呼叫端的輸入。排序後：

1. 從左到右枚舉 `first`。
2. 令 `second = first + 1`，`third = nums.Length - 1`。
3. 計算三數總和：
   - `sum == 0`：記錄答案，並同時收縮左右指針。
   - `sum < 0`：目前總和太小，將 `second` 右移以取得較大的值。
   - `sum > 0`：目前總和太大，將 `third` 左移以取得較小的值。
4. `first` 或找到答案後的左右指針遇到重複值時直接跳過，避免重複搜尋。
5. 若 `nums[first] > 0`，後面的值都不小於它，三數總和不可能回到零，可以提早結束。

排序讓指針移動具備方向性：不需要重新掃描所有第三個數，就能排除不可能的區間。

### 範例演示

輸入：

```text
[-1,0,1,2,-1,-4]
```

複製並排序後：

```text
[-4,-1,-1,0,1,2]
```

代表性流程：

| `first` | `second` | `third` | 總和 | 動作 |
| ---: | ---: | ---: | ---: | --- |
| `-4` | `-1` | `2` | `-3` | 總和太小，`second` 右移 |
| `-4` | `0` | `2` | `-2` | 總和太小，`second` 右移 |
| `-4` | `1` | `2` | `-1` | 總和太小，這輪結束 |
| `-1` | `-1` | `2` | `0` | 加入 `[-1,-1,2]`，兩端收縮 |
| `-1` | `0` | `1` | `0` | 加入 `[-1,0,1]` |

下一個 `first` 仍是 `-1`，因為與前一次相同而跳過。最後得到：

```text
[[-1,-1,2],[-1,0,1]]
```

### 複雜度

- 時間複雜度：`O(n²)`。排序為 `O(n log n)`，外層枚舉與雙指針掃描為 `O(n²)`。
- 額外空間：不含答案儲存時為 `O(n)`，用來保存排序複本；若計入去重集合則為 `O(n + k)`，其中 `k` 是答案數。
- 輸入副作用：無，原始 `nums` 保持不變。

## 解法二：三層迴圈暴力枚舉

### 設計說明

`ThreeSum2` 直接枚舉所有滿足以下關係的索引：

```text
first < second < third
```

這個限制保證：

- 三個索引一定互不相同。
- 同一組索引不會因排列順序不同而重複枚舉。

每次計算 `nums[first] + nums[second] + nums[third]`。總和為零時，將三個值排序成標準形式，再加入 HashSet。HashSet 會排除「索引不同、值卻相同」的重複答案。

這是最容易從題意直接推導的版本，適合用來驗證其他最佳化解法，但不適合題目允許的最大資料量。

### 範例演示

輸入：

```text
[-1,0,1,2,-1,-4]
```

部分枚舉結果如下：

| 索引 `(i,j,k)` | 三個值 | 總和 | 處理 |
| --- | --- | ---: | --- |
| `(0,1,2)` | `[-1,0,1]` | `0` | 加入 `[-1,0,1]` |
| `(0,1,3)` | `[-1,0,2]` | `1` | 忽略 |
| `(0,3,4)` | `[-1,2,-1]` | `0` | 正規化為 `[-1,-1,2]` 後加入 |
| `(1,2,4)` | `[0,1,-1]` | `0` | 正規化為 `[-1,0,1]`，HashSet 判定重複 |

即使 `(0,1,2)` 與 `(1,2,4)` 使用不同索引，兩者代表相同的值組合，因此最終只保留：

```text
[[-1,-1,2],[-1,0,1]]
```

### 複雜度

- 時間複雜度：`O(n³)`，三層迴圈枚舉所有三索引組合。
- 額外空間：`O(k)`，用來保存不重複的答案。
- 輸入副作用：無，方法只讀取 `nums`。

## 解法三：HashSet + Two Sum

### 設計說明

`ThreeSum3` 固定 `first` 後，將剩餘問題改寫成：

```text
complement = -nums[first] - nums[second]
```

對固定的 `first`：

1. 建立空的 `seen` HashSet。
2. 從 `first + 1` 開始掃描 `second`。
3. 若 `complement` 已存在於 `seen`，表示先前位置可作為第三個不同索引，三數總和為零。
4. 檢查完成後才把 `nums[second]` 加入 `seen`，確保目前元素不會和自己配對。
5. 每次更換 `first` 都建立新的 `seen`，避免混用不屬於目前 Two Sum 範圍的值。

找到答案後仍透過共用正規化與 HashSet 去重。

### 範例演示

使用輸入 `[-1,0,1,2,-1,-4]`，先固定索引 `0` 的 `-1`：

| `second` 值 | 需要的 `complement` | 檢查前的 `seen` | 結果 |
| ---: | ---: | --- | --- |
| `0` | `1` | `{}` | 尚未出現；加入 `0` |
| `1` | `0` | `{0}` | 找到 `0`；加入 `[-1,0,1]` |
| `2` | `-1` | `{0,1}` | 尚未出現；加入 `2` |
| `-1` | `2` | `{0,1,2}` | 找到 `2`；加入 `[-1,-1,2]` |
| `-4` | `5` | `{-1,0,1,2}` | 尚未出現 |

其他 `first` 可能再次找到相同值組合，但答案 HashSet 會排除重複，最後得到：

```text
[[-1,-1,2],[-1,0,1]]
```

### 複雜度

- 時間複雜度：`O(n²)`；外層固定第一個數，內層掃描剩餘元素，HashSet 查詢平均為 `O(1)`。
- 額外空間：`O(n + k)`；`seen` 最多保存 `O(n)` 個值，另有 `k` 組不重複答案。
- 輸入副作用：無，方法只讀取 `nums`。

## 三種解法比較

| 解法 | 核心概念 | 時間複雜度 | 額外空間 | 是否保留輸入 | 特點 |
| --- | --- | --- | --- | --- | --- |
| `ThreeSum` | 排序 + 雙指針 | `O(n²)` | `O(n + k)` | 是 | 實務上最適合本題，指針移動具方向性 |
| `ThreeSum2` | 三層迴圈 | `O(n³)` | `O(k)` | 是 | 最貼近題意，容易理解但效能最差 |
| `ThreeSum3` | HashSet + Two Sum | `O(n²)` | `O(n + k)` | 是 | 不需排序，以額外雜湊空間換取查找速度 |

`k` 代表不重複答案的數量。
