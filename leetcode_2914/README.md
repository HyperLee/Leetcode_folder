# LeetCode 2914. 使二進位字串變美麗的最少修改次數

## 題目說明

給定二進位字串 `s`，每次可以把一個位置的 `0` 改成 `1`，或把 `1` 改成 `0`。求出讓整個字串變美麗所需的最少修改次數。

美麗字串可以完整切成一段或多段連續的子字串，每段的長度都是偶數，而且每段內的字元都相同。例如 `1100` 可切成 `11 | 00`，而 `0000` 可以整串視為一段。

### 輸入限制

- `2 <= s.Length <= 100000`。
- `s.Length` 為偶數。
- `s` 只包含 `0` 和 `1`，索引從 `0` 開始。

[LeetCode 官方題面](https://leetcode.com/problems/minimum-number-of-changes-to-make-binary-string-beautiful/)

## 貪心法 `MinChanges`

### 從偶數段長找出固定配對

從索引 `0` 出發，每走完一段就前進偶數個位置，因此各段的起點與右側的切割邊界都落在偶數索引。以長度為 `8` 的字串為例，段與段之間只可能在索引 `2`、`4`、`6` 的字元前切開。

```text
Index:   0 1 | 2 3 | 4 5 | 6 7
Pair:     0  |  1  |  2  |  3
```

所以 `(0, 1)`、`(2, 3)` 等固定配對一定各自完整落在某一段裡。美麗字串的每段都由相同字元組成，配對內的兩個字元也必須相同。反過來，只要每個配對相同，就能把每組當成長度為 `2` 的合法段落。

### 為什麼逐組計數就是最小值

| 原本的配對 | 最少修改次數 | 做法 |
| --- | ---: | --- |
| `00`、`11` | 0 | 直接保留這組。 |
| `01`、`10` | 1 | 任選一個位置改成與另一個位置相同。 |

每個不相同的配對都至少要修改一個位置。各組使用的索引互不重疊，因此一次修改只能補足一組的需求。逐組各改一次便可讓所有配對相同，剛好達到這個下限。

### 程式如何掃描

1. 將累計值 `changes` 設為 `0`。
2. 從 `i = 0` 開始，比較 `s[i]` 與 `s[i + 1]`。兩者不同就把 `changes` 加 `1`。
3. 每輪以 `i += 2` 移到下一組。對合法輸入，最後一組是 `(n - 2, n - 1)`，其中 `n` 是字串長度。
4. 回傳 `changes`。演示中的修改字串用來說明成本，程式只累計次數。

掃描共比較 `n / 2` 組，時間複雜度為 **`O(n)`**，額外空間複雜度為 **`O(1)`**。

### ASCII 演示一 `1001`

```text
Index:    0 1 | 2 3
Input:    1 0 | 0 1

i     Compare    Cost    Total
0     1 != 0       1        1
2     0 != 1       1        2

10 | 01 -> 11 | 00
Return 2
```

索引 `0`、`1` 這組可以把索引 `1` 改成 `1`，索引 `2`、`3` 這組可以把索引 `3` 改成 `0`。兩組各改一次，得到合法分段 `11 | 00`。

### ASCII 演示二 `00100111`

```text
Index:    0 1 | 2 3 | 4 5 | 6 7
Input:    0 0 | 1 0 | 0 1 | 1 1

i     Compare    Cost    Total
0     0 == 0       0        0
2     1 != 0       1        1
4     0 != 1       1        2
6     1 == 1       0        2

00 | 10 | 01 | 11 -> 00 | 11 | 00 | 11
Return 2
```

第一組與最後一組已符合條件。中間兩組分別修改索引 `3` 和 `5`，累計值依序為 `0 -> 1 -> 2 -> 2`。

## XOR 累加 `MinChangesXor`

`'0'` 和 `'1'` 的 UTF-16 編碼分別是 `0x0030` 和 `0x0031`，只有最低位元不同。每組直接把 `s[i] ^ s[i + 1]` 加到答案。`00` 和 `11` 得到 `0`，`01` 和 `10` 得到 `1`，剛好是該組的修改次數。

## SIMD 批次比較 `MinChangesSimd`

1. 用 `MemoryMarshal.Cast<char, uint>` 將每兩個 UTF-16 字元視為一個 `uint`，直接讀取原本的字串記憶體。
2. 每次載入四個 `uint` 到 `Vector128<uint>`，也就是四組配對。每個元素右移 16 位，再和原值做 XOR，使配對內兩個字元的最低位元對齊比較。用 `& 1u` 取出各組的 `0` 或 `1`。
3. 將每批結果累加到向量，最後用 `Vector128.Sum` 加總四個元素。尾端不足四組時，逐組做 XOR。執行環境缺少 128 位元向量硬體加速時，整串交由 `MinChangesXor` 處理。

以 `0010011110` 為例，SIMD 先處理 `00 | 10 | 01 | 11`，得到 `2`，尾端的 `10` 再加 `1`，總共需要修改 `3` 次。

## 三種解法比較

| 解法 | 處理方式 | 時間 | 額外空間 | 優點 | 缺點與限制 | 適用情境 |
| --- | --- | --- | --- | --- | --- | --- |
| 貪心 `MinChanges` | 每輪用 `!=` 比較一組 | `O(n)` | `O(1)` | 直接表達「不同就加一」，易於閱讀與維護 | 原始碼每組都有一次 `if` 判斷 | LeetCode 提交、解題教學 |
| XOR `MinChangesXor` | 每輪累加一組的 XOR 結果 | `O(n)` | `O(1)` | 每組直接得到 `0` 或 `1`，迴圈內省去逐組的 `if` | 直接用 XOR 計數仰賴 `'0'` 和 `'1'` 的字元編碼只差最低位元 | 學習位元運算、比較逐組處理的寫法 |
| SIMD `MinChangesSimd` | 每批處理四組，尾端逐組做 XOR | `O(n)` | `O(1)` | 有硬體加速時可平行處理多組，直接讀取字串記憶體 | 實作較複雜，需加總向量與處理尾端，缺少加速時回退至 XOR | 比較長字串的批次處理效能 |

令 `n` 為字串長度。三種解法都檢查相同的 `n / 2` 組固定配對，且只使用固定數量的計數器或向量，所以時間同為 `O(n)`，額外空間同為 `O(1)`。SIMD 在有硬體加速時，每次向量迴圈處理四組，減少了迴圈次數。實際速度取決於 CPU、JIT、輸入長度和相同與不同配對的分布，需要透過效能測試比較。

## 建置與執行範例

安裝 .NET 10 SDK 後，在包含本 README 的目錄執行下列指令。

```powershell
dotnet build ./leetcode_2914/leetcode_2914.csproj -c Release
dotnet run --project ./leetcode_2914/leetcode_2914.csproj -c Release --no-build
```

`Main` 對每筆輸入執行三種解法。七筆案例涵蓋官方範例、合法分段、剛好填滿一批 SIMD 的 8 字元、含一組尾端的 10 字元，以及 100,000 字元的題目上限。任一解法的結果與預期不符時，該案例會顯示 `FAIL`，程序跑完所有案例後以非零狀態碼結束。

```text
s = "1001" | greedy = 2 | xor = 2 | simd = 2 | expected = 2 | PASS
s = "10" | greedy = 1 | xor = 1 | simd = 1 | expected = 1 | PASS
s = "0000" | greedy = 0 | xor = 0 | simd = 0 | expected = 0 | PASS
s = "1100" | greedy = 0 | xor = 0 | simd = 0 | expected = 0 | PASS
s = "00100111" | greedy = 2 | xor = 2 | simd = 2 | expected = 2 | PASS
s = "0010011110" | greedy = 3 | xor = 3 | simd = 3 | expected = 3 | PASS
重複 01（長度 100000） | greedy = 50000 | xor = 50000 | simd = 50000 | expected = 50000 | PASS
```
