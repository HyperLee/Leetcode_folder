# LeetCode 961：在長度 2N 的陣列中找出重複 N 次的元素

這是一個以 .NET 10 撰寫的可執行教學範例。專案提供三種解法，從直觀的
`HashSet`、利用數值範圍的頻率陣列，到只使用常數額外空間的鄰距檢查，
並以五組固定案例驗證答案與輸入陣列是否保持不變。

- 題目：[N-Repeated Element in Size 2N Array](https://leetcode.com/problems/n-repeated-element-in-size-2n-array/)
- 專案：`leetcode_961/leetcode_961.csproj`
- 目標框架：`.NET 10`

## 題目說明

給定一個長度為 `2 * n` 的整數陣列 `nums`：

- 陣列共有 `n + 1` 個不同的值。
- 其中 `n` 個值各出現一次。
- 唯一剩下的值恰好出現 `n` 次。

請回傳重複 `n` 次的元素。

### 官方範例

```text
輸入：nums = [1,2,3,3]
輸出：3
```

```text
輸入：nums = [2,1,2,5,3,2]
輸出：2
```

```text
輸入：nums = [5,1,5,2,5,3,5,4]
輸出：5
```

### 限制條件

- `2 <= n <= 5000`
- `nums.Length == 2 * n`
- `0 <= nums[i] <= 10^4`
- `nums` 共有 `n + 1` 個不同元素。
- 唯一一個元素恰好重複 `n` 次，其餘元素各出現一次。

## 解題概念與出發點

題目給的資料分布非常特殊：除了答案以外，其他值都只出現一次。因此不必
完整統計所有元素後再尋找最大頻率；只要能發現「某個值第二次出現」，便可
立即確定它就是答案。

這個觀察帶出兩個直接解法：

1. 用集合記住曾經看過的值。
2. 用元素值作為陣列索引，記住每個值的出現次數。

還可以進一步利用答案佔陣列一半的密度。設重複值出現 `n` 次，如果任意兩次
相鄰出現的位置都至少相距 4，那麼它們至少需要：

```text
1 + 4 * (n - 1) = 4n - 3
```

個位置。但原陣列只有 `2n` 個位置，而且 `n >= 2`，所以 `4n - 3 > 2n`。
這形成矛盾，代表必定存在一對重複值，其索引距離介於 1 到 3。第三種解法
因此只需要檢查這三種距離，不必配置額外資料結構。

## 解法比較

| 解法 | 方法 | 時間複雜度 | 額外空間 | 特點 |
| --- | --- | --- | --- | --- |
| `RepeatedNTimes` | `HashSet<int>` | O(n) | O(n) | 最直觀，不依賴元素值上限 |
| `RepeatedNTimes2` | 固定頻率陣列 | O(n) | O(U)，`U = 10001` | 查找快速，但依賴 `nums[i]` 的範圍 |
| `RepeatedNTimes3` | 距離 1～3 比較 | O(n) | O(1) | 空間最佳，需要理解密度推理 |

三種方法都只讀取 `nums`，不會排序或改寫輸入陣列。若傳入資料不符合題目
保證而找不到答案，實作會回傳 `-1` 作為不可達情況的防禦值。

## 解法一：HashSet

### 設計

`HashSet<int>` 用來保存已經看過的元素。從左到右掃描 `nums`，呼叫
`seen.Add(num)`：

- 回傳 `true`：這是第一次看見 `num`，繼續掃描。
- 回傳 `false`：`num` 已在集合內，這是它第二次出現。

由於題目保證其他元素只出現一次，第一個加入失敗的值必定就是重複 `n` 次
的答案，可以立即回傳，不必掃完剩餘內容。

### 正確性

集合在處理目前元素以前，包含所有已掃描過的不同值。若 `Add` 失敗，代表
目前值曾經出現；題目又保證只有答案會出現超過一次，所以回傳值必為答案。

### 範例演示

以 `[2, 1, 2, 5, 3, 2]` 為例：

| 讀取值 | 加入前集合 | `Add` 結果 | 動作 |
| --- | --- | --- | --- |
| `2` | `{}` | `true` | 保存 `2` |
| `1` | `{2}` | `true` | 保存 `1` |
| `2` | `{2, 1}` | `false` | `2` 已出現，回傳 `2` |

## 解法二：固定頻率陣列

### 設計

因為 `0 <= nums[i] <= 10000`，可配置長度為 `10001` 的 `int[]`，直接使用
元素值作為索引。每讀取一個 `num` 就執行 `frequencies[num]++`；當計數到達
`2` 時，表示已找到唯一可能重複的元素。

這個方法省去雜湊運算，但將正確性建立在題目明確給定的數值範圍上。如果值域
變得很大或允許負數，HashSet 會比配置巨大陣列更合適。

### 正確性

`frequencies[x]` 等於目前已掃描區段中 `x` 的出現次數。當某個計數首次到達
2，該值已重複；其他值依題意只能出現一次，因此它必定是答案。

### 範例演示

以 `[10000, 1, 10000, 2]` 為例：

| 讀取值 | 更新後計數 | 動作 |
| --- | --- | --- |
| `10000` | `frequencies[10000] = 1` | 繼續 |
| `1` | `frequencies[1] = 1` | 繼續 |
| `10000` | `frequencies[10000] = 2` | 回傳 `10000` |

這個案例也驗證頻率陣列能正確處理題目允許的元素上界。

## 解法三：鄰距檢查

### 設計

依序檢查索引距離 `1`、`2`、`3`：

```text
nums[i] == nums[i - distance]
```

只要找到相等的一對，就回傳該元素。外層距離只有三種固定值，所以即使程式
形式是雙層迴圈，總比較次數仍不超過約 `3 * nums.Length`，時間複雜度仍是
O(n)，額外空間則是 O(1)。

### 正確性

前面的密度推理證明，合法輸入中必定有兩個重複值的索引距離不超過 3。
演算法完整檢查距離 1、2、3 的所有索引對，因此一定會檢查到其中一對。
其他值只出現一次，不可能形成相等的一對，所以找到的值必定是答案。

### 範例演示

以 `[0, 1, 2, 0]` 為例：

1. 距離 1：比較 `(0,1)`、`(1,2)`、`(2,0)`，皆不相等。
2. 距離 2：比較 `(0,2)`、`(1,0)`，皆不相等。
3. 距離 3：比較索引 `0` 與 `3`，兩者皆為 `0`。
4. 回傳 `0`。

這是重複元素相隔最遠仍需要被檢查的情況。

`Main` 會以三種解法分別執行下列五組案例：

| 案例 | 輸入 | 預期 | 驗證重點 |
| --- | --- | --- | --- |
| 1 | `[1, 2, 3, 3]` | `3` | 相鄰重複 |
| 2 | `[2, 1, 2, 5, 3, 2]` | `2` | 官方一般案例 |

每次呼叫都使用獨立副本，PASS 必須同時滿足：

- 實際答案等於預期答案。
- 呼叫後的輸入內容與呼叫前完全相同。

因此總共有 `5 個案例 * 3 種解法 = 15` 項驗證。
