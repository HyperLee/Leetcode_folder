# 3875. Construct Uniform Parity Array I

[![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4)](https://dotnet.microsoft.com/)

這是一個使用 C# 與 .NET 10 撰寫的 LeetCode 3875 解題範例。專案除了保留
LeetCode 要求的 `UniformArray` 方法，也在 `Main` 中提供不需要輸入資料的固定案例，
方便直接建置、執行並觀察 PASS/FAIL 結果。

- 題目：[Construct Uniform Parity Array I](https://leetcode.com/problems/construct-uniform-parity-array-i/description/)
- 解法：數學分析與奇偶性證明
- 執行方式：.NET 10 console application

## 題目說明

給定一個由 `n` 個互異整數組成的陣列 `nums1`，要建立另一個長度相同的
`nums2`，使 `nums2` 的所有元素要嘛都是奇數，要嘛都是偶數。

對每個索引 `i`，必須選擇下列其中一種操作：

1. 直接保留：`nums2[i] = nums1[i]`
2. 選擇另一個索引 `j`：`nums2[i] = nums1[i] - nums1[j]`，且 `j != i`

`UniformArray` 回傳 `true` 代表至少存在一種合法的 `nums2`；若不存在則回傳
`false`。

## 限制條件

依照官方題目限制：

- `1 <= n == nums1.length <= 100`
- `1 <= nums1[i] <= 100`
- `nums1` 中的元素互不相同

題目沒有要求 `nums2` 的元素必須為正數，因此例如 `2 - 3 = -1` 是合法結果。

## 解題概念與出發點

這題的重點不是搜尋每個元素要使用哪一種操作，而是觀察奇偶性：

- 奇數減奇數會得到偶數。
- 偶數減奇數會得到奇數。
- 直接保留元素時，元素的奇偶性不變。

只要能把所有元素統一成奇數或統一成偶數，就符合題目要求。

### 關鍵觀察：答案對所有合法輸入都成立

可以分成兩種情況：

1. `nums1` 全部是奇數，或全部是偶數。
   這時對每個索引都使用第一種操作，直接保留原值即可。
   `nums2` 會與 `nums1` 相同，因此所有元素具有相同奇偶性。

2. `nums1` 同時包含奇數與偶數。
   任選 `nums1` 中的一個奇數 `x` 作為基準：
   - 原本是奇數的元素直接保留。
   - 原本是偶數的元素改成「該偶數減去 `x`」。

   因為偶數減奇數一定是奇數，所以最後所有元素都會是奇數。
   需要使用減法的元素原本是偶數，而基準 `x` 位於奇數元素的位置，因此
   減法中的索引自然符合 `j != i`。

因此，不論輸入是全奇數、全偶數，或是奇偶混合，都一定能構造出符合條件的
`nums2`。在題目保證輸入合法的前提下，答案固定為 `true`。

## 解法設計

### 方法一：數學分析

#### 方法目標

`UniformArray(int[] nums1)` 只需要判斷「是否存在」符合條件的 `nums2`，
不需要把這個 `nums2` 實際建立出來。

#### 設計流程

```text
輸入：符合題目限制的 nums1

若 nums1 全部同奇偶：
    所有 nums2[i] 直接使用 nums1[i]
否則：
    選擇任一個奇數 x
    奇數元素直接保留
    每個偶數元素減去 x，得到奇數

因為上述兩種情況都能成功，回傳 true
```

#### 正確性說明

設 `nums1` 是題目保證的合法輸入。

- 若 `nums1` 的所有元素同奇偶，直接複製每個元素後，`nums2` 的所有元素
  仍同奇偶，構造成功。
- 若 `nums1` 同時有奇數和偶數，選一個奇數 `x`。奇數元素直接保留仍為奇數；
  偶數元素減去奇數 `x` 後為奇數。因此所有 `nums2` 元素都是奇數，構造成功。

兩種可能涵蓋所有輸入，所以每個合法 `nums1` 都存在可行的 `nums2`，
`UniformArray` 回傳 `true` 是正確的。

#### 為什麼程式可以直接回傳 `true`？

這個方法的回傳型別是 `bool`，題目只要求回答能否完成構造，而不是要求回傳
構造後的陣列。由於數學證明已經證明所有合法輸入都可行，程式不需要：

- 掃描陣列找奇數或偶數；
- 嘗試不同的索引 `j`；
- 實際配置或填入 `nums2`。

所以目前實作的 `return true` 代表的是「在題目輸入契約下，構造一定存在」，
不是忽略輸入資料。

#### 複雜度

- 時間複雜度：`O(1)`
- 額外空間複雜度：`O(1)`

這是針對目前 `bool` API 的複雜度：方法不遍歷 `nums1`，也不建立 `nums2`。
若另寫一個真正回傳 `nums2` 的展示方法，建立陣列本身會需要 `O(n)` 時間與
`O(n)` 空間，但那不是本專案目前的 API。

## 範例演示流程

### 範例一：`nums1 = [2, 3]`

陣列同時有偶數 `2` 與奇數 `3`，選 `x = 3`：

```text
索引 0：2 是偶數，使用 2 - 3 = -1
索引 1：3 是奇數，直接保留 3

nums2 = [-1, 3]
```

`-1` 與 `3` 都是奇數，因此結果為 `true`。對索引 0 使用的基準位於索引 1，
符合 `j != i`。

### 範例二：`nums1 = [4, 6]`

兩個元素都是偶數，不需要使用減法：

```text
索引 0：直接保留 4
索引 1：直接保留 6

nums2 = [4, 6]
```

所有元素都是偶數，因此結果為 `true`。

### 全部為奇數：`nums1 = [1, 3, 5]`

所有元素已經是奇數，直接保留：

```text
nums2 = [1, 3, 5]
```

不需要挑選基準或執行減法，結果為 `true`。

### `n = 1` 的邊界：`nums1 = [1]`

只有一個元素時，直接使用第一種操作即可：

```text
nums2 = [1]
```

單一元素自然具有一致的奇偶性，結果為 `true`。

### `n = 100` 的邊界：`nums1 = [1, 2, ..., 100]`

這組資料同時包含奇數與偶數，可以選最前面的奇數 `x = 1`：

- 奇數元素直接保留，例如 `1`、`3`、`5`。
- 偶數元素減去 `1`，例如 `2 - 1 = 1`、`4 - 1 = 3`、`100 - 1 = 99`。

所有結果都會是奇數，因此最大長度的合法輸入也能成功。

## Main 固定測試案例

`Main` 不讀取命令列或主控台輸入，而是使用五組固定資料：

| 案例 | 輸入特性 | 預期結果 |
| --- | --- | --- |
| 官方範例 1 | 奇偶混合：`[2, 3]` | `true` |
| 官方範例 2 | 全部為偶數：`[4, 6]` | `true` |
| 全部為奇數 | `[1, 3, 5]` | `true` |
| `n = 1` 邊界 | `[1]` | `true` |
| `n = 100` 邊界 | `Enumerable.Range(1, 100)` | `true` |

每組案例都由 `RunTestCase` 呼叫 `UniformArray`，比較預期與實際結果，
並輸出 `PASS` 或 `FAIL`。最後列出通過與失敗總數。
