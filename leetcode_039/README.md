# LeetCode 39：組合總和

這個專案是 LeetCode 39「Combination Sum / 組合總和」的 C# console 實作。程式使用排序、深度優先搜尋與回溯，找出所有總和等於目標值的不重複組合，並提供 5 組可直接執行的驗證案例。

## 題目說明

給定一個元素互不相同的正整數陣列 `candidates`，以及正整數 `target`，找出所有數字總和等於 `target` 的不同組合。

- 每個候選數字可以不限次數重複選取。
- 答案中的組合不能重複。
- 組合內數字的排列順序不影響組合是否相同。例如 `[2, 2, 3]` 與 `[3, 2, 2]` 應視為同一組答案。
- 答案可以任意順序回傳。

題目連結：

- [LeetCode 39. Combination Sum](https://leetcode.com/problems/combination-sum/description/)
- [力扣 39. 组合总和](https://leetcode.cn/problems/combination-sum/description/)

## 限制條件

LeetCode 原題限制如下：

- `1 <= candidates.length <= 30`
- `2 <= candidates[i] <= 40`
- `candidates` 的所有元素互不相同。
- `1 <= target <= 40`
- 對每一組輸入，總和等於 `target` 的不同組合少於 150 組。

> [!IMPORTANT]
> 目前 `CombinationSum` 會使用 `Array.Sort` 原地排序 `candidates`。呼叫完成後，傳入陣列會變成遞增順序；若呼叫端需要保留原始順序，應先自行複製陣列。

## 解題概念與出發點

一般巢狀迴圈無法預先知道一個組合需要選取幾個數字。例如 `target = 8` 時，答案可能是四個數字 `[2, 2, 2, 2]`，也可能只有兩個數字 `[3, 5]`。因此適合使用回溯法動態建立不同長度的組合。

每一層遞迴都要做三件事：

1. **選擇**：把目前候選數字加入組合。
2. **探索**：扣除該數字後，遞迴搜尋剩餘目標值。
3. **撤銷**：移除剛加入的數字，改走其他候選分支。

搜尋過程另外維護 `start` 索引，限制下一層只能選擇目前位置或右側的數字：

- 遞迴仍從目前索引 `i` 開始，所以同一數字可以重複選取。
- 不會回頭選擇較小索引的數字，因此只會產生 `[2, 2, 3]`，不會再產生 `[3, 2, 2]`。

## 解法一：排序搭配回溯

### 設計步驟

1. 先將 `candidates` 依遞增順序排序。
2. 建立 `combination` 保存目前遞迴路徑，並從 `start = 0` 開始搜尋。
3. 當剩餘目標值為 `0`，複製目前路徑並加入結果。
4. 從 `start` 開始逐一考慮候選數字：
   - 如果候選值大於剩餘目標值，由於後續數字只會更大，可直接停止本層迴圈。
   - 否則選取該數字，遞迴搜尋 `target - candidates[i]`。
   - 遞迴回來後移除最後一個數字，繼續探索其他分支。
5. 遞迴時傳入目前索引 `i`，允許再次使用同一候選數字。

核心狀態可以理解為：

```text
Backtrack(candidates, remainingTarget, result, currentCombination, start)
```

- `remainingTarget`：目前還需要湊出的數值。
- `currentCombination`：目前已選擇的數字。
- `start`：本層允許選擇的最小候選索引。

### 範例演示流程

以 `candidates = [2, 3, 6, 7]`、`target = 7` 為例：

| 步驟 | 目前組合 | 剩餘目標 | start | 動作 |
| --- | --- | ---: | ---: | --- |
| 1 | `[]` | 7 | 0 | 選擇 `2` |
| 2 | `[2]` | 5 | 0 | 索引仍為 0，再次選擇 `2` |
| 3 | `[2, 2]` | 3 | 0 | `2` 仍可選，先探索 `[2, 2, 2]`，回溯後改選 `3` |
| 4 | `[2, 2, 3]` | 0 | 1 | 命中目標，複製組合加入結果 |
| 5 | `[]` | 7 | 0 | 其他分支完成後選擇 `7` |
| 6 | `[7]` | 0 | 3 | 再次命中目標，加入結果 |

最後得到：

```text
[[2, 2, 3], [7]]
```

### 如何避免排列重複

找到 `[2, 2, 3]` 後，搜尋不會再從索引 0 回頭選取 `2`。因此走到以 `3` 開頭的分支時，只能繼續使用 `3`、`6` 或 `7`，不可能產生 `[3, 2, 2]`。

這項限制排除的是同一批數字的不同排列，不會排除合法的重複選取。因為選取 `2` 後仍以同一索引遞迴，所以 `[2, 2, 3]` 中的兩個 `2` 仍可正常產生。

### 剪枝流程

假設目前組合為 `[2, 2]`，剩餘目標為 `3`：

1. 候選值 `2 <= 3`，可以繼續探索。
2. 候選值 `3 == 3`，可以直接形成答案 `[2, 2, 3]`。
3. 下一個候選值 `6 > 3`，而陣列已排序，後面的 `7` 也一定超過剩餘目標。
4. 程式使用 `break` 結束本層搜尋，不再建立必定失敗的分支。

排序不只讓輸出組合維持遞增，也使這項提前停止的判斷成立。

### 複雜度分析

令 `n` 為候選數量，`m` 為最小候選值：

- 排序時間為 `O(n log n)`。
- 回溯樹最大深度約為 `target / m`；搜尋時間會隨可行選擇呈指數成長，可用 `O(n^(target / m))` 表示寬鬆上界，實際執行量會受排序剪枝與答案數量影響。
- 不計回傳結果時，遞迴呼叫堆疊與目前組合需要 `O(target / m)` 額外空間。
- 結果集合所需空間取決於有效組合的數量與各組合長度。

## 結果驗證方式

題目允許以任意順序回傳答案，因此 console harness 不直接依原始列舉順序比較巢狀集合。`FormatCombinations` 會先排序每一個組合，再將所有組合依固定順序排列，讓等價答案得到相同文字後再判斷 `PASS` 或 `FAIL`。

顯示輸入時會先保留一份原始資料，因此未排序案例仍會印出 `[7, 3, 2, 6]`；這不會改變 `CombinationSum` 本身原地排序輸入的契約。
