## 題目說明

給定兩個字串 `s` 與 `t`。如果 `t` 是 `s` 的字母異位詞，回傳 `true`；否則回傳 `false`。

「字母異位詞」必須符合兩個條件：

1. 兩個字串長度相同。
2. 每一個字母在兩個字串中的出現次數完全相同。

字母順序不需要相同。例如：

- `s = "anagram"`、`t = "nagaram"`：兩邊都有三個 `a`，以及各一個 `n`、`g`、`r`、`m`，因此結果為 `true`。
- `s = "rat"`、`t = "car"`：`t` 包含 `c`，但 `s` 沒有；`s` 包含 `t`，但 `t` 沒有，因此結果為 `false`。

## 限制條件

- `1 <= s.length, t.length <= 5 × 10^4`
- `s` 與 `t` 只包含小寫英文字母。

題意與限制以 [LeetCode 242 — Valid Anagram](https://leetcode.com/problems/valid-anagram/) 為準。

> [!NOTE]
> 本專案依原題限制設計。固定陣列解法以 `字元 - 'a'` 作為索引，因此呼叫端必須遵守小寫英文字母輸入契約。

## 解題概念與出發點

判斷字母異位詞時，真正重要的不是字母所在的位置，而是每個字母的出現頻率。

一種直觀做法是先排序兩個字串，再比較排序結果，但排序需要 `O(n log n)` 時間。由於題目只允許 26 個小寫英文字母，可以直接計數：

1. 先檢查長度。長度不同代表字元總數不同，可立即回傳 `false`。
2. 統計 `s` 與 `t` 中每個字母的頻率差。
3. 所有字母的頻率差都為零時，兩字串才互為字母異位詞。

兩種解法都採用這個判定原則，差別在於頻率表的表示方式，以及建立和抵銷計數的流程。

## 解法一：固定 26 格陣列

### 設計說明

`IsAnagram` 建立長度為 26 的 `int[]`，索引 `0` 到 `25` 分別代表 `a` 到 `z`。字元 `c` 對應的索引可由 `c - 'a'` 算出。

演算法在同一輪同時讀取 `s[i]` 與 `t[i]`：

1. `s[i]` 對應的計數加一。
2. `t[i]` 對應的計數減一。
3. 走訪結束後檢查 26 格計數。
4. 任一格不為零時回傳 `false`；全部為零時回傳 `true`。

這個方法維護的關鍵不變量是：`charCount[x]` 始終表示目前已讀取區段中，字母 `x` 在 `s` 的出現次數減去它在 `t` 的出現次數。正數代表 `s` 較多，負數代表 `t` 較多。

### 正確性

- 長度不同時，兩字串的字元總數不同，不可能互為字母異位詞。
- 長度相同時，每輪各處理 `s` 與 `t` 的一個字元，不會遺漏任何位置。
- 最終某格大於零，代表該字母在 `s` 中較多；小於零則代表在 `t` 中較多。兩種情況都不是字母異位詞。
- 只有 26 格全部為零，才能證明每個小寫英文字母的出現次數都相同。

### 範例演示

輸入 `s = "anagram"`、`t = "nagaram"`。下表只列出有變化的字母；數值表示 `s` 頻率減去 `t` 頻率：

| 輪次 | `s[i]` 加一 | `t[i]` 減一 | 非零頻率差 |
|---:|---|---|---|
| 1 | `a` | `n` | `a: 1, n: -1` |
| 2 | `n` | `a` | 全部歸零 |
| 3 | `a` | `g` | `a: 1, g: -1` |
| 4 | `g` | `a` | 全部歸零 |
| 5 | `r` | `r` | 全部維持零 |
| 6 | `a` | `a` | 全部維持零 |
| 7 | `m` | `m` | 全部維持零 |

最後 26 格都是零，因此回傳 `true`。

### 複雜度與取捨

- 時間複雜度：`O(n + 26)`，簡化為 `O(n)`。
- 輔助空間複雜度：`O(26)`，簡化為 `O(1)`。
- 優點：只需一次同步走訪，記憶體固定，常數成本低。
- 注意事項：陣列索引設計直接依賴小寫英文字母限制，不能直接接受其他字元集合。

## 解法二：Dictionary 計數

### 設計說明

`IsAnagram2` 使用 `Dictionary<char, int>`，key 是實際出現過的字母，value 是尚未被第二個字串抵銷的次數：

1. 走訪 `s`，建立完整頻率表。
2. 走訪 `t`，找到對應 key 後將計數減一。
3. 如果 `t` 出現字典中不存在的字母，立即回傳 `false`。
4. 走訪字典，確認所有 value 都已歸零。

這個方法把「建立需求量」與「用第二個字串滿足需求量」拆成兩個階段。第二階段完成後，字典中的剩餘值就是兩字串的頻率差。

### 正確性

- 長度檢查先排除字元總數不同的情況。
- 第一輪完成後，字典精確保存 `s` 中每個字母的完整頻率。
- 第二輪每讀到 `t` 的一個字母，就抵銷 `s` 中同一字母的一次出現。
- `t` 出現未記錄的字母，代表兩邊字母集合不同。
- 最後任一 value 不為零，代表該字母的出現次數不同；所有 value 為零時，頻率才完全一致。

### 範例演示

輸入 `s = "anagram"`、`t = "nagaram"`：

1. 讀完 `s` 後，字典為 `{ a: 3, n: 1, g: 1, r: 1, m: 1 }`。
2. 依序讀取 `t`：

| 讀取字母 | 抵銷後仍為正數的計數 |
|---|---|
| `n` | `a: 3, g: 1, r: 1, m: 1` |
| `a` | `a: 2, g: 1, r: 1, m: 1` |
| `g` | `a: 2, r: 1, m: 1` |
| `a` | `a: 1, r: 1, m: 1` |
| `r` | `a: 1, m: 1` |
| `a` | `m: 1` |
| `m` | 無，所有計數皆為零 |

所有字母都能在字典中找到，且最終計數全部歸零，因此回傳 `true`。

### 複雜度與取捨

- 時間複雜度：建立、抵銷及檢查共為 `O(n + k)`，簡化為 `O(n)`。
- 輔助空間複雜度：`O(k)`，`k` 是 `s` 中不同字母數；依本題限制 `k <= 26`。
- 優點：key 直接保存字元，頻率建立與抵銷流程容易觀察，也不需預先配置更大的字元範圍。
- 注意事項：雜湊表有額外管理成本；就本題固定 26 個字母的條件而言，陣列通常更精簡。

## 兩種解法比較

| 比較項目 | 固定 26 格陣列 | `Dictionary<char, int>` |
|---|---|---|
| 主要 API | `IsAnagram` | `IsAnagram2` |
| 頻率表示 | `int[26]` | 字元到整數的雜湊表 |
| 主要流程 | 同步加一、減一，再檢查陣列 | 建立 `s` 頻率、用 `t` 抵銷，再檢查字典 |
| 字串走訪 | 一次同步走訪 | 分別走訪 `s`、`t` |
| 時間複雜度 | `O(n)` | `O(n)`，平均雜湊操作為 `O(1)` |
| 輔助空間 | `O(1)` | `O(k)`，本題 `k <= 26` |
| 適用輸入 | 嚴格限定小寫英文字母 | key 表示較彈性，但本 API 仍遵守原題限制 |
| 主要優勢 | 固定空間且常數成本低 | 資料含義直觀，容易延伸字元集合 |

## 可執行案例

| 案例 | `s` | `t` | 預期 | 驗證重點 |
|---:|---|---|---|---|
| 1 | `anagram` | `nagaram` | `true` | 官方可重新排列範例 |
| 2 | `rat` | `car` | `false` | 官方字母集合不同範例 |
| 3 | `aacc` | `ccac` | `false` | 長度相同但重複字母頻率不同 |
| 4 | `ab` | `a` | `false` | 長度不同時提前結束 |

每一組案例都會交給兩種解法，並將實際值與預期值直接比較。六組案例乘以兩種解法，共有 12 項驗證。

目前沒有獨立的自動化測試專案；驗收方式是成功建置後執行這個固定 console 驗證器，確認每一項都顯示 `PASS`。
