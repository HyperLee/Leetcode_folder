## 題目說明

給定一個 `m x n` 的整數矩陣 `image`，其中 `image[row][column]` 代表一個像素的顏色。另給起點 `(sr, sc)` 與目標顏色 `color`，請從起點開始，將所有符合下列條件的像素改為目標顏色：

1. 像素原本的顏色必須與起點像素的原始顏色相同。
2. 像素必須能透過上、下、左、右相鄰關係與起點連通。
3. 對角線接觸不算相連。

方法會直接修改輸入矩陣，最後回傳完成填色的同一個矩陣。

題目連結：[LeetCode 733. Flood Fill](https://leetcode.com/problems/flood-fill/description/)

## 限制條件

- `m == image.Length`
- `n == image[i].Length`
- `1 <= m, n <= 50`
- `0 <= image[i][j], color < 2^16`
- `0 <= sr < m`
- `0 <= sc < n`

因此輸入一定是非空矩陣，起點也一定在矩陣範圍內。演算法不需要處理空矩陣或非法座標。

## 解題概念與出發點

這題可以視為「找出起點所在的同色連通區」：

- 每個像素是一個節點。
- 上、下、左、右的相鄰像素之間是一條邊。
- 只有顏色等於起點原色的節點可以繼續走訪。
- 走訪到的節點都改成目標顏色。

一般圖形走訪需要額外的 `visited` 集合，但這題可以直接利用改色後的矩陣作為走訪標記。只要在展開鄰居前將像素改成 `color`，之後再遇到它時，其顏色已不等於起點原色，自然不會被重複處理。

若起點原色已經等於目標顏色，DFS 與 BFS 都會立刻回傳。這個判斷除了省略不必要的搜尋，也避免「改色」無法留下已走訪狀態，導致像素彼此反覆展開。

## 解法一：DFS 遞迴

### 設計

`FloodFill` 先保存起點的原始顏色，再呼叫 `DFS`：

1. 若起點原色等於目標顏色，直接回傳原矩陣。
2. `DFS` 檢查目前像素是否仍等於起點原色。
3. 符合時先將目前像素改成目標顏色，代表已走訪。
4. 依序檢查下、右、左、上四個方向。
5. 只有座標仍在矩陣內時才進入下一層遞迴。
6. 若像素不是起點原色，該遞迴分支自然停止。

DFS 會沿著其中一條路徑持續深入，直到碰到邊界或不同顏色，再回到上一層探索尚未處理的方向。

### 複雜度

- 時間複雜度：`O(m x n)`。最壞情況下，每個像素都屬於同一連通區並被處理一次。
- 額外空間：`O(m x n)`。最壞情況下，遞迴呼叫堆疊可能包含所有像素。

### 範例演示

輸入：

```text
image = [[1,1,1],[1,1,0],[1,0,1]]
sr = 1, sc = 1, color = 2
```

起點 `(1, 1)` 的原色為 `1`：

1. 將 `(1, 1)` 改為 `2`。
2. 向下遇到 `(2, 1) = 0`，停止該分支。
3. 向右遇到 `(1, 2) = 0`，停止該分支。
4. 向左走到 `(1, 0) = 1`，改為 `2`，再遞迴展開其鄰居。
5. 從 `(1, 0)` 連到 `(0, 0)`，再連到 `(0, 1)` 與 `(0, 2)`，這些像素依序改為 `2`。
6. `(2, 2)` 雖然也是 `1`，但只與連通區對角線接觸，無法透過四方向到達，所以保持不變。

結果：

```text
[[2,2,2],[2,2,0],[2,0,1]]
```

## 解法二：BFS 佇列

### 設計

`FloodFill2` 使用 `Queue<(int Row, int Column)>` 保存下一批要展開的像素：

1. 若起點原色等於目標顏色，直接回傳原矩陣。
2. 將起點改成目標顏色後放入佇列。
3. 每次取出佇列前端的像素，檢查它的四方向鄰居。
4. 若鄰居在範圍內且仍等於起點原色，就立即改色並放入佇列。
5. 重複直到佇列清空。

關鍵是「入列時立即改色」，而不是等到出列才改色。同一個像素可能同時是多個已走訪像素的鄰居；若延後改色，它可能在不同方向被重複放入佇列。

### 複雜度

- 時間複雜度：`O(m x n)`。每個符合條件的像素最多入列與出列一次。
- 額外空間：`O(m x n)`。最壞情況下，佇列可能保存大量待處理像素。

### 範例演示

使用與 DFS 相同的輸入，佇列狀態可簡化表示如下：

1. 起點改色並入列：`[(1,1)]`
2. 取出 `(1,1)`，可加入的同色鄰居為 `(1,0)`、`(0,1)`：`[(1,0),(0,1)]`
3. 取出 `(1,0)`，加入 `(0,0)`：`[(0,1),(0,0)]`
4. 取出 `(0,1)`，加入 `(0,2)`；其他同色鄰居已在入列時改色，不會重複加入：`[(0,0),(0,2)]`
5. 依序取出剩餘像素，沒有新的同色鄰居後佇列清空。
6. `(2,2)` 不在起點的四方向連通區內，因此維持 `1`。

結果同樣是：

```text
[[2,2,2],[2,2,0],[2,0,1]]
```

## 解法比較

| 比較項目 | DFS | BFS |
| --- | --- | --- |
| 主要結構 | 遞迴呼叫堆疊 | `Queue` |
| 走訪順序 | 沿單一路徑深入後回溯 | 逐層向外展開 |
| 已走訪標記 | 遞迴前改色 | 入列時改色 |
| 時間複雜度 | `O(m x n)` | `O(m x n)` |
| 最壞額外空間 | `O(m x n)` | `O(m x n)` |
| 實務差異 | 寫法精簡，但大型連通區會增加遞迴深度 | 沒有遞迴深度問題，但需管理顯式佇列 |

兩種方法的結果與漸進複雜度相同，差異主要在走訪順序與工作記憶體的形式。

## 可執行案例

主程式固定驗證以下情境，並為 DFS 與 BFS 建立彼此獨立的矩陣副本：

1. 官方連通區案例。
2. 目標色等於原色。
3. 單一像素矩陣。
4. 從矩陣邊界開始填色。
5. 相同顏色分屬不同連通區。

深拷貝很重要，因為兩個解法都會原地修改輸入；若共用同一份矩陣，後執行的解法拿到的將是前一個解法已經改過的資料。
