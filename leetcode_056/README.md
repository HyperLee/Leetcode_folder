## 題目說明

給定一組區間 `intervals`，每個區間以 `[start, end]` 表示。請合併所有互相重疊的區間，回傳一組彼此不重疊、且能完整覆蓋原輸入範圍的區間。

兩個區間只要端點相接也視為重疊。例如 `[1, 4]` 與 `[4, 5]` 必須合併成 `[1, 5]`。

### 範例

```text
輸入：intervals = [[1,3],[2,6],[8,10],[15,18]]
輸出：[[1,6],[8,10],[15,18]]
```

`[1,3]` 與 `[2,6]` 互相重疊，因此合併為 `[1,6]`；其餘兩段與前一段沒有交集，所以各自保留。

### 限制條件

- `1 <= intervals.Length <= 10^4`
- `intervals[i].Length == 2`
- `0 <= start_i <= end_i <= 10^4`

本專案的兩種公開解法都以輸入符合以上限制為前提，不額外處理空陣列、負座標或起點大於終點等非法資料。

## 解題概念與出發點

合併區間的困難在於：原始輸入不保證依起點排序。若直接拿每個區間和其他所有區間比較，容易形成 `O(n²)` 的兩層迴圈，而且合併後還必須重新確認是否又和第三段重疊。

要讓問題變簡單，可以先想辦法建立「由左到右」的處理順序：

1. 排序法直接按照起點排列所有區間。
2. 事件掃描法利用座標範圍有限，依序走訪每個可能的座標。

不論採用哪一種方法，核心問題都是判斷：

- 目前是否正在某一段被區間覆蓋的範圍內？
- 新區間是延續目前範圍，還是必須建立另一段結果？
- 何時可以確定目前合併區間已經結束？

## 解法一：排序後線性合併

對應方法：

```csharp
public static int[][] Merge(int[][] intervals)
```

### 設計說明

先將所有區間按照起點由小到大排序。排序後有一個重要性質：

> 目前區間只需要和「最後一段合併結果」比較，不需要回頭檢查更早的結果。

假設最後一段結果是 `[lastStart, lastEnd]`，目前區間是 `[currentStart, currentEnd]`：

- `currentStart <= lastEnd`：兩段重疊或端點相接，將最後結果的右端點更新為 `max(lastEnd, currentEnd)`。
- `currentStart > lastEnd`：中間已有空隙，不可能合併，將目前區間加入結果。

### 演算法不變量

每次進入迴圈時，`result` 必須符合以下條件：

1. 已處理過的區間都被完整覆蓋。
2. `result` 內各區間依起點遞增。
3. `result` 內相鄰區間互不重疊。
4. 最後一段是唯一可能和目前區間重疊的結果。

這個不變量讓每個排序後的區間只需要處理一次。

### 範例演示

輸入：

```text
[[1,3],[2,6],[8,10],[15,18]]
```

依起點排序後順序不變：

```text
[[1,3],[2,6],[8,10],[15,18]]
```

| 步驟 | 目前區間 | 合併前結果 | 判斷 | 合併後結果 |
|---:|---|---|---|---|
| 1 | `[1,3]` | `[]` | 尚無結果，建立第一段 | `[[1,3]]` |
| 2 | `[2,6]` | `[[1,3]]` | `2 <= 3`，重疊 | `[[1,6]]` |
| 3 | `[8,10]` | `[[1,6]]` | `8 > 6`，不重疊 | `[[1,6],[8,10]]` |
| 4 | `[15,18]` | `[[1,6],[8,10]]` | `15 > 10`，不重疊 | `[[1,6],[8,10],[15,18]]` |

第二步不能直接把右端點指定為 `6` 而不做比較。若目前結果是 `[1,10]`，下一段是 `[2,6]`，正確結果仍應是 `[1,10]`，因此必須使用 `Math.Max`。

### 輸入資料的變動

這個方法呼叫 `Array.Sort`，因此會原地改變外層 `intervals` 的順序。結果清單也會引用輸入的內層陣列；當右端點向外延伸時，對應的輸入區間端點可能一起改變。

主控台案例執行器會在呼叫每一種解法前深層複製輸入，避免這項特性污染後續驗證。若應用程式必須保留呼叫端資料，也應先建立深層副本。

### 複雜度

- 排序：`O(n log n)`
- 線性掃描：`O(n)`
- 總時間複雜度：`O(n log n)`
- 回傳結果空間：最壞為 `O(n)`
- 排序本身可能使用的額外空間依執行環境實作而定

### 優缺點

優點：

- 不依賴座標數值上限，適用範圍較廣。
- 排序後的判斷規則簡單，容易證明正確性。
- 當座標範圍很大但區間數不多時仍有效率。

缺點：

- 排序需要 `O(n log n)` 時間。
- 現有實作會改變輸入資料。
- 必須理解結果內層陣列和輸入之間的參考關係。

## 解法二：座標事件掃描

對應方法：

```csharp
public static int[][] MergeBySweepLine(int[][] intervals)
```

### 設計說明

題目保證所有座標都介於 `0` 到 `10000`，因此可以建立兩個長度為 `10001` 的事件陣列：

- `startCounts[x]`：有多少區間從座標 `x` 開始。
- `endCounts[x]`：有多少區間在座標 `x` 結束。

接著由 `0` 掃描到 `10000`，使用 `activeIntervals` 表示目前有多少區間正在覆蓋掃描位置：

1. 若掃描前 `activeIntervals == 0`，而此座標存在起點，表示新的合併區間從這裡開始。
2. 將此座標的起點數加入 `activeIntervals`。
3. 再將此座標的終點數從 `activeIntervals` 扣除。
4. 若扣除後回到 0，表示目前合併區間在此座標結束。

### 為什麼同座標要先開始、再結束？

考慮 `[1,4]` 與 `[4,5]`：

- 掃描到 `4` 之前，第一段區間仍在活動中。
- 座標 `4` 同時是第二段的起點與第一段的終點。
- 若先結束第一段，活動數會暫時歸零，錯誤地輸出 `[1,4]`。
- 先加入第二段後再結束第一段，活動數仍大於零，掃描會持續到 `5`，正確輸出 `[1,5]`。

零長度區間 `[2,2]` 也能正確處理：掃描到 `2` 時先開始一段，活動數由 0 變成 1；同一座標再結束，活動數回到 0，因此輸出 `[2,2]`。

### 範例演示

輸入：

```text
[[1,4],[4,5]]
```

只列出有事件的座標：

| 座標 | 起點數 | 終點數 | 掃描前活動數 | 加入起點後 | 扣除終點後 | 動作 |
|---:|---:|---:|---:|---:|---:|---|
| 1 | 1 | 0 | 0 | 1 | 1 | 記錄合併起點 `1` |
| 4 | 1 | 1 | 1 | 2 | 1 | 活動數未歸零，繼續合併 |
| 5 | 0 | 1 | 1 | 1 | 0 | 輸出 `[1,5]` |

事件掃描不需要重新排列 `intervals`，輸出區間也全部使用新陣列建立，因此呼叫完成後輸入保持不變。

### 複雜度

令 `U = 10001`，代表可能的座標數量：

- 建立事件：`O(n)`
- 掃描座標：`O(U)`
- 總時間複雜度：`O(n + U)`
- 事件陣列空間：`O(U)`
- 回傳結果空間：最壞為 `O(n)`

雖然題目中的 `U` 是固定常數，但保留 `O(n + U)` 的表示方式可以清楚反映這個方法會掃描整個座標範圍。

### 優缺點

優點：

- 不需要排序。
- 不修改輸入資料。
- 能直接表達「目前有多少區間正在覆蓋此座標」。
- 在座標範圍小且固定時，執行時間穩定。

缺點：

- 依賴 `0 <= coordinate <= 10000` 的題目限制。
- 即使只有一個區間，仍會掃描 10001 個座標。
- 若座標上限擴大到數十億，事件陣列會浪費大量時間與記憶體，不適合直接沿用。

## 兩種解法比較

| 比較項目 | `Merge` 排序法 | `MergeBySweepLine` 事件掃描法 |
|---|---|---|
| 建立由左到右順序 | 排序所有區間 | 掃描所有可能座標 |
| 核心狀態 | 最後一段合併結果 | 活動區間數 |
| 時間複雜度 | `O(n log n)` | `O(n + U)` |
| 額外事件空間 | 不需要 | `O(U)` |
| 是否依賴座標上限 | 否 | 是，`U = 10001` |
| 是否修改輸入 | 是 | 否 |
| 適合情境 | 通用座標、區間數主導成本 | 座標範圍小且固定 |

一般情況下，排序法較通用，也是合併區間最常見的解法。事件掃描法則展示如何把題目的座標限制轉換成另一種資料結構與時間複雜度；兩者並非永遠有一方較快，選擇取決於區間數量與座標範圍。
