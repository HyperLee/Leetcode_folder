# 3903. Smallest Stable Index I

[![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4)](https://dotnet.microsoft.com/)

這是一個使用 C# 與 .NET 10 撰寫的 LeetCode 3903 解題範例。專案保留三種可獨立呼叫的解法，並在 `Main` 中提供不需要輸入資料的固定案例，方便直接建置、執行與比較每種解法的結果。

- 題目：[Smallest Stable Index I](https://leetcode.com/problems/smallest-stable-index-i/description/)
- 解法：逐一枚舉、前綴最大值與後綴最小值預處理、後綴陣列搭配滾動前綴最大值
- 執行方式：.NET 10 console application

## 題目說明

給定一個長度為 `n` 的整數陣列 `nums` 與整數 `k`。陣列索引從 `0` 開始，對每個索引 `i` 定義不穩定分數（instability score）為：

```text
max(nums[0..i]) - min(nums[i..n - 1])
```

其中：

- `max(nums[0..i])` 是從索引 `0` 到 `i` 的前綴區間最大值。
- `min(nums[i..n - 1])` 是從索引 `i` 到 `n - 1` 的後綴區間最小值。
- 如果不穩定分數小於或等於 `k`，索引 `i` 就是穩定索引。

請回傳最小的穩定索引。如果不存在穩定索引，回傳 `-1`。

### 官方範例 1

```text
nums = [5, 0, 1, 4], k = 3
答案 = 3
```

逐一計算如下：

| 索引 `i` | `max(nums[0..i])` | `min(nums[i..n-1])` | 不穩定分數 | 是否穩定 |
| ---: | ---: | ---: | ---: | :---: |
| 0 | 5 | 0 | 5 | 否 |
| 1 | 5 | 0 | 5 | 否 |
| 2 | 5 | 1 | 4 | 否 |
| 3 | 5 | 4 | 1 | 是 |

索引 `3` 是第一個滿足 `score <= k` 的位置，因此回傳 `3`。

### 官方範例 2

```text
nums = [3, 2, 1], k = 1
答案 = -1
```

三個索引的不穩定分數都為 `3 - 1 = 2`，全部大於 `k = 1`，所以沒有穩定索引。

### 官方範例 3

```text
nums = [0], k = 0
答案 = 0
```

唯一索引的分數為 `0 - 0 = 0`，符合條件，因此回傳 `0`。

## 限制條件

依照 [LeetCode 3903 官方題目頁](https://leetcode.cn/problems/smallest-stable-index-i/)：

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 10^9`
- `0 <= k <= 10^9`

因此輸入陣列一定非空，程式可以安全地使用 `nums[0]` 初始化前綴或後綴的起始值。`nums[i]` 與 `k` 的最大值使得差值不超過 `10^9`，仍可使用 C# `int` 表示。

## 解題概念與出發點

題目要求的是「最小」穩定索引，所以所有解法都遵循同一個外層策略：

1. 按照 `i = 0, 1, 2, ...` 的順序檢查索引。
2. 取得目前前綴的最大值與後綴的最小值。
3. 計算 `max - min`。
4. 第一次得到小於或等於 `k` 的結果時立即回傳。

直接按照定義計算可以得到容易理解的解法；進一步觀察後，可以把每個索引需要的兩個區間資訊預先計算出來：

- 前綴最大值可以由左到右累積：

  ```text
  preMax[i] = max(preMax[i - 1], nums[i])
  ```

- 後綴最小值可以由右到左累積：

  ```text
  sufMin[i] = min(sufMin[i + 1], nums[i])
  ```

這樣每個索引的分數就能在 `O(1)` 時間取得，整體時間從 `O(n^2)` 降到 `O(n)`。

## 解法設計

### 方法一：逐一枚舉 `FirstStableIndex`

#### 設計想法

這個方法直接按照題目定義計算：

- 外層迴圈從左到右枚舉索引 `i`。
- `maxValue` 持續記錄目前前綴 `[0, i]` 的最大值，因此不需要每次重新掃描左側。
- `minValue` 從 `nums[i]` 開始，透過內層迴圈掃描 `[i, n - 1]`，找出目前後綴最小值。
- 若 `maxValue - minValue <= k`，立即回傳 `i`。

#### 流程演示

以 `nums = [5, 0, 1, 4]`、`k = 3` 為例：

1. `i = 0`：前綴最大值為 `5`，掃描整個後綴得到最小值 `0`，分數為 `5`，不符合。
2. `i = 1`：前綴最大值仍為 `5`，後綴 `[0, 1, 4]` 最小值為 `0`，分數為 `5`，不符合。
3. `i = 2`：前綴最大值仍為 `5`，後綴 `[1, 4]` 最小值為 `1`，分數為 `4`，不符合。
4. `i = 3`：前綴最大值仍為 `5`，後綴 `[4]` 最小值為 `4`，分數為 `1`，符合 `1 <= 3`，回傳 `3`。

#### 正確性

在每個外層迴圈的索引 `i`：

- `maxValue` 是 `nums[0..i]` 的最大值。
- 內層迴圈完成後，`minValue` 是 `nums[i..n-1]` 的最小值。

所以 `maxValue - minValue` 正好是題目定義的不穩定分數。外層迴圈由小索引往大索引檢查，第一次通過的索引必定是最小穩定索引。

#### 複雜度

- 時間複雜度：`O(n^2)`。每個索引都可能重新掃描右側區間。
- 額外空間複雜度：`O(1)`。只使用數個累積變數。

### 方法二：完整前綴／後綴預處理 `FirstStableIndex2`

#### 設計想法

這個方法分成三個階段：

1. 從右到左建立 `sufMin`，讓 `sufMin[i]` 保存 `nums[i..n-1]` 的最小值。
2. 從左到右建立 `preMax`，讓 `preMax[i]` 保存 `nums[0..i]` 的最大值。
3. 從左到右比較 `preMax[i] - sufMin[i]` 與 `k`。

建立後綴陣列的遞推關係是：

```text
sufMin[n - 1] = nums[n - 1]
sufMin[i] = min(sufMin[i + 1], nums[i])
```

建立前綴陣列的遞推關係是：

```text
preMax[0] = nums[0]
preMax[i] = max(preMax[i - 1], nums[i])
```

#### 為什麼後綴從 `n - 2` 開始，前綴從 `1` 開始？

這裡的 `n` 代表陣列長度，不是最後一個索引。陣列的合法索引範圍是 `0` 到 `n - 1`。建立前綴與後綴陣列時，會先處理一個邊界位置，再利用那個已經計算好的值往外推導。

以 `n = 4` 為例，索引排列如下：

```text
索引：  0    1    2    3
       └──────────────┘
       第一個         最後一個索引 n - 1
```

後綴最小值先設定最後一格：

```text
sufMin[3] = nums[3]       // 先處理最後一個索引 n - 1
```

接著由右到左計算：

```text
i = 2：sufMin[2] = min(sufMin[3], nums[2])
i = 1：sufMin[1] = min(sufMin[2], nums[1])
i = 0：sufMin[0] = min(sufMin[1], nums[0])
```

因為公式需要使用 `sufMin[i + 1]`，而掃描方向是由右到左，所以 `i + 1` 正好是上一個已經計算完成的右側位置。`sufMin[n - 1]` 已經先初始化，因此第一個還沒計算的位置就是 `n - 2`。如果從 `n - 1` 開始，就會嘗試讀取不存在的 `sufMin[n]`，而且最後一格本來就已經有答案。

前綴最大值則先設定第一格：

```text
preMax[0] = nums[0]
```

接著由左到右計算：

```text
i = 1：preMax[1] = max(preMax[0], nums[1])
i = 2：preMax[2] = max(preMax[1], nums[2])
i = 3：preMax[3] = max(preMax[2], nums[3])
```

因為公式需要使用 `preMax[i - 1]`，所以必須先讓 `preMax[0]` 存在，第一個需要計算的位置就是 `i = 1`。如果從 `i = 0` 開始，就會嘗試讀取不存在的 `preMax[-1]`。

因此兩個迴圈的起點可以整理成：

| 陣列 | 先初始化的位置 | 掃描方向 | 第一個需要計算的位置 | 使用的已知值 |
| --- | ---: | --- | ---: | --- |
| `sufMin` | `n - 1` | 由右到左 | `n - 2` | `sufMin[i + 1]` |
| `preMax` | `0` | 由左到右 | `1` | `preMax[i - 1]` |

這裡的 `preMax` 是「前綴最大值」，不是把元素相加的「前綴和」；`sufMin` 則是「後綴最小值」。當 `n = 1` 時，索引 `0` 同時是第一格與最後一格，兩個邊界值都已直接初始化，因此後綴迴圈從 `-1` 開始但不會執行，前綴迴圈從 `1` 開始也不會執行。

#### 流程演示

對 `nums = [5, 0, 1, 4]`：

```text
preMax = [5, 5, 5, 5]
sufMin = [0, 0, 1, 4]
```

接著逐格相減：

| 索引 `i` | `preMax[i]` | `sufMin[i]` | 分數 | 判斷 |
| ---: | ---: | ---: | ---: | :---: |
| 0 | 5 | 0 | 5 | `5 > 3`，繼續 |
| 1 | 5 | 0 | 5 | `5 > 3`，繼續 |
| 2 | 5 | 1 | 4 | `4 > 3`，繼續 |
| 3 | 5 | 4 | 1 | `1 <= 3`，回傳 3 |

#### 正確性

`preMax` 與 `sufMin` 的遞推式分別保證每個位置保存正確的前綴最大值與後綴最小值。因此兩者相減就是該索引的不穩定分數；最後由左到右尋找，仍能保證回傳最小穩定索引。

#### 複雜度

- 時間複雜度：`O(n)`。建立兩個陣列與最後掃描各需要一次線性遍歷。
- 額外空間複雜度：`O(n)`。配置 `preMax` 與 `sufMin` 兩個長度為 `n` 的陣列。

### 方法三：後綴陣列搭配滾動前綴最大值 `FirstStableIndex3`

#### 設計想法

方法二已經把時間降到 `O(n)`，但 `preMax` 陣列不一定需要完整保存。尋找答案本來就會由左到右進行，因此只要一個變數 `preMax` 保存目前的前綴最大值即可：

1. 先由右到左建立 `sufMin`。
2. 再由左到右走訪陣列。
3. 每到索引 `i`，用 `max(preMax, nums[i])` 更新前綴最大值。
4. 立刻用 `preMax - sufMin[i]` 判斷是否穩定。

由於題目保證 `nums[i] >= 0`，程式以 `0` 作為 `preMax` 的初始值不會小於任何合法輸入元素。

#### 流程演示

仍以 `nums = [5, 0, 1, 4]`、`k = 3` 為例。後綴陣列先建立為 `[0, 0, 1, 4]`，左到右判斷時只保留一個 `preMax`：

| 索引 `i` | 目前元素 | 更新後 `preMax` | `sufMin[i]` | 分數 | 判斷 |
| ---: | ---: | ---: | ---: | ---: | :---: |
| 0 | 5 | 5 | 0 | 5 | 不穩定 |
| 1 | 0 | 5 | 0 | 5 | 不穩定 |
| 2 | 1 | 5 | 1 | 4 | 不穩定 |
| 3 | 4 | 5 | 4 | 1 | 穩定，回傳 3 |

#### 正確性

在處理索引 `i` 前，`preMax` 代表前一個位置以前的前綴最大值；更新後就成為 `nums[0..i]` 的最大值。`sufMin[i]` 已由右向左預先算好，代表 `nums[i..n-1]` 的最小值。因此每次比較都使用題目要求的兩個區間資訊，而且第一次成功時仍是最小索引。

#### 複雜度

- 時間複雜度：`O(n)`。
- 額外空間複雜度：`O(n)`，只配置 `sufMin`；相較方法二少配置一個 `preMax` 陣列。

## 三種解法比較

| 解法 | 核心做法 | 時間複雜度 | 額外空間複雜度 | 特點 |
| --- | --- | ---: | ---: | --- |
| `FirstStableIndex` | 每個索引重新掃描後綴 | `O(n^2)` | `O(1)` | 最直接，適合理解題目定義 |
| `FirstStableIndex2` | 同時保存前綴最大值與後綴最小值 | `O(n)` | `O(n)` | 每個索引的資訊完整保存 |
| `FirstStableIndex3` | 保存後綴最小值，前綴最大值滾動計算 | `O(n)` | `O(n)` | 少一個前綴陣列，仍維持線性時間 |
