# LeetCode 57：插入區間（Insert Interval）

這是一個使用 C# 與 .NET 10 實作的主控台專案。程式保留一個單次掃描解法，並在 `Main` 中執行五組固定案例，以逐端點比較的方式顯示 `PASS/FAIL`。

## 題目說明

給定一組按照起點遞增排序、彼此不重疊的區間 `intervals`，以及一個待插入區間 `newInterval`。

請把 `newInterval` 插入原有區間，必要時合併所有重疊區間，使回傳結果仍然：

1. 按照區間起點遞增排序。
2. 任兩個區間都不重疊。
3. 完整涵蓋原有區間與新區間代表的範圍。

不要求在原陣列上直接修改，可以建立新的結果陣列。

題目連結：[LeetCode 57 - Insert Interval](https://leetcode.com/problems/insert-interval/description/)

### 題目範例

```text
輸入：intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]]
      newInterval = [4,8]
輸出：[[1,2],[3,10],[12,16]]
```

`[4,8]` 會依序與 `[3,5]`、`[6,7]`、`[8,10]` 重疊，因此這四段範圍最後合併成 `[3,10]`。

## 限制條件

- `0 <= intervals.length <= 10^4`
- `intervals[i].length == 2`
- `0 <= start_i <= end_i <= 10^5`
- `intervals` 按照 `start_i` 遞增排序。
- `intervals` 中的區間彼此不重疊。
- `newInterval.length == 2`
- `0 <= start <= end <= 10^5`

## 解題概念與出發點

輸入已經排序且沒有重疊，這兩個條件非常重要。它們代表不需要先重新排序，也不需要反覆回頭檢查已處理的區間。

把 `newInterval` 的左右端點暫存在 `left`、`right`，作為「目前仍可能繼續擴張的合併區間」。接著由左到右掃描每個原始區間。對任一 `interval`，它和 `[left,right]` 的關係只可能是以下三種：

1. **完全位於左側**
   - 條件：`interval[1] < left`
   - 目前區間在新區間之前，而且沒有交集。
   - 直接加入答案，不需要改變合併邊界。

2. **完全位於右側**
   - 條件：`interval[0] > right`
   - 目前區間在待合併區間之後，而且沒有交集。
   - 如果合併區間尚未加入答案，先加入 `[left,right]`，再加入目前區間。
   - 因為輸入已排序，後續區間也只會在更右邊，所以合併區間只需加入一次。

3. **兩個區間有重疊**
   - 不符合上述兩個條件時，兩個區間必定相交或端點相接。
   - 使用 `Math.Min` 更新左端點，使用 `Math.Max` 更新右端點。
   - 此時不能立刻加入答案，因為擴張後的區間仍可能和下一個區間重疊。

掃描結束後，如果合併區間尚未加入，代表它位於所有區間之後，或一路合併到最後一個區間；此時再補入答案。

## 解法一：單次掃描並延後輸出合併區間

### 設計說明

`Insert` 維持四個主要狀態：

- `left`：目前合併範圍的左端點。
- `right`：目前合併範圍的右端點。
- `merged`：合併後的區間是否已經放入答案。
- `ansList`：依正確順序收集輸出區間。

初始的 `[left,right]` 就是 `newInterval`。每遇到重疊區間，只擴張這兩個端點；等到第一次遇見右側區間時，才把完整的合併結果加入 `ansList`。

這個「延後加入」的設計可以避免產生 `[3,8]`、`[3,8]`、`[3,10]` 等中間結果，也不需要加入後再回頭修改答案。

### 範例演示流程

輸入：

```text
intervals   = [[1,2],[3,5],[6,7],[8,10],[12,16]]
newInterval = [4,8]
```

| 目前區間 | 判斷 | 合併範圍 `[left,right]` | 答案內容 |
|---|---|---|---|
| 初始狀態 | 以 `[4,8]` 作為待合併範圍 | `[4,8]` | `[]` |
| `[1,2]` | 完全位於左側，直接加入 | `[4,8]` | `[[1,2]]` |
| `[3,5]` | 與 `[4,8]` 重疊，擴張左端點 | `[3,8]` | `[[1,2]]` |
| `[6,7]` | 包含在目前合併範圍內 | `[3,8]` | `[[1,2]]` |
| `[8,10]` | 端點相接也算重疊，擴張右端點 | `[3,10]` | `[[1,2]]` |
| `[12,16]` | 完全位於右側，先加入合併結果 | `[3,10]` | `[[1,2],[3,10],[12,16]]` |

最終輸出：

```text
[[1,2],[3,10],[12,16]]
```

### 正確性說明

- 左側區間的終點小於 `left`，不可能與待合併區間重疊，因此可以保持原順序直接加入。
- 右側區間的起點大於 `right`，待合併區間已不可能再與它或更前面的資料重疊；先加入合併結果即可維持排序。
- 其餘情況必定重疊，取較小左端點與較大右端點會得到兩段範圍的聯集。
- 輸入已排序，因此掃描過的左側區間不必重新檢查；第一次進入右側後，後續區間也不可能再與合併範圍交錯。

所以每個輸入區間都被保留或合併一次，最後答案仍然排序且彼此不重疊。

### 複雜度分析

- 時間複雜度：`O(n)`，每個原始區間只掃描一次。
- 輸出空間複雜度：`O(n)`，最差情況需要保存全部原始區間及新區間。

## 可執行驗收案例

`Main` 會執行以下五種情況：

| 案例 | `intervals` | `newInterval` | 預期結果 |
|---|---|---|---|
| 空陣列 | `[]` | `[5,7]` | `[[5,7]]` |
| 插在全部區間之前 | `[[3,5],[7,9]]` | `[0,1]` | `[[0,1],[3,5],[7,9]]` |
| 插在全部區間之後 | `[[1,2],[3,5]]` | `[6,8]` | `[[1,2],[3,5],[6,8]]` |
| 合併單一區間 | `[[1,3],[6,9]]` | `[2,5]` | `[[1,5],[6,9]]` |
| 合併多個區間 | `[[1,2],[3,5],[6,7],[8,10],[12,16]]` | `[4,8]` | `[[1,2],[3,10],[12,16]]` |

測試不是比較格式化字串，而是先比較區間數量，再逐一比較每個區間的所有端點。
