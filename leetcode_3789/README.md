# LeetCode 3789｜滿足採購需求的最低成本

使用 C# 分別實作分階段貪心與三種候選方案比較，兩種解法都能在常數時間內算出滿足兩類需求的最低成本。專案以 .NET 10 主控台執行測資。

## 題目說明

給定三種物品的單價，以及兩類需求的最低數量。每種物品可購買任意非負整數件，目標是以最低總成本讓兩類需求都達標。

| 物品 | 單價 | 第 1 類貢獻 | 第 2 類貢獻 |
| --- | ---: | ---: | ---: |
| 第 1 類 | `cost1` | 1 | 0 |
| 第 2 類 | `cost2` | 0 | 1 |
| 第 3 類 | `costBoth` | 1 | 1 |

`need1` 與 `need2` 是達標門檻。若其中一類已達標，仍可購買第 3 類物品來滿足另一類，即使會讓已達標的一類超額。

### 限制條件

- `1 <= cost1, cost2, costBoth <= 10^6`
- `0 <= need1, need2 <= 10^9`
- 輸入為五個整數，回傳最低總成本。C# 使用 `long` 儲存結果。

### 官方範例

| 輸入 `(cost1, cost2, costBoth, need1, need2)` | 最低成本 | 購買方式 |
| --- | ---: | --- |
| `(3, 2, 1, 3, 2)` | 3 | 買 3 件第 3 類，兩類各得到 3 單位。 |
| `(5, 4, 15, 2, 3)` | 22 | 買 2 件第 1 類與 3 件第 2 類。 |
| `(5, 4, 15, 0, 0)` | 0 | 買 0 件。 |

[LeetCode 官方題目](https://leetcode.com/problems/minimum-cost-to-acquire-required-items/description/)

## 解法導讀

建議先閱讀[解法二：三種候選方案](#解法二三種候選方案-minimumcost2)，掌握「全部單品、混合購買、全部組合包」三大類，再閱讀[解法一：貪心法](#解法一貪心法-minimumcost)，理解價格條件如何提前決定選擇。解法編號與程式中的方法名稱保持一致，不代表必須依編號閱讀。

| 解法 | 方法 | 核心思路 |
| --- | --- | --- |
| 解法一：分階段貪心 | `MinimumCost` | 推理價格關係，決定共同需求與剩餘需求的買法 |
| 解法二：三種候選方案 | `MinimumCost2` | 計算三種完整方案的成本，再取最小值 |

兩種解法的時間與額外空間複雜度皆為 `O(1)`。兩者如何對應，可參考[兩種解法比較](#兩種解法比較)。

### 共用名詞

以下用 **A** 表示第 1 類需求，**B** 表示第 2 類需求；A 單品、B 單品分別是第 1、2 類物品，**AB 組合包**是第 3 類物品。

一件 AB 組合包固定提供 A、B 各 1 單位，不能改成提供 2 個 A 或 2 個 B。

## 解法一：貪心法 `MinimumCost`

### 先記住：現在缺什麼，就比較能補足它的買法

本節沿用[共用名詞](#共用名詞)：A、B 分別代表第 1、2 類需求，AB 組合包代表第 3 類物品。

```text
A、B 都需要：
    組合包 vs. 兩種單品各一件
    比較 costBoth 與 cost1 + cost2

只剩 A：
    組合包 vs. A 單品
    比較 costBoth 與 cost1

只剩 B：
    組合包 vs. B 單品
    比較 costBoth 與 cost2
```

**比較哪些價格，取決於當下還需要補足哪些需求。** 兩類都缺時，組合包可以同時取代兩件單品；只剩一類缺時，組合包只能取代該類的一件單品，另一類的貢獻會成為超額供應。

### 依照程式逐步理解

#### 步驟 1：判斷是否全部買單品即可

```csharp
if (cost1 + cost2 <= costBoth)
{
    totalCost = 1L * cost1 * need1 + 1L * cost2 * need2;
}
```

當 A、B 各缺 1 單位時，買兩種單品各一件與買一件組合包，得到的貢獻相同。若 `cost1 + cost2 <= costBoth`，分開買較便宜或同價。

而且兩種單價都為正，所以此時 `cost1 < costBoth`、`cost2 < costBoth`。即使只缺 A 或只缺 B，組合包也沒有價格優勢。因此直接用各類單價乘上需求量即可。

例如 `(5, 4, 15, 2, 3)`：兩件單品合計 9 元，比組合包的 15 元便宜；全部買單品的成本為 `2 * 5 + 3 * 4 = 22`。

#### 步驟 2：組合包較便宜，先補共同需求

進入 `else` 表示 `costBoth < cost1 + cost2`，因此每一對「A、B 各缺 1 單位」的共同需求，都適合用組合包處理。

```csharp
int pairedCount = Math.Min(need1, need2);
totalCost = 1L * pairedCount * costBoth;
```

若 `need1 = 3`、`need2 = 2`，需求可以這樣配對：

```text
                 第 1 對   第 2 對   未配對
A 需求：           [A]       [A]       [A]
B 需求：           [B]       [B]
                   |         |
                 AB 一件   AB 一件

共同需求 = min(3, 2) = 2 對
剩餘需求 = A 一個
```

`pairedCount` 是**兩類都需要的配對數，不是組合包的購買上限**。先買 2 件組合包後，是否要為剩餘的 A 再買組合包，要在下一階段重新比較價格。

#### 步驟 3：扣掉已補足的需求

```csharp
need1 -= pairedCount;
need2 -= pairedCount;
```

上述例子的剩餘需求會從 `(3, 2)` 變成 `(1, 0)`。因為兩邊都扣掉原本的最小值，**至少一邊一定變成 0**；若原本需求相等，則兩邊都變成 0。

因此後面使用 `if / else if`，只需要處理其中一類的剩餘需求。這裡的 `need1`、`need2` 已改為表示尚未補足的數量。

#### 步驟 4：只剩一類需求，重新比較價格

```csharp
if (need1 > 0)
{
    totalCost += 1L * need1 * Math.Min(cost1, costBoth);
}
else if (need2 > 0)
{
    totalCost += 1L * need2 * Math.Min(cost2, costBoth);
}
```

假設只剩 A，每補 1 單位有兩種買法：買 A 單品，花費 `cost1`；或買組合包，花費 `costBoth`，同時多得到一個已不需要的 B。

題目只要求「至少」滿足需求，允許 B 超額，所以每個剩餘 A 的成本是 `Math.Min(cost1, costBoth)`。只剩 B 時同理，使用 `Math.Min(cost2, costBoth)`。若兩邊都為 0，這兩個分支都不執行。

**組合包比兩件單品合計便宜，不代表它比其中一件單品也便宜。** 例如 `cost1 = 6`、`cost2 = 3`、`costBoth = 5`：共同需求選組合包，因為 `5 < 6 + 3`；但只剩 B 時選 B 單品，因為 `3 < 5`。

### 為什麼能得到最低成本

先用替換買法來理解：當組合包比兩件單品合計便宜時，只要某個買法中還有 A、B 單品各一件，就可以把這兩件換成一件組合包。得到的 A、B 數量相同，成本卻降低。因此共同需求應持續用組合包替換，直到其中一類達標，也就是先處理 `min(need1, need2)` 對。

之後只剩一類需求，單品與組合包都能補足它，每個單位都選較便宜的即可。若兩件單品合計比組合包便宜或同價，則反過來把組合包換成兩件單品不會增加成本，全部買單品就有最低成本。

若想從成本公式理解相同結論，可參考解法二的[為什麼只比較三個候選點就夠](#為什麼只比較三個候選點就夠)。該節集中說明成本函數與區間變化；解法一則直接利用價格比較，決定應選哪個候選點。

### ASCII 流程圖

`n1`、`n2` 是當前需求，`c1`、`c2`、`cb` 是三種物品的單價。

```text
Start
  |
  v
c1 + c2 <= cb?
  +-- yes --> Return n1*c1 + n2*c2
  |
  +-- no ---> p = min(n1, n2)
              total = p*cb
              n1 = n1 - p, n2 = n2 - p
                |
                v
              n1 > 0?
                +-- yes --> Return total + n1*min(c1, cb)
                |
                +-- no ---> n2 > 0?
                             +-- yes --> Return total + n2*min(c2, cb)
                             |
                             +-- no ---> Return total
```

### 範例演示

**官方範例 1，共同購買後仍用第 3 類補足。** 輸入 `(3, 2, 1, 3, 2)`。

| 當下需求 | 比較價格 | 選擇 | 剩餘需求 `(A, B)` | 累計成本 |
| --- | --- | --- | --- | ---: |
| A、B 都需要 | 組合包 1 vs. 兩件單品合計 `3 + 2 = 5` | 買 2 件組合包 | `(1, 0)` | `2 * 1 = 2` |
| 只剩 A | 組合包 1 vs. A 單品 3 | 再買 1 件組合包 | `(0, 0)` | `2 + 1 * 1 = 3` |

最後總共買了 3 件組合包，**實際取得 A、B 各 3 個，B 超額 1 個**。表格與下圖的剩餘需求最低記為 0，超額不表示負的需求。

```text
Remaining (3, 2) | cost = 0
  -> buy 2 x type 3 -> remaining (1, 0) | cost = 0 + 2*1 = 2
  -> buy 1 x type 3 -> remaining (0, 0) | cost = 2 + 1*1 = 3
  -> return 3        (received 3 units of each type)
```

**官方範例 2，分開購買。** 輸入 `(5, 4, 15, 2, 3)`。組合包 15 元，兩件單品合計 `5 + 4 = 9` 元；而單獨補 A 的 5 元、補 B 的 4 元也都低於 15 元，因此全部買單品。程式直接計算 `2 * 5 + 3 * 4 = 22`，下表與流程把算式拆成兩筆採購。

| 採購步驟 | 選擇依據 | 剩餘需求 `(A, B)` | 累計成本 |
| --- | --- | --- | ---: |
| 買 2 件 A 單品 | A 單品 5 < 組合包 15 | `(0, 3)` | `2 * 5 = 10` |
| 買 3 件 B 單品 | B 單品 4 < 組合包 15 | `(0, 0)` | `10 + 3 * 4 = 22` |

```text
Remaining (2, 3) | cost = 0
  -> buy 2 x type 1 -> remaining (0, 3) | cost = 0 + 2*5 = 10
  -> buy 3 x type 2 -> remaining (0, 0) | cost = 10 + 3*4 = 22
  -> return 22
```

**第 2 類剩餘需求以單類物品補足。** 輸入 `(6, 3, 5, 1, 4)`。

| 當下需求 | 比較價格 | 選擇 | 剩餘需求 `(A, B)` | 累計成本 |
| --- | --- | --- | --- | ---: |
| A、B 都需要 | 組合包 5 vs. 兩件單品合計 `6 + 3 = 9` | 買 1 件組合包 | `(0, 3)` | `1 * 5 = 5` |
| 只剩 B | 組合包 5 vs. B 單品 3 | 買 3 件 B 單品 | `(0, 0)` | `5 + 3 * 3 = 14` |

第一階段比較 `5` 與 `9`，第二階段比較 `5` 與 `3`。需求不同，價格比較的對象也跟著改變，所以共同需求買組合包，剩餘需求改買 B 單品。

```text
Remaining (1, 4) | cost = 0
  -> buy 1 x type 3 -> remaining (0, 3) | cost = 0 + 1*5 = 5
  -> buy 3 x type 2 -> remaining (0, 0) | cost = 5 + 3*3 = 14
  -> return 14
```

### 複雜度與數值範圍

- 時間複雜度為 `O(1)`，因為只做固定次數的比較與算術運算。
- 額外空間複雜度為 `O(1)`，因為只保存固定數量的變數。
- 單價乘上需求量可達 `10^6 * 10^9 = 10^15`，超過 `int` 的上限。程式把 `1L` 放在乘法最前面，讓第一步就用 `long` 計算。若乘完才轉型，先前的 `int` 乘法可能已經溢位。

## 解法二：三種候選方案 `MinimumCost2`

### 先記住：只比較三個組合包數量

先決定組合包數量，再用單品補足缺口。沿用[共用名詞](#共用名詞)：A、B 分別代表第 1、2 類需求，AB 組合包代表第 3 類物品。只需比較下列三種完整採購方案：

| 方案 | 組合包數量 | 其餘需求如何處理 | 程式變數 |
| --- | ---: | --- | --- |
| 全部單品 | `0` | A、B 各自買足原始需求 | `separate` |
| 混合購買 | `min(need1, need2)` | 共同需求用組合包，剩餘需求買單品 | `mixed` |
| 全部組合包 | `max(need1, need2)` | 兩類都達標，允許較小需求那類超額 | `allBoth` |

**三種方案各自計算完整成本，最後取最小值，不需要把三個成本相加。** 混合方案固定只買到共同需求量；若繼續買組合包更便宜，會由「全部組合包」方案涵蓋。

### 依照程式逐步理解

#### 步驟 1：取得共同需求與最大需求

```csharp
long paired = Math.Min(need1, need2);
long maxNeed = Math.Max(need1, need2);
```

`paired` 是兩類都需要的配對數，`maxNeed` 是只靠組合包就能讓兩類達標的最少件數。這裡保留原始需求與單價，不需要交換參數，也不需要扣除需求。

#### 步驟 2：計算全部單品的成本

```csharp
long separate = 1L * need1 * cost1 + 1L * need2 * cost2;
```

A 買 `need1` 件單品，B 買 `need2` 件單品，不買組合包。這對應組合包數量 `x = 0`。

#### 步驟 3：計算混合購買的成本

```csharp
long mixed = paired * costBoth
           + (need1 - paired) * cost1
           + (need2 - paired) * cost2;
```

先買 `paired` 件組合包，兩類各得到 `paired` 單位，再分別用單品補足原始需求的缺口。因為 `paired` 是兩邊的最小值，後面兩項至少有一項為 0，不會重複計費。

例如 `need1 = 1`、`need2 = 4`，先買 1 件組合包，再買 3 件 B 單品。若 A 的需求較大，相同公式也會自動改為補 A 單品。

#### 步驟 4：計算全部組合包的成本，再取最小值

```csharp
long allBoth = maxNeed * costBoth;

return Math.Min(separate, Math.Min(mixed, allBoth));
```

買 `maxNeed` 件組合包，兩類各得到 `maxNeed` 單位，因此一定達標。即使其中一類需求為 0，也可以選此方案，因為題目允許超額供應。

### 為什麼只比較三個候選點就夠

假設買了 `x` 件組合包，剩餘缺口使用單品補足，最低成本為：

```text
F(x) = x * costBoth
     + max(need1 - x, 0) * cost1
     + max(need2 - x, 0) * cost2
```

令 `p = min(need1, need2)`、`m = max(need1, need2)`，觀察多買 1 件組合包時的成本變化：

| 原本組合包數量 | 多買 1 件後少買的單品 | 成本變化 `F(x+1) - F(x)` |
| --- | --- | --- |
| `0 <= x < p` | A、B 單品各 1 件 | `costBoth - cost1 - cost2` |
| `p <= x < m` | 仍有缺口那一類的單品 1 件 | `costBoth - 該類單價` |
| `x >= m` | 不會少買任何單品 | `costBoth`，必定為正 |

每個區間內的成本變化固定，所以成本只會持續增加、持續減少，或保持不變。**區間內的最低成本一定可以在端點取得**，不必逐一枚舉中間的整數；變化為 0 時，端點同樣是最低值之一。

因此只需檢查 `x = 0`、`x = p`、`x = m`。超過 `m` 後兩類都已達標，只會多花錢。若需求相等或其中一類為 0，候選點可能重複，仍可使用相同公式；兩類需求皆為 0 時，三個成本也都是 0。

### ASCII 流程圖

```text
Start
  |
  v
p = min(need1, need2), m = max(need1, need2)
  |
  +--> x = 0 : separate = need1*cost1 + need2*cost2
  |
  +--> x = p : mixed = p*costBoth
  |                  + (need1-p)*cost1 + (need2-p)*cost2
  |
  +--> x = m : allBoth = m*costBoth
  |
  v
Return min(separate, mixed, allBoth)
```

### 範例演示

**混合方案最低。** 輸入 `(6, 3, 5, 1, 4)`，`paired = 1`、`maxNeed = 4`。

| 方案 | A 單品件數 | B 單品件數 | 組合包件數 | 成本 |
| --- | ---: | ---: | ---: | ---: |
| 全部單品 | 1 | 4 | 0 | `1*6 + 4*3 = 18` |
| 混合購買 | 0 | 3 | 1 | `1*5 + 0*6 + 3*3 = 14` |
| 全部組合包 | 0 | 0 | 4 | `4*5 = 20` |

```text
x (type 3 count):  0    1    2    3    4    5
F(x):            18   14   16   18   20   25
                  ^    ^              ^
Candidates:       0    p=1            m=4
Result: min(18, 14, 20) = 14
```

從 0 件增加到 1 件組合包，成本減少 `5 - 6 - 3 = -4`；從 1 件到 4 件，每增加 1 件的成本變化是 `5 - 3 = 2`。超過 4 件後，每件只增加 5 元。最低點因此在 `x = 1`。

**另外兩種方案也都可能勝出：**

| 輸入 | `separate` | `mixed` | `allBoth` | 最低成本與選擇 |
| --- | ---: | ---: | ---: | --- |
| `(3, 2, 1, 3, 2)` | `3*3 + 2*2 = 13` | `2*1 + 1*3 = 5` | `3*1 = 3` | 3，全部組合包，B 超額 1 單位 |
| `(5, 4, 15, 2, 3)` | `2*5 + 3*4 = 22` | `2*15 + 1*4 = 34` | `3*15 = 45` | 22，全部單品 |

### 複雜度與數值範圍

- 時間複雜度為 `O(1)`：固定比較三種方案，不受需求數量影響。
- 額外空間複雜度為 `O(1)`：只保存固定數量的變數。
- `separate` 的候選成本最高可達 `2 * 10^15`，仍在 `long` 範圍內。這是候選成本的上限，不代表最終最低成本一定達到該值。
- `separate` 的兩個乘積都先使用 `1L`；`paired`、`maxNeed` 本身為 `long`，所以混合方案與全部組合包方案的乘法也都使用 `long`。

## 兩種解法比較

| 比較項目 | 解法一 `MinimumCost` | 解法二 `MinimumCost2` |
| --- | --- | --- |
| 思考方式 | 依價格決定共同需求與剩餘需求的買法 | 計算三種完整方案，再取最小值 |
| 正確性重點 | 替換單品與組合包不會增加成本 | 成本分段線性，最低值可在端點取得 |
| 參數處理 | 扣除配對數，更新剩餘需求 | 保留原始需求與單價 |
| 時間／額外空間 | `O(1)`／`O(1)` | `O(1)`／`O(1)` |

### 從三種方案理解貪心判斷

**解法二把三種成本全部算出來；解法一根據價格關係，提前判斷哪種方案可取得最低成本。** 因此可以把解法一視為對三種方案進一步推理的寫法，兩者的漸進複雜度相同。

以下價格條件都使用原始參數。「剩餘類單價」指共同需求配對後，仍有需求那一類的單品價格：原本 `need1 > need2` 時為 `cost1`，原本 `need2 > need1` 時為 `cost2`。

| 價格條件 | 解法一的選擇 | 對應解法二的候選方案 |
| --- | --- | --- |
| `costBoth >= cost1 + cost2` | 全部買單品即可取得最低成本 | `separate` |
| `costBoth < cost1 + cost2`，且剩餘類單價 `<= costBoth` | 共同需求買組合包，剩餘需求買單品 | `mixed` |
| `costBoth < cost1 + cost2`，且剩餘類單價 `> costBoth` | 共同需求與剩餘需求都買組合包 | `allBoth` |

第一列能直接選全部單品，是因為兩種單價皆為正，此時組合包也比任一單品貴。後兩列則先確定組合包比兩件單品合計便宜，再比較它能否更便宜地補足單邊需求。

同價時可能有多個最佳方案：`costBoth == cost1 + cost2` 時，`separate` 與 `mixed` 同價；在共同需求選組合包的條件下，若剩餘類單價等於 `costBoth`，`mixed` 與 `allBoth` 同價。方法只回傳最低成本，不需要指定唯一的採購方式。

需求相等時，配對後沒有剩餘需求，`mixed` 與 `allBoth` 是同一個候選點，不必判斷剩餘類單價。任一類需求為 0 時，`separate` 與 `mixed` 的候選點重合；兩類皆為 0 時，三個候選成本都是 0。這些情況仍適用既有公式與程式。

建議先用解法二建立三種方案的整體概念，再用解法一練習價格條件與貪心推理。兩種解法都已達到常數複雜度，分支較少不保證實際執行更快。
