## 題目說明

給定二維陣列 `books`，其中 `books[i] = [thickness_i, height_i]` 分別表示第 `i` 本書的厚度與高度；另外給定每層書架的最大寬度 `shelfWidth`。

擺放時必須遵守以下規則：

1. 書本必須按照原陣列順序擺放，不能重新排序。
2. 同一層所有書本的厚度總和不得超過 `shelfWidth`。
3. 每一層的高度由該層最高的書決定。
4. 所有層的高度相加，就是書架的總高度。

目標是選擇每一層的分界位置，使放完所有書本後的總高度最小。

### 官方範例一

```text
輸入：books = [[1,1],[2,3],[2,3],[1,1],[1,1],[1,1],[1,2]], shelfWidth = 4
輸出：6
```

其中一個最佳分層方式的各層高度為 `1`、`3`、`2`，總高度為 `1 + 3 + 2 = 6`。

### 官方範例二

```text
輸入：books = [[1,3],[2,4],[3,2]], shelfWidth = 6
輸出：4
```

三本書的總厚度剛好為 `6`，可以全部放在同一層；這一層的高度由最高的第二本書決定，因此答案為 `4`。

## 限制條件

依 [LeetCode 1105 官方題面](https://leetcode.com/problems/filling-bookcase-shelves/description/)：

- `1 <= books.length <= 1000`
- `books[i].length == 2`
- `1 <= thickness_i <= shelfWidth <= 1000`
- `1 <= height_i <= 1000`
- 所有書本必須依照輸入順序擺放。

三個公開解法都依照上述合法輸入契約運作，不額外處理 `null`、空陣列、欄位不足或單本書厚度超過書架寬度的輸入。三種解法只讀取 `books`，不會排序或修改其中的數值。

## 解題概念與出發點

### 1. 決策不是書本順序，而是分層位置

題目已固定書本順序，所以不能把高度相近的書任意放在一起。唯一可以選擇的是：目前這一層要連續放到哪一本書，下一本書則成為下一層的起點。

如果有 `n` 本書，每兩本相鄰書之間都可能「切開」或「不切開」。當書架足夠寬時，可能的分層組合數量會隨 `n` 呈指數成長，這正是暴力搜尋成本高的來源。

### 2. 一層的成本由最大高度決定

假設目前考慮把索引 `start..end` 的書放在同一層：

```text
該層合法條件 = thickness[start] + ... + thickness[end] <= shelfWidth
該層高度     = max(height[start], ..., height[end])
```

在擴張同一層的結尾時，可以累加寬度並同步維護最大高度，不需要每次重新掃描整段書本。

### 3. 重複子問題形成動態規劃狀態

不同的前段分層方式可能讓後續都從同一本書開始。從某個索引開始的「最小剩餘高度」只與該索引及固定的輸入有關，因此可以快取並重用。

同一個狀態有兩種常見表示方式：

- Top-down：`f(i)` 表示從第 `i` 本書開始擺放的最小剩餘高度。
- Bottom-up：`dp[i]` 表示前 `i` 本書已擺放完成時的最小總高度。

兩者枚舉的是相同分層選擇，只是計算方向相反。

## 解法一：Bottom-up 動態規劃

### 設計說明

`MinHeightShelves` 使用一維陣列 `dp`：

```text
dp[i] = 依序放完前 i 本書的最小總高度
dp[0] = 0
```

對每個 `bookCount`，先把第 `bookCount - 1` 本書視為最後一層的最後一本，再向前枚舉 `startIndex`：

1. 累加 `books[startIndex][0]` 至目前層寬度。
2. 如果總寬度超過 `shelfWidth`，立即停止；再往前只會更寬。
3. 更新目前層的最大書本高度。
4. 使用以下轉移式更新答案：

```text
dp[bookCount] = min(
    dp[bookCount],
    dp[startIndex] + books[startIndex..bookCount-1] 的最大高度
)
```

`dp[startIndex]` 已包含最後一層之前的最佳高度；加上目前最後一層的高度，就得到一個完整候選答案。

### 正確性說明

任何擺放前 `bookCount` 本書的合法方案，都有且只有一個最後一層起點 `startIndex`。在固定該起點後：

- 最後一層的高度必定是區間內書本高度最大值。
- 最後一層之前的最佳高度已由 `dp[startIndex]` 記錄。

演算法會倒序枚舉所有寬度合法的 `startIndex` 並取最小值，因此不會漏掉任何合法的最後一層分法。由 `dp[0] = 0` 逐步計算至 `dp[n]`，最終即得到全部書本的最小總高度。

### 複雜度

- 時間複雜度：`O(n²)`。
- 額外空間複雜度：`O(n)`。
- 是否修改輸入：否。

### 範例演示流程

使用 `books = [[1,3],[2,4],[2,2]]`、`shelfWidth = 3`：

```text
dp[0] = 0

bookCount = 1：
    最後一層放第 0 本，寬度 1、高度 3
    dp[1] = dp[0] + 3 = 3

bookCount = 2：
    最後一層只放第 1 本：dp[1] + 4 = 7
    最後一層放第 0..1 本：寬度 3、高度 4，dp[0] + 4 = 4
    dp[2] = 4

bookCount = 3：
    最後一層只放第 2 本：dp[2] + 2 = 6
    嘗試加入第 1 本後寬度為 4，超過上限，停止向前擴張
    dp[3] = 6
```

最後 `dp = [0,3,4,6]`，答案為 `6`。

## 解法二：Top-down 記憶化動態規劃

### 設計說明

`MinHeightShelves2` 從索引 `0` 呼叫遞迴 helper，並用 `memo[startIndex]` 保存狀態：

```text
f(startIndex) = 從 startIndex 開始擺放剩餘書本的最小高度
f(n) = 0
```

每個狀態從 `startIndex` 向右擴張目前層的 `endIndex`。只要目前層仍未超寬，就形成一個候選答案：

```text
目前層最大高度 + f(endIndex + 1)
```

所有候選答案的最小值會寫入 `memo[startIndex]`。之後若另一條搜尋路徑再次需要相同起點，就直接回傳快取結果，不再展開同一棵子樹。

### 正確性說明

對任意 `startIndex`，目前層一定包含第 `startIndex` 本書，並在某個寬度合法的 `endIndex` 結束。演算法枚舉所有這類結尾；固定目前層後，剩餘問題正是 `f(endIndex + 1)`。基底 `f(n) = 0` 表示所有書都已擺放。每層都在全部合法候選中取最小值，所以 `f(0)` 是全域最佳答案；記憶化只重用已證明相同的狀態，不會改變結果。

### 複雜度

- 時間複雜度：`O(n²)`；最多計算 `n` 個起點，每個起點最多向右掃描 `n` 本書。
- 額外空間複雜度：`O(n)`，包含 memo 與遞迴堆疊。
- 是否修改輸入：否。

### 範例演示流程

同樣使用 `books = [[1,3],[2,4],[2,2]]`、`shelfWidth = 3`：

```text
f(2)：
    最後一本自成一層，高度 2
    f(2) = 2

f(1)：
    第 1 本自成一層：4 + f(2) = 6
    第 1..2 本厚度為 4，超寬
    f(1) = 6

f(0)：
    第 0 本自成一層：3 + f(1) = 9
    第 0..1 本放同層：4 + f(2) = 6
    再加入第 2 本後厚度為 5，超寬
    f(0) = min(9, 6) = 6
```

`f(1)` 與 `f(2)` 只需真正計算一次，後續查詢直接使用 memo。

## 解法三：暴力搜尋

### 設計說明

`MinHeightShelves3` 使用與 Top-down 解法相同的遞迴狀態與分支，但刻意不建立 memo。每次來到 `startIndex`，都重新枚舉目前層可放到哪一本書，再遞迴搜尋剩餘部分。

這個版本清楚呈現原始問題的完整決策樹，適合用來理解「重複子問題」從何而來，也可作為小型案例的基準答案。不過它不適合接近 `books.length = 1000` 的輸入，因此測試程式會在上界案例明確略過此解法。

### 正確性說明

每一個合法書架配置都能唯一表示為一系列連續區間。遞迴在每個起點枚舉目前層的所有合法結尾，因此會走訪所有合法的區間切分組合。到達陣列尾端時回傳 `0`，回溯時逐層加上各層最大高度並取最小值，所以回傳結果必定是所有合法配置中的最小總高度。

### 複雜度

- 時間複雜度：`O(2ⁿ)`；最寬鬆情況下，每個相鄰位置都可能切開或合併。
- 遞迴堆疊空間複雜度：`O(n)`。
- 是否修改輸入：否。

### 範例演示流程

對 `[[1,3],[2,4],[2,2]]`、寬度 `3`，合法搜尋分支如下：

```text
分支 A：第 0 本單獨一層
    [0] 高度 3
    第 1 本只能單獨一層，高度 4
    第 2 本單獨一層，高度 2
    總高度 = 3 + 4 + 2 = 9

分支 B：第 0..1 本放在同一層
    [0..1] 厚度 1 + 2 = 3，高度 max(3,4) = 4
    [2] 高度 2
    總高度 = 4 + 2 = 6

第 0..2 本厚度為 5，超過書架寬度，不是合法分支。
```

比較所有合法分支後，最小值為 `6`。

## 三種解法比較

| 解法 | 計算方向 | 重用子問題 | 時間複雜度 | 額外空間 | 適用情境 |
| --- | --- | --- | --- | --- | --- |
| Bottom-up DP | 從前 `i` 本逐步擴張 | `dp[i]` | `O(n²)` | `O(n)` | 正式提交、無遞迴版本 |
| Top-down DP | 從目前起點向後搜尋 | `memo[startIndex]` | `O(n²)` | `O(n)` | 容易從遞迴定義推導 |
| 暴力搜尋 | 枚舉完整分層樹 | 無 | `O(2ⁿ)` | `O(n)` | 小型案例與教學基準 |

三個公開 API 都接受相同的 `int[][] books` 與 `int shelfWidth`，並回傳 `int` 最小總高度。三者都不修改輸入。
