# LeetCode 2911｜得到 K 個半回文串的最少修改次數

## 題目說明

給定字串 `s` 和整數 `k`，將 `s` 切成恰好 `k` 個連續子字串，再替換一些字元，使每段都成為半回文串。每替換一個位置算一次修改，求所有切法的最少總修改次數。完整雙語題意與範例見 [PROBLEM.md](PROBLEM.md)。

長度為 `m` 的子字串要成為半回文串，必須有一個真因數 `d`，滿足 `1 <= d < m` 且 `m % d == 0`。從段內偏移 `0` 到 `d - 1` 各取一組字元，每組沿著原字串每隔 `d` 個位置取一次。同一段的所有組都要各自形成迴文，才算符合這個 `d`。例如 `abcabc` 的 `d = 3` 會得到 `aa`、`bb`、`cc` 三組。題目給的 `k` 決定要切幾段，每段則可以各自選擇 `d`。

### 限制條件

- `2 <= s.Length <= 200`
- `1 <= k <= floor(s.Length / 2)`
- `s` 只包含小寫英文字母。

長度為 `1` 的子字串沒有真因數，因此每一段至少要有兩個字元。當 `k = floor(s.Length / 2)` 且字串長度為偶數時，每一段都必須恰好有兩個字元。

## 共用預處理｜計算每一段的修改成本

令 `n = s.Length`。一旦切點固定，每個位置只屬於一段。各段可以獨立選擇 `d` 和修改的字元，所以整體成本就是各段最低成本的總和。先算出所有區間的成本，DP 枚舉切點時便能直接查表。

### 為什麼只需數不相等的配對？

固定 `d` 時，段內偏移為 `offset` 的組包含 `offset + t * d`，其中 `t` 從 `0` 走到 `m / d - 1`。要讓這組成為迴文，第 `t` 個字元必須和第 `m / d - 1 - t` 個字元相等。每對不相等的字元至少要改一個，將其中一個改成另一個即可。每個位置最多只屬於一對，奇數長度的組中央也無需修改，所以不相等的配對數就是固定 `d` 的最少修改次數。

以下配對使用從 `0` 開始的段內索引。`1` 代表這對字元需要一次修改。

```text
offset      0   1   2   3   4   5
character   a   b   c   a   b   c

d = 1   [0,1,2,3,4,5]  abcabc   (0,5):1 + (1,4):0 + (2,3):1 = 2
d = 2   [0,2,4]        acb      (0,4):1
        [1,3,5]        bac      (1,5):1                       = 2
d = 3   [0,3]          aa       (0,3):0
        [1,4]          bb       (1,4):0
        [2,5]          cc       (2,5):0                       = 0
```

這段的成本是 `min(2, 2, 0) = 0`。若它位於原字串的 `l` 位置，`SegmentCost` 會在這些段內索引加上 `l`，直接比較原字串上的字元。

### 查表如何建立？

1. `BuildCosts` 枚舉 `d = 1..floor(n / 2)`，將 `d` 加入長度 `2d, 3d, ...` 的真因數清單。從 `2d` 開始可排除長度等於 `d` 的情況。
2. 枚舉左右端點 `l` 與 `r`，從 `r = l + 1` 開始，確保區間長度至少為 `2`。將每個合法 `d` 的配對成本取最小值，寫入 `cost[l][r]`。左右端點都包含在這段內。

## 共用 DP 狀態與切點

`F(seg, start)` 表示將從索引 `start` 到 `n - 1` 的後綴恰好切成 `seg` 段的最少修改次數。答案是 `F(k, 0)`。若 `seg = 1`，整個後綴就是最後一段，因此 `F(1, start) = cost[start][n-1]`。

當還有兩段以上時，令 `e` 為第一段的結尾索引。第一段至少兩個字元，所以 `e >= start + 1`。切完後還要留下 `n - 1 - e` 個字元給 `seg - 1` 段，所以 `e <= n - 1 - 2 * (seg - 1)`。

```text
index   start              e  e+1                    n-1
        [ cost[start][e]    ] [ F(seg - 1, e + 1)      ]
        |--- first segment --| |--- remaining suffix --|
```

對每個合法 `e` 計算 `cost[start][e] + F(seg - 1, e + 1)`，再取最小值。每種合法切法都會從其中一個 `e` 開始。固定 `e` 後，第一段與後綴各自達到最低成本，就能得到該切點的最佳結果。由一段的基底往上套用這個推論，可得到任意合法段數的最少成本。

## 方法一｜自頂向下記憶化搜尋

### 按程式執行順序

1. **準備成本表與記憶表。** `MinimumChanges` 呼叫 `BuildCosts(s)`，接著建立 `memo[k + 1][n]`，第一個索引是剩餘段數，第二個索引是後綴起點。每格填入 `-1`，因此計算完畢且成本剛好為 `0` 的狀態仍可被辨識。入口 `Solve(k, 0, ...)` 從完整字串開始。
2. **先處理遞迴終點，再查記憶表。** 若 `seg == 1`，最後一段的起點已知，右端就是 `n - 1`，直接回傳 `cost[start][n - 1]`。其餘狀態先查 `memo[seg][start]`，若已有結果就立即回傳。
3. **依序試第一段的每個結尾。** `e` 從 `start + 1` 走到 `limit`。對每個 `e`，先拿到第一段成本 `cost[start][e]`，再呼叫 `Solve(seg - 1, e + 1, ...)` 求出剩下各段的最低成本。兩者相加得到這個切點的總成本，再用 `Math.Min` 更新 `best`。初始值 `n` 是安全上界，因為把每段改成全是同一字元，最多只需要修改 `n` 個位置。
4. **等所有切點比較完才記錄。** `memo[seg][start] = best` 保存的是整個後綴的最佳值。`Solve` 回傳後，上一層才將這個值加到自己選定的第一段成本。

### 範例演示

以 `s = "abababab", k = 3` 為例，`n = 8`。起點是 `0`，第一次切分的上限為 `7 - 2 * (3 - 1) = 3`，可選 `e = 1, 2, 3`。下圖各邊的數字是第一段成本，葉節點的數字是最後一段的成本。

```text
F(3,0)
|-- e=1, "ab"  costs 1 --> F(2,2) = min(1,0,1) = 0
|   |-- e=3, "ab"  costs 1 --> F(1,4) = 0  ("abab")
|   |-- e=4, "aba" costs 0 --> F(1,5) = 0  ("bab")
|   `-- e=5, "abab" costs 0 -> F(1,6) = 1  ("ab")
|-- e=2, "aba" costs 0 --> F(2,3) = min(1,1) = 1
|   |-- e=4, "ba"  costs 1 --> F(1,5) = 0  ("bab")
|   `-- e=5, "bab" costs 0 --> F(1,6) = 1  ("ab")
`-- e=3, "abab" costs 0 -> F(2,4) = 2
    `-- e=5, "ab"  costs 1 --> F(1,6) = 1  ("ab")

F(3,0) = min(1 + 0, 0 + 1, 0 + 2) = 1
```

跟著第一條分支看，`e = 1` 固定第一段為索引 `0..1` 的 `ab`，目前成本為 `1`。遞迴進入 `Solve(2, 2, ...)`，由於還要保留最後一段，現在的上限是 `7 - 2 = 5`。三次嘗試依序得到 `1 + 0 = 1`、`0 + 0 = 0`、`0 + 1 = 1`，所以這一層的 `best` 從 `8` 更新為 `1`、`0`、`0`。寫入 `memo[2][2] = 0` 後回到最外層，第一個切點的總成本就是 `1 + 0 = 1`，對應 `ab | aba | bab`。另外兩個切點的成本為 `1` 和 `2`，所以最後寫入 `memo[3][0] = 1`。

### 什麼時候真的會讀到 `memo`？

上圖中的 `F(1,6)` 雖然出現多次，每次都只需一次成本表查詢。要觀察多段狀態的重用，可以用 `s = "ababababab", k = 4`。下圖的兩條路徑在切完前兩段後，都留下索引 `5..9` 的 `babab`，而且都還需要切兩段。

```text
Solve(4, 0)
|-- e=1: "ab"  -> Solve(3, 2)
|                 `-- e=4: "aba" -> Solve(2, 5) -> compute and store 1
`-- e=2: "aba" -> Solve(3, 3)
                  `-- e=4: "ba"  -> Solve(2, 5) -> read memo[2][5] = 1
```

第一次計算 `Solve(2, 5, ...)` 時，`e = 6` 對應 `ba | bab`，成本為 `1 + 0`，`e = 7` 對應 `bab | ab`，成本為 `0 + 1`。第二次到達時，前兩段的切法雖然變了，待處理的後綴與剩餘段數相同，因此可以直接回傳 `1`。前兩段各自的成本由呼叫端加上。

## 方法二｜自底向上滾動 DP

### 按程式執行順序

1. **填入一段的基底。** `MinimumChanges2` 建好同一張成本表，然後對 `start = 0..n-2` 設定 `prev[start] = cost[start][n - 1]`。從這些起點到字串尾端至少有兩個字元，整段可直接查成本。若 `k == 1`，後面的迴圈不會執行，`prev[0]` 就是答案。
2. **開始下一層。** 令 `seg` 從 `2` 增加到 `k`。進入每層時，`prev[start]` 已保存 `F(seg - 1, start)`。建立填滿 `n` 的 `cur`，用來累計本層最小值。只有 `n - start >= 2 * seg` 的起點能湊足段數，所以起點迴圈的條件是 `start + 2 * seg <= n`。
3. **針對同一個起點比較切點。** 每試一個 `e`，就用 `cost[start][e] + prev[e + 1]` 更新 `cur[start]`。`limit` 保證 `e + 1` 到字串尾端至少有 `2 * (seg - 1)` 個字元，因此讀到的一定是前一層有效的值。
4. **讓本層成為下一輪的前一層。** 等所有起點都算完後才執行 `prev = cur`。這次指派讓 `prev` 指向已完成的陣列，下一輪會建立新的 `cur`。算到 `seg = k` 後，從索引 `0` 讀出整個字串的最低成本。

### 範例演示

同樣使用 `s = "abababab", k = 3`。表格的欄是後綴的起始索引，`-` 表示後綴長度不足。

```text
start      0  1  2  3  4  5  6  7
           -----------------------
seg = 1    0  0  0  0  0  0  1  -
seg = 2    0  0  0  1  2  -  -  -
seg = 3    1  2  3  -  -  -  -  -
```

1. 初始化 `seg = 1`。例如，`start = 4` 的後綴 `abab` 用 `d = 2` 得到 `aa`、`bb`，成本為 `0`。`start = 6` 的後綴 `ab` 只可用 `d = 1`，成本為 `1`。
2. 由 `seg = 1` 算出 `seg = 2`。字串長度為 `8`，本層可處理 `start = 0..4`，第一段最晚在 `e = 5` 結束。以下用 `start = 3` 示範內層迴圈。兩個候選都讀取一段的資料，因此本層其他起點是否已更新，對這組計算沒有影響。
3. 本層完成後，`prev = cur` 將兩段的結果交給下一輪。計算 `seg = 3` 時，第一段最晚在 `e = 3` 結束。只要把相應的三個兩段結果接到第一段成本後面，就能完成 `start = 0` 的狀態。程式仍會算完本層的其他合法起點，最後回傳 `prev[0]`。

```text
seg = 2, start = 3         cur[3] starts at 8
e = 4 : cost[3][4] + prev[5] = 1 + 0 = 1    cur[3] = 1
e = 5 : cost[3][5] + prev[6] = 0 + 1 = 1    cur[3] = 1

prev = cur                 prev now holds the seg = 2 row

seg = 3, start = 0         cur[0] starts at 8
e = 1 : cost[0][1] + prev[2] = 1 + 0 = 1    cur[0] = 1
e = 2 : cost[0][2] + prev[3] = 0 + 1 = 1    cur[0] = 1
e = 3 : cost[0][3] + prev[4] = 0 + 2 = 2    cur[0] = 1

prev = cur                 return prev[0] = 1
```

在上例中，自頂向下從 `F(3,0)` 追到 `F(2,2)`、`F(2,3)` 和 `F(2,4)`，取得答案所需的三個子問題。自底向上先填好整個兩段的有效範圍，之後在最終轉移直接讀取 `prev[2]`、`prev[3]` 和 `prev[4]`。兩種方法使用相同的區間成本和切點，計算順序決定它們何時查表、何時保存結果。

### 複雜度比較

| 階段 | 時間 | 額外空間 |
| --- | --- | --- |
| 共用真因數與區間成本預處理 | `O(n³ log n)` 上界 | `O(n²)` |
| 方法一的 DP | `O(k n²)` | `O(k n)`，含深度最多 `k` 的遞迴堆疊 |
| 方法二的 DP | `O(k n²)` | `O(n)`，計算時只保留相鄰兩層 |

真因數清單共存放 `O(n log n)` 筆資料，因為每個 `d` 最多加入 `floor(n / d) - 1` 個清單。每筆長度與真因數的組合最多用於 `n` 個區間，每個區間最多比較 `n / 2` 對字元，因此預處理時間的上界為 `O(n³ log n)`。兩種 DP 都至多算 `O(k n)` 個狀態，每個狀態最多枚舉 `O(n)` 個切點。方法一只搜尋可從 `(k, 0)` 到達的狀態，方法二按段數循序填表。加入共用成本表後，兩種方法的總額外空間都是 `O(n²)`，因為 `k <= n / 2`。
