## 題目說明

給定一棵二元樹的根節點 `root`，回傳節點值的層序遍歷結果：先由上到下逐層走訪，同一層則由左到右排列。

例如：

```text
輸入：root = [3,9,20,null,null,15,7]
輸出：[[3],[9,20],[15,7]]
```

對應的樹：

```text
        3
       / \
      9  20
         / \
        15  7
```

### 限制條件

- 樹中的節點數量介於 `0` 到 `2000`。
- `-1000 <= Node.val <= 1000`。
- 空樹必須回傳空集合 `[]`。
- 結果必須保留每一層由左至右的節點順序。

## 解題概念與出發點

層序遍歷的核心不是依節點值排序，而是按照「節點與根節點的距離」分組。根節點位於第 0 層，它的子節點位於第 1 層，依此類推。

因此需要同時解決兩件事：

1. 判斷每個節點屬於哪一層。
2. 確保同一層的節點維持由左至右的順序。

本專案保留兩種思考方式：

- **BFS**：天然依距離由近到遠處理節點；只要固定每輪佇列中的節點數，就能切出一層。
- **DFS**：先沿著分支深入，但在遞迴參數中攜帶 `depth`，即可把節點放進正確的層級集合。

## 解法一：BFS 搭配佇列

### 設計說明

`LevelOrder` 使用 `Queue<TreeNode>` 保存已發現、但尚未處理的節點。

每輪 `while` 開始時，佇列中剛好是目前準備處理的最前方若干節點。先將 `queue.Count` 保存為 `levelSize`，接著只取出這 `levelSize` 個節點。過程中加入佇列的左右子節點屬於下一層，不會在本輪被提前處理。

處理節點時固定先加入左子節點，再加入右子節點，因此下一層仍會保持由左至右的順序。

### 演算法步驟

1. 建立空結果；若 `root` 為 `null`，直接回傳。
2. 將根節點加入佇列。
3. 當佇列不為空時：
   - 保存目前的 `queue.Count` 作為本層節點數。
   - 依序取出這些節點，將節點值加入本層集合。
   - 將非空的左、右子節點加入佇列。
   - 將完成的本層集合加入結果。
4. 回傳所有層級。

### 為什麼能得到正確結果

根節點先單獨進入佇列，因此第一輪只會產生第 0 層。假設某輪開始時，佇列前方的 `levelSize` 個節點正好屬於同一層；處理它們時加入的所有子節點都比父節點深一層，而且會排在既有節點之後。由於本輪只處理固定的 `levelSize` 個節點，這些子節點會完整留到下一輪。依此逐層推進，即可得到由上到下、每層由左至右的結果。

### 官方範例演示

輸入：

```text
[3,9,20,null,null,15,7]
```

| 輪次 | 輪次開始時的佇列 | 本層取出的值 | 加入下一層的節點 | 累積結果 |
| --- | --- | --- | --- | --- |
| 1 | `[3]` | `[3]` | `9, 20` | `[[3]]` |
| 2 | `[9, 20]` | `[9, 20]` | `15, 7` | `[[3], [9, 20]]` |
| 3 | `[15, 7]` | `[15, 7]` | 無 | `[[3], [9, 20], [15, 7]]` |

佇列清空後，回傳：

```text
[[3], [9, 20], [15, 7]]
```

### 複雜度

- 時間複雜度：`O(n)`，每個節點只會入列與出列一次。
- 額外空間複雜度：`O(w)`，`w` 是樹的最大寬度；不計輸出集合。
- 輸出空間：`O(n)`。

## 解法二：DFS 搭配深度索引

### 設計說明

`LevelOrder2` 建立結果集合後，呼叫 `AddNodeByDepth(node, depth, result)` 執行遞迴。

`depth` 表示目前節點所在層級。當 `result.Count == depth` 時，代表第一次走到這個深度，因此先新增一個空的層級集合，再把目前節點值加入 `result[depth]`。

遞迴固定先走左子樹、再走右子樹。雖然 DFS 會先深入分支，但同一深度的左側節點總會比右側節點先加入，因此各層仍保持由左至右。

### 演算法步驟

1. 建立空結果，從根節點與深度 `0` 開始遞迴。
2. 若目前節點為 `null`，結束該分支。
3. 若結果中還沒有目前深度的集合，先建立該層。
4. 將目前節點值加入 `result[depth]`。
5. 以 `depth + 1` 依序走訪左子樹與右子樹。
6. 所有遞迴完成後回傳結果。

### 為什麼能得到正確結果

每次遞迴都攜帶從根節點累積而來的正確深度，所以節點一定會加入對應的 `result[depth]`。前序走訪的順序是「目前節點、左子樹、右子樹」；對任一深度而言，左側分支中的節點一定先於右側分支加入，因此同層順序仍符合由左至右。所有非空節點都恰好被走訪一次，所以不會遺漏或重複。

### 官方範例演示

| 遞迴順序 | 節點 | 深度 | 動作 | 累積結果 |
| --- | ---: | ---: | --- | --- |
| 1 | `3` | 0 | 建立第 0 層並加入 `3` | `[[3]]` |
| 2 | `9` | 1 | 建立第 1 層並加入 `9` | `[[3], [9]]` |
| 3 | `20` | 1 | 將 `20` 加入既有第 1 層 | `[[3], [9, 20]]` |
| 4 | `15` | 2 | 建立第 2 層並加入 `15` | `[[3], [9, 20], [15]]` |
| 5 | `7` | 2 | 將 `7` 加入既有第 2 層 | `[[3], [9, 20], [15, 7]]` |

遞迴結束後，回傳：

```text
[[3], [9, 20], [15, 7]]
```

### 複雜度

- 時間複雜度：`O(n)`，每個節點只會被走訪一次。
- 額外空間複雜度：`O(h)`，`h` 是樹高，來自遞迴呼叫堆疊；不計輸出集合。
- 輸出空間：`O(n)`。

> [!NOTE]
> 在高度接近節點數的極度偏斜樹中，DFS 需要較深的遞迴堆疊；BFS 則主要受最大樹寬影響。

## 兩種解法比較

| 比較項目 | BFS：`LevelOrder` | DFS：`LevelOrder2` |
| --- | --- | --- |
| 核心資料結構 | 佇列 | 遞迴呼叫堆疊與深度索引 |
| 分層方式 | 每輪固定 `queue.Count` | 使用 `depth` 定位結果集合 |
| 時間複雜度 | `O(n)` | `O(n)` |
| 額外空間 | `O(w)` | `O(h)` |
| 優點 | 流程直接對應層序遍歷 | 展示 DFS 也能依深度分組 |
| 注意事項 | 寬樹可能讓佇列較大 | 偏斜樹可能產生較深遞迴 |
