## 題目說明

給定整數陣列 `score`，其中 `score[i]` 表示第 `i` 位選手的分數。所有分數皆不重複，分數越高，名次越前面。

名次需要轉換成以下文字：

- 第一名：`"Gold Medal"`
- 第二名：`"Silver Medal"`
- 第三名：`"Bronze Medal"`
- 第四名之後：使用名次的十進位字串，例如 `"4"`、`"5"`

最後回傳與輸入長度相同的字串陣列，且 `answer[i]` 必須是原本第 `i` 位選手的名次。也就是說，排序只能協助計算名次，不能讓輸出失去原始選手順序。

題目來源：[LeetCode 506. Relative Ranks](https://leetcode.com/problems/relative-ranks/)

### 限制條件

- `n == score.length`
- `1 <= n <= 10^4`
- `0 <= score[i] <= 10^6`
- `score` 中的所有分數皆互不重複。

### 官方範例

| 輸入 | 輸出 |
|---|---|
| `[5,4,3,2,1]` | `["Gold Medal","Silver Medal","Bronze Medal","4","5"]` |
| `[10,3,8,9,4]` | `["Gold Medal","5","Bronze Medal","Silver Medal","4"]` |

第二個範例中，原始選手順序的分數依序是 `10`、`3`、`8`、`9`、`4`：

- `10` 是最高分，因此第一個輸出是 `"Gold Medal"`。
- `3` 是最低分，但仍位於原陣列索引 `1`，所以第二個輸出是 `"5"`。
- `8`、`9`、`4` 分別取得第三、第二、第四名。

## 解題概念與出發點

這題包含兩個彼此相關、但不能混為一談的順序：

1. **排名順序**：分數由高到低，負責決定每位選手的名次。
2. **輸出順序**：維持輸入陣列的索引順序，負責把名次交還給正確的選手。

如果只排序 `score` 並直接回傳排序後的名次，答案會變成「依名次排列」，而不是題目要求的「依原始選手排列」。因此，解題關鍵不是排序本身，而是排序完成後如何找回每筆資料原本的位置。

本專案以兩種方式保存這個關聯：

- 解法一在排序前，把每個分數和原始索引綁在一起。
- 解法二排序分數副本，再以字典建立「分數到名次」的映射。

因為題目保證所有分數互不重複，所以分數可以安全地作為字典鍵。兩種方法都不需要修改呼叫端傳入的陣列。

## 解法一：索引配對排序

公開方法：`FindRelativeRanks(int[] score)`

### 設計說明

這個方法把每位選手轉換成一組二元素資料：

```text
[分數, 原始索引]
```

接著依第一個元素，也就是分數，由高到低排序。排序後陣列的位置就是從零開始的排名位置：

- 排序位置 `0` 對應第一名。
- 排序位置 `1` 對應第二名。
- 排序位置 `2` 對應第三名。
- 其他排序位置 `i` 對應名次 `i + 1`。

決定名次文字後，不直接寫入排序位置，而是透過資料中保存的原始索引寫入答案陣列。如此便能同時利用排序決定名次，又保持輸出順序不變。

排序比較器使用 `CompareTo`：

```csharp
(first, second) => second[0].CompareTo(first[0])
```

這比以 `second[0] - first[0]` 判斷順序更健全，因為相減式比較器在一般整數資料中可能溢位。

### 執行步驟

1. 建立與 `score` 等長的配對陣列。
2. 對每個索引 `i` 保存 `[score[i], i]`。
3. 依分數由高到低排序配對陣列。
4. 走訪排序結果，以目前排序位置產生名次文字。
5. 讀取配對中的原始索引，把名次寫入答案的正確位置。
6. 回傳答案陣列。

### 範例演示：`[10,3,8,9,4]`

建立分數與索引配對：

| 原始索引 | 分數 | 配對 |
|---:|---:|---|
| 0 | 10 | `[10,0]` |
| 1 | 3 | `[3,1]` |
| 2 | 8 | `[8,2]` |
| 3 | 9 | `[9,3]` |
| 4 | 4 | `[4,4]` |

依分數降冪排序：

| 排序位置 | 配對 | 名次文字 | 寫入答案位置 |
|---:|---|---|---:|
| 0 | `[10,0]` | `"Gold Medal"` | 0 |
| 1 | `[9,3]` | `"Silver Medal"` | 3 |
| 2 | `[8,2]` | `"Bronze Medal"` | 2 |
| 3 | `[4,4]` | `"4"` | 4 |
| 4 | `[3,1]` | `"5"` | 1 |

依照保存的原始索引寫回後：

```text
["Gold Medal", "5", "Bronze Medal", "Silver Medal", "4"]
```

### 正確性說明

排序後第 `i` 筆資料前方恰好有 `i` 位分數更高的選手，因此它的名次必為 `i + 1`。題目保證分數不重複，所以不需要處理同分名次。

每筆排序資料都保存唯一的原始索引。把由排序位置決定的名次寫入該索引後，答案中的每個位置都會對應原本同一位選手。因此，方法得到正確排名，也滿足原始輸出順序要求。

### 複雜度

- **時間複雜度：`O(n log n)`**
  - 建立配對與寫回答案各需要 `O(n)`。
  - 排序需要 `O(n log n)`，為主要成本。
- **額外空間複雜度：`O(n)`**
  - 配對陣列保存每筆分數與原始索引。
- **輸出空間：`O(n)`**
  - 回傳名次陣列包含 `n` 筆字串。

## 解法二：排序副本＋字典映射

公開方法：`FindRelativeRanks2(int[] score)`

### 設計說明

這個方法先複製 `score`，只排序副本，因此原始輸入保持不變。排序後由最高分往最低分走訪，將每個分數對應到名次文字：

```text
分數 -> 名次文字
```

映射建立完成後，再依原始 `score` 的順序逐一查詢字典。因為最後一次走訪使用的是原陣列順序，所以產生的答案自然與輸入對齊。

這個方法依賴題目的「所有分數互不重複」條件。如果允許同分，單純以分數作為字典鍵仍可共用同一名次文字，但排名規則和排序位置計算就必須另外定義；本題不需要處理該情況。

### 執行步驟

1. 複製 `score`，得到不影響原輸入的 `sortedScores`。
2. 將副本由小到大排序。
3. 從排序陣列尾端開始讀取，依序取得最高分、第二高分與後續分數。
4. 使用排序位置產生名次文字，寫入 `rankByScore` 字典。
5. 依原始 `score` 順序走訪，以分數查詢名次。
6. 回傳與輸入順序相同的答案陣列。

### 範例演示：`[10,3,8,9,4]`

複製並排序後：

```text
[3, 4, 8, 9, 10]
```

由尾端往前建立字典：

| 讀取順序 | 分數 | 排名 | 字典項目 |
|---:|---:|---:|---|
| 1 | 10 | 1 | `10 -> "Gold Medal"` |
| 2 | 9 | 2 | `9 -> "Silver Medal"` |
| 3 | 8 | 3 | `8 -> "Bronze Medal"` |
| 4 | 4 | 4 | `4 -> "4"` |
| 5 | 3 | 5 | `3 -> "5"` |

再依原始順序查詢：

| 原始分數 | 查詢結果 |
|---:|---|
| 10 | `"Gold Medal"` |
| 3 | `"5"` |
| 8 | `"Bronze Medal"` |
| 9 | `"Silver Medal"` |
| 4 | `"4"` |

最終結果：

```text
["Gold Medal", "5", "Bronze Medal", "Silver Medal", "4"]
```

### 正確性說明

排序副本從最大值往最小值的第 `i` 次讀取，正好取得第 `i + 1` 名的分數，因此建立的每一筆「分數到名次」映射都正確。

原始陣列中的每個分數都唯一，且一定已存在於字典中。按照原陣列索引依序查詢時，每個答案位置會得到該位置選手的正確名次，所以輸出同時符合排名與原始順序要求。

### 複雜度

- **時間複雜度：`O(n log n)`**
  - 複製、建立字典及產生答案各需要 `O(n)`。
  - 排序副本需要 `O(n log n)`。
- **額外空間複雜度：`O(n)`**
  - 使用分數副本與分數到名次的字典。
- **輸出空間：`O(n)`**
  - 回傳名次陣列包含 `n` 筆字串。

## 兩種解法比較

| 比較項目 | 解法一：索引配對排序 | 解法二：排序副本＋字典映射 |
|---|---|---|
| 公開 API | `FindRelativeRanks` | `FindRelativeRanks2` |
| 保存原順序的方法 | 每筆排序資料攜帶原始索引 | 依分數查詢名次字典 |
| 排序資料 | `[分數, 原始索引]` 配對 | 純分數副本 |
| 排序方向 | 直接降冪 | 升冪後由尾端讀取 |
| 時間複雜度 | `O(n log n)` | `O(n log n)` |
| 額外空間 | `O(n)` | `O(n)` |
| 是否修改輸入 | 否 | 否 |
| 優點 | 名次與選手位置關聯直接 | 資料流清楚，查表還原容易理解 |
| 主要依賴 | 正確保存原始索引 | 分數互不重複，適合作為字典鍵 |

兩種方法的漸進複雜度相同。解法一將位置資訊帶進排序流程，解法二則把「排名」與「依原順序輸出」拆成兩個階段；選擇哪一種主要取決於希望呈現的資料模型。
