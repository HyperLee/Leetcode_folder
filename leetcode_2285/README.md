## 題目說明

官方題目：

- [LeetCode 英文題目](https://leetcode.com/problems/maximum-total-importance-of-roads/description/)
- [LeetCode 中文題目](https://leetcode.cn/problems/maximum-total-importance-of-roads/description/)

有 `n` 座城市，編號為 `0` 到 `n - 1`。`roads[i] = [a, b]` 表示城市 `a` 與城市 `b` 之間有一條雙向道路。

必須把 `1` 到 `n` 這 `n` 個不同整數各分配給一座城市，而且每個數值只能使用一次。一條道路的重要性等於它連接的兩座城市數值之和。目標是在最佳分配下，求出所有道路重要性的最大總和。

例如道路 `[0, 1]` 的兩端若分別獲得數值 `2` 與 `4`，這條道路的重要性就是 `2 + 4 = 6`。

## 限制條件與輸入契約

| 條件 | 官方範圍 |
| --- | --- |
| 城市數量 | `2 <= n <= 5 * 10^4` |
| 道路數量 | `1 <= roads.Length <= 5 * 10^4` |
| 每筆道路資料 | `roads[i].Length == 2` |
| 城市編號 | `0 <= roads[i][0], roads[i][1] <= n - 1` |
| 道路兩端 | `roads[i][0] != roads[i][1]` |
| 重複道路 | 不存在 |

兩個公開方法都依照 LeetCode 呼叫契約處理合法輸入，不另外定義 `null`、空道路集合、自環、重複道路或越界城市編號的行為。兩種解法都只讀取 `roads`，不會修改輸入陣列。

回傳型別使用 `long`。即使每座城市的數值與道路數量都能放進 `int`，所有道路的重要性總和仍可能超過 32 位元整數範圍。

## 解題概念與出發點

### 1. 把每條道路拆成兩端城市的貢獻

假設城市 `i` 被分配到數值 `value[i]`，它連接的道路數量，也就是城市度數，記為 `degree[i]`。

每一條道路 `[a, b]` 對總和的貢獻是：

```text
value[a] + value[b]
```

把所有道路相加後，每座城市的數值會按照它出現在道路端點的次數重複出現，因此總和可以改寫為：

```text
總重要性 = Σ degree[i] * value[i]
```

問題因此不需要逐條道路嘗試各種權重組合，而是要決定如何把 `1..n` 配給各城市度數。

### 2. 高度數城市必須配到較大的重要性

考慮兩座城市 A、B，且：

```text
degree[A] < degree[B]
value[A]  > value[B]
```

目前兩座城市的貢獻是：

```text
degree[A] * value[A] + degree[B] * value[B]
```

交換兩個數值後，總和增加量為：

```text
(degree[B] - degree[A]) * (value[A] - value[B]) > 0
```

這表示「較低度數卻取得較大數值」不可能是最佳安排，因為交換後一定更好。因此最佳策略就是讓度數與重要性使用相同順序配對：度數越大，分配到的數值越大。

### 3. 度數相同時不必在意城市順序

若兩座城市度數相同，交換它們的數值不會改變總和。演算法只需要知道排序後的度數，或每種度數有幾座城市，不需要真的保存唯一的城市權重配置。

## 解法一：排序城市度數

### API

```csharp
public static long MaximumImportance(int n, int[][] roads)
```

### 設計說明

1. 建立長度為 `n` 的 `cityDegrees`。
2. 對每條道路 `[a, b]`，分別增加 `cityDegrees[a]` 與 `cityDegrees[b]`。
3. 將所有城市度數由小到大排序。
4. 讓排序後索引 `i` 的度數取得重要性 `i + 1`。
5. 累加 `cityDegrees[i] * (i + 1)`。

這個方法不需要記錄「哪一座城市」取得哪個數值，因為展開總和後只剩度數與數值的乘積。排序後直接做內積，就能得到最佳總和。

### 範例演示流程

官方範例一：

```text
n = 5
roads = [[0,1],[1,2],[2,3],[0,2],[1,3],[2,4]]
```

先統計每座城市的度數：

| 城市 | 相連道路 | 度數 |
| ---: | --- | ---: |
| 0 | `[0,1]`, `[0,2]` | 2 |
| 1 | `[0,1]`, `[1,2]`, `[1,3]` | 3 |
| 2 | `[1,2]`, `[2,3]`, `[0,2]`, `[2,4]` | 4 |
| 3 | `[2,3]`, `[1,3]` | 2 |
| 4 | `[2,4]` | 1 |

```text
原始度數 = [2, 3, 4, 2, 1]
排序度數 = [1, 2, 2, 3, 4]
```

依序配對重要性 `1..5`：

| 排序位置 | 度數 | 重要性 | 貢獻 |
| ---: | ---: | ---: | ---: |
| 0 | 1 | 1 | 1 |
| 1 | 2 | 2 | 4 |
| 2 | 2 | 3 | 6 |
| 3 | 3 | 4 | 12 |
| 4 | 4 | 5 | 20 |

```text
最大總重要性 = 1 + 4 + 6 + 12 + 20 = 43
```

### 正確性說明

每座城市的數值在總和中恰好出現 `degree[i]` 次，所以目標等價於最大化 `Σ degree[i] * value[i]`。若有一對城市的度數順序與數值順序相反，交換數值會使總和增加；持續消除所有反序配對後，度數與數值必定同序。`MaximumImportance` 正是把兩者都由小到大配對，因此結果為全域最大值。

### 複雜度與輸入契約

- 時間複雜度：`O(m + n log n)`，其中 `m` 是道路數量。
- 額外空間複雜度：`O(n)`，保存每座城市的度數。
- 修改輸入：否。
- 優點：概念直接，程式精簡，與「排序後同序配對」的證明一致。
- 注意點：一般比較排序需要 `O(n log n)` 時間。

## 解法二：度數頻率桶

### API

```csharp
public static long MaximumImportance2(int n, int[][] roads)
```

### 設計說明

本題是沒有自環與重複道路的簡單無向圖，一座城市最多只能連接其餘 `n - 1` 座城市，因此度數一定介於 `0` 到 `n - 1`。這個有限範圍可以用計數排序的想法取代比較排序。

1. 與解法一相同，先統計每座城市的度數。
2. 建立長度為 `n` 的 `degreeFrequencies`。
3. 對每座城市的度數 `degree`，增加 `degreeFrequencies[degree]`。
4. 從度數 `0` 掃描到 `n - 1`。
5. 每遇到一座該度數的城市，就分配下一個重要性並累加乘積。

頻率桶由小到大展開後，得到的度數序列與 `Array.Sort` 完全相同，但只需線性掃描。

### 範例演示流程

官方範例一的城市度數仍是：

```text
[2, 3, 4, 2, 1]
```

建立頻率桶後：

| 度數 | 城市數量 | 分配的重要性 | 本桶貢獻 |
| ---: | ---: | --- | ---: |
| 0 | 0 | 無 | 0 |
| 1 | 1 | `1` | `1 * 1 = 1` |
| 2 | 2 | `2, 3` | `2 * (2 + 3) = 10` |
| 3 | 1 | `4` | `3 * 4 = 12` |
| 4 | 1 | `5` | `4 * 5 = 20` |

```text
最大總重要性 = 1 + 10 + 12 + 20 = 43
```

桶中只記錄城市數量。度數相同的城市彼此交換重要性不會改變答案，因此不需要知道每個桶中包含哪些城市。

### 正確性說明

`degreeFrequencies[d]` 精確記錄度數為 `d` 的城市數。從 `d = 0` 到 `n - 1` 依頻率展開，會依非遞減順序列出每座城市的度數；逐一分配遞增的重要性 `1..n`，與解法一的排序後同序配對完全相同。根據前述交換論證，這個配對必定最大化總重要性，因此 `MaximumImportance2` 回傳正確答案。

### 複雜度與輸入契約

- 時間複雜度：`O(m + n)`，統計道路、建立頻率桶與展開桶都為線性時間。
- 額外空間複雜度：`O(n)`，保存城市度數與度數頻率。
- 修改輸入：否。
- 優點：利用題目給定的度數上界，省去比較排序。
- 注意點：頻率陣列長度必須涵蓋最大可能度數 `n - 1`。

## 兩種解法比較

| 比較項目 | `MaximumImportance` | `MaximumImportance2` |
| --- | --- | --- |
| 核心方法 | 排序所有城市度數 | 依度數範圍建立頻率桶 |
| 時間複雜度 | `O(m + n log n)` | `O(m + n)` |
| 額外空間複雜度 | `O(n)` | `O(n)` |
| 修改輸入 | 否 | 否 |
| 是否保存城市權重 | 否 | 否 |
| 教學重點 | 貪心同序配對與交換論證 | 用值域取代比較排序 |

解法一較直觀，適合作為主要貪心解法；解法二進一步觀察「度數最大只有 `n - 1`」，用頻率桶把排序階段降為線性時間。兩者使用相同的最佳配對原理，輸出必須一致。
