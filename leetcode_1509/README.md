## 題目說明

給定一個整數陣列 `nums`。一次操作可以選擇任一元素，並把它修改為任意整數。最多執行三次操作後，求陣列最大值與最小值之間能達到的最小差值。

- [LeetCode 英文題目](https://leetcode.com/problems/minimum-difference-between-largest-and-smallest-value-in-three-moves/description/)
- [LeetCode 中文題目](https://leetcode.cn/problems/minimum-difference-between-largest-and-smallest-value-in-three-moves/description/)

### 限制條件

- `1 <= nums.Length <= 100_000`
- `-1_000_000_000 <= nums[i] <= 1_000_000_000`
- 最多可以修改三個元素。

## 解題核心與出發點

### 為什麼只需要處理極端值？

目標是縮小 `最大值 - 最小值`。修改位於中間的元素，不會改變最大值或最小值，因此也不會讓極差變小。真正有意義的操作只有兩類：

1. 把目前最大的元素改小。
2. 把目前最小的元素改大。

從「最後留下哪些值決定上下界」的角度看，修改一個極端值，等價於不讓該值繼續擔任最大值或最小值。最多修改三個元素，因此只需要研究如何從左右兩端合計排除三個極端值。

### 三次修改只有四種分配方式

假設陣列已由小到大排序，長度為 `n`。令 `i` 表示從左側排除的最小值數量，則右側會排除 `3 - i` 個最大值：

| `i` | 修改最小值個數 | 修改最大值個數 | 修改後的最小值 | 修改後的最大值 | 候選差值 |
| ---: | ---: | ---: | --- | --- | --- |
| 0 | 0 | 3 | `nums[0]` | `nums[n - 4]` | `nums[n - 4] - nums[0]` |
| 1 | 1 | 2 | `nums[1]` | `nums[n - 3]` | `nums[n - 3] - nums[1]` |
| 2 | 2 | 1 | `nums[2]` | `nums[n - 2]` | `nums[n - 2] - nums[2]` |
| 3 | 3 | 0 | `nums[3]` | `nums[n - 1]` | `nums[n - 1] - nums[3]` |

四個候選值可統一寫成：

```text
nums[n - 4 + i] - nums[i]，其中 i = 0, 1, 2, 3
```

若 `nums.Length <= 4`，最多三次修改足以讓所有元素變成相同值，所以答案必定是 `0`。

## 解法比較

| 方法 | 核心作法 | 時間複雜度 | 額外空間 | 是否修改輸入 |
| --- | --- | --- | --- | --- |
| `MinDifference` | 完整排序後列舉四種邊界 | `O(n log n)` | `O(log n)` | 是，`Array.Sort` 會改變順序 |
| `MinDifference2` | 一次掃描維護四大、四小值 | `O(n)` | `O(1)` | 否 |

兩種方法列舉的仍是相同四種情況。差異只在於：第一種方法排序整個陣列；第二種方法只收集真正會影響答案的八個極端值。

## 解法一：完整排序

### 設計步驟

1. 取得陣列長度 `n`。
2. 若 `n <= 4`，直接回傳 `0`。
3. 使用 `Array.Sort(nums)` 將輸入由小到大排序。
4. 對 `i = 0..3` 計算 `nums[n - 4 + i] - nums[i]`。
5. 回傳四個候選差值中的最小值。

這個方法直接把所有候選邊界放到正確位置，因此程式短且容易驗證。代價是排序需要 `O(n log n)` 時間，而且會直接改變呼叫者傳入的陣列順序。

### 範例演示

輸入：

```text
[1, 5, 0, 10, 14]
```

排序後：

```text
[0, 1, 5, 10, 14]
```

四種候選情況如下。表格中的箭頭只示範一種可行的修改方式；被選中的值只要改到保留下來的上下界之間即可。程式本身不會真的逐項執行這些替換，而是直接使用排序後的索引計算四個候選差值。

| `i` | 修改最小端（改大） | 修改最大端（改小） | 修改後陣列範例 | 新上下界 | 差值 |
| ---: | --- | --- | --- | --- | ---: |
| 0 | — | `5、10、14 → 1` | `[0, 1, 1, 1, 1]` | `0` 到 `1` | `1 - 0 = 1` |
| 1 | `0 → 1` | `10、14 → 5` | `[1, 1, 5, 5, 5]` | `1` 到 `5` | `5 - 1 = 4` |
| 2 | `0、1 → 5` | `14 → 10` | `[5, 5, 5, 10, 10]` | `5` 到 `10` | `10 - 5 = 5` |
| 3 | `0、1、5 → 10` | — | `[10, 10, 10, 10, 14]` | `10` 到 `14` | `14 - 10 = 4` |

最小候選值為 `1`，因此答案是 `1`。

## 解法二：維護四個極值

### 設計步驟

1. 若陣列長度不超過 4，直接回傳 `0`。
2. 建立固定長度為 4 的 `maxValues`，維持由大到小排列。
3. 建立固定長度為 4 的 `minValues`，維持由小到大排列。
4. 掃描每個輸入值，將它插入適當位置；若它不屬於前四大或前四小，就忽略它。
5. 以 `maxValues[i] - minValues[3 - i]` 配對四種上下界，取最小值。

每次插入最多移動四個位置，固定長度不隨 `n` 增加，因此每個元素的處理成本是常數，總時間為 `O(n)`，額外空間也是 `O(1)`。

### 極值陣列如何更新

同樣以 `[1, 5, 0, 10, 14]` 為例。表格中的 `—` 代表該位置尚未被實際輸入值填滿：

| 讀取值 | `maxValues`（大到小） | `minValues`（小到大） |
| ---: | --- | --- |
| 初始 | `[—, —, —, —]` | `[—, —, —, —]` |
| 1 | `[1, —, —, —]` | `[1, —, —, —]` |
| 5 | `[5, 1, —, —]` | `[1, 5, —, —]` |
| 0 | `[5, 1, 0, —]` | `[0, 1, 5, —]` |
| 10 | `[10, 5, 1, 0]` | `[0, 1, 5, 10]` |
| 14 | `[14, 10, 5, 1]` | `[0, 1, 5, 10]` |

掃描完成後：

```text
maxValues = [14, 10, 5, 1]
minValues = [0, 1, 5, 10]
```

### 四種配對

| `i` | 計算 | 差值 | 對應操作 |
| ---: | --- | ---: | --- |
| 0 | `maxValues[0] - minValues[3]` | `14 - 10 = 4` | 修改三個最小值 |
| 1 | `maxValues[1] - minValues[2]` | `10 - 5 = 5` | 修改兩個最小值、一個最大值 |
| 2 | `maxValues[2] - minValues[1]` | `5 - 1 = 4` | 修改一個最小值、兩個最大值 |
| 3 | `maxValues[3] - minValues[0]` | `1 - 0 = 1` | 修改三個最大值 |

最小候選值同樣是 `1`。這個方法沒有排序整個輸入，也不會改變輸入陣列。
