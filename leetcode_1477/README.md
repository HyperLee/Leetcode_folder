# LeetCode 1477：Find Two Non-overlapping Sub-arrays Each With Target Sum

[![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4?logo=dotnet&logoColor=white)](https://dotnet.microsoft.com/)

- [LeetCode 英文題目](https://leetcode.com/problems/find-two-non-overlapping-sub-arrays-each-with-target-sum/description/)
- [LeetCode 中文題目](https://leetcode.cn/problems/find-two-non-overlapping-sub-arrays-each-with-target-sum/description/)

## 題目說明

給定一個正整數陣列 `arr` 與正整數 `target`，請找出兩個互不重疊的連續子陣列，且兩個子陣列的總和都必須等於 `target`。

可能存在多組符合條件的答案，因此要讓兩個子陣列的長度總和最小。如果找不到兩個合法且互不重疊的子陣列，回傳 `-1`。

例如：

```text
arr = [3, 2, 2, 4, 3], target = 3

[3] 位於索引 0
[3] 位於索引 4

兩段長度總和 = 1 + 1 = 2
```

## 限制條件

依照題目限制：

- `1 <= arr.length <= 10^5`
- `1 <= arr[i] <= 1000`
- `1 <= target <= 10^8`
- `arr` 的元素都是正整數，因此可以使用滑動視窗維護連續區間總和。

## 解題概念與出發點

這題不是只要找到兩段符合條件的子陣列，而是要在所有合法配對中找出最短總長度。因此，找到一段 `target` 子陣列時，還需要快速知道它左側或右側最短的可配對子陣列。

題目的正整數限制是滑動視窗成立的關鍵：

1. 右端點向右移動時，視窗總和只會增加或維持增加。
2. 當總和大於 `target` 時，向右移動左端點會讓總和減少。
3. 不需要重新計算每個區間的總和，因此可以在線性時間內掃描陣列。

任意一組合法答案都可以按照位置分成「左邊的第一段」與「右邊的第二段」。兩個解法分別選擇其中一段作為目前掃描的區間，再查詢另一側已知的最短長度。

不存在合法子陣列時，程式使用 `n + 1` 作為哨兵值。因為答案最多不會超過 `n`，最後只要判斷答案是否仍大於 `n`，就能轉換成 `-1`。

## 解法一：滑動視窗 + 前綴最小值

實作：`Program.MinSumOfLengths`

### 狀態定義

令 `preMin[i]` 表示：

> 所有右端點小於 `i`、總和等於 `target` 的子陣列中，最短的長度。

例如，當目前找到的第二段是 `[l, r]` 時，第一段的右端點必須小於 `l`。因此可以直接使用 `preMin[l]`，確保兩段不重疊。

### 掃描流程

由左至右枚舉右端點 `r`：

1. 將 `arr[r]` 加入目前視窗總和。
2. 若總和大於 `target`，持續移動左端點 `l`，直到總和不超過 `target`。
3. 若總和剛好等於 `target`，目前視窗 `[l, r]` 就是一個候選的第二段。
4. 用 `preMin[l] + (r - l + 1)` 更新答案。
5. 將目前找到的最短 target 子陣列長度保存到 `preMin[r + 1]`，供之後的視窗使用。

核心關係可以表示為：

```text
第一段的右端點 < l       第二段 [l, r]
|---------------------|   |-----------|
        preMin[l]          r - l + 1

候選答案 = preMin[l] + (r - l + 1)
```

### 範例流程

在看完整案例前，先把滑動視窗中的兩個指標分開理解。每次外層迴圈處理一個新的右端點 `r`，所以 `r` 會逐格向右擴張；只有當加入 `arr[r]` 後，總和大於 `target`，內層 `while` 才會讓左端點 `l` 向右移動：

```text
先加入 arr[r]，讓視窗向右擴張
        ↓
while (sum > target)：
    移除視窗最左側的 arr[l]
    l 向右移動一格
        ↓
最後檢查「完整的 [l, r]」是否剛好等於 target
```

因此，`l` 每次移動一格的意思是「把一個元素從目前視窗移除」，不是「把這個被移除的元素單獨拿來當成區間」。移除完成後，真正要判斷的仍然是剩下的完整視窗 `[l, r]`：

- `sum < target`：目前視窗還不夠大，先保留它，等待下一輪把新的 `arr[r + 1]` 加進來。
- `sum == target`：完整的 `[l, r]` 才是一段合法的 target 子陣列。
- `sum > target`：持續移動 `l`，直到總和降到 `target` 以下；因為陣列元素都是正整數，移除左側元素一定會讓總和變小。

先用一個比較能看出「視窗累積」的例子觀察這件事：`arr = [1, 2, 1, 2, 3, 2, 3]`、`target = 5`。

| `r` | 加入 `arr[r]` 後 | `while` 移除過程 | 縮小後的完整視窗 | 本輪結果 |
|---:|---|---|---|---|
| 0 | `[0, 0]`，總和 1 | 無 | `[0, 0]`，總和 1 | 小於 `target`，保留並等待下一個元素 |
| 1 | `[0, 1]`，總和 3 | 無 | `[0, 1]`，總和 3 | 小於 `target`，視窗仍是兩個元素 |
| 2 | `[0, 2]`，總和 4 | 無 | `[0, 2]`，總和 4 | 小於 `target`，視窗繼續等待擴張 |
| 3 | `[0, 3]`，總和 6 | 移除 `arr[0] = 1`，總和變 5；`l: 0 → 1` | `[1, 3]`，總和 5 | 找到完整區間 `[2, 1, 2]`，長度 3 |
| 4 | `[1, 4]`，總和 8 | 移除 `arr[1] = 2` 後為 6，再移除 `arr[2] = 1` 後為 5；`l: 1 → 3` | `[3, 4]`，總和 5 | `l` 在同一輪移動兩格，找到 `[2, 3]`，長度 2 |
| 5 | `[3, 5]`，總和 7 | 移除 `arr[3] = 2`，總和變 5；`l: 3 → 4` | `[4, 5]`，總和 5 | 找到 `[3, 2]`，長度 2 |
| 6 | `[4, 6]`，總和 8 | 移除 `arr[4] = 3`，總和變 5；`l: 4 → 5` | `[5, 6]`，總和 5 | 找到 `[2, 3]`，長度 2 |

這個追蹤可以看到兩種情況：`r = 0` 到 `r = 2` 時，總和還沒有超過 `target`，所以 `l` 完全不動，視窗從 `[0, 0]` 擴張成 `[0, 2]`；到了 `r = 4`，總和一次超過很多，`while` 便在同一個外層迴圈中連續移動 `l` 兩格。這才是「滑動」的完整過程：右端點持續擴張，左端點只在需要縮小時追趕，而且兩個端點都只會向右移動。

接著回到題目的案例 `arr = [3, 2, 2, 4, 3]`、`target = 3`。此時 `n = 5`，不存在子陣列時的哨兵值是 `6`。這組資料中的 `target` 較小，因此很多輪在加入新元素後都會立刻超過 `target`，看起來才會常常縮成單元素甚至空視窗；那是輸入資料造成的結果，不代表滑動視窗每次只能處理一格。

| `r` | 加入 `arr[r]` 後 | `while` 移除過程 | 縮小後的完整視窗 | 本輪處理與 `preMin[r + 1]` |
|---:|---|---|---|---|
| 0 | `[0, 0]`，總和 3 | 無 | `[0, 0]`，總和 3 | 找到 `[3]`，長度 1；`preMin[1] = 1` |
| 1 | `[0, 1]`，總和 5 | 移除 `arr[0] = 3`，總和變 2；`l: 0 → 1` | `[1, 1]`，總和 2 | 小於 `target`，不是候選；沿用最短長度，`preMin[2] = 1` |
| 2 | `[1, 2]`，總和 4 | 移除 `arr[1] = 2`，總和變 2；`l: 1 → 2` | `[2, 2]`，總和 2 | 小於 `target`，不是候選；`preMin[3] = 1` |
| 3 | `[2, 3]`，總和 6 | 先移除 `arr[2] = 2`，總和變 4；再移除 `arr[3] = 4`，總和變 0；`l: 2 → 4` | 空視窗，`l = 4`、`r = 3`，總和 0 | 仍未找到 target 區間；`preMin[4] = 1` |
| 4 | 上一輪是空視窗，加入 `arr[4] = 3` 後為 `[4, 4]`，總和 3 | 無 | `[4, 4]`，總和 3 | 找到第二個 `[3]`，查詢 `preMin[4] = 1`；候選答案為 2，`preMin[5] = 1` |

在 `r = 4` 時：

```text
索引：   0  1  2  3  4
數值：  [3,  2,  2,  4,  3]
第一段： [3]                 索引 0，長度 1
第二段：                  [3] 索引 4，長度 1

答案 = preMin[4] + 1 = 1 + 1 = 2
```

這裡的 `preMin[4]` 不是只記錄索引 3 的資料，而是記錄「所有右端點小於 4 的 target 子陣列」中最短的長度。前面在 `r = 0` 找到的 `[0, 0]` 長度為 1，之後雖然 `r = 1` 到 `r = 3` 沒有找到新的 target 視窗，這個最短值仍會一路被保存到 `preMin[4]`。因此當目前視窗 `[4, 4]` 成為第二段時，可以立即用左側最短的第一段配對。

換句話說，原案例看起來像「每次只往前一格」，是因為每次加入新元素後總和很快就超過 3，`l` 只好追上 `r`；實際的演算法仍然先擴張視窗，再視總和決定是否縮小。每個元素最多被 `r` 加入一次，也最多被 `l` 移除一次，所以整體時間複雜度仍然是 `O(n)`。

### 為什麼可以取最短前綴

對固定的第二段 `[l, r]`，第一段只能位於 `l` 左側。任何更長的第一段都不可能比 `preMin[l]` 更好，因此只需保留左側最短長度。

由左至右掃描時，每一個可能的右端點都會被處理；每次找到 target 視窗時，又都會與相容的左側最佳結果配對，所以所有可能的最佳配對都不會被漏掉。

### 複雜度

- 時間：`O(n)`。每個元素最多加入視窗一次、從視窗移除一次。
- 空間：`O(n)`，用於 `preMin`。

## 解法二：前後綴分解

實作：`Program.MinSumOfLengths2`

解法二把問題拆成兩個階段：先預處理每個右側區域的最佳結果，再由左至右尋找第一段。

### 狀態定義

令 `sufMin[i]` 表示：

> 所有左端點大於或等於 `i`、總和等於 `target` 的子陣列中，最短的長度。

當第一段是 `[left, r]` 時，第二段的左端點必須大於 `r`，所以可以查詢 `sufMin[r + 1]`：

```text
第一段 [left, r]       第二段的搜尋範圍
|---------------|      |-------------------|
                      r + 1              n - 1

候選答案 = (r - left + 1) + sufMin[r + 1]
```

### 第一階段：由右至左建立 `sufMin`

從右端點開始向左掃描，利用滑動視窗找出每個起點之後的 target 子陣列：

1. 將 `arr[l]` 加入視窗。
2. 若總和大於 `target`，移動右端點 `r`，縮小視窗。
3. 若總和等於 `target`，更新目前找到的最短長度。
4. 把目前的最短長度保存到 `sufMin[l]`。

程式只會處理 `l` 大於 0 的位置，因為第二階段限制第一段的右端點 `r < n - 1`，所以查詢的第二段起點 `r + 1` 至少是 1；`sufMin[0]` 不會被使用。

### 第二階段：由左至右尋找第一段

再次使用滑動視窗，由左至右枚舉第一段的右端點 `r`：

1. 找到總和等於 `target` 的第一段 `[left, r]`。
2. 查詢右側 `sufMin[r + 1]`。
3. 將第一段長度與右側最短長度相加，更新答案。

### 範例流程

以 `arr = [7, 3, 4, 7]`、`target = 7` 為例：

```text
索引：  0  1  2  3
數值： [7, 3, 4, 7]
        └────┘       [3,4] 也是 target 子陣列，但長度為 2
        [7]       [7]      兩個單元素子陣列長度總和為 2
```

右至左預處理：

| 起點 `l` | 找到的 target 子陣列 | 目前最短長度 | `sufMin[l]` |
|---:|---|---:|---:|
| 3 | `[3, 3]`，長度 1 | 1 | 1 |
| 2 | 沒有更短的區間 | 1 | 1 |
| 1 | `[1, 2]`，長度 2 | 1 | 1 |

左至右掃描時，第一個 `[0, 0]` 的長度為 1，右側查詢 `sufMin[1] = 1`：

```text
第一段：[7]       長度 1
第二段：         [7] 長度 1

候選答案 = 1 + sufMin[1] = 1 + 1 = 2
```

### 正確性說明

每組合法答案都能唯一按照陣列位置排序為左段與右段。前處理階段為每個可能的右側起點保存最短可行子陣列；掃描第一段時，`sufMin[r + 1]` 恰好涵蓋所有不與第一段重疊的第二段。

因此，對每個可行的第一段，演算法都會選到該右側區域的最佳配對，最後取所有配對的最小值即可得到全域最佳答案。

### 複雜度

- 時間：`O(n)`。右至左與左至右的滑動視窗各自線性掃描。
- 空間：`O(n)`，用於 `sufMin`。

## 兩種解法比較

| 項目 | 解法一 | 解法二 |
|---|---|---|
| 主要狀態 | `preMin[i]`：左側最短區間 | `sufMin[i]`：右側最短區間 |
| 配對方式 | 目前第二段 + 左側最佳第一段 | 目前第一段 + 右側最佳第二段 |
| 掃描方式 | 一次由左至右完成 | 先右至左，再左至右 |
| 時間複雜度 | `O(n)` | `O(n)` |
| 空間複雜度 | `O(n)` | `O(n)` |

兩種解法都依賴正整數陣列的單調性；差別主要在於將「已掃描區域的最佳結果」保存在左側或右側。
