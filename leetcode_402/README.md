## 題目說明

給定一個代表非負整數的字串 `num` 與整數 `k`，必須從 `num` 中移除恰好 `k` 位數字。剩餘數字的相對順序不能改變，目標是讓結果的數值盡可能小。

輸出以字串表示，不能包含前導零；若所有數字都被移除，或剩下的數字全部為零，則回傳 `"0"`。

題目來源：[LeetCode 402. Remove K Digits](https://leetcode.com/problems/remove-k-digits/description/)

### 限制條件

- `1 <= k <= num.length <= 10^5`
- `num` 僅由數字 `0` 到 `9` 組成。
- 除了 `"0"` 本身之外，`num` 不含前導零。

### 官方範例

| 輸入 | 輸出 | 說明 |
|---|---|---|
| `num = "1432219", k = 3` | `"1219"` | 移除 `4`、`3` 與其中一個 `2`。 |
| `num = "10200", k = 1` | `"200"` | 移除最高位 `1`，再去除結果的前導零。 |
| `num = "10", k = 2` | `"0"` | 所有位數都被移除，以 `"0"` 表示空結果。 |

## 解題概念與出發點

比較兩個長度相同、沒有前導零的數字時，第一個不同的位數決定大小。較小的數字越早出現在高位，整體數值就越小。

因此，當相鄰位數出現 `num[i] > num[i + 1]` 時：

- 保留 `num[i]` 會讓較大的數字繼續占據高位。
- 刪除 `num[i]` 可讓較小的 `num[i + 1]` 提前一位。
- 這是目前能取得的最大字典序改善，所以應優先刪除 `num[i]`。

如果整個序列都非遞減，例如 `"123456"`，找不到可以讓較小數字提前的下降位置。此時應刪除最後一位，因為尾端對數值大小的影響最小。

兩種解法都遵守這個貪心選擇：

1. 直觀模擬每刪除一位就重新尋找下降位置。
2. 單調堆疊在一次掃描中維持同樣的判斷，避免重複走訪。

## 解法一：單調遞增堆疊

`RemoveKdigits` 使用 `StringBuilder` 模擬堆疊，讓已處理的數字盡量保持非遞減。

### 設計步驟

1. 建立空堆疊，並以 `remainingRemovals` 記錄尚可刪除的位數。
2. 由左向右讀取每個數字 `digit`。
3. 當堆疊非空、仍有刪除額度，且堆疊頂端大於 `digit` 時：
   - 刪除堆疊頂端。
   - 將刪除額度減一。
   - 繼續比較新的堆疊頂端，因為目前數字可能一次取代多個較大的高位。
4. 將 `digit` 放入堆疊。
5. 掃描結束後若仍有刪除額度，代表結果一路非遞減，從尾端刪除剩餘位數。
6. 略過前導零；若沒有非零數字，回傳 `"0"`。

### 為什麼正確

當堆疊頂端 `x` 大於目前數字 `y` 時，刪除 `x` 會讓較小的 `y` 提前到更高位。任何保留 `x` 而改刪後方數字的方案，在第一個不同位置仍會保留較大的 `x`，因此不可能產生更小結果。

堆疊反覆套用這個選擇，會得到所有合法保留序列中字典序最小的前綴。若最後仍需刪除數字，當前序列必為非遞減；此時刪除越靠後的數字越不影響高位，所以從尾端刪除最佳。最後去除前導零只改變字串表示，不改變數值。

### 範例演示：`"1432219", k = 3`

| 讀入數字 | 操作 | 堆疊 | 剩餘刪除數 |
|---|---|---|---:|
| `1` | 直接加入 | `1` | 3 |
| `4` | `1 <= 4`，直接加入 | `14` | 3 |
| `3` | `4 > 3`，彈出 `4` 後加入 `3` | `13` | 2 |
| `2` | `3 > 2`，彈出 `3` 後加入 `2` | `12` | 1 |
| `2` | 頂端等於 `2`，直接加入 | `122` | 1 |
| `1` | `2 > 1`，彈出一個 `2` 後加入 `1` | `121` | 0 |
| `9` | 已無刪除額度，直接加入 | `1219` | 0 |

最終堆疊為 `"1219"`，沒有前導零，因此直接回傳 `"1219"`。

### 複雜度

- **時間複雜度：`O(n)`**
  - 每個數字最多加入堆疊一次、彈出一次。
  - 正規化結果最多再掃描一次。
- **額外空間複雜度：`O(n)`**
  - 最壞情況下堆疊保存全部輸入數字。
- **輸出空間：`O(n - k)`**
  - 回傳字串最多包含 `n - k` 位。

## 解法二：直觀貪心模擬

`RemoveKdigits2` 直接模擬「每次刪除第一個下降位置」的想法。這個版本容易理解，但每刪除一位都要重新掃描目前字串，只適合作為教學基準或處理小型輸入。

### 設計步驟

1. 將輸入複製到可刪除字元的 `StringBuilder`。
2. 重複以下流程 `k` 次：
   - 由左向右尋找第一個 `digits[i] > digits[i + 1]`。
   - 找到時刪除 `digits[i]`，讓右側較小數字提前。
   - 若整個序列都非遞減，刪除最後一位。
3. 刪除完成後略過前導零。
4. 若結果為空或全部為零，回傳 `"0"`。

### 為什麼正確

每一輪的第一個下降位置，是目前字串中最早可以讓較小數字前移的位置。若不刪除該位而刪除更後面的數字，結果在這個較早位置仍保留較大的數字，因此一定不會更小。

若不存在下降位置，字串已非遞減。刪除中間任何數字都會讓更大的後繼數字提前，而刪除尾端不會改變任何更高位，所以尾端是最佳刪除位置。每輪都做出當前最佳選擇，重複 `k` 次即可得到全域最小結果。

### 範例演示：`"1432219", k = 3`

1. `"1432219"` 的第一個下降位置是 `4 > 3`，刪除 `4`：
   - 結果變成 `"132219"`。
2. `"132219"` 的第一個下降位置是 `3 > 2`，刪除 `3`：
   - 結果變成 `"12219"`。
3. `"12219"` 的第一個下降位置是第二個 `2 > 1`，刪除該 `2`：
   - 結果變成 `"1219"`。
4. 已完成三次刪除，且結果沒有前導零：
   - 回傳 `"1219"`。

### 複雜度

- **時間複雜度：`O(k * n)`**
  - 每輪可能掃描目前字串一次。
  - `StringBuilder.Remove` 也可能搬移其後字元。
  - 當 `k` 與 `n` 同階時，最壞可達 `O(n^2)`。
- **額外空間複雜度：`O(n)`**
  - 使用一份可修改的輸入副本。
- **輸出空間：`O(n - k)`**
  - 回傳字串最多包含 `n - k` 位。

> [!NOTE]
> 題目允許 `num.length` 達到 `10^5`。提交到線上評測時應優先使用解法一；解法二用來呈現未最佳化前的直接貪心思路。

## 兩種解法比較

| 比較項目 | 解法一：單調遞增堆疊 | 解法二：直觀貪心模擬 |
|---|---|---|
| 公開 API | `RemoveKdigits` | `RemoveKdigits2` |
| 核心想法 | 一次掃描時立即移除較大的高位 | 每輪重新尋找第一個下降位置 |
| 時間複雜度 | `O(n)` | `O(k * n)`，最壞 `O(n^2)` |
| 額外空間 | `O(n)` | `O(n)` |
| 優點 | 能處理題目上限，效率穩定 | 流程直觀，適合理解貪心選擇 |
| 適用情境 | 正式解答與大型輸入 | 教學、驗證概念與小型輸入 |
