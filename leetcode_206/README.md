# LeetCode 206 - Reverse Linked List

![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4)
![Language](https://img.shields.io/badge/language-C%23-239120)

這個專案是 [LeetCode 206「Reverse Linked List」](https://leetcode.com/problems/reverse-linked-list/) 的 C# Console 教學範例。程式保留兩種迭代寫法，從不同角度說明如何原地反轉單向鏈結串列，並在 `Main` 中執行固定案例驗證結果。

## 題目說明

給定單向鏈結串列的頭節點 `head`，將整條鏈結串列反轉，並回傳反轉後的新頭節點。

例如：

```text
輸入：1 → 2 → 3 → 4 → 5 → null
輸出：5 → 4 → 3 → 2 → 1 → null
```

反轉的是每個節點的 `next` 指向，不需要建立另一份包含相同資料的新鏈結串列。

## 限制條件

- 鏈結串列的節點數量介於 `0` 與 `5000` 之間。
- `-5000 <= Node.val <= 5000`。
- `head` 可以是 `null`，代表空鏈結串列。
- 節點值可以重複；反轉只改變節點順序，不改變節點值。

## 解題概念與出發點

單向鏈結串列的節點只知道「下一個節點」，不知道「上一個節點」。假設目前位於節點 `curr`：

```text
prev ← curr → next
```

若直接執行 `curr.next = prev`，原本由 `curr.next` 指向的剩餘串列就會失去參考。因此，每一輪都必須按照以下順序處理：

1. 先保存原本的下一個節點。
2. 將目前節點的 `next` 改為指向已反轉區段。
3. 更新已反轉區段的頭。
4. 移動到剛才保存的下一個節點。

兩個解法執行的指標操作本質相同，但命名與觀察角度不同：

- 解法一把過程視為「從原串列逐節點拆下，接到新串列頭部」。
- 解法二明確使用 `prev`、`curr`、`next`，把串列分為已反轉與尚未處理兩個區段。

> [!IMPORTANT]
> 兩個方法都會原地修改傳入節點的 `next`。範例 runner 因此會為每個解法重新建立獨立串列，避免第一個解法的修改影響第二個解法。

## 解法一：逐節點接到新頭部

### 設計說明

`ReverseList` 使用兩個主要參考：

- `head`：目前尚未處理區段的第一個節點。
- `root`：已反轉區段的新頭節點，初始為 `null`。

每輪先把 `head.next` 保存到 `next`，再將 `head` 接到 `root` 前方。完成後，`root` 更新為目前節點，而 `head` 移動到 `next`。

迴圈期間維持以下不變量：

- `root` 指向已反轉完成的所有節點。
- `head` 指向下一個待處理節點。
- 已反轉區段最後一個節點的 `next` 正確指向 `null`。

當 `head` 成為 `null`，所有節點都已移到反轉區段，`root` 就是答案。

### 範例演示

輸入：

```text
1 → 2 → 3 → null
```

| 階段 | 暫存 `next` | 反轉後的 `root` | 尚未處理的 `head` |
| --- | --- | --- | --- |
| 初始 | 尚未建立 | `null` | `1 → 2 → 3 → null` |
| 第 1 輪 | `2` | `1 → null` | `2 → 3 → null` |
| 第 2 輪 | `3` | `2 → 1 → null` | `3 → null` |
| 第 3 輪 | `null` | `3 → 2 → 1 → null` | `null` |

最後回傳 `root`：

```text
3 → 2 → 1 → null
```

### 正確性直覺

每一輪只把一個節點從尚未處理區段移到已反轉區段的最前方，且移動前會保存下一個節點，因此不會遺失剩餘串列。當尚未處理區段為空時，每個原始節點恰好被移動一次，順序也恰好完全反轉。

### 複雜度

- 時間複雜度：`O(n)`，每個節點只處理一次。
- 額外空間複雜度：`O(1)`，只使用固定數量的節點參考。

## 解法二：prev、curr、next 三指標

### 設計說明

`ReverseList2` 明確將三個角色分開：

- `prev`：已反轉區段的頭節點，初始為 `null`。
- `curr`：本輪要反轉指向的節點，初始為原本的 `head`。
- `next`：暫存 `curr` 原本的下一個節點。

每一輪依序執行：

1. `next = curr.next`：保留尚未處理區段。
2. `curr.next = prev`：反轉目前節點的指向。
3. `prev = curr`：擴大已反轉區段。
4. `curr = next`：前進到下一個待處理節點。

當 `curr` 為 `null`，`prev` 便指向反轉後的完整串列。

### 範例演示

輸入：

```text
1 → 2 → 3 → null
```

| 階段 | `prev` | `curr` | 保存的 `next` | 本輪完成後 |
| --- | --- | --- | --- | --- |
| 初始 | `null` | `1` | 尚未建立 | 尚未反轉 |
| 第 1 輪 | `1` | `2` | `2` | `1 → null` |
| 第 2 輪 | `2` | `3` | `3` | `2 → 1 → null` |
| 第 3 輪 | `3` | `null` | `null` | `3 → 2 → 1 → null` |

最後回傳 `prev`：

```text
3 → 2 → 1 → null
```

### 正確性直覺

迴圈開始時，`prev` 永遠是已正確反轉區段的頭，`curr` 則是尚未處理區段的頭。每輪把 `curr` 接到 `prev` 前方後，再讓兩者向前推進一格，因此不變量持續成立。迴圈結束時尚未處理區段為空，`prev` 就涵蓋全部節點。

### 複雜度

- 時間複雜度：`O(n)`，每個節點只處理一次。
- 額外空間複雜度：`O(1)`，只使用 `prev`、`curr`、`next` 等固定參考。

## 兩種解法比較

| 比較項目 | 解法一：接到新頭部 | 解法二：三指標 |
| --- | --- | --- |
| 核心命名 | `head`、`root`、`next` | `prev`、`curr`、`next` |
| 思考方式 | 把目前節點拆下並接到新頭 | 維護前、中、後三個位置 |
| 是否原地修改 | 是 | 是 |
| 時間複雜度 | `O(n)` | `O(n)` |
| 額外空間複雜度 | `O(1)` | `O(1)` |
| 空串列結果 | `null` | `null` |

兩種寫法都符合題目要求。解法一適合從「建立反轉區段」理解；解法二的命名更接近常見教材與面試解法。

## 邊界情況

### 空鏈結串列

`head` 一開始就是 `null`，迴圈不會執行，方法直接回傳 `null`。

```text
[] → []
```

### 單一節點

唯一節點的 `next` 原本就是 `null`。執行一輪後仍回傳同一節點。

```text
[1] → [1]
```

### 重複值與負值

演算法只調整節點參考，不比較或修改節點值，因此重複值與負值不需要特殊處理。

```text
[-1, 2, 2, 0] → [0, 2, 2, -1]
```
