## 題目說明

樓梯共有 `n + 1` 階，編號為 `0..n`，從第 `0` 階出發，起始費用是 `0`。每次只能向前跳 `1`、`2` 或 `3` 階，且必須恰好抵達第 `n` 階。

從第 `i` 階跳到第 `j` 階，需要支付：

```text
落點階梯的費用 + 跳躍距離的平方
costs[j] + (j - i)^2       （題目的 1-based 表示法）
costs[j - 1] + (j - i)^2   （實際 C# 陣列表示法）
```

跳過的階梯不收費，起點不收費；目標是回傳最小總費用。

### 限制與索引

- `1 <= n == costs.Length <= 100000`。
- `1 <= costs[i] <= 10000`。
- 所有解法均假設輸入符合題目限制，不額外檢查 `null`、長度不符或無效數值。

```text
階梯編號       0      1      2      3      4
落點費用       0      1      2      3      4
C# 陣列索引    -      0      1      2      3
                     costs = [1, 2, 3, 4]

任一階梯 i 的合法方向（目的地不得超過 n）：
  i --(+1，平方費用 1)--> i+1
  i --(+2，平方費用 4)--> i+2
  i --(+3，平方費用 9)--> i+3
每條箭頭還要另外加上目的階梯費用。
```

### 官方範例

| 範例 | n | costs | 最小費用 | 一條最佳路徑 |
| --- | --- | --- | --- | --- |
| 一 | 4 | `[1, 2, 3, 4]` | 13 | `0 → 1 → 2 → 4` |
| 二 | 4 | `[5, 1, 6, 2]` | 11 | `0 → 2 → 4` |
| 三 | 3 | `[9, 8, 3]` | 12 | `0 → 3` |

範例一的費用是 `(1+1) + (2+1) + (4+4) = 13`：

```text
[0] --1階/費用2--> [1] --1階/費用3--> [2] --2階/費用8--> [4]
                                                跳過 [3]
累計 0              2                 5                  13
```

範例二是 `(1+4) + (2+4) = 11`；範例三是 `3+9 = 12`。

上述路徑用於說明答案。三個公開方法均只回傳 `int` 最小費用，沒有重建或回傳路徑。

## 共同推導：從最後一步出發

### 為何不能只看眼前費用？

最便宜的下一步未必通往整段路徑的最低費用。例如 `costs = [1, 2, 3, 4]`，若每次挑選當次支出最少的一跳，會連續走一階，總費用 `2+3+4+5 = 14`；最佳路徑最後從第 `2` 階直接跳到第 `4` 階，總費用為 `13`。需要同時比較「之前已付多少」與「這次要付多少」。

### 狀態、轉移與邊界

令 `f[k]` 表示從第 `0` 階到第 `k` 階的最小總費用。起點是 `f[0] = 0`。若最後一跳長度為 `d`，則前驅是 `k-d`：

```text
f[k] = costs[k-1] + min(f[k-d] + d*d)
                     其中 1 <= d <= min(3, k)

等價的前驅形式：
f[k] = costs[k-1] + min(f[j] + (k-j)^2)
                     max(0, k-3) <= j < k
```

```text
f[k-3] -- +9 --\
f[k-2] -- +4 ---+--> 取最小值 --> + costs[k-1] --> f[k]
f[k-1] -- +1 --/
只考慮編號 >= 0 的前驅。
```

所有候選最後都落在同一階，因此可以先選最小前驅支出，再統一加一次落點費用。小階數不可讀取負索引：第 `1` 階只有前驅 `0`，第 `2` 階只有前驅 `0、1`。

正確性的關鍵是：每條到達 `k` 的路徑必定來自上述合法前驅。對固定前驅而言，若之前的路徑不是最小費用，就能換成更便宜的路徑而不影響最後一跳。因此逐一比較「前驅最佳費用 + 最後一跳費用」，既涵蓋所有可能，也能取得最佳答案。

以下三種解法的差別是計算順序與保存狀態的方式，並非不同的轉移公式。

## 解法一：滾動變數 `ClimbStairs`

### 「前三階」是哪些階梯？

計算第 `k` 階的最低總費用時，只需要知道它前面最近三階，也就是第 `k-3、k-2、k-1` 階的最低總費用。因為每次只能跳 `1、2、3` 階，最後一跳只能從這三個位置出發。

**「前三階」的位置會隨著目前計算的階梯往前移動，並非固定指最初的第 1、2、3 階。**

| 目前要計算的階梯 | 最後一跳可能的出發位置 |
| --- | --- |
| 第 4 階 | 第 1、2、3 階 |
| 第 5 階 | 第 2、3、4 階 |
| 第 n 階（終點） | 第 n-3、n-2、n-1 階中，編號不小於 0 的位置 |

所以「終點的前三階」適用於最後一輪；整個迴圈則是從第 `1` 階一路計算到第 `n` 階。第 `1、2` 階的合法前驅較少，稍後會說明初始化如何處理。

### 為什麼要加上 9、4、1？

題目的單次跳躍費用是 `costs[j] + (j-i)²`，其中 `i` 是出發階梯，`j` 是目的階梯。以目的地固定為第 `4` 階（`j = 4`）為例：

| 出發階梯 i | 目的階梯 j | 跳躍距離 j-i | 平方費用 (j-i)² |
| --- | --- | --- | --- |
| 1 | 4 | `4-1 = 3` | `3² = 3 × 3 = 9` |
| 2 | 4 | `4-2 = 2` | `2² = 2 × 2 = 4` |
| 3 | 4 | `4-3 = 1` | `1² = 1 × 1 = 1` |

**跳躍距離是 `3、2、1`；程式加上的 `9、4、1`，是這些距離的平方。** C# 陣列從索引 `0` 開始，第 `4` 階的落點費用因此存於 `costs[3]`。

再區分兩種費用：`f[k]` 是從起點到第 `k` 階的「累積最低總費用」，`costs[k-1]` 則只是第 `k` 階本身的「落點費用」。例如，經由第 `1` 階再跳到第 `4` 階：

```text
總費用 = 到第 1 階已付的最低費用 + 最後一跳的費用
       = f[1] + ((4-1)² + costs[3])
       = f[1] + 9 + costs[3]
         └─┘   │   └──────┘
       累積費用 跳距平方 落點費用
```

三個候選完整寫出來就是：

```text
從第 1 階來：f[1] + (4-1)² + costs[3] = f[1] + 9 + costs[3]
從第 2 階來：f[2] + (4-2)² + costs[3] = f[2] + 4 + costs[3]
從第 3 階來：f[3] + (4-3)² + costs[3] = f[3] + 1 + costs[3]

f[4] = min(f[1] + 9, f[2] + 4, f[3] + 1) + costs[3]
```

三個候選的落點相同，所以先取最小值，再統一加一次落點費用。

### 對應到 a、b、c 與 next

每一輪只需要最近三個狀態，不必保留完整陣列。程式用 `a、b、c` 保存它們，並用 `next` 保存目前這一階的新答案。

注意：**題目公式中的 `i` 表示出發階梯，程式迴圈的 `i` 則是陣列索引，兩者用途不同。** 程式目前計算的目的階梯為 `k = i + 1`，落點費用是 `costs[i] = costs[k-1]`。當三個前驅都合法時，計算前的變數意義為：

| 變數 | 對應狀態 | 到目的地的跳距 |
| --- | --- | --- |
| `a` | `f[k-3]` | 3，平方為 9 |
| `b` | `f[k-2]` | 2，平方為 4 |
| `c` | `f[k-1]` | 1，平方為 1 |

```csharp
int next = Math.Min(Math.Min(a + 9, b + 4), c + 1) + costs[i];
```

這行先比較「前驅的累積最低費用 + 這次跳躍的平方費用」，再加上目前階梯的落點費用。巢狀的 `Math.Min` 只是用來取三個候選的最小值。

### 算完一階後，如何移動視窗？

先用舊的 `a、b、c` 算出 `next`，再依序更新：

```csharp
a = b;
b = c;
c = next;
```

`a = b` 是把當下 `b` 的數值複製給 `a`，不會讓兩個變數永久綁定；之後 `b` 改變，`a` 不會跟著改變。三行由上往下依序執行，因此 `a` 接收舊的 `b`、`b` 接收舊的 `c`，最後 `c` 接收剛算好的 `next`。

**`a、b、c` 只在進入迴圈前初始化為 `0`，下一輪會沿用這一輪更新後的值，不會重新歸零。** 新答案先存進 `c`，之後也會逐輪移到 `b` 和 `a`，供後續計算使用。

以剛算完第 `4` 階、準備算第 `5` 階為例：

```text
計算第 4 階前：a = f[1]，b = f[2]，c = f[3]
算出新答案：  next = f[4]

a = b;       → a 保存舊的 f[2]
b = c;       → b 保存舊的 f[3]
c = next;    → c 保存新的 f[4]

計算第 5 階前：a = f[2]，b = f[3]，c = f[4]
```

變數名稱維持不變，但代表的階梯持續往前移動。必須先算好 `next` 再更新；若太早覆寫，就會混用不同階數的資料。迴圈結束後 `c` 即為 `f[n]`，因此回傳 `c`。

### 為什麼 a、b、c 都能初始化為 0？

程式將 `a、b、c` 都初始化為 `0`。前兩個起始位置是虛擬狀態，並不代表可以從負階梯出發：

- 計算第 `1` 階時，三個候選為 `9、4、1`，合法的 `f[0]+1` 必定勝出。
- 計算第 `2` 階時，唯一仍虛擬的候選是 `0+9`，合法的 `f[0]+4 = 4` 更小。
- 從第 `3` 階開始，三個變數全都代表合法狀態。

所以這份初始化不會選中非法前驅；它依賴本題固定跳距平方，不宜直接套用到其他轉移成本。

### 範例演示與 ASCII 視窗

使用 `costs = [1, 2, 3, 4]`，`k = i + 1` 是本輪要計算的階梯。「本輪開始」表示尚未執行本輪的三行賦值，但已經沿用上一輪更新後的結果。三個候選依序為 `a+9、b+4、c+1`；`next` 則是「最小候選值 + 本階落點費用 `costs[k-1]`」。

| k | 本輪開始 `(a,b,c)` | 三個候選的完整算式 | next | 更新後 `(a,b,c)` |
| --- | --- | --- | --- | --- |
| 1 | `(0,0,0)` | `0+9=9、0+4=4、0+1=1` | `1+1=2` | `(0,0,2)` |
| 2 | `(0,0,2)` | `0+9=9、0+4=4、2+1=3` | `3+2=5` | `(0,2,5)` |
| 3 | `(0,2,5)` | `0+9=9、2+4=6、5+1=6` | `6+3=9` | `(2,5,9)` |
| 4 | `(2,5,9)` | `2+9=11、5+4=9、9+1=10` | `9+4=13` | `(5,9,13)` |

**每列的「更新後」，就是下一列的「本輪開始」。** 例如第 1 輪把 `c` 更新為 `2`，所以第 2 輪的 `c+1` 就變成 `2+1=3`。

把第 1 輪到第 2 輪之間的執行過程展開來看：

```csharp
// 第 1 輪開始：a = 0、b = 0、c = 0，costs[0] = 1。
int next = Math.Min(Math.Min(a + 9, b + 4), c + 1) + costs[0];
// next = min(9, 4, 1) + 1 = 2。

a = b;     // a = 0，複製當下 b 的值。
b = c;     // b = 0，複製當下 c 的值。
c = next;  // c = 2，保存這一輪的新答案。

// 第 2 輪開始：沿用 a = 0、b = 0、c = 2，costs[1] = 2。
next = Math.Min(Math.Min(a + 9, b + 4), c + 1) + costs[1];
// 三個候選是 0+9=9、0+4=4、2+1=3。
// next = min(9, 4, 3) + 2 = 5。

a = b;     // a = 0。
b = c;     // b = 2。
c = next;  // c = 5，下一輪便從 (0,2,5) 開始。
```

再用 ASCII 視窗回顧完整四輪：

```text
初始    [a=0, b=0, c=0]
算第1階       | next=2
更新    [a=0, b=0, c=2]
算第2階       | next=5
更新    [a=0, b=2, c=5]
算第3階       | next=9
更新    [a=2, b=5, c=9]
算第4階       | next=13
更新    [a=5, b=9, c=13] --> 回傳 13
```

每階只做固定次數的比較：時間 `O(n)`，額外空間 `O(1)`。此寫法適合只需要最小費用的情境。

## 解法二：記憶化搜尋 `ClimbStairs2`

### 設計與快取

將共同狀態寫成 `Dfs(i)`：要求第 `i` 階答案，就先要求合法前驅的答案，直到 `Dfs(0) = 0`。程式依 `j = max(i-3, 0)..i-1` 的順序搜尋。

**`Dfs(i)` 表示「從第 0 階到第 i 階的最低總費用」，不是從第 i 階到終點的剩餘費用。** 向較小階梯遞迴，是先取得計算所需的前驅答案；實際爬樓梯的方向仍是由前驅往第 `i` 階跳。

同一個階梯會被不同分支重複詢問。使用長度 `n+1` 的 `memo` 保存結果：首次遇到時計算並寫入，之後直接回傳。每次呼叫 `ClimbStairs2` 都重新配置快取，不讓其他輸入的答案污染本次結果。

`memo[i] == 0` 表示未計算，因為有效輸入下落點費用與跳距平方都為正，任何非起點狀態的答案必定大於 `0`。起點則在查快取之前直接回傳 `0`。

### i、j、res 與 memo 各自保存什麼？

| 名稱 | 意義 |
| --- | --- |
| `i` | 這次呼叫要求答案的目的階梯 |
| `j` | 最後一跳的出發階梯，範圍為 `max(i-3, 0)..i-1` |
| `Dfs(j, costs, memo)` | 從起點到前驅 `j` 已付的最低總費用 |
| `(i-j) * (i-j)` | 從 `j` 跳到 `i` 的距離平方，即 `9、4、1` 中的合法項目 |
| `res` | 迴圈內保存目前最小的「前驅費用＋跳距平方」；迴圈後加上落點費用，才是本階完整答案 |
| `memo[i]` | 已完成的第 `i` 階最低總費用；保存數值，不保存行走路徑 |

以下是 `Dfs` 的核心流程，與程式實作相同，依執行順序加上說明：

```csharp
// 1. 起點沒有費用，直接返回，不必查詢或寫入快取。
if (i == 0)
{
    return 0;
}

// 2. 這一階已經算過，就直接回傳，不再搜尋前驅。
if (memo[i] != 0)
{
    return memo[i];
}

// 3. 尚未取得任何候選，先用最大值作為比較起點。
int res = int.MaxValue;
for (int j = Math.Max(i - 3, 0); j < i; j++)
{
    // 先等 Dfs(j) 回傳，再比較「前驅最低費用＋跳距平方」。
    res = Math.Min(res, Dfs(j, costs, memo) + ((i - j) * (i - j)));
}

// 4. 各候選都落在第 i 階，統一加上 costs[i - 1]。
res += costs[i - 1];
// 5. 保存完整答案，讓之後的呼叫可以直接重用。
memo[i] = res;
return res;
```

每個非起點至少有合法前驅 `i-1`，所以迴圈一定會取得候選並取代 `int.MaxValue`。落點費用在迴圈外加一次，即可避免與「已付的累積費用」混淆。

### 遞迴如何暫停、返回與繼續？

以 `n = 7` 的新一次呼叫為例，按照程式先搜尋最小合法前驅的順序，最初會出現以下依賴鏈；這裡只畫局部流程，不代表完整搜尋：

```text
Dfs(7)：i=7、j=4，等待 Dfs(4) 的答案
  Dfs(4)：i=4、j=1，等待 Dfs(1) 的答案
    Dfs(1)：i=1、j=0，等待 Dfs(0) 的答案
      Dfs(0)：回傳 0
    Dfs(1)：比較 0+1，加上 costs[0]，寫入 memo[1] 並回傳
  Dfs(4)：用剛取得的 memo[1]+9 更新 res，再繼續 j=2、3
          等所有候選比較完，加上 costs[3]，寫入 memo[4] 並回傳
Dfs(7)：用剛取得的 memo[4]+9 更新 res，再繼續 j=5、6
        等所有候選比較完，加上 costs[6]，寫入 memo[7] 並回傳
```

**每次呼叫都有自己的 `i、j、res`，但同一次搜尋共用同一份 `memo`。** 子呼叫的區域變數不會覆寫父呼叫的區域變數；父呼叫暫停在需要子答案的運算式，等子呼叫回傳後，才更新自己的 `res` 並繼續下一個前驅。

### 範例演示與 ASCII 呼叫流程

仍使用 `[1, 2, 3, 4]`。以下依實際前驅遍歷順序展開；`hit` 是讀取先前已完成的快取：

```text
Dfs(4)
+-- Dfs(1)
|   +-- Dfs(0) = 0
|   `-- memo[1] = 0+1+1 = 2
+-- Dfs(2)
|   +-- Dfs(0) = 0
|   +-- Dfs(1) = 2 [hit]
|   `-- memo[2] = min(0+4, 2+1)+2 = 5
+-- Dfs(3)
|   +-- Dfs(0) = 0
|   +-- Dfs(1) = 2 [hit]
|   +-- Dfs(2) = 5 [hit]
|   `-- memo[3] = min(0+9, 2+4, 5+1)+3 = 9
`-- memo[4] = min(2+9, 5+4, 9+1)+4 = 13

memo: [0, 2, 5, 9, 13] --> 回傳 13
```

`memo[0]` 仍為預設值，起點不需要寫入快取。雖然從目標開始發問，每個狀態仍須等待前驅算好才能完成。

例如 `Dfs(4)` 的第一個分支已算出 `memo[1] = 2`。之後計算 `Dfs(2)` 時再次詢問 `Dfs(1)`，便在快取判斷處直接回傳 `2`，不再呼叫 `Dfs(0)`、比較候選或重寫答案。重複呼叫仍會發生，但相同非起點狀態的完整計算只做一次。

每個非起點狀態最多計算一次，每次最多三個前驅，時間 `O(n)`。快取占 `O(n)`，最壞呼叫堆疊也占 `O(n)`，合計額外空間仍為 `O(n)`。

> [!NOTE]
> 大 `n` 時，遞迴可能受執行環境的堆疊限制影響。本次環境通過 `n = 100000` 的測試，不代表所有平台與組態皆可承受相同深度；大量資料可使用解法一或解法三。

## 解法三：陣列遞推 `ClimbStairs3`

### 從遞迴轉成迴圈

所有前驅編號都小於目前階梯，故按 `1..n` 由小到大計算即可，無須由遞迴安排依賴：

| 記憶化搜尋 | 陣列遞推 |
| --- | --- |
| `Dfs(0) = 0` | `f[0] = 0`，使用陣列預設值 |
| 呼叫 `Dfs(j)` | 直接讀取已完成的 `f[j]` |
| 寫入 `memo[i]` | 寫入 `f[i]` |
| 要求 `Dfs(n)` | 迴圈結束回傳 `f[n]` |

每一階以 `res = int.MaxValue` 開始，從合法前驅取最小支出，再加上 `costs[i-1]`。每階至少有前驅 `i-1`，因此在加落點費用前，`res` 一定已被有效候選取代，不會拿 `int.MaxValue` 直接相加。

### 兩層迴圈與 res 的更新範圍

外層的 `i` 是目前要計算的目的階梯，從 `1` 走到 `n`；內層的 `j` 則枚舉最後一跳的出發階梯。`Math.Max(i - 3, 0)` 避免負階梯，`j < i` 確保只使用較小階梯的答案：

```csharp
int[] f = new int[n + 1]; // f[0] = 0，另保留第 1..n 階的答案。
for (int i = 1; i <= n; i++)
{
    int res = int.MaxValue; // 每一階重新開始比較候選。
    for (int j = Math.Max(i - 3, 0); j < i; j++)
    {
        // f[j] 已在之前的外層迴圈算好；第 0 階則使用初始值 0。
        res = Math.Min(res, f[j] + ((i - j) * (i - j)));
    }

    f[i] = res + costs[i - 1]; // 補上本階落點費用，保存完整答案。
}

return f[n];
```

開始計算第 `i` 階時，`f[0..i-1]` 都已有正確答案，而內層只會讀取其中最近的最多三格。因此未計算格子的預設值 `0` 不會被拿來當候選，也不需要像解法二那樣用數值判斷是否算過。

**`res` 只負責目前這一階的比較，每進入下一輪外層迴圈都重新初始化；之前各階的完整答案則持續保存在 `f`。** 若沿用上一階的 `res`，它可能來自不符合本階跳距的候選，不能代表本階的最低支出。

### 範例演示與 ASCII 填表

| 階梯 i | 合法前驅 j | 前驅費用加跳距平方 | `costs[i-1]` | f[i] |
| --- | --- | --- | --- | --- |
| 1 | 0 | `0+1=1` | 1 | 2 |
| 2 | 0, 1 | `0+4=4, 2+1=3` | 2 | 5 |
| 3 | 0, 1, 2 | `0+9=9, 2+4=6, 5+1=6` | 3 | 9 |
| 4 | 1, 2, 3 | `2+9=11, 5+4=9, 9+1=10` | 4 | 13 |

把第 `4` 階的內層迴圈單獨展開，便能看出 `res` 如何保留目前最小值：

| 執行位置 | 本次候選 | 更新後的 res |
| --- | --- | --- |
| 本階開始 | 尚未比較 | `int.MaxValue` |
| `j = 1` | `f[1] + (4-1)² = 2+9 = 11` | `min(int.MaxValue, 11) = 11` |
| `j = 2` | `f[2] + (4-2)² = 5+4 = 9` | `min(11, 9) = 9` |
| `j = 3` | `f[3] + (4-3)² = 9+1 = 10` | `min(9, 10) = 9` |

內層結束後才計算 `f[4] = res + costs[3] = 9+4 = 13`。表中的 `res = 9` 尚未包含第 `4` 階的落點費用，不可直接當作 `f[4]`。

```text
階梯         0   1   2   3   4
初始 f      [0,  0,  0,  0,  0]  未計算格的 0 不會被讀取
完成 i=1    [0,  2,  0,  0,  0]
完成 i=2    [0,  2,  5,  0,  0]
完成 i=3    [0,  2,  5,  9,  0]
完成 i=4    [0,  2,  5,  9, 13] --> 回傳 f[4]

計算第4階：
f[1]=2 -- +9 --> 11 --\
f[2]=5 -- +4 -->  9 ---+--> min=9 --> +costs[3]=4 --> 13
f[3]=9 -- +1 --> 10 --/
```

雖然程式有兩層迴圈，內層的執行次數不會隨 `i` 一直增加：第 `1` 階檢查一次、第 `2` 階檢查兩次，之後每階都只檢查三次。總轉移次數最多 `3n`，因此時間為 `O(n)`，而非 `O(n²)`；保存 `n+1` 格，額外空間為 `O(n)`。

這個版本保留完整費用表，適合學習與除錯。計算第 `i` 階時，只有 `f[i-3]、f[i-2]、f[i-1]` 中的合法狀態會被讀取；更早的狀態已不會再用到。將這三格分別存入解法一的 `a、b、c`，算完後再向前移動，就能把空間降為 `O(1)`。解法一前兩輪的虛擬狀態初始化，則依該節的說明處理。

## 解法比較與數值範圍

| 方法 | 計算方式 | 時間 | 額外空間 | 特點 |
| --- | --- | --- | --- | --- |
| `ClimbStairs` | 由前往後、三個滾動變數 | O(n) | O(1) | 空間最省；需理解視窗與初始化 |
| `ClimbStairs2` | 由目標遞迴、快取結果 | O(n) | O(n) | 直接表達依賴；有堆疊深度限制 |
| `ClimbStairs3` | 由前往後、完整陣列 | O(n) | O(n) | 狀態明確，沒有遞迴堆疊 |

逐次走一階一定合法，每步最多 `10000+1`，故最小總費用不超過 `100000 * 10001 = 1000100000`，小於 `int.MaxValue = 2147483647`。中間候選最多在前驅最小費用上加 `9`，即使再加落點費用 `10000`，使用此寬鬆上界也仍在 `int` 範圍內。

最大階數且所有落點費用為 `10000` 的固定案例，最佳費用為 `333639996`：可用 `33332` 次三階跳與兩次兩階跳抵達，費用是 `33332 * 10009 + 2 * 10004`。至少需要 `33334` 跳；在這個跳數下，兩次二階跳比一次一階跳更便宜。也可用下界證明最優：每個跳距 `d ∈ {1,2,3}` 都滿足 `d² >= 5d-6`，故跳 `m` 次的總費用至少為 `10000m + 5n - 6m = 9994m + 5n`。這個下界隨 `m` 增加，在 `m = 33334` 時恰好是 `333639996`，而上述路徑達到下界。
