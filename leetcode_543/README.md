## 題目說明

給定一棵二元樹的根節點 `root`，回傳這棵樹的直徑長度。

二元樹的直徑是樹中任意兩個節點之間最長路徑的長度。路徑可以經過根節點，也可以完全位於某棵子樹內；長度以兩個節點之間的**邊數**計算，而不是節點數。

例如，對二元樹 `[1,2,3,4,5]`，路徑 `4 → 2 → 1 → 3` 包含 3 條邊，因此答案為 `3`。

題目連結：[LeetCode 543. Diameter of Binary Tree](https://leetcode.com/problems/diameter-of-binary-tree/)

## 限制條件

- 樹中的節點數介於 `1` 與 `10^4` 之間。
- `-100 <= Node.val <= 100`。
- 節點值不影響直徑；演算法只使用樹的連接結構。
- 題目保證至少有一個節點，但本專案的 `DiameterOfBinaryTree` 也能接受 `null`，並回傳 `0`。

## 解題概念與出發點

若只計算 `root.left` 與 `root.right` 的高度總和，會漏掉「最長路徑完全位於某棵子樹」的情況。因此，不能只在整棵樹的根節點計算一次，而要在**每一個節點**都檢查直徑候選值。

對任一節點 `node`：

1. `left` 是左子樹的最大高度。
2. `right` 是右子樹的最大高度。
3. 通過 `node` 的最長路徑會從左側最深節點走到 `node`，再走到右側最深節點，因此候選直徑為 `left + right`。
4. 父節點只能沿著 `node` 的其中一側繼續延伸，所以 `node` 向上回傳的高度是 `max(left, right) + 1`。

這正好適合後序遍歷：先取得左右子樹的答案，再處理目前節點。

> [!IMPORTANT]
> `MaxDepth` 回傳的是以節點數表示的子樹高度，但 `left + right` 恰好等於通過目前節點的邊數。例如左右高度都是 1 時，兩個葉節點之間會經過 2 條邊。

## 解法一：後序 DFS

### 設計流程

`DiameterOfBinaryTree` 是公開入口：

1. 將最大直徑 `max` 重設為 `0`，確保連續計算不同樹時不會沿用前一筆結果。
2. 從根節點呼叫 `MaxDepth`。
3. DFS 完成後回傳走訪期間記錄到的最大直徑。

`MaxDepth` 負責同時完成兩件事：

- 回傳目前子樹高度，供父節點使用。
- 用左右子樹高度和更新整棵樹的最大直徑。

虛擬碼如下：

```text
DiameterOfBinaryTree(root):
    max = 0
    MaxDepth(root)
    return max

MaxDepth(node):
    if node is null:
        return 0

    left = MaxDepth(node.left)
    right = MaxDepth(node.right)

    max = maximum(max, left + right)
    return maximum(left, right) + 1
```

### 為什麼這個方法正確

每一條樹中路徑都有一個最高的轉折節點。當後序 DFS 走訪到該節點時，左子樹高度與右子樹高度分別代表路徑可向兩側延伸的最大距離，兩者相加就是通過該節點的最長路徑。

演算法會對每個節點執行同樣的比較，所以一定會檢查到全樹最長路徑的轉折節點。`max` 保留所有候選值中的最大值，最終即為二元樹直徑。

### 複雜度分析

- **時間複雜度：** `O(n)`。每個節點只被 DFS 造訪一次。
- **額外空間複雜度：** `O(h)`。遞迴呼叫堆疊取決於樹高 `h`。
  - 平衡樹約為 `O(log n)`。
  - 完全偏斜時最壞為 `O(n)`。

## 五組範例演示

### 案例 1：官方範例一

輸入：`[1,2,3,4,5]`

```text
    1
   / \
  2   3
 / \
4   5
```

1. 節點 `4`、`5`、`3` 都是葉節點，各自回傳高度 `1`。
2. 節點 `2` 的左右高度都是 `1`，候選直徑為 `1 + 1 = 2`，並回傳高度 `2`。
3. 節點 `1` 收到左高度 `2`、右高度 `1`，候選直徑為 `3`。
4. 最大直徑為 `3`，代表路徑 `4 → 2 → 1 → 3` 或 `5 → 2 → 1 → 3`。

預期輸出：`3`

### 案例 2：官方範例二

輸入：`[1,2]`

```text
  1
 /
2
```

1. 節點 `2` 回傳高度 `1`。
2. 節點 `1` 的左右高度為 `1` 與 `0`。
3. 候選直徑為 `1`，也就是節點 `2` 到節點 `1` 的一條邊。

預期輸出：`1`

### 案例 3：單一節點

輸入：`[1]`

1. 節點 `1` 的左右子樹皆為空，高度都是 `0`。
2. 候選直徑為 `0 + 0 = 0`。
3. 樹中沒有任何邊，因此直徑為 `0`。

預期輸出：`0`

### 案例 4：最長路徑不經過根節點

輸入：`[1,2,null,3,4,5,null,null,6]`

```text
      1
     /
    2
   / \
  3   4
 /     \
5       6
```

1. 葉節點 `5`、`6` 各回傳高度 `1`。
2. 節點 `3` 與 `4` 各自產生候選直徑 `1`，並回傳高度 `2`。
3. 節點 `2` 收到左右高度 `2` 與 `2`，候選直徑更新為 `4`，對應路徑 `5 → 3 → 2 → 4 → 6`。
4. 根節點 `1` 的候選直徑只有 `3`，不會覆蓋既有最大值 `4`。
5. 這證明只計算根節點的左右高度並不足夠。

預期輸出：`4`

### 案例 5：向右偏斜樹

輸入：`[1,null,2,null,3,null,4]`

```text
1
 \
  2
   \
    3
     \
      4
```

1. 節點 `4` 回傳高度 `1`。
2. 回到節點 `3` 時，候選直徑為 `1`，回傳高度 `2`。
3. 回到節點 `2` 時，候選直徑為 `2`，回傳高度 `3`。
4. 回到節點 `1` 時，候選直徑為 `3`。

預期輸出：`3`
