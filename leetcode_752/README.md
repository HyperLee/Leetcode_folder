## 題目說明

一把鎖有四個環形轉輪，每個轉輪包含 `0` 到 `9`。每次只能將其中一個轉輪旋轉一格，而且數字可以環繞：

- `9` 往後一格會回到 `0`。
- `0` 往前一格會回到 `9`。

鎖的初始狀態固定為 `0000`。`deadends` 列出不可進入的狀態；一旦轉到其中之一，鎖就會卡住。給定解鎖目標 `target`，需要回傳從 `0000` 到達目標的最少旋轉次數；若不存在合法路徑，回傳 `-1`。

題目原文：[LeetCode 752 - Open the Lock](https://leetcode.com/problems/open-the-lock/)

## 限制條件

- `1 <= deadends.Length <= 500`
- 每個 `deadends[i]` 的長度都是 `4`
- `target` 的長度是 `4`
- `target` 不會出現在 `deadends` 中
- `target` 與每個 `deadends[i]` 都只包含數字

## 解題概念與出發點

### 將轉盤狀態視為圖

每一個四位字串都是圖上的一個節點，例如 `0000`、`0009`、`1202`。每次旋轉一個轉輪一格，就相當於沿著一條邊前往相鄰節點。

四個位置各能往前或往後旋轉，因此每個合法狀態最多有：

```text
4 個轉輪 × 2 個方向 = 8 個相鄰狀態
```

所有可能狀態只有 `0000` 到 `9999`，合計 10,000 個。`Get` 會產生目前狀態的八個鄰居；`NumtPre` 與 `NumSucc` 負責處理數字減一、加一以及 `0`／`9` 的環繞。

### 為什麼選擇 BFS

每一條邊都代表一次旋轉，成本完全相同。BFS 會按照「距離起點 0 次、1 次、2 次……」的順序逐層探索，所以第一次找到目標時，使用的旋轉次數必然最少。

死路不能加入搜尋邊界；已經看過的狀態也不能重複加入，否則環形轉輪會讓搜尋在相同狀態之間來回循環。

## 解法一：單向 BFS

### 設計說明

`OpenLock` 從 `0000` 開始，以 `Queue<string>` 保存下一批要探索的狀態：

1. 先把 `deadends` 轉為 `HashSet<string>`，讓死路判斷維持常數時間。
2. 若 `0000` 本身是死路，立即回傳 `-1`。
3. 若目標就是 `0000`，不需要旋轉，回傳 `0`。
4. 將 `0000` 放入佇列與 `seen` 集合。
5. 每輪先記住佇列目前的數量，只處理同一層的節點。
6. 對每個狀態產生八個鄰居，略過死路與已拜訪狀態。
7. 找到目標時回傳目前層數加一；本層結束後才增加 `step`。
8. 若佇列耗盡仍未找到目標，回傳 `-1`。

`seen.Add(nextStatus)` 同時完成「是否第一次遇到」與「標記已拜訪」兩件事，確保每個狀態最多進入佇列一次。

### 範例演示

使用官方一般案例：

```text
deadends = ["0201", "0101", "0102", "1212", "2002"]
target = "0202"
```

搜尋從第 0 層的 `0000` 開始。第 1 層會包含旋轉任一輪一次的合法狀態，例如 `1000`、`9000`、`0100` 與 `0009`。BFS 繼續逐層擴展，並排除 `0201`、`0101` 等死路。

其中一條長度為 6 的合法最短路徑是：

```text
0000 → 1000 → 1100 → 1200 → 1201 → 1202 → 0202
  0       1       2       3       4       5       6 次
```

到達 `0202` 時位於第 6 層，因此回傳 `6`。演算法實際找到的路徑可能不同，但第一次命中目標的層數一定相同。

## 解法二：雙向 BFS

### 設計說明

`OpenLock2` 同時從 `0000` 與 `target` 建立 `HashSet<string>` 搜尋邊界：

1. `frontier` 初始為 `{ "0000" }`。
2. `oppositeFrontier` 初始為 `{ target }`。
3. 每輪比較兩側大小；若目前這一側較大，就交換兩個邊界。
4. 只擴展較小邊界中的狀態，以降低該輪產生的鄰居數量。
5. 若某個鄰居已存在於另一側邊界，代表兩邊搜尋相遇，回傳 `step + 1`。
6. 死路與已拜訪狀態不加入下一層。
7. 任一邊界耗盡仍未相遇時，回傳 `-1`。

雙向 BFS 仍然依層搜尋，只是把一條深度為 `d` 的搜尋路徑拆成從兩端接近的兩部分。對狀態分支很多、答案距離較深的案例，通常不必像單向 BFS 一樣展開大量靠近起點但離目標很遠的狀態。

### 範例演示

仍以 `0000` 到 `0202` 為例。實際 frontier 會同時包含許多狀態，以下用同一條合法最短路徑說明兩側如何接近：

| 起點側距離 | 起點側代表狀態 | 目標側距離 | 目標側代表狀態 |
|---:|:---:|---:|:---:|
| 0 | `0000` | 0 | `0202` |
| 1 | `1000` | 1 | `1202` |
| 2 | `1100` | 2 | `1201` |
| 3 | `1200` | 3 | `1200` |

起點側與目標側在 `1200` 相遇，兩側距離合計為 `3 + 3 = 6`。程式每輪實際擴展較小的 frontier，因此左右兩側不一定嚴格交替，但相遇時得到的仍是最少旋轉次數。

## 兩種解法比較

令狀態總數為 `S = 10,000`，轉輪數為 `W = 4`。每個狀態最多產生 `2W = 8` 個鄰居。

| 比較項目 | 單向 BFS | 雙向 BFS |
|---|---|---|
| 公開方法 | `OpenLock` | `OpenLock2` |
| 搜尋起點 | 只從 `0000` | 從 `0000` 與 `target` |
| 邊界結構 | `Queue<string>` | 兩個 `HashSet<string>` |
| 最壞時間複雜度 | `O(S × W)`，此題可視為 `O(S)` | `O(S × W)`，此題可視為 `O(S)` |
| 最壞空間複雜度 | `O(S)` | `O(S)` |
| 優點 | 流程直接，容易理解與除錯 | 通常能縮小實際展開的搜尋範圍 |
| 代價 | 深層目標可能產生較寬的 frontier | 邊界交換與相遇判斷較複雜 |

雙向 BFS 改善的是實務上需要展開的節點數；在最壞情況下，兩種方法仍可能檢查大部分 10,000 個狀態，因此最壞漸進複雜度相同。

## 邊界情況

- `target == "0000"`：不需要旋轉，回傳 `0`。
- `deadends` 包含 `"0000"`：起點已卡住，回傳 `-1`。
- `0` 往前旋轉會變成 `9`；`9` 往後旋轉會變成 `0`。
- 目標周圍所有可進入方向都被死路阻斷時，搜尋耗盡並回傳 `-1`。
- `0000` 到 `5555` 的每一位最短距離都是 5，合計最少需要 20 次旋轉。
