## 題目描述

給定一個會議時間區間陣列 `intervals`，其中每個元素的格式為 `[start, end]`，請判斷一個人是否能參加所有會議。

只要任意兩場會議在時間上重疊，就無法參加全部會議；反之則可以。

### 題目連結

- [LeetCode 252 - Meeting Rooms](https://leetcode.com/problems/meeting-rooms/description/)
- [LeetCode Wiki - 252. 會議室](https://leetcode.doocs.org/lc/252/)

### 限制條件

- `0 <= intervals.Length <= 10^4`
- 每個區間都有兩個整數：`[start, end]`
- `0 <= start < end <= 10^6`

> [!IMPORTANT]
> 會議區間採用「結束時間可以銜接下一場開始時間」的判定方式。因此 `[1,5]` 與 `[5,10]` 不算重疊；只有前一場的 `end >` 下一場的 `start` 時才有衝突。

## 解題概念與出發點

未排序的區間可能讓衝突出現在陣列中相距很遠的位置。若直接比較所有區間組合，需要 `O(n^2)` 時間。排序可以把時間關係整理成線性順序，接著只需一次掃描便能判斷是否有衝突。

本專案保留兩種同為 `O(n log n)` 的做法：

1. **排序完整區間**：依開始時間重排 `intervals`，比較相鄰會議。
2. **分離開始與結束時間**：分別排序 `starts` 與 `ends`，比較下一個開始時間與前一個結束時間。

兩種方法的核心都是：

```text
下一場開始時間 < 前一場尚未結束的時間
                    ↓
                 發生重疊
```

## 解法一：排序完整區間

### 設計說明

`CanAttendMeetings` 直接依每個區間的開始時間排序整個 `intervals`。排序後，開始時間會由小到大排列；若存在衝突，至少會有一組相鄰區間滿足：

```csharp
intervals[i - 1][1] > intervals[i][0]
```

其中：

- `intervals[i - 1][1]` 是前一場會議的結束時間。
- `intervals[i][0]` 是下一場會議的開始時間。
- 使用 `>` 而不是 `>=`，所以首尾相接的會議可以依序參加。

### 演算法步驟

1. 若輸入為 null、空陣列或只有一場會議，直接回傳 `true`。
2. 依開始時間由小到大原地排序 `intervals`。
3. 從第二個區間開始逐一檢查。
4. 若前一場的結束時間大於目前會議的開始時間，立即回傳 `false`。
5. 掃描結束仍未發現衝突，回傳 `true`。

### 為什麼只比較相鄰區間

排序後，任何較晚開始的會議都排在後方。假設某個區間和更前面的非相鄰區間重疊，該較早區間的結束時間也一定晚於排在它們之間的下一個開始時間，因此衝突會先在某一組相鄰區間被發現，不必做所有兩兩比較。

### 範例演示

輸入：

```text
[[0,30],[5,10],[15,20]]
```

1. 依開始時間排序後仍為 `[[0,30],[5,10],[15,20]]`。
2. 比較第一、二場：前一場結束時間為 `30`，下一場開始時間為 `5`。
3. 因為 `30 > 5`，兩場會議重疊。
4. 立即回傳 `false`，不必繼續掃描。

### 複雜度與特性

- 時間複雜度：`O(n log n)`，排序為主要成本；掃描為 `O(n)`。
- 額外空間複雜度：排序實作使用的堆疊空間通常為 `O(log n)`。
- 輸入副作用：**會改變外層區間陣列的排列順序**。
- 優點：程式精簡，排序後的區間順序直觀。
- 缺點：呼叫端若仍需要原始順序，必須先自行複製輸入。

## 解法二：分離開始與結束時間

### 設計說明

`CanAttendMeetings2` 不排序原始區間，而是建立：

- `starts`：所有會議的開始時間。
- `ends`：所有會議的結束時間。

兩個陣列各自排序後，`ends[i - 1]` 表示目前最早需要被銜接的結束時間，而 `starts[i]` 表示下一個開始時間。若：

```csharp
starts[i] < ends[i - 1]
```

代表下一場已開始，但前一場尚未結束，因此存在重疊。

### 演算法步驟

1. 若輸入為 null、空陣列或只有一場會議，直接回傳 `true`。
2. 將每個區間的開始時間放入 `starts`，結束時間放入 `ends`。
3. 分別將 `starts` 與 `ends` 由小到大排序。
4. 從索引 `1` 開始，比較 `starts[i]` 與 `ends[i - 1]`。
5. 發現 `starts[i] < ends[i - 1]` 時回傳 `false`。
6. 所有開始時間都能接在前一個結束時間之後時回傳 `true`。

### 範例演示

輸入：

```text
[[0,30],[5,10],[15,20]]
```

拆分並排序後：

```text
starts = [0,5,15]
ends   = [10,20,30]
```

1. 從 `i = 1` 開始，比較 `starts[1] = 5` 與 `ends[0] = 10`。
2. 因為 `5 < 10`，代表第二個開始事件發生時，最早的結束事件仍未發生。
3. 同一時間至少有兩場會議進行，因此回傳 `false`。

若輸入為 `[[1,5],[5,10]]`：

```text
starts = [1,5]
ends   = [5,10]
```

此時 `starts[1] = ends[0] = 5`，不符合 `<`，所以兩場可以首尾相接並回傳 `true`。

### 複雜度與特性

- 時間複雜度：`O(n log n)`，來自兩個一維陣列的排序。
- 額外空間複雜度：`O(n)`，用來保存 `starts` 與 `ends`。
- 輸入副作用：不修改原始 `intervals`。
- 優點：保留輸入順序，並以時間事件的角度呈現重疊判斷。
- 缺點：需要兩個額外陣列，空間用量高於解法一。

## 兩種解法比較

| 比較項目 | 解法一：排序完整區間 | 解法二：分離起訖時間 |
| --- | --- | --- |
| 核心資料 | 原始二維區間 | 兩個一維時間陣列 |
| 時間複雜度 | `O(n log n)` | `O(n log n)` |
| 額外空間 | 通常為 `O(log n)` | `O(n)` |
| 修改輸入 | 會重排區間 | 不會 |
| 判斷方式 | 比較相鄰區間 | 比較下一個開始與前一個結束 |
| 適合情境 | 可接受重排、希望節省額外陣列 | 必須保留輸入順序 |

主程式固定驗證以下六種情境，每個案例會分別執行兩種解法，共十二項檢查：

| 案例 | 輸入 | 預期 | 驗證重點 |
| --- | --- | --- | --- |
| 題目範例一 | `[[0,30],[5,10],[15,20]]` | `false` | 一開始便出現重疊 |
| 題目範例二 | `[[7,10],[2,4]]` | `true` | 未排序且不重疊 |
