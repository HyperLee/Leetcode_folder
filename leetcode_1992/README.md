## 題目說明

給定一個以 0 為起點的 `m x n` 二元矩陣 `land`：

- `0` 代表森林。
- `1` 代表農地。
- 每一組農地都是完全填滿的矩形。
- 不同農地群組不會在上下左右四個方向相鄰；斜角相鄰則不受此限制。

若一組農地的左上角為 `(r1, c1)`、右下角為 `(r2, c2)`，就以 `[r1, c1, r2, c2]` 表示。請回傳所有農地群組；答案順序不限，沒有農地時回傳空陣列。

題目原文：[Find All Groups of Farmland](https://leetcode.com/problems/find-all-groups-of-farmland/)

### 限制條件

- `m == land.length`
- `n == land[i].length`
- `1 <= m, n <= 300`
- `land` 只包含 `0` 與 `1`
- 每一組農地皆為矩形

## 解題觀察與出發點

矩形與「群組間不四向相鄰」是最重要的兩個保證：

1. 一個農地群組只需要回傳兩個角落，不必列出所有格子。
2. 每組矩形只有左上角的上方與左方都不是農地；其餘農地至少會在上方或左方接到同組農地。
3. 若不利用矩形形狀，也可以把每組農地視為一個四方向連通元件，走訪全部格子並統計座標邊界。
4. 題目允許答案以任意順序回傳，因此測試會先依四個座標排序再比較，避免把順序差異誤判為錯誤。

## 解法一：左上角掃描與邊界延伸

公開 API：

```csharp
public static int[][] FindFarmland(int[][] land)
```

### 設計說明

這個解法直接利用題目的矩形保證，不需要另外用 flood-fill 與 visited 走訪每個群組：

1. 由上到下、由左到右掃描整個矩陣。
2. 遇到森林時略過。
3. 若目前農地的上方也是農地，表示它不是群組第一列；若左方也是農地，表示它不是群組第一欄。兩者任一成立即可略過。
4. 剩下的位置必為某一群組的左上角 `(r1, c1)`。
5. 從左上角向下走到該矩形最後一列，再從左下角向右走到最後一欄，得到右下角 `(r2, c2)`。
6. 加入 `[r1, c1, r2, c2]`，繼續掃描。

### 為什麼正確

- 若某格是群組左上角，其上方與左方不可能屬於同一矩形；又因不同群組不四向相鄰，所以這兩個位置也不可能屬於其他群組。
- 若某格不是左上角，它位於矩形的非首列或非首欄，因此上方或左方至少有一格同組農地，會被判斷式排除。
- 題目保證農地是完整矩形，所以沿左邊界向下、再沿底邊向右，必定停在唯一的右下角。

因此每個群組恰好被記錄一次，而且四個座標正確。

### 範例演示

輸入：

```text
[[1,0,0],
 [0,1,1],
 [0,1,1]]
```

1. 掃描到 `(0,0)`：目前是農地，且沒有上方或左方格子，因此是左上角。向下、向右都無法延伸，記錄 `[0,0,0,0]`。
2. `(1,1)` 是農地，上方 `(0,1)` 與左方 `(1,0)` 都是森林，因此是另一組左上角。
3. 從 `(1,1)` 向下抵達 `(2,1)`，再由底邊向右抵達 `(2,2)`，記錄 `[1,1,2,2]`。
4. `(1,2)`、`(2,1)`、`(2,2)` 都在上方或左方接到同組農地，不會重複建立群組。

結果：`[[0,0,0,0],[1,1,2,2]]`

### 複雜度

- 時間：`O(mn)`。完整掃描需要 `mn` 次檢查；各群組延伸所走過的邊界總量不超過矩陣規模的常數倍。
- 額外空間：`O(1)`，不計回傳結果。

## 解法二：迭代深度優先搜尋

公開 API：

```csharp
public static int[][] FindFarmlandDfs(int[][] land)
```

### 設計說明

這個解法把每組農地視為四方向連通元件，適合用來理解一般矩陣走訪：

1. 建立與 `land` 同尺寸的 `visited`，保留原始輸入不變。
2. 掃描矩陣，遇到尚未拜訪的農地時開始一輪 DFS。
3. 將起點放入 `Stack<(Row, Column)>`，並在「入棧時」立刻標記，避免同一格被不同鄰居重複加入。
4. 每次彈出一格，更新最小列、最小欄、最大列與最大欄。
5. 檢查上、下、左、右四個鄰居，把範圍內、屬於農地且尚未拜訪的格子加入堆疊。
6. 堆疊清空時，四個極值就是該群組的左上角與右下角。

程式使用顯式堆疊，而不是遞迴函式；在最大 `300 x 300` 的單一農地群組中，也不會依賴呼叫堆疊深度。

### 為什麼正確

- DFS 只沿四方向移動，因此只會走到與起點同組的農地；不同群組不四向相鄰，不會被混在一起。
- 所有可達鄰居都會入棧，所以 DFS 結束時已拜訪該群組的每一格。
- 矩形內最小列與最小欄組成左上角，最大列與最大欄組成右下角。
- `visited` 確保每格最多處理一次，每個群組也只會啟動一次 DFS。

### 範例演示

仍以 `[[1,0,0],[0,1,1],[0,1,1]]` 為例：

1. `(0,0)` 啟動第一輪 DFS；沒有四向農地鄰居，邊界維持 `(0,0)`，得到 `[0,0,0,0]`。
2. 掃描到 `(1,1)` 時啟動第二輪 DFS，初始邊界皆為 `(1,1)`。
3. 四方向搜尋陸續拜訪 `(1,2)`、`(2,1)`、`(2,2)`；最大列更新為 `2`，最大欄更新為 `2`。
4. 堆疊清空後得到 `[1,1,2,2]`。後續掃描遇到這三格時，因為已標記而直接略過。

結果：`[[0,0,0,0],[1,1,2,2]]`

### 複雜度

- 時間：`O(mn)`，每格最多入棧與出棧一次。
- 額外空間：`O(mn)`，最壞情況下 `visited` 與堆疊都與矩陣大小同階；不計回傳結果。

## 解法比較

| 面向 | 左上角掃描 | 迭代 DFS |
| --- | --- | --- |
| 是否修改輸入 | 否 | 否 |
| 使用的題目特性 | 矩形、群組不四向相鄰 | 四方向連通、矩形邊界 |
| 時間複雜度 | `O(mn)` | `O(mn)` |
| 額外空間 | `O(1)` | `O(mn)` |
| 優點 | 程式直接、空間需求低 | 容易延伸到一般連通區域問題 |
| 取捨 | 高度依賴矩形保證 | 需要 visited 與顯式堆疊 |

## 可執行測試設計

`Main` 會對兩種解法執行相同的六組資料，共 12 項檢查：

1. 官方混合範例：單格與 `2 x 2` 農地。
2. 整張矩陣都是農地。
3. 只有森林，確認空結果。
4. 單列農地延伸到右邊界。
5. 單欄內有兩組分離農地。
6. 多個不同尺寸、位於角落與邊界的農地群組。

每組都顯示 Input、Expected、Actual 與 PASS/FAIL。只要任一檢查失敗，程式便設定非零結束碼，方便在終端或 CI 中偵測錯誤。本專案目前沒有獨立的自動化測試專案，因此以建置與這組 deterministic console harness 作為驗收方式。
