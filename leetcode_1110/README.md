## 題目說明

給定一棵二元樹的根節點 `root`，樹上每個節點的值都不相同。另給定整數陣列 `to_delete`；凡是值出現在 `to_delete` 中的節點，都必須從樹中刪除。

刪除完成後，原本的一棵樹可能分裂成多棵互不相連的樹，也就是一座森林。回傳森林中每棵樹的根節點；答案的排列順序不受限制。

### 官方範例一

```text
輸入：root = [1,2,3,4,5,6,7], to_delete = [3,5]
輸出：[[1,2,null,4],[6],[7]]
```

刪除節點 `3` 後，它原本的左右子節點 `6`、`7` 都失去父節點，因此各自成為新樹根。節點 `5` 是葉節點，刪除後不會產生新樹。原始根 `1` 沒有被刪除，因此保留為第一棵樹的根。

```text
刪除前：              刪除後：
        1                    1       6       7
      /   \                /
     2     3              2
    / \   / \            /
   4   5 6   7          4
```

### 官方範例二

```text
輸入：root = [1,2,4,null,3], to_delete = [3]
輸出：[[1,2,4]]
```

節點 `3` 是節點 `2` 的右側葉節點。刪除它只需要把 `2.right` 設為 `null`；原始根 `1` 仍存在，所以森林只有一棵樹。

## 限制條件

依 [LeetCode 1110 官方題面](https://leetcode.com/problems/delete-nodes-and-return-forest/)：

- 樹中的節點數量最多為 `1000`。
- 每個節點值介於 `1` 到 `1000`，且所有節點值互不相同。
- `to_delete.length <= 1000`。
- `to_delete` 中的值介於 `1` 到 `1000`，且互不相同。
- 森林中各棵樹的回傳順序不受限制。

本專案的三個公開解法遵循題目合法輸入契約，同時接受 `root == null`，方便固定 harness 驗證空樹。三種解法都會原地修改傳入樹的左右連結，因此同一棵樹不能依序重複交給不同解法；測試程式會為每次呼叫重建獨立樹。

## 解題概念與出發點

### 1. 什麼節點會成為森林根節點？

一個未被刪除的節點會成為森林根節點，只有兩種情況：

1. 它是原始樹根。
2. 它的父節點被刪除。

因此走訪時不只要知道「目前節點是否刪除」，還需要知道「目前節點是否已經沒有保留中的父節點」。程式使用 `isRoot` 表示這個狀態。

```text
isRoot = true 且目前節點未刪除
    => 將目前節點加入森林

目前節點被刪除
    => 它的左右子節點在下一層都成為候選根
```

### 2. 刪除不是只略過輸出，也要斷開連結

如果只把節點從答案中省略，保留中的父節點可能仍然指向它，結果就不是真正分離的森林。三種解法都會把對應的 `left` 或 `right` 設為 `null`，但斷鏈時機不同：

- 後序解法由遞迴回傳值決定父節點最後要接回哪棵子樹。
- 前序解法在進入待刪節點時，透過保存的父節點立即斷鏈。
- 迭代解法把父節點及左右位置一起放入堆疊，彈出節點時斷鏈。

### 3. 為什麼需要 `HashSet<int>`？

每個節點都要判斷自己的值是否位於 `to_delete`。若每次線性掃描陣列，最壞會花費 `O(n × d)`；先將刪除值放入 `HashSet<int>`，建立集合需要 `O(d)`，每個節點平均只需 `O(1)` 查詢，整體即可維持 `O(n + d)`。

### 4. 答案順序沒有意義，但樹的結構有意義

森林可以用任何順序回傳，所以 `[[1,2,null,4],[6],[7]]` 與 `[[7],[1,2,null,4],[6]]` 是同一個答案；然而 `[1,2,null,4]` 與 `[1,2,4]` 的結構不同，不能只比較節點集合。

固定 harness 會：

1. 以層序格式序列化每棵樹，保留結構所需的 `null`。
2. 移除尾端不影響結構判讀的 `null`。
3. 將森林內的樹字串以 ordinal 順序排序。
4. 比較完整的正規化字串。

如此既容許合法的森林順序差異，也能抓出連結位置錯誤、遺漏節點或多餘節點。

## 解法一：後序遞迴 DFS

### 設計說明

`DelNodes` 先將 `toDelete` 轉成集合，再呼叫：

```csharp
DFS(node, isRoot, toDeleteSet, roots)
```

`DFS` 的回傳值定義是：「處理完刪除後，父節點應該接回的子樹根」。

- 空節點回傳 `null`。
- 未刪除節點回傳自己。
- 被刪除節點回傳 `null`。

每個節點先遞迴處理左右子樹，再把回傳值寫回 `node.left`、`node.right`。因此當子節點被刪除時，父節點會自然收到 `null`；當子節點保留時，父節點仍接回原子樹。

### 核心流程

```text
deleted = toDeleteSet.Contains(node.val)

node.left  = DFS(node.left,  deleted, ...)
node.right = DFS(node.right, deleted, ...)

如果 isRoot 且 node 未刪除：
    roots.Add(node)

如果 node 被刪除：回傳 null
否則：回傳 node
```

把 `deleted` 傳給子節點作為下一層的 `isRoot`，正好表達「父節點刪除後，未刪除子節點會成為新根」。

### 正確性說明

後序遍歷保證判斷目前節點之前，左右子樹都已完成刪除：

- 遞迴回傳 `null` 時，對應的待刪子節點會從目前節點斷開。
- 遞迴回傳非空節點時，該節點是處理完成後應保留的子樹根。
- 每個原始根或被刪除節點的未刪除直接子節點，都會收到 `isRoot = true`，因此恰好加入森林一次。
- 其他未刪除節點仍具有保留中的父節點，不會被錯誤加入森林。

所以回傳集合包含且只包含刪除完成後各棵樹的根。

### 官方範例一演示

```text
先走到葉節點 4：
    4 不刪除、isRoot = false，回傳 4

走到葉節點 5：
    5 在刪除集合，回傳 null
    因此 2.right 變為 null

走到節點 3：
    3 在刪除集合
    子節點 6、7 都以 isRoot = true 被處理，且未刪除
    將 6、7 加入森林
    3 回傳 null，因此 1.right 變為 null

回到節點 1：
    1 是原始根且未刪除，加入森林
```

正規化結果為 `[[1,2,null,4],[6],[7]]`。

### 複雜度與副作用

- 時間複雜度：`O(n + d)`。
- 額外空間複雜度：`O(d + h)`，包含刪除集合與遞迴堆疊。
- 是否修改輸入：是，會重寫左右子節點連結。
- 特性：程式最精簡，斷鏈由回傳值自然完成；樹高很大時會使用較深的呼叫堆疊。

## 解法二：前序遞迴 DFS

### 設計說明

`DelNodes2` 使用 `DeletePreOrder`，每次遞迴額外攜帶：

- `parent`：目前節點的保留中父節點。
- `isLeftChild`：目前節點位於父節點左側或右側。
- `isRoot`：目前節點是否為候選森林根。

這個版本一進入節點就決定是否刪除。若目前節點要刪除，會先保存 `left`、`right`，再從父節點斷鏈並清空自身連結，最後遞迴走訪保存下來的子節點。

### 為什麼必須先保存左右子節點？

前序版本在走訪子樹前就刪除目前節點。如果直接執行：

```text
node.left = null
node.right = null
```

再讀取子節點，原本的子樹入口已經遺失。正確順序是：

```text
left = node.left
right = node.right

斷開 node

遞迴 left
遞迴 right
```

這正是前序刪除與後序回傳最大的設計差異。

### 官方範例一演示

```text
進入 1：
    原始根且未刪除，加入森林

進入 2：
    未刪除，保留與 1 的連結

進入 5：
    先保存空的左右子節點
    透過 parent = 2、isLeftChild = false，設定 2.right = null

進入 3：
    先保存子節點 6、7
    透過 parent = 1、isLeftChild = false，設定 1.right = null
    清空 3 的左右連結

進入 6、7：
    兩者的 isRoot 都是 true，且未刪除，各自加入森林
```

最後仍得到 `[[1,2,null,4],[6],[7]]`。

### 正確性說明

每個節點在進入時立即處理：

- 待刪節點會從唯一的父節點連結斷開。
- 待刪節點的原左右子節點以 `isRoot = true` 繼續遍歷。
- 保留節點的子節點仍以目前節點為父節點，維持原本結構。
- 只有候選根且未被刪除的節點加入答案。

所有節點恰好被走訪一次，因此不會遺漏或重複處理；加入森林的條件與題目對新根的定義完全一致。

### 複雜度與副作用

- 時間複雜度：`O(n + d)`。
- 額外空間複雜度：`O(d + h)`。
- 是否修改輸入：是，會立即斷開父子連結並清空被刪節點的左右連結。
- 特性：刪除動作明確可見，適合理解父節點方向；狀態參數比後序版本多。

## 解法三：迭代 DFS

### 設計說明

`DelNodes3` 將前序解法的呼叫框架改成顯式堆疊。每個堆疊項目保存：

```csharp
(TreeNode Node, TreeNode? Parent, bool IsLeftChild, bool IsRoot)
```

彈出節點後，處理方式與前序遞迴相同：判斷是否加入森林、保存子節點、斷開待刪節點，再把子節點壓入堆疊。

### 堆疊順序

堆疊是後進先出。為了讓實際走訪順序維持「根、左、右」，程式先壓入右子節點，再壓入左子節點：

```text
push(right)
push(left)

下一次 pop() 會先取得 left
```

森林本身允許任意回傳順序，因此正確性不依賴這個選擇；維持一般前序順序只是讓追蹤流程較直觀。

### 官方範例一演示

```text
初始 stack：[(1, parent=null, isRoot=true)]

pop 1：
    1 加入森林
    push 3，再 push 2

pop 2：
    push 5，再 push 4

pop 4：
    保留，不產生新根

pop 5：
    從 2.right 斷開

pop 3：
    從 1.right 斷開
    push 7 與 6，兩者 isRoot = true、parent = null

pop 6、7：
    各自加入森林
```

### 正確性說明

每個非空節點只會被壓入與彈出一次。堆疊項目完整保存遞迴版本需要的父節點、左右位置與候選根狀態，所以每次迭代執行的狀態轉移與前序遞迴相同。由於前序遞迴已涵蓋所有節點並正確斷鏈，將呼叫堆疊等價替換為顯式堆疊不會改變森林結果。

### 複雜度與副作用

- 時間複雜度：`O(n + d)`。
- 額外空間複雜度：`O(n + d)`；最壞情況下顯式堆疊保存 `O(n)` 個節點。
- 是否修改輸入：是，行為與前序版本相同。
- 特性：不依賴遞迴呼叫堆疊，適合展示如何手動保存遍歷狀態；堆疊項目較大。

## 三種解法比較

| 解法 | 處理時機 | 如何斷鏈 | 時間複雜度 | 額外空間 | 主要特色 |
| --- | --- | --- | --- | --- | --- |
| 後序遞迴 DFS | 子樹完成後 | 用遞迴回傳值重寫 `left/right` | `O(n + d)` | `O(d + h)` | 最精簡，回傳值語意清楚 |
| 前序遞迴 DFS | 進入節點時 | 使用 `parent` 與左右方向立即斷開 | `O(n + d)` | `O(d + h)` | 刪除動作直觀，需先保存子節點 |
| 迭代 DFS | 節點彈出堆疊時 | 堆疊保存父節點及左右方向 | `O(n + d)` | `O(n + d)` | 不依賴遞迴，狀態較完整 |

其中：

- `n` 是二元樹節點數量。
- `d` 是 `to_delete` 的長度。
- `h` 是二元樹高度。
- 三種解法都會修改輸入樹；輸出森林所需的根節點集合不計入額外空間。
