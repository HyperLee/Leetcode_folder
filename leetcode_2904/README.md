# LeetCode 2904：最短且字典序最小的美麗子字串

![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4?logo=dotnet)

## 題目說明

給定一個二進位字串 `s` 與正整數 `k`。

如果一個子字串中恰好包含 `k` 個 `1`，就稱它為美麗子字串。請先找出所有美麗子字串中的最短長度，再從這些相同長度的候選中回傳字典序最小者。如果不存在符合條件的子字串，則回傳空字串。

字典序比較的規則是：從左到右找到第一個不同的位置，該位置字元較小的字串，字典序就較小。對二進位字串而言，`0` 的字典序小於 `1`。

- [LeetCode 英文題目](https://leetcode.com/problems/shortest-and-lexicographically-smallest-beautiful-string/description/)
- [LeetCode 中文題目](https://leetcode.cn/problems/shortest-and-lexicographically-smallest-beautiful-string/description/)

## 限制條件

- `1 <= s.Length <= 100`
- `1 <= k <= s.Length`
- `s` 是只包含 `0` 和 `1` 的二進位字串。

`n` 代表 `s.Length`。由於 `n` 最大只有 100，枚舉法雖然較慢，仍可在題目限制內完成；滑動視窗則能進一步降低搜尋成本。

## 解題核心與出發點

這題有兩層排序目標，不能只找到任意一個包含 `k` 個 `1` 的子字串：

1. 先比較長度，必須選最短的美麗子字串。
2. 長度相同時，再比較字典序，必須保留字典序較小者。

因此，兩種解法都會在找到合法候選後執行相同的選擇規則：

```text
候選長度較短 → 更新答案
候選長度相同且字典序較小 → 更新答案
其他情況 → 保留原答案
```

枚舉法直接枚舉長度，所以可以由最短的可能長度 `k` 開始搜尋。滑動視窗則固定右端點，透過移動左端點移除多餘的 `1` 與不影響計數的前置 `0`，讓每個右端點只保留最短的合法候選。

## 解法比較

| 方法 | 核心作法 | 時間複雜度 | 額外空間 | 輸入是否被修改 |
| --- | --- | --- | --- | --- |
| `ShortestBeautifulSubstring` | 由長度 `k` 到 `n`，檢查每個窗口中的 `1` 數量 | `O(n³)` | `O(n)` | 否 |
| `ShortestBeautifulSubstring2` | 維護左右指標與窗口內的 `1` 數量 | 指標掃描為 `O(n)`；目前建立候選字串後最壞為 `O(n²)` | `O(n)` | 否 |

枚舉法的 `O(n³)` 來自三層成本：外層嘗試 `O(n)` 種長度、每個長度檢查 `O(n)` 個窗口，以及建立子字串並計算 `1` 數量需要 `O(n)`。滑動視窗的左右指標各自只向右移動，但目前 C# 實作會對每個合法窗口呼叫 `Substring`，並使用 `CompareOrdinal` 比較候選，因此實際最壞時間以 `O(n²)` 計算較準確。

## 解法一：枚舉所有長度與窗口

### 設計步驟

1. 令候選長度 `m` 從 `k` 開始遞增到 `s.Length`。
2. 對目前長度 `m`，逐一取出每個連續窗口。
3. 計算窗口中 `1` 的數量，只有恰好等於 `k` 才是合法候選。
4. 對相同長度的候選使用字典序比較，保留較小者。
5. 只要目前長度找到至少一個合法候選，就立即回傳；因為後續長度不可能更短。
6. 如果所有長度都沒有合法候選，回傳空字串。

### 為什麼外層由 `k` 開始？

一個子字串若包含 `k` 個 `1`，至少需要 `k` 個字元，因此長度不可能小於 `k`。外層從 `k` 依序往上搜尋，第一個找到合法候選的 `m` 就是最短美麗子字串長度。

### 範例演示：`s = "100011001"`、`k = 3`

先檢查長度 3 與 4 的窗口：

| 候選長度 `m` | 窗口中的 `1` 數量 | 結果 |
| ---: | --- | --- |
| 3 | 所有窗口最多只有 2 個 `1` | 沒有合法候選 |
| 4 | `"1000"`、`"0001"`、`"0011"`、`"0110"`、`"1100"`、`"1001"` 最多只有 2 個 `1` | 沒有合法候選 |

接著檢查長度 5：

| 窗口 | `1` 的數量 | 是否合法 |
| --- | ---: | --- |
| `"10001"` | 2 | 否 |
| `"00011"` | 2 | 否 |
| `"00110"` | 2 | 否 |
| `"01100"` | 2 | 否 |
| `"11001"` | 3 | 是 |

長度 5 是第一個找到合法候選的長度，因此立即回傳 `"11001"`。不需要再檢查長度 6 以上的窗口。

## 解法二：滑動視窗

### 維護的狀態

- `right`：目前掃描到的右端點。
- `left`：目前窗口的左端點。
- `cnt`：窗口內 `1` 的數量。
- `ans`：目前找到的最短、且在同長度下字典序最小的答案。

### 設計步驟

1. 先計算整個字串的 `1` 數量。若總數小於 `k`，直接回傳空字串。
2. 每次將 `right` 向右移動，並把新字元加入 `cnt`。
3. 當 `cnt > k` 時，從左側移除字元，直到窗口不再超過 `k` 個 `1`。
4. 當左端點是 `0` 時，持續移除它。移除前置 `0` 不會改變 `cnt`，卻能縮短窗口。
5. 當 `cnt == k` 時，當前窗口是以 `right` 結尾的最短合法候選，依長度及字典序規則更新 `ans`。
6. 掃描完成後回傳 `ans`。

### 為什麼可以移除左側字元？

當窗口有超過 `k` 個 `1`，左側的字元一定要被移除，直到只剩下 `k` 個 `1`。當窗口已經有恰好 `k` 個 `1`，左側若是 `0`，移除它不會讓窗口失去合法性，卻會讓候選更短。

因此，`while (cnt > k || s[left] == '0')` 會把窗口縮成「以目前 `right` 結尾、且仍然合法的最短窗口」。每個右端點都先完成這個縮減，再與全域答案比較。

### 範例演示：`s = "100011001"`、`k = 3`

字串中的 `1` 位於索引 `0、4、5、8`：

1. 掃描到索引 5 時，窗口 `0..5` 是 `"100011"`，剛好有 3 個 `1`，先記錄為合法候選。
2. 掃描到索引 8 時，窗口暫時包含 4 個 `1`。先移除索引 0 的 `1`，再移除索引 1、2、3 的前置 `0`。
3. `left` 移到索引 4，窗口變成 `4..8` 的 `"11001"`，剛好有 3 個 `1`，且長度比 `"100011"` 更短，因此更新答案。
4. 掃描結束，回傳 `"11001"`。

### 同長度時的字典序比較

`"11011011"`、`k = 3` 沒有長度 3 的合法子字串。滑動視窗會先找到長度 4 的 `"1101"`，之後在移除左側多餘的 `1` 後找到另一個長度 4 候選 `"1011"`。兩者長度相同，而 `"1011"` 的第二個字元 `0` 小於 `"1101"` 的第二個字元 `1`，所以答案更新為 `"1011"`。
