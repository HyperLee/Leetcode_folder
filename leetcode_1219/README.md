## 題目說明

給定一個 `m x n` 整數矩陣 `grid`，每一格的數值代表該處黃金量；數值 `0` 表示空地，不能進入。採礦路徑必須遵守下列規則：

1. 進入含金格時，會收集該格全部黃金。
2. 每一步只能往上、下、左、右移動一格。
3. 同一條路徑不能重複造訪同一格。
4. 不能走進黃金量為 `0` 的格子。
5. 可以從任意含金格開始，也可以在任意含金格停止。

目標是回傳任一合法路徑可收集的最大黃金總量。

### 官方範例一

```text
輸入：grid = [[0,6,0],[5,8,7],[0,9,0]]
輸出：24
```

最佳路徑為 `9 -> 8 -> 7`，總和是 `9 + 8 + 7 = 24`。

```text
0  6  0
5  8  7
0  9  0

路徑：9 ↑ 8 → 7
```

雖然中央的 `8` 還能走向 `5` 或 `6`，但同一條路徑不能在離開後再回到 `8`，因此不能把四個分支全部相加。

### 官方範例二

```text
輸入：grid = [[1,0,7],[2,0,6],[3,4,5],[0,3,0],[9,0,20]]
輸出：28
```

路徑 `1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7` 可以收集 `28`。下方的 `3`、`9`、`20` 位於其他互不連通區塊；一次採礦只能選擇一條連續路徑，不能把不同區塊的答案相加。

## 限制條件

依 [LeetCode 1219 官方題面](https://leetcode.com/problems/path-with-maximum-gold/description/)：

- `m == grid.length`。
- `n == grid[i].length`。
- `1 <= m, n <= 15`。
- `0 <= grid[i][j] <= 100`。
- 整張矩陣最多只有 `25` 個含金格。

這些限制帶來兩個重要設計條件：

- 矩陣最多有 `225` 格，但真正需要納入路徑狀態的含金格最多只有 `25` 個。
- 解法三可以安全使用 32 位元的 `uint`，以其中 25 個位元表示目前路徑造訪過哪些含金格。

三個公開 API 都依照題目的合法非空矩形輸入契約設計。全零矩陣是合法輸入，答案為 `0`。

## 解題概念與出發點

### 1. 把矩陣視為圖

每個含金格可視為圖上的節點；兩個含金格若上下左右相鄰，就有一條可走的邊。題目要求的是：

> 從任意節點出發，在不重複節點的條件下，尋找節點權重總和最大的簡單路徑。

矩陣可能包含環，例如四個相連的含金格：

```text
1 1
1 1
```

若沒有記錄目前路徑已走過的格子，搜尋會在環中來回，無法正確終止。因此三種解法雖然保存狀態的方式不同，都必須維護「目前路徑已造訪集合」。

### 2. 為什麼必須嘗試每個含金格當起點？

題目沒有指定入口，也不要求從邊界開始。最佳路徑可能從任何含金格出發；若只選左上角、第一個含金格或最大值格，都可能錯過最佳答案。

因此共同外層流程是：

```text
best = 0

逐格掃描 grid：
    如果目前格含有黃金：
        從目前格開始搜尋所有合法路徑
        更新 best

回傳 best
```

### 3. 路徑狀態必須回溯，而不是永久標記

「不能重複造訪」只限制同一條路徑，不代表某格被一個分支使用後，其他分支就永遠不能使用。

以官方範例一中央的 `8` 為例：從 `9` 走到 `8` 時，可以分別嘗試走向 `6`、`5`、`7`。搜尋完 `6` 的分支後，必須撤銷該分支的造訪狀態，才能正確測試 `5` 與 `7`。

三種解法分別以以下方式表達這個不變量：

- 解法一：把目前格暫時改成 `0`，回傳前還原原值。
- 解法二：把 `visited[row, column]` 暫時設為 `true`，回傳前改回 `false`。
- 解法三：每個堆疊狀態保存自己的不可變位元遮罩；產生下一個狀態時建立新遮罩。

### 4. 為什麼不直接對座標做一般記憶化？

同一個座標在不同已造訪集合下，可選擇的後續路徑不同。例如到達中央格時，左側格已走過與尚未走過會得到不同答案。只使用 `(row, column)` 當快取鍵會混合不同狀態，導致錯誤結果。

完整狀態至少必須包含「目前位置 + 已造訪集合」。本專案著重比較三種狀態表示，不額外建立可能非常龐大的所有狀態快取。

## 解法一：原地標記遞迴回溯

### 設計說明

`GetMaximumGold` 保留既有解法的核心策略：搜尋進入某格後，先把黃金加入目前總和，再暫時把該格設為 `0`。因為搜尋本來就不能走進零值格，所以 `0` 同時表示：

- 原本就是空地。
- 目前路徑已造訪，暫時不能再次進入。

不需要額外的 `visited` 陣列。四個方向都探索完成後，再把原始黃金值寫回矩陣，讓其他起點與其他分支能使用該格。

```text
DFS(row, column, gold)：
    gold += grid[row][column]
    更新全域 maximumGold

    originalGold = grid[row][column]
    grid[row][column] = 0

    對四個相鄰方向：
        如果新座標合法且黃金量 > 0：
            DFS(nextRow, nextColumn, gold)

    grid[row][column] = originalGold
```

`maximumGold` 是解題物件的欄位，因此公開方法在每次呼叫開始時都必須重設為 `0`。否則同一物件先計算答案 `24`，再計算全零矩陣時，第二次可能錯誤地沿用 `24`。固定案例刻意重複使用同一個 `Program` 物件驗證這項行為。

### 官方範例一演示

從黃金量 `9` 的格子開始：

```text
步驟 1：進入 9
目前總和 = 9
暫時標記：grid[2][1] = 0

步驟 2：向上進入 8
目前總和 = 9 + 8 = 17
暫時標記：grid[1][1] = 0

步驟 3：依序測試 8 的其他相鄰分支
走到 6：總和 23
走到 5：總和 22
走到 7：總和 24，更新最大值

步驟 4：各分支回傳前還原 6、5、7
步驟 5：離開 8 與 9 前依序還原原值
```

這次起點得到的最佳值是 `24`。外層仍會嘗試其他含金格當起點，以保證答案不依賴起點選擇。

### 正確性說明

對任一遞迴呼叫，進入時目前格尚未出現在當前路徑：

1. 暫時設為 `0` 後，所有更深層呼叫都無法再次進入目前格，因此產生的每條路徑都不含重複格。
2. 方法逐一探索所有合法的未造訪相鄰格，因此不會漏掉任何可行的下一步。
3. 每次進入格子都更新最大值，涵蓋題目允許在任意位置停止的情況。
4. 回傳前還原原值，使其他分支看到與進入本呼叫前相同的矩陣。
5. 外層以每個含金格為起點，所以所有合法簡單路徑都會被考慮。

因此最後得到的 `maximumGold` 正是所有合法路徑中的最大黃金量。

### 複雜度與副作用

令 `K` 為含金格數，且 `K <= 25`：

- 時間複雜度：最壞可表示為 `O(K × 3^K)`；第一步最多四個方向，之後通常至多剩三個未立即返回的方向，實際數量也受零值格與矩陣形狀限制。
- 額外空間複雜度：`O(K)`，來自遞迴呼叫堆疊。
- 搜尋期間是否修改輸入：會暫時修改。
- 呼叫完成後輸入是否不變：是，每層遞迴都會回溯還原。

## 解法二：visited 遞迴 DFS

### 設計說明

`GetMaximumGold2` 建立與矩陣同尺寸的 `bool[,] visited`。矩陣只讀取黃金量，造訪狀態完全放在額外陣列中。

`CollectWithVisited` 的回傳值定義為：

> 從目前格開始，在目前已造訪狀態下，包含目前格可收集的最大黃金量。

```text
CollectWithVisited(row, column)：
    visited[row, column] = true
    bestContinuation = 0

    對四個相鄰方向：
        如果座標合法、含有黃金且尚未造訪：
            bestContinuation = max(
                bestContinuation,
                CollectWithVisited(nextRow, nextColumn))

    visited[row, column] = false
    回傳 grid[row][column] + bestContinuation
```

與解法一不同，這個 helper 不需要共用的累計黃金欄位。每一層直接回傳「目前格 + 最佳後續分支」，外層再比較所有起點。

### 官方範例一演示

仍從 `9` 開始：

```text
進入 9：visited[2,1] = true
    進入 8：visited[1,1] = true
        進入 6：回傳 6，並清除 visited[0,1]
        進入 5：回傳 5，並清除 visited[1,0]
        進入 7：回傳 7，並清除 visited[1,2]
        8 選擇最佳後續 7，回傳 8 + 7 = 15
    9 回傳 9 + 15 = 24
離開 9：visited[2,1] = false
```

遞迴在 `8` 只選一個最大後續分支，而不是把 `6 + 5 + 7` 全部加入，因為單一路徑離開 `8` 後不能返回再走另一個分支。

### 正確性說明

`visited` 精確表示目前遞迴路徑：

1. 進入目前格時設為 `true`，因此更深層搜尋不會重複使用它。
2. 所有合法且未造訪的相鄰格都會被遞迴計算。
3. `bestContinuation` 選擇其中最大者；選擇不繼續移動時保留初始值 `0`，涵蓋任意停止。
4. 回傳目前格黃金加上最佳後續值，正好得到從目前格出發的最佳路徑。
5. 回傳前把狀態改回 `false`，不會污染其他分支與起點。

外層比較每個含金起點的回傳值，因此得到全域最佳答案。

### 複雜度與副作用

- 時間複雜度：最壞 `O(K × 3^K)`。
- 額外空間複雜度：`O(m × n + K)`，包含 `visited` 矩陣與遞迴堆疊。
- 是否修改輸入：否，`grid` 全程只讀。
- 特性：狀態含意最直觀，適合希望明確區分「空地」與「已造訪」的情境。

## 解法三：迭代 DFS 與位元遮罩

### 設計說明

`GetMaximumGold3` 先掃描矩陣，依序把每個含金格編號為 `0..K-1`，零值格記為 `-1`。因題目保證 `K <= 25`，可使用一個 `uint` 的位元表示所有含金格的造訪狀態。

每個堆疊項目保存：

```csharp
(int Row, int Column, uint VisitedMask, int Gold)
```

- `Row`、`Column`：目前位置。
- `VisitedMask`：目前路徑已造訪哪些含金格。
- `Gold`：目前路徑累計黃金量。

每個含金格都會建立一個起始狀態。彈出狀態後，若相鄰含金格對應的位元尚未出現，就把新位置、新遮罩與新總和推入堆疊。

```text
為每個含金格建立 bit index

對每個含金起點：
    push(起點座標, 起點位元, 起點黃金)

當 stack 非空：
    state = pop()
    更新 best

    對四個相鄰方向：
        nextBit = 1 << 相鄰格索引
        如果相鄰格合法且 (mask & nextBit) == 0：
            push(相鄰座標, mask | nextBit, gold + 相鄰格黃金)
```

位元遮罩是值型別；建立下一個狀態時使用 `visitedMask | nextBit`，不會修改父狀態。因此不需要像遞迴版本一樣明確執行「取消造訪」。

### 官方範例一演示

依列優先掃描，五個含金格可編號為：

| 索引 | 座標 | 黃金 |
|---:|---:|---:|
| 0 | `(0,1)` | 6 |
| 1 | `(1,0)` | 5 |
| 2 | `(1,1)` | 8 |
| 3 | `(1,2)` | 7 |
| 4 | `(2,1)` | 9 |

從 `9` 走到 `8` 再走到 `7` 的狀態變化如下：

```text
起點 9：mask = 10000，gold = 9
走到 8：mask = 10100，gold = 17
走到 7：mask = 11100，gold = 24
```

在 `8` 的狀態也會產生走向 `6`、`5` 的獨立堆疊項目。它們各自保存自己的遮罩與總和，彼此不會污染；搜尋完成後最大值仍是 `24`。

### 正確性說明

每個堆疊狀態一一對應一條合法路徑：

1. 起始狀態只包含一個含金格，是合法路徑。
2. 只有座標合法、含有黃金且位元尚未出現的相鄰格才能產生下一個狀態，因此延伸後仍是合法且不重複的路徑。
3. 每個合法的下一步都會被推入堆疊，不會漏掉任何路徑分支。
4. 每次彈出都更新答案，所以任何長度的路徑都可成為停止點。
5. 所有含金格都建立起始狀態，因此涵蓋所有合法起點。

由數學歸納可知，堆疊會產生全部且只有合法路徑；取所有狀態總和的最大值即為題目答案。

### 複雜度與副作用

- 時間複雜度：最壞 `O(K × 3^K)`，與遞迴回溯同樣需要列舉合法簡單路徑。
- 額外空間複雜度：`O(m × n + K)`；索引矩陣需要 `O(m × n)`，深度優先堆疊在每層保留有限數量的待探索分支。
- 是否修改輸入：否。
- 特性：沒有遞迴呼叫堆疊，單一 `uint` 即可攜帶整條路徑的造訪集合；這項設計依賴題目「最多 25 個含金格」的限制。

## 三種解法比較

| 解法 | 路徑狀態 | 遞迴 | 搜尋期間修改 `grid` | 呼叫後保留輸入 | 額外空間 |
|---|---|---:|---:|---:|---:|
| 原地標記回溯 | 暫時將目前格設為 `0` | 是 | 是 | 是 | `O(K)` |
| `visited` DFS | `bool[,]` | 是 | 否 | 是 | `O(mn + K)` |
| 迭代 DFS | `uint` 位元遮罩 | 否 | 否 | 是 | `O(mn + K)` |

三種解法的核心搜尋範圍相同，主要差異在於如何表示與還原「目前路徑已造訪集合」：

- 解法一最省額外矩陣，但回溯還原是正確性的必要條件。
- 解法二最容易直接閱讀，代價是一個與輸入同尺寸的布林矩陣。
- 解法三善用 `K <= 25`，以位元操作讓每個路徑狀態自包含，也避免遞迴深度。

## 固定案例與驗證方式

`Main` 使用同一個 `Program` 實例依序執行七組案例。這項安排會讓「全零矩陣與重複呼叫」案例偵測解法一是否忘記在新呼叫開始前清除舊答案。

| 案例 | 測試重點 | 預期 |
|---|---|---:|
| 官方範例一 | 多分支回溯與轉彎 | 24 |
| 官方範例二 | 長路徑與不連通區塊 | 28 |
| 全零矩陣與重複呼叫 | 無合法起點、狀態不得殘留 | 0 |
| 單一含金格上界 | 單格、格值上界 | 100 |
| 重複黃金數值 | 不能以數值代替座標識別造訪格 | 4 |
| 互不連通區塊 | 只能選一個連續區塊 | 12 |
| `15 x 15`、25 個含金格 | 尺寸與含金格數量上界 | 25 |

每個案例對每種解法都會：

1. 深層複製一份獨立矩陣。
2. 執行解法並比較 Expected 與 Actual。
3. 再把執行後矩陣與原始矩陣逐列比較。
4. 只有答案正確且輸入完全不變才輸出 `PASS`。

七組案例乘以三種解法，共有 21 項檢查。任何一項失敗時，程式會將 process exit code 設為 `1`，方便 shell、CI 或 VS Code 判斷執行是否成功。
