# 3942. 排序排列的最少操作數

![.NET 10](https://img.shields.io/badge/.NET-10.0-512BD4)
![C%23](https://img.shields.io/badge/C%23-C%23-239120)

給定由 `0` 到 `n - 1` 組成的排列，只能反轉整個陣列或向左旋轉一格。找出將陣列排序為遞增順序所需的最少操作數；若無法完成，回傳 `-1`。

題目來源：[LeetCode 3942. Minimum Operations to Sort a Permutation](https://leetcode.com/problems/minimum-operations-to-sort-a-permutation/description/)

## 題目說明

每次操作只能選擇以下其中一種：

1. **反轉整個陣列**：順序完全倒轉。
2. **向左旋轉一格**：第一個元素移到最後，其餘元素向左移一格。

解法接收一個排列 `nums`，回傳排序所需的最少操作數。若兩種操作無法將它變成遞增排列，回傳 `-1`。

## 限制條件

- `1 <= n == nums.length <= 10^5`
- `0 <= nums[i] <= n - 1`
- `nums` 是 `0` 到 `n - 1` 的一個排列，因此每個值恰好出現一次。

## 解題概念與出發點

先觀察操作對元素順序的影響：左旋只會改變陣列的起點，不會改變環狀排列的方向；反轉會將方向倒過來。因此，從值 `0` 開始沿原陣列循環查看，只有兩種順序可能被排序：

- 遞增方向：`0, 1, 2, ..., n - 1`
- 遞減方向：`0, n - 1, n - 2, ..., 1`

若兩種順序都不符合，操作只能旋轉或反轉這個環狀排列，不能把其他相鄰關係變成排序所需的順序，所以答案是 `-1`。若其中一種符合，再計算該方向下的兩條候選操作路徑，取較小值。

## 解法一：循環模擬

`MinOperations` 先找到 `0` 的索引 `start`，再令 `i` 從 `1` 遞增至 `n - 1`，檢查循環索引 `nums[(start + i) % n]`：

- 若該值等於 `i`，符合遞增方向。
- 若該值等於 `n - i`，符合遞減方向。
- 若兩種方向都不符合，立即回傳 `-1`。

掃描完成後，以 `start` 計算兩條候選路徑：

| 環狀方向 | 操作路徑 | 操作數 |
| --- | --- | ---: |
| 遞增 | 直接左旋 `start` 次 | `start` |
| 遞增 | 反轉、左旋 `n - start` 次、再反轉 | `n - start + 2` |
| 遞減 | 反轉，再左旋 `n - start - 1` 次 | `n - start` |
| 遞減 | 先左旋 `start + 1` 次，再反轉 | `start + 2` |

所以：

```text
遞增：min(start, n - start + 2)
遞減：min(n - start, start + 2)
```

單一元素 `[0]` 已經排序，直接回傳 `0`。

### 正確性說明

左旋保留環狀順序，反轉只會將環狀方向倒轉。因此，能排序的排列必須是遞增序列或遞減序列的一種循環位移；從 `0` 開始比較所有後續元素，正好能完整判斷這兩種可能。若兩者皆不成立，就不存在可到達排序結果的操作序列。

若循環方向為遞增，直接左旋 `start` 次可將 `0` 移到開頭並得到排序結果；另一條等價路徑由兩次反轉與 `n - start` 次左旋組成。若方向為遞減，反轉後左旋 `n - start - 1` 次，或先左旋 `start + 1` 次再反轉，都能得到排序結果。程式比較相應路徑的操作數並取最小值，因此回傳最少操作數。

最少性的依據是反轉會改變後續左旋的等效方向：令 `R` 表示反轉、`L` 表示左旋，則 `R² = I`，且 `R L^k R = L^{-k}`（左旋方向反轉）。因此，遞增目標只需比較不反轉的直接路徑與用一對反轉改走另一方向的路徑；遞減目標則比較單次反轉搭配兩種旋轉方向的路徑。額外的整圈旋轉或反轉對只會增加操作數，不會縮短這些模 `n` 的最短旋轉距離。

### 複雜度

- 時間：`O(n)`。找出 `0` 最多掃描 `n` 個元素，方向檢查再掃描一次。
- 額外空間：`O(1)`。只使用索引、方向旗標與計數值。

## 範例演示

以下依序追蹤 `start`、循環索引、目前值，以及遞增／遞減方向是否仍成立。題目範例使用同一個 `MinOperations` 解法；最後另列單元素邊界案例。

### 範例一：`nums = [0, 2, 1]`

`start = 0`。從 `0` 開始檢查：

| `i` | 循環索引 `(start + i) % n` | 目前值 | 遞增預期 `i` | 遞減預期 `n - i` | 結果 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 1 | 2 | 1 | 2 | 遞增不符，遞減符合 |
| 2 | 2 | 1 | 2 | 1 | 遞增不符，遞減符合 |

判定為遞減方向，`min(n - start, start + 2) = min(3, 2) = 2`。

```text
[0, 2, 1]
左旋一格 -> [2, 1, 0]
反轉     -> [0, 1, 2]
```

### 範例二：`nums = [1, 0, 2]`

`start = 1`。循環檢查的值是 `nums[2] = 2`、`nums[0] = 1`，符合 `0, 2, 1` 的遞減方向。兩條路徑操作數為 `n - start = 2` 與 `start + 2 = 3`，因此答案為 `2`。

```text
[1, 0, 2]
反轉     -> [2, 0, 1]
左旋一格 -> [0, 1, 2]
```

### 範例三：`nums = [2, 0, 1, 3]`

`start = 1`。`i = 1` 時，循環值為 `1`，遞增方向仍成立；`i = 2` 時，循環值為 `3`，但遞增與遞減預期都為 `2`。兩種方向皆被排除，提早回傳 `-1`。

```text
[2, 0, 1, 3] -> -1
```

### 邊界案例：`nums = [0]`

`n = 1`，陣列已排序，不需任何操作，回傳 `0`。
