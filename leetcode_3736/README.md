## 題目說明

給定整數陣列 `nums`。每次操作只能選擇一個元素，將它的值增加 `1`。請回傳讓所有元素相等所需的最少總操作次數。

### 限制條件

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`

兩個方法均假設呼叫端提供符合題目限制的非空、非 `null` 陣列，不另外處理非法輸入。

### 官方範例

| 輸入 | 最少操作次數 | 說明 |
|---|---:|---|
| `[2,1,3]` | 3 | 2 增加 1 次，1 增加 2 次，全部變成 3。 |
| `[4,4,5]` | 2 | 兩個 4 各增加 1 次，全部變成 5。 |

範例一可依序操作：

```text
[2,1,3] → [3,1,3] → [3,2,3] → [3,3,3]
```

範例二可依序操作：

```text
[4,4,5] → [5,4,5] → [5,5,5]
```

## 解題思路與最優性證明

### 出發點：共同目標應該是多少？

本題只能增加元素，不能減少。設原始最大值為 `M`，最後的共同目標為 `T`。原本等於 `M` 的元素無法變小，因此任何可行解都必須滿足 `T >= M`。

如果指定目標 `T`，第 `i` 個元素需要增加 `T - nums[i]` 次。每次操作只影響一個元素，因此把所有差距相加就是達到該目標的確切成本：

```text
cost(T) = Σ(T - nums[i]) = n × T - Σnums[i]
```

把目標從 `M` 提高到 `M + k`（`k > 0`），每個元素都要額外增加 `k` 次，總共多出 `n × k` 次。因此選擇最小可行目標 `M` 一定最佳：

```text
最少操作次數 = Σ(M - nums[i])
```

這就是貪心選擇的依據。只需要找最大值並加總差距，無須排序，也無須逐次模擬增加操作；各元素的操作順序不影響總成本。

### 答案範圍

至少有一個元素已等於最大值，該元素貢獻 0。其餘至多 99 個元素，每個差距至多為 `100 - 1 = 99`，所以答案上界為 `99 × 99 = 9801`。99 個 1 與 1 個 100 可達到此上界，現有 `int` 足以儲存答案。

## 兩種解法的設計與比較

兩者採用相同的貪心策略，差異在於如何取得最大值。

| 方法 | 最大值取得方式 | 時間複雜度 | 額外空間 | 修改輸入 |
|---|---|---|---|---|
| `MinMoves(int[] nums)` | LINQ `nums.Max()` | `O(n)` | `O(1)` | 否 |
| `MinMoves2(int[] nums)` | 手動 `foreach` 與 `Math.Max` | `O(n)` | `O(1)` | 否 |

兩個方法回傳型別皆為 `int`，保留在 `Program` 類別內。額外空間指解法本身，不計 `Main` 的測試資料及輸出字串。即使掃描兩次，`O(n) + O(n)` 仍為 `O(n)`。

### 解法一：LINQ 最大值與差距加總

`MinMoves` 先呼叫 `nums.Max()` 取得共同目標，接著用一次 `foreach` 加總 `max - num`。

1. `max` 儲存原始最大值，後續不再改變。
2. `moves` 從 0 開始，儲存已處理元素所需的操作次數。
3. 每處理一個 `num`，將它與目標的差距加入 `moves`。
4. 掃描結束後回傳 `moves`，即所有元素到達最佳目標的總成本。

這種寫法直接表達「取得最大值」的意圖，程式較精簡。專案透過隱含 using 使用 LINQ，無須額外套件。

#### `[2,1,3]` 演示

`nums.Max()` 取得最大值 3。從概念上看，最大候選值依序為 2、2、3；這是最大值的推導過程，不依賴 LINQ 內部的特定實作方式。

| 階段 | 讀取元素 | 最大候選值 |
|---|---:|---:|
| 第一個元素 | 2 | 2 |
| 比較下一個元素 | 1 | 2 |
| 比較最後一個元素 | 3 | 3 |

確定 `max = 3`，將 `moves` 初始化為 0：

| 當前元素 `num` | 差距 `3 - num` | 累加後 `moves` |
|---:|---:|---:|
| 2 | 1 | 1 |
| 1 | 2 | 3 |
| 3 | 0 | 3 |

最終回傳 3。

#### 其他情境

- `[4,4,5]`：`nums.Max()` 得到 5，差距依序為 1、1、0，累計值依序為 1、2、2，回傳 2。
- `[7,7,7]`：最大值為 7，每個差距皆為 0，累計值一直為 0，回傳 0。

### 解法二：手動找最大值，再加總差距

`MinMoves2` 將第一輪掃描明確寫出，適合觀察最大值如何維護。

1. 由於輸入保證非空，用 `nums[0]` 初始化 `max`。
2. 第一輪對每個 `x` 執行 `max = Math.Max(max, x)`；每次比較後，`max` 都是目前已讀元素的最大值。
3. 第一輪結束，才確定整個陣列的共同目標。
4. 第二輪將 `max - x` 加入 `moves`，結束後回傳總和。

分成兩輪可避免在最大值尚未確定時，用較小的暫時目標計算差距；若後面出現更大的元素，先前元素所需的增加次數也會改變。

#### `[2,1,3]` 演示

初始化 `max = nums[0] = 2`，`moves = 0`。第一輪包含首元素，因此第一次比較為 `Math.Max(2, 2)`：

| 第一輪讀取 `x` | 更新方式 | 更新後 `max` |
|---:|---|---:|
| 2 | `Math.Max(2, 2)` | 2 |
| 1 | `Math.Max(2, 1)` | 2 |
| 3 | `Math.Max(2, 3)` | 3 |

第二輪的目標固定為 3：

| 第二輪讀取 `x` | 差距 `3 - x` | 累加後 `moves` |
|---:|---:|---:|
| 2 | 1 | 1 |
| 1 | 2 | 3 |
| 3 | 0 | 3 |

最終回傳 3，與解法一相同。

#### 其他情境

- `[4,4,5]`：初始化為 4，第一輪的最大值依序為 4、4、5；第二輪差距為 1、1、0，累計值為 1、2、2，回傳 2。
- `[7,7,7]`：初始化為 7，第一輪始終為 7；第二輪所有差距為 0，回傳 0。
