## 題目說明

實作 `myAtoi(string s)`，將字串轉換成 32 位元有號整數。解析時必須依序遵守以下規則：

1. 略過開頭的 ASCII 空白字元 `' '`。
2. 讀取至多一個正號 `'+'` 或負號 `'-'`；沒有符號時視為正數。
3. 連續讀取數字，直到遇到第一個非數字字元或字串結尾。
4. 如果沒有讀到任何數字，回傳 `0`。
5. 結果超出 `[-2³¹, 2³¹ - 1]` 時，截斷為 `int.MinValue` 或 `int.MaxValue`。

例如：

- `"42"` 轉換為 `42`。
- `" -042"` 先略過空白、讀取負號，再把 `042` 轉換為 `-42`。
- `"1337c0d3"` 讀到 `c` 時停止，因此結果是 `1337`。
- `"words and 987"` 的第一個有效位置不是符號或數字，因此回傳 `0`。

### 限制條件

- `0 <= s.Length <= 200`
- `s` 由英文字母、數字 `0-9`、空白 `' '`、正號 `'+'`、負號 `'-'` 與小數點 `'.'` 組成。
- 輸出必須落在 32 位元有號整數範圍：
  - 最小值：`-2³¹`，即 `-2147483648`
  - 最大值：`2³¹ - 1`，即 `2147483647`

## 共同解題概念

兩種解法的核心都是「只掃描一次字串」，並把解析過程拆成四個階段：

1. **前導空白階段**：只允許略過字串最前方的空白。
2. **符號階段**：只允許讀取一次正號或負號。
3. **數字階段**：逐位執行 `result = result * 10 + digit`。
4. **停止階段**：遇到非數字字元、無效排列或字串結尾後，不再讀取後續內容。

關鍵不只是把字元轉成數字，還要在運算發生前判斷下一步是否超出 32 位元整數範圍。兩種解法都不使用 `int.Parse` 或例外處理代替解析規則。

## 解法一：手動索引掃描

公開方法：

```csharp
public static int MyAtoi(string s)
```

### 設計說明

這個解法用索引 `i` 明確控制目前讀到的位置：

1. 使用 `while` 略過前導空白。
2. 檢查第一個非空白字元：
   - `'-'`：記錄負號並前進一格。
   - `'+'`：維持正號並前進一格。
   - 數字：直接進入數字累積。
   - 其他字元：沒有合法數字可讀，回傳 `0`。
3. 只要目前字元介於 `'0'` 與 `'9'`，就換算成 `digit` 並加入結果。
4. 遇到非數字字元便結束迴圈，忽略後面的所有內容。
5. 最後依先前記錄的符號回傳正值或負值。

### 溢位判斷

若直接執行：

```text
result = result * 10 + digit
```

運算本身可能先溢位，因此必須在計算前確認：

```text
result * 10 + digit <= int.MaxValue
```

移項後可得到：

```text
result <= (int.MaxValue - digit) / 10
```

因此當下列條件成立時，代表加入目前數字後將超出範圍：

```csharp
result > (int.MaxValue - digit) / 10
```

此時可依符號直接回傳 `int.MaxValue` 或 `int.MinValue`，不必真的執行可能溢位的乘法。

### 範例演示

#### 一般負數：`" -042"`

| 步驟 | 讀取內容 | 累積值 | 說明 |
|---|---|---:|---|
| 1 | `␠` | 0 | 略過前導空白 |
| 2 | `-` | 0 | 記錄為負數 |
| 3 | `0` | 0 | `0 × 10 + 0 = 0` |
| 4 | `4` | 4 | `0 × 10 + 4 = 4` |
| 5 | `2` | 42 | `4 × 10 + 2 = 42` |
| 6 | 字串結尾 | -42 | 套用負號後回傳 |

#### 遇到非數字：`"1337c0d3"`

依序累積 `1 → 13 → 133 → 1337`。讀到 `c` 時，數字迴圈立即停止；後面的 `0d3` 不再處理，結果為 `1337`。

#### 正向溢位：`"2147483648"`

讀取最後一位 `8` 前，`result` 已是 `214748364`。此時：

```text
(2147483647 - 8) / 10 = 214748363
```

因為 `214748364 > 214748363`，可在乘法前判定即將溢位並回傳 `2147483647`。

### 複雜度

- 時間複雜度：`O(n)`，最壞情況掃描整個字串一次。
- 空間複雜度：`O(1)`，只使用固定數量的索引與整數變數。

## 解法二：有限狀態機

公開方法：

```csharp
public static int MyAtoi2(string s)
```

### 解題出發點

手動掃描依靠條件分支維護「現在還能接受什麼字元」。有限狀態機則把這項隱含資訊明確命名，使每個字元是否有效由「目前狀態」與「字元類型」共同決定。

程式使用四種狀態：

- `Start`：尚未讀到符號或數字，可以略過前導空白。
- `Signed`：已讀取正號或負號，下一個字元必須是數字。
- `InNumber`：正在累積數字；只有下一個數字能繼續解析。
- `End`：解析完成或輸入無效，停止讀取。

每個輸入字元會被分類為：

- `Space`
- `Sign`
- `Digit`
- `Other`

### 狀態轉移表

| 目前狀態 | 空白 `Space` | 符號 `Sign` | 數字 `Digit` | 其他 `Other` |
|---|---|---|---|---|
| `Start` | `Start` | `Signed` | `InNumber` | `End` |
| `Signed` | `End` | `End` | `InNumber` | `End` |
| `InNumber` | `End` | `End` | `InNumber` | `End` |
| `End` | `End` | `End` | `End` | `End` |

這張表直接表達以下規則：

- 空白只能出現在最前面。
- 正負號只能出現一次，而且必須位於第一個非空白位置。
- 符號後面必須接數字。
- 開始讀取數字後，任何非數字字元都會結束解析。

### 數值累積與截斷

狀態機使用 `long magnitude` 保存目前的非負絕對值，並依符號決定合法上限：

- 正數上限：`2147483647`
- 負數絕對值上限：`2147483648`

負數的絕對值上限比正數多 `1`，這正是 `int.MinValue` 與 `int.MaxValue` 不對稱的原因。每次加入新數字前仍先使用除法公式判斷是否超出對應上限；一旦超出，就把 `magnitude` 設為上限並停止掃描。

### 範例演示

#### 一般負數：`" -042"`

| 字元 | 類型 | 狀態轉移 | 動作 |
|---|---|---|---|
| `␠` | `Space` | `Start → Start` | 略過空白 |
| `-` | `Sign` | `Start → Signed` | 將符號設為 `-1` |
| `0` | `Digit` | `Signed → InNumber` | `magnitude = 0` |
| `4` | `Digit` | `InNumber → InNumber` | `magnitude = 4` |
| `2` | `Digit` | `InNumber → InNumber` | `magnitude = 42` |

掃描結束後套用負號，得到 `-42`。

#### 遇到非數字：`"1337c0d3"`

前四個數字讓狀態維持在 `InNumber`，並得到 `magnitude = 1337`。讀到 `c` 時，字元類型為 `Other`，狀態由 `InNumber` 轉為 `End`，後續字元不再解析。

#### 負向溢位：`"-2147483649"`

讀到負號後，合法絕對值上限設定為 `2147483648`。最後一位 `9` 會使數值超過此上限，因此將絕對值截斷為 `2147483648`；套用負號後回傳 `-2147483648`。

### 複雜度

- 時間複雜度：`O(n)`，每個字元最多分類與轉移一次。
- 空間複雜度：`O(1)`，狀態轉移表大小固定，不隨輸入長度增加。

## 兩種解法比較

| 比較項目 | 解法一：手動索引掃描 | 解法二：有限狀態機 |
|---|---|---|
| 主要結構 | 索引、條件分支、數字迴圈 | 狀態、字元分類、轉移表 |
| 優點 | 程式直接、額外結構少 | 規則集中、狀態邊界清楚 |
| 取捨 | 規則增加時分支容易變複雜 | 初始程式碼與概念較多 |
| 溢位策略 | 使用 `int` 並在乘法前檢查 | 使用 `long` 絕對值並依符號選擇上限 |
| 時間複雜度 | `O(n)` | `O(n)` |
| 空間複雜度 | `O(1)` | `O(1)` |
| 適合情境 | 規則固定、追求簡潔實作 | 需要清楚呈現解析狀態或擴充規則 |
