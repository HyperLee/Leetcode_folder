# LeetCode 2778：特殊元素平方和

![C#](https://img.shields.io/badge/language-C%23-239120) ![.NET 10](https://img.shields.io/badge/.NET-10-512BD4)

以 C# 實作兩種解法：逐一枚舉位置、枚舉成對因數。程式包含八筆固定測試，直接執行即可比較兩種方法的預期值與實際值。

## 題目說明

題目來源：[LeetCode 英文題目](https://leetcode.com/problems/sum-of-squares-of-special-elements/description/)／[中文題目](https://leetcode.cn/problems/sum-of-squares-of-special-elements/)。

給定長度為 `n` 的整數陣列 `nums`。題目的位置從 **1** 開始：若位置 `p` 能整除 `n`，即 `n % p == 0`，該位置的元素就是特殊元素。回傳所有特殊元素的平方和。

這裡以 `p` 表示題目位置，避免和程式中的 `i` 混淆。特殊的是**位置**，不是元素值；不需要判斷 `n % nums[i]`。

### 官方範例

| 輸入 | 特殊位置（從 1 開始） | 平方和 | 輸出 |
|---|---|---|---:|
| `[1,2,3,4]` | 1、2、4 | `1² + 2² + 4²` | 21 |
| `[2,7,1,19,18,3]` | 1、2、3、6 | `2² + 7² + 1² + 3²` | 63 |

第二個範例中，值 `19` 與 `18` 位於位置 4、5。因為 4、5 都不能整除 6，所以不加入答案；值 7 位於位置 2，則必須加入。

### 限制條件與輸入契約

- `1 <= nums.length == n <= 50`。
- `1 <= nums[i] <= 50`。
- 兩個方法都假設輸入為非 `null` 且符合題目限制的陣列，不額外定義空陣列或超出限制的行為。
- 兩個方法都只讀取陣列，不會修改元素，也不會排序。

## 解題出發點：先找位置，再取元素

答案可表示為「對所有 `n` 的正因數位置 `p`，累加 `nums[p - 1]²`」。位置和索引的換算如下：

| 題目位置 `p` | C# 索引 | 要讀取的元素 | 篩選條件 |
|---:|---:|---|---|
| 1 | 0 | `nums[0]` | `n % 1 == 0` |
| 2 | 1 | `nums[1]` | `n % 2 == 0` |
| p | p − 1 | `nums[p - 1]` | `n % p == 0` |
| n | n − 1 | `nums[n - 1]` | `n % n == 0` |

位置 1 與位置 `n` 永遠符合條件，但 `n = 1` 時兩者是同一個位置，只能計算一次。

接下來有兩個方向：先檢查所有位置，再篩選因數；或直接利用因數成對的性質，找出要讀取的位置。

## 解法一：逐一枚舉位置 `SumOfSquares`

### 設計與變數對應

| 變數 | 意義 |
|---|---|
| `n` | 陣列長度，也是要被整除的數 |
| `i` | 從 0 到 `n - 1` 的 C# 索引 |
| `i + 1` | 當前元素在題目中的一基底位置 |
| `ans` | 已處理範圍內所有特殊元素的平方和 |

初始化 `ans = 0`，接著逐一檢查 `i`。當 `n % (i + 1) == 0` 時，位置符合條件，執行 `ans += nums[i] * nums[i]`；否則保持 `ans`。迴圈結束後直接回傳 `ans`。

判斷的位置用 `i + 1`，讀取的索引用 `i`。若改成 `n % i`，第一輪會除以零，其他輪也會把位置錯移一格。

### 官方範例一的完整流程

`nums = [1,2,3,4]`，`n = 4`，初始 `ans = 0`。

| `i` | 位置 `i + 1` | 元素 | `4 % (i + 1)` | 動作 | 更新後 `ans` |
|---:|---:|---:|---:|---|---:|
| 0 | 1 | 1 | 0 | 加上 1² | 1 |
| 1 | 2 | 2 | 0 | 加上 2² | 5 |
| 2 | 3 | 3 | 1 | 跳過 | 5 |
| 3 | 4 | 4 | 0 | 加上 4² | 21 |

### 官方範例二的完整流程

`nums = [2,7,1,19,18,3]`，`n = 6`，初始 `ans = 0`。

| `i` | 位置 `i + 1` | 元素 | `6 % (i + 1)` | 動作 | 更新後 `ans` |
|---:|---:|---:|---:|---|---:|
| 0 | 1 | 2 | 0 | 加上 2² | 4 |
| 1 | 2 | 7 | 0 | 加上 7² | 53 |
| 2 | 3 | 1 | 0 | 加上 1² | 54 |
| 3 | 4 | 19 | 2 | 跳過 | 54 |
| 4 | 5 | 18 | 1 | 跳過 | 54 |
| 5 | 6 | 3 | 0 | 加上 3² | 63 |

### 正確性與複雜度

每輪結束後，`ans` 恰好等於索引 0 至當前 `i` 中符合特殊條件的元素平方和。起始尚未處理元素，因此總和為 0；每輪只在條件成立時加入當前元素，維持這個性質。全部索引處理完畢後，即得到所求答案。每個索引只出現一次，不會重複累加。

檢查 `n` 次，每次工作為常數時間，因此時間複雜度為 **O(n)**。僅使用固定數量的整數變數，額外空間為 **O(1)**。

## 解法二：枚舉成對因數 `SumOfSquares2`

### 為什麼只需檢查到平方根？

若 `i` 能整除 `n`，則 `i × (n / i) = n`，所以 `i` 與 `n / i` 都是因數。例如 `n = 12` 的因數配對為 `(1,12)`、`(2,6)`、`(3,4)`。

每組配對至少有一個因數不大於 `√n`：如果兩個都大於 `√n`，乘積就會大於 `n`。因此枚舉較小的因數，就能連同較大的因數一起處理。

程式使用 `i * i <= n`，不需要計算浮點平方根。等號不可省略，否則會漏掉完全平方數的中間因數。

### 設計與操作順序

| 表達式 | 意義 |
|---|---|
| `i` | 從 1 開始的候選因數，也是題目的一基底位置 |
| `n / i` | 當 `n % i == 0` 時找到的配對因數位置 |
| `i - 1` | 較小因數位置對應的 C# 索引 |
| `n / i - 1` | 配對因數位置對應的 C# 索引 |
| `nums[i - 1]` | 較小因數位置上的元素值 |
| `nums[n / i - 1]` | 配對因數位置上的元素值 |
| `nums[n / i - 1] * nums[n / i - 1]` | 配對位置上的元素平方，也就是這次要加入答案的數值 |
| `ans` | 已找到且未重複計算的特殊元素平方和 |

1. 以 `i = 1` 起始，在 `i * i <= n` 時繼續枚舉。
2. 先判斷 `n % i == 0`；不成立時跳過，不能把截斷後的整數商當成配對因數。
3. 成立時，先累加 `nums[i - 1] * nums[i - 1]`。
4. 若 `i * i != n`，再累加 `nums[n / i - 1] * nums[n / i - 1]`。
5. 遞增 `i`，迴圈結束後回傳 `ans`。

### 從配對位置到實際累加：完整程式碼代入

程式累加的是**元素值的平方**。`n / i` 先找出配對位置，再減 1 轉成 C# 索引，最後透過 `nums[...]` 取得元素值。

以 `nums = [2,7,1,19,18,3]`、`n = 6`、`i = 2` 為例，`6 % 2 == 0`，因此可以使用配對因數：

| 步驟 | 表達式代入 | 結果的意義 |
|---|---|---|
| 找配對位置 | `n / i = 6 / 2 = 3` | 題目從 1 開始的位置 3 |
| 轉換成 C# 索引 | `n / i - 1 = 3 - 1 = 2` | 陣列索引 2 |
| 讀取元素 | `nums[n / i - 1] = nums[2] = 1` | 位置 3 上的元素值為 1 |
| 計算平方 | `nums[2] * nums[2] = 1 * 1 = 1` | 加入答案的數值為 1 |

原始累加式與逐步化簡如下；這些是同一行的不同寫法，實際只累加一次：

```csharp
ans += nums[n / i - 1] * nums[n / i - 1];
// 代入 n = 6、i = 2：
// ans += nums[6 / 2 - 1] * nums[6 / 2 - 1];
// ans += nums[2] * nums[2];
// ans += 1 * 1;
```

這一輪先由第一行加入 `nums[i - 1]² = nums[1]² = 7²`，使 `ans` 從 13 變成 62；再由配對位置加入 `nums[2]² = 1²`，得到 63。不能直接把配對位置 3 平方後加入答案。

### 為什麼需要 `if (i * i != n)`？

第一行 `ans += nums[i - 1] * nums[i - 1]` 已經計算位置 `i` 的元素。第二行只有在配對位置 `n / i` 與 `i` 不同時才需要執行。

在外層已確認 `n % i == 0`，且 `i > 0` 的前提下，兩個位置相同的條件可推導為：

```text
i == n / i
    ↓ 兩邊乘以 i
i * i == n
```

因此，這裡的 `i * i != n` 等價於 `i != n / i`。當兩個位置相同時，減 1 後也指向同一個 C# 索引，必須略過第二次累加。**條件不成立時，第一行仍已計算該元素，只是第二行不再重複計算。**

判斷的是位置是否相同；不同位置即使元素值相同，仍須分別累加。

| 條件 | 用途 |
|---|---|
| `i * i <= n` | 控制迴圈範圍；包含等號才能處理平方根因數 |
| `n % i == 0` | 篩選因數；成立才處理這組特殊位置 |
| `i * i != n` | 防止重複；配對位置不同才加入第二個元素的平方 |

原始 XML 說明中的枚舉範圍較概略，實際程式的上界是 `i * i <= n`。

### 官方範例一的完整流程

`nums = [1,2,3,4]`，`n = 4`，初始 `ans = 0`。

| `i` | `i * i <= 4` | `4 % i` | 第一個位置／索引 | 配對位置／索引 | 累加順序 | 更新後 `ans` |
|---:|---|---:|---|---|---|---:|
| 1 | 是 | 0 | 1／0 | 4／3 | 0 → 加 1² 得 1 → 加 4² 得 17 | 17 |
| 2 | 是 | 0 | 2／1 | 2／1 | 加 2² 得 21；配對相同，略過 | 21 |
| 3 | 否 | — | — | — | 結束迴圈 | 21 |

累加順序為位置 1、4、2，與解法一不同，但選到的元素完全相同。

### 官方範例二的完整流程

`nums = [2,7,1,19,18,3]`，`n = 6`，初始 `ans = 0`。

| `i` | `i * i <= 6` | `6 % i` | 第一個位置／索引 | 配對位置／索引 | 累加順序 | 更新後 `ans` |
|---:|---|---:|---|---|---|---:|
| 1 | 是 | 0 | 1／0 | 6／5 | 0 → 加 2² 得 4 → 加 3² 得 13 | 13 |
| 2 | 是 | 0 | 2／1 | 3／2 | 13 → 加 7² 得 62 → 加 1² 得 63 | 63 |
| 3 | 否 | — | — | — | 結束迴圈 | 63 |

### 長度 9：平方根因數只算一次

取 `nums = [1,2,3,4,5,6,7,8,9]`，特殊位置為 1、3、9。

| `i` | 判斷 | 處理位置 | 增加的平方 | 更新後 `ans` |
|---:|---|---|---|---:|
| 1 | `9 % 1 == 0` | 1、9 | 1² + 9² | 82 |
| 2 | `9 % 2 != 0` | 無 | 0 | 82 |
| 3 | `9 % 3 == 0` 且 `3 * 3 == 9` | 3，只處理一次 | 3² | 91 |
| 4 | `4 * 4 > 9` | 結束 | — | 91 |

特別看 `i = 3` 這一輪，兩個陣列存取式分別代入後為：

```text
第一個位置：nums[i - 1]     = nums[3 - 1]     = nums[2] = 3
配對位置：  nums[n / i - 1] = nums[9 / 3 - 1] = nums[2] = 3
```

兩者都讀取同一個 `nums[2]`。實際執行順序是：

```csharp
// 第一行已經加入位置 3 的元素平方，ans 從 82 變成 91。
ans += nums[i - 1] * nums[i - 1];

// 3 * 3 != 9 為 false，跳過第二次累加。
if (i * i != n)
{
    ans += nums[n / i - 1] * nums[n / i - 1];
}
```

若移除去重判斷，位置 3 會被加兩次，錯誤結果為 `1² + 9² + 3² + 3² = 100`，正確結果則是 `1² + 9² + 3² = 91`。長度 1 也走相同邏輯：配對 `(1,1)` 都指向 `nums[0]`，只處理一次。

### 正確性與複雜度

只有整除成立時才讀取因數位置，因此不會加入非特殊元素。所有因數都屬於某組配對，而每組的較小因數必定出現在枚舉範圍內，因此不會遺漏。不同配對的較小因數不同，較大因數不會再次作為另一組的較小因數出現；相等的平方根因數則由條件排除第二次累加。因此每個特殊元素恰好計算一次。

迴圈檢查 `⌊√n⌋` 個候選因數，每次最多累加兩個平方，時間複雜度為 **O(√n)**；額外空間為 **O(1)**。

## 兩種方法比較與數值範圍

| 項目 | `SumOfSquares` | `SumOfSquares2` |
|---|---|---|
| 出發點 | 掃描所有位置，再判斷是否特殊 | 直接找因數位置 |
| `i` 的意義 | 零基底索引 | 一基底因數位置 |
| 時間 | O(n) | O(√n) |
| 額外空間 | O(1) | O(1) |
| 注意事項 | 用 `i + 1` 判斷位置 | 因數索引減 1、平方根因數去重 |

兩種方法都用整數乘法計算平方。依題目限制，每個平方最多為 `50 × 50 = 2500`，至多有 50 個元素，即使全部加入也僅為 `125000`，小於 `int.MaxValue = 2147483647`。這是安全上界，不代表長度 50 時所有位置都是因數。實際上 50 的因數只有 1、2、5、10、25、50，元素全為 50 時結果為 `6 × 2500 = 15000`。
