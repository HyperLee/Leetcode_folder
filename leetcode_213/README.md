## 題目說明

一條街道上的房屋圍成一個環，每間房屋內都有一筆非負金額。相鄰房屋的防盜系統互相連接，因此同一晚不能搶劫任意兩間相鄰房屋。

環形排列代表：

- 一般相鄰房屋不能同時選擇。
- 第一間房屋與最後一間房屋也相鄰，不能同時選擇。

給定整數陣列 `nums`，其中 `nums[i]` 表示第 `i` 間房屋的金額，目標是在不觸發警報的前提下，求出最多可以取得的金額。

題目連結：[LeetCode 213. House Robber II](https://leetcode.com/problems/house-robber-ii/description/)

## 限制條件

LeetCode 題目限制如下：

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 1000`

本專案的 `Rob` 與 `Rob2` 另外保留空陣列的防禦行為：當 `nums.Length == 0` 時回傳 `0`。兩個公開方法皆要求 `nums` 不可為 `null`，且不會修改輸入陣列。

## 解題概念與出發點

### 為什麼不能直接套用線性版本？

在線性街道中，只需處理「不能選相鄰房屋」。環形街道還多了一條首尾限制：索引 `0` 與索引 `n - 1` 不能同時出現在答案中。

任何合法答案一定符合下列至少一種情況：

1. 不選最後一間，只考慮索引 `0..n-2`。
2. 不選第一間，只考慮索引 `1..n-1`。

如果最佳答案同時不選首尾，它也會被上述兩個區間涵蓋。因此只要分別求出兩個線性區間的最佳值，再取最大值即可：

```text
answer = max(
    robLinear(nums, 0, n - 2),
    robLinear(nums, 1, n - 1)
)
```

當陣列只有一間房屋時，兩個區間的拆分不成立，所以兩種解法都先直接回傳 `nums[0]`。

## 解法一：滾動動態規劃

### 設計說明

`Rob` 先處理空陣列與單一房屋，再呼叫 `RobRange` 計算兩個線性區間。

對線性區間中的第 `i` 間房屋，有兩種選擇：

- 搶第 `i` 間：前一間不能搶，金額為 `dp[i - 2] + nums[i]`。
- 不搶第 `i` 間：保留處理至前一間的最佳值 `dp[i - 1]`。

狀態轉移式為：

```text
dp[i] = max(dp[i - 2] + nums[i], dp[i - 1])
```

目前狀態只依賴前兩個狀態，因此不必建立完整 `dp` 陣列：

- `previousTwo`：處理到前兩間房屋時的最佳金額。
- `previousOne`：處理到前一間房屋時的最佳金額。
- `current`：搶目前房屋與略過目前房屋兩者的較大值。

每輪計算後將兩個狀態向前滾動，即可把額外空間降為常數。

### 範例演示：`[1, 2, 3, 1]`

#### 區間一：不含最後一間 `[1, 2, 3]`

| 處理位置 | `previousTwo` | `previousOne` | 計算 | 結果 |
| --- | ---: | ---: | --- | ---: |
| 初始化前兩間 | 1 | 2 | `max(1, 2)` | 2 |
| 金額 3 | 1 | 2 | `max(1 + 3, 2)` | 4 |

此區間最佳值為 `4`，代表選擇金額 `1` 與 `3`。

#### 區間二：不含第一間 `[2, 3, 1]`

| 處理位置 | `previousTwo` | `previousOne` | 計算 | 結果 |
| --- | ---: | ---: | --- | ---: |
| 初始化前兩間 | 2 | 3 | `max(2, 3)` | 3 |
| 金額 1 | 2 | 3 | `max(2 + 1, 3)` | 3 |

此區間最佳值為 `3`。最後取 `max(4, 3) = 4`。

### 複雜度

- 時間複雜度：`O(n)`，兩個線性區間各走訪一次。
- 空間複雜度：`O(1)`，只保存固定數量的滾動狀態。

## 解法二：遞迴記憶化

### 設計說明

`Rob2` 使用與解法一相同的環形拆分，但改以由上而下的方式求解每個線性區間。

令 `F(i)` 表示從索引 `i` 到目前區間終點可以取得的最大金額：

```text
F(i) = max(
    nums[i] + F(i + 2),  // 搶目前房屋，跳過下一間
    F(i + 1)             // 不搶目前房屋
)
```

當 `i` 超過區間終點時，表示沒有剩餘房屋，回傳 `0`。若同一個索引已計算過，就直接讀取 `memo[i]`，避免遞迴樹重複展開。

兩個線性區間必須建立各自獨立的 `memo`。雖然它們可能使用相同索引，但區間終點不同；同一索引在不同終點下代表的子問題並不相同，若共用快取可能讀到不屬於目前區間的結果。

陣列金額皆為非負數，因此以 `-1` 安全表示「尚未計算」。

### 範例演示：`[1, 2, 3, 1]`

#### 區間一：索引 `0..2`

以 `F(i)` 表示從索引 `i` 到索引 `2` 的最佳值：

```text
F(2) = max(3 + F(4), F(3)) = max(3, 0) = 3
F(1) = max(2 + F(3), F(2)) = max(2, 3) = 3
F(0) = max(1 + F(2), F(1)) = max(4, 3) = 4
```

索引 `2` 的結果被 `memo` 保存；後續再次需要 `F(2)` 時可直接回傳 `3`。

#### 區間二：索引 `1..3`

此區間使用新的快取：

```text
F(3) = max(1 + F(5), F(4)) = 1
F(2) = max(3 + F(4), F(3)) = max(3, 1) = 3
F(1) = max(2 + F(3), F(2)) = max(3, 3) = 3
```

最後取兩個區間的最大值：`max(4, 3) = 4`。

### 複雜度

- 時間複雜度：`O(n)`，每個區間中的每個索引最多實際計算一次。
- 空間複雜度：`O(n)`，包含記憶化陣列與最深 `O(n)` 的遞迴呼叫堆疊。

## 兩種解法比較

| 項目 | 解法一：滾動動態規劃 | 解法二：遞迴記憶化 |
| --- | --- | --- |
| 公開方法 | `Rob` | `Rob2` |
| 思考方向 | 由小區間向大區間推導 | 從目標問題遞迴拆解子問題 |
| 時間複雜度 | `O(n)` | `O(n)` |
| 空間複雜度 | `O(1)` | `O(n)` |
| 優點 | 空間效率高、沒有遞迴堆疊 | 遞迴定義直接對應「搶或不搶」的選擇 |
| 注意事項 | 必須正確維護前兩個滾動狀態 | 兩個線性區間不能共用 memo |

兩種公開方法都不修改輸入陣列。測試入口仍為每次呼叫建立陣列副本，使每個解法取得獨立資料，避免未來修改其中一個實作時互相影響。
