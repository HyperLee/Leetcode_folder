## 題目說明

給定兩棵二元樹 `root` 與 `subRoot`，判斷 `subRoot` 是否為 `root` 的子樹。

子樹必須從 `root` 中的某個節點開始，包含該節點以下的所有後代，而且節點值、左右方向與整體結構都要和 `subRoot` 完全相同。只找到相同的一部分節點，或節點值相同但左右結構不同，都不能算是子樹。

### 限制條件

- `root` 的節點數範圍為 `[1, 2000]`。
- `subRoot` 的節點數範圍為 `[1, 1000]`。
- `-10^4 <= root.val <= 10^4`。
- `-10^4 <= subRoot.val <= 10^4`。

> [!TIP]
> 這題可以拆成兩個問題：先在主樹中尋找可能的子樹根節點，再解 LeetCode 100「Same Tree」，確認兩棵樹是否完全相同。

## 解題概念與出發點

判定子樹時，只有節點值相同還不夠。以下兩棵樹的節點值都是 `1, 1`，但結構不同：

```text
主樹候選：       候選子樹：
    1                1
   /                  \
  1                    1
```

因此每一種解法都必須同時保證：

1. 候選子樹從主樹中的某個完整節點開始。
2. 每個對應節點的值相同。
3. 左右子樹的位置相同。
4. 空分支的位置也相同。

本專案提供以下公開方法：

| 方法 | 核心策略 | 適合用途 |
| --- | --- | --- |
| `IsSubtree` | 走訪主樹的每個節點，對候選位置執行 Same Tree | 最直觀，容易由題意推導 |
| `IsSubtree2` | 將兩棵樹完整序列化，再以 KMP 搜尋子樹序列 | 線性字串匹配，適合比較進階方法 |

## 解法一：遞迴尋找候選根並比較整棵樹

### 設計說明

`IsSubtree` 對主樹進行深度優先搜尋。每到一個節點，就把它視為可能的子樹根，呼叫 `IsSameTree` 檢查：

1. 兩個目前節點都為 `null`：這一條分支完全相同，回傳 `true`。
2. 只有一個節點為 `null`：結構不同，回傳 `false`。
3. 兩個節點值不同：內容不同，回傳 `false`。
4. 目前節點相同：左右子樹都必須繼續相同。

如果目前位置不是答案，`IsSubtree` 會分別前往主樹的左、右子樹尋找。兩邊只要有一邊找到完整匹配，就可以回傳 `true`。

### 範例演示

輸入：

```text
root    = [3,4,5,1,2]
subRoot = [4,1,2]
```

搜尋流程：

| 步驟 | 主樹候選節點 | 比較結果 | 後續動作 |
| --- | ---: | --- | --- |
| 1 | `3` | `3 != 4` | 搜尋主樹的左、右子樹 |
| 2 | `4` | 根節點值相同 | 進入 `IsSameTree` |
| 3 | 左側 `1` 對 `1` | 節點值及兩個空分支相同 | 左子樹通過 |
| 4 | 右側 `2` 對 `2` | 節點值及兩個空分支相同 | 右子樹通過 |
| 5 | 候選根 `4` | 左右子樹都相同 | 回傳 `true` |

### 為什麼官方反例失敗

對 `root = [3,4,5,1,2,null,null,null,null,0]` 而言，值為 `4` 的節點看似能對上 `subRoot = [4,1,2]`，但主樹中的節點 `2` 還有一個值為 `0` 的左子節點。候選子樹在相同位置是空分支，所以 `IsSameTree` 會判定結構不同。

### 複雜度

令主樹節點數為 `m`、候選子樹節點數為 `n`：

- 時間複雜度：最差為 `O(m × n)`。主樹的每個節點都可能觸發一次最多比較 `n` 個節點的 Same Tree。
- 空間複雜度：`O(h₁ + h₂)`，其中 `h₁`、`h₂` 分別為兩棵樹的高度；最差退化樹可達 `O(m + n)`。

## 解法二：前序序列化與 KMP

### 設計說明

`IsSubtree2` 先把兩棵樹依「根、左、右」順序轉成字串，再判斷候選子樹的完整字串是否出現在主樹字串中。

序列化不能只記錄節點值，還需要兩種保護：

- 每個非空節點使用 `^值,`，例如 `^12,`。`^` 明確標示數值 token 的起點，避免 `2` 誤匹配到 `12` 內部。
- 每個空分支使用 `#,`。空分支 token 能區分「左邊有節點」和「右邊有節點」等不同樹形。

例如：

```text
    1        1
   /          \
  1            1

左樹：^1,^1,#,#,#,
右樹：^1,#,^1,#,#,
```

兩棵樹雖然具有相同節點值，但序列化結果不同。

完成序列化後，程式使用 KMP：

1. 對候選子樹字串建立 LPS（Longest Prefix Suffix）表。
2. 從頭掃描主樹字串與候選字串。
3. 字元相同時同時前進。
4. 發生失配且已匹配部分內容時，依 LPS 回退候選字串索引，不回頭重掃主字串。
5. 候選字串全部匹配完成即回傳 `true`。

### 範例演示

同樣使用官方正例：

```text
root    = [3,4,5,1,2]
subRoot = [4,1,2]
```

前序序列化結果：

```text
root    => ^3,^4,^1,#,#,^2,#,#,^5,#,#,
subRoot => ^4,^1,#,#,^2,#,#,
```

KMP 先略過主樹開頭的 `^3,`。從 `^4,` 開始，後續的 `^1,#,#,^2,#,#,` 都和候選字串相同，因此找到完整且連續的模式，回傳 `true`。

官方反例中，主樹候選位置的節點 `2` 後方還會出現 `^0,#,#,`，但候選子樹在該位置預期的是 `#,`。序列不再連續相同，所以不會誤判。

多位數案例 `root = [12]`、`subRoot = [2]` 會得到：

```text
root    => ^12,#,#,
subRoot => ^2,#,#,
```

由於兩個數值都必須從 `^` token 起點開始匹配，`^2,` 不會出現在 `^12,` 中。

### 複雜度

令兩棵樹序列化後的字串長度分別為 `S`、`T`：

- 時間複雜度：序列化與 KMP 合計為 `O(S + T)`。在題目節點值位數有界時，可視為 `O(m + n)`。
- 空間複雜度：`O(S + T)`，用於兩份序列化字串、候選字串的 LPS 表與遞迴走訪堆疊。

## 測試案例

主控台執行器會讓兩種解法共同驗證下列案例：

| 案例 | `root` | `subRoot` | 預期 | 驗證重點 |
| --- | --- | --- | --- | --- |
| 官方正例 | `[3,4,5,1,2]` | `[4,1,2]` | `true` | 一般子樹匹配 |
| 官方反例 | `[3,4,5,1,2,null,null,null,null,0]` | `[4,1,2]` | `false` | 多出的後代不可忽略 |
| 整棵樹相同 | `[1,2,3]` | `[1,2,3]` | `true` | 根節點直接匹配 |
| 單一葉節點 | `[1,2,3]` | `[3]` | `true` | 最小非空子樹 |
| 重複值、結構不同 | `[1,1]` | `[1,null,1]` | `false` | null 位置與左右方向 |
| 多位數 token | `[12]` | `[2]` | `false` | 數值 token 邊界 |
